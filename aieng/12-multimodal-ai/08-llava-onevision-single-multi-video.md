# LLaVA-OneVision:单图、多图、视频,一个模型全包

> LLaVA-OneVision(Li et al., 2024 年 8 月)之前,开放 VLM 世界是几条平行谱系:单图有 LLaVA-1.5,多图有 Mantis、VILA,视频有 Video-LLaVA、Video-LLaMA。各自赢各自的基准,在别家基准上翻车。LLaVA-OneVision 主张:一套课程就能训出一个在三种场景都称王的模型,而且涌现出的任务迁移效应(单图技能迁移到视频、多图推理迁移回单图)胜过一堆专家模型之和。配方简单得出人意料:跨场景恒定的视觉 token 预算,加上一条从 单图 → OneVision(多图)→ 视频 的显式课程。本课精读这份预算、这条课程,以及涌现行为。

**类型:** 动手构建
**编程语言:** Python(标准库,token 预算求解器 + 课程规划器)
**前置要求:** 第 12 阶段第 05 课(LLaVA)、第 12 阶段第 06 课(任意分辨率)
**预计耗时:** 约 180 分钟

## 学习目标

- 设计一份在单图、多图、视频输入下保持恒定的视觉 token 预算。
- 排定一条训练课程,让技能从单图迁移到视频而不发生灾难性遗忘。
- 解释为什么课程排对时,同参数量下单模型能击败专家模型。
- 说出 LLaVA-OneVision 报告的三项涌现能力:多摄像头推理、set-of-mark 提示、iPhone 截图智能体。

## 问题

图像、多图、视频,对模型的压力各不相同。

单图要高分辨率 token(AnyRes,约 2880 个视觉 token)来抓 OCR 和细节。每样本预算:1 张图,2880 token。

多图要几张中等分辨率的图(每张约 576 token),跨图推理才装得进上下文。每样本预算:4–8 张图,每张 576,共 2300–4600 token。

视频要很多低分辨率帧(池化后每帧约 196 token)来捕捉时序动态。每样本预算:8–32 帧,每帧 196,共 1600–6200 token。

分开训练,你只需选一份预算;合训一个模型,就得让预算跨场景合理伸缩,又不撑爆上下文。

OneVision 之前,默认答案是"训一个场景,无视其余"。Video-LLaVA 用额外训练阶段把视频改装到图像模型上;LLaVA-NeXT 靠平铺加多图支持。没有一个能干净地同时处理三者。

## 概念

### OneVision token 预算

LLaVA-OneVision 选定统一的视觉 token 预算:每样本约 3000–4000 token,按场景分配:

- **单图:** AnyRes-9(3x3 切块 + 缩略图),每块 384 分辨率、729 patch,激进 2x2 双线性池化 → 每块 182。总计:9 * 182 + 182 = 1820 token。或 AnyRes-4,每块 729 = 2916 + 729。
- **多图:** 每张图中等分辨率(384,不切块),不池化 729 token。预算 6 张图 → 4374 token。
- **视频:** 32 帧,384 分辨率,激进 3x3 双线性池化 → 每帧 81 token。总计:32 * 81 = 2592 token。

分配维持总 token 大致恒定。LLM 永远看不到撑爆上下文的批次。编码器按场景产出不同几何,但 LLM 消费同一份预算。

### 三阶段课程

LLaVA-OneVision 分三阶段训练:

1. **单图 SFT(SI 阶段)。** 全部数据是 单图+文本,在高分辨率 AnyRes 输入上训练。教会感知、OCR 和细粒度理解。数据用 LLaVA-NeXT 数据加 OneVision 专属单图数据。
2. **OneVision SFT(OV 阶段)。** 混合 单图 + 多图 + 视频(均匀抽帧),在统一 token 预算上训练。教模型处理异构批次形状。不重置权重——从 SI 阶段继续。
3. **任务迁移(TT 阶段)。** 按目标任务配比继续,通常按产品需要偏向多图或视频。可选做部署微调。

关键:课程顺序要紧。先训视频或先训多图,图像表现都比先训单图差——哪怕数据完全相同。论文对此有显式消融。

### 为什么课程有效

单图训练打造感知底座:patch token 携带细粒度视觉特征,LLM 学会把它们与文本整合。多图和视频引入结构性挑战(哪张是哪张、先发生了什么),没有强感知底座很难学会。

如果从零混训所有场景,模型会感知欠拟合(每批次单图数据有限)、结构过拟合(多图/视频数据很多)。结果:一个会跨图推理套路、视觉却肤浅的模型。

课程排序让你从 SI 阶段拿到感知强度,再从 OV 阶段拿到组合/时序推理,两头都不丢。

### 涌现的跨场景技能

LLaVA-OneVision 论文报告了三项涌现能力:

1. **多摄像头推理。** 训练时多图与视频是分开的;推理时被要求推理一个多摄像头驾驶场景。模型正确整合了各个视角——尽管训练里从没见过这种格式。
2. **Set-of-mark 提示。** 用户在图上给物体标数字记号,模型推理"3 号标记相对 7 号标记在做什么"。训练里既没有标记也没有标注;它从 空间定位 + 多图引用 的组合中学来。
3. **iPhone 截图智能体。** 用户提供 iPhone 屏幕截图,要求规划下一次点击。训练数据是 UI 截图、用户工作流视频、多图前后对比对。泛化到了智能体场景。

这些都不是训过的任务;它们从课程的组合结构中涌现。

### 视觉 token 池化

token 预算离不开池化。OneVision 在 2D patch 网格上做双线性插值:24x24 = 576 patch 变 12x12 = 144(2 倍)或 8x8 = 64(3 倍)。池化在 patch 网格空间做,而不是 token 空间,以保住局部性。

每个场景的池化倍数本身也是超参数。池化越少 = token 越多 = 表示越丰富;池化越多 = token 越少 = 装得下的帧/图越多。

### LLaVA-OneVision-1.5

2025 年的续作(LLaVA-OneVision-1.5,arXiv 2509.23661)在训练数据、模型权重和代码上"完全开放",部分基准追平了与专有模型的差距,把配方民主化。同一课程,更多数据,更强基座 LLM,架构不变。

### 与 Qwen2.5-VL 的对照

Qwen2.5-VL(第 12.09 课)做了不同选择:用 M-RoPE 和动态 FPS,而不是固定池化。它的预算随输入伸缩——1 分钟视频比 5 秒视频用更多 token。LLaVA-OneVision 固定预算、调池化。两条路都通;它们拿可配置性换可预测性。

## 投入使用

`code/main.py` 是 OneVision 式 VLM 的课程与预算规划器。给定每样本 token 预算和目标场景配比(比如 40% 单图、30% 多图、30% 视频),它会:

- 按场景分配分辨率、池化倍数和帧数。
- 检查每个场景是否装进共享预算。
- 报告预期 token 数、LLM FLOPs,以及哪些场景 token 不足。
- 打印逐阶段训练排期。

用它规划 OneVision 微调,或给 VLM 部署的按请求成本做 sanity check。

## 交付

本课产出 `outputs/skill-onevision-budget-planner.md`。给定目标任务分布和每样本预算,产出 AnyRes 倍数、逐帧池化、视频帧数和课程各阶段权重。每当你训练或微调统一场景 VLM,都用它。

## 练习

1. 你的产品支持 80% 单图、10% 多图(2–4 张)、10% 视频(8–16 帧)。设计 token 预算。不重度做多图省下的预算,你会花在哪里?

2. 读 LLaVA-OneVision 第 4.3 节(涌现能力)。提出第四项该课程很可能解锁、但论文没报告的涌现技能。

3. 调换课程顺序——先多图,再单图,再视频。预测哪些基准会退化,为什么。

4. 论文报告的视频基准,训练时每样本只用 8 帧。推理时能泛化到 30 秒视频吗?先崩的是 token 预算还是时序推理?

5. 24x24 patch 双线性池化到 12x12,是每维 4 倍缩减。用标准库 Python 实现这个池化,验证每个 2x2 块的均值与双线性输出一致。

## 关键术语

| 术语 | 人们常说的是 | 实际含义是 |
|------|-----------------|------------------------|
| OneVision 场景 | "单图、多图或视频" | 统一 VLM 处理的三种输入形态之一;预算跨场景恒定 |
| Token 预算 | "每样本多少 token" | 训练/推理时每样本 LLM 看到的视觉 token 总数,典型 3000–4000 |
| 课程 | "训练顺序" | 为涌现迁移而选的阶段排序(单图 → 多图 → 视频) |
| 双线性池化 | "token 缩减" | 对 patch 网格(2D)做双线性插值,减 token 数同时保住局部性 |
| 涌现技能 | "没训过,居然会" | 训练数据中没有对应样本、却因课程组合在推理时出现的能力 |
| AnyRes-k | "k 切块配置" | k 个定分辨率子切块加一张缩略图,典型 k ∈ {4, 9} |
| 任务迁移 | "跨场景泛化" | 经共享骨干,单图上学到的技能应用到视频上(反之亦然) |
