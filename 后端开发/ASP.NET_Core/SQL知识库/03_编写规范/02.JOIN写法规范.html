JOIN 写法规范

JOIN 写法规范

JOIN 写错了不报错但结果错——数据多了少了你都不一定能发现。这篇把各种 JOIN 的语义、常见误区、写法规范理清楚。

七种 JOIN 一张图

INNER JOIN     → 两边都匹配才出
LEFT JOIN      → 左表全出，右表没匹配的补 NULL
RIGHT JOIN     → 右表全出，左表没匹配的补 NULL
FULL JOIN      → 两边全出，没匹配的各自补 NULL
CROSS JOIN     → 笛卡尔积，每行配每行
SELF JOIN      → 自己 JOIN 自己（不是关键字，是用法）
CROSS APPLY    → 类似 JOIN，但右边可以引用左边的列

实际开发中 INNER JOIN 和 LEFT JOIN 占 95%，其他偶尔用。

INNER JOIN vs LEFT JOIN

什么时候用 INNER JOIN

两边都必须有对应数据才有意义的时候：

-- 查订单和对应的客户信息（没客户的订单不可能存在）
SELECT o.OrderId, c.CustomerName
FROM Orders o
INNER JOIN Customers c ON o.CustomerId = c.CustomerId;

什么时候用 LEFT JOIN

左表的数据不管有没有匹配都要出来的时候：

-- 查所有客户及其订单数（包括没下过单的客户）
SELECT c.CustomerName, COUNT(o.OrderId) AS OrderCount
FROM Customers c
LEFT JOIN Orders o ON c.CustomerId = o.CustomerId
GROUP BY c.CustomerName;

如果用 INNER JOIN，没下单的客户就丢了。

常见误区

误区一：LEFT JOIN 后在 WHERE 里过滤右表

-- ❌ 这样写 LEFT JOIN 等于变成了 INNER JOIN
SELECT c.*, o.OrderDate
FROM Customers c
LEFT JOIN Orders o ON c.CustomerId = o.CustomerId
WHERE o.Status = 1;
-- 没有订单的客户 o.Status 是 NULL，NULL = 1 为 false，被过滤掉了

-- ✅ 过滤条件放到 ON 里
SELECT c.*, o.OrderDate
FROM Customers c
LEFT JOIN Orders o ON c.CustomerId = o.CustomerId AND o.Status = 1;
-- 这样没订单的客户还在，o 的列是 NULL

核心规则：LEFT JOIN 的右表过滤条件写在 ON 里，不要写在 WHERE 里。WHERE 里只放左表的条件。

误区二：多表 LEFT JOIN 的顺序

-- A LEFT JOIN B LEFT JOIN C
-- 如果 B 没匹配，C 的 ON 条件引用了 B 的列
SELECT a.*, b.BName, c.CName
FROM TableA a
LEFT JOIN TableB b ON a.Id = b.AId
LEFT JOIN TableC c ON b.Id = c.BId;  -- b.Id 可能是 NULL
-- 如果 B 没匹配，b.Id = NULL，C 也不会匹配
-- 这是正确的行为，但要清楚这个链式效果

误区三：INNER JOIN 和 WHERE 混用

-- 这两种写法效果一样
-- 写法 1：条件在 ON 里
SELECT * FROM Orders o
INNER JOIN Customers c ON o.CustomerId = c.CustomerId AND c.City = '北京';

-- 写法 2：条件在 WHERE 里
SELECT * FROM Orders o
INNER JOIN Customers c ON o.CustomerId = c.CustomerId
WHERE c.City = '北京';

-- 对于 INNER JOIN，放 ON 还是 WHERE 结果一样（优化器会合并）
-- 但建议：连接条件放 ON，过滤条件放 WHERE，逻辑更清晰

CROSS JOIN 什么时候用

笛卡尔积看起来很危险，但有合理场景：

-- 生成报表框架：每个月 × 每个部门
SELECT m.MonthName, d.DeptName
FROM Months m
CROSS JOIN Departments d;
-- 12 个月 × 5 个部门 = 60 行框架

-- 然后 LEFT JOIN 实际数据
SELECT m.MonthName, d.DeptName, ISNULL(t.Total, 0) AS Total
FROM Months m
CROSS JOIN Departments d
LEFT JOIN (
    SELECT MONTH(OrderDate) AS M, DeptId, SUM(Amount) AS Total
    FROM Orders GROUP BY MONTH(OrderDate), DeptId
) t ON m.MonthNum = t.M AND d.DeptId = t.DeptId;

CROSS APPLY vs LEFT JOIN

CROSS APPLY 像是 "对左表每一行执行一次子查询"：

-- 每个客户最近 3 笔订单
SELECT c.CustomerName, t.OrderDate, t.Amount
FROM Customers c
CROSS APPLY (
    SELECT TOP 3 OrderDate, Amount
    FROM Orders o
    WHERE o.CustomerId = c.CustomerId
    ORDER BY OrderDate DESC
) t;

用 LEFT JOIN 写这个很难（要先窗口函数编号再过滤），CROSS APPLY 直观很多。

CROSS APPLY vs OUTER APPLY：

  • CROSS APPLY = 右边没结果就不出这行（类似 INNER JOIN）
  • OUTER APPLY = 右边没结果也出这行，补 NULL（类似 LEFT JOIN）

JOIN 条件写法规范

别忘了 ON 条件

-- ❌ 忘了 ON 条件，变成笛卡尔积
SELECT * FROM Orders o
INNER JOIN Customers c;  -- 语法错误（INNER JOIN 必须有 ON）

-- 但 CROSS JOIN 不需要 ON
SELECT * FROM Orders CROSS JOIN Customers;  -- 合法但危险

多条件 ON

-- 复合键关联
SELECT *
FROM OrderDetail od
INNER JOIN Product p ON od.ProductId = p.ProductId AND od.WarehouseId = p.WarehouseId;

不等值 JOIN

-- 薪资在某个等级范围内
SELECT e.EmpName, g.GradeName
FROM Employees e
INNER JOIN SalaryGrade g ON e.Salary BETWEEN g.MinSalary AND g.MaxSalary;

性能注意点

  1. JOIN 列要有索引。两边都要有，不然变成 Hash Match 或 Nested Loops 全扫

  2. 小表 JOIN 大表比大表 JOIN 大表快。能先过滤就先过滤

  3. 避免在 ON 里用函数：

-- ❌
ON YEAR(a.OrderDate) = YEAR(b.ShipDate)

-- ✅
ON a.OrderDate >= b.ShipDateStart AND a.OrderDate < b.ShipDateEnd

  1. JOIN 顺序：SQL Server 优化器会自动调整 JOIN 顺序找最优计划，但写的时候按逻辑顺序排列方便人读

  2. JOIN 太多：超过 5-6 张表 JOIN 的查询考虑拆成临时表分步执行
