动态 SQL 安全写法

动态 SQL 安全写法

动态 SQL 能力强大，但也是 SQL 注入的重灾区。写不好就是给黑客开后门。这篇讲怎么在必须用动态 SQL 的场景下安全地写。

什么时候必须用动态 SQL

大多数情况不需要动态 SQL。但有些场景静态 SQL 写不了：

  1. 表名/列名是变量——SQL 参数化不能参数化表名
  2. 动态 PIVOT——列名来自数据
  3. 动态排序——ORDER BY 的列名是前端传的
  4. 通用查询存储过程——WHERE 条件完全动态
  5. DDL 操作——CREATE/ALTER/DROP 不能参数化

最大的错误：直接拼字符串

-- ❌ 绝对不要这样写
DECLARE @sql NVARCHAR(MAX);
SET @sql = 'SELECT * FROM Users WHERE UserName = ''' + @UserName + '''';
EXEC(@sql);

-- 如果 @UserName = "'; DROP TABLE Users; --"
-- 拼出来的 SQL 是：
-- SELECT * FROM Users WHERE UserName = ''; DROP TABLE Users; --'
-- 删库跑路

正确写法：sp_executesql + 参数化

DECLARE @sql NVARCHAR(MAX);
DECLARE @params NVARCHAR(MAX);

SET @sql = N'SELECT * FROM Users WHERE UserName = @name AND Status = @status';
SET @params = N'@name NVARCHAR(50), @status INT';

EXEC sp_executesql @sql, @params, @name = @UserName, @status = @Status;

sp_executesql 的优势：

  1. 防注入：参数值不会被当成 SQL 代码执行
  2. 计划重用：参数化的 SQL 可以重用执行计划，EXEC() 拼出来的每次不同都要重新编译
  3. 类型安全：参数有明确的数据类型

动态表名/列名的安全处理

表名和列名不能用参数化，只能拼字符串。怎么防注入？用 QUOTENAME：

DECLARE @TableName NVARCHAR(128) = N'Orders';
DECLARE @sql NVARCHAR(MAX);

-- QUOTENAME 会加上方括号并转义内部的特殊字符
SET @sql = N'SELECT * FROM ' + QUOTENAME(@TableName);
EXEC sp_executesql @sql;

-- QUOTENAME('Orders') → [Orders]
-- QUOTENAME('Orders]; DROP TABLE Users;--') → [Orders]; DROP TABLE Users;--]
-- 方括号保护了表名，注入代码变成了表名的一部分（查不到这个表，只会报错不会执行）

但更安全的做法是白名单验证：

-- 只允许查询特定的几张表
IF @TableName NOT IN ('Orders', 'Customers', 'Products')
BEGIN
    RAISERROR('非法表名', 16, 1);
    RETURN;
END

动态 WHERE 条件

CREATE PROCEDURE usp_SearchOrders
    @CustomerId INT = NULL,
    @Status INT = NULL,
    @StartDate DATE = NULL,
    @EndDate DATE = NULL
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @sql NVARCHAR(MAX) = N'SELECT * FROM Orders WHERE 1=1';
    DECLARE @params NVARCHAR(MAX) = N'
        @p_CustomerId INT,
        @p_Status INT,
        @p_StartDate DATE,
        @p_EndDate DATE';

    IF @CustomerId IS NOT NULL
        SET @sql += N' AND CustomerId = @p_CustomerId';

    IF @Status IS NOT NULL
        SET @sql += N' AND Status = @p_Status';

    IF @StartDate IS NOT NULL
        SET @sql += N' AND OrderDate >= @p_StartDate';

    IF @EndDate IS NOT NULL
        SET @sql += N' AND OrderDate < @p_EndDate';

    SET @sql += N' ORDER BY OrderDate DESC';

    EXEC sp_executesql @sql, @params,
        @p_CustomerId = @CustomerId,
        @p_Status = @Status,
        @p_StartDate = @StartDate,
        @p_EndDate = @EndDate;
END;

关键：WHERE 条件值用参数，不要拼进去。WHERE 1=1 是为了方便后面统一用 AND 开头。

动态排序

ORDER BY 没法参数化，但可以用 CASE WHEN：

-- 方法 1：CASE WHEN（列数少的时候）
SELECT * FROM Orders
ORDER BY
    CASE @SortColumn
        WHEN 'OrderDate' THEN OrderDate
        WHEN 'Amount' THEN Amount
    END;
-- 问题：不同列类型不同，CASE 要求返回类型一致，很难写

-- 方法 2：动态 SQL（更实用）
DECLARE @sql NVARCHAR(MAX) = N'SELECT * FROM Orders ORDER BY ';

-- 白名单验证排序列
SET @sql += CASE @SortColumn
    WHEN 'OrderDate' THEN 'OrderDate'
    WHEN 'Amount' THEN 'Amount'
    WHEN 'CustomerName' THEN 'CustomerName'
    ELSE 'OrderDate'  -- 默认
END;

SET @sql += CASE WHEN @SortDirection = 'ASC' THEN ' ASC' ELSE ' DESC' END;

EXEC sp_executesql @sql;

动态 PIVOT

DECLARE @cols NVARCHAR(MAX), @sql NVARCHAR(MAX);

-- 从数据里查出列名
SELECT @cols = STRING_AGG(QUOTENAME(Subject), ',')
FROM (SELECT DISTINCT Subject FROM Scores) t;

SET @sql = N'
SELECT StudentName, ' + @cols + '
FROM (SELECT StudentName, Subject, Score FROM Scores) src
PIVOT (MAX(Score) FOR Subject IN (' + @cols + ')) pvt';

EXEC sp_executesql @sql;

这里列名来自数据，没法参数化。QUOTENAME 保证了每个列名都被方括号包裹。

EXEC vs sp_executesql

EXEC(@sql)sp_executesql
参数化❌ 不支持✅ 支持
防注入❌✅
计划重用❌ 差✅ 好
什么时候用DDL 语句其他所有场景
-- DDL 只能用 EXEC
DECLARE @sql NVARCHAR(MAX) = 'CREATE INDEX IX ON ' + QUOTENAME(@TableName) + '(Id)';
EXEC(@sql);

-- DML 用 sp_executesql
DECLARE @sql NVARCHAR(MAX) = 'SELECT * FROM Orders WHERE Id = @id';
EXEC sp_executesql @sql, N'@id INT', @id = 100;

调试动态 SQL

动态 SQL 出错了不好调——你看到的只是一堆字符串拼接。

-- 在执行前先 PRINT 出来看看
PRINT @sql;
-- EXEC sp_executesql @sql, ...;

-- 或者用 RAISERROR 输出（PRINT 有 4000 字符限制）
RAISERROR(@sql, 0, 1) WITH NOWAIT;

安全清单

做法安全性
sp_executesql + 参数化值✅ 安全
QUOTENAME 包裹表名/列名✅ 安全
白名单验证表名/列名✅ 最安全
直接拼用户输入的值❌ 注入！
EXEC() 拼字符串❌ 危险
过滤单引号（替换 ' 为 ''）⚠️ 有漏洞，不可靠
