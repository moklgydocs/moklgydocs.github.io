性能篇：推拉结合的热重载方案

问题：改了数据库拿不到最新值

数据库配置和 appsettings.json 有一个本质区别：修改 JSON 文件时操作系统会发送文件变更事件通知程序，但在 Navicat / pgAdmin 里改了一条数据库记录，ASP.NET Core 应用完全不知情。

如果发现 IOptionsMonitor.CurrentValue 返回的还是旧值，问题一定出在刷新机制上。

方案一：API 按需触发（零延迟）

在 ConfigurationSource 里暴露 Provider 的引用，通过 API 接口触发 ReloadFromDatabase()。

// Program.cs
builder.Configuration.AddMokDatabaseConfiguration<SSODbContext>(out var dbConfigSource);
builder.Services.AddSingleton(dbConfigSource);

var app = builder.Build();

// 暴露刷新接口
app.MapPost("/api/system/config/refresh", 
    (EFConfigurationSource<SSODbContext> source) =>
{
    source.Provider.ReloadFromDatabase();
    return Results.Ok(new { message = "配置已从数据库重新加载" });
});

后台管理界面点"保存配置"时，顺手 POST 一下这个接口，下一微秒全网配置就生效了。

方案二：BackgroundService 定时轮询

如果不想依赖前端配合调接口，或者存在运维直接改库的场景，用后台定时任务兜底：

using Microsoft.Extensions.Hosting;
using Microsoft.Extensions.Logging;

namespace Mok.SqlFactory.Services
{
    public class DbConfigRefreshService<TContext> : BackgroundService 
        where TContext : Microsoft.EntityFrameworkCore.DbContext
    {
        private readonly EFConfigurationSource<TContext> _source;
        private readonly ILogger<DbConfigRefreshService<TContext>> _logger;
        private readonly TimeSpan _refreshInterval = TimeSpan.FromMinutes(1);

        public DbConfigRefreshService(
            EFConfigurationSource<TContext> source, 
            ILogger<DbConfigRefreshService<TContext>> logger)
        {
            _source = source;
            _logger = logger;
        }

        protected override async Task ExecuteAsync(CancellationToken stoppingToken)
        {
            _logger.LogInformation(
                "配置热重载服务已启动，轮询间隔: {interval}", 
                _refreshInterval);

            while (!stoppingToken.IsCancellationRequested)
            {
                try
                {
                    await Task.Delay(_refreshInterval, stoppingToken);
                    _source.Provider.ReloadFromDatabase();
                }
                catch (TaskCanceledException)
                {
                    break; // 系统正在关闭
                }
                catch (Exception ex)
                {
                    // 数据库短暂断连不能让后台任务崩溃
                    _logger.LogError(ex, "刷新数据库配置时发生错误");
                }
            }
        }
    }
}

注册时需要注意 DI 解析问题——EFConfigurationSource<TContext> 是在配置阶段创建的，不在 DI 容器的常规注册链路中。需要用工厂委托把已有的实例传进去：

// 在扩展方法内部
services.AddHostedService(sp => 
{
    var logger = sp.GetRequiredService<ILogger<DbConfigRefreshService<TContext>>>();
    return new DbConfigRefreshService<TContext>(configSource, logger);
});

推荐方案：推拉结合

单纯的轮询有延迟，单纯的 API 触发依赖前端配合。最佳实践是两者组合：

策略角色延迟说明
API 接口 /refresh主力（Push）0后台界面保存配置后立即调用
BackgroundService安全网（Pull）5 分钟兜底：防止有人直接改库不走界面
// 后台管理的保存接口
[HttpPost("save")]
public async Task<IActionResult> SaveConfig(ConfigDto dto)
{
    var setting = await _dbContext.AppSettings.FindAsync(dto.Id);
    setting.Value = dto.Value;
    await _dbContext.SaveChangesAsync();

    // 保存后立即触发热更新
    _configSource.Provider.ReloadFromDatabase();

    return Ok("保存并生效");
}

管理员在界面上点完保存，配置瞬间生效。定时器的轮询间隔反而可以拉长到 5 分钟，纯做兜底。

轮询间隔怎么定

app_settings 表通常只有几十到几百条数据。PostgreSQL 执行一次全表扫描耗时不到 1 毫秒。所以：

  • 10 秒：适合没有管理界面、运维直接改库的场景。对数据库压力约等于零。
  • 1 分钟：默认值，大多数场景够用。
  • 5 分钟：搭配 API 推送时作为安全网。

终极封装：一行代码搞定一切

把配置源注册、DbContext 注册、后台服务全部封装到一个扩展方法中：

namespace Mok.SqlFactory.Extensions
{
    public static class AppBuilderExtensions
    {
        public static IHostApplicationBuilder AddDefaultDbAndAppSettings<TContext>(
            this IHostApplicationBuilder builder)
            where TContext : DbContext
        {
            var dbContextType = typeof(TContext);
            var attribute = dbContextType.GetCustomAttribute<DefaultConnectionNameAttribute>();
            if (attribute == null)
                throw new InvalidOperationException(
                    $"{dbContextType.Name} 缺少 [DefaultConnectionName] 特性");

            var tempConfig = builder.Configuration.Build();
            var connectionString = tempConfig.GetConnectionString(attribute.ConnectionName);
            if (string.IsNullOrEmpty(connectionString))
                throw new ArgumentException(
                    $"未找到 ConnectionStrings:{attribute.ConnectionName}");

            var factory = DatabaseFactoryManager.GetFactory(attribute.DatabaseType);

            Action<DbContextOptionsBuilder> optionsAction = options =>
            {
                factory.Configure(options, connectionString);
            };

            // 阶段 A：接管配置系统
            var dbConfigSource = new EFConfigurationSource<TContext>(optionsAction);
            builder.Configuration.Add(dbConfigSource);

            // 阶段 B：接管依赖注入
            builder.Services.AddDbContext<TContext>(optionsAction);
            builder.Services.AddSingleton(dbConfigSource);

            builder.Services.AddHostedService(sp => 
            {
                var logger = sp.GetRequiredService<ILogger<DbConfigRefreshService<TContext>>>();
                return new DbConfigRefreshService<TContext>(dbConfigSource, logger);
            });

            return builder;
        }
    }
}

调用端 Program.cs 变成：

var builder = WebApplication.CreateBuilder(args);

// 一行搞定：加载数据库配置 + 注入 DbContext + 开启热更新轮询
builder.AddDefaultDbAndAppSettings<SSODbContext>();

// 注册业务 Options
builder.Services.AddDefaultOptions(builder.Configuration);

var app = builder.Build();
app.Run();

扩展的是 IHostApplicationBuilder（而非 WebApplicationBuilder），这样不管是 Web 项目还是纯后台 Worker Service，都能共用这套基础设施。
