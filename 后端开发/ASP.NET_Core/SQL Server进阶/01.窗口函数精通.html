窗口函数精通

第一章：窗口函数精通

窗口函数是 SQL 从"会用"到"精通"的分水岭。 掌握它，你的 SQL 表达能力直接跃升一个维度。

一、窗口函数 vs GROUP BY —— 本质区别

GROUP BY 的问题：
  SELECT DepartmentId, AVG(Salary) 
  FROM Employees 
  GROUP BY DepartmentId
  
  → 每个部门只有一行结果
  → 原始行被"压缩"了
  → 你看不到每个员工的信息了

窗口函数的优势：
  SELECT 
      EmployeeId, Name, DepartmentId, Salary,
      AVG(Salary) OVER(PARTITION BY DepartmentId) AS DeptAvgSalary
  FROM Employees
  
  → 每行结果都保留
  → 每行多了一个"部门平均工资"列
  → 既能看个体，又能看整体

┌──────────┬──────┬──────┬────────┬──────────────┐
│EmployeeId│ Name │ Dept │ Salary │ DeptAvgSalary│
├──────────┼──────┼──────┼────────┼──────────────┤
│ 1        │ 张三 │ IT   │ 15000  │ 13333        │
│ 2        │ 李四 │ IT   │ 12000  │ 13333        │
│ 3        │ 王五 │ IT   │ 13000  │ 13333        │
│ 4        │ 赵六 │ HR   │ 10000  │ 11000        │
│ 5        │ 钱七 │ HR   │ 12000  │ 11000        │
└──────────┴──────┴──────┴────────┴──────────────┘

每个人都在，同时能看到部门平均值 ✅

二、窗口函数语法框架

函数名([参数]) OVER (
    [PARTITION BY 分区列]        -- 按什么分组（不压缩行）
    [ORDER BY 排序列 [ASC|DESC]] -- 分区内排序
    [ROWS/RANGE 窗口范围]        -- 计算范围（帧）
)
语法拆解：

OVER()                    → 整张表作为一个窗口
OVER(PARTITION BY dept)   → 按部门分窗口
OVER(ORDER BY salary)     → 整表排序
OVER(PARTITION BY dept ORDER BY salary) → 部门内按薪资排序

窗口帧（frame）：
ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW   → 从分区起点到当前行
ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING            → 前一行到后一行
ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING → 整个分区

三、排名函数 —— 面试必考 TOP 3

3.1 ROW_NUMBER() —— 连续编号，无重复

-- 每个部门按薪资排名
SELECT 
    Name, DepartmentId, Salary,
    ROW_NUMBER() OVER(PARTITION BY DepartmentId ORDER BY Salary DESC) AS Rn
FROM Employees;
结果：
┌──────┬──────┬────────┬────┐
│ Name │ Dept │ Salary │ Rn │
├──────┼──────┼────────┼────┤
│ 张三 │ IT   │ 15000  │ 1  │ ← 即使相同薪资也不会重复
│ 王五 │ IT   │ 13000  │ 2  │
│ 李四 │ IT   │ 12000  │ 3  │
│ 钱七 │ HR   │ 12000  │ 1  │ ← 新分区重新编号
│ 赵六 │ HR   │ 10000  │ 2  │
└──────┴──────┴────────┴────┘

3.2 RANK() —— 有并列，有跳号

SELECT 
    Name, Salary,
    RANK() OVER(ORDER BY Salary DESC) AS Rnk
FROM Employees;
结果：
┌──────┬────────┬─────┐
│ Name │ Salary │ Rnk │
├──────┼────────┼─────┤
│ 张三 │ 15000  │ 1   │
│ 王五 │ 13000  │ 2   │
│ 李四 │ 12000  │ 3   │ ← 并列第3
│ 钱七 │ 12000  │ 3   │ ← 并列第3
│ 赵六 │ 10000  │ 5   │ ← 跳过了4！
└──────┴────────┴─────┘

3.3 DENSE_RANK() —— 有并列，不跳号

SELECT 
    Name, Salary,
    DENSE_RANK() OVER(ORDER BY Salary DESC) AS DRnk
FROM Employees;
结果：
┌──────┬────────┬──────┐
│ Name │ Salary │ DRnk │
├──────┼────────┼──────┤
│ 张三 │ 15000  │ 1    │
│ 王五 │ 13000  │ 2    │
│ 李四 │ 12000  │ 3    │ ← 并列第3
│ 钱七 │ 12000  │ 3    │ ← 并列第3
│ 赵六 │ 10000  │ 4    │ ← 紧接第4，不跳号
└──────┴────────┴──────┘

三者对比

                  相同值    跳号?    适用场景
ROW_NUMBER()     不并列     N/A     分页、去重、取第一条
RANK()           并列       是      竞赛排名（标准排名）
DENSE_RANK()     并列       否      薪资等级、成绩档次

面试经典题：每个部门薪资前3名？

SELECT * FROM (
    SELECT 
        Name, DepartmentId, Salary,
        DENSE_RANK() OVER(PARTITION BY DepartmentId ORDER BY Salary DESC) AS Rnk
    FROM Employees
) t
WHERE Rnk <= 3;

3.4 NTILE(N) —— 平均分桶

-- 把员工按薪资分成4组（四分位数）
SELECT 
    Name, Salary,
    NTILE(4) OVER(ORDER BY Salary) AS Quartile
FROM Employees;
结果：
┌──────┬────────┬──────────┐
│ Name │ Salary │ Quartile │
├──────┼────────┼──────────┤
│ 赵六 │ 10000  │ 1        │ ← 最低25%
│ 李四 │ 12000  │ 2        │
│ 钱七 │ 12000  │ 2        │
│ 王五 │ 13000  │ 3        │
│ 张三 │ 15000  │ 4        │ ← 最高25%
└──────┴────────┴──────────┘

场景：把用户分成高中低活跃度、销售额分档等

四、聚合窗口函数 —— 不压缩行的统计

4.1 SUM/AVG/COUNT/MAX/MIN OVER()

SELECT 
    Name, DepartmentId, Salary,
    
    -- 部门总薪资
    SUM(Salary) OVER(PARTITION BY DepartmentId) AS DeptTotal,
    
    -- 部门平均
    AVG(Salary) OVER(PARTITION BY DepartmentId) AS DeptAvg,
    
    -- 部门人数
    COUNT(*) OVER(PARTITION BY DepartmentId) AS DeptCount,
    
    -- 个人占部门比例
    CAST(Salary * 100.0 / SUM(Salary) OVER(PARTITION BY DepartmentId) AS DECIMAL(5,2)) 
        AS SalaryPercent,
    
    -- 全公司总薪资
    SUM(Salary) OVER() AS CompanyTotal

FROM Employees;
结果：
┌──────┬──────┬────────┬──────────┬─────────┬──────────┬──────────────┬──────────────┐
│ Name │ Dept │ Salary │ DeptTotal│ DeptAvg │ DeptCount│ SalaryPercent│ CompanyTotal │
├──────┼──────┼────────┼──────────┼─────────┼──────────┼──────────────┼──────────────┤
│ 张三 │ IT   │ 15000  │ 40000    │ 13333   │ 3        │ 37.50        │ 62000        │
│ 王五 │ IT   │ 13000  │ 40000    │ 13333   │ 3        │ 32.50        │ 62000        │
│ 李四 │ IT   │ 12000  │ 40000    │ 13333   │ 3        │ 30.00        │ 62000        │
│ 钱七 │ HR   │ 12000  │ 22000    │ 11000   │ 2        │ 54.55        │ 62000        │
│ 赵六 │ HR   │ 10000  │ 22000    │ 11000   │ 2        │ 45.45        │ 62000        │

-- 最近3天移动平均
SELECT

五、偏移函数 —— LAG / LEAD / FIRST_VALUE / LAST_VALUE

5.1 LAG() / LEAD() —— 看前一行 / 后一行

-- 环比分析：每日销售额与前一天对比
SELECT 
    OrderDate, Amount,
    LAG(Amount, 1, 0) OVER(ORDER BY OrderDate) AS PrevDayAmount,
    Amount - LAG(Amount, 1, 0) OVER(ORDER BY OrderDate) AS DayOverDay,
    LEAD(Amount, 1) OVER(ORDER BY OrderDate) AS NextDayAmount
FROM DailySales;
结果：
┌────────────┬────────┬───────────────┬────────────┬───────────────┐
│ OrderDate  │ Amount │ PrevDayAmount │ DayOverDay │ NextDayAmount │
├────────────┼────────┼───────────────┼────────────┼───────────────┤
│ 2024-01-01 │ 100    │ 0             │ 100        │ 200           │
│ 2024-01-02 │ 200    │ 100           │ 100        │ 150           │
│ 2024-01-03 │ 150    │ 200           │ -50        │ 300           │
│ 2024-01-04 │ 300    │ 150           │ 150        │ 250           │
│ 2024-01-05 │ 250    │ 300           │ -50        │ NULL          │
└────────────┴────────┴───────────────┴────────────┴───────────────┘

LAG(列, 偏移量, 默认值)  → 往前看
LEAD(列, 偏移量, 默认值) → 往后看

5.2 FIRST_VALUE() / LAST_VALUE()

-- 每个部门薪资最高和最低的人
SELECT 
    Name, DepartmentId, Salary,
    FIRST_VALUE(Name) OVER(
        PARTITION BY DepartmentId 
        ORDER BY Salary DESC
    ) AS HighestPaidName,
    LAST_VALUE(Name) OVER(
        PARTITION BY DepartmentId 
        ORDER BY Salary DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS LowestPaidName
FROM Employees;
⚠️ LAST_VALUE 陷阱：
默认窗口帧是 ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
所以 LAST_VALUE 默认只能看到"当前行"，不是分区最后一行！
必须显式设置 ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING

六、高频业务场景

场景1：分页 —— ROW_NUMBER 实现

-- 高性能分页（偏移量分页）
;WITH PagedData AS (
    SELECT 
        *, 
        ROW_NUMBER() OVER(ORDER BY CreatedAt DESC) AS RowNum
    FROM Orders
    WHERE Status = 'Completed'
)
SELECT * FROM PagedData
WHERE RowNum BETWEEN 21 AND 40;  -- 第2页，每页20条

-- SQL Server 2012+ 更简洁的写法
SELECT * FROM Orders
WHERE Status = 'Completed'
ORDER BY CreatedAt DESC
OFFSET 20 ROWS FETCH NEXT 20 ROWS ONLY;

场景2：每组取第一条（去重保留最新）

-- 每个用户最近一次订单
;WITH LatestOrders AS (
    SELECT 
        *,
        ROW_NUMBER() OVER(PARTITION BY UserId ORDER BY OrderDate DESC) AS Rn
    FROM Orders
)
SELECT * FROM LatestOrders WHERE Rn = 1;

场景3：连续登录天数

-- 找出连续登录3天以上的用户
;WITH LoginDays AS (
    SELECT DISTINCT UserId, CAST(LoginTime AS DATE) AS LoginDate
    FROM UserLogins
),
Groups AS (
    SELECT 
        UserId, LoginDate,
        -- 关键技巧：日期减去行号，连续的日期会得到相同的值
        DATEADD(DAY, -ROW_NUMBER() OVER(PARTITION BY UserId ORDER BY LoginDate), LoginDate) AS Grp
    FROM LoginDays
)
SELECT UserId, MIN(LoginDate) AS StartDate, MAX(LoginDate) AS EndDate,
       COUNT(*) AS ConsecutiveDays
FROM Groups
GROUP BY UserId, Grp
HAVING COUNT(*) >= 3
ORDER BY UserId, StartDate;
原理解析：

登录日期      ROW_NUMBER    日期 - 行号 = Grp
2024-01-01    1             2023-12-31
2024-01-02    2             2023-12-31  ← 相同！连续
2024-01-03    3             2023-12-31  ← 相同！连续
2024-01-05    4             2024-01-01  ← 不同！断开了
2024-01-06    5             2024-01-01  ← 相同！连续

按 Grp 分组后，COUNT >= 3 就是连续3天以上 ✅

场景4：累计占比（帕累托分析 / 80-20法则）

-- 找出贡献了80%销售额的TOP客户
;WITH CustomerSales AS (
    SELECT 
        CustomerId,
        SUM(Amount) AS TotalAmount
    FROM Orders
    GROUP BY CustomerId
),
Ranked AS (
    SELECT 
        CustomerId, TotalAmount,
        SUM(TotalAmount) OVER(ORDER BY TotalAmount DESC) AS RunningTotal,
        SUM(TotalAmount) OVER() AS GrandTotal
    FROM CustomerSales
)
SELECT 
    CustomerId, TotalAmount,
    CAST(RunningTotal * 100.0 / GrandTotal AS DECIMAL(5,2)) AS CumulativePercent
FROM Ranked
WHERE RunningTotal <= GrandTotal * 0.8 -- 前80%
   OR TotalAmount = (SELECT MIN(TotalAmount) FROM Ranked WHERE RunningTotal <= GrandTotal * 0.8);

场景5：同比环比分析

-- 月度销售同比环比
;WITH MonthlySales AS (
    SELECT 
        YEAR(OrderDate) AS Y,
        MONTH(OrderDate) AS M,
        SUM(Amount) AS MonthAmount
    FROM Orders
    GROUP BY YEAR(OrderDate), MONTH(OrderDate)
)
SELECT 
    Y, M, MonthAmount,
    
    -- 环比（上个月）
    LAG(MonthAmount, 1) OVER(ORDER BY Y, M) AS PrevMonth,
    CASE 
        WHEN LAG(MonthAmount, 1) OVER(ORDER BY Y, M) > 0 
        THEN CAST((MonthAmount - LAG(MonthAmount, 1) OVER(ORDER BY Y, M)) * 100.0 
             / LAG(MonthAmount, 1) OVER(ORDER BY Y, M) AS DECIMAL(5,2))
    END AS MoM_Percent,
    
    -- 同比（去年同月）
    LAG(MonthAmount, 12) OVER(ORDER BY Y, M) AS SameMonthLastYear,
    CASE 
        WHEN LAG(MonthAmount, 12) OVER(ORDER BY Y, M) > 0 
        THEN CAST((MonthAmount - LAG(MonthAmount, 12) OVER(ORDER BY Y, M)) * 100.0 
             / LAG(MonthAmount, 12) OVER(ORDER BY Y, M) AS DECIMAL(5,2))
    END AS YoY_Percent

FROM MonthlySales
ORDER BY Y, M;

七、窗口帧（Frame）详解

-- 窗口帧语法
ROWS BETWEEN <起点> AND <终点>

-- 起点/终点可以是：
UNBOUNDED PRECEDING    -- 分区第一行
N PRECEDING            -- 当前行前N行
CURRENT ROW            -- 当前行
N FOLLOWING            -- 当前行后N行
UNBOUNDED FOLLOWING    -- 分区最后一行
常见帧定义：

ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
  → 从分区起点到当前行（默认，累计计算）

ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
  → 整个分区（等价于不加ORDER BY的PARTITION BY）

ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
  → 前2行到当前行（3行移动窗口）

ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
  → 前1行到后1行（3行居中窗口）

ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
  → 当前行到分区末尾（反向累计）

ROWS vs RANGE 的区别

-- 有重复值时，ROWS 和 RANGE 行为不同

-- ROWS：物理行，精确控制
SUM(Salary) OVER(ORDER BY Salary ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
-- 严格按行计算，即使两行 Salary 相同也分别计算

-- RANGE：逻辑范围，相同值一起算
SUM(Salary) OVER(ORDER BY Salary RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
-- 相同 Salary 的行会一起包含进来

-- 💡 建议：除非你明确需要 RANGE 的语义，否则总是用 ROWS

八、递归 CTE —— 树形结构和序列生成

8.1 基本语法

;WITH RecursiveCTE AS (
    -- 锚定成员（起始条件）
    SELECT Id, Name, ParentId, 0 AS Level
    FROM Departments
    WHERE ParentId IS NULL
    
    UNION ALL
    
    -- 递归成员（循环条件）
    SELECT d.Id, d.Name, d.ParentId, r.Level + 1
    FROM Departments d
    INNER JOIN RecursiveCTE r ON d.ParentId = r.Id
)
SELECT * FROM RecursiveCTE
OPTION (MAXRECURSION 100);  -- 防止无限递归

8.2 生成日期序列

-- 生成2024年所有日期
;WITH DateSeries AS (
    SELECT CAST('2024-01-01' AS DATE) AS Dt
    UNION ALL
    SELECT DATEADD(DAY, 1, Dt)
    FROM DateSeries
    WHERE Dt < '2024-12-31'
)
SELECT Dt FROM DateSeries
OPTION (MAXRECURSION 366);

8.3 组织架构展开

;WITH OrgTree AS (
    SELECT Id, Name, ManagerId, 
           CAST(Name AS NVARCHAR(MAX)) AS OrgPath,
           0 AS Level
    FROM Employees
    WHERE ManagerId IS NULL  -- CEO
    
    UNION ALL
    
    SELECT e.Id, e.Name, e.ManagerId,
           CAST(t.OrgPath + ' > ' + e.Name AS NVARCHAR(MAX)),
           t.Level + 1
    FROM Employees e
    INNER JOIN OrgTree t ON e.ManagerId = t.Id
)
SELECT 
    REPLICATE('    ', Level) + Name AS OrgChart,
    OrgPath, Level
FROM OrgTree
ORDER BY OrgPath;

        总监王五
            经理赵六
            经理钱七
    VP刘总

九、面试高频题精选

题1：第二高薪资

-- 方法1：DENSE_RANK
SELECT DISTINCT Salary FROM (
    SELECT Salary, DENSE_RANK() OVER(ORDER BY Salary DESC) AS Rnk
    FROM Employees
) t WHERE Rnk = 2;

-- 方法2：子查询
SELECT MAX(Salary) FROM Employees
WHERE Salary < (SELECT MAX(Salary) FROM Employees);

-- 方法3：OFFSET
SELECT DISTINCT Salary FROM Employees
ORDER BY Salary DESC
OFFSET 1 ROWS FETCH NEXT 1 ROWS ONLY;

题2：部门薪资中位数

SELECT DepartmentId, AVG(Salary) AS MedianSalary
FROM (
    SELECT 
        DepartmentId, Salary,
        ROW_NUMBER() OVER(PARTITION BY DepartmentId ORDER BY Salary) AS Rn,
        COUNT(*) OVER(PARTITION BY DepartmentId) AS Cnt
    FROM Employees
) t
WHERE Rn IN (Cnt/2, Cnt/2 + 1, (Cnt+1)/2)
GROUP BY DepartmentId;

题3：找出连续3天销售额递增的日期段

;WITH DailySales AS (
    SELECT 
        SaleDate, Amount,
        LAG(Amount) OVER(ORDER BY SaleDate) AS PrevAmount,
        CASE 
            WHEN Amount > LAG(Amount) OVER(ORDER BY SaleDate) THEN 1 
            ELSE 0 
        END AS IsIncreasing
    FROM Sales
),
Groups AS (
    SELECT *,
        SUM(CASE WHEN IsIncreasing = 0 THEN 1 ELSE 0 END) 
            OVER(ORDER BY SaleDate) AS Grp
    FROM DailySales
)
SELECT Grp, MIN(SaleDate) AS StartDate, MAX(SaleDate) AS EndDate,
       COUNT(*) AS Days
FROM Groups
WHERE IsIncreasing = 1
GROUP BY Grp
HAVING COUNT(*) >= 2;  -- 至少连续2天递增 = 3天的序列

十、性能注意事项

窗口函数性能要点：

1. PARTITION BY 列建议有索引
   → 否则需要排序操作（Sort），大表很慢

2. ORDER BY 列建议有索引
   → 窗口函数内部需要排序

3. 最佳索引：覆盖索引
   CREATE INDEX IX_Dept_Salary ON Employees(DepartmentId, Salary)
   INCLUDE (Name)
   → PARTITION BY DepartmentId ORDER BY Salary 不需要额外排序

4. 避免在WHERE中直接使用窗口函数
   ❌ WHERE ROW_NUMBER() OVER(...) = 1
   ✅ 用子查询/CTE包装后再过滤

5. 多个窗口函数如果OVER()相同，引擎只排序一次
   → 尽量保持相同的 PARTITION BY + ORDER BY

6. ROWS 通常比 RANGE 性能好
   → ROWS 不需要处理"相同值"的逻辑

十一、窗口函数速查表

函数类型说明是否需要 ORDER BY
ROW_NUMBER()排名连续编号✅
RANK()排名并列跳号✅
DENSE_RANK()排名并列不跳号✅
NTILE(N)排名平均分N桶✅
SUM() OVER聚合求和可选
AVG() OVER聚合平均可选
COUNT() OVER聚合计数可选
MAX() OVER聚合最大值可选
MIN() OVER聚合最小值可选
LAG(col, n)偏移前第n行✅
LEAD(col, n)偏移后第n行✅
FIRST_VALUE()偏移窗口第一个值✅

PERCENT_RANK()分布百分比排名✅
