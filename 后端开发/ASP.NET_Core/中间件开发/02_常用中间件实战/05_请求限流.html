请求限流

请求限流

限流是保护系统不被突发流量击穿的核心手段。它不是拒绝用户，而是用可控的方式让系统在高负载下依然稳定运行。理解四种经典算法、掌握分布式实现、学会使用ASP.NET Core 7+内置限流，是构建高可用API的必备能力。

一、限流算法对比

1.1 固定窗口（Fixed Window）

将时间划分为固定长度的窗口（如每分钟），在每个窗口内统计请求数，超过阈值则拒绝。

时间轴（每分钟一个窗口）：

|--- 第1分钟 ---|--- 第2分钟 ---|--- 第3分钟 ---|
  100个请求 ✓     120个请求 ✗     80个请求 ✓
  (限制100)       (超限20个)      (限制100)

优点：实现简单，内存开销小
缺点：窗口边界处可能出现2倍突发流量

边界突发问题：

第1分钟末尾0.5秒：100个请求 ← 窗口内满额
第2分钟开头0.5秒：100个请求 ← 新窗口，又满额
→ 1秒内200个请求通过，2倍突发！

1.2 滑动窗口（Sliding Window）

不使用固定边界，而是统计"过去N秒"的请求数。滑动窗口解决了固定窗口的边界突发问题。

固定窗口：         滑动窗口：
|--- W1 ---|       |------ 当前时刻往前60秒 ------|
            |--- W2 ---|    任何时刻都看过去60秒

滑动窗口更平滑，无边界突发

优点：比固定窗口更平滑，无边界突发
缺点：需要记录每个请求的时间戳，内存开销较大

1.3 令牌桶（Token Bucket）

系统以固定速率向桶中放入令牌，桶有最大容量。每个请求需要取出一个令牌，桶空则拒绝。

        放入令牌（速率 r）
           ↓ ↓ ↓ ↓ ↓
       ┌─────────────┐
       │  ○ ○ ○ ○ ○  │  ← 桶中令牌（最多 b 个）
       │  ○ ○ ○      │
       └──────┬──────┘
              ↓
         请求取走令牌

关键特性：

  • 允许突发流量：桶满时可瞬间消耗所有令牌
  • 长期平均速率受控：令牌补充速率 r 决定长期吞吐
  • 参数：r（补充速率）、b（桶容量/突发容量）

1.4 漏桶（Leaky Bucket）

请求进入桶中排队，桶以固定速率"漏出"请求进行处理。桶满则新请求被拒绝。

        请求涌入（不均匀）
        ↓ ↓↓↓ ↓ ↓↓↓
       ┌─────────────┐
       │  █ █ █ █ █  │  ← 桶中排队的请求
       │  █ █ █      │
       └──────┬──────┘
              ↓ ↓ ↓ ↓ ↓  ← 匀速流出（固定速率）
           处理请求

与令牌桶的区别：

维度令牌桶漏桶
流出速率可突发恒定
突发能力允许（消耗积攒的令牌）不允许（匀速流出）
适用场景允许短时突发的API严格匀速的下游调用
核心思想控制平均速率控制绝对速率

二、令牌桶限流中间件实现

2.1 完整TokenBucket类

/// <summary>
/// 令牌桶限流器
/// </summary>
public class TokenBucket
{
    private readonly double _capacity;         // 桶容量（最大令牌数）
    private readonly double _refillRate;        // 令牌补充速率（个/秒）
    private double _tokens;                     // 当前令牌数
    private long _lastRefillTimestamp;          // 上次补充时间（Ticks）

    private readonly object _lock = new();

    /// <summary>
    /// 创建令牌桶
    /// </summary>
    /// <param name="capacity">桶容量（允许的最大突发量）</param>
    /// <param name="refillRate">令牌补充速率（个/秒）</param>
    public TokenBucket(double capacity, double refillRate)
    {
        if (capacity <= 0)
            throw new ArgumentOutOfRangeException(nameof(capacity));
        if (refillRate <= 0)
            throw new ArgumentOutOfRangeException(nameof(refillRate));

        _capacity = capacity;
        _refillRate = refillRate;
        _tokens = capacity;  // 初始满桶
        _lastRefillTimestamp = DateTime.UtcNow.Ticks;
    }

    /// <summary>
    /// 尝试消耗一个令牌
    /// </summary>
    public bool TryConsume(int tokensToConsume = 1)
    {
        lock (_lock)
        {
            Refill();

            if (_tokens >= tokensToConsume)
            {
                _tokens -= tokensToConsume;
                return true;
            }

            return false;
        }
    }

    /// <summary>
    /// 尝试消耗令牌，返回等待时间（如果需要等待）
    /// </summary>
    public (bool IsAllowed, TimeSpan? WaitTime) TryConsumeWithWaitTime(
        int tokensToConsume = 1)
    {
        lock (_lock)
        {
            Refill();

            if (_tokens >= tokensToConsume)
            {
                _tokens -= tokensToConsume;
                return (true, null);
            }

            // 计算需要等待多久才有足够令牌
            var deficit = tokensToConsume - _tokens;
            var waitSeconds = deficit / _refillRate;
            return (false, TimeSpan.FromSeconds(waitSeconds));
        }
    }

    /// <summary>
    /// 获取当前可用令牌数
    /// </summary>
    public double GetAvailableTokens()
    {
        lock (_lock)
        {
            Refill();
            return _tokens;
        }
    }

    /// <summary>
    /// 补充令牌（按时间流逝计算应补充的令牌数）
    /// </summary>
    private void Refill()
    {
        var now = DateTime.UtcNow.Ticks;
        var elapsedTicks = now - _lastRefillTimestamp;
        var elapsedSeconds = elapsedTicks / (double)TimeSpan.TicksPerSecond;

        var tokensToAdd = elapsedSeconds * _refillRate;
        _tokens = Math.Min(_capacity, _tokens + tokensToAdd);
        _lastRefillTimestamp = now;
    }
}

public class RateLimitOptions
{
    /// <summary>桶容量（最大突发请求数）</summary>
    public int Capacity { get; set; } = 100;

    /// <summary>令牌补充速率（个/秒）</summary>

    /// <summary>客户端识别策略</summary>
    public RateLimitIdentityStrategy IdentityStrategy { get; set; }
        = RateLimitIdentityStrategy.IpAddress;

    /// <summary>自定义客户端标识提取函数</summary>
    public Func<HttpContext, string>? CustomIdentifierExtractor { get; set; }

    /// <summary>排除的路径</summary>
    public List<string> ExcludedPaths { get; set; } = new()
    {
        "/health",
        "/metrics"
    };

    /// <summary>429响应消息</summary>
    public string RateLimitMessage { get; set; } =
        "Rate limit exceeded. Please try again later.";

    /// <summary>是否在响应头中返回限流信息</summary>
    public bool IncludeRateLimitHeaders { get; set; } = true;
}

2.4 完整中间件实现

/// <summary>
/// 令牌桶限流中间件
/// </summary>
public class TokenBucketRateLimitMiddleware
{
    private readonly RequestDelegate _next;
    private readonly RateLimitOptions _options;
    private readonly ConcurrentDictionary<string, TokenBucket> _buckets = new();
    private readonly ILogger<TokenBucketRateLimitMiddleware> _logger;

    public TokenBucketRateLimitMiddleware(
        RequestDelegate next,
        IOptions<RateLimitOptions> options,
        ILogger<TokenBucketRateLimitMiddleware> logger)
    {
        _next = next;
        _options = options.Value;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 检查排除路径
        if (IsExcludedPath(context.Request.Path))
        {
            await _next(context);
            return;
        }

        // 获取客户端标识
        var identifier = GetIdentifier(context);

        // 获取或创建令牌桶
        var bucket = _buckets.GetOrAdd(identifier,
            _ => new TokenBucket(_options.Capacity, _options.RefillRate));

        // 尝试消耗令牌
        var (isAllowed, waitTime) = bucket.TryConsumeWithWaitTime();

        // 设置限流响应头
        if (_options.IncludeRateLimitHeaders)
        {
            var available = bucket.GetAvailableTokens();
            context.Response.Headers["X-RateLimit-Limit"] =
                _options.Capacity.ToString();
            context.Response.Headers["X-RateLimit-Remaining"] =
                ((int)available).ToString();
        }

        if (!isAllowed)
        {
            _logger.LogWarning(
                "限流：客户端 {Identifier} 被限流，{Method} {Path}，" +
                "需等待 {WaitMs}ms",
                identifier, context.Request.Method,
                context.Request.Path,
                waitTime?.TotalMilliseconds);

            context.Response.StatusCode =
                StatusCodes.Status429TooManyRequests;

            if (waitTime.HasValue)
            {
                context.Response.Headers["Retry-After"] =
                    ((int)waitTime.Value.TotalSeconds).ToString();
            }

            await Write429Response(context, waitTime);
            return;
        }

        await _next(context);
    }

    /// <summary>
    /// 获取客户端标识
    /// </summary>
    private string GetIdentifier(HttpContext context)
    {
        // 自定义提取函数优先
        if (_options.CustomIdentifierExtractor != null)
        {
            return _options.CustomIdentifierExtractor(context);
        }

        return _options.IdentityStrategy switch
        {
            RateLimitIdentityStrategy.IpAddress =>
                GetClientIp(context),
            RateLimitIdentityStrategy.UserId =>
                context.User?.FindFirst(ClaimTypes.NameIdentifier)?.Value
                    ?? GetClientIp(context),
            RateLimitIdentityStrategy.ApiKey =>
                context.Request.Headers["X-API-Key"].FirstOrDefault()
                    ?? context.Request.Query["api_key"].FirstOrDefault()
                    ?? GetClientIp(context),
            RateLimitIdentityStrategy.IpAndPath =>
                $"{GetClientIp(context)}:{context.Request.Path}",
            RateLimitIdentityStrategy.Global =>
                "__global__",
            _ => GetClientIp(context)
        };
    }

    private static string GetClientIp(HttpContext context)
    {
        var forwardedFor = context.Request.Headers["X-Forwarded-For"]
            .FirstOrDefault();
        if (!string.IsNullOrEmpty(forwardedFor))
        {
            return forwardedFor.Split(',').First().Trim();
        }
        return context.Connection.RemoteIpAddress?.ToString() ?? "unknown";
    }

    /// <summary>
    /// 写入429响应
    /// </summary>
    private async Task Write429Response(HttpContext context, TimeSpan? waitTime)
    {
        context.Response.ContentType = "application/json";

        var response = new
        {
            status = 429,
            message = _options.RateLimitMessage,
            retryAfterSeconds = waitTime.HasValue
                ? (int)waitTime.Value.TotalSeconds
                : (int?)null
        };

        await context.Response.WriteAsJsonAsync(response);
    }

    private bool IsExcludedPath(PathString path)
    {
        return _options.ExcludedPaths.Any(excluded =>
            path.StartsWithSegments(excluded, StringComparison.OrdinalIgnoreCase));
    }
}

/// <summary>
/// 限流中间件扩展
/// </summary>
public static class RateLimitMiddlewareExtensions
{
    public static IApplicationBuilder UseTokenBucketRateLimit(
        this IApplicationBuilder app,
        Action<RateLimitOptions>? configure = null)
    {
        var options = new RateLimitOptions();
        configure?.Invoke(options);

        return app.UseMiddleware<TokenBucketRateLimitMiddleware>(
            Options.Create(options));
    }
}

三、分布式限流

单机内存限流在多实例部署时失效——每个实例各有限流器，总通过量是 N 倍。分布式限流用 Redis 作为共享存储，所有实例共用一个计数器。

3.1 Redis + Lua脚本实现

Lua脚本在Redis中原子执行，避免竞态条件：

/// <summary>
/// Redis分布式限流器
/// </summary>
public class RedisRateLimiter
{
    private readonly IConnectionMultiplexer _redis;
    private readonly ILogger<RedisRateLimiter> _logger;

    public RedisRateLimiter(
        IConnectionMultiplexer redis,
        ILogger<RedisRateLimiter> logger)
    {
        _redis = redis;
        _logger = logger;
    }
}

3.2 固定窗口Redis实现

/// <summary>
/// Redis固定窗口限流
/// </summary>
public class RedisFixedWindowRateLimiter : RedisRateLimiter
{
    // Lua脚本：原子性地递增计数器并检查是否超限
    // KEYS[1] = 限流Key
    // ARGV[1] = 窗口大小（秒）
    // ARGV[2] = 限制数量
    private const string Script = @"
        local current = redis.call('INCR', KEYS[1])
        if current == 1 then
            redis.call('EXPIRE', KEYS[1], ARGV[1])
        end
        if current > tonumber(ARGV[2]) then
            return 0
        end
        return 1
    ";

    public RedisFixedWindowRateLimiter(
        IConnectionMultiplexer redis,
        ILogger<RedisFixedWindowRateLimiter> logger)
        : base(redis, logger)
    {
    }

    /// <summary>
    /// 固定窗口限流检查
    /// </summary>
    /// <param name="identifier">客户端标识</param>
    /// <param name="windowSeconds">窗口大小（秒）</param>
    /// <param name="limit">窗口内最大请求数</param>
    public async Task<bool> IsAllowedAsync(
        string identifier, int windowSeconds, int limit)
    {
        var db = _redis.GetDatabase();
        var key = $"ratelimit:fixed:{identifier}:{DateTimeOffset.UtcNow.ToUnixTimeSeconds() / windowSeconds}";

        var result = (int)await db.ScriptEvaluateAsync(
            Script,
            new RedisKey[] { key },
            new RedisValue[] { windowSeconds, limit });

        return result == 1;
    }
}

3.3 滑动窗口Redis实现

滑动窗口用 Sorted Set 存储，每个请求的时间戳作为 score：

/// <summary>
/// Redis滑动窗口限流
/// </summary>
public class RedisSlidingWindowRateLimiter : RedisRateLimiter
{
    // KEYS[1] = 限流Key (Sorted Set)
    // ARGV[1] = 窗口起始时间戳
    // ARGV[2] = 当前时间戳
    // ARGV[3] = 限制数量
    // ARGV[4] = 过期时间（秒）
    private const string Script = @"
        -- 移除窗口外的旧记录
        redis.call('ZREMRANGEBYSCORE', KEYS[1], '-inf', ARGV[1])

        -- 统计当前窗口内的请求数
        local count = redis.call('ZCARD', KEYS[1])

        if count >= tonumber(ARGV[3]) then
            return 0
        end

        -- 添加当前请求
        redis.call('ZADD', KEYS[1], ARGV[2], ARGV[2] .. ':' .. math.random(1000000))

        -- 设置过期时间，自动清理
        redis.call('EXPIRE', KEYS[1], ARGV[4])

        return 1
    ";

    public RedisSlidingWindowRateLimiter(
        IConnectionMultiplexer redis,
        ILogger<RedisSlidingWindowRateLimiter> logger)
        : base(redis, logger)
    {
    }

    /// <summary>
    /// 滑动窗口限流检查
    /// </summary>
    /// <param name="identifier">客户端标识</param>
    /// <param name="windowSeconds">窗口大小（秒）</param>
    /// <param name="limit">窗口内最大请求数</param>
    public async Task<bool> IsAllowedAsync(
        string identifier, int windowSeconds, int limit)
    {
        var db = _redis.GetDatabase();
        var key = $"ratelimit:sliding:{identifier}";
        var now = DateTimeOffset.UtcNow.ToUnixTimeMilliseconds();
        var windowStart = now - (windowSeconds * 1000L);

        var result = (int)await db.ScriptEvaluateAsync(
            Script,
            new RedisKey[] { key },
            new RedisValue[]
            {
                windowStart,      // ARGV[1]: 窗口起始
                now,              // ARGV[2]: 当前时间
                limit,            // ARGV[3]: 限制数量
                windowSeconds + 1 // ARGV[4]: 过期时间
            });

        return result == 1;
    }
}

3.4 分布式限流中间件

/// <summary>
/// Redis分布式限流中间件
/// </summary>
public class RedisRateLimitMiddleware
{
    private readonly RequestDelegate _next;
    private readonly RedisFixedWindowRateLimiter _fixedWindowLimiter;
    private readonly RateLimitOptions _options;
    private readonly ILogger<RedisRateLimitMiddleware> _logger;

    public RedisRateLimitMiddleware(
        RequestDelegate next,
        RedisFixedWindowRateLimiter fixedWindowLimiter,
        IOptions<RateLimitOptions> options,
        ILogger<RedisRateLimitMiddleware> logger)
    {
        _next = next;
        _fixedWindowLimiter = fixedWindowLimiter;
        _options = options.Value;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        if (IsExcludedPath(context.Request.Path))
        {
            await _next(context);
            return;
        }

        var identifier = GetIdentifier(context);
        var isAllowed = await _fixedWindowLimiter.IsAllowedAsync(
            identifier, windowSeconds: 60, limit: _options.Capacity);

        if (!isAllowed)
        {
            _logger.LogWarning("分布式限流：{Identifier} 被限流", identifier);

            context.Response.StatusCode = StatusCodes.Status429TooManyRequests;
            context.Response.Headers["Retry-After"] = "60";
            await context.Response.WriteAsJsonAsync(new
            {
                status = 429,
                message = "Rate limit exceeded"
            });
            return;
        }

        await _next(context);
    }

    private string GetIdentifier(HttpContext context) =>
        context.Connection.RemoteIpAddress?.ToString() ?? "unknown";

    private bool IsExcludedPath(PathString path) =>
        _options.ExcludedPaths.Any(p =>
            path.StartsWithSegments(p, StringComparison.OrdinalIgnoreCase));
}

四、ASP.NET Core 7+内置限流

ASP.NET Core 7 引入了 Microsoft.AspNetCore.RateLimiting 中间件，内置支持四种限流算法。

4.1 服务注册

// Program.cs
builder.Services.AddRateLimiter(options =>
{
    // 全局限流配置
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        context => RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? "unknown",
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 100,
                Window = TimeSpan.FromMinutes(1),
                QueueProcessingOrder = QueueProcessingOrder.OldestFirst,
                QueueLimit = 0
            }));

    // 定义命名策略
    options.AddFixedWindowLimiter("fixed", opt =>
    {
        opt.PermitLimit = 100;
        opt.Window = TimeSpan.FromMinutes(1);
        opt.QueueLimit = 0;
    });

    options.AddSlidingWindowLimiter("sliding", opt =>
    {
        opt.PermitLimit = 100;
        opt.Window = TimeSpan.FromMinutes(1);
        opt.SegmentsPerWindow = 6;  // 10秒一个分段
        opt.QueueLimit = 0;
    });

    options.AddTokenBucketLimiter("token-bucket", opt =>
    {
        opt.TokenLimit = 200;
        opt.ReplenishmentPeriod = TimeSpan.FromSeconds(1);
        opt.TokensPerPeriod = 20;
        opt.QueueLimit = 0;
    });

    options.AddConcurrencyLimiter("concurrency", opt =>
    {
        opt.PermitLimit = 10;
        opt.QueueLimit = 5;
        opt.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
    });

    // 429响应自定义
    options.OnRejected = async (context, cancellationToken) =>
    {
        context.HttpContext.Response.StatusCode = StatusCodes.Status429TooManyRequests;
        context.HttpContext.Response.ContentType = "application/json";

        var retryAfter = context.Lease.TryGet(
            MetadataName.RetryAfter, out var retry)
            ? retry.TotalSeconds
            : 60;

        await context.HttpContext.Response.WriteAsJsonAsync(new
        {
            status = 429,
            message = "请求频率超限，请稍后重试",
            retryAfterSeconds = (int)retryAfter
        }, cancellationToken: cancellationToken);
    };
});

4.2 固定窗口限流

// 注册策略
options.AddFixedWindowLimiter("api-general", opt =>
{
    opt.PermitLimit = 60;                       // 每分钟60个请求
    opt.Window = TimeSpan.FromMinutes(1);
    opt.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
    opt.QueueLimit = 10;                        // 排队10个
});

固定窗口是最简单的限流算法。PermitLimit 是窗口内允许的最大请求数，Window 是时间窗口长度。QueueLimit 设置大于0时，超限请求会排队等待而不是直接拒绝。

4.3 滑动窗口限流

options.AddSlidingWindowLimiter("api-smooth", opt =>
{
    opt.PermitLimit = 60;                       // 每分钟60个请求
    opt.Window = TimeSpan.FromMinutes(1);
    opt.SegmentsPerWindow = 6;                  // 分6段，每段10秒
    opt.QueueLimit = 0;
});

SegmentsPerWindow 将窗口分成多个段。值为6时，每段10秒，窗口以10秒为单位滑动，比固定窗口更平滑。段数越多越精确，但内存开销也越大。

4.4 令牌桶限流

options.AddTokenBucketLimiter("api-burst", opt =>
{
    opt.TokenLimit = 200;                       // 桶容量200
    opt.ReplenishmentPeriod = TimeSpan.FromSeconds(1);  // 每秒补充
    opt.TokensPerPeriod = 20;                   // 每秒补充20个
    opt.QueueLimit = 0;
});

令牌桶允许突发——桶满时可以瞬间消耗200个令牌，但长期平均速率受 TokensPerPeriod / ReplenishmentPeriod 控制。上面的配置允许突发200个请求，长期平均每秒20个。

4.5 并发限流

options.AddConcurrencyLimiter("api-concurrent", opt =>
{
    opt.PermitLimit = 10;                       // 最多10个并发请求
    opt.QueueLimit = 20;                        // 排队等待20个
    opt.QueueProcessingOrder = QueueProcessingOrder.OldestFirst;
});

并发限流不关注时间窗口，只关注"同时有多少请求正在处理"。适用于保护下游服务（如数据库连接数、外部API并发数）。

4.6 全局限流 vs 端点限流

全局限流：所有请求共享限流策略

builder.Services.AddRateLimiter(options =>
{
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        context => RateLimitPartition.GetFixedWindowLimiter(
            partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? "global",
            factory: _ => new FixedWindowRateLimiterOptions
            {
                PermitLimit = 100,
                Window = TimeSpan.FromMinutes(1)
            }));
});

端点限流：只在特定端点上启用

// 方式1：在Minimal API上使用
app.MapGet("/api/weather", () => Results.Ok(weatherData))
   .RequireRateLimiting("api-burst");

// 方式2：在Controller上使用特性
[HttpGet]
[EnableRateLimiting("api-burst")]
public async Task<IActionResult> GetWeather() { ... }

// 方式3：全局启用，特定端点禁用
[HttpGet("/health")]
[DisableRateLimiting]
public IActionResult Health() => Ok();

4.7 自定义限流策略

基于分区（Partition）的限流策略，可以根据请求特征动态选择限流参数：

builder.Services.AddRateLimiter(options =>
{
    options.GlobalLimiter = PartitionedRateLimiter.Create<HttpContext, string>(
        context =>
        {
            // VIP用户：更高限额
            var clientId = context.User?.FindFirst("client_id")?.Value;
            if (!string.IsNullOrEmpty(clientId))
            {
                if (IsVipClient(clientId))
                {
                    return RateLimitPartition.GetTokenBucketLimiter(
                        partitionKey: $"vip:{clientId}",
                        factory: _ => new TokenBucketRateLimiterOptions
                        {
                            TokenLimit = 500,
                            ReplenishmentPeriod = TimeSpan.FromSeconds(1),
                            TokensPerPeriod = 50
                        });
                }

                // 普通认证用户
                return RateLimitPartition.GetTokenBucketLimiter(
                    partitionKey: $"user:{clientId}",
                    factory: _ => new TokenBucketRateLimiterOptions
                    {
                        TokenLimit = 100,
                        ReplenishmentPeriod = TimeSpan.FromSeconds(1),
                        TokensPerPeriod = 10
                    });
            }

            // 未认证用户：最严格限制
            return RateLimitPartition.GetFixedWindowLimiter(
                partitionKey: context.Connection.RemoteIpAddress?.ToString() ?? "anonymous",
                factory: _ => new FixedWindowRateLimiterOptions
                {
                    PermitLimit = 20,
                    Window = TimeSpan.FromMinutes(1)
                });
        });
});

4.8 注册中间件

var app = builder.Build();

// 限流中间件应在路由之后、授权之前注册
app.UseRateLimiter();

// 或者更精确的位置
app.UseRouting();
app.UseRateLimiter();
app.UseAuthorization();
app.MapControllers();
app.Run();

4.9 内置限流 vs 自定义实现对比

维度ASP.NET Core内置自定义中间件Redis分布式
多实例支持不支持（进程内）不支持支持
算法种类固定/滑动/令牌桶/并发自定义固定/滑动
配置方式代码/特性代码/配置文件代码/配置
端点级控制[EnableRateLimiting]需手动实现需手动实现
分区策略PartitionedRateLimiter需手动实现需手动实现
性能最优（无网络开销）优一般（Redis RTT）
一致性最终一致（各实例独立）最终一致强一致
适用场景单实例/无严格限流需要完全控制多实例严格限流

选择建议：

  • 单实例部署 → 使用内置限流
  • 多实例部署、限流要求不严格 → 使用内置限流（各实例独立计数，总量约为 N × limit）
  • 多实例部署、限流要求严格 → 使用Redis分布式限流
  • 需要自定义算法 → 自定义中间件
