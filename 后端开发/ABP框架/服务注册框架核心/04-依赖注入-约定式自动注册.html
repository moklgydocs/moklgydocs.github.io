依赖注入 - 约定式自动注册

04 - 依赖注入：约定式自动注册

本章讲解 MokFramework 的约定式依赖注入系统——如何让框架自动发现和注册服务，
免去手动 services.AddXxx<IService, Implementation>() 的繁琐工作。

设计思路

在一个大型项目中，可能有数十甚至数百个服务需要注册到 DI 容器。
传统做法是在 Program.cs 或某个启动类中逐一注册，不仅枯燥，还容易遗漏。

MokFramework 提供了三种注册方式（按优先级）：

优先级方式适用场景
最高[Dependency] 特性需要精确控制生命周期/注册行为
中标记接口 (ITransientDependency 等)最常用，一行搞定
最低手动注册不符合约定的特殊服务

第一步：定义标记接口

三个空接口，分别对应 DI 的三种生命周期：

// 文件：MokFramework.Core/DependencyInjection/ITransientDependency.cs
public interface ITransientDependency { }

// 文件：MokFramework.Core/DependencyInjection/ISingletonDependency.cs
public interface ISingletonDependency { }

// 文件：MokFramework.Core/DependencyInjection/IScopedDependency.cs
public interface IScopedDependency { }

使用示例：

// 实现 ITransientDependency → 自动注册为 Transient
public class GreetingService : IGreetingService, ITransientDependency
{
    public string Greet(string name) => $"Hello, {name}!";
}

第二步：定义 DI 特性

对于需要更精细控制的场景，提供 [Dependency] 和 [ExposeServices] 特性。

DependencyAttribute

// 文件：MokFramework.Core/DependencyInjection/DependencyAttribute.cs

[AttributeUsage(AttributeTargets.Class)]
public class DependencyAttribute : Attribute
{
    /// <summary>
    /// 生命周期：Transient / Scoped / Singleton
    /// </summary>
    public ServiceLifetime Lifetime { get; set; }

    /// <summary>
    /// 是否使用 TryAdd（如果已注册则不覆盖）
    /// </summary>
    public bool TryRegister { get; set; }

    /// <summary>
    /// 是否替换已有的注册
    /// </summary>
    public bool ReplaceServices { get; set; }

    public DependencyAttribute(ServiceLifetime lifetime = ServiceLifetime.Transient)
    {
        Lifetime = lifetime;
    }
}

三种注册语义：

// 1. 默认 Add — 总是添加（可能产生多个注册）
[Dependency(ServiceLifetime.Scoped)]
public class OrderService : IOrderService { }
// → services.AddScoped<IOrderService, OrderService>()

// 2. TryAdd — 只在没有注册过时才添加
[Dependency(ServiceLifetime.Scoped, TryRegister = true)]
public class DefaultOrderService : IOrderService { }
// → services.TryAddScoped<IOrderService, DefaultOrderService>()

// 3. Replace — 替换已有的注册
[Dependency(ServiceLifetime.Scoped, ReplaceServices = true)]
public class CustomOrderService : IOrderService { }
// → services.Replace(ServiceDescriptor.Scoped<IOrderService, CustomOrderService>())

ExposeServicesAttribute

控制一个类暴露为哪些服务类型：

// 文件：MokFramework.Core/DependencyInjection/ExposeServicesAttribute.cs

[AttributeUsage(AttributeTargets.Class)]
public class ExposeServicesAttribute : Attribute
{
    /// <summary>
    /// 显式指定的服务类型
    /// </summary>
    public Type[] ServiceTypes { get; }

    /// <summary>
    /// 是否包含实现类自身（默认 true）
    /// </summary>
    public bool IncludeSelf { get; set; } = true;

    /// <summary>
    /// 是否同时包含约定发现的接口（默认 false）
    /// </summary>
    public bool IncludeDefaults { get; set; } = false;
}

使用示例：

// 只暴露 IOrderService 和 OrderService 自身
// 即使实现了 IOrderQuery，也不会注册 IOrderQuery
[ExposeServices(typeof(IOrderService), IncludeSelf = true)]
public class OrderService : IOrderService, IOrderQuery { }
// → services.AddXxx<IOrderService, OrderService>()
// → services.AddXxx<OrderService>()
// ❌ 不会注册 IOrderQuery → OrderService

第三步：实现约定注册器

ConventionalRegistrar 是整个 DI 系统的引擎，负责扫描程序集并自动注册服务。

整体流程

ConventionalRegistrar.RegisterAssembly(assembly, services)
│
├── 遍历程序集中所有 public 类型
│   ├── 跳过：抽象类、接口、泛型定义、静态类
│   └── 对每个有效类型调用 RegisterType()
│
└── RegisterType(type, services)
    ├── 1. GetLifetimeOrNull(type) → 确定生命周期
    │   ├── [Dependency] 特性 → 使用指定的 Lifetime        (最高优先)
    │   ├── ITransientDependency → Transient               (次高)
    │   ├── ISingletonDependency → Singleton               (次高)
    │   ├── IScopedDependency → Scoped                     (次高)
    │   └── 都不满足 → null → 跳过此类型                    (不注册)
    │
    ├── 2. GetServiceTypes(type) → 确定暴露的服务类型
    │   ├── [ExposeServices] 特性 → 使用指定的 ServiceTypes  (最高优先)
    │   └── 约定匹配 → I{ClassName} 接口 + 自身类型          (默认)
    │
    └── 3. 注册到 DI 容器
        ├── 对每个服务类型创建 ServiceDescriptor
        └── 根据 TryRegister / ReplaceServices 选择注册方式

核心代码解析

确定生命周期

private static ServiceLifetime? GetLifetimeOrNull(Type type)
{
    // 优先级 1：[Dependency] 特性
    var attr = type.GetCustomAttribute<DependencyAttribute>();
    if (attr != null)
        return attr.Lifetime;

    // 优先级 2：标记接口
    if (typeof(ITransientDependency).IsAssignableFrom(type))
        return ServiceLifetime.Transient;

    if (typeof(ISingletonDependency).IsAssignableFrom(type))
        return ServiceLifetime.Singleton;

    if (typeof(IScopedDependency).IsAssignableFrom(type))
        return ServiceLifetime.Scoped;

    // 不参与自动注册
    return null;
}

确定服务类型

private static List<Type> GetServiceTypes(Type type)
{
    // 优先级 1：[ExposeServices] 特性
    var exposeAttr = type.GetCustomAttribute<ExposeServicesAttribute>();
    if (exposeAttr != null)
    {
        var types = new List<Type>(exposeAttr.ServiceTypes);

        if (exposeAttr.IncludeSelf)
            types.Add(type);

        if (exposeAttr.IncludeDefaults)
            AddDefaultInterfaces(type, types);

        return types;
    }

    // 优先级 2：约定匹配 + 自身类型
    var serviceTypes = new List<Type> { type };  // 总是注册自身
    AddDefaultInterfaces(type, serviceTypes);
    return serviceTypes;
}

I{ClassName} 约定匹配

这是最有趣的部分——如何自动找到一个类对应的服务接口。

private static void AddDefaultInterfaces(Type type, List<Type> serviceTypes)
{
    // 遍历类实现的所有接口
    foreach (var iface in type.GetInterfaces())
    {
        // 跳过标记接口
        if (iface == typeof(ITransientDependency) ||
            iface == typeof(ISingletonDependency) ||
            iface == typeof(IScopedDependency))
            continue;

        // 跳过系统接口
        if (iface.Namespace?.StartsWith("System") == true)
            continue;

        // 核心约定：接口名 == "I" + 类名
        if (iface.Name == $"I{type.Name}")
        {
            if (!serviceTypes.Contains(iface))
                serviceTypes.Add(iface);
        }
    }
}

匹配示例：

类名接口匹配？原因
GreetingServiceIGreetingService✅"I" + "GreetingService" == "IGreetingService"
GreetingServiceITransientDependency❌是标记接口，跳过
GreetingServiceIDisposable❌System 命名空间，跳过
OrderServiceIOrderQuery❌"I" + "OrderService" != "IOrderQuery"

注册到容器

private static void RegisterType(Type type, IServiceCollection services)
{
    var lifetime = GetLifetimeOrNull(type);
    if (lifetime == null) return;  // 不参与自动注册

    var serviceTypes = GetServiceTypes(type);
    var depAttr = type.GetCustomAttribute<DependencyAttribute>();

    foreach (var serviceType in serviceTypes)
    {
        var descriptor = new ServiceDescriptor(serviceType, type, lifetime.Value);

        if (depAttr?.ReplaceServices == true)
        {
            // 替换模式：移除旧的，添加新的
            services.Replace(descriptor);
        }
        else if (depAttr?.TryRegister == true)
        {
            // 尝试模式：已存在则不添加
            services.TryAdd(descriptor);
        }
        else
        {
            // 默认模式：总是添加
            services.Add(descriptor);
        }
    }
}

实际注册效果

场景 1：标记接口

public class GreetingService : IGreetingService, ITransientDependency { }

注册结果：

services.AddTransient<IGreetingService, GreetingService>();  // I{ClassName} 匹配
services.AddTransient<GreetingService>();                     // 自身类型

场景 2：[Dependency] + [ExposeServices]

[Dependency(ServiceLifetime.Scoped)]
[ExposeServices(typeof(IOrderService), IncludeSelf = true)]
public class OrderService : IOrderService { }

注册结果：

services.AddScoped<IOrderService, OrderService>();  // ExposeServices 指定
services.AddScoped<OrderService>();                  // IncludeSelf = true

场景 3：只有标记接口，没有匹配的 I

public class BackgroundWorker : ISingletonDependency { }
// 没有 IBackgroundWorker 接口

注册结果：

services.AddSingleton<BackgroundWorker>();  // 只注册自身

ConventionalRegistrar 在模块生命周期中的位置

ConfigureModuleServicesAsync()
│
├── Phase 2: ConfigureServices
│   ├── ★ ConventionalRegistrar.RegisterAssembly(Module.GetType().Assembly)
│   │   └── 扫描模块所在程序集，自动注册服务
│   ├── Module.ConfigureServicesAsync()
│   │   └── 模块可以覆盖/补充约定注册
│   └── (下一个模块重复以上步骤)

关键：ConventionalRegistrar 在每个模块的 ConfigureServices 之前执行。

这意味着：

  • 约定注册先完成
  • 模块可以在 ConfigureServices 中用 Replace 替换约定注册的服务
  • 这给了模块完全的控制权
