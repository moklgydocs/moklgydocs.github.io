常量加载

常量加载

核心要点

常量加载指令是 IL 中最基础的指令族，用于将各种类型的常量值压入求值栈。掌握 ldc、ldstr、ldnull、ldtoken 是理解所有 IL 代码的基础。

一、ldc —— 数值常量加载

ldc（Load Constant）系列指令将数值常量压入求值栈。

1.1 ldc.i4 —— 32 位整数

ldc.i4 有多种编码形式，从最短的 1 字节到最长的 6 字节：

指令操作码字节大小加载的值说明
ldc.i4.m10x151-1特殊值，常用于表示 -1
ldc.i4.00x1610
ldc.i4.10x1711
ldc.i4.20x1812
ldc.i4.30x1913
ldc.i4.40x1A14
ldc.i4.50x1B15
ldc.i4.60x1C16
ldc.i4.70x1D17
ldc.i4.80x1E18
ldc.i4.s0x1F2-128 ~ 127短格式，1 字节有符号操作数
ldc.i40x205-2^31 ~ 2^31-1完整格式，4 字节有符号操作数

编码优化

ldc.i4.0 到 ldc.i4.8 是快捷指令（Short Form），仅占 1 字节。ldc.i4.s 占 2 字节，ldc.i4 占 5 字节。C# 编译器会自动选择最短编码：

  • 值 -1 到 8：使用 1 字节快捷指令
  • 值 -128 到 127（超出快捷范围）：使用 ldc.i4.s（2 字节）
  • 其他值：使用 ldc.i4（5 字节）

这是 IL 编码优化最直观的例子——常用值用更短的编码。

1.2 ldc.i8 —— 64 位整数

指令操作码字节大小加载的值
ldc.i80x219-2^63 ~ 2^63-1

ldc.i8 后跟 8 字节有符号整数操作数，共占 9 字节。

1.3 ldc.r4 与 ldc.r8 —— 浮点数

指令操作码字节大小加载的值
ldc.r40x22532 位浮点数（float）
ldc.r80x23964 位浮点数（double）

1.4 ldc 全家福

指令类型字节大小C# 类型
ldc.i4.m1int321int (-1)
ldc.i4.0 ~ ldc.i4.8int321int (0-8)

没有 ldc.u 系列

IL 没有无符号整数的专用加载指令。uint、ulong 等无符号类型使用与有符号相同的 ldc.i4 / ldc.i8 指令加载，区别在于类型的使用方式（如 conv.u4、conv.u8 等转换指令）。

二、ldstr —— 字符串常量加载

ldstr 从程序集的元数据中加载字符串字面量，将其压入求值栈。

2.1 基本用法

// C# 源码
string greeting = "Hello, World!";
// IL 代码
IL_0000: ldstr        "Hello, World!"   // 从元数据 #US 堆加载字符串
IL_0005: stloc.0                         // 存入局部变量

2.2 求值栈状态

执行前：  [ ]
执行后：  [ "Hello, World!" ]    ← 栈顶是字符串对象引用

2.3 驻留（Interning）

字符串驻留

ldstr 不会每次创建新的字符串对象。CLR 维护一个字符串驻留池（Intern Pool），相同内容的字符串字面量在运行时指向同一个 string 对象。

string a = "hello";
string b = "hello";
// a 和 b 引用同一个对象（因为 ldstr 检查驻留池）
Console.WriteLine(ReferenceEquals(a, b)); // True

这是 ldstr 的特殊行为，不同于 new string(...) 或字符串拼接的结果。

三、ldnull —— 加载 null 引用

ldnull 将一个 null 引用压入求值栈。

3.1 基本用法

// C# 源码
string name = null;
// IL 代码
IL_0000: ldnull          // 压入 null 引用
IL_0001: stloc.0         // 存入局部变量

3.2 求值栈状态

执行前：  [ ]
执行后：  [ null ]    ← 栈顶是 null 引用

3.3 ldnull 的常见用途

// 初始化引用类型为 null
string s = null;

// 条件赋值
string result = flag ? "yes" : null;

// 方法参数传递
ProcessData(null);

ldnull 与 ldc.i4.0

ldnull 压入的是 null 引用（O 类型，对象引用），ldc.i4.0 压入的是整数 0（I4 类型）。虽然底层都是 0，但类型语义不同。CLR 验证器不允许将 null 当整数使用，反之亦然。

四、ldtoken —— 加载元数据标记

ldtoken 将元数据标记（Type/Method/Field）对应的运行时表示压入求值栈，用于实现 typeof()、nameof() 等反射操作。

4.1 typeof 的 IL 实现

// C# 源码
Type t = typeof(string);
// IL 代码
IL_0000: ldtoken       [mscorlib]System.String    // 加载 System.String 的元数据标记
IL_0005: call          class [mscorlib]System.Type [mscorlib]System.Type::GetTypeFromHandle(
                                                       valuetype [mscorlib]System.RuntimeTypeHandle)
IL_000a: stloc.0

4.2 求值栈状态

执行 ldtoken 后：  [ RuntimeTypeHandle ]    ← 元数据标记的运行时句柄
执行 call 后：     [ Type ]                 ← 转换为 Type 对象

4.3 ldtoken 的三种用法

加载目标栈上类型C# 用法
类型RuntimeTypeHandle → Typetypeof(T)
方法RuntimeMethodHandle → MethodInfo反射获取方法
字段RuntimeFieldHandle → FieldInfo反射获取字段

4.4 nameof 的 IL 实现

// C# 源码
string name = nameof(Console.WriteLine);
// IL 代码
IL_0000: ldtoken       void [mscorlib]System.Console::WriteLine(string)
IL_0005: call          class [mscorlib]System.Reflection.MethodBase
                       [mscorlib]System.Reflection.MethodBase::GetMethodFromHandle(
                           valuetype [mscorlib]System.RuntimeMethodHandle)
IL_000a: callvirt      instance string [mscorlib]System.Reflection.MemberInfo::get_Name()
IL_000f: stloc.0

nameof 的编译期 vs 运行期

nameof 在 C# 7+ 中已优化为编译期常量字符串，不再需要 ldtoken + 反射调用。但早期版本中 nameof 确实通过 ldtoken 实现。如果你在旧版本 .NET 中看到 nameof 产生了反射调用，这就是原因。

五、完整示例：常量加载对比

// C# 源码
public class Constants
{
    public void Demo()
    {
        int i = 42;
        long l = 123456789L;
        float f = 3.14f;
        double d = 2.718281828;
        string s = "Hello";
        object o = null;
        Type t = typeof(int);
    }
}
// IL 反编译输出（带求值栈状态注释）
.method public hidebysig instance void Demo() cil managed
{
    .maxstack 1
    .locals init (
        int32 i,      // V_0
        int64 l,      // V_1
        float32 f,    // V_2
        float64 d,    // V_3
        string s,     // V_4
        object o,     // V_5
        class [mscorlib]System.Type t  // V_6
    )

    // int i = 42;
    IL_0000: ldc.i4.s     42            // [ 42 ]
    IL_0002: stloc.0                     // [ ]

    // long l = 123456789L;
    IL_0003: ldc.i8       123456789     // [ 123456789L ]
    IL_000c: stloc.1                     // [ ]

    // float f = 3.14f;
    IL_000d: ldc.r4       3.14          // [ 3.14f ]
    IL_0012: stloc.2                     // [ ]

    // double d = 2.718281828;
    IL_0013: ldc.r8       2.718281828   // [ 2.718281828 ]
    IL_001c: stloc.3                     // [ ]

    // string s = "Hello";
    IL_001d: ldstr        "Hello"       // [ "Hello" ]
    IL_0022: stloc.s      s             // [ ]

    // object o = null;
    IL_0024: ldnull                      // [ null ]
    IL_0025: stloc.s      o             // [ ]

    // Type t = typeof(int);
    IL_0027: ldtoken      [mscorlib]System.Int32   // [ RuntimeTypeHandle ]
    IL_002c: call         class [mscorlib]System.Type
                       [mscorlib]System.Type::GetTypeFromHandle(
                           valuetype [mscorlib]System.RuntimeTypeHandle)
                                              // [ Type ]
    IL_0031: stloc.s      t             // [ ]

    IL_0033: ret
}

六、求值栈状态追踪

让我们追踪一个稍复杂的表达式：

// C# 源码
int result = 10 + 20 * 3;
// IL 代码 + 求值栈状态
//                                     求值栈
IL_0000: ldc.i4.s     10        //    [ 10 ]
IL_0002: ldc.i4.s     20        //    [ 10, 20 ]
IL_0004: ldc.i4.3               //    [ 10, 20, 3 ]
IL_0005: mul                    //    [ 10, 60 ]         ← 20 * 3 = 60
IL_0006: add                    //    [ 70 ]             ← 10 + 60 = 70
IL_0007: stloc.0                //    [ ]                ← result = 70

运算顺序

IL 是"后缀"形式（类似逆波兰表达式），操作数在前，运算符在后。这正适合栈式机器——先把操作数压栈，再执行运算。C# 的运算优先级在编译时已经处理为正确的 IL 指令顺序。

面试技巧

面试常考

  1. "ldc.i4.0 和 ldc.i4.s 0 有什么区别？" —— 结果相同，但编码不同。ldc.i4.0 是 1 字节快捷指令（操作码 0x16），ldc.i4.s 0 是 2 字节（操作码 0x1F + 0x00）。编译器优先使用快捷指令以减小代码体积。
  2. "为什么 IL 要为 0-8 设计专用指令？" —— 这些是最常用的整数值（循环索引、布尔值、数组访问等），1 字节编码相比 ldc.i4 的 5 字节编码节省大量空间，对频繁出现的小整数效果显著。
  3. "ldstr 加载的字符串是否每次都创建新对象？" —— 不是。ldstr 使用字符串驻留池，相同内容的字符串字面量指向同一个对象。这是 CLR 的优化。
  4. "ldnull 和 ldc.i4.0 的区别？" —— 类型语义不同。ldnull 压入的是 O 类型（对象引用），ldc.i4.0 压入的是 I4 类型（32位整数）。CLR 验证器不允许混淆使用。
  5. "typeof(T) 在 IL 中是如何实现的？" —— ldtoken T 加载类型的运行时句柄（RuntimeTypeHandle），然后调用 Type.GetTypeFromHandle() 转换为 Type 对象。
  6. "ldc.i4.m1 加载的是 -1，有什么实际用途？" —— 常用于表示"未找到"的返回值（如 Array.IndexOf 返回 -1），以及枚举中的特殊值。m1 = minus one。
