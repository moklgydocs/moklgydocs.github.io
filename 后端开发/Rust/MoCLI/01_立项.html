MoCLI · 01 项目立项

MoCLI · 项目立项文档

角色：【PM】主导

一、项目背景

Mo 的后端服务每天产生大量结构化 JSON 日志（每台服务器约 10GB/天），运维团队需要从中查找错误、统计异常频率、导出 CSV 报告给研发分析。

现状痛点：

  • 用 grep 过滤速度可以，但无法处理 JSON 结构化字段
  • Python 脚本读取 1GB 文件时内存占用 > 2GB（全量加载）
  • 没有标准的输出格式，报告格式五花八门

为什么用 Rust：这是 Phase 2 的过渡项目。CLI 工具不需要异步，但要处理大文件 + 高性能，恰好是 Rust 所有权 + 迭代器的理想练习场景。

二、用户故事（User Story）

作为 Mo 后端运维，我需要一个命令行工具，能从 GB 级 JSON 日志文件中，按时间范围和错误级别过滤，统计错误频率，并导出 CSV 报告，以便在不超过 50MB 内存的情况下快速得到分析结果。

三、验收标准（Acceptance Criteria）

AC1：mo-cli --help 显示所有参数及说明
AC2：能流式处理 1GB 日志文件，内存占用全程 < 50MB（不一次性加载）
AC3：支持 --level error|warn|info 过滤日志级别
AC4：支持 --from 2024-01-01T00:00:00 --to 2024-01-02T00:00:00 时间段过滤
AC5：输出 CSV 报告（--output report.csv）包含：时间、级别、消息、计数
AC6：使用 rayon 并行处理时，速度 > 单线程 2x（criterion benchmark 测试）
AC7：cargo test 全绿，cargo clippy --deny warnings 零警告

四、项目目标与范围

目标

不在本项目范围内

  • 不支持网络日志采集（仅读本地文件）
  • 不需要 GUI 界面
  • 不需要实时日志监控（tail -f 模式）

五、技术选型决策

方案理由
clap derive 模式 ✅代码即文档，自动生成 --help，类比 System.CommandLine
serde + serde_json ✅事实标准，编译时派生，零运行时开销
rayon ✅数据并行只需 .par_iter()，类比 PLINQ
anyhow ✅简化错误处理，快速原型，error context 友好
criterion ✅统计正确的 benchmark，比 std::time::Instant 准确
actix-web ❌本项目是 CLI，不需要 Web

六、风险识别

风险可能性影响缓解措施
日志格式非标准 JSON中高每行解析失败时跳过并计数，最后报告解析失败行数
rayon 并行：共享状态竞争低中用 Mutex<HashMap> 或分片后合并，避免全局锁
内存超限（50MB）低高逐行读取，不缓存原始行，统计用 HashMap 而非 Vec
