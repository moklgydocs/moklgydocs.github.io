STaR、V-STaR、Quiet-STaR——自学成才的推理

最小的自我改进循环,就住在推理过程(rationale)里:模型生成一条思维链,留下那些最终答对的,拿它们微调。这就是 STaR。V-STaR 加一个验证器,让推理时的挑选更准;Quiet-STaR 把推理过程压到每个 token 上。三者都有效,但没有一个是魔法——这个循环会保留任何碰巧走到正确答案的捷径。

类型: 学习
编程语言: Python(标准库,自举循环模拟器)
前置要求: 第 13 阶段 · 01-03(推理与思维链),第 15 阶段 · 01(长程框架)
预计耗时: 约 60 分钟

问题

教模型推理,最直接的办法是收集人写的推理轨迹。这又贵又慢,而且上限就是人类愿意写多少高质量思维链。

STaR(Self-Taught Reasoner,Zelikman 等人,2022)问:如果让模型自己写推理过程,再对着已知答案打分呢?循环是:

  1. 采样一条推理轨迹加答案。
  2. 最终答案正确,就保留这条轨迹。
  3. 在保留的轨迹上微调。
  4. 重复。

它有效。GSM8K 和 CommonsenseQA 都有提升,而且不需要新的人工标注。但这个循环有个内建偏差:只要走出正确答案,推理过程就被保留——不管推理本身是否靠谱。V-STaR(Hosseini 等人,2024)用一个学习的验证器补上这个洞;Quiet-STaR(Zelikman 等人,2024)则把这个思想推广到逐 token 的内部推理。

概念

STaR:在有效的东西上自举

从一个推理能力薄弱的基座模型开始。对每个训练题,采样一条推理加答案。答案与标签一致,就保留(问题, 推理, 答案)三元组。在保留集上微调。重复。

有一个细节要紧:如果模型某题永远答不对,循环在它身上就学不到东西。STaR 为此加了合理化(rationalization):对模型失败的题,把正确答案作为提示注入,重新 prompt 模型产出一条通往该答案的推理。合理化得来的推理也加进训练集。

原论文结果(Zelikman 等人,2022):GPT-J 基座模型经多轮带合理化的 STaR,GSM8K 从 5.8% 升到 10.7%,约 5 个百分点的绝对提升。CommonsenseQA 上,STaR 训练的 GPT-J 6B 达到 72.5%,与微调过的 GPT-3 175B(约 73%)相当——那是一个大约 30 倍大、用手工标注推理训练的模型。

V-STaR:用 DPO 训练验证器

STaR 把错误推理全扔了。Hosseini 等人(2024)发现那也是数据:每一对(推理, "这对不对")都能训练一个验证器。他们用 DPO 在正确与错误解答上构建排序器。推理时采样 N 条推理,取验证器排序最高的那条。

报告的增量:在 GSM8K 和 MATH 上,比此前的自我改进基线高 +4 到 +17 个百分点,且大部分增益来自用验证器做推理时挑选,而不是对生成器做更多微调。

Quiet-STaR:逐 token 的内部推理

Zelikman 等人(2024)问:如果模型学会在每个 token 位置生成一小段内部推理,而不只是在问题与答案之间呢?Quiet-STaR 训练模型在每个待预测 token 前发出一段隐藏的"想法",再用一个学习的权重,把"带想法的预测"与基线预测混合。

结果:Mistral 7B 在零样本下,GSM8K 从 5.9% 升到 10.9%,CommonsenseQA 从 36.3% 升到 47.2%,全程没有任务相关微调。模型学会了"何时思考"——难的 token 得到更长的内部推理,容易的几乎没有。

为什么三者共享同一个安全隐患

三种方法都把最终答案当作梯度信号。一条经由错误推理走到正确答案的推理——利用捷径、靠猜、或用不能泛化的模式——会被正向强化。分布内的问题上,捷径有效;分布外,它无声地断掉。

V-STaR 的验证器通过学习给推理排序来缓解,但验证器本身也是在同一套标签上训的。它可能学会偏爱"格式漂亮的错误推理"而不是"诚实的不确定"。更安全的设计是把 STaR 式数据与以下两者结合:(a) 过程监督奖励模型(奖励中间步骤,而不只是答案);(b) 能打破简单捷径的留出 OOD 评估。

对比

方法训练信号推理成本数据浪费已知失败模式
STaR答对才留(推理, 答案)1x丢弃全部错误推理捷径推理
STaR + 合理化同上 + 提示正确答案的重试1x较少合理化推理可能不自然
V-STaRSTaR + 双类样本 DPO 验证器Nx(best-of-N)极少验证器可能强化"自信的错误"
Quiet-STaR逐 token 推理 + 混合权重1.5-3x极少仍是答案条件化的梯度

在 2026 年技术栈中的位置

STaR 老了。但这个模式在 2025–2026 年到处复活。可验证数学问题上的 RL(DeepSeek-R1、Kimi-k1.5、o1),就是规模化之后的 STaR 答案条件化梯度信号。过程奖励模型(Lightman 等人,2023;OpenAI 的 "Let's verify step by step")是过程监督的替代方案。AlphaEvolve(第 3 课)是代码版 STaR,只不过标签换成了程序评估器。Darwin Godel Machine(第 4 课)则是作用在智能体脚手架本身上的 STaR。

理解了 STaR,这些全都一点就通。它是最小可行的自我改进循环。

reflection-loop

投入使用

code/main.py 在玩具算术任务上跑一个模拟 STaR 循环。你可以看到:

  • 准确率如何随自举轮次攀升。
  • 捷径如何溜进来:模拟器内置一类"偷懒"推理,40% 的时候蒙对答案,但泛化很差。看 STaR 会不会留下它们。
  • 验证器(V-STaR 式)在推理时有帮助,但无法完全剪掉训练期引入的捷径。

交付

outputs/skill-star-loop-reviewer.md 帮你在投入训练之前,审计一条自学推理流水线的提案。

练习

  1. 运行模拟器。把捷径频率分别设为 0 和 0.4。两次运行在训练分布上都超过 90%,但最终准确率差多少?

  2. 给模拟器加一个留出 OOD 测试。从不同的分布出题,在分布内和 OOD 集合上分别评估自举后的模型,量化差距。

  3. 读 Quiet-STaR 论文(arXiv:2403.09629)第 3 节。各用三句话解释"end-of-thought" token 和混合权重头。

  4. 对比 STaR 的"答对才留"过滤器和"逐步独立奖励推理"的过程监督替代方案。指出标注成本差异与可能的质量差异。

  5. 设计一个能抓住部署模型中捷径推理的评估。不必完美——只要能打破 STaR 循环会强化的最简单捷径。

关键术语

术语人们常说的实际含义
STaR"自学推理器"在产出正确答案的模型自产推理上微调;重复
合理化(Rationalization)"带提示的重试"对基座模型失败的题,注入正确答案后重新 prompt 出推理
V-STaR"验证器 STaR"在正确与错误推理上用 DPO 训验证器,推理时用它挑选
Quiet-STaR"逐 token 推理"在每个 token 位置生成隐藏想法,与基线预测混合
答案条件化梯度"结果导向信号"训练循环奖励最终答案,而不是推理步骤
过程奖励模型"步骤级验证器"在逐步正确性上训练的奖励模型,不看结果——与 STaR 相对
捷径推理(Shortcut rationale)"答案对,推理错"经由不可泛化模式走到标签的推理;STaR 会保留它们
