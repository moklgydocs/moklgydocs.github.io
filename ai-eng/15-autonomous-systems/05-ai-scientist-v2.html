AI Scientist v2——workshop 级的自治研究

Sakana 的 AI Scientist v2(Yamada 等人,arXiv:2504.08066)跑通完整的研究循环:假设、代码、实验、图表、写作、投稿。它是第一个让生成的论文通过 ICLR 2025 workshop 同行评审的系统。独立评估(Beel 等人)则发现:42% 的实验因代码错误失败,文献综述频繁把已有概念错标为原创。Sakana 自己的文档也警告:这套代码库会执行 LLM 写的代码,建议用 Docker 隔离。这幅图的两半,都是重点。

类型: 学习
编程语言: Python(标准库,研究循环状态机玩具)
前置要求: 第 15 阶段 · 03(AlphaEvolve),第 15 阶段 · 04(DGM)
预计耗时: 约 60 分钟

问题

研究是开放式任务。与 AlphaEvolve 的算法搜索或 DGM 的基准限定自我修改不同,研究成果没有机器可检验的正确性标准。论文由评审人评判,不是单元测试。这让循环更难闭合——但闭合了也更值钱,因为复利式的进步就活在研究里。

AI Scientist v1(Sakana,2024)从人工撰写的模板出发来闭合循环:LLM 在固定脚手架里填实验。AI Scientist v2(Yamada 等人,2025)则通过带视觉-语言模型评审循环的智能体式树搜索,去掉了模板要求。系统生成想法、实现实验、产出图表、写论文,并按评审意见迭代。

同行评审的结论:一篇 v2 生成的论文被 ICLR 2025 workshop 接收(已披露来源)。独立评估的结论:这套系统远谈不上可靠。两个都成立。

概念

架构

  1. 想法生成。 LLM 按主题和已有文献提出研究想法。v1 用模板;v2 在假设空间上做智能体搜索。
  2. 新颖性检查。 文献检索步骤检查想法是否已发表。Beel 等人评估中发现错标的正是这一步——成熟方法频繁被判定为原创。
  3. 实验计划。 智能体起草实验方案并写代码。
  4. 执行。 代码在沙箱中运行,失败喂回重试循环。Beel 等人的测量中,42% 的实验在这一步因代码错误失败。
  5. 图表生成。 视觉-语言模型阅读生成的图,并重绘得更清晰。这是 v2 的关键技术新增。
  6. 写作。 LLM 起草论文,与内部评审器迭代。
  7. 可选:投稿。 论文投给会议。

workshop 接收意味着什么

一篇 v2 生成的论文通过了 ICLR 2025 workshop 的同行评审,作者向程序委员会披露了论文来源。这次接收是一个数据点,不是宣称系统"会做研究"的许可证。

重要的背景:workshop 论文的门槛低于主会论文;同行评审本身噪声很大,任何一天都有一部分投稿被接收。一次成功是概念验证,不是可靠性声明。2026 年那篇 Nature 论文记录了端到端循环,但它本身由人类研究者合著——不是"系统写了篇 Nature"。

独立评估发现了什么

Beel 等人(arXiv:2502.14297)做了外部评估。头条发现:

  • 实验失败。 42% 的实验因代码错误失败(import 错误、形状不匹配、未定义变量)。重试循环抓住一部分,没抓住全部。
  • 新颖性错标。 文献检索步骤频繁把已有概念标为原创。这是研究版的幻觉。
  • 呈现质量落差。 视觉-语言的图表评审产出了出版级的视觉效果,把底层的实验缺陷遮住了。

最后一条对本阶段最重要。一个产出"令人信服的输出"却没做"令人信服的研究"的系统,比一个明显失败的系统更危险,而不是更安全。评估必须打到底层主张,不能停在图上。

沙箱逃逸之忧

Sakana 自己的仓库 README 警告:

由于本软件会执行 LLM 生成的代码,我们无法保证安全。存在危险包、不受控的网络访问和意外进程派生的风险。请自担风险使用,并考虑 Docker 隔离。

这就是未验证领域中自治的运行形态:LLM 写代码,代码被执行,代码能做进程被允许做的任何事。没有一个硬性限制文件系统、网络和进程动作的沙箱,任何自我导向的研究智能体都可能外泄数据、烧光算力,或改写自己。

AlphaEvolve 的沙箱故事好讲,因为它的评估器很紧。AI Scientist v2 的循环跑的是开放式代码、开放式目标。这就是为什么它需要更强的隔离(Docker 起步;seccomp / gVisor 更佳),以及每一份产出离开系统前的人工评审。

v2 在前沿技术栈中的位置

系统目标产出形态评估器已知失败
AlphaEvolve算法代码单测 + 基准受评估器严苛度所限
DGM智能体脚手架代码SWE-bench奖励黑客
AI Scientist v2研究论文文本 + 代码 + 图同行评审(弱)实验失败、错标、美化掩盖缺陷

三者之中,v2 的自动评估器最弱、输出面最宽、产出物到公众的路径最短。安全工作的大头,是运行控制(沙箱、评审、披露)在扛。

mx-research-loop

投入使用

code/main.py 把 v2 循环模拟成一个状态机:想法 → 新颖性检查 → 实验 → 图表 → 写作 → 评审 → 接收或迭代。每个状态的可配置失败概率取自 Beel 等人的发现。跑 N 轮循环,数一数:

  • 多少想法走到了投稿。
  • 多少投稿带着"被美化论文遮住的关键实验缺陷"。
  • 重试预算如何在质量与产出率之间权衡。

交付

outputs/skill-ai-scientist-sandbox-review.md 是一份双闸门评审清单:研究循环智能体产出的任何东西,离开沙箱前都要过它。

练习

  1. 用默认参数运行 code/main.py。多大比例的循环产出"干净"的论文?多大比例产出"实验有缺陷但被图表评审美化过去"的论文?

  2. 默认值用的就是 Beel 等人的 42% / 25%。分别用 --experiment-failure 0.20 --novelty-mislabel 0.10 和 --experiment-failure 0.60 --novelty-mislabel 0.40 重跑。两次运行中,"美化但有缺陷"的比例如何移动?

  3. 读 Sakana 的 AI Scientist v2 仓库 README 中关于沙箱要求的部分。对一次多日自治运行,说出你会在 Docker 之外再加的两条限制。

  4. 读 Beel 等人第 4 节"呈现质量落差"部分。设计一个能抓住"看起来漂亮但实验有缺陷"论文的补充评估器。

  5. 为研究智能体的产出设计一套比"博士读每篇论文"更可扩展的人工评审协议。找出瓶颈,绕着它设计。
