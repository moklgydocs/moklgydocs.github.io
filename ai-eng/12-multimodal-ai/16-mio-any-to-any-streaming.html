MIO 与任意到任意的流式多模态模型

GPT-4o 交付了一个多数开放模型复制不了的产品:一个能听语音、看视频、实时开口回答的智能体。到 2024 年底,开放生态给出的答案是 MIO(Wang et al., 2024 年 9 月)。MIO 把文本、图像、语音、音乐都分词,在交错序列上训练一个因果 Transformer,实现任意模态到任意模态的生成。AnyGPT(Zhan et al., 2024 年 2 月)是概念验证,MIO 是规模化;Unified-IO 2(Allen AI, 2023 年 12 月)是带视觉+动作定位的表亲。本课精读任意到任意模式——四个分词器、一个 Transformer、流式友好的解码。

类型: 学习
编程语言: Python(标准库,四模态 token 分配器 + 流式解码循环)
前置要求: 第 12 阶段第 11 课(Chameleon)、第 6 阶段(语音与音频)
预计耗时: 约 120 分钟

学习目标

  • 设计一个能装下文本、图像、语音、音乐 token 而不撞车的共享词表。
  • 从压缩与重建的权衡,对比 SEED-Tokenizer(图像)与 SpeechTokenizer 残差 VQ(语音)。
  • 解释逐步构建任意到任意生成的四阶段课程。
  • 说出三个开放的任意到任意配方及其主要取舍:MIO、AnyGPT、Unified-IO 2。

问题

统一多模态模型,号称容易,规模化难建。2024 年之前,多数"任意到任意"系统是拼接的:视觉模型 → 文本表示 → 语音模型 → 音频。每一跳都丢信息、加延迟、复杂化训练。GPT-4o 的演示视频展示了亚秒响应的单模型方案;开放系统落后数月。

工程挑战:

  • 每种模态都要有分词器,压缩要到"重建够用"的程度,产出 token 的速率还得是 Transformer 吃得下的。
  • 单一词表要分配空间给文本(3.2 万+)、图像(1.6 万+)、语音(4 千+)、音乐(8 千+),至少四万多个条目。
  • 训练数据要么覆盖每一种输入-输出配对(文→图、图→语音、语音→图……),要么靠模型自己组合。
  • 推理输出 token 必须够快,撑得起对话延迟(首个音频字节 <500ms)。

概念

四个分词器,四种模态

MIO 的分词器栈:

  • 文本: 标准 BPE,词表约 32000。
  • 图像: SEED-Tokenizer(2023)——带离散码本的量化 VAE,4096 条目,每图 32x32 个 token。
  • 语音: SpeechTokenizer 残差 VQ(2023)——把 16kHz 波形编码进 8 层层级码本;第 1 层是粗略内容,后面各层补韵律与说话人身份。
  • 音乐: 类似的残差 VQ(Meta 的 MusicGen / Encodec 家族),4–8 层码本。

每种模态产出整数 token。token 在共享词表中占不相交的 ID 段:

text:   0..31999
image:  32000..36095  (4096 image tokens)
speech: 36096..40191  (4096 speech base tokens, plus residual layers)
music:  40192..48383  (8192 music tokens)
sep:    48384..48390  (<image>, <speech>, <music>, </...>, etc.)

总计约 4.8 万词表。输入嵌入与输出投影覆盖全部。

流式解码

语音生成用残差 VQ。Transformer 预测基础(第 0 层)语音 token;并行解码的残差量化器预测后续各层。16kHz 下,每个第 0 层 token 约对应 50ms 音频。

流式模式:

  1. 用户对麦克风说话;实时音频分词器每 50ms 吐出语音 token。
  2. MIO 边收边消费(prompt prefill + 增量前向)。
  3. 输出 token 边生成边流出;并行语音解码器把它们转成音频采样,延迟约 50–150ms。
  4. 首个音频字节时间:MIO 论文约 300–500ms,逼近 GPT-4o 的约 250ms。

Mini-Omni(arXiv:2408.16725)、GLM-4-Voice(arXiv:2412.02612)和 Moshi(arXiv:2410.00037)是互补的流式语音-LLM 设计。Moshi 尤其做到了单 GPU 上 160ms 往返。

四阶段课程

MIO 的训练课程:

  1. 第 1 阶段 —— 对齐。 大规模模态对语料:文-图、文-语音、文-音乐。每对用自己词表段,训练共享词表。
  2. 第 2 阶段 —— 交错。 多模态交错文档(带图带视频的博客、带转录的播客等)。训练跨模态上下文。
  3. 第 3 阶段 —— 语音增强。 额外音频数据,在不损失文本能力的前提下提升语音质量。
  4. 第 4 阶段 —— SFT。 跨模态指令微调:VQA、描述、解说、语音到语音对话。

缺一个阶段就退化特定能力:跳过第 2 阶段丢跨模态上下文;跳过第 3 阶段语音就差。

视觉思维链(chain-of-visual-thought)

MIO 提出视觉思维链:模型把中间图像 token 作为推理步骤吐出来。对"猫在爬树吗?"这个问题,模型:

  1. 吐出 <image> token,渲染场景(来自输入图或一幅草图)。
  2. 吐出分析草图的文本。
  3. 吐出最终答案。

渲染出的中间图像充当草稿纸。空间推理任务上基准提升。这个思路镜像了文本推理的思维链。

任意到任意的竞争者们

  • AnyGPT(arXiv:2402.12226):4 种模态(文本、图像、语音、音乐),设计相似。
  • Unified-IO 2(arXiv:2312.17172):加视觉动作输出、深度、法线。任务更多样,规模更小。
  • NExT-GPT(arXiv:2309.05519):LLM + 模态专属扩解散码器。不是单模型路线。
  • CoDi(arXiv:2305.11846):可组合扩散;经共享潜在空间做任意到任意。

MIO 是最接近纯 token 任意到任意的;AnyGPT 是它的概念祖先。

延迟预算

对话产品的每个组件延迟都要紧:

  • 麦克风到音频 token:约 50ms。
  • Prefill(音频 token + 历史):8B 模型约 100ms。
  • 首个输出 token:约 50ms。
  • 并行残差 VQ + 语音解码器:约 100–150ms。

首个音频字节总时间:至少约 300ms。GPT-4o 宣称约 250ms,Moshi 宣称 160ms。公开基准上 MIO/AnyGPT 在 400–600ms 区间。

为什么任意到任意仍然难

即使到 2026 年,开放的任意到任意模型在两根轴上仍落后闭源:

  • 语音质量。 残差 VQ 分词器有损;对话语音听起来比 ElevenLabs 级声音机械。
  • 跨模态推理。 让模型"把你看到的唱出来",失败率仍远高于纯视觉任务。

这些是开放研究问题。Qwen3-Omni(第 12.20 课)是 2025 年最先进的开放尝试。

any-to-any-stream

投入使用

code/main.py:

  • 定义四模态词表分配并打印。
  • 把一组多模态输入(文本、图像、音频片段、音乐)路由过分词器路由器。
  • 模拟文转语音回答的流式解码,带延迟计数。
  • 给定编码器、prefill 和解码器延迟,计算预期的首个音频字节时间。

交付

本课产出 outputs/skill-any-to-any-pipeline-auditor.md。给定对话产品规格(输入模态、输出模态、延迟目标),审计 MIO 家族的设计选择并计算延迟预算。

练习

  1. 你的产品接受语音输入、返回语音输出。端到端延迟预算目标是多少?列出耗时的组件。

  2. SpeechTokenizer 残差 VQ 用 8 层码本。论证为什么必须并行解码残差层(而非串行),以及它带来多少延迟节省。

  3. 你的词表有 3.2 万文本 + 4 千图像 + 4 千语音。加 8 千音乐和约 10 个分隔符。隐藏维 4096 时,嵌入矩阵的参数成本是多少?

  4. 视觉思维链会吐出中间图像。哪类问题受益?哪类问题被额外 token 拖累?

  5. 读 Moshi(arXiv:2410.00037)。描述它的"内心独白"(inner monologue)技术,并与 MIO 的视觉思维链对比。

关键术语

术语人们常说的是实际含义是
任意到任意"多模态进出"单一模型,在任意方向上接受和产出 文本、图像、语音、音乐
残差 VQ"语音分词器栈"多码本分词,每层补充信息;基层是内容,后层是韵律
SEED-Tokenizer"图像编码"MIO 使用的 4096 条目码本离散图像分词器
视觉思维链"视觉草稿纸"模型在给出最终答案前,先生成一幅中间图像作为推理步骤
首个音频字节时间"TTFAB"从用户说话到首个音频输出的延迟;有对话感需 <500ms
四阶段课程"训练配方"对齐 → 交错 → 语音增强 → SFT,按此顺序
