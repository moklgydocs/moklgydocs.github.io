文档与图表理解

文档与图表理解

文档不是照片。PDF、学术论文、发票、手写表单里有版式、表格、图示、脚注、页眉和语义结构,这些是普通图像理解抓不住的。VLM 之前的技术栈是一条流水线:Tesseract OCR + LayoutLMv3 + 表格抽取启发式。VLM 浪潮用免 OCR 模型取代了它——Donut(2022)、Nougat(2023)、DocLLM(2023)——直接吐出结构化标记。到 2026 年,前沿就是"把页面图以 2576px 原生分辨率喂给 Claude Opus 4.7",结构化标记输出是白送的。本课梳理文档 AI 的三个时代。

类型: 动手构建
编程语言: Python(标准库,版式感知文档解析器骨架)
前置要求: 第 12 阶段 · 05(LLaVA)、第 5 阶段(NLP)
预计耗时: 约 180 分钟

学习目标

  • 解释文档 AI 的三个时代:OCR 流水线、免 OCR、VLM 原生。
  • 描述 LayoutLMv3 的三路输入:文本、版式(bbox)、图像 patch,以及统一掩码。
  • 对比 Donut(免 OCR,图像 → 标记)、Nougat(学术论文 → LaTeX)、DocLLM(版式感知生成式)、PaliGemma 2(VLM 原生)。
  • 为新任务(发票、学术论文、手写表单、中文收据)挑选文档模型。

问题

"读懂这份 PDF"听起来简单,实则不然。信息藏在:

  • 文本内容(90% 的信号)。
  • 版式(页眉、脚注、边栏、双栏格式)。
  • 表格(行、列、合并单元格)。
  • 图与示意图。
  • 手写批注。
  • 字体与排版(标题 vs 正文)。

裸 OCR 只吐出文本,其余全丢。一个关心发票的系统必须知道"Total: $1,245"来自右下角,而不是某条脚注。

概念

时代 1 —— OCR 流水线(2021 年前)

经典技术栈:

  1. PDF → 每页一张图。
  2. Tesseract(或商用 OCR)抽取文本和逐词包围框。
  3. 版式分析器识别区块(页眉、表格、段落)。
  4. 表格结构识别器解析表格。
  5. 领域规则 + 正则抽取字段。

干净的印刷文本上能用。一遇到手写、扫描歪斜、复杂表格、非英文文字就崩。每种失败模式都要一条定制的异常路径。

TrOCR(2021)

TrOCR(Li 等,arXiv:2109.10282)用合成 + 真实文本图像训练的 Transformer 编码器-解码器,取代了 Tesseract 的经典 CNN-CTC。在手写和多语言文本上干净利落地胜出。它仍是流水线(检测 → TrOCR → 版式),但 OCR 这一步进步巨大。

时代 2 —— 免 OCR(2022–2023)

第一批免 OCR 模型说:彻底跳过检测,把图像像素直接映射成结构化输出。

Donut(Kim 等,arXiv:2111.15664):

  • 编码器-解码器 Transformer,编码器是 Swin-B。
  • 输出是表单理解的 JSON、摘要的 markdown,或任何任务特定 schema。
  • 无 OCR、无版式、无检测。

Nougat(Blecher 等,arXiv:2308.13418):

  • 专为学术论文训练。
  • 输出 LaTeX / markdown。
  • 处理公式、多栏版式、图。
  • 每个 arXiv 解析器都在调用的模型。

这些是专才,不是通才:Donut 读学术论文会失败,Nougat 读发票会失败。

LayoutLMv3(2022)

另一条路线。LayoutLMv3(Huang 等,arXiv:2204.08387)保留 OCR,但加入版式理解:

  • 三路输入:OCR 文本 token、逐 token 的 2D 包围框、图像 patch。
  • 跨三种模态的统一掩码训练目标(掩码文本、掩码 patch、掩码版式)。
  • 下游:分类、实体抽取、表格问答。

LayoutLMv3 是基于 OCR 的文档理解的巅峰:表单和发票上很强,需要上游 OCR,在 VLM 之前的标准化文档基准上准确率最高。

DocLLM(2023)

DocLLM(Wang 等,arXiv:2401.00908)是 LayoutLM 的生成式兄弟:以版式 token 为条件生成自由形式的回答。更适合文档问答;仍依赖 OCR 输入。

时代 3 —— VLM 原生(2024+)

2024 年,VLM 好用到可以整个取代流水线:把整页高分辨率图像喂给 VLM,问问题,拿答案。

  • LLaVA-NeXT 336-tile AnyRes 能处理小文档。
  • Qwen2.5-VL 动态分辨率原生支持 2048+ 像素。
  • Claude Opus 4.7 支持 2576px 文档。
  • PaliGemma 2(2025 年 4 月)专为文档 + 手写训练。

VLM 原生与 OCR 流水线的差距迅速闭合。到 2026 年,VLM 原生在这些场景胜出:

  • 场景文字(手写 + 印刷、混写文字)。
  • 带合并单元格的复杂表格。
  • 嵌在文本里的数学公式。
  • 带文字标注的图。

OCR 流水线仍在这些场景胜出:

  • 海量纯扫描工作负载,单页延迟敏感。
  • 流水线可靠性(确定性失败 vs VLM 幻觉)。
  • 要求 OCR 输出可审计的合规环境。

Claude 4.7 / GPT-5 前沿

在 2576 像素原生输入下,前沿 VLM 的文档理解接近人类准确率。2026 年初的基准数字:

  • DocVQA:Claude 4.7 约 95.1,PaliGemma 2 约 88.4,Nougat 约 77.3,流水线 LayoutLMv3 约 83。
  • ChartQA:Claude 4.7 约 92.2,GPT-4V 约 78。
  • VisualMRC:Claude 4.7 约 94。

闭源模型的领先主要来自分辨率和基座 LLM 规模。7B 开源模型落后几个点,但在追赶。

数学公式与 LaTeX 输出

学术论文需要精确的 LaTeX 公式输出。Nougat 专为此训练。带 LaTeX 目标训练的 VLM(Qwen2.5-VL-Math、Nougat 衍生)能产出可用的 LaTeX;没有显式 LaTeX 训练的 VLM,产出可读但不精确的转写。

2026 年的学术论文流水线:PDF 先过 Nougat,难处理的页面再交给 VLM。

手写

仍是最难的子任务。印刷 + 手写混合(医生病历、填写表单)的场景,论成本 OCR 流水线仍胜过 VLM。纯手写 VLM 在进步(Claude 4.7、PaliGemma 2)。

2026 年配方

新上一个文档 AI 项目:

  • 海量纯印刷发票:LayoutLMv3 + 规则,成本最优。
  • 混合文档(学术 + 手写 + 表单):VLM 原生(PaliGemma 2 或 Qwen2.5-VL)。
  • 完整 arXiv 摄取:Nougat 管公式,VLM 管图。
  • 强监管:OCR 流水线为主 + VLM 交叉校验。

投入使用

code/main.py:

  • 一个玩具版式感知分词器:给定(文本, bbox)对,产出 LayoutLMv3 风格的输入。
  • 一个 Donut 风格任务 schema 生成器:表单的 JSON 模板。
  • 一次对比:OCR 流水线、Donut、Nougat、VLM 原生各自的每页 token 预算。

交付

本课产出 outputs/skill-document-ai-stack-picker.md。给定一个文档 AI 项目(领域、规模、质量、监管),在 OCR 流水线、免 OCR 专才、VLM 原生之间做选择。

练习

  1. 你的项目是每天 1000 万张发票。哪套技术栈在不损失准确率的前提下把单页成本压到最低?

  2. 为什么 LayoutLMv3 在表单问答上胜过纯 CLIP 系 VLM,却在场景文字上落败?bbox 流放弃了什么?

  3. Nougat 生成 LaTeX。各提一个测试用例:一个 VLM 原生的 LaTeX 保真度胜过 Nougat,一个 Nougat 胜出。

  4. 读 PaliGemma 2 论文(Google,2024)。相对 PaliGemma 1,提升文档准确率的关键训练数据新增是什么?

  5. 设计一个监管安全的混合方案:OCR 流水线为主,VLM 做二次交叉校验。两者不一致时如何裁决?

关键术语

术语人们常说的实际含义
OCR 流水线"Tesseract 那种"分阶段堆栈:检测 → OCR → 版式 → 规则;确定性,但脆弱
免 OCR"Donut 那种"图像直接到输出的 Transformer,跳过显式 OCR;单一模型
版式感知"LayoutLM"输入含逐 token 包围框坐标;跨模态统一掩码
VLM 原生"前沿 VLM"高分辨率页面图直接喂给 Claude/GPT/Qwen VLM;没有流水线
DocVQA"文档基准"文档 VQA 标准;被引最多的分数
标记输出"LaTeX / MD"结构化输出格式而非自由文本;支撑下游自动化
