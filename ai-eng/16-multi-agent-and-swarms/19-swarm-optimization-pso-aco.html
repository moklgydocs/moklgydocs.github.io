面向 LLM 的群体优化(PSO、ACO)

面向 LLM 的群体优化(PSO、ACO)

仿生优化正在 LLM 领域回潮。LMPSO(arXiv:2504.09247)把 PSO 用在每个粒子的速度就是一段提示词、由 LLM 生成下一个候选解的场景;在结构化序列输出(数学表达式、程序)上效果不错。Model Swarms(arXiv:2410.11163)把每个 LLM 专家当作模型权重流形上的一个 PSO 粒子,报告在 9 个数据集上、仅用 200 个实例就相对 12 个基线取得 13.3% 的平均提升。SwarmPrompt(ICAART 2025)把 PSO 与灰狼算法混合用于提示词优化。AMRO-S(arXiv:2603.12933)是受 ACO 启发的信息素专家,用于多智能体 LLM 路由——4.7 倍加速、可解释的路由证据、把推理与学习解耦的质量门控异步更新。本课在提示词参数空间上实现 PSO、在智能体路由上实现 ACO,测量这些经典算法为什么适合 LLM 时代,以及什么时候不适合。

类型: 学习 + 动手构建
编程语言: Python(标准库)
前置要求: 第 16 阶段 · 09(并行蜂群网络)、第 16 阶段 · 14(共识与 BFT)
预计耗时: 约 75 分钟

问题

你有一个在任务评测上拿 62 分的提示词,想改进它。最朴素的做法是无梯度的手动微调,但扩展性很差。强化学习需要奖励信号和足够多的 rollout 来训练。对提示词做反向传播也不现实——提示词是离散字符串,不是可微参数。

经典的仿生优化——PSO 面向连续搜索空间,ACO 面向路径选择——正是为这种情形设计的:无梯度、基于群体、单次评估便宜。把它们和 LLM 搭配起来做无梯度搜索这一步,你就得到了一个出人意料地实用的优化器。

同样的模式也适用于多智能体系统中的智能体路由。ACO 风格的信息素轨迹记录哪个智能体在哪类任务上表现最好,让路由器利用这条轨迹,并通过信息素衰减让路径可以被重新发现。

概念

PSO 复习(Kennedy & Eberhart 1995)

粒子群优化(Particle Swarm Optimization):连续搜索空间中的一群粒子。每个粒子有位置 x_i 和速度 v_i。每次迭代:

v_i <- w * v_i + c1 * r1 * (p_best_i - x_i) + c2 * r2 * (g_best - x_i)
x_i <- x_i + v_i
evaluate fitness(x_i)
update p_best_i if improved
update g_best if global best

其中 p_best 是粒子自己的历史最优,g_best 是整个群体的最优,w, c1, c2 是惯性 + 认知 + 社会权重,r1, r2 是随机因子。

LLM 输出上的 PSO —— LMPSO

arXiv:2504.09247 把 PSO 适配到 LLM 生成的结构化输出(数学表达式、程序)。每个粒子是一个候选输出。速度是一段提示词,描述如何把当前输出朝个体/全局最优方向修改。LLM 根据速度提示词生成新输出。速度的"惯性"就是类似"做小的增量修改"这样的提示词。

它在以下情况效果好:

  • 输出是结构化的(可解析、可评估)。
  • 适应度是自动计算的(跑测试、算术求值)。
  • 群体小(约 10-30 个粒子),LLM 调用总量可控。

当适应度需要人工评审时效果就不好——每次迭代的成本会高到无法承受。

Model Swarms

arXiv:2410.11163 把 PSO 从输出层搬到了模型层。每个"粒子"是一个专家 LLM(参数)。群体通过无梯度更新把参数推向集体最优。报告:9 个数据集上、每次迭代仅用 200 个实例,相对 12 个基线平均提升 13.3%。

关键洞见是:LLM 专家模型本来就位于一个共享参数流形的邻近区域(adapter 权重、LoRA 增量)。在这个低维子空间上做 PSO 既便宜又有效。

ACO 复习(Dorigo 1992)

蚁群优化(Ant Colony Optimization):蚂蚁在图上爬行;每条路径有一条信息素轨迹。蚂蚁的移动概率按信息素强度加权。完成任务的蚂蚁按解的质量成比例地释放信息素。信息素随时间衰减。

AMRO-S —— 用于智能体路由的 ACO

arXiv:2603.12933 把 ACO 用于多智能体路由。每种任务类型是一个"目的地";每个智能体是一条可能的路径。产生好输出的路径,其信息素会增强。主要贡献:

  • 可解释的路由证据。 信息素强度是人类可读的信号。
  • 质量门控的异步更新。 信息素只在质量检查通过后更新,把推理与学习解耦。
  • 在多智能体路由基准上提速 4.7 倍。

质量门控很关键:没有它,快但错的智能体会积累信息素,系统就会锁定在糟糕的路由上。

什么时候给 LLM 用 PSO / ACO

用 PSO 的场景:

  • 搜索空间是连续的,或可映射到连续参数(提示词嵌入、LoRA 权重、数值型生成参数)。
  • 适应度便宜且自动。
  • 群体可以很小(10-30)。

用 ACO 的场景:

  • 你面对的是一个路由或路径选择问题。
  • 决策随时间强化(同样的任务类型会反复出现)。
  • 你需要路由决策的可解释证据。

两个都不要用的场景:

  • 适应度需要人工评审(每次迭代太贵)。
  • 搜索空间是离散且组合性的、PSO 覆盖不了(改用遗传算法)。
  • 实时决策有严格延迟要求(相对单趟启发式,PSO/ACO 收敛慢)。

为什么仿生方法仍然能赢

基于梯度的方法需要可微信号。LLM 输出和路由决策并不是天然可微的。伪梯度方法(强化学习出来的路由器、DPO 风格的提示词调优)可行,但需要昂贵的训练。

PSO 和 ACO 只需要一个评估器函数。只要你能给一个候选输出或一次路由决策打分,你就能在这个空间上做优化。这把适用门槛拉低了很多。

实际限制

  • 群体预算。 N 个粒子 × T 次迭代 × 单次评估成本。按 LLM 评估约 $0.02/次算,一个 20 粒子、跑 50 次迭代的 PSO 约花 $20。按此做规划。
  • 探索 vs 利用。 信息素衰减率和 PSO 惯性之间存在权衡;衰减太快 → 忘掉解;太慢 → 卡在早期局部最优上。
  • 灾难性漂移。 如果适应度地形变化(新数据分布),两种算法都可能先收敛再发散。监控最优适应度的稳定性。

动手构建

code/main.py 实现了:

  • LMPSO —— 在数值型提示词参数(temperature、top_k 权重)上做 PSO。每个粒子的"LLM 生成"用一个脚本化的适应度函数模拟。跑 30 次迭代,展示 g_best 的收敛。
  • AMRO_S —— ACO 风格路由。3 个智能体、4 种任务类型、信息素矩阵、100 个被路由的任务。打印(任务类型 → 智能体选择)随时间的分布,展示轨迹形成过程。
  • 对比:同一任务流上的随机路由 vs ACO 路由。测量质量和延迟。

运行:

python3 code/main.py

预期输出:

  • LMPSO:g_best 适应度在 30 次迭代内从随机水平提升到接近最优。
  • AMRO-S:信息素表稳定在每种任务类型的正确智能体上;ACO 路由在质量上比随机路由好约 30-40%,延迟也更低(重试更少)。

投入使用

outputs/skill-swarm-optimizer.md 帮助在 PSO、ACO、遗传算法和基于梯度的优化器之间做选择,面向 LLM / 智能体优化问题。

交付

  • 从小做起。 10-20 个粒子、20-50 次迭代。只有当收敛曲线显示明确收益时再放大。
  • 每次迭代记录信息素或 g_best。 没有轨迹就去调试群体优化器,非常痛苦。
  • 质量门控更新。 尤其是 ACO 路由:快而错的智能体绝不能积累信息素。
  • 分布漂移时重置衰减。 评测分布一变,老化的信息素就过时了;重置或临时加倍衰减率。
  • 给每次迭代的成本设上限。 输出"每次迭代成本"指标。每次迭代花 $500、只提升 0.5% 的 PSO 是没法交付的。

练习

  1. 运行 code/main.py。观察 LMPSO 的收敛。把群体大小改为 5、10、20、50。多大规模时收敛时间开始饱和?
  2. 实现一个"灾难性漂移"实验:第 30 次迭代后改变适应度函数。PSO 适应得多快?重置 p_best 有帮助吗?
  3. 给 AMRO-S 加一个质量门控:只在评测分数 > 0.7 的运行上释放信息素。相比无门控版本,收敛有什么变化?
  4. 阅读 LMPSO(arXiv:2504.09247)。把论文的"速度即提示词"映射回你的数值速度。模拟中丢失了什么、保留了什么?
  5. 阅读 AMRO-S(arXiv:2603.12933)。实现解耦的"推理快速路径"和异步信息素更新。在持续负载下,这会如何改变系统延迟?

ACO"蚁群优化"Dorigo 1992。通过信息素轨迹做路径/路由优化。
