技能库与终身学习(Voyager)

技能库与终身学习(Voyager)

Voyager(Wang 等,TMLR 2024)把可执行代码当作技能:技能是命名的、可检索的、可组合的,并由环境反馈打磨。这就是 Claude Agent SDK 技能、skillkit 和 2026 年技能库模式的参考架构。

类型: 动手构建
编程语言: Python(标准库)
前置要求: 第 14 阶段 · 07(MemGPT)、第 14 阶段 · 08(Letta 块)
预计耗时: 约 75 分钟

学习目标

  • 说出 Voyager 的三个组件——自动课程、技能库、迭代提示机制——及各自的角色。
  • 解释为什么 Voyager 把动作空间设为代码,而非原语命令。
  • 用纯标准库实现技能库:注册、检索、组合、失败驱动的打磨。
  • 把 Voyager 的模式映射到 2026 年的 Claude Agent SDK 技能和 skillkit 生态。

问题

每个会话都从零重建每项能力的智能体,在三件事上都做错了:

  1. 浪费 token。 每个任务都重新引出同样的推理。
  2. 丢失进展。 会话 A 学到的纠正传不到会话 B。
  3. 长程组合上失败。 复杂任务需要能力层级,一次性提示词表达不了。

Voyager 的答案:把每项可复用能力当作一段命名的代码,存进库里,按相似度可检索,与其他技能可组合,由执行反馈打磨。

概念

三个组件

Voyager(arXiv:2305.16291)把智能体组织为:

  1. 自动课程。 好奇心驱动的提议器,根据智能体当前的技能集和环境状态挑下一个任务。探索是自底向上的。
  2. 技能库。 每个技能是可执行代码。任务成功就新增技能。技能按"查询对描述"的相似度检索。
  3. 迭代提示机制。 失败时,智能体收到执行错误、环境反馈和自验证输出,然后改写技能。

Minecraft 评估(Wang 等,2024):独特物品多 3.3 倍,石器快 8.5 倍,铁器快 6.4 倍,地图跋涉距离长 2.3 倍。数字是 Minecraft 特有的,模式是可迁移的。

动作空间 = 代码

大多数智能体发出原语命令。Voyager 发出 JavaScript 函数。一个技能是:

async function craftIronPickaxe(bot) {
  await mineIron(bot, 3);
  await mineStick(bot, 2);
  await placeCraftingTable(bot);
  await craft(bot, 'iron_pickaxe');
}

由子技能组合而成,按描述和嵌入存储,作为程序被检索,而不是提示词。

这就是 2026 年的 Claude Agent SDK 技能:一段命名的、可检索的代码加说明,智能体按需加载。

技能检索

新任务"做一把钻石镐"。智能体:

  1. 嵌入任务描述。
  2. 查询技能库,取 top-k 相似技能。
  3. 检索到 craftIronPickaxe、mineDiamond、placeCraftingTable 等。
  4. 用检索到的原语 + 新逻辑,组合出新技能。

这就是 MCP 资源(第 13 阶段)和 Agent SDK 技能实现的模式:在知识/代码面上做检索,范围限定在当前任务。

迭代打磨

Voyager 的反馈循环:

  1. 智能体写一个技能。
  2. 技能对环境运行。
  3. 返回三种信号之一:success、error(带堆栈)、self-verification failure。
  4. 智能体以该信号为上下文重写技能。
  5. 循环,直到成功或达到最大轮数。

这就是应用在代码生成上的 Self-Refine(第 05 课),验证由环境落地。CRITIC(第 05 课)是同一模式,只是验证器是外部工具。

课程与探索

Voyager 的课程模块根据智能体拥有什么、还没做过什么,提出诸如"在湖边建个庇护所"的任务。提议器用环境状态 + 技能清单,挑一个略高于当前能力的任务——探索的甜点位。

对生产智能体,这翻译成一个"还缺什么"操作:给定当前技能库和一个领域,哪些技能我们还没覆盖?团队通常以人工课程评审的方式实现它。

这个模式在哪里出错

  • 技能库腐化。 同一个技能以略不同的描述被加了 10 次。写入时去重;检索只返回一个。
  • 组合技能漂移。 父技能依赖的子技能被打磨过。给技能做版本;钉在 v1 的父技能不会 magically 用上 v3。
  • 检索质量。 库超过几百个技能后,对描述的向量检索会退化。辅以标签过滤和硬约束("只要 category=tooling 的技能")。
voyager-skills

动手构建

code/main.py 用纯标准库实现技能库:

  • Skill —— 名称、描述、代码(字符串)、版本、标签、依赖。
  • SkillLibrary —— 注册、搜索(token 重叠)、组合(依赖拓扑排序)、打磨(更新时版本递增)。
  • 一个脚本化智能体:注册三个原语技能,组合出第四个,遇到失败,打磨。

运行:

python3 code/main.py

轨迹展示库写入、检索、组合、一次失败执行和一次 v2 打磨——端到端的 Voyager 循环。

投入使用

  • Claude Agent SDK 技能(Anthropic)—— 2026 年参考:每个技能有描述、代码和说明;智能体会话中按需加载。
  • skillkit(npm: skillkit)—— 跨 32+ AI 编程智能体的技能管理。
  • 自定义技能库 —— 领域特定(数据智能体的 SQL 技能、基础设施智能体的 Terraform 技能)。Voyager 模式可缩小。
  • OpenAI Agents SDK tools —— 低端形态;每个工具就是一个轻量技能。

交付

outputs/skill-skill-library.md:为任何目标运行环境生成 Voyager 形状的技能库,接好注册、检索、版本化和打磨。

练习

  1. 给 compose() 加依赖环检测器。技能 A 依赖 B、B 依赖 A 时会发生什么?报错还是警告?
  2. 实现逐技能版本钉住。父技能组合了子技能 crafting@1 时,对 crafting@2 的打磨绝不能悄悄升级父技能。
  3. 把 token 重叠检索换成 sentence-transformers 嵌入(或标准库 BM25 实现)。在 50 技能的玩具库上测 retrieval@5。
  4. 加一个"课程"智能体:给定当前库和一个领域描述,提议 5 个缺失技能。每周调用一次。
  5. 读 Anthropic 的 Claude Agent SDK 技能文档。把玩具库移植到 SDK 的技能 schema。可发现性有什么变化?

关键术语

术语人们常说的实际含义
技能"可复用能力"命名的代码块 + 描述,按相似度可检索
技能库"智能体的'怎么做'记忆"技能的持久存储,可搜索、可组合
课程"任务提议器"由当前能力缺口驱动的自底向上目标生成器
组合"技能 DAG"技能调用技能;执行时拓扑排序
迭代打磨"自我纠正循环"环境反馈 + 错误 + 自验证折回下一个版本
动作空间即代码"程序化动作"发出函数而非原语命令,表达时间延展的行为
写入去重"技能坍缩"近重复描述坍缩为一个 经典 技能
