记忆块与睡眠时计算

记忆块与睡眠时计算

模型可以直接编辑的离散功能记忆块,外加一个在主智能体空闲时异步整合记忆的睡眠时智能体。这两个想法,是把记忆扩展到单段对话之外的方式。

类型: 动手构建
编程语言: Python(标准库)
前置要求: 第 14 阶段 · 07(MemGPT)
预计耗时: 约 75 分钟

学习目标

  • 说出 Letta 用的三层记忆(core、recall、archival)及各自的角色。
  • 解释记忆块模式:Human 块、Persona 块和用户自定义块作为一等带类型对象。
  • 描述什么是睡眠时计算,为什么它在关键路径之外,以及为什么它可以用比主智能体更强的模型。
  • 实现一个脚本化双智能体循环:主智能体服务回答,睡眠时智能体在轮次之间整合块。

问题

MemGPT(第 07 课)解决了虚拟记忆的控制流。三个生产问题随后浮现:

  1. 延迟。 每个记忆操作都在关键路径上。如果用户等着的时候智能体还得剪枝、摘要或调和,尾延迟就爆了。
  2. 记忆腐化。 写入不断累积,已被推翻的事实留着不走,检索被陈旧内容淹没。
  3. 结构丢失。 扁平的归档存储表达不了"Human 块永远在提示词里;Persona 块永远在提示词里;Task 块按会话切换"。

Letta(letta.com)是原 MemGPT 项目 2024 年采用的平台名——论文的模式仍叫 MemGPT——2026 年的 Letta V1 重写是后来独立的一步。记忆块让结构显式化;睡眠时计算把整合移出关键路径。

概念

三层

层范围存在哪由谁写入
Core永远可见主提示词内智能体工具调用 + 睡眠时改写
Recall对话历史可检索自动轮次日志
Archival任意事实向量 + KV + 图智能体工具调用 + 睡眠时摄取

Core 就是 MemGPT 的 core;Recall 是对话缓冲区加上被驱逐的尾巴;Archival 是外部存储。这个三分法理顺了 MemGPT 两层结构的过载。

记忆块

块是 core 层中带类型的、持久的、可编辑的区段。原 MemGPT 论文定义了两个:

  • Human 块 —— 关于用户的事实(姓名、角色、偏好、目标)。
  • Persona 块 —— 智能体的自我概念(身份、语气、约束)。

Letta 推广为任意用户自定义块:当前目标的 Task 块、代码库事实的 Project 块、硬约束的 Safety 块。每个块有 id、label、value、limit(字符上限)、description(让模型知道何时编辑它)。

块通过工具面编辑:

  • block_append(label, text)
  • block_replace(label, old, new)
  • block_read(label)
  • block_summarize(label) —— 压缩接近上限的块。

睡眠时计算

2025 年 Letta 新增:在后台跑第二个智能体,离开关键路径。睡眠时智能体处理对话转录和代码库上下文,把 learned_context 写进共享块,并整合或作废归档记录。

由此得到的性质:

  • 零延迟成本。 主回答不等待记忆操作。
  • 可以用更强的模型。 睡眠时智能体不受延迟约束,可以更贵、更慢。
  • 天然的整合窗口。 用户不等的时候做去重、摘要、作废被推翻的事实。

这个形状和人类工作方式一致:白天干活,睡一觉,长期记忆在夜里沉淀。

原生推理

Letta V1(letta_v1_agent,2026)弃用 send_message/心跳和内联 Thought: token,转向原生推理。Responses API(OpenAI)和带扩展思考的 Messages API(Anthropic)在独立通道产出推理,跨轮透传(生产中跨提供商加密)。控制循环仍是 ReAct,只是思考轨迹是结构化的,不是提示词形状的。

这个模式在哪里出错

  • 块膨胀。 无限 block_append 很快撞上上限。在写入前接一个块摘要器,超限就先压缩。
  • 静默漂移。 睡眠时智能体改写了块,主智能体毫无察觉。给块做版本化,在轨迹里暴露 diff。
  • 被投毒的整合。 睡眠时智能体把攻击者可触达的内容整合进了 core。第 27 课的教训同样适用于睡眠时这一面。
memory-blocks

动手构建

code/main.py 实现:

  • Block —— id、label、value、limit、description。
  • BlockStore —— CRUD + near_limit(label) 辅助函数。
  • 两个脚本化智能体 —— PrimaryAgent 服务轮次,SleepTimeAgent 在轮次间整合。
  • 一条轨迹:三轮对话带块写入,加一次睡眠时 pass——摘要一个块、作废一条陈旧事实。

运行:

python3 code/main.py

转录展示分工:主轮次快、只做原始写入;睡眠 pass 负责压实和清理。

投入使用

  • Letta(letta.com)参考实现。自托管或托管云。
  • Claude Agent SDK 技能就是块形状的知识——技能是命名的、带版本的、可按需检索加载的指令块。
  • 自建:想掌控存储后端的团队。用 Letta 的 API 契约,方便日后迁移。

交付

outputs/skill-memory-blocks.md:为任何运行环境生成 Letta 形状的块系统,带睡眠时钩子,含安全规则和出处接线。

练习

  1. 加一个 block_summarize 工具:near_limit 返回真时,用模型生成的摘要替换块内容。哪个触发阈值能同时最小化摘要调用次数和块溢出?
  2. 实现归档的睡眠时去重:文本 token 重叠 >90% 的两条记录合并为一条。只在睡眠 pass 做,永远不上关键路径。
  3. 给块做版本化:每次写入记录旧值和 diff。暴露 block_history(label),让运维能调试"智能体为什么忘了 X"。
  4. 把睡眠时智能体当不可信写入者:它们碰 Persona 或 Safety 块时,提交前要求第二个智能体复核。
  5. 把示例移植到 Letta API(letta_v1_agent)。块 schema 有什么变化?原生推理如何改变轨迹形状?
