发布模式详解

dotnet publish 有好几种模式，到底该选哪个？选错了要么服务器还得装 Runtime，要么包大得离谱。

四种发布模式

模式                    需要装Runtime？   产物大小     适用场景
────────────────────────────────────────────────────────────
FDD（框架依赖）          ✅ 需要          小(5-20MB)   服务器已装 Runtime
SCD（自包含）            ❌ 不需要        大(60-80MB)  服务器没装 Runtime
SingleFile（单文件）      看情况          中等         简化部署
ReadyToRun（预编译AOT）   看情况          更大         追求启动速度

FDD —— 框架依赖部署（默认）

# 最基本的发布
dotnet publish -c Release -o ./publish

# 产物：
# publish/
# ├── ERP.Host.dll          ← 你的代码
# ├── ERP.Host.deps.json    ← 依赖清单
# ├── ERP.Host.runtimeconfig.json  ← Runtime 配置
# ├── appsettings.json
# └── 各种依赖 dll...
# 服务器上运行
dotnet ERP.Host.dll

# ⚠️ 服务器必须已安装对应版本的 .NET Runtime
dotnet --info   # 查看已安装的 Runtime

优点：产物小，多个应用共享 Runtime
缺点：服务器要装 Runtime，版本要对得上

SCD —— 自包含部署

# 打包时带上 Runtime
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64

# 产物：60-80MB
# 包含了 .NET Runtime，服务器不需要安装任何东西
# 服务器上直接运行可执行文件
chmod +x ./ERP.Host
./ERP.Host

# 不需要 dotnet 命令

优点：不依赖服务器环境，部署最简单
缺点：包大，每个应用都有一份 Runtime

SingleFile —— 单文件发布

# 把所有文件打成一个可执行文件
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64 \
  -p:PublishSingleFile=true

# 产物：一个 ERP.Host 可执行文件（60-80MB）
# 服务器上
chmod +x ./ERP.Host
./ERP.Host

# 运行时会解压到临时目录
# 首次启动比较慢，后续正常

优点：部署就是复制一个文件
缺点：首次启动慢，调试不方便

ReadyToRun —— 预编译

# 预编译为本地代码，加快启动速度
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64 \
  -p:PublishReadyToRun=true

# 可以和 SingleFile 组合
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64 \
  -p:PublishSingleFile=true \
  -p:PublishReadyToRun=true

优点：启动速度快（减少 JIT 编译）
缺点：产物更大，构建更慢

Trimming —— 裁剪

# 移除未使用的代码，减小体积
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64 \
  -p:PublishTrimmed=true

# SCD 从 60MB → 30-40MB

注意

Trimming 可能裁掉用反射加载的代码。ASP.NET Core 项目慎用，需要充分测试。

选哪个？

场景                              推荐模式
────────────────────────────────────────────
Docker 容器部署                    FDD（基础镜像已有 Runtime）
服务器已统一安装 Runtime            FDD
服务器环境不可控                    SCD
追求最简部署                       SCD + SingleFile
追求启动速度                       SCD + ReadyToRun

我们的 ERP 项目推荐

# Docker 部署 → FDD（最小镜像）
dotnet publish -c Release -o ./publish

# 直接部署到 Linux → SCD
dotnet publish -c Release -o ./publish \
  --self-contained true \
  -r linux-x64

csproj 里配置发布选项

<PropertyGroup>
  <TargetFramework>net8.0</TargetFramework>

  <!-- 发布相关 -->
  <RuntimeIdentifier>linux-x64</RuntimeIdentifier>
  <SelfContained>true</SelfContained>
  <PublishSingleFile>true</PublishSingleFile>
  <PublishReadyToRun>true</PublishReadyToRun>

  <!-- 这样 dotnet publish -c Release 就够了 -->
</PropertyGroup>

Linux 安装 .NET Runtime

FDD 模式需要在服务器上装 Runtime：

# CentOS/RHEL
sudo rpm -Uvh https://packages.microsoft.com/config/centos/7/packages-microsoft-prod.rpm
sudo yum install -y aspnetcore-runtime-8.0

# Ubuntu
wget https://packages.microsoft.com/config/ubuntu/22.04/packages-microsoft-prod.deb -O packages-microsoft-prod.deb
sudo dpkg -i packages-microsoft-prod.deb
sudo apt update
sudo apt install -y aspnetcore-runtime-8.0

# 验证
dotnet --list-runtimes
