环境变量与多环境配置

同一套 compose 文件，开发用一套配置，测试用一套，生产用一套。通过环境变量和 override 机制实现。

环境变量的优先级

从高到低：

1. docker compose run -e 传入的变量
2. environment 字段直接写死的
3. env_file 文件里的
4. Dockerfile 里的 ENV
5. .env 文件里的（给 compose 自身用的变量）

.env 文件

.env 是给 docker-compose.yml 自身做变量替换用的，不会自动传给容器。

# .env
APP_VERSION=v1.2.3
DB_PASSWORD=secret123
COMPOSE_PROJECT_NAME=erp
# docker-compose.yml 里这样引用
services:
  erp-api:
    image: erp-api:${APP_VERSION}    # → erp-api:v1.2.3
    environment:
      - DB_PASSWORD=${DB_PASSWORD}   # 这样才传给容器
# COMPOSE_PROJECT_NAME 控制容器名前缀
# 默认是目录名，设置后：erp-erp-api-1, erp-postgres-1

env_file —— 批量传环境变量给容器

services:
  erp-api:
    env_file:
      - ./common.env           # 通用变量
      - ./erp-api.env          # 服务专属变量
# common.env
TZ=Asia/Shanghai
ASPNETCORE_ENVIRONMENT=Production

# erp-api.env
ASPNETCORE_URLS=http://+:5000
ConnectionStrings__Default=Host=postgres;Port=5432;Database=erp;Username=postgres;Password=secret
Redis__Connection=redis:6379

env_file vs environment

  • env_file：变量多的时候用，保持 yml 干净
  • environment：变量少或需要用 ${VAR} 替换时用
  • 两个可以混用，environment 优先级更高

多环境方案

方案一：多个 .env 文件

project/
├── docker-compose.yml       # 通用配置
├── .env.development         # 开发环境变量
├── .env.staging             # 测试环境变量
└── .env.production          # 生产环境变量
# 指定 env 文件启动
docker compose --env-file .env.development up -d
docker compose --env-file .env.production up -d

方案二：override 文件（推荐）

Compose 自动加载 docker-compose.override.yml，可以覆盖主文件的配置。

project/
├── docker-compose.yml               # 基础配置
├── docker-compose.override.yml      # 开发环境（默认加载）
├── docker-compose.staging.yml       # 测试环境
└── docker-compose.production.yml    # 生产环境

docker-compose.yml（基础）：

services:
  erp-api:
    image: erp-api:${APP_VERSION:-latest}
    restart: unless-stopped
    depends_on:
      - postgres
      - redis
    networks:
      - app-net

  postgres:
    image: postgres:16
    volumes:
      - pgdata:/var/lib/postgresql/data
    networks:
      - app-net

  redis:
    image: redis:7-alpine
    networks:
      - app-net

volumes:
  pgdata:

networks:
  app-net:

docker-compose.override.yml（开发环境，自动加载）：

services:
  erp-api:
    ports:
      - "5000:5000"
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
      - ASPNETCORE_URLS=http://+:5000
      - ConnectionStrings__Default=Host=postgres;Port=5432;Database=erp_dev;Username=postgres;Password=dev123
    volumes:
      - ./src:/app    # 挂载源码，支持热重载

  postgres:
    ports:
      - "5432:5432"    # 对外开放，方便用 DBeaver 连
    environment:
      POSTGRES_PASSWORD: dev123
      POSTGRES_DB: erp_dev

  redis:
    ports:
      - "6379:6379"

docker-compose.production.yml（生产环境）：

services:
  erp-api:
    expose:
      - "5000"         # 不对外暴露，走 Nginx
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - ASPNETCORE_URLS=http://+:5000
      - ConnectionStrings__Default=Host=postgres;Port=5432;Database=erp;Username=postgres;Password=${DB_PASSWORD}
    deploy:
      resources:
        limits:
          memory: 512M
          cpus: '1.5'
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:5000/health"]
      interval: 30s
      timeout: 5s
      retries: 3

  postgres:
    # 不对外暴露端口
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}
      POSTGRES_DB: erp

  redis:
    command: redis-server --requirepass ${REDIS_PASSWORD} --maxmemory 256mb

  nginx:
    image: nginx:alpine
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
    depends_on:
      - erp-api
    networks:
      - app-net
# 开发环境（自动加载 override）
docker compose up -d

# 生产环境（指定文件）
docker compose -f docker-compose.yml -f docker-compose.production.yml up -d

# 简写：设置环境变量
export COMPOSE_FILE=docker-compose.yml:docker-compose.production.yml
docker compose up -d

变量替换语法

services:
  erp-api:
    image: erp-api:${APP_VERSION}            # 必须有值
    image: erp-api:${APP_VERSION:-latest}    # 为空时用默认值 latest
    image: erp-api:${APP_VERSION:?请设置版本号}  # 为空时报错

检查最终配置

# 查看合并后的最终配置（排查变量替换是否正确）
docker compose config

# 指定文件
docker compose -f docker-compose.yml -f docker-compose.production.yml config

# 只看某个服务
docker compose config --services
