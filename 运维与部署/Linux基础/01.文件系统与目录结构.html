文件系统与目录结构

文件系统与目录结构

拿到一台新服务器，第一件事不是装软件，是搞清楚东西放在哪。

Linux 不像 Windows 有 C盘 D盘，整个系统就是一棵目录树，根节点是 /。

目录树全景

/
├── bin/        → 基础命令（ls, cp, cat, grep...）
├── sbin/       → 系统管理命令（systemctl, fdisk, iptables...）
├── etc/        → 配置文件（nginx.conf, sshd_config, hosts...）
├── home/       → 普通用户的家目录（/home/deploy, /home/zhangsan）
├── root/       → root 用户的家目录
├── var/        → 可变数据
│   ├── log/    → 系统日志（messages, secure, dmesg）
│   ├── lib/    → 程序运行数据（mysql, docker）
│   └── run/    → 运行时文件（pid文件）
├── tmp/        → 临时文件（重启会清空）
├── usr/        → 用户程序（类似 Windows 的 Program Files）
│   ├── bin/    → 用户命令
│   ├── lib/    → 库文件
│   ├── local/  → 手动安装的软件（/usr/local/nginx）
│   └── share/  → 共享资源（文档、字体）
├── opt/        → 第三方大型软件（/opt/dotnet, /opt/gitlab）
├── proc/       → 虚拟文件系统，映射内核信息（/proc/cpuinfo）
├── sys/        → 虚拟文件系统，映射硬件信息
├── dev/        → 设备文件（/dev/sda = 第一块硬盘）
├── mnt/        → 临时挂载点
├── media/      → 可移动设备挂载点（U盘、光驱）
├── boot/       → 内核和启动文件
└── lib/        → 系统库文件（.so 动态链接库）

太多了记不住没关系，日常只需要盯住这几个：

/etc/        → 改配置来这里
/var/log/    → 查日志来这里
/opt/ 或 /usr/local/  → 装软件来这里
/home/deploy → 放应用来这里
/tmp/        → 临时扔东西来这里

做 .NET 部署你会碰到的目录

你的应用放哪？

两种常见方案：

# 方案一：放 /opt 下（推荐，和 Docker/GitLab 等放一起）
/opt/apps/
├── erp-api/
│   ├── ERP.Host.dll
│   ├── appsettings.json
│   ├── appsettings.Production.json
│   └── logs/
├── sso-server/
│   ├── SSO.Host.dll
│   └── ...
└── auth-center/
    └── ...

# 方案二：放用户家目录下
/home/deploy/apps/
├── erp-api/
└── sso-server/

选哪个都行，关键是统一，别这个项目放 /opt 那个放 /home，过俩月你自己都找不到。

日志放哪？

# 方案一：应用目录下的 logs 子目录
/opt/apps/erp-api/logs/
├── 2024-04-14.log
└── 2024-04-13.log

# 方案二：集中到 /var/log 下（方便统一收集）
/var/log/apps/
├── erp-api/
│   └── app.log
└── sso-server/
    └── app.log

用 Serilog 的话，在 appsettings.Production.json 里配路径就行：

{
  "Serilog": {
    "WriteTo": [
      {
        "Name": "File",
        "Args": {
          "path": "/opt/apps/erp-api/logs/app-.log",
          "rollingInterval": "Day",
          "retainedFileCountLimit": 30
        }
      }
    ]
  }
}

Docker 相关目录

装了 Docker 之后，这几个目录会出现：

/var/lib/docker/        → Docker 的数据目录（镜像、容器、卷）
  ├── image/            → 镜像存储
  ├── containers/       → 容器数据
  ├── volumes/          → 数据卷
  └── overlay2/         → 联合文件系统层（最占空间的地方）

/etc/docker/            → Docker 配置
  └── daemon.json       → Docker 守护进程配置

# ⚠️ /var/lib/docker 会越来越大
# 生产环境建议把它挂到大磁盘分区

文件操作命令速查

导航与查看

# 当前在哪？
pwd                         # /home/deploy

# 列目录
ls                          # 简单列出
ls -la                      # 详细列出（权限、大小、时间）
ls -lh                      # 人类可读的大小（K/M/G）
ls -lt                      # 按修改时间排序（最新在前）
ls -lS                      # 按文件大小排序

# 切换目录
cd /opt/apps/erp-api        # 绝对路径
cd ..                       # 上一级
cd ~                        # 回家目录
cd -                        # 回到上一次所在的目录（很好用）

# 看目录树结构
tree /opt/apps              # 需要先装：yum install tree
tree -L 2 /opt/apps         # 只看两层

文件操作

# 创建
mkdir -p /opt/apps/erp-api/logs    # -p 递归创建（父目录不存在也不报错）
touch app.log                       # 创建空文件（或更新时间戳）

# 复制
cp appsettings.json appsettings.json.bak    # 备份配置
cp -r erp-api/ erp-api-backup/              # 复制整个目录（-r 递归）

# 移动/重命名
mv app.log app.log.old                       # 重命名
mv /tmp/publish/* /opt/apps/erp-api/         # 移动文件

# 删除
rm app.log                                   # 删文件
rm -rf /opt/apps/erp-api-old/               # ⚠️ 删目录（不可恢复！）

# 软链接（快捷方式）
ln -s /opt/apps/erp-api/current /opt/apps/erp-api/releases/v1.2.3
# 部署新版本时只需更新软链接指向，回滚也只是换个指向

关于 rm -rf

rm -rf / 会删掉整个系统，不会有任何提示。

实际工作中的安全习惯：

  1. 删除前先 ls 确认路径是对的
  2. 变量拼路径时加引号：rm -rf "${APP_DIR}" 而不是 rm -rf $APP_DIR
  3. 如果 $APP_DIR 为空，rm -rf $APP_DIR/ 会变成 rm -rf /，引号可以防住

文件内容查看

# 整个文件
cat nginx.conf                # 小文件直接看
less nginx.conf               # 大文件分页看（q 退出，/关键词 搜索）
head -20 app.log              # 看前 20 行
tail -50 app.log              # 看最后 50 行

# ⭐ 实时追踪日志（排查问题最常用）
tail -f /opt/apps/erp-api/logs/app.log
tail -f /var/log/nginx/error.log

# 多个日志同时追踪
tail -f /opt/apps/erp-api/logs/app.log /var/log/nginx/error.log

搜索

# 在文件内容中搜索
grep "Exception" app.log                    # 找异常
grep -i "error" app.log                     # -i 忽略大小写
grep -n "500" access.log                    # -n 显示行号
grep -r "ConnectionString" /opt/apps/       # -r 递归搜索目录
grep -c "404" access.log                    # -c 只统计匹配数量

# 搜索文件
find /opt/apps -name "appsettings*.json"               # 按名字找
find /opt/apps -name "*.log" -mtime +30                # 30天前的日志
find /opt/apps -name "*.log" -mtime +30 -delete        # 找到并删除
find / -name "dotnet" -type f                          # 找 dotnet 可执行文件
find /var/log -size +100M                              # 找大于100M的文件

# which / whereis：找命令在哪
which dotnet                  # /usr/bin/dotnet
which nginx                   # /usr/sbin/nginx
whereis docker                # 显示二进制、源码、手册页位置

磁盘空间管理

服务器跑着跑着磁盘满了，这是你一定会碰到的问题。

# 查看磁盘使用情况
df -h
# 输出示例：
# Filesystem      Size  Used Avail Use% Mounted on
# /dev/sda1        50G   38G   12G  76% /
# /dev/sdb1       200G   89G  111G  45% /data

# 查看当前目录下每个子目录的大小
du -sh *
# 输出示例：
# 2.3G    docker
# 150M    erp-api
# 80M     sso-server

# 找出最占空间的目录（从大到小）
du -sh /* 2>/dev/null | sort -rh | head -10
# 这条命令排查磁盘满的时候特别好用
# 从根目录开始，逐层往下找，定位到具体是哪个目录在吃空间

# Docker 占空间排查
docker system df              # 看镜像/容器/卷各占多少
docker system prune -a        # ⚠️ 清理所有未使用的（慎用）
docker image prune            # 只清理悬空镜像

磁盘满了的排查套路

Step 1: df -h 看哪个分区满了
Step 2: cd 到那个分区的挂载点
Step 3: du -sh * | sort -rh | head 找最大的目录
Step 4: cd 进去，重复 Step 3，直到定位到具体文件
Step 5: 确认可以删除后，rm 或 truncate

常见元凶：
  /var/log/       → 日志没有轮转
  /var/lib/docker → 废弃的镜像和容器
  /tmp/           → 临时文件没清理
  应用的 logs 目录  → 没配置日志保留策略

日志轮转配置

别等磁盘满了才想起来。装完应用就把日志轮转配上：

# /etc/logrotate.d/erp-api
/opt/apps/erp-api/logs/*.log {
    daily               # 每天轮转
    rotate 30           # 保留 30 天
    compress            # 压缩旧日志
    delaycompress       # 延迟一天再压缩
    missingok           # 日志文件不存在不报错
    notifempty          # 空文件不轮转
    copytruncate        # 复制后清空（不影响正在写入的进程）
}
# 测试轮转配置是否正确
logrotate -d /etc/logrotate.d/erp-api

# 手动执行一次轮转
logrotate -f /etc/logrotate.d/erp-api

文件压缩与传输

压缩/解压

# tar.gz（最常见）
tar -czf erp-api-v1.2.3.tar.gz erp-api/     # 打包压缩
tar -xzf erp-api-v1.2.3.tar.gz              # 解压
tar -xzf erp-api-v1.2.3.tar.gz -C /opt/apps # 解压到指定目录
tar -tzf erp-api-v1.2.3.tar.gz              # 只看内容，不解压

# zip（和 Windows 交互时用）
zip -r erp-api.zip erp-api/
unzip erp-api.zip -d /opt/apps

参数记忆：

  • -c create（创建）
  • -x extract（解压）
  • -z gzip（压缩算法）
  • -f file（指定文件名，必须放最后）
  • -v verbose（显示过程）
  • -C 指定解压目录

文件传输

# 从本机上传到服务器
scp publish.tar.gz deploy@192.168.1.100:/opt/apps/

# 从服务器下载到本机
scp deploy@192.168.1.100:/opt/apps/erp-api/logs/app.log ./

# 上传整个目录
scp -r ./publish/ deploy@192.168.1.100:/opt/apps/erp-api/

# rsync（增量同步，比 scp 快，适合部署）
rsync -avz --delete ./publish/ deploy@192.168.1.100:/opt/apps/erp-api/
# -a 归档模式（保留权限、时间戳等）
# -v 显示过程
# -z 压缩传输
# --delete 目标端多余的文件删掉（和源保持一致）

环境变量

.NET 应用经常通过环境变量传配置（数据库连接串、密钥等）。

# 查看所有环境变量
env
printenv

# 查看特定变量
echo $PATH
echo $ASPNETCORE_ENVIRONMENT
echo $DOTNET_ROOT

# 临时设置（当前会话有效）
export ASPNETCORE_ENVIRONMENT=Production
export ASPNETCORE_URLS="http://0.0.0.0:5000"

# 永久设置 —— 方法一：写到用户配置文件
echo 'export ASPNETCORE_ENVIRONMENT=Production' >> ~/.bashrc
source ~/.bashrc    # 使其立即生效

# 永久设置 —— 方法二：写到 /etc/profile.d/（对所有用户生效）
cat > /etc/profile.d/dotnet.sh << 'EOF'
export DOTNET_ROOT=/opt/dotnet
export PATH=$PATH:$DOTNET_ROOT
export ASPNETCORE_ENVIRONMENT=Production
EOF
source /etc/profile.d/dotnet.sh

# 在 systemd 服务中设置（推荐，只对该服务生效）
# 在 .service 文件的 [Service] 段加：
# Environment=ASPNETCORE_ENVIRONMENT=Production
# Environment=ASPNETCORE_URLS=http://0.0.0.0:5000

PATH 变量

PATH 决定了你在终端输入命令时，系统去哪些目录找可执行文件。

echo $PATH
# /usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/root/bin

# 装了 .NET 但输入 dotnet 提示找不到？大概率是 PATH 没配
which dotnet    # 如果没输出，说明 PATH 里没有

# 手动找到 dotnet 在哪
find / -name "dotnet" -type f 2>/dev/null
# /opt/dotnet/dotnet

# 加到 PATH
export PATH=$PATH:/opt/dotnet
dotnet --version    # 现在能用了

动手练习

拿到一台新 CentOS 服务器后，按顺序操作一遍：

  1. pwd → ls -la / → 熟悉根目录结构
  2. mkdir -p /opt/apps/test-api/logs → 创建应用目录
  3. echo "hello" > /opt/apps/test-api/logs/app.log → 写个测试日志
  4. tail -f /opt/apps/test-api/logs/app.log → 另开终端追踪（Ctrl+C 退出）
  5. df -h → 看磁盘使用情况
  6. du -sh /var/* → 看 /var 下谁最占空间
  7. find / -name "*.conf" -path "*/nginx/*" → 找 Nginx 配置文件
  8. grep -rn "listen" /etc/nginx/ → 在 Nginx 配置里搜端口
  9. 配置一个日志轮转：创建 /etc/logrotate.d/test-api
  10. tar -czf test-backup.tar.gz /opt/apps/test-api/ → 打个备份包

全部跑通了，说明文件系统这块你够用了。
