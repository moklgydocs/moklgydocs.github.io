网络模式

网络模式

容器之间怎么通信？容器怎么访问外网？外部怎么访问容器？搞清楚 Docker 网络模式就明白了。

四种网络模式

模式          特点                          适用场景
─────────────────────────────────────────────────────
bridge        默认模式，容器有独立网络栈      大多数场景
host          共享宿主机网络栈               对网络性能要求极高
none          没有网络                       安全隔离/批处理任务
自定义bridge   用户自建bridge网络             多容器互联（推荐）

bridge（默认模式）

每个容器有自己的 IP，通过 docker0 网桥和宿主机通信。

# 默认就是 bridge
docker run -d --name erp-api -p 5000:5000 erp-api:v1.0

# 查看容器 IP
docker inspect erp-api --format '{{.NetworkSettings.IPAddress}}'
# 172.17.0.2

# 宿主机访问容器：通过端口映射
curl http://localhost:5000

# 容器访问宿主机：用宿主机 IP 或 host.docker.internal
# 容器访问外网：默认可以（通过NAT）

自定义 bridge 网络（推荐）

默认 bridge 网络有个问题：容器间只能用 IP 互访，不能用容器名。自定义网络就可以。

# 创建自定义网络
docker network create app-network

# 容器加入同一个网络
docker run -d --name erp-api --network app-network -p 5000:5000 erp-api:v1.0
docker run -d --name postgres --network app-network postgres:16
docker run -d --name redis --network app-network redis:7-alpine

# 现在 erp-api 里可以直接用容器名访问
# 连接字符串写：Host=postgres;Port=5432;...
# Redis 连接写：redis:6379

这就是为什么 docker-compose 里可以用服务名互访 —— 它自动创建了自定义网络。

host 模式

容器直接用宿主机的网络，没有隔离，也没有端口映射。

docker run -d --name erp-api --network host erp-api:v1.0
# 应用监听 5000，宿主机的 5000 端口直接就能访问
# 不需要 -p 参数
优点：网络性能最好（没有 NAT 开销）
缺点：端口冲突（两个容器不能监听同一端口）
场景：对网络延迟敏感的场景

网络管理命令

# 查看所有网络
docker network ls
# NETWORK ID   NAME          DRIVER    SCOPE
# abc123       bridge        bridge    local
# def456       host          host      local
# 789ghi       app-network   bridge    local

# 查看网络详情（包括哪些容器在用）
docker network inspect app-network

# 创建网络
docker network create app-network
docker network create --subnet=172.20.0.0/16 app-network  # 指定子网

# 容器连接/断开网络
docker network connect app-network erp-api
docker network disconnect app-network erp-api

# 删除网络
docker network rm app-network
docker network prune              # 删除所有未使用的网络

实际场景

.NET API + PostgreSQL + Redis

# 1. 创建网络
docker network create erp-network

# 2. 启动数据库
docker run -d \
  --name postgres \
  --network erp-network \
  -e POSTGRES_PASSWORD=MySecret123 \
  -e POSTGRES_DB=erp \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16

# 3. 启动 Redis
docker run -d \
  --name redis \
  --network erp-network \
  redis:7-alpine

# 4. 启动应用
docker run -d \
  --name erp-api \
  --network erp-network \
  -p 5000:5000 \
  -e ConnectionStrings__Default="Host=postgres;Port=5432;Database=erp;Username=postgres;Password=MySecret123" \
  -e Redis__Connection="redis:6379" \
  erp-api:v1.0

# 应用里用 "postgres" 和 "redis" 作为主机名
# Docker DNS 会自动解析为对应容器的 IP

容器访问宿主机服务

有时候数据库装在宿主机上，容器里的应用要连它：

# Linux：用宿主机的真实 IP
docker run -d --name erp-api \
  -e ConnectionStrings__Default="Host=192.168.1.100;..." \
  erp-api:v1.0

# Docker Desktop（Mac/Windows）：用特殊域名
# host.docker.internal

# Linux 20.10+：也可以用
docker run -d --name erp-api \
  --add-host=host.docker.internal:host-gateway \
  -e ConnectionStrings__Default="Host=host.docker.internal;..." \
  erp-api:v1.0

排错

容器间连不通？

1. 在同一个网络里吗？
   → docker network inspect 网络名 → 看 Containers 列表

2. 用容器名还是 IP？
   → 默认 bridge 只能用 IP
   → 自定义网络才能用容器名

3. 端口对吗？
   → docker exec 容器A curl http://容器B:端口

4. 防火墙？
   → Docker 会自动配 iptables 规则
   → 但有些安全软件可能干扰
