Pipeline 语法

Pipeline 语法

Pipeline 是 Jenkins 的核心能力。代码即流水线，Jenkinsfile 跟着代码一起版本管理。

声明式 vs 脚本式

声明式（Declarative）：
  ✅ 结构清晰，大多数场景够用
  ✅ 推荐新手使用
  ❌ 灵活性有限

脚本式（Scripted）：
  ✅ 完全的 Groovy 编程能力
  ✅ 最大灵活性
  ❌ 复杂，不易维护

推荐使用声明式，99% 的场景够用了。

声明式 Pipeline 完整结构

pipeline {
    // 在哪里执行
    agent any

    // 环境变量
    environment {
        APP_NAME = 'erp-api'
        DOCKER_REGISTRY = 'registry.company.com'
    }

    // 构建选项
    options {
        timeout(time: 30, unit: 'MINUTES')    // 超时
        timestamps()                           // 日志加时间戳
        disableConcurrentBuilds()             // 禁止并发构建
        buildDiscarder(logRotator(numToKeepStr: '10'))  // 保留 10 次构建
    }

    // 触发器
    triggers {
        gitlab(triggerOnPush: true, triggerOnMergeRequest: true)
    }

    // 参数化构建
    parameters {
        string(name: 'VERSION', defaultValue: 'latest', description: '版本号')
        choice(name: 'ENV', choices: ['dev', 'staging', 'prod'], description: '部署环境')
        booleanParam(name: 'SKIP_TEST', defaultValue: false, description: '跳过测试')
    }

    // 阶段
    stages {
        stage('Checkout') {
            steps {
                git branch: 'develop',
                    url: 'http://gitlab.company.com/group/erp-api.git',
                    credentialsId: 'gitlab-cred'
            }
        }

        stage('Build') {
            steps {
                sh 'dotnet publish -c Release -o ./publish'
            }
        }

        stage('Test') {
            when {
                not { expression { params.SKIP_TEST } }
            }
            steps {
                sh 'dotnet test --no-build'
            }
        }

        stage('Docker Build') {
            steps {
                sh "docker build -t ${DOCKER_REGISTRY}/${APP_NAME}:${params.VERSION} ."
            }
        }

        stage('Deploy') {
            when { branch 'main' }
            steps {
                sh "docker push ${DOCKER_REGISTRY}/${APP_NAME}:${params.VERSION}"
            }
        }
    }

    // 构建后操作
    post {
        success {
            echo '✅ 构建成功！'
            updateGitlabCommitStatus name: 'build', state: 'success'
        }
        failure {
            echo '❌ 构建失败！'
            updateGitlabCommitStatus name: 'build', state: 'failed'
            mail to: 'dev@company.com',
                 subject: "❌ ${APP_NAME} 构建失败 #${BUILD_NUMBER}",
                 body: "查看: ${BUILD_URL}"
        }
        always {
            cleanWs()    // 清理工作空间
        }
    }
}

常用 steps

执行命令

// Shell（Linux）
sh 'dotnet build'
sh '''
    echo "多行命令"
    dotnet publish -c Release
    docker build -t myapp .
'''

// 带返回值
def version = sh(script: 'git describe --tags', returnStdout: true).trim()

// Windows
bat 'dotnet build'

文件操作

// 写文件
writeFile file: 'version.txt', text: "${BUILD_NUMBER}"

// 读文件
def content = readFile('version.txt')

// 检查文件
fileExists('Dockerfile')

// 归档产物
archiveArtifacts artifacts: 'publish/**', fingerprint: true

// 删除目录
dir('publish') { deleteDir() }

凭据

// 用户名密码
withCredentials([usernamePassword(
    credentialsId: 'gitlab-cred',
    usernameVariable: 'GIT_USER',
    passwordVariable: 'GIT_PASS')]) {
    sh "git clone http://${GIT_USER}:${GIT_PASS}@gitlab.company.com/repo.git"
}

// SSH 密钥
withCredentials([sshUserPrivateKey(
    credentialsId: 'deploy-ssh-key',
    keyFileVariable: 'SSH_KEY')]) {
    sh "ssh -i ${SSH_KEY} deploy@server 'docker compose up -d'"
}

// 文本密钥
withCredentials([string(credentialsId: 'api-token', variable: 'TOKEN')]) {
    sh "curl -H 'Authorization: Bearer ${TOKEN}' https://api.example.com"
}

SSH 部署

// 用 Publish Over SSH 插件
sshPublisher(publishers: [
    sshPublisherDesc(
        configName: 'prod-server',
        transfers: [
            sshTransfer(
                sourceFiles: 'publish/**',
                remoteDirectory: '/opt/apps/erp-api/',
                execCommand: 'cd /opt/apps/erp-api && docker compose up -d'
            )
        ]
    )
])

when 条件

stage('Deploy to Prod') {
    when {
        branch 'main'                           // 只在 main 分支
    }
}

stage('Deploy to Dev') {
    when {
        branch 'develop'
    }
}

stage('Test') {
    when {
        not { expression { params.SKIP_TEST } }  // 参数控制
    }
}

stage('Release') {
    when {
        tag pattern: "v\\d+\\.\\d+\\.\\d+", comparator: "REGEXP"  // tag 匹配
    }
}

stage('Manual Deploy') {
    when {
        beforeInput true
    }
    input {
        message "部署到生产环境？"
        ok "确认部署"
    }
}

并行执行

stage('Parallel Tests') {
    parallel {
        stage('Unit Test') {
            steps { sh 'dotnet test --filter Category=Unit' }
        }
        stage('Integration Test') {
            steps { sh 'dotnet test --filter Category=Integration' }
        }
        stage('Lint') {
            steps { sh 'dotnet format --verify-no-changes' }
        }
    }
}

Jenkinsfile 放在哪

项目仓库根目录：
  erp-api/
  ├── Jenkinsfile           ← 放这里
  ├── ERP.Host/
  ├── ERP.Application/
  └── docker-compose.yml

Jenkins Job 配置：
  Pipeline → Definition → Pipeline script from SCM
  → SCM: Git
  → Repository URL: http://gitlab.company.com/group/erp-api.git
  → Script Path: Jenkinsfile

好处：流水线跟着代码走，改流水线也走 MR 审核。
