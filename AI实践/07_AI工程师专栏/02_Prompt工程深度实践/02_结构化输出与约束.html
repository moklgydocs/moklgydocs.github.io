结构化输出与 JSON Schema 约束

为什么需要结构化输出

LLM 默认输出自然语言文本，但生产系统需要结构化数据：

  • API 间传递需要 JSON
  • 数据库写入需要固定 Schema
  • 前端渲染需要确定字段
  • 自动化流程需要可解析的格式

三种实现方式

方式 1：Prompt 内约束（最通用）

prompt = """请分析以下代码的安全问题，严格按 JSON 格式输出：

{
  "issues": [
    {
      "type": "sql_injection",
      "line": 3,
      "severity": "critical",
      "description": "字符串拼接构造SQL",
      "fix": "使用参数化查询"
    }
  ],
  "risk_score": 85,
  "summary": "发现1个严重安全漏洞"
}

代码：
{code}

只输出JSON，不要其他内容。"""

优点：所有模型通用 缺点：不保证 100% 遵守

方式 2：Function Calling 约束

tools = [{
    "type": "function",
    "function": {
        "name": "analyze_code",
        "description": "分析代码安全问题",
        "parameters": {
            "type": "object",
            "properties": {
                "issues": {
                    "type": "array",
                    "items": {
                        "type": "object",
                        "properties": {
                            "type": {"type": "string", "enum": ["sql_injection", "xss", "auth_bypass", "data_leak"]},
                            "severity": {"type": "string", "enum": ["critical", "high", "medium", "low"]},
                            "line": {"type": "integer"},
                            "description": {"type": "string"},
                            "fix": {"type": "string"}
                        },
                        "required": ["type", "severity", "description"]
                    }
                },
                "risk_score": {"type": "integer", "minimum": 0, "maximum": 100},
                "summary": {"type": "string"}
            },
            "required": ["issues", "risk_score", "summary"]
        }
    }
}]

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "分析这段代码..."}],
    tools=tools,
    tool_choice={"type": "function", "function": {"name": "analyze_code"}}
)

优点：强约束，Schema 校验 缺点：模型需支持 Function Calling

方式 3：Structured Output（OpenAI 专用）

from pydantic import BaseModel
from openai import OpenAI

class Issue(BaseModel):
    type: str
    severity: str
    line: int | None = None
    description: str
    fix: str | None = None

class CodeAnalysis(BaseModel):
    issues: list[Issue]
    risk_score: int
    summary: str

client = OpenAI()
response = client.beta.chat.completions.parse(
    model="gpt-4o-2024-08-06",
    messages=[{"role": "user", "content": "分析这段代码..."}],
    response_format=CodeAnalysis,
)

analysis = response.choices[0].message.parsed
print(analysis.risk_score)  # int 类型，保证是数字

优点：最强约束 + Pydantic 校验 缺点：仅部分模型支持

生产级防御代码

无论哪种方式，都需要兜底处理：

import json
import re
from pydantic import ValidationError

def safe_parse_llm_output(raw: str, schema: type) -> BaseModel | None:
    """安全解析 LLM 输出，带重试和降级"""
    # 1. 尝试直接解析
    try:
        data = json.loads(raw)
        return schema.model_validate(data)
    except (json.JSONDecodeError, ValidationError):
        pass

    # 2. 尝试提取 JSON 块
    json_match = re.search(r'```(?:json)?\s*(.*?)```', raw, re.DOTALL)
    if json_match:
        try:
            data = json.loads(json_match.group(1))
            return schema.model_validate(data)
        except (json.JSONDecodeError, ValidationError):
            pass

    # 3. 尝试用花括号计数提取 JSON（处理嵌套）
    extracted = _extract_json_from_text(raw)
    if extracted:
        try:
            data = json.loads(extracted)
            return schema.model_validate(data)
        except (json.JSONDecodeError, ValidationError):
            pass

    return None

def _extract_json_from_text(text: str) -> str | None:
    """从文本中提取 JSON，处理嵌套花括号"""
    # 找到第一个 { 的位置
    start = text.find('{')
    if start == -1:
        return None

    # 用栈匹配花括号
    depth = 0
    for i in range(start, len(text)):
        if text[i] == '{':
            depth += 1
        elif text[i] == '}':
            depth -= 1
            if depth == 0:
                return text[start:i+1]

    # 没有匹配的闭合花括号
    return None

选型建议

场景推荐方式原因
OpenAI/GPT 系列Structured Output最强约束，类型安全
DeepSeek/Qwen（支持 FC）Function Calling兼容性好，约束力强
任何模型Prompt 内约束 + 解析兜底通用性最强

生产提示

永远不要假设 LLM 会 100% 遵守格式约束。在解析层做防御性编程，处理 JSON 格式错误、字段缺失、类型不匹配等异常。
