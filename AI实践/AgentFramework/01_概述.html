概述与第一个代理

概述与第一个代理

版本基准：prerelease（框架仍在快速演进，API 可能变动）

先搞清楚它是什么

定位

Microsoft Agent Framework 是微软官方的 AI 代理应用开发框架。它不是大模型本身，也不是聊天界面，而是一套 SDK 和运行时——帮你把 LLM 封装成"能干活、能协作、能记住事、能走流程"的应用程序。

直接调 OpenAI API 像雇临时工，每次说话都没记忆，只能一问一答；用 Agent Framework 像雇正式员工，有岗位说明、有工具、有记忆、能协作、能按流程办事。

0.2 它解决什么问题

不用框架、自己裸写 LLM 应用，会撞上这几个坑：

  • 没记忆：每次请求都是独立的，用户说"刚才那个再改改"，模型不知道"刚才"是啥
  • 工具调用乱：想让模型查数据库、发邮件、调 API，得自己写一堆 if/else 解析模型输出
  • 多代理协作难：让"写手代理"写稿、"审稿代理"审稿、"排版代理"排版，自己编排流程会乱
  • 状态丢失：长任务中途崩了，重做得从头来
  • 生产级特性缺：日志、遥测、限流、人审（human-in-the-loop）都得自己造

Agent Framework 把这些都封装好了，你只需要关注业务逻辑。

0.3 它和 AutoGen / Semantic Kernel 的关系

这是新手最容易懵的点。官方原话：

Agent Framework 是下一代 Semantic Kernel 和 AutoGen。

具体说，AutoGen 是微软早期的多代理框架，主打简单抽象；Semantic Kernel 是企业级 SDK，主打类型安全、状态管理、遥测、与 .NET 深度整合。两个框架各自发展，定位有重叠。Agent Framework 是同一团队开发的继承者，把 AutoGen 的简单和 SK 的企业级特性揉到一起，再加了一层图形化工作流。AutoGen 和 SK 现在都进入维护模式。

所以结论很简单：新学的直接学 Agent Framework，别再从 AutoGen 或 SK 起步。

0.4 两大核心抽象：Agent 和 Workflow

这是整个框架的两条主线，理解了这两个概念，后面所有内容都是它们的展开。

Agent 是一个能调用 LLM 和工具的"智能员工"，适合开放式、对话式、需要 LLM 自主决策的场景，比如客服对话、研究助手。控制权在 LLM 手里——它自己决定调什么工具、怎么回答。

Workflow 是把多个 Agent 和函数串起来的"流程图"，适合步骤明确、需要显式控制执行顺序的场景，比如"先查库存→再生成报价单→发邮件"这种固定流程。控制权在开发者手里——流程写死，LLM 只在节点里被调用。

官方给了一条决策原则：如果能用普通函数解决问题，就别用 AI 代理。只有当任务真的需要 LLM 的理解和决策能力时才上 Agent，否则是杀鸡用牛刀——又慢又贵还不稳定。

0.5 框架的基础构建块

官方文档提到这些 building blocks，先了解概念，不必现在深究：

  • 模型客户端（Model Client）：连接 LLM 的适配器，支持 Azure OpenAI、OpenAI、Anthropic、Ollama、Microsoft Foundry 等
  • 代理会话（Agent Session）：管理对话状态，让 Agent 有"记忆"
  • 上下文提供程序（Context Provider）：给 Agent 提供记忆/RAG 上下文
  • 中间件（Middleware）：拦截 Agent 的调用，类似 ASP.NET 的 middleware 管道，可加日志、过滤、改写
  • MCP 客户端（MCP Client）：连接 Model Context Protocol 服务器，复用外部工具

第一个代理（Hello Agent）

1.1 装 NuGet 包

C# 项目要装三个包：

dotnet add package Azure.AI.Projects --prerelease
dotnet add package Azure.Identity
dotnet add package Microsoft.Agents.AI.Foundry --prerelease
  • Azure.AI.Projects：Azure AI 项目的客户端 SDK，用来连 Azure AI Foundry 项目
  • Azure.Identity：Azure 的身份认证（DefaultAzureCredential 等）
  • Microsoft.Agents.AI.Foundry：Agent Framework 的核心包（Foundry 适配版），prerelease 因为框架还在预览阶段

--prerelease 必须加，现在还不是稳定版。

1.2 最小可运行代码

using System;
using Azure.AI.Projects;
using Azure.Identity;
using Microsoft.Agents.AI;

// 1. 从环境变量读配置
var endpoint = Environment.GetEnvironmentVariable("AZURE_OPENAI_ENDPOINT")
    ?? throw new InvalidOperationException("Set AZURE_OPENAI_ENDPOINT");
var deploymentName = Environment.GetEnvironmentVariable("AZURE_OPENAI_DEPLOYMENT_NAME")
    ?? "gpt-4o-mini";

// 2. 创建 Agent
AIAgent agent = new AIProjectClient(new Uri(endpoint), new DefaultAzureCredential())
    .AsAIAgent(
        model: deploymentName,                    // 用哪个模型
        instructions: "You are a friendly assistant. Keep your answers brief.",  // 系统提示词
        name: "HelloAgent");                      // 给 Agent 起个名字

// 3. 运行 Agent
Console.WriteLine(await agent.RunAsync("What is the largest city in France?"));

1.3 逐行讲解

读配置。AZURE_OPENAI_ENDPOINT 是你的 Azure OpenAI 服务地址，类似 https://xxx.openai.azure.com/。AZURE_OPENAI_DEPLOYMENT_NAME 是你在 Azure 上部署模型时起的名字，比如 gpt-4o-mini。从环境变量读是为了不把密钥硬编码进代码。

创建 Agent。拆开这行链式调用看：

new AIProjectClient(new Uri(endpoint), new DefaultAzureCredential())

AIProjectClient 是连接 Azure AI 项目的客户端。DefaultAzureCredential 是 Azure 的"万能凭证"，会按顺序尝试本地登录、VS Code 登录、CLI 登录、Managed Identity 等。

官方有警告：DefaultAzureCredential 只适合开发环境。生产环境要用 ManagedIdentityCredential 这类特定凭证，否则有安全风险和性能问题。

.AsAIAgent(model: ..., instructions: ..., name: ...)

这是扩展方法，把 AIProjectClient 包装成 AIAgent 对象。model 指定用哪个模型，instructions 是系统提示词，相当于告诉这个员工"你的岗位是什么、怎么干活"，name 是 Agent 的名字，后面多代理协作时用来区分。

AIAgent 是 Agent Framework 里"代理"的根类型，后面所有功能都围绕它扩展。

运行 Agent。

await agent.RunAsync("What is the largest city in France?")

RunAsync 异步执行，传入用户提问，返回 Agent 的回答（string）。还有个流式版本：

await foreach (var update in agent.RunStreamingAsync("Tell me a one-sentence fun fact."))
{
    Console.Write(update);  // 一个 token 一个 token 地打印
}

流式响应是模型边生成边返回，用户体验更好，像 ChatGPT 那种打字效果。

1.4 小结

到这里你看到的 Agent 本质上就是"模型客户端 + 指令 + 名字"，是对 LLM 调用的封装。AIAgent 是核心类型，RunAsync / RunStreamingAsync 是基本调用方法。instructions 决定 Agent 的人格和风格，是塑造行为的第一道旋钮。

现在这个 Agent 还是个光杆司令——没记忆、没工具、没同事，后面几章开始给它加装备。

学习路线图（4 周计划）

阶段一：概念建立（1 周）— 你现在在这

目标是看懂官方文档每个章节在讲什么，能跟人讲清楚 Agent Framework 是什么。

阅读顺序按依赖关系排，不太建议跳：

Day官方页面学完能回答
1overview（概述）框架是什么、解决什么、和 SK/AutoGen 关系
2get-started/your-first-agent创建第一个 Agent，理解 AIAgent 类型
3get-started/add-tools给 Agent 加工具，理解 function calling
4get-started/multi-turn多轮对话，理解 Session 状态管理
5get-started/memory内存和持久化，理解记忆怎么存
6get-started/workflows工作流，理解 Agent vs Workflow 边界
7get-started/hosting托管，理解怎么部署到生产

这一阶段的产出是每章一份笔记（Markdown），用自己话复述。

阶段二：深入核心（1 周）

  • Agents 章节：tools / skills / conversations / providers
  • Workflows 章节：executors / edges / workflows
  • 理解每个抽象的边界：什么时候用什么

阶段三：动手实战（1 周）

  • 本地搭环境（.NET SDK + Azure 账号 + API key）
  • 跑通官方 samples
  • 自己写一个小项目（比如"客服 Agent + 工单工作流"）

阶段四：进阶集成（1 周）

  • 持久扩展（Durable Extension）— 长任务、人审
  • A2A 协议 — 多代理跨服务通信
  • DevUI — 调试可视化
