全局样式与字体

全局样式与字体

本步目标

配置全局样式文件（Tailwind v4 语法）、Geist 字体、亮暗主题 CSS 变量体系，让项目具备完整的视觉基础。

前置知识

Tailwind CSS v4 的新语法

Tailwind v4 相比 v3 有重大变化：

特性v3v4
入口指令@tailwind base; @tailwind components; @tailwind utilities;@import "tailwindcss";
设计令牌tailwind.config.js 中的 theme.extendCSS 中的 @theme 块
配置文件必须有 tailwind.config.js不再需要（零配置）
内容检测content: ["./src/**/*.{ts,tsx}"]自动检测

后端类比：Tailwind v3 → v4 的迁移类似 .NET Framework → .NET Core 的迁移——配置方式完全不同，但核心概念不变。v4 的 @theme 类比 appsettings.json 的配置节，@import 类比 Program.cs 中的 builder.Services.AddXXX()。

CSS 变量（Custom Properties）

CSS 变量是浏览器原生的样式变量机制：

:root {
  --background: oklch(1 0 0);       /* 定义变量 */
}

.dark {
  --background: oklch(0.145 0 0);    /* 暗黑模式覆盖 */
}

.card {
  background-color: var(--background); /* 使用变量 */
}

后端类比：CSS 变量类比 WPF 的 ResourceDictionary——你定义一组命名的资源（颜色、间距），在运行时可以通过切换字典来更换主题。也类似 .NET 的 IConfiguration——定义配置键值对，运行时按需读取。

oklch 色彩空间

oklch 是一种感知均匀的色彩空间，比 hsl 更先进：

hsl: 色相(H) 饱和度(S) 亮度(L)
  问题：同样的亮度值，黄色看起来比蓝色亮很多（感知不均匀）

oklch: 亮度(L) 色度(C) 色相(H)
  优势：同样的亮度值，不同色相看起来确实一样亮（感知均匀）
色彩空间感知均匀性浏览器支持shadcn/ui 使用
hsl不均匀全部v3 之前
oklch均匀现代浏览器v4 推荐

为什么感知均匀很重要？ 当你调整亮暗主题的颜色时，oklch 确保亮色和暗色的视觉对比度一致。用 hsl 可能出现"暗色模式下某些颜色看起来太亮"的问题。

next-themes 的 dark mode 机制

next-themes 使用 class 策略实现暗黑模式：

1. ThemeProvider 检测系统偏好 / localStorage 中的主题设置
2. 给 <html> 标签添加或移除 class="dark"
3. CSS 中 .dark 选择器覆盖 :root 中的 CSS 变量
4. 所有使用 CSS 变量的组件自动更新样式

后端类比：类似 IOptionsMonitor<T> 的 Change Token 机制——主题配置变化时，所有依赖主题的组件自动响应更新，无需手动通知。

src/main.tsx 完整代码

import { StrictMode } from "react"
import { createRoot } from "react-dom/client"
import { ThemeProvider } from "next-themes"
import App from "./App"
import "@/styles/index.css"

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <ThemeProvider attribute="class" defaultTheme="light" enableSystem disableTransitionOnChange>
      <App />
    </ThemeProvider>
  </StrictMode>
)

简单验证页面：亮/暗切换按钮

// src/App.tsx
import { useTheme } from "next-themes"
import { Button } from "@/components/ui/button"
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card"
import { Sun, Moon } from "lucide-react"

function App() {
  const { theme, setTheme } = useTheme()

  return (
    <div className="min-h-screen flex items-center justify-center bg-background p-8">
      <Card className="w-[400px]">
        <CardHeader>
          <CardTitle>主题切换验证</CardTitle>
        </CardHeader>
        <CardContent>
          <p className="mb-4 text-muted-foreground">当前主题：{theme}</p>
          <Button
            onClick={() => setTheme(theme === "dark" ? "light" : "dark")}
            className="gap-2"
          >
            {theme === "dark" ? <Sun className="h-4 w-4" /> : <Moon className="h-4 w-4" />}
            切换到{theme === "dark" ? "亮色" : "暗色"}模式
          </Button>
        </CardContent>
      </Card>
    </div>
  )
}

export default App

代码讲解

Tailwind v4 的变化

不再需要 tailwind.config.js：v4 通过 @theme 块在 CSS 中定义设计令牌，取代了 v3 的 JS 配置文件：

/* v3：tailwind.config.js */
module.exports = {
  theme: {
    extend: {
      fontFamily: { sans: ["Inter", "system-ui"] }
    }
  }
}

/* v4：直接在 CSS 中定义 */
@theme inline {
  --font-sans: "Geist Variable", system-ui, sans-serif;
}

@theme inline 的含义：inline 表示这些变量只在当前 CSS 文件中定义，不会生成独立的 CSS 层。这样避免了样式优先级冲突。

CSS 变量的设计令牌体系

shadcn/ui 定义了一整套语义化的 CSS 变量，形成"设计令牌"体系：

--background    → 页面背景色
--foreground    → 页面前景色（文字颜色）
--primary      → 主操作色（主按钮）
--secondary    → 次要操作色
--muted        → 弱化区域背景色
--destructive  → 危险操作色（删除按钮）
--border       → 边框颜色
--ring         → 焦点环颜色

每个变量都有对应的 -foreground 变量，确保前景和背景的对比度。

后端类比：这套变量体系类似 .NET 的 IConfiguration——你定义一组语义化的配置键（如 ConnectionStrings:Default），运行时根据环境（Development/Production）读取不同的值。亮色模式和暗色模式就是两个不同的"环境"。

oklch vs hsl 的视觉均匀性差异

hsl 的"50% 亮度"：
  黄色 hsl(60, 100%, 50%) → 看起来非常亮
  蓝色 hsl(240, 100%, 50%) → 看起来暗得多
  → 同样的"50% 亮度"，视觉感受完全不同

oklch 的"50% 亮度"：
  黄色 oklch(0.5 0.2 90) → 看起来确实是中等亮度
  蓝色 oklch(0.5 0.2 270) → 看起来也是中等亮度
  → 感知均匀，设计调参时更可预测

ThemeProvider attribute="class" 工作原理

<ThemeProvider attribute="class" defaultTheme="light" enableSystem disableTransitionOnChange>
Prop作用
attribute="class"通过给 <html> 添加/移除 class="dark" 来切换主题
defaultTheme="light"默认亮色模式
enableSystem检测系统偏好（如果用户系统设了暗色，自动跟随）
disableTransitionOnChange切换主题时禁用 CSS transition，避免页面元素逐个变色的闪烁

工作流程：

1. 页面加载 → ThemeProvider 检查 localStorage 有无存储的主题
2. 没有 → 检查系统偏好（enableSystem）
3. 没有 → 使用 defaultTheme="light"
4. 确定主题 → 给 <html> 添加 class="dark" 或移除
5. CSS 变量切换 → 所有组件自动更新
6. 主题选择写入 localStorage 持久化

踩坑提醒

  1. Tailwind v4 和 v3 语法不兼容：不能混用 @tailwind base 和 @import "tailwindcss"。如果网上搜到的教程用 v3 语法，需要自行转换。
  2. @theme inline 必须写在 index.css 中：不能拆分到其他文件再 @import，因为 inline 关键字要求变量和当前 CSS 文件在同一个作用域。
  3. 字体文件通过 npm 包引入而非 CDN：@import "@fontsource-variable/geist" 从 node_modules 中引入字体，离线可用、不依赖外部 CDN。不要换成 CDN 链接引入。
  4. disableTransitionOnChange 避免暗黑切换闪烁：不加这个 prop，切换主题时每个元素会逐个执行 CSS transition 变色，页面会出现"波浪式闪烁"。加上后切换瞬间完成，视觉更干净。
