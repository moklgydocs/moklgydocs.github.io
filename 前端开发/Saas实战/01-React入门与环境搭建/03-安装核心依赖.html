安装核心依赖

安装核心依赖

这一步解决什么问题？

安装路由、状态管理、HTTP 客户端、CSS 框架、UI 组件、图标、动画等全部项目依赖，理解每个包的用途和分类。这一步完成后，package.json 中将包含 AdminWeb 所需的全部运行时和开发时依赖。

前置知识

前端依赖的分类：dependencies vs devDependencies

{
  "dependencies": {
    "react": "^19.2.6"       // 运行时依赖——打包进最终产物
  },
  "devDependencies": {
    "typescript": "~6.0.2"   // 开发时依赖——不进最终产物
  }
}
分类何时安装是否进入生产包后端类比
dependenciespnpm add xxx是NuGet 的 PackageReference（运行时依赖）
devDependenciespnpm add -D xxx否NuGet 的 DotNetCliToolReference / 开发时工具

判断标准：代码里 import 了这个包，就是 dependencies；只有构建/检查时用到，就是 devDependencies。

⚠️ 【易错点】误把运行时依赖装到 devDependencies：开发时一切正常（pnpm dev 会加载所有依赖），但生产构建时 devDependencies 不打包，运行时找不到模块直接报错。反过来问题不大——把开发工具装到 dependencies 只是增加了生产包体积，不会报错。

版本号语义：SemVer

^19.2.6  →  兼容 19.x.x（主版本号不变）
~6.0.2   →  兼容 6.0.x（次版本号不变）
19.2.6   →  精确锁定
  • major（主版本号）：不兼容的 API 变更
  • minor（次版本号）：向后兼容的新功能
  • patch（修订号）：向后兼容的 bug 修复

后端类比：和 .NET 的 SemVer 完全一致。^19.2.6 类比 NuGet 的浮动版本 [19.2.6, 20.0.0)。

⚠️ 【易错点】^ 允许升级 minor 版本，但 pnpm-lock.yaml 锁定了具体版本。只有删除 lock 文件再 pnpm install 才会升级。所以团队协作中 pnpm-lock.yaml 必须提交到 Git。

为什么有些用 pnpm add 有些用 pnpm add -D？

运行时要用到的包（React、axios、zustand 等）必须放在 dependencies，否则生产环境打包后找不到。只在开发时用的工具（TypeScript、ESLint、类型声明）放 devDependencies，减小生产包体积。

代码实现

路由

pnpm add react-router react-router-dom
  • react-router：路由核心库，提供路由匹配、导航等基础能力
  • react-router-dom：浏览器端的路由绑定，提供 <BrowserRouter>、<Link>、<Navigate> 等组件

后端类比：相当于 ASP.NET Core 的 Endpoint Routing——app.UseEndpoints() 定义路由模板，[Route] 特性声明路由。区别是前端路由在客户端匹配 URL，不请求服务器；后端路由是服务端匹配请求路径。

🤔 导师提问：为什么要装两个包（react-router + react-router-dom）？提示：React Native 应用用 react-router-native 而不是 react-router-dom。核心库和平台绑定的分离，和 .NET 的 Microsoft.Extensions.DependencyInjection.Abstractions 与 Microsoft.Extensions.DependencyInjection 的分离有什么相似之处？

状态管理

pnpm add zustand
  • zustand：极简的状态管理库。比 Redux 简洁得多——不需要 reducer、action、dispatch 那套模板代码，一个 create 函数搞定

后端类比：相当于一个客户端的 Scoped Service + 内存缓存。全局共享数据（如当前用户、菜单树）存在 zustand store 中，任何组件都能读取。类似 MediatR 的发布-订阅模式，但更轻量。

🤔 导师提问：为什么选 zustand 而不是 Redux？Redux 有中间件、DevTools、时间旅行调试，看起来更强大。提示：想想你真的需要 Redux 的那套模板代码吗？zustand 一个 create 函数就能做到的事，Redux 需要多少个文件？

⚠️ 【设计取舍】zustand vs Redux：AdminWeb 选择 zustand 的三个原因——①API 极简（一个 create 函数 vs Redux 的 action/reducer/store 三件套）；②无需 Provider 包裹（Redux 必须在根组件包 <Provider>）；③内置 persist 中间件（Token 持久化只需一行代码）。缺点：生态不如 Redux 丰富，中间件少。

HTTP 客户端

pnpm add axios
  • axios：最流行的 HTTP 客户端，支持拦截器（interceptor）、请求/响应转换、自动 JSON 解析、请求取消等

后端类比：相当于 HttpClient + DelegatingHandler 管道。axios 的请求拦截器类似 ASP.NET Core 的中间件，可以在请求发出前插入 Token、在响应返回后统一处理错误码。

🤔 导师提问：浏览器原生的 fetch 也能发请求，为什么还要装 axios？提示：axios 的拦截器机制是 fetch 没有的。如果用 fetch，你要怎么实现"每个请求自动注入 Bearer Token"和"401 自动刷新"？

CSS 框架

pnpm add tailwindcss @tailwindcss/vite
  • tailwindcss：原子化 CSS 框架，通过组合工具类构建 UI（如 flex items-center gap-4 p-6 rounded-lg shadow-md）
  • @tailwindcss/vite：Tailwind 的 Vite 插件，提供即时编译和 HMR

后端类比：Tailwind 的"原子化"思路类似 LINQ——不写命令式的 CSS 类，而是声明式组合工具类。就像 LINQ 用 .Where().Select().OrderBy() 组合查询，Tailwind 用 flex p-4 rounded 组合样式。

⚠️ 【设计取舍】Tailwind v4 使用 @tailwindcss/vite Vite 插件而非传统的 PostCSS 插件（postcss + tailwindcss）。Vite 插件方式编译更快，但和某些 PostCSS 插件不兼容。AdminWeb 不使用额外的 PostCSS 插件，所以选择 Vite 插件方式。

图标

pnpm add lucide-react
  • lucide-react：Lucide 图标库的 React 封装，提供 1000+ 精美 SVG 图标，支持尺寸/颜色/描边宽度自定义

Toast 通知

pnpm add sonner
  • sonner：轻量级 Toast 通知库，提供顶部弹出的提示消息，支持自动消失、可关闭、可堆叠、自定义样式

后端类比：类似 ASP.NET Core 的 TempData，用于一次性消息提示。但 Toast 更强大——可以展示成功/错误/警告等不同级别，还能堆叠显示多条。

工具函数

pnpm add clsx tailwind-merge class-variance-authority
  • clsx：条件类名拼接工具。clsx("foo", condition && "bar") → "foo bar" 或 "foo"
  • tailwind-merge：智能合并 Tailwind 类名，处理冲突。twMerge("px-2", "px-4") → "px-4"
  • class-variance-authority (CVA)：组件变体管理工具，定义组件的不同样式变体（如 Button 的 primary/secondary/outline 变体）

后端类比：clsx 像 string.Join 过滤 null 后拼接；twMerge 像 CSS cascade 的智能版，知道 p-4 应该覆盖 p-2；CVA 像工厂模式，根据参数返回不同的类名组合。

🤔 导师提问：clsx 只做拼接不做冲突解决，twMerge 只做冲突解决不做条件拼接——为什么一个库不能同时做两件事？提示：这叫"单一职责原则"，和后端的 SOLID 原则一样。如果 twMerge 也要处理条件逻辑，它的代码会变得多复杂？

主题切换

pnpm add next-themes
  • next-themes：亮/暗主题切换库，支持系统偏好检测、localStorage 持久化、class 策略（给 <html> 加 dark class）

⚠️ 【易错点】next-themes 名字带"next"但不是 Next.js 专属。它同时支持 SPA 和 Next.js，AdminWeb 作为纯 SPA 也使用它。不要因为名字而跳过这个库。

动画

pnpm add framer-motion
  • framer-motion：React 动画库，提供声明式的动画 API、弹簧物理动画、手势交互、布局动画、退出动画等

后端类比：类似 CSS transitions 的增强版，但更像是编程式的动画引擎——你可以用 spring（弹簧）参数控制动画曲线，而不是手写 cubic-bezier。

⚠️ 【性能陷阱】framer-motion 包体积较大（~30KB gzipped）。AdminWeb 在登录页和部分交互中使用了动画，如果你只需要简单的 CSS transition，可以考虑不用此库。但 AdminWeb 已选择引入，后续页面开发中会用到 AnimatePresence（退出动画）和 motion（布局动画）。

字体

pnpm add @fontsource-variable/geist @fontsource-variable/geist-mono
  • @fontsource-variable/geist：Geist 可变字体（正文字体），由 Vercel 设计
  • @fontsource-variable/geist-mono：Geist Mono 可变字体（等宽字体，用于代码块）

为什么用 Variable Font？ 可变字体是 OpenType 字体规范的新特性，一个字体文件包含所有字重（100-900），而不是每个字重一个文件。好处：更小的文件大小、更平滑的字重变化、离线可用（npm 包而非 CDN）。

🤔 导师提问：字体通过 npm 包引入而非 Google Fonts CDN——这和后端的 NuGet 包 vs 在线下载有什么区别？npm 字体包的好处是离线可用、版本锁定。但缺点是什么？提示：字体文件会增加 node_modules 体积和首次打包时间。

类型声明与构建工具（开发依赖）

pnpm add -D @types/node @rolldown/plugin-babel
  • @types/node：Node.js API 的类型声明，让 TypeScript 认识 path、__dirname 等 Node.js 全局变量（在 vite.config.ts 中用到）
  • @rolldown/plugin-babel：Rolldown 的 Babel 插件，用于集成 React Compiler（下一步配置 vite.config.ts 时需要）

⚠️ 【易错点】@types/node 是开发依赖——用 pnpm add -D 而非 pnpm add。如果把 @types/node 装到 dependencies，生产环境打包会多出无用的类型声明文件。

⚠️ 【易错点】@rolldown/plugin-babel 也是开发依赖。它是构建时工具，运行时不需要。如果漏装这个包，下一步 vite.config.ts 中 import babel from "@rolldown/plugin-babel" 会报错。

代码讲解

为什么不直接装 shadcn/ui 的 npm 包？

shadcn/ui 的核心理念是 "拥有你的代码"（You own the code）。它不是一个 npm 包，而是一个组件代码生成器：

传统 UI 库（Ant Design / Element Plus）：
  pnpm add antd → 引入编译好的 npm 包 → 你的代码依赖上游

shadcn/ui：
  pnpm dlx shadcn add button → 源码复制到 src/components/ui/button.tsx → 你拥有完整代码
特性npm 包方式shadcn/ui 方式
代码所有权上游库你的项目
自定义自由度受限（需要覆盖样式）完全自由（直接改源码）
版本更新pnpm update手动 shadcn add 覆盖
包体积整个库只安装用到的组件

后端类比：npm 包方式类似运行时反射——你依赖外部程序集，行为受上游控制。shadcn/ui 方式类似 .NET Source Generator——代码在编译时生成到你的项目中，你拥有完全的控制权。后续步骤会详细讲解 shadcn/ui 的初始化。

clsx + tailwind-merge + CVA 三者的分工

用户输入: "px-4", isActive && "bg-blue-500", variantClass
    │
    ▼
clsx(): 条件拼接，处理 false/undefined/null
    → "px-4 bg-blue-500 variant-class"
    │
    ▼
twMerge(): 解决 Tailwind 类冲突
    → "px-4 bg-blue-500 variant-class"  (如果有 px-2 px-4，只保留 px-4)
    │
    ▼
最终类名字符串
  • clsx：只管拼接，不管语义。clsx("px-2", "px-4") → "px-2 px-4"（两个都保留了！）
  • twMerge：理解 Tailwind 的语义。twMerge("px-2", "px-4") → "px-4"（后者覆盖前者）
  • CVA：定义变体规则，输出类名。不处理合并，只负责"根据 variant 输出对应的类名组合"

它们组合起来就是 cn() 函数（后续步骤创建）：twMerge(clsx(inputs))。

踩坑提醒

  1. 版本锁定：团队协作时，pnpm-lock.yaml 必须提交到 Git。不要手动删除 lock 文件再 pnpm install，这会导致版本漂移。
  2. peerDependencies 警告：安装时如果看到 WARN peer dep missing，说明某个包期望的宿主包版本和你安装的不一致。大多数情况可以忽略，但如果运行报错，按提示安装对应版本。
  3. pnpm 的 strict-peer-dependencies：pnpm 默认严格检查 peer 依赖。如果安装失败，可以临时加 --no-strict-peer-dependencies，但不建议长期使用。
  4. 不要用 pnpm add shadcn 代替 pnpm dlx shadcn：shadcn 是 CLI 工具，不是运行时依赖。它应该在命令行直接执行，而不是作为项目依赖。
  5. 网络问题：如果 pnpm add 速度很慢，可能是 npm registry 在国内访问不稳定。可以配置镜像：pnpm config set registry https://registry.npmmirror.com。类比后端：这就像配置 NuGet 镜像源。
  6. 安装后验证：执行 pnpm list --depth 0 确认所有包都已安装。如果某个包缺失，重新 pnpm install。
