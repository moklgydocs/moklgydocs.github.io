07 - 功能开关：运行时特性控制的三种操作

07 - 功能开关：运行时特性控制的三种操作

这一步解决什么问题？
功能开关（Feature Flag）让运营人员在运行时控制租户的功能访问，无需重新部署。不同于配置中心的键值对管理，功能开关是布尔型的控制——某个功能对某个租户是开还是关。本节实现功能开关的查询、值获取和缓存失效操作。

ASP.NET Core 开发者的直觉：featuresApi.isEnabled() 对应 FeatureManager.IsEnabledAsync()，featuresApi.getValue() 对应 FeatureManager.GetFeatureValueAsync()，featuresApi.invalidateCache() 对应 IMemoryCache.Remove()。功能开关通常有后端缓存（如 Redis），invalidateCache 清除缓存后下次请求会重新从数据库加载。

前置知识

  • 理解配置中心（模块 09）与功能开关的区别——前者管理服务级配置，后者管理租户级功能访问
  • 熟悉 ASP.NET Core 的 FeatureManager 功能开关框架
  • 了解上一节（06-租户详情）中 Switch 切换的交互模式

一、功能开关 vs 配置中心

先区分两个容易混淆的概念：

维度配置中心功能开关
数据类型任意值（string）布尔值（enabled/disabled）+ 可选 JSON 值
管理粒度按服务按租户 + 按特性
修改方式直接编辑值检查启用/获取值/清除缓存
页面入口/config/*/ops/features
后端类比IConfiguration["Key"]FeatureManager.IsEnabledAsync("Key")
缓存5 秒轮询热重载Redis 缓存 + 手动失效

关键理解：配置中心管理的是服务级别的配置（如数据库连接串），功能开关管理的是租户级别的功能访问（如某租户是否启用了高级报表）。两者互补，不替代。

🤔 导师提问：配置中心和功能开关的区分，在后端对应 IConfiguration 和 FeatureManager 两个不同的抽象。回忆你在 ASP.NET Core 中使用 IOptions<T> 读取配置，和使用 FeatureManager.IsEnabledAsync() 检查功能开关——两者的缓存策略有什么不同？为什么功能开关需要手动失效缓存，而配置中心通常用轮询热重载？

二、API 层设计

2.1 features.ts 的三个方法

// src/api/ops/features.ts
import { get, post } from "./http"
import type { FeatureFlagCheckResult, FeatureFlagValueResult } from "@/types"

export const featuresApi = {
  isEnabled: (tenantId: string, featureKey: string) =>
    get<FeatureFlagCheckResult>(`/api/tenant-ops/features/tenants/${tenantId}/${featureKey}`),
  getValue: (tenantId: string, featureKey: string) =>
    get<FeatureFlagValueResult>(`/api/tenant-ops/features/tenants/${tenantId}/${featureKey}/value`),
  invalidateCache: (tenantId: string, featureKey: string) =>
    post<{ message: string }>(`/api/tenant-ops/features/tenants/${tenantId}/${featureKey}/invalidate`),
}

三个方法的 URL 路径构成了清晰的层级：

/api/tenant-ops/features/tenants/:tenantId/:featureKey          → 检查启用
/api/tenant-ops/features/tenants/:tenantId/:featureKey/value     → 获取值
/api/tenant-ops/features/tenants/:tenantId/:featureKey/invalidate → 清除缓存

2.2 返回类型

// src/types/index.ts
export interface FeatureFlagCheckResult {
  tenantId: string
  featureKey: string
  enabled: boolean       // 是否启用
}

export interface FeatureFlagValueResult {
  tenantId: string
  featureKey: string
  value: string | null   // 功能值（JSON 字符串）
}

【易错点】 FeatureFlagValueResult.value 是 string | null，不是 object。后端返回的是 JSON 字符串（如 "{"maxUsers":100}"），前端需要用 JSON.parse() 解析。这和配置中心类似——后端不假设值的结构，只传字符串。

2.3 租户详情页中的功能开关

除了独立的功能开关管理页面，租户详情页也有功能开关的标签页。但两者的操作方式不同：

页面API操作
/ops/features（独立页面）featuresApi.isEnabled/getValue/invalidateCache查询 + 缓存管理
/ops/tenants/:id（租户详情）tenantsApi.getFeatures/setFeature列表 + 开关切换

独立页面是管理员工具——检查某个功能的状态、获取值、清除缓存。租户详情是运营操作——为某个租户开启或关闭功能。

三、完整源码

3.1 FeaturesPage 组件

// src/pages/ops/features/index.tsx
import { useState } from "react"
import { AnimatedPage } from "@/components/shared/animated-page"
import { PageHeader } from "@/components/shared/page-header"
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"
import { Label } from "@/components/ui/label"
import { Badge } from "@/components/ui/badge"
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card"
import { toast } from "sonner"
import { featuresApi } from "@/api/ops/features"
import type { FeatureFlagCheckResult, FeatureFlagValueResult } from "@/types"
import { ToggleLeft, Code, RefreshCw } from "lucide-react"

export default function FeaturesPage() {
  const [tenantId, setTenantId] = useState("")
  const [featureKey, setFeatureKey] = useState("")

  // ── Check ──
  const [checkResult, setCheckResult] = useState<FeatureFlagCheckResult | null>(null)
  const [checkLoading, setCheckLoading] = useState(false)

  // ── Get Value ──
  const [valueResult, setValueResult] = useState<ValueResult | null>(null)
  const [valueLoading, setValueLoading] = useState(false)

  // ── Invalidate Cache ──
  const [invalidateLoading, setInvalidateLoading] = useState(false)

  async function handleCheck() {
    if (!tenantId.trim() || !featureKey.trim()) {
      toast.error("请输入租户 ID 和特性键名")
      return
    }
    setCheckLoading(true)
    setCheckResult(null)
    try {
      const res = await featuresApi.isEnabled(tenantId, featureKey)
      setCheckResult(res.data ?? null)
    } catch (err) {
      toast.error("查询失败", { description: err instanceof Error ? err.message : String(err) })
    } finally {
      setCheckLoading(false)
    }
  }

  async function handleGetValue() {
    if (!tenantId.trim() || !featureKey.trim()) {
      toast.error("请输入租户 ID 和特性键名")
      return
    }
    setValueLoading(true)
    setValueResult(null)
    try {
      const res = await featuresApi.getValue(tenantId, featureKey)
      setValueResult(res.data ?? null)
    } catch (err) {
      toast.error("获取值失败", { description: err instanceof Error ? err.message : String(err) })
    } finally {
      setValueLoading(false)
    }
  }

  async function handleInvalidate() {
    if (!tenantId.trim() || !featureKey.trim()) {
      toast.error("请输入租户 ID 和特性键名")
      return
    }
    setInvalidateLoading(true)
    try {
      await featuresApi.invalidateCache(tenantId, featureKey)
      toast.success("缓存已失效")
    } catch (err) {
      toast.error("失效缓存失败", { description: err instanceof Error ? err.message : String(err) })
    } finally {
      setInvalidateLoading(false)
    }
  }

  return (
    <AnimatedPage>
      <div className="space-y-6">
        <PageHeader title="特性开关管理" description="查询与管理租户特性开关状态、值及缓存" />

        <Card>
          <CardHeader>
            <CardTitle className="flex items-center gap-2">
              <ToggleLeft className="h-5 w-5" />
              特性开关查询
            </CardTitle>
          </CardHeader>
          <CardContent className="space-y-6">
            {/* 输入区 */}
            <div className="flex items-end gap-3 flex-wrap">
              <div className="space-y-1.5">
                <Label className="text-xs">租户 ID</Label>
                <Input placeholder="输入租户 ID" value={tenantId} onChange={e => setTenantId(e.target.value)} className="h-8 text-sm w-56" />
              </div>
              <div className="space-y-1.5">
                <Label className="text-xs">特性键名</Label>
                <Input placeholder="输入 feature key" value={featureKey} onChange={e => setFeatureKey(e.target.value)} className="h-8 text-sm w-56" />
              </div>
              <div className="flex gap-2">
                <Button size="sm" onClick={handleCheck} disabled={checkLoading}>
                  <ToggleLeft className="h-3.5 w-3.5 mr-1.5" />
                  {checkLoading ? "查询中..." : "Check"}
                </Button>
                <Button size="sm" variant="outline" onClick={handleGetValue} disabled={valueLoading}>
                  <Code className="h-3.5 w-3.5 mr-1.5" />
                  {valueLoading ? "获取中..." : "Get Value"}
                </Button>
                <Button size="sm" variant="outline" onClick={handleInvalidate} disabled={invalidateLoading}>
                  <RefreshCw className={`h-3.5 w-3.5 mr-1.5 ${invalidateLoading ? "animate-spin" : ""}`} />
                  失效缓存
                </Button>
              </div>
            </div>

            {/* Check 结果 */}
            {checkResult && (
              <div className="flex items-center gap-2 border rounded-lg p-4">
                <span className="text-sm text-muted-foreground">启用状态：</span>
                <Badge variant={checkResult.enabled ? "default" : "secondary"}>
                  {checkResult.enabled ? "已启用" : "未启用"}
                </Badge>
                <span className="text-xs text-muted-foreground">
                  （{checkResult.tenantId} / {checkResult.featureKey}）
                </span>
              </div>
            )}

            {/* Get Value 结果 */}
            {valueResult && (
              <div className="space-y-1.5 border rounded-lg p-4">
                <div className="flex items-center gap-2 text-sm text-muted-foreground">
                  <Code className="h-3.5 w-3.5" />
                  特性值
                  <span className="text-xs">（{valueResult.tenantId} / {valueResult.featureKey}）</span>
                </div>
                <pre className="bg-muted rounded px-3 py-2 text-sm font-mono overflow-auto max-h-48">
                  {valueResult.value ?? "null"}
                </pre>
              </div>
            )}
          </CardContent>
        </Card>
      </div>
    </AnimatedPage>
  )
}

四、逐行讲解

4.1 独立 loading 状态

const [checkLoading, setCheckLoading] = useState(false)
const [valueLoading, setValueLoading] = useState(false)
const [invalidateLoading, setInvalidateLoading] = useState(false)

三个按钮各有独立的 loading 状态。如果只用一个 loading 状态，点击 Check 后 Get Value 和失效缓存按钮也会被禁用。

【易错点】 不要试图用一个 loading 状态管理三个异步操作。虽然可以用 { action: "check" | "getValue" | "invalidate" } 对象来区分，但三个独立 boolean 更简单、更不容易出 bug。

4.2 结果清空模式

async function handleCheck() {
  // ...
  setCheckResult(null)  // 先清空旧结果
  // ... 发起请求
  setCheckResult(res.data ?? null)  // 设置新结果
}

每次点击查询按钮时，先清空旧结果，再显示新结果。这避免了"新请求还在加载时，界面上显示的是上一次的结果"的困惑。

4.3 输入验证

if (!tenantId.trim() || !featureKey.trim()) {
  toast.error("请输入租户 ID 和特性键名")
  return
}

三个 handler 都有相同的输入验证。如果后续要增加更多查询操作，可以抽取为公共函数：

function validateInputs(): boolean {
  if (!tenantId.trim() || !featureKey.trim()) {
    toast.error("请输入租户 ID 和特性键名")
    return false
  }
  return true
}

4.4 Check 结果的展示

{checkResult && (
  <div className="flex items-center gap-2 border rounded-lg p-4">
    <span className="text-sm text-muted-foreground">启用状态：</span>
    <Badge variant={checkResult.enabled ? "default" : "secondary"}>
      {checkResult.enabled ? "已启用" : "未启用"}
    </Badge>
    <span className="text-xs text-muted-foreground">
      （{checkResult.tenantId} / {checkResult.featureKey}）
    </span>
  </div>
)}

Badge 的 variant 根据结果动态切换：

  • enabled: true → variant="default"（蓝/绿实心）
  • enabled: false → variant="secondary"（灰色）

【设计取舍】 为什么"未启用"不是 destructive？因为功能未启用不一定是异常——可能就是没订阅该功能。只有"应该启用但没启用"才是异常，这需要业务逻辑判断，不能仅凭 enabled 布尔值决定。

🤔 导师提问：Badge 的 variant 选择是 UI 层面的业务决策——"未启用"用 secondary 而非 destructive。在后端，你可能用日志级别来区分类似场景：INFO（正常未启用）vs ERROR（应该启用但未启用）。前端如何获取"应该启用"这个业务上下文？是前端自己维护期望值，还是后端 API 应该返回更丰富的状态？

4.5 Get Value 结果的展示

{valueResult && (
  <div className="space-y-1.5 border rounded-lg p-4">
    <div className="flex items-center gap-2 text-sm text-muted-foreground">
      <Code className="h-3.5 w-3.5" />
      特性值
      <span className="text-xs">（{valueResult.tenantId} / {valueResult.featureKey}）</span>
    </div>
    <pre className="bg-muted rounded px-3 py-2 text-sm font-mono overflow-auto max-h-48">
      {valueResult.value ?? "null"}
    </pre>
  </div>
)}

值用 <pre> 标签展示，font-mono 等宽字体适合显示 JSON。max-h-48 限制最大高度，超出时显示滚动条——避免长 JSON 撑破页面布局。

4.6 RefreshCw 的旋转动画

<RefreshCw className={`h-3.5 w-3.5 mr-1.5 ${invalidateLoading ? "animate-spin" : ""}`} />

animate-spin 是 Tailwind 的旋转动画类，只在 loading 时添加。失效缓存按钮的图标在请求期间旋转，给用户"正在处理"的视觉反馈。

五、租户详情页中的功能开关

5.1 Switch 开关切换

租户详情页的功能开关标签页使用 Switch 组件，而非独立页面的查询模式：

// src/pages/ops/tenants/detail/index.tsx
{features.map((feat) => (
  <div key={feat.id} className="flex items-center justify-between px-5 py-3">
    <div>
      <p className="font-medium">{feat.displayName ?? feat.featureKey}</p>
      <p className="text-xs text-muted-foreground font-mono">{feat.featureKey}</p>
      {feat.description && (
        <p className="text-xs text-muted-foreground mt-0.5">{feat.description}</p>
      )}
    </div>
    <Switch
      checked={feat.isEnabled}
      onCheckedChange={() => handleToggleFeature(feat)}
      disabled={togglingFeature === feat.featureKey}
    />
  </div>
))}

5.2 切换逻辑

const handleToggleFeature = async (feat: TenantFeatureFlagDto) => {
  if (!id) return
  setTogglingFeature(feat.featureKey)
  try {
    await tenantsApi.setFeature(id, {
      featureKey: feat.featureKey,
      isEnabled: !feat.isEnabled,
      displayName: feat.displayName ?? undefined,
      description: feat.description ?? undefined,
    })
    toast.success(feat.isEnabled ? "特性已关闭" : "特性已开启")
    fetchFeatures()
  } catch {
    toast.error("切换特性失败")
  } finally {
    setTogglingFeature(null)
  }
}

【易错点】 setFeature 的请求体包含了 displayName 和 description。这是因为后端的 SetFeatureFlagRequest 是全量更新——即使只改了 isEnabled，也要把其他字段传回去，否则后端可能将它们设为 null。

// src/types/index.ts
export interface SetFeatureFlagRequest {
  featureKey: string
  isEnabled: boolean
  valueJson?: string
  displayName?: string
  description?: string
}

5.3 togglingFeature 防重复提交

const [togglingFeature, setTogglingFeature] = useState<string | null>(null)

<Switch
  disabled={togglingFeature === feat.featureKey}
  onCheckedChange={() => handleToggleFeature(feat)}
/>

togglingFeature 记录当前正在切换的 featureKey。切换期间，对应的 Switch 被禁用，防止用户快速连续点击导致重复请求。

【易错点】 如果不用 togglingFeature 而用一个全局 loading 状态，所有 Switch 都会被禁用——用户只能等一个操作完成才能切换下一个。用 featureKey 级别的 loading，只有正在操作的那个 Switch 被禁用。

🤔 导师提问：togglingFeature 用 string | null 类型追踪当前正在切换的功能键，实现行级 loading。在后端，你可能用锁或并发令牌来防止重复提交。前端的防重复提交和后端的并发控制，在思路上有什么异同？如果两个运营员同时切换同一个功能开关，会发生什么？

六、缓存失效的使用场景

6.1 什么时候需要失效缓存？

场景 1：管理员在后端直接修改了数据库中的功能开关值
  → 后端缓存中还是旧值
  → 前端查询得到的是过时数据
  → 需要手动失效缓存

场景 2：工作流审批通过后，功能开关应该自动启用
  → 但缓存还没更新
  → 需要失效缓存让新值生效

6.2 为什么不自动刷新缓存？

性能考虑。每次查询都读数据库会增加数据库压力。后端使用 Redis 缓存功能开关值，设置 TTL（如 5 分钟）。invalidateCache 是紧急操作，用于绕过缓存。

【易错点】 invalidateCache 是管理操作，普通用户不应有此权限。当前页面的失效缓存按钮没有做权限控制——实际项目中应该根据用户角色决定是否显示。

🤔 导师提问：缓存失效是紧急操作，应该限制权限。在后端，你通常用 [Authorize(Roles = "Admin")] 来控制。前端目前没有权限控制——失效缓存按钮对所有用户可见。回顾篇章 4 的权限中心，设计一个 usePermission Hook，让 <Button> 根据用户角色自动隐藏或禁用。

八、小结

要点说明
三个操作isEnabled（检查）、getValue（获取值）、invalidateCache（失效缓存）
独立 loading三个按钮各有独立 loading 状态
结果清空每次查询前清空旧结果，避免混淆
Switch 切换租户详情页用 Switch，非查询模式
缓存失效紧急操作，应限制权限
两种页面独立页面=运维排查，租户详情=运营操作
防重复提交featureKey 级别的 loading

🤔 导师提问：独立页面和租户详情页使用了不同的 API 集合来操作同一个功能开关——featuresApi vs tenantsApi。这就像后端有两种 Controller 操作同一个聚合根：一个只读查询 Controller，一个写操作 Controller。这种"读写分离"的 API 设计有什么好处？如果 featuresApi 也需要修改功能开关，API 路径应该如何设计？

🔧 验证步骤

  1. 在功能开关管理页面输入租户 ID 和特性键名，点击 Check——确认返回 FeatureFlagCheckResult，Badge 显示"已启用"或"未启用"
  2. 点击 Get Value——确认返回 FeatureFlagValueResult，值用 <pre> 标签等宽字体展示
  3. 点击"失效缓存"——确认 RefreshCw 图标旋转，请求完成后 toast 提示"缓存已失效"
  4. 进入租户详情页的功能开关 Tab，点击某个 Switch——确认状态切换后 toast 提示"特性已开启"或"特性已关闭"
  5. 快速连续点击同一个 Switch——确认只有第一次请求生效，togglingFeature 防止了重复提交

⚠️ 踩坑提醒

  1. 三个按钮各有独立 loading 状态：不要用一个 loading 状态管理三个异步操作，否则点击 Check 后 Get Value 和失效缓存按钮也会被禁用。
  2. setFeature 是全量更新：即使只改了 isEnabled，也要把 displayName 和 description 传回去，否则后端可能将它们设为 null。
  3. 缓存失效是管理操作：普通用户不应有此权限。当前页面没有做权限控制——实际项目中应该根据用户角色决定是否显示失效缓存按钮。
  4. 独立页面和租户详情使用不同 API：featuresApi 是只读查询，tenantsApi.getFeatures/setFeature 是读写操作。不要混淆两者。
