租户选择

租户选择

这一步解决什么问题？

SaaS 系统的核心特征是多租户隔离——一个用户可能属于多个组织，不同组织下的数据完全隔离。登录后必须确定当前操作的租户上下文。这一步我们实现租户选择页面：当用户关联多个租户时，让用户选择进入哪个租户。这类似 ASP.NET Core 中登录后选择"身份"——但这里的"身份"不是用户角色，而是组织上下文。

前置知识

概念你需要知道的ASP.NET Core 类比
多租户隔离不同租户的数据完全隔离，API 请求带 X-Tenant-Id类似按 TenantId 切换数据库连接
switch_tenant Grant Type自定义 OAuth2 扩展，用当前 Token 换新租户 Token类似 SignInManager.RefreshSignInAsync()
<Navigate> vs navigate()渲染函数中用声明式 <Navigate>，事件处理器中用命令式 navigate()类似 RedirectResult vs 手动修改 Response
framer-motion 交错动画staggerContainer + staggerItem 实现子元素依次入场无直接类比，CSS animation-delay 的声明式版本
window.location.reload()完全刷新页面，所有状态重置类似 Response.Redirect 导致的全页面刷新

多租户判断逻辑

登录后，系统根据用户关联的租户数量决定下一步：

租户数量 = 0  →  平台管理员，无租户上下文，直接进入首页
租户数量 = 1  →  单租户用户，自动选中该租户，直接进入首页
租户数量 ≥ 2  →  多租户用户，跳转到租户选择页

类比后端：类似根据用户角色决定默认页面。AdminWeb 是根据租户数量决定是否需要选择。在 ASP.NET Core 中，这类似于用户有多个"模拟（Impersonation）"身份时的选择逻辑。

SelectTenantPage 完整代码（来自 AdminWeb 源码）

// src/pages/select-tenant/index.tsx
/** 状态管理：useState */
import { useState } from "react"
/** 路由导航：useNavigate */
import { useNavigate } from "react-router-dom"
/** 动画库：framer-motion */
import { motion } from "framer-motion"
/** 认证状态仓库：提供租户列表、Token 管理、认证状态 */
import { useAuthStore } from "@/stores/auth-store"
/** 认证 API：租户切换接口 */
import { authApi } from "@/api/auth/auth"
/** UI 组件：按钮 */
import { Button } from "@/components/ui/button"
/** 图标：建筑图标（租户）、加载指示器、右箭头 */
import { Building2, Loader2, ChevronRight } from "lucide-react"
/** 品牌组件：Logo 与 LogoMark */
import { Logo, LogoMark } from "@/components/brand/logo"
/** 动画变体：交错容器与子项 */
import { staggerContainer, staggerItem } from "@/lib/motion"
/** 消息提示 */
import { toast } from "sonner"

/**
 * 选择租户页面组件
 *
 * 当用户账号关联多个租户时，登录后跳转到此页面供用户选择要进入的租户。
 * 选择租户后会调用切换接口获取新 Token，更新本地存储后跳转到主页。
 *
 * 核心功能：
 * - 展示当前用户可用的租户列表
 * - 点击租户卡片触发切换，获取新租户的 access_token 和 refresh_token
 * - 切换期间禁用所有租户按钮并显示加载状态
 * - 未认证或无可用租户时自动重定向
 *
 * 守卫逻辑：
 * - 未认证 → 跳转登录页
 * - 无可用租户 → 跳转主页
 */
export default function SelectTenantPage() {
  /** 路由导航实例 */
  const navigate = useNavigate()
  /** 从认证仓库获取租户列表、Token 设置方法、当前租户设置方法、认证状态 */
  const { availableTenants, setTokens, setCurrentTenant, isAuthenticated } = useAuthStore()
  /** 当前正在切换的租户 ID，用于显示加载状态；null 表示无切换进行中 */
  const [loading, setLoading] = useState<string | null>(null)

  // 守卫：未认证则跳转回登录页
  if (!isAuthenticated) {
    navigate("/login", { replace: true })
    return null
  }

  // 守卫：无可用租户则直接跳转主页
  if (!availableTenants || availableTenants.length === 0) {
    navigate("/", { replace: true })
    return null
  }

  /**
   * 选择租户并切换
   *
   * 调用后端 switchTenant 接口，成功后用新 Token 替换当前 Token，
   * 更新当前租户信息，弹出成功提示并跳转主页。
   * 接口失败时弹出错误提示。
   *
   * @param tenant - 用户选择的租户对象，包含 tenantId、tenantName、tenantIdentifier
   */
  const handleSelect = async (tenant: (typeof availableTenants)[number]) => {
    // 记录正在切换的租户 ID，用于显示该租户项的加载状态
    setLoading(tenant.tenantId)
    try {
      const res = await authApi.switchTenant(tenant.tenantId)
      if (res.access_token) {
        // 用新租户的 Token 替换当前 Token
        setTokens(res.access_token, res.refresh_token)
        // 更新当前租户信息到认证仓库
        setCurrentTenant(tenant.tenantId, tenant.tenantName)
        toast.success(`已进入「${tenant.tenantName}」`)
        navigate("/", { replace: true })
      } else {
        toast.error("切换租户失败")
      }
    } catch {
      toast.error("切换租户失败")
    } finally {
      // 无论成功或失败，都清除加载状态
      setLoading(null)
    }
  }

  return (
    <div className="flex min-h-screen items-center justify-center bg-background p-8">
      {/* 交错动画容器：子元素依次入场 */}
      <motion.div
        variants={staggerContainer}
        initial="initial"
        animate="animate"
        className="w-full max-w-md"
      >
        {/* 标题区域：Logo + 页面标题 + 提示文案 */}
        <motion.div variants={staggerItem} className="mb-8 text-center">
          <Logo size="lg" className="mx-auto mb-6" />
          <h2 className="text-2xl font-bold tracking-tight">选择租户</h2>
          <p className="text-sm text-muted-foreground mt-1">
            您的账号关联了多个租户，请选择要进入的租户
          </p>
        </motion.div>

        {/* 租户列表 — 每个租户渲染为一个可点击的卡片按钮 */}
        <motion.div variants={staggerItem} className="space-y-3">
          {availableTenants.map((tenant) => (
            <Button
              key={tenant.tenantId}
              variant="outline"
              className="w-full h-auto py-4 px-4 justify-between"
              disabled={loading !== null}
              onClick={() => handleSelect(tenant)}
            >
              {/* 租户信息：图标 + 名称 + 标识符 */}
              <div className="flex items-center gap-3">
                {/* 租户图标 — 使用主题色的浅色背景圆角方块 */}
                <div className="flex h-10 w-10 items-center justify-center rounded-lg bg-primary/10">
                  <Building2 className="h-5 w-5 text-primary" />
                </div>
                <div className="text-left">
                  <div className="font-medium">{tenant.tenantName}</div>
                  <div className="text-xs text-muted-foreground font-mono">
                    {tenant.tenantIdentifier}
                  </div>
                </div>
              </div>
              {/* 切换中显示加载图标，否则显示右箭头 */}
              {loading === tenant.tenantId ? (
                <Loader2 className="h-4 w-4 animate-spin text-muted-foreground" />
              ) : (
                <ChevronRight className="h-4 w-4 text-muted-foreground" />
              )}
            </Button>
          ))}
        </motion.div>

        {/* 底部版权信息 */}
        <motion.div
          variants={staggerItem}
          className="mt-8 flex items-center justify-center gap-2 text-xs text-muted-foreground/50"
        >
          <LogoMark className="h-4 w-4 !shadow-none" />
          <span>沐川科创 &copy; {new Date().getFullYear()}</span>
        </motion.div>
      </motion.div>
    </div>
  )
}

租户切换的完整流程

用户选择租户 → handleSelect(tenant)
  │
  ├─ 1. setLoading(tenantId)  → 显示 loading，禁用所有按钮
  │
  ├─ 2. authApi.switchTenant(tenantId)
  │     POST /connect/token
  │     grant_type=urn:custom:switch_tenant
  │     subject_token=当前access_token
  │     tenant_id=目标租户ID
  │     → 获得包含新租户信息的 access_token + refresh_token
  │
  ├─ 3. setTokens(新access_token, 新refresh_token)
  │     → 更新 Zustand store + localStorage
  │
  ├─ 4. setCurrentTenant(tenantId, tenantName)
  │     → 设置当前租户上下文（后续 API 请求自动带 X-Tenant-Id）
  │
  └─ 5. navigate("/", { replace: true })
        → 跳转首页（replace 避免回退到选择页）

类比后端：切换租户类似 ASP.NET Core 中的"模拟（Impersonation）"——用一个身份换取另一个身份的上下文。但 AdminWeb 的实现更轻量——不需要重新认证，只是换了租户上下文。SSO 服务器签发新 Token 时会替换 tenant_id 等 claims，后端只信任 JWT 中的 claims。

🤔 导师提问：AppHeader 切换租户后用 window.location.reload()，而 SelectTenantPage 用 navigate()。如果 AppHeader 也改用 navigate()，会出什么问题？

【易错点】setTokens 必须在 setCurrentTenant 之前

// ✅ 正确顺序：先更新 Token，再更新租户信息
setTokens(res.access_token, res.refresh_token)  // 1. Token 先更新
setCurrentTenant(tenant.tenantId, tenant.tenantName)  // 2. 租户信息后更新

// ❌ 错误顺序：先更新租户信息，再更新 Token
setCurrentTenant(tenant.tenantId, tenant.tenantName)  // 1. 租户信息更新了
setTokens(res.access_token, res.refresh_token)  // 2. 但 Token 还是旧的
// 问题：如果中间有 API 请求触发，X-Tenant-Id 是新租户，但 Token 中的 claims 还是旧租户

页面级守卫的问题

// ⚠️ 当前写法：在渲染函数中调用 navigate()
if (!isAuthenticated) {
  navigate("/login", { replace: true })
  return null
}

// ✅ 推荐写法：使用 Navigate 组件
if (!isAuthenticated) {
  return <Navigate to="/login" replace />
}

【易错点】在 React 18+ 的并发模式下，渲染函数可能被多次调用。navigate() 会产生副作用（改变路由），而 <Navigate> 是声明式的，React 会在合适的时机处理跳转。

【设计取舍】为什么 SelectTenantPage 用 navigate() 而非 Navigate

SelectTenantPage 当前使用 navigate() 做守卫，而 ProtectedRoute 使用 <Navigate>。原因是历史实现——SelectTenantPage 最早独立实现了守卫逻辑，后来才抽象出 ProtectedRoute。未来应该统一改为 <Navigate> 组件。

App Header 租户切换器

登录后用户也可以通过顶部导航栏的租户切换器切换租户，无需返回选择页。

// src/components/layout/app-header.tsx（租户切换相关代码）
const handleSwitchTenant = async (tenant: { tenantId: string; tenantName: string }) => {
  if (tenant.tenantId === currentTenantId || switchingTenant) return
  setSwitchingTenant(true)
  try {
    const res = await authApi.switchTenant(tenant.tenantId)
    if (res.access_token) {
      setTokens(res.access_token, res.refresh_token)
      setCurrentTenant(tenant.tenantId, tenant.tenantName)
      toast.success(`已切换到「${tenant.tenantName}」`)
      window.location.reload()
    } else {
      toast.error("切换租户失败")
    }
  } catch {
    toast.error("切换租户失败")
  } finally {
    setSwitchingTenant(false)
  }
}

window.location.reload() vs navigate() 对比

AppHeader 的 handleSwitchTenant 使用 window.location.reload() 而不是 navigate()：

方式效果适用场景
window.location.reload()完全刷新页面，所有状态重置，重新执行 React 根渲染需要确保所有组件重新初始化
navigate("/")SPA 内部跳转，组件状态可能残留简单路由跳转
navigate("/", { replace: true })SPA 内部跳转，替换历史记录不想让用户回退到旧页面

【设计取舍】为什么 AppHeader 切换租户用 reload()？

切换租户后，当前页面的数据都属于旧租户。如果只用 navigate("/")：

  1. 缓存的数据还是旧租户的（如 React Query 缓存、组件 state）
  2. 某些组件可能不会重新渲染（因为路由没变）
  3. 网络请求的拦截器可能还没拿到新 Token

window.location.reload() 虽然粗暴，但确保了一致性——所有状态清零，重新从 localStorage 恢复认证状态，所有 API 请求用新 Token。

SelectTenantPage 为什么可以用 navigate()？ 因为它是从登录/选择页跳转到首页，不存在旧数据残留的问题——用户还没有进入任何业务页面。

三种渲染状态

🤔 导师提问：currentTenantName 和 availableTenants 这两个状态存储在全局 store 中，而不是组件的本地 state。为什么这一点很重要？

条件1：currentTenantName 不存在
  → 不渲染任何租户信息（平台管理员或未选租户）

条件2：availableTenants.length > 1（多租户）
  → 渲染 DropdownMenu，点击可切换
  → 当前租户显示 ✓ 标记
  → 切换中显示 Loader2 旋转图标

条件3：availableTenants.length === 1（单租户）
  → 只显示租户名称，不可点击
  → 没有 DropdownMenu，没有下拉箭头

【性能陷阱】DropdownMenu 的 disabled 状态

<Button variant="outline" size="sm" disabled={switchingTenant}>

切换中禁用按钮，防止用户重复点击。但 switchingTenant 是 boolean，不像 SelectTenantPage 的 loading 那样精确到具体租户。因为 DropdownMenu 中同时只有一个按钮（Trigger），所以用 boolean 就够了。

项目审视：AdminWeb 的 SSO 实现

做得好的地方

  1. 完整的登录流程：token 获取 → 用户信息加载 → 租户选择 → 路由跳转，每一步都有降级策略
  2. 自定义 grant_type 切换租户：用户无需重新输入密码，体验流畅
  3. logout 不阻塞 UI：先清本地、再跳转，后端异步撤销
  4. 并发刷新队列：避免重复刷新

可以改进的地方

  1. JWT 解析应提取 exp，定期检查过期：当前方案完全依赖 401 触发刷新
  2. 登录页缺少验证码：应考虑暴力破解防护
  3. token 刷新用裸 axios：应复用 ssoHttp 的 postForm
  4. select-tenant 页面用 navigate() 做守卫：应改用 <Navigate> 组件

验证步骤

  1. 用多租户账号登录，确认到达 /select-tenant 页面
  2. 点击一个租户卡片，确认：页面跳转到 /，Console 中 useAuthStore.getState().currentTenantId 有值
  3. 在 localStorage 中查看 admin-auth，确认 currentTenantId 和 currentTenantName 已更新
  4. 进入首页后，点击右上角的租户切换下拉菜单，选择另一个租户
  5. 确认页面刷新（window.location.reload()），Console 中 currentTenantId 已切换为新租户

踩坑提醒

  1. setTokens 必须在 setCurrentTenant 之前调用：如果先更新租户信息再更新 Token，中间触发 API 请求时 X-Tenant-Id 是新租户，但 Token 中的 claims 还是旧租户
  2. 切换租户必须换取新 Token，不能只改前端本地变量：如果只在前端改 tenantId，后端不信任——JWT 中的 claims 还是旧租户，数据隔离被破坏
  3. SelectTenantPage 的守卫用了 navigate() 而非 <Navigate>：在 React 18+ 并发模式下渲染函数中调用 navigate() 可能产生副作用，应改为 <Navigate> 组件
  4. 切换期间必须禁用所有租户按钮：如果不禁用，用户快速点击两个租户会导致两次 switchTenant 调用，产生竞态条件
  5. AppHeader 切换租户后用 window.location.reload()：因为当前页面的缓存数据还是旧租户的，SPA 内部跳转无法清理所有状态
