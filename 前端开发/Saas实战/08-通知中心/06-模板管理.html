06 - 模板管理：CRUD + 多维度发送通知

这一步解决什么问题？
通知不是随意发的——需要有模板定义内容格式（标题、正文、变量），还需要选择收件人（按用户、角色、部门、公司、岗位）。模板管理页是通知中心最复杂的页面，1058 行代码涵盖了模板 CRUD 和多维度发送通知两大功能。

ASP.NET Core 类比：模板管理 ≈ 你的 NotificationTemplatesController 的全部 Action（CRUD），发送通知 ≈ 一个复杂的 Service 方法，需要聚合多个数据源（用户搜索、角色成员、部门人员等）来确定收件人列表。

前置知识

  • 第 1-5 节的 SignalR、通知 Store、API 层、铃铛和通知列表页
  • React useState + useEffect + useCallback 的组合模式
  • ASP.NET Core 的 DTO 分离模式（CreateRequest vs UpdateRequest）
  • Scriban 模板语法（{{ model.PropertyName }}）和模板变量替换
  • Map 数据结构的基本操作（get/set/new Map(prev)）

💡 template 参数决定新建/编辑模式：

2.2 表单状态与初始化

const [form, setForm] = useState<CreateTemplateRequest>({
  code: "",
  name: "",
  description: "",
  isEnabled: true,
  inAppTitleTemplate: "",
  inAppBodyTemplate: "",
  emailSubjectTemplate: "",
  emailBodyTemplate: "",
  smsTemplate: "",
})

useEffect(() => {
  if (template) {
    setForm({
      code: template.code,
      name: template.name,
      description: template.description ?? "",
      isEnabled: template.isEnabled,
      inAppTitleTemplate: template.inAppTitleTemplate ?? "",
      inAppBodyTemplate: template.inAppBodyTemplate ?? "",
      emailSubjectTemplate: template.emailSubjectTemplate ?? "",
      emailBodyTemplate: template.emailBodyTemplate ?? "",
      smsTemplate: template.smsTemplate ?? "",
    })
  } else {
    setForm({
      code: "", name: "", description: "", isEnabled: true,
      inAppTitleTemplate: "", inAppBodyTemplate: "",
      emailSubjectTemplate: "", emailBodyTemplate: "", smsTemplate: "",
    })
  }
}, [template, open])

逐行精讲：

标记代码解读
【设计取舍】useState<CreateTemplateRequest>新建和编辑共用同一个表单状态类型。编辑时只是初始值不同，提交时区分调用 createTemplate 还是 updateTemplate
【易错点】useEffect 依赖 [template, open]必须依赖 open！因为对话框关闭再打开时，需要重置表单。只依赖 template 不够——同一个模板编辑两次，template 引用没变，不会重新初始化
【易错点】template.inAppTitleTemplate ?? ""后端可选字段可能是 undefined，但受控组件的 value 不能是 undefined（React 会报警告），必须用空字符串兜底

2.3 通用 set 辅助函数

const set = (key: keyof CreateTemplateRequest, value: unknown) =>
  setForm((prev) => ({ ...prev, [key]: value }))

💡 这是 React 表单的常用模式：一个 set 函数替代 10 个 setCode、setName、setDescription...

// 没有 set 辅助函数：
<Input value={form.code} onChange={(e) => setForm(prev => ({ ...prev, code: e.target.value }))} />

// 有 set 辅助函数：
<Input value={form.code} onChange={(e) => set("code", e.target.value)} />

const handleSubmit = async () => {
  if (!form.code || !form.name) {
    toast.error("编码和名称不能为空")

  }

  try {

⚠️ 【易错点】编辑时只传 UpdateTemplateRequest，不传 code 和 name！

因为 UpdateTemplateRequest 类型定义里没有 code 和 name——模板编码和名称创建后不可修改。UI 上编码输入框也有 disabled={isEdit} 来体现这一点。

3.1 Scriban 变量提取

/** 从 Scriban 模板中提取变量名，如 {{ model.UserName }} → UserName */
function extractVariables(template: string): string[] {
  const re = /\{\{\s*model\.(\w+)\s*\}\}/g
  const vars = new Set<string>()
  let m: RegExpExecArray | null
  while ((m = re.exec(template)) !== null) vars.add(m[1])
  return [...vars]
}

逐行精讲：

标记代码解读
【易错点】/\{\{\s*model\.(\w+)\s*\}\}/g正则解析 Scriban 模板。\{\{ 匹配 {{，\s* 匹配可选空格，(\w+) 捕获变量名，/g 全局匹配
【设计取舍】new Set<string>()用 Set 去重！如果模板中 {{ model.UserName }} 出现多次，只提取一次

🤔 导师提问：extractVariables 用正则从模板字符串中提取变量名。这和 ASP.NET Core 中用反射从 SendNotificationRequest.Model 属性获取字段名是两种完全不同的思路。正则提取的局限是什么？如果用户写了 {{ model.User.Name }}（嵌套属性），当前正则能匹配到吗？

3.2 统一已选用户（跨 Tab 去重）

interface SelectedEntry {
  userName: string
  displayName: string | null
  sources: string[]
}

const [selectedUsers, setSelectedUsers] = useState<Map<string, SelectedEntry>>(new Map())

⚠️ 【易错点】为什么用 Map 而不是数组？
5 个 Tab（用户/角色/部门/公司/岗位）可能选出同一个人。Map<userId, SelectedEntry> 用 userId 去重，sources 数组记录这个用户来自哪些来源。

用户"张三"可能同时出现在：
- 按用户搜索：张三(用户搜索)
- 按角色 Admin：张三(角色:Admin)
- 按部门 技术部：张三(部门:技术部)

Map 中只有一条记录：
  key: "zhang-san-id"
  value: { userName: "张三", sources: ["用户搜索", "角色:Admin", "部门:技术部"] }

3.3 添加/移除用户

const addUsers = (users: Array<{ id: string; userName: string; displayName?: string | null }>, source: string) => {
  setSelectedUsers(prev => {
    const next = new Map(prev)
    for (const u of users) {
      const existing = next.get(u.id)
      if (existing) {
        if (!existing.sources.includes(source)) existing.sources = [...existing.sources, source]
      } else {
        next.set(u.id, { userName: u.userName, displayName: u.displayName ?? null, sources: [source] })
      }
    }
    return next
  })
}

const removeSelectedUser = (userId: string) => {
  setSelectedUsers(prev => { const next = new Map(prev); next.delete(userId); return next })
}

逐行精讲：

标记代码解读
【易错点】const next = new Map(prev)必须创建新 Map！直接修改 prev 违反 React 不可变数据原则，状态不会触发重渲染
【设计取舍】existing.sources = [...existing.sources, source]同样要创建新数组！直接 push 是修改原数组

3.6 树形复选框渲染

function renderTreeCheckboxes<T extends { id: string; children?: T[] }>(
  nodes: T[],
  checked: Set<string>,
  setChecked: (fn: (prev: Set<string>) => Set<string>) => void,
  getLabel: (node: T) => string,
  depth = 0,
) {
  return nodes.map(node => (
    <div key={node.id}>
      <label className="flex items-center gap-2 px-3 py-1.5 hover:bg-muted/50 cursor-pointer"
        style={{ paddingLeft: `${12 + depth * 20}px` }}>
        <Checkbox checked={checked.has(node.id)} onCheckedChange={c => {
          setChecked(prev => { const next = new Set(prev); c ? next.add(node.id) : next.delete(node.id); return next })
        }} />
        <span className="text-sm truncate">{getLabel(node)}</span>
      </label>
      {node.children?.length && renderTreeCheckboxes(node.children, checked, setChecked, getLabel, depth + 1)}
    </div>
  ))
}

逐行精讲：

标记代码解读
【设计取舍】泛型 <T extends { id: string; children?: T[] }>部门和公司都是树形结构，用泛型统一渲染逻辑，避免写两遍几乎相同的代码
【易错点】depth * 20 缩进递归渲染树形结构时，用 depth 控制缩进层级。depth=0 是根节点，depth=1 是子节点，以此类推
【易错点】c ? next.add(node.id) : next.delete(node.id)onCheckedChange 的参数 c 是 `boolean

3.7 部门解析：包含子部门

const resolveOrgUnits = async () => {
  if (checkedOrgUnits.size === 0) return
  setOrgResolving(true)
  try {
    const allIds = orgIncludeChildren
      ? Array.from(checkedOrgUnits).flatMap(id => collectDescendantIds(orgTree, id))
      : Array.from(checkedOrgUnits)
    const uniqueIds = [...new Set(allIds)]
    const promises = uniqueIds.map(async unitId => {
      const res = await orgUnitsApi.getUsers(unitId)
      if (res.success && res.data) {
        const ids: string[] = res.data
        const users = ids.map(uid => ({ id: uid, userName: uid.slice(0, 8), displayName: null as string | null }))
        const unit = findTreeNode(orgTree, unitId)
        addUsers(users, `部门: ${unit?.displayName ?? unitId.slice(0, 8)}`)
      }
    })
    await Promise.all(promises)
    toast.success(`已解析 ${checkedOrgUnits.size} 个部门的用户`)
    setCheckedOrgUnits(new Set())
  } catch { toast.error("解析部门用户失败") }
  finally { setOrgResolving(false) }
}

逐行精讲：

标记代码解读
【设计取舍】orgIncludeChildren复选框"包含子部门"：勾选时选中部门下所有后代部门的用户，不勾选时只选当前部门
【易错点】[...new Set(allIds)]去重！包含子部门时，多个已选部门可能有共同的子部门。Set 自动去重，避免对同一部门调两次 getUsers
【性能陷阱】Promise.all(promises)并发请求所有部门的用户列表。如果选了 50 个部门，会同时发 50 个请求。对于大规模使用，应该考虑批量接口

3.8 提交发送

const handleSubmit = async () => {
  if (!activeTemplate) { toast.error("请选择通知模板"); return }
  const userIds = Array.from(selectedUsers.keys())
  if (userIds.length === 0) { toast.error("请选择收件人"); return }

  let model: Record<string, unknown> | undefined
  if (modelJson.trim()) {
    try { model = JSON.parse(modelJson) } catch { toast.error("模板变量 JSON 格式错误"); return }
  }

  setLoading(true)
  try {
    const req: SendNotificationRequest = {
      templateCode: activeTemplate.code,
      recipientUserIds: userIds,

      priority: priority as NotificationPriority,

    const res = await sendNotification(req)
    const d = res.data

}

⚠️ 【易错点】channels: selectedChannels.length > 0 ? selectedChannels : undefined

🤔 导师提问：channels 为空时传 undefined 而非 []，让后端使用模板默认渠道。在 ASP.NET Core 的 API 设计中，null 和空数组 [] 的语义通常是不同的。你怎么在 Swagger 文档中向调用者说明"不传 channels = 使用默认，传空数组 = 不发任何渠道"这种区别？

⚠️ 【易错点】JSON.parse(modelJson)
模板变量由用户在 Textarea 里手动输入 JSON。这很容易格式错误（少个逗号、多个逗号、忘了引号...），必须 try-catch。

      setFormOpen(true)
    }
  } catch {
    toast.error("获取模板详情失败")
  }
}

const handleSend = async (item: TemplateListDto) => {
  try {
    const res = await getTemplate(item.id)
    if (res.data) {
      setSendTemplate(res.data)
      setSendOpen(true)
    }
  } catch {
    toast.error("获取模板详情失败")
  }
}

💡 为什么列表点编辑/发送时，还要调 getTemplate？
因为列表返回的是 TemplateListDto（只有基本信息），编辑/发送需要 TemplateDetailDto（包含各渠道模板内容）。这是一个按需加载详情的模式。

踩坑提醒

  1. 编辑模板时 code 和 name 字段必须 disabled：这两个字段是模板的唯一标识，修改会导致已有的发送记录无法关联到正确模板
  2. selectedUsers 用 Map 而不是数组：跨 Tab 选择用户时，Map 的 key 天然去重，避免同一用户被多次添加
  3. extractVariables 的正则要容错空格：{{ model.UserName }} 和 {{model.UserName}} 都应该被匹配，正则中需要 \s* 容差
  4. 5 个收件人 Tab 是懒加载：只有切换到对应 Tab 时才加载数据，避免一次性发 5 个请求拖慢页面
  5. 部门"包含子部门"需要递归收集：collectDescendantIds 递归遍历部门树，收集所有后代部门 ID
