07 - 通知偏好设置：卡片式开关管理

这一步解决什么问题？ 用户可能不想接收短信通知（省钱），或者不想接收邮件通知（太吵）。偏好设置页面让用户自己控制每个渠道的开关。紧急通知不受偏好影响——服务端会强制发送。

前置知识

  • React 状态管理（useState、useEffect）
  • Map<string, boolean> 的用法和不可变更新
  • shadcn/ui Card、Switch 组件的用法
  • CSS Grid 响应式布局（grid-cols-2、grid-cols-3）
  • PageToolbar、PageHeader 共享组件
  • 通知渠道枚举（NotificationChannel）和偏好 DTO（PreferenceDto）

代码实现

以下代码来自 AdminWeb/src/pages/notify/preferences/index.tsx：

import { useState, useEffect } from "react"
import { toast } from "sonner"
import { Save, RefreshCw } from "lucide-react"
import { AnimatedPage } from "@/components/shared/animated-page"
import { PageHeader } from "@/components/shared/page-header"
import { PageToolbar, ToolbarButton } from "@/components/shared/page-toolbar"
import { Switch } from "@/components/ui/switch"
import { Card, CardContent, CardDescription, CardHeader, CardTitle } from "@/components/ui/card"
import { getPreferences, updatePreferences } from "@/api/notify/preferences"
import { NotificationChannel } from "@/types/notification"
import type { PreferenceDto, UpdatePreferenceRequest } from "@/types/notification"

// ── 渠道配置 ──
const channelConfig = [
  {
    channel: NotificationChannel.InApp,
    label: "站内信",
    description: "通过 SignalR 实时推送到浏览器，并在通知铃铛中显示",
    icon: "🔔",
  },
  {
    channel: NotificationChannel.Email,
    label: "邮件通知",
    description: "发送邮件到您的注册邮箱",
    icon: "📧",
  },
  {
    channel: NotificationChannel.Sms,
    label: "短信通知",
    description: "发送短信到您的手机号（可能产生费用）",
    icon: "📱",
  },
  {
    channel: NotificationChannel.WeChatTemplate,
    label: "微信消息",
    description: "通过微信公众号/小程序推送消息（即将上线）",
    icon: "💬",
    disabled: true,
  },
  {
    channel: NotificationChannel.MobilePush,
    label: "移动推送",
    description: "通过 APP 推送通知到手机（即将上线）",
    icon: "📲",
    disabled: true,
  },
]

/**
 * 通知偏好设置页面
 * 管理各通知渠道（站内信、邮件、短信、微信、移动推送）的接收开关。
 * 紧急通知会忽略偏好设置强制发送。
 */
export default function NotificationPreferencesPage() {
  const [preferences, setPreferences] = useState<Map<string, boolean>>(new Map())
  const [loading, setLoading] = useState(false)
  const [saving, setSaving] = useState(false)

  const fetchPreferences = async () => {
    setLoading(true)
    try {
      const res = await getPreferences()
      const prefs = res.data ?? []
      // 只取全局偏好（templateCode 为空）
      const map = new Map<string, boolean>()
      prefs
        .filter((p: PreferenceDto) => !p.templateCode)
        .forEach((p: PreferenceDto) => map.set(p.channel, p.isEnabled))
      setPreferences(map)
    } catch {
      toast.error("获取偏好设置失败")
    } finally {
      setLoading(false)
    }
  }

  useEffect(() => { fetchPreferences() }, [])

  const toggleChannel = (channel: string) => {
    setPreferences((prev) => {
      const next = new Map(prev)
      const current = next.get(channel) ?? true // 默认开启
      next.set(channel, !current)
      return next
    })
  }

  const handleSave = async () => {
    setSaving(true)
    try {
      const updates: UpdatePreferenceRequest[] = channelConfig
        .filter((c) => !c.disabled)
        .map((c) => ({
          channel: c.channel,
          isEnabled: preferences.get(c.channel) ?? true,
        }))
      await updatePreferences(updates)
      toast.success("偏好设置已保存")
    } catch {
      toast.error("保存失败")
    } finally {
      setSaving(false)
    }
  }

  return (
    <AnimatedPage className="flex flex-col h-full">
      <div className="p-4 pb-0 space-y-4">
        <PageHeader title="通知偏好" description="管理各通知渠道的接收设置，紧急通知会忽略此设置强制发送" />
      </div>

      <PageToolbar
        actions={
          <>
            <ToolbarButton icon={Save} variant="primary" onClick={handleSave} disabled={saving}>
              {saving ? "保存中..." : "保存设置"}
            </ToolbarButton>
            <ToolbarButton icon={RefreshCw} onClick={fetchPreferences}>刷新</ToolbarButton>
          </>
        }
      />

      <div className="p-4 space-y-4 overflow-auto flex-1">
        {loading ? (
          <div className="text-center text-muted-foreground py-12">加载中...</div>
        ) : (
          <div className="grid gap-4 md:grid-cols-2 lg:grid-cols-3">
            {channelConfig.map((cfg) => {
              const isEnabled = preferences.get(cfg.channel) ?? true
              return (
                <Card key={cfg.channel} className={cfg.disabled ? "opacity-50" : ""}>
                  <CardHeader className="pb-3">
                    <div className="flex items-center justify-between">
                      <div className="flex items-center gap-2">
                        <span className="text-xl">{cfg.icon}</span>
                        <CardTitle className="text-base">{cfg.label}</CardTitle>
                      </div>
                      <Switch
                        checked={isEnabled}
                        onCheckedChange={() => toggleChannel(cfg.channel)}
                        disabled={cfg.disabled}
                      />
                    </div>
                  </CardHeader>
                  <CardContent>
                    <CardDescription>{cfg.description}</CardDescription>
                    {cfg.disabled && (
                      <p className="text-xs text-amber-600 mt-2">此渠道尚未实现，将在后续版本中上线</p>
                    )}
                  </CardContent>
                </Card>
              )
            })}
          </div>
        )}
      </div>
    </AnimatedPage>
  )
}

渠道配置：声明式数据驱动

channelConfig 数组定义了所有渠道的展示配置，页面通过 .map() 渲染卡片：

channelConfig (数据)
     │
     │ .map(cfg => <Card .../>)
     ▼
┌──────────────────────────────────────────────────┐
│ 配置项 → UI 组件的映射                             │
│                                                   │
│ channel     → key (React 列表渲染)                │
│ icon        → <span>{cfg.icon}</span>            │
│ label       → <CardTitle>{cfg.label}</CardTitle> │
│ description → <CardDescription>{cfg.description}</CardDescription>│
│ disabled    → className="opacity-50" + Switch disabled│
└──────────────────────────────────────────────────┘

【设计取舍】 为什么不用后端返回渠道列表？因为 UI 展示的 icon、label、description 是前端展示逻辑，后端不关心用铃铛还是信封图标。channelConfig 是前端专属的展示配置。

【易错点】 disabled: true 的渠道：微信和移动推送标注了 disabled: true，表示"尚未实现"。UI 效果是卡片半透明（opacity-50）、Switch 不可点击、显示"此渠道尚未实现"的黄色提示。这是功能预告的常见 UI 模式——让用户知道未来会有这个功能，但当前不可用。

🤔 导师提问：channelConfig 是前端硬编码的渠道配置。如果后端新增了第 6 个渠道（如"钉钉推送"），前端需要同步修改 channelConfig。这和 ASP.NET Core 中"数据库驱动菜单 vs 硬编码菜单"的取舍类似——你觉得什么情况下应该由后端返回渠道列表？什么情况下前端硬编码更合理？

偏好状态：Map<channel, isEnabled>

行代码解析
useState<Map<string, boolean>>(new Map())偏好状态【设计取舍】 用 Map 而非 Record<string, boolean> 存储。Map 的语义更清晰——"从渠道名到开关状态的映射"。new Map(prev) 创建副本比 {...prev} 更明确表达"创建新引用"的意图
.filter((p) => !p.templateCode)只取全局偏好【设计取舍】 PreferenceDto 中 templateCode 有值的是模板级偏好，null 的是全局偏好。当前 UI 只管理全局开关，不支持"某个模板单独关通知"
map.set(p.channel, p.isEnabled)填充 Map【易错点】 Map 的 key 是渠道字符串（如 "inApp"），value 是布尔开关。如果后端没返回某个渠道的偏好，Map 里就没有这个 key

🤔 导师提问：偏好状态用 Map<string, boolean> 存储，key 是渠道名（如 "inApp"），value 是开关状态。在 ASP.NET Core 后端，PreferenceDto 有 id、channel、isEnabled、templateCode 四个字段，但前端只用了 channel 和 isEnabled。为什么前端不需要 id？想想提交更新时后端怎么识别要更新哪条记录——是靠 id 还是靠 channel？

切换开关：toggleChannel

行代码解析
const next = new Map(prev)创建新 Map【易错点】 和数组一样，React 状态更新要求不可变数据。直接修改 prev 的 Map 不会触发重渲染：prev.set(channel, !current); return prev 是错误的
next.get(channel) ?? true默认值【易错点】 如果 Map 中没有某个渠道的 key（比如新用户后端还没创建偏好记录），next.get(channel) 返回 undefined。?? true 表示默认开启——新用户应该默认收到所有通知

保存偏好：handleSave

行代码解析
.filter((c) => !c.disabled)不保存 disabled 渠道【设计取舍】 微信和移动推送尚未实现，传给后端也没意义
preferences.get(c.channel) ?? true默认值【易错点】 和 toggleChannel 一样的默认值逻辑。用户没改过某个渠道 → Map 里没值 → 默认 true
一次性批量保存updatePreferences(updates)【设计取舍】 一个 PUT 请求保存所有渠道，比每个 Switch 变化都发一次请求更高效。用户可以"改了又改回来"而不触发无意义的 API 调用

🤔 导师提问：当前 toggleChannel 只修改本地 Map，不调 API，等到用户点"保存设置"才批量提交。如果用户切换了开关但没保存就关闭页面，修改就丢了。在 ASP.NET Core 中，表单的"未保存提示"通常怎么实现？前端的 beforeunload 事件你能用起来吗？

数据流：加载 → 展示 → 修改 → 保存

① 加载
getPreferences() ──→ PreferenceDto[]
  ├─ .filter(!templateCode) ──→ 只保留全局偏好
  └─ .forEach → Map.set(channel, isEnabled)

② 展示
channelConfig.map(cfg => {
  isEnabled = preferences.get(cfg.channel) ?? true
  return <Card><Switch checked={isEnabled} .../></Card>
})

③ 修改（纯本地）
toggleChannel(channel) ──→ Map.set(channel, !current)
⚠ 不发 API！等用户点"保存设置"

④ 保存
handleSave() ──→ channelConfig.filter(!disabled)
  │  .map(c => ({ channel, isEnabled: preferences.get() }))
  └─ updatePreferences(updates) ──→ PUT /api/notification-preferences

踩坑提醒

  1. channelConfig 是前端硬编码的：后端只存储偏好的键值对，不返回渠道列表元数据。新增渠道必须同步修改前端配置。
  2. ?? true 默认值：新用户没有偏好记录时，后端返回的 isEnabled 可能为 null，?? true 确保默认开启所有通知。
  3. toggleChannel 只修改本地 Map，不调 API：用户切换开关后必须手动点"保存设置"才会持久化。如果忘记保存就关闭页面，修改会丢失。
  4. .filter(!templateCode) 只取全局偏好：PreferenceDto 中 templateCode 有值的是模板级偏好，null 的是全局偏好，必须区分过滤。
  5. Map 的不可变更新：toggleChannel 中 new Map(prev) 创建新 Map 实例，确保 React 检测到引用变化触发重渲染。

概念级（理解 Why）

  1. 为什么 channelConfig 是前端硬编码的，而不是从后端获取渠道列表？
  2. 微信和移动推送标注 disabled: true，而不是直接从列表中移除，为什么？

推理级（推导 What-if）

  1. 如果后端添加了第 6 个渠道（如"钉钉推送"），前端需要改哪些地方？
  2. 当前 toggleChannel 只修改本地 Map，不调 API。如果用户切换了开关但没保存就关闭页面，数据会丢失吗？怎么改进？

动手级（代码实践）

  1. 给页面添加"未保存提示"：如果用户修改了开关但没保存，尝试离开页面时（关闭 Tab 或导航）弹出确认对话框。提示：用 beforeunload 事件。
  2. 实现模板级偏好：在每个 Card 下方添加"按模板设置"折叠面板，展示每个模板的独立开关。数据从 PreferenceDto.templateCode 过滤。

验证步骤

  1. 导航到通知偏好页面，观察 5 张渠道卡片加载完成（预期：站内信、邮件、短信为可操作状态，微信和移动推送为半透明 disabled 状态）
  2. 点击站内信的 Switch 关闭它，观察开关状态变化（预期：Switch 从开变为关，但页面无 API 请求——修改仅在本地）
  3. 点击"保存设置"按钮，观察 Network 面板发出 PUT /notify-api/api/notification-preferences 请求（预期：请求体包含 3 个渠道的偏好，站内信 isEnabled: false）
  4. 刷新页面，观察偏好是否持久化（预期：站内信仍为关闭状态，说明服务端已保存）
  5. 将站内信重新开启并保存，再次刷新确认恢复为开启状态（预期：偏好设置可双向切换并持久化）
