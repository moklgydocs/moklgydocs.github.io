配额管理

配额管理

|

这一步解决什么问题？ SaaS 多租户环境下，存储不是无限的。如果一个租户上传了 10TB 数据，其他租户就没有空间了。配额管理就是给每个租户设定存储上限，类似云服务商的"套餐容量"。类比 SQL Server 的 MAXSIZE 设置：ALTER DATABASE MyDb MODIFY FILE (SIZE = 10GB, MAXSIZE = 50GB)。前端配额页面要做的就是可视化这个上限——进度条、使用率、文件类型分布，让管理员和租户都能看清资源消耗。

前置知识

  • 01 篇文件服务架构：QuotaDto 类型定义（quotaBytes、usedBytes、usagePercentage）
  • 02 篇文件 API 层：quotaApi.getCurrent()、quotaApi.getStats()、quotaApi.getAllStats() 的用法
  • Promise.allSettled vs Promise.all 的区别

🤔 导师提问：后端配额校验通常在 Service 层做：上传前检查 usedBytes + fileSize > quotaBytes 则拒绝。前端配额页面只是展示，不参与校验。为什么前端的配额展示仍然重要？如果只靠后端校验，用户体验会有什么问题？

import { useState, useEffect, useCallback } from "react"
import { AnimatedPage } from "@/components/shared/animated-page"
import { toast } from "sonner"
import { HardDrive, FileType2, BarChart3, Loader2, RotateCcw } from "lucide-react"
import { PageHeader } from "@/components/shared/page-header"
import { StatCard } from "@/components/shared/stat-card"
import { EmptyState } from "@/components/shared/empty-state"
import { Card, CardContent, CardHeader, CardTitle } from "@/components/ui/card"
import { Progress } from "@/components/ui/progress"
import { Button } from "@/components/ui/button"
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"
import { Table, TableBody, TableCell, TableHead, TableHeader, TableRow } from "@/components/ui/table"
import { quotaApi } from "@/api/file/quota"
import type { QuotaDto, StorageStatsDto } from "@/types"
import { formatBytes } from "@/lib/file-utils"

/** 使用率颜色 class */
function progressColorClass(pct: number): string {
  if (pct >= 90) return "text-destructive"
  if (pct >= 70) return "text-warning"
  return "text-success"
}

/** 进度条颜色（CSS 变量覆盖） */
function progressBarClass(pct: number): string {
  if (pct >= 90) return "[&_[data-slot=progress-indicator]]:bg-destructive"
  if (pct >= 70) return "[&_[data-slot=progress-indicator]]:bg-warning"
  return ""
}

/** 计算剩余空间 */
function remainingSpace(quota: QuotaDto): string {
  const remaining = Math.max(0, quota.quotaBytes - quota.usedBytes)
  return formatBytes(remaining)
}

export default function FileQuotaPage() {
  const [quota, setQuota] = useState<QuotaDto | null>(null)
  const [stats, setStats] = useState<StorageStatsDto | null>(null)
  const [loadingQuota, setLoadingQuota] = useState(false)
  const [loadingStats, setLoadingStats] = useState(false)
  const [lastRefresh, setLastRefresh] = useState<Date>(new Date())

  const loadData = useCallback(async () => {
    setLoadingQuota(true)
    setLoadingStats(true)

    const [quotaRes, statsRes] = await Promise.allSettled([
      quotaApi.getCurrent(),
      quotaApi.getStats(),
    ])

    if (quotaRes.status === "fulfilled" && quotaRes.value.success && quotaRes.value.data?.usagePercentage !== undefined) {
      setQuota(quotaRes.value.data ?? null)
    } else if (quotaRes.status === "fulfilled" && quotaRes.value.success) {
      toast.error("配额数据格式异常")
    } else {
      toast.error("加载配额信息失败")
    }
    setLoadingQuota(false)

    if (statsRes.status === "fulfilled" && statsRes.value.success) {
      setStats(statsRes.value.data ?? null)
    } else {
      toast.error("加载存储统计失败")
    }
    setLoadingStats(false)
    setLastRefresh(new Date())
  }, [])

  useEffect(() => {
    loadData()
  }, [loadData])

  const typeEntries = stats
    ? Object.entries(stats.filesByType).sort(([, a], [, b]) => b - a)
    : []

  return (
    <AnimatedPage>
    <div className="p-6 space-y-6">
      <PageHeader
        title="存储配额"
        description="查看当前租户的存储使用情况与统计信息"
        lastUpdated={lastRefresh}

        <Tooltip>
          <TooltipTrigger asChild>
            <Button variant="outline" size="sm" onClick={loadData}>
              <RotateCcw className="h-3.5 w-3.5 mr-1" />
              刷新
            </Button>
          </TooltipTrigger>
          <TooltipContent>刷新配额数据</TooltipContent>
        </Tooltip>
      </PageHeader>

      {/* 配额使用概览 */}
      <Card size="sm" className="shadow-sm">
        <CardHeader className="pb-2">
          <CardTitle className="flex items-center gap-2 text-base">
            <HardDrive className="h-4 w-4" />
            配额使用情况
          </CardTitle>
        </CardHeader>
        <CardContent>
          {loadingQuota ? (
            <div className="flex items-center justify-center py-8">
              <Loader2 className="h-6 w-6 animate-spin text-muted-foreground" />
            </div>
          ) : quota ? (
            <div className="space-y-4">
              <div className="space-y-2">
                <div className="flex items-center justify-between text-sm">
                  <span>
                    已用{" "}
                    <span className={`font-semibold ${progressColorClass(quota.usagePercentage)}`}>
                      {formatBytes(quota.usedBytes)}
                    </span>
                    {" / "}
                    <span className="font-semibold">{formatBytes(quota.quotaBytes)}</span>
                  </span>
                  <span className={`font-bold text-base ${progressColorClass(quota.usagePercentage)}`}>
                    {quota.usagePercentage.toFixed(1)}%

逐行讲解

progressColorClass — 使用率分级着色

function progressColorClass(pct: number): string {
  if (pct >= 90) return "text-destructive"   // 红色
  if (pct >= 70) return "text-warning"       // 黄色
  return "text-success"                       // 绿色
}
  • 三级告警阈值：70% 警告、90% 危险。类比监控系统的 SLI 告警规则。【设计取舍】阈值写死在组件内，如果需要可配置可提取为常量或从后端获取。

progressBarClass — CSS 选择器覆盖进度条颜色

function progressBarClass(pct: number): string {
  if (pct >= 90) return "[&_[data-slot=progress-indicator]]:bg-destructive"
  if (pct >= 70) return "[&_[data-slot=progress-indicator]]:bg-warning"
  return ""
}
  • [&_[data-slot=progress-indicator]]：Tailwind 的任意变体语法，选中子元素 [data-slot=progress-indicator]。【易错点】不能直接给 <Progress> 组件传 className="bg-destructive"，因为 Progress 的根元素是容器而非指示条。必须穿透到内部元素。

🤔 导师提问：配额使用率达到 90% 时进度条变红，并显示"存储空间即将用满"警告。类比后端的告警系统（Prometheus + AlertManager），这里的 70%/90% 阈值是硬编码的。如果不同租户的告警阈值不同（比如付费租户 95% 才告警），这个设计需要怎么改？

Promise.allSettled — 并行加载配额和统计

const [quotaRes, statsRes] = await Promise.allSettled([
  quotaApi.getCurrent(),
  quotaApi.getStats(),
])
  • allSettled vs all：all 会在任一请求失败时整体 reject，allSettled 则等所有请求完成，各自报告成功/失败。【设计取舍】配额和统计是两个独立接口，一个失败不应影响另一个的展示。

🤔 导师提问：progressColorClass 和 progressBarClass 是两个独立函数，分别返回文字颜色和进度条颜色。如果只改了其中一个忘了改另一个，就会出现"文字红色但进度条绿色"的不一致。类比后端，这就像业务规则散落在多个地方。你能想到什么设计模式来确保告警颜色的一致性？

验证步骤

  1. 打开存储配额页面，确认顶部显示"已用 XX / 总配额 XX"，进度条颜色为绿色（使用率 < 70%）
  2. 上传多个文件使使用率超过 70%，刷新页面，确认进度条变为黄色，文字也变为 text-warning
  3. 继续上传文件使使用率接近 90%，确认进度条变为红色，且出现"存储空间即将用满"的警告文字
  4. 查看"文件类型分布"表格，确认各文件类型的数量和占用空间与实际上传一致，占比进度条正确显示百分比
  5. 点击"刷新"按钮，确认数据重新加载且 lastUpdated 时间更新

踩坑提醒

  1. Promise.allSettled 的结果判断：allSettled 返回的每个结果都有 status: "fulfilled" | "rejected"，必须检查 status 才能安全访问 value。直接访问 quotaRes.value 会在 rejected 时得到 undefined，导致运行时错误。
  2. 进度条颜色需要穿透到子元素：<Progress> 组件的根元素是容器，不是指示条。必须用 [&_[data-slot=progress-indicator]]:bg-destructive 这样的 Tailwind 任意变体语法选中内部元素，直接传 className="bg-destructive" 只会改变容器颜色而非进度条本身。
  3. 使用率分级着色一致性：progressColorClass 和 progressBarClass 是两个独立函数，如果只改了其中一个忘了改另一个，会出现"文字红色但进度条绿色"的不一致。应考虑合并为一个函数返回颜色配置对象。

🤔 思考题

概念级：配额使用率达到多少时，进度条会变成红色？
