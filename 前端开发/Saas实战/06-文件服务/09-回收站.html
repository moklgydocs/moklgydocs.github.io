回收站

回收站

|

这一步解决什么问题？ 文件删除不是"一刀切"——用户可能误删重要文件，需要后悔药。回收站就是这颗后悔药，类比 Windows 回收站或 Gmail 的"已删除邮件"。在后端，这对应软删除（Soft Delete）模式：UPDATE Files SET Status = 1 WHERE Id = @Id，而非 DELETE FROM Files WHERE Id = @Id。文件元数据保留，只是标记为"已删除"，在一定保留期内可以恢复。

前置知识

  • 01 篇文件服务架构：FILE_STATUS（Active=0, Deleted=1）软删除设计
  • 02 篇文件 API 层：filesApi.recycleBin()、filesApi.restore()、filesApi.purge()、批量操作的用法
  • 03 篇文件管理器：删除文件后的"撤销"Toast 模式（事务补偿）

🤔 导师提问：软删除在数据库中保留了已删除的记录，这意味着查询时需要加 WHERE Status = 0 过滤。类比 EF Core 的全局查询过滤器 HasQueryFilter(f => !f.IsDeleted)，前端回收站页面是否也需要类似的"过滤"？为什么 filesApi.list 和 filesApi.recycleBin 返回的数据天然不会混淆？

软删除 vs 硬删除

操作后端 SQL前端含义
删除（移入回收站）UPDATE ... SET Status = 1文件从列表消失，进入回收站
恢复UPDATE ... SET Status = 0文件回到原位置
永久删除DELETE FROM Files ...数据库物理删除，不可恢复

⚠️ 永久删除是不可逆操作，类比 SQL 的 DROP TABLE，必须二次确认。

🤔 导师提问：回收站页面用 AlertDialog（强制确认对话框）来保护永久删除操作，而普通删除（移入回收站）在 03 篇只用了一个 Toast + 撤销按钮。为什么两种删除的确认级别不同？类比后端，这就像"逻辑删除"和"物理删除"需要不同的审批流程——你在设计 API 时如何体现这种差异？

完整代码

来源：src/pages/file/recycle-bin.tsx

import { useState, useEffect, useCallback, useMemo } from "react"
import { useNavigate } from "react-router-dom"
import { AnimatedPage } from "@/components/shared/animated-page"
import { toast } from "sonner"
import { RotateCcw, Trash2, AlertTriangle } from "lucide-react"
import { PageHeader } from "@/components/shared/page-header"
import { ProTable } from "@/components/shared/pro-table"
import type { Column } from "@/components/shared/data-table"
import {
  AlertDialog, AlertDialogAction, AlertDialogCancel, AlertDialogContent,
  AlertDialogDescription, AlertDialogFooter, AlertDialogHeader,
  AlertDialogMedia, AlertDialogTitle,
} from "@/components/ui/alert-dialog"
import { QueryFilter } from "@/components/shared/query-filter"
import { Button } from "@/components/ui/button"
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"
import { filesApi } from "@/api/file/files"
import { Checkbox } from "@/components/ui/checkbox"
import type { FileObjectDto } from "@/types"

export default function FileRecycleBinPage() {
  const navigate = useNavigate()
  const [files, setFiles] = useState<FileObjectDto[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [loading, setLoading] = useState(false)

  // 选中状态
  const [selectedIds, setSelectedIds] = useState<Set<string>>(new Set())
  const hasSelection = selectedIds.size > 0

  // 搜索状态
  const [searchValue, setSearchValue] = useState("")

  // 批量操作确认
  const [batchAction, setBatchAction] = useState<"restore" | "purge" | null>(null)
  const [submitting, setSubmitting] = useState(false)

  // 单选
  const toggleSelect = (id: string) => {
    setSelectedIds(prev => {
      const next = new Set(prev)
      if (next.has(id)) next.delete(id)
      else next.add(id)
      return next
    })
  }

  // 全选 / 取消全选
  const toggleSelectAll = () => {
    if (hasSelection) setSelectedIds(new Set())
    else setSelectedIds(new Set(files.map(f => f.id)))
  }

  /** 加载回收站列表 */
  const loadData = useCallback(async () => {
    setLoading(true)
    try {
      const res = await filesApi.recycleBin({ pageIndex: page, pageSize: 20, fileName: searchValue || undefined })
      setFiles(res.data?.items ?? [])
      setTotal(res.data?.totalCount ?? 0)
      setSelectedIds(new Set())
    } catch {
      toast.error("加载回收站失败")
    } finally {
      setLoading(false)
    }
  }, [page, searchValue])

  useEffect(() => { loadData() }, [loadData])

  /** 单个恢复 */
  const [restoreTarget, setRestoreTarget] = useState<FileObjectDto | null>(null)
  const [restoring, setRestoring] = useState(false)

  const handleRestore = async () => {
    if (!restoreTarget) return
    setRestoring(true)
    try {
      await filesApi.restore(restoreTarget.id)
      toast.success("已恢复", {
        action: { label: "查看", onClick: () => navigate("/file") }
      })
      setRestoreTarget(null)
      loadData()
    } catch {
      toast.error("恢复失败")
    } finally {
      setRestoring(false)
    }
  }

  /** 单个永久删除 */
  const [purgeTarget, setPurgeTarget] = useState<FileObjectDto | null>(null)
  const [purging, setPurging] = useState(false)

  const handlePurge = async () => {
    if (!purgeTarget) return
    setPurging(true)
    try {
      await filesApi.purge(purgeTarget.id)
      toast.success("文件已永久删除，无法恢复")
      setPurgeTarget(null)
      loadData()
    } catch {
      toast.error("永久删除失败")
    } finally {
      setPurging(false)
    }
  }

  /** 批量恢复 */
  const handleBatchRestore = async () => {
    setSubmitting(true)
    try {
      const ids = Array.from(selectedIds)
      const res = await filesApi.batchRestore(ids)
      toast.success(`成功恢复 ${res.data?.successCount ?? 0} 个文件` +
        ((res.data?.failedCount ?? 0) > 0 ? `，${res.data?.failedCount} 个失败` : ""))
      setSelectedIds(new Set())
      setBatchAction(null)
      loadData()
    } catch {
      toast.error("批量恢复失败")
    } finally {
      setSubmitting(false)
    }
  }

  /** 批量永久删除 */
  const handleBatchPurge = async () => {
    setSubmitting(true)
    try {
      const ids = Array.from(selectedIds)
      const res = await filesApi.batchPurge(ids)
      toast.success(`成功删除 ${res.data?.successCount ?? 0} 个文件` +
        ((res.data?.failedCount ?? 0) > 0 ? `，${res.data?.failedCount} 个失败` : ""))
      setSelectedIds(new Set())
      setBatchAction(null)
      loadData()
    } catch {
      toast.error("批量删除失败")
    } finally {
      setSubmitting(false)
    }
  }

  const columns: Column<FileObjectDto>[] = useMemo(() => [
    {
      key: "__select__",
      title: (
        <Checkbox
          checked={hasSelection && files.length > 0 && selectedIds.size === files.length}
          onCheckedChange={() => toggleSelectAll()}
        />
      ),
      width: "48px",
      render: (_: unknown, record: FileObjectDto) => (
        <Checkbox
          checked={selectedIds.has(record.id)}
          onCheckedChange={() => toggleSelect(record.id)}
        />
      ),
    },
    {
      key: "displayName",
      title: "文件名",
      render: (_: unknown, record: FileObjectDto) => (
        <span className="font-medium">{record.displayName ?? record.fileName}</span>
      ),
    },
    {
      key: "sizeBytes",
      title: "大小",
      width: "100px",
      render: (_: unknown, record: FileObjectDto) =>
        record.sizeBytes === 0 ? "0 B" :
        `${((record.sizeBytes / 1024 / 1024) > 1
          ? (record.sizeBytes / 1024 / 1024).toFixed(2) + " MB"
          : (record.sizeBytes / 1024).toFixed(2) + " KB")}`,
    },
    {
      key: "lastModificationTime",
      title: "删除时间",
      width: "160px",
      render: (_: unknown, record: FileObjectDto) =>
        record.lastModificationTime
          ? new Date(record.lastModificationTime).toLocaleString("zh-CN")
          : "-",
    },
    {
      key: "daysRemaining",
      title: "剩余天数",
      width: "100px",
      render: (_: unknown, record: FileObjectDto) => {
        if (!record.lastModificationTime) {
          return <span className="text-muted-foreground text-xs">立即清理</span>
        }
        const RETENTION_DAYS = 30
        const deleteTime = new Date(record.lastModificationTime).getTime()
        const now = Date.now()
        const elapsedDays = (now - deleteTime) / (1000 * 60 * 60 * 24)
        const remaining = Math.max(0, Math.ceil(RETENTION_DAYS - elapsedDays))
        if (remaining <= 0) {
          return <span className="text-destructive text-xs font-medium">立即清理</span>
        }
        if (remaining > 365) {
          return <span className="text-muted-foreground text-xs">永久保留</span>
        }
        return <span className="text-warning text-xs">剩余 {remaining} 天</span>
      },
    },
    {
      key: "__actions__",
      title: "操作",
      width: "140px",
      render: (_: unknown, record: FileObjectDto) => (
        <div className="flex items-center gap-1">
          <Button variant="outline" size="sm" className="h-7 text-xs"
            onClick={() => setRestoreTarget(record)}>
            <RotateCcw className="mr-1 h-3.5 w-3.5" />
            恢复
          </Button>
          <Button variant="outline" size="sm"
            className="h-7 text-xs text-destructive border-destructive hover:bg-destructive/10"
            onClick={() => setPurgeTarget(record)}>
            <Trash2 className="mr-1 h-3.5 w-3.5" />
            永久删除
          </Button>
        </div>
      ),
    },
  ], [hasSelection, selectedIds, files])

  return (
    <AnimatedPage>
    <div className="p-6 space-y-4">
      <PageHeader
        title="回收站"
        description="管理已删除的文件，可在保留期内恢复"
        breadcrumb={[{ label: "文件管理", href: "/file" }, { label: "回收站" }]}
      >
        <div className="flex items-center gap-1.5 text-sm text-warning bg-warning/10 px-3 py-1.5 rounded-md border border-warning/30">
          <AlertTriangle className="h-3.5 w-3.5" />
          永久删除后无法恢复
        </div>
      </PageHeader>

      <QueryFilter
        fields={[{ key: "keyword", label: "文件名", type: "input", placeholder: "搜索文件名..." }]}
        values={{ keyword: searchValue }}
        onValuesChange={(v) => setSearchValue(v.keyword ?? "")}
        onSearch={loadData}
        onReset={() => { setSearchValue(""); }}
      />

      {/* 批量操作栏 */}
      {hasSelection && (
        <div className="flex items-center gap-2 px-1">
          <span className="text-sm text-muted-foreground">已选 {selectedIds.size} 个文件</span>
          <Tooltip>
            <TooltipTrigger asChild>
              <Button variant="outline" size="sm" className="h-7 text-xs"
                onClick={() => setBatchAction("restore")}>
                <RotateCcw className="mr-1 h-3.5 w-3.5" />
                批量恢复
              </Button>
            </TooltipTrigger>
            <TooltipContent>恢复选中的文件</TooltipContent>
          </Tooltip>
          <Tooltip>
            <TooltipTrigger asChild>
              <Button variant="outline" size="sm"
                className="h-7 text-xs text-destructive border-destructive hover:bg-destructive/10"
                onClick={() => setBatchAction("purge")}>
                <Trash2 className="mr-1 h-3.5 w-3.5" />
                批量永久删除
              </Button>
            </TooltipTrigger>
            <TooltipContent>永久删除选中的文件</TooltipContent>
          </Tooltip>
        </div>
      )}

      <ProTable
        columns={columns}
        data={files}
        total={total}
        page={page}
        pageSize={20}
        loading={loading}
        onPageChange={(p) => setPage(p)}
        onRefresh={loadData}
        rowKey="id"
        emptyState={{
          title: "回收站为空",
          description: "回收站中没有文件",
        }}
      />

      {/* 单个恢复确认 / 单个永久删除确认 / 批量恢复确认 / 批量永久删除确认 */}
      {/* ... AlertDialog 组件，见完整源码 ... */}
    </div>
    </AnimatedPage>
  )
}

逐行讲解

batchAction — 单状态管理两种批量操作

const [batchAction, setBatchAction] = useState<"restore" | "purge" | null>(null)
  • 用一个 state 管理两种确认弹窗："restore" = 批量恢复确认，"purge" = 批量永久删除确认，null = 不弹窗。【设计取舍】也可以用两个 boolean 状态（batchRestoreOpen / batchPurgeOpen），但单状态更简洁，且互斥——不可能同时弹两个确认框。

🤔 导师提问：batchAction 是 "restore" | "purge" | null 的联合类型状态，类比后端可以用枚举 enum BatchAction { Restore, Purge, None }。TypeScript 的联合类型和 C# 枚举在类型安全上有什么差异？如果给 batchAction 赋了一个拼写错误的字符串，两种语言分别会在什么时候报错？

剩余天数计算

const RETENTION_DAYS = 30
const deleteTime = new Date(record.lastModificationTime).getTime()
const now = Date.now()
const elapsedDays = (now - deleteTime) / (1000 * 60 * 60 * 24)
const remaining = Math.max(0, Math.ceil(RETENTION_DAYS - elapsedDays))
  • RETENTION_DAYS = 30：硬编码 30 天保留期。【易错点】TODO 注释说明应从后端 API 获取保留策略，当前是前端假设值。如果后端改为 60 天保留期，前端还在显示 30 天就会误导用户。
  • Math.max(0, ...)：确保不显示负数。如果文件已超期但未被自动清理，显示"立即清理"而非"剩余 -5 天"。

恢复成功的 Toast 导航

toast.success("已恢复", {
  action: { label: "查看", onClick: () => navigate("/file") }
})
  • action 按钮：恢复成功后提供"查看"快捷入口，跳转到文件管理页。类比 Gmail 删除邮件后的"撤销"按钮，给用户即时反馈的下一步操作。

batchPurge — del 方法带 body

batchPurge(fileIds: string[]) {
  return del<BatchOperationResult>(
    "/api/files/recycle-bin/batch-purge",
    { data: { fileIds } }  // ← DELETE 请求带 body
  )
}
  • { data: { fileIds } }：axios 的 del 方法第二个参数是 config，data 字段用于传请求体。【易错点】不能写成 del("/api/...", { fileIds })，因为 del 的第二个参数不是请求体而是 config 对象。DELETE 请求带 body 不是标准做法，但有些后端框架支持。

🤔 导师提问：handleRestore 成功后的 Toast 带"查看"按钮跳转到文件管理页，而 handlePurge 成功后只显示"文件已永久删除"。为什么恢复需要提供导航而永久删除不需要？类比后端，这就像事务回滚后可以继续操作，但 DROP TABLE 后只能重建——两种操作后的"下一步"有什么本质不同？

验证步骤

  1. 在文件管理器中删除一个文件，确认弹出"已移入回收站"Toast，然后打开回收站页面，确认该文件出现在列表中
  2. 在回收站中找到该文件，观察"剩余天数"列是否正确显示（如"剩余 30 天"），点击"恢复"按钮，确认弹出恢复确认对话框
  3. 确认恢复后，文件从回收站列表中消失，点击 Toast 中的"查看"按钮跳转到文件管理器，确认文件重新出现在原位置
  4. 再删除一个文件，在回收站中点击"永久删除"，确认弹出 AlertDialog 二次确认（不是普通确认），确认后文件彻底消失
  5. 选中多个文件，点击"批量恢复"，确认所有选中文件恢复成功，Toast 显示"成功恢复 X 个文件"

踩坑提醒

  1. RETENTION_DAYS = 30 是前端硬编码：当前保留天数是前端假设值，未从后端获取。如果后端改为 60 天保留期，前端还在显示 30 天就会误导用户。应从后端 API 获取保留策略。
  2. 永久删除必须用 AlertDialog 二次确认：永久删除是不可逆操作（类比 SQL DROP TABLE），不能用普通确认框或 Toast。AlertDialog 会阻止用户的其他操作直到做出选择，确保不会误操作。
  3. del 方法带 body 的写法：filesApi.batchPurge 使用 del<BatchOperationResult>("/api/files/recycle-bin/batch-purge", { data: { fileIds } })，注意 del 的第二个参数是 config 对象而非请求体，必须用 { data: ... } 包裹。直接传 { fileIds } 会被当作 config 而非请求体。
