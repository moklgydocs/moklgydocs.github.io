文件管理器

文件管理器

|

这一步解决什么问题？ API 层建好了，现在要构建文件管理的核心界面——文件管理器。这是用户与文件服务交互的主入口，类似于 Windows 资源管理器或 macOS Finder。类比 ASP.NET Core 的文件管理场景：你可能用 Directory.GetDirectories() 列文件夹、Directory.GetFiles() 列文件、File.Move() 移动文件——但那是服务端命令式操作。前端需要把这些操作变成交互式 UI：左侧文件夹树、右侧文件列表、面包屑导航、批量操作栏。

前置知识

  • 02 篇文件 API 层：filesApi（列表、上传、下载、删除、批量操作）和 foldersApi（树结构、CRUD）
  • React useState + useCallback + useEffect 的基本使用
  • ASP.NET Core Directory/File 静态类的文件操作类比

为什么用"左侧树 + 右侧列表"布局？

这不是随意选择。在 Windows Explorer、macOS Finder、Google Drive 中，这种布局已经是事实标准。类比后端开发工具：

  • Solution Explorer（VS）= 左侧文件夹树
  • 代码编辑区 = 右侧文件列表/预览

用户的心智模型已经固化，不要发明新布局。

/**
 * 文件夹树节点组件的 Props 接口
 */
interface FolderTreeItemProps {
  node: FolderTreeNode
  selectedId: string | null
  onSelect: (id: string, name: string, path: string) => void
  onRename: (folder: FolderTreeNode) => void
  onDelete: (folder: FolderTreeNode) => void
  depth?: number
}

/**
 * 文件夹树节点组件
 * 递归渲染文件夹层级结构，支持展开/折叠、选中、重命名和删除操作。
 */
function FolderTreeItem({
  node,
  selectedId,
  onSelect,
  onRename,
  onDelete,
  depth = 0,
}: FolderTreeItemProps) {
  const [expanded, setExpanded] = useState(true)
  const isSelected = selectedId === node.id

  return (
    <div>
      <div
        className={`group flex items-center gap-1 rounded px-1 py-1 cursor-pointer text-sm transition-colors ${
          isSelected ? "bg-primary/10 text-primary font-medium" : "hover:bg-muted"
        }`}
        style={{ paddingLeft: `${(depth + 1) * 12}px` }}
      >
        {node.children.length > 0 ? (
          <button
            onClick={(e) => {
              e.stopPropagation()
              setExpanded((prev) => !prev)
            }}
            className="shrink-0"
          >
            <ChevronRight
              className={`h-3 w-3 transition-transform ${expanded ? "rotate-90" : ""}`}
            />
          </button>
        ) : (
          <span className="w-3 shrink-0" />
        )}

        <FolderOpen className="h-3.5 w-3.5 shrink-0 text-amber-500" />

        <span
          className="flex-1 truncate"
          onClick={() => onSelect(node.id, node.name, node.fullPath)}
        >
          {node.name}
        </span>

        <DropdownMenu>
          <DropdownMenuTrigger asChild>
            <button
              className="opacity-0 group-hover:opacity-100 p-0.5 rounded hover:bg-muted-foreground/20"
              onClick={(e) => e.stopPropagation()}
            >
              <MoreHorizontal className="h-3.5 w-3.5" />
            </button>
          </DropdownMenuTrigger>
          <DropdownMenuContent align="start" className="text-xs">
            <DropdownMenuItem onClick={() => onRename(node)}>
              <Pencil className="mr-1.5 h-3.5 w-3.5" />
              重命名
            </DropdownMenuItem>
            <DropdownMenuSeparator />
            <DropdownMenuItem
              className="text-destructive focus:text-destructive"
              onClick={() => onDelete(node)}
            >
              <Trash2 className="mr-1.5 h-3.5 w-3.5" />
              删除
            </DropdownMenuItem>
          </DropdownMenuContent>
        </DropdownMenu>
      </div>

      {expanded && node.children.length > 0 && (
        <div>
          {node.children.map((child) => (
            <FolderTreeItem
              key={child.id}
              node={child}
              selectedId={selectedId}
              onSelect={onSelect}
              onRename={onRename}
              onDelete={onDelete}
              depth={depth + 1}
            />
          ))}
        </div>
      )}
    </div>
  )
}

移动文件对话框

interface MoveDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  folders: FolderTreeNode[]
  onConfirm: (targetFolderId: string | null) => void
  loading?: boolean
}

function MoveDialog({ open, onOpenChange, folders, onConfirm, loading }: MoveDialogProps) {
  const [selected, setSelected] = useState<string>("__root__")

  const flattenFolders = (nodes: FolderTreeNode[], depth = 0): { id: string; name: string; depth: number }[] => {
    return nodes.flatMap((n) => [
      { id: n.id, name: n.name, depth },
      ...flattenFolders(n.children, depth + 1),
    ])
  }

  const allFolders = flattenFolders(folders)

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="max-w-sm">
        <DialogHeader>
          <DialogTitle>移动到文件夹</DialogTitle>
        </DialogHeader>
        <Select value={selected} onValueChange={setSelected}>
          <SelectTrigger>
            <SelectValue />
          </SelectTrigger>
          <SelectContent>
            <SelectItem value="__root__">根目录</SelectItem>
            {allFolders.map((f) => (
              <SelectItem key={f.id} value={f.id}>
                {"　".repeat(f.depth) + f.name}
              </SelectItem>
            ))}
          </SelectContent>
        </Select>
        <DialogFooter>
          <Button variant="outline" onClick={() => onOpenChange(false)} disabled={loading}>
            取消
          </Button>
          <Button
            onClick={() => onConfirm(selected === "__root__" ? null : selected)}
            disabled={loading}
          >
            {loading ? "移动中..." : "确认移动"}
          </Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  )
}

下载逻辑（大文件预签名 URL + 小文件 Blob）

  /** 大文件阈值：超过此大小使用预签名 URL 下载，避免内存溢出 */
  const PRESIGNED_DOWNLOAD_THRESHOLD = 10 * 1024 * 1024 // 10MB

  /** 下载单文件 */
  const handleDownload = async (file: FileObjectDto) => {
    try {
      const fileName = file.displayName ?? file.fileName

      // 大文件走预签名 URL：浏览器直接从 MinIO/S3 下载，零内存开销
      if (file.sizeBytes > PRESIGNED_DOWNLOAD_THRESHOLD) {
        const res = await filesApi.getPresignedDownloadUrl(file.id)
        const presignedUrl = res.data?.url
        if (!presignedUrl) {
          toast.error("获取下载链接失败")
          return
        }
        const a = document.createElement("a")
        a.href = presignedUrl
        a.download = fileName
        a.target = "_blank"
        a.rel =noopener noreferrer"
        document.body.appendChild(a)
        a.click()
        setTimeout(() => document.body.removeChild(a), 100)
        return
      }

      // 小文件走 blob 下载
      const res = await filesApi.download(file.id)
      const blob = res.data instanceof Blob
        ? res.data
        : new Blob([res.data as BlobPart], { type: file.contentType ?? "application/octet-stream" })

      const url = URL.createObjectURL(blob)
      const a = document.createElement("a")
      a.href = url
      a.download = fileName
      document.body.appendChild(a)
      a.click()
      setTimeout(() => {
        document.body.removeChild(a)
        URL.revokeObjectURL(url)
      }, 100)
    } catch {
      toast.error("下载失败")
    }
  }

逐行讲解

FolderTreeItem 递归渲染

function FolderTreeItem({ node, selectedId, onSelect, onRename, onDelete, depth = 0 }: FolderTreeItemProps) {
  const [expanded, setExpanded] = useState(true)  // ← 默认展开
  • depth = 0：递归深度参数，用于计算缩进。类比后端递归方法中的 level 参数。【性能陷阱】如果文件夹树超过 1000 节点，应考虑虚拟滚动（如 react-window），否则 DOM 节点过多。
  • useState(true)：默认展开所有节点。【设计取舍】也可改为默认折叠、按需加载（惰性展开），适合超大树。

style={{ paddingLeft: \${(depth + 1) * 12}px` }}`

  • 用 style 而非 Tailwind 的 pl-* 是因为缩进量是动态计算的。12px 是每级缩进量，类似 VS Code 的树缩进。

flattenFolders — 树 → 扁平列表

const flattenFolders = (nodes: FolderTreeNode[], depth = 0): { id: string; name: string; depth: number }[] => {
  return nodes.flatMap((n) => [
    { id: n.id, name: n.name, depth },
    ...flattenFolders(n.children, depth + 1),
  ])
}
  • 递归将树扁平化为列表，用于移动对话框的 Select 下拉。【易错点】"　".repeat(f.depth) 用全角空格缩进，半角空格会被 HTML 折叠。

下载双策略

const PRESIGNED_DOWNLOAD_THRESHOLD = 10 * 1024 * 1024 // 10MB
  • ≤10MB：走 filesApi.download() → 后端返回 Blob → 前端 URL.createObjectURL → 触发下载
  • >10MB：走 filesApi.getPresignedDownloadUrl() → 拿到 MinIO 预签名 URL → 浏览器直接从 MinIO 下载

【性能陷阱】大文件走 Blob 下载会把整个文件加载到浏览器内存。1GB 文件 = 1GB JS 堆占用，可能直接 OOM。预签名 URL 让浏览器直接从存储后端下载，零内存开销。

URL.revokeObjectURL(url)

setTimeout(() => {
  document.body.removeChild(a)
  URL.revokeObjectURL(url)
}, 100)
  • 必须调用 revokeObjectURL：每个 createObjectURL 都会在内存中持有 Blob 引用，不释放就内存泄漏。【易错点】setTimeout 延迟 100ms 是因为 a.click() 是异步的，立即释放会导致下载中断。

🤔 导师提问：删除文件后弹出的 Toast 带一个"撤销"按钮，点击后调用 filesApi.restore(fileId) 恢复文件。类比后端，这就像"事务补偿"而非"事务回滚"——先提交删除，再通过反向操作恢复。这种模式和数据库事务回滚相比，有什么风险？

验证步骤

  1. 打开文件管理器页面，点击左侧文件夹树中的不同文件夹，观察右侧文件列表是否随之切换，确认 currentFolderId 联动正确
  2. 右键点击文件夹树节点，选择"重命名"，输入新名称后确认，检查文件夹树和面包屑导航是否同步更新
  3. 选中一个文件，点击下载，检查小文件（≤10MB）是否通过 Blob 方式下载（Network 面板看到 /download 请求，response type 为 blob）
  4. 删除一个文件，观察是否弹出"已移入回收站"Toast 且带"撤销"按钮，点击"撤销"后文件重新出现在列表中

踩坑提醒

  1. 缩略图 <img> 不携带 Bearer Token：表格列定义中 <img src={thumbUrl}> 直接请求后端缩略图接口，但 <img> 标签不走 axios 拦截器，不会自动携带 Token。对于私有文件（accessLevel = 0），缩略图请求会返回 401。生产环境应使用 02 篇的 fetchImageBlobUrl 先 fetch 再创建 Blob URL，或让后端对缩略图接口做特殊处理。
  2. flattenFolders 用全角空格缩进：移动对话框中 "　".repeat(f.depth) 使用全角空格，因为 HTML 会折叠连续半角空格。如果误用半角空格，文件夹层级缩进会丢失。
  3. URL.revokeObjectURL 必须延迟调用：下载逻辑中 setTimeout(() => URL.revokeObjectURL(url), 100) 延迟 100ms 是因为 a.click() 是异步的，立即释放 Blob URL 会导致下载中断。
