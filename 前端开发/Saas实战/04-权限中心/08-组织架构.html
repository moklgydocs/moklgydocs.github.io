08 - 组织架构

08 - 组织架构

这一步解决什么问题？ 组织架构是权限中心的"骨架"——它定义了公司、部门、岗位的层级关系，为数据权限和审批流程提供基础。就像 ASP.NET Core 里 Claim 中的组织信息（部门ID、岗位ID），权限中心的组织架构把用户映射到组织树上。我们要实现左右分栏的组织管理页面：左侧是公司+部门的混合树，右侧是选中节点的详情面板。

前置知识

阅读本文档前，你需要了解：

  • 01-RBAC模型与权限树：数据权限与组织架构的关系
  • 02-权限API层：companiesApi、orgUnitsApi 的调用方式
  • 递归组件模式：React 中递归渲染树形结构的方法
  • 左右分栏布局：CSS Flex 布局中 flex-1、min-w-0 的用法

一、ASP.NET Core 类比：组织架构 = Claim 中的组织信息

在 ASP.NET Core 里，用户的组织信息存在 JWT Claim 中：

// ASP.NET Core: 从 Claim 中读取组织信息
var companyId = User.FindFirst("CompanyId")?.Value;
var departmentId = User.FindFirst("DepartmentId")?.Value;
var positionId = User.FindFirst("PositionId")?.Value;

// 数据权限过滤
var query = _dbContext.PurchaseOrders
    .Where(o => o.CompanyId == companyId);  // 只能看到本公司的数据

权限中心的组织架构更完善：

JWT Claim 方式                    →    权限中心组织架构
───────────────                  →    ────────────────
组织信息存在 JWT 中（静态）        →    组织信息在数据库中（动态可修改）
只有简单的 ID 引用                →    完整的树形结构（公司→子公司→部门→子部门）
修改组织需要重新签发 Token        →    修改组织即时生效
无法表达层级关系                  →    path 字段记录完整层级路径

二、数据模型：两棵树

组织架构由两棵独立的树组成：

2.1 公司树（支持上下级公司嵌套）

// src/types/index.ts
export interface CompanyDto {
  id: string
  parentId: string | null
  code: string           // 公司编码
  name: string           // 公司名称
  shortName: string | null
  profile: CompanyProfileDto | null  // 工商信息（法人、税号等）
  path: string           // 层级路径，如 "/总部/华东区/上海分公司"
  level: number          // 层级深度
  sort: number
  isEnabled: boolean
  creationTime: string
  children: CompanyDto[]  // 子公司列表（递归嵌套）
}

export interface CompanyProfileDto {
  id: string
  companyId: string
  legalPerson: string | null    // 法人
  taxNumber: string | null      // 税号
  address: string | null
  contactPhone: string | null
}

2.2 部门树（组织单元）

export interface OrgUnitDto {
  id: string
  parentId: string | null
  code: string           // 部门编码
  displayName: string    // 部门名称
  path: string           // 层级路径
  level: number
  sort: number
  isEnabled: boolean
  children: OrgUnitDto[] // 子部门列表（递归嵌套）
}

2.3 混合树节点

🤔 导师提问：公司树和部门树是两棵独立的树，但前端用 OrgTreeNode 联合类型把它们合并成一棵可视化树。在 ASP.NET Core 中，如果你用 EF Core 加载两棵树，通常需要两个 DbSet 和两次查询。而前端这里把它们合成一棵树展示。为什么不在数据库层面就设计成一棵混合树？提示：想想"部门必须属于某个公司"这个约束——如果用一棵混合树，父子关系的类型约束怎么表达？

前端需要把两棵树合并为一棵可视化树，使用联合类型 OrgTreeNode：

export type OrgTreeNode =
  | { type: "company"; data: CompanyDto; children: OrgTreeNode[] }
  | { type: "orgUnit"; data: OrgUnitDto; children: OrgTreeNode[] }

四、通用 Tree 组件的使用

组织树使用了项目自研的 <Tree> 通用组件，支持搜索、右键菜单和自定义渲染：

// src/pages/perm/organization/org-tree-panel.tsx

/** 混合树节点扩展数据 */
interface OrgNodeExtra {
  type: "company" | "orgUnit"
  raw: CompanyDto | OrgUnitDto
}

/** 将后端两棵树转换为通用 TreeNodeData */
function toTreeData(companies: CompanyDto[], orgUnits: OrgUnitDto[]): TreeNodeData<OrgNodeExtra>[] {
  const companyNodes: TreeNodeData<OrgNodeExtra>[] = companies.map((c) => ({
    id: `company:${c.id}`,
    parentId: c.parentId ? `company:${c.parentId}` : null,
    displayName: c.name,
    path: c.path,
    level: c.level,
    sort: c.sort,
    icon: "Building2",
    isEnabled: c.isEnabled,
    code: c.code,
    children: toTreeData(c.children ?? [], []),
    data: { type: "company" as const, raw: c },
  }))

  const orgUnitNodes: TreeNodeData<OrgNodeExtra>[] = orgUnits.map((ou) => ({
    id: `orgUnit:${ou.id}`,
    parentId: ou.parentId ? `orgUnit:${ou.parentId}` : null,
    displayName: ou.displayName,
    path: ou.path,
    level: ou.level,
    sort: ou.sort,
    icon: "FolderTree",
    isEnabled: ou.isEnabled,
    code: ou.code,
    children: toTreeData([], ou.children ?? []),
    data: { type: "orgUnit" as const, raw: ou },
  }))

  return [...companyNodes, ...orgUnitNodes]
}

4.1 ID 前缀策略

🤔 导师提问：公司节点 ID 格式为 company:{id}，部门节点 ID 格式为 orgUnit:{id}。这种"前缀 + 真实 ID"的编码策略，在 ASP.NET Core 中有类似的做法吗？想想 Claim 的 Type 字段——它也是"前缀 + 名称"的格式（如 http://schemas.xmlsoap.org/ws/2005/05/identity/claims/name）。前缀策略解决了什么问题？如果不加前缀，公司 ID 和部门 ID 碰巧相同时会怎样？

公司节点 ID 格式为 company:{id}，部门节点 ID 格式为 orgUnit:{id}。前缀确保两种节点的 ID 不会冲突，也便于从 ID 解析出节点类型。

4.2 自定义节点渲染器

🤔 导师提问：OrgNodeRenderer 根据 extra.type 决定显示 Building2（公司）还是 FolderTree（部门）图标，还根据 isEnabled 决定是否显示删除线和"禁"标签。在 ASP.NET Core Razor 中，你会用 @if 条件渲染不同的 HTML。React 的 JSX 条件渲染（{condition && <Element />}）和 Razor 的 @if 有什么区别？为什么 React 推荐用 {condition && ...} 而不是三元表达式？

function OrgNodeRenderer({ node, isExpanded, isSelected, toggleExpand, indent, hasChildren }: TreeNodeRendererProps<OrgNodeExtra>) {
  const extra = node.data!
  const isCompany = extra.type === "company"
  const IconComp = isCompany ? Building2 : FolderTree
  const iconColor = isCompany ? "text-blue-500" : "text-amber-500"

  return (
    <div
      className={`flex items-center gap-1.5 py-1.5 px-2 rounded-md cursor-pointer group transition-colors ${
        isSelected ? "bg-primary/10 text-primary" : "hover:bg-muted/50"
      }`}
      style={{ paddingLeft: indent }}
      onClick={() => toggleExpand()}
    >
      {/* 展开箭头 */}
      <button className="h-5 w-5 flex items-center justify-center shrink-0"
        onClick={(e) => { e.stopPropagation(); if (hasChildren) toggleExpand() }}>
        {hasChildren ? (
          <svg className={`h-3.5 w-3.5 text-muted-foreground transition-transform duration-200 ${isExpanded ? "rotate-90" : ""}`}
            viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2">
            <polyline points="9 18 15 12 9 6" />
          </svg>
        ) : (
          <span className="h-3.5 w-3.5" />
        )}
      </button>
      {/* 类型图标 */}
      <IconComp className={`h-4 w-4 ${iconColor} shrink-0`} />
      {/* 名称 */}
      <span className={`text-sm truncate flex-1 ${!node.isEnabled ? "text-muted-foreground line-through" : ""}`}>
        {node.displayName}
      </span>
      {/* 禁用标签 */}
      {!node.isEnabled && (
        <span className="text-[10px] px-1 py-0 bg-muted rounded shrink-0">禁</span>
      )}
    </div>
  )
}

五、主页面：状态编排

5.1 并行加载两棵树

// src/pages/perm/organization/index.tsx
export default function OrganizationPage() {
  const [companyTree, setCompanyTree] = useState<CompanyDto[]>([])
  const [orgUnitTree, setOrgUnitTree] = useState<OrgUnitDto[]>([])
  const [selectedNode, setSelectedNode] = useState<OrgTreeNode | null>(null)
  // ... 对话框状态

  /** 并行加载公司树和部门树数据 */
  const fetchData = useCallback(async () => {
    setLoading(true)
    try {
      const [companyRes, orgUnitRes] = await Promise.all([
        companiesApi.getTree(),
        orgUnitsApi.getTree(),
      ])
      if (companyRes.success && companyRes.data) setCompanyTree(companyRes.data)
      if (orgUnitRes.success && orgUnitRes.data) setOrgUnitTree(orgUnitRes.data)
    } catch {
      toast.error("获取组织数据失败")
    } finally {
      setLoading(false)
    }
  }, [])

  useEffect(() => { fetchData() }, [fetchData])
  // ...
}

🤔 导师提问：fetchData 使用 Promise.all 并行加载公司树和部门树。在 ASP.NET Core 中，Task.WhenAll 做同样的事。但注意这里有一个细节：两个请求都成功才更新状态（if (companyRes.success && companyRes.data)）。如果公司树加载成功但部门树失败，页面只显示公司树——这是合理的行为吗？如果两个请求应该"要么全成功要么全失败"，应该怎么改？

5.2 选中节点的数据同步

树数据更新后（创建/编辑/删除），选中节点的详情面板也需要同步更新。通过递归查找实现：

/** 递归在公司树中查找指定 ID 的节点 */
function findCompany(tree: CompanyDto[], id: string): CompanyDto | null {
  for (const node of tree) {
    if (node.id === id) return node
    if (node.children?.length) {
      const found = findCompany(node.children, id)
      if (found) return found
    }
  }
  return null
}

// 在渲染时用最新的树数据更新选中节点
const currentSelectedCompany =
  selectedNode?.type === "company"
    ? findCompany(companyTree, selectedNode.data.id)
    : null

const currentSelectedOrgUnit =
  selectedNode?.type === "orgUnit"
    ? findOrgUnit(orgUnitTree, selectedNode.data.id)
    : null

六、删除约束

公司和部门都有删除约束：

<ConfirmDialog
  title="删除公司"
  description={`确定删除公司 "${deleteCompanyTarget?.name}" 吗？如果该公司下有子公司、岗位或部门关联，删除将被拒绝。`}
/>

<ConfirmDialog
  title="删除部门"
  description={`确定删除部门 "${deleteOrgUnitTarget?.displayName}" 吗？如果该部门下有子部门，删除将被拒绝。`}
/>

后端会在以下情况拒绝删除：

  • 公司下还有子公司
  • 公司下还有岗位
  • 部门下还有子部门
  • 节点下还有关联的用户

💡 ASP.NET Core 类比：这就像数据库的外键约束——你不能删除一条被其他表引用的记录。后端返回错误消息，前端显示给用户。

🤔 导师提问：删除约束在后端执行（拒绝删除），前端只负责显示错误提示。为什么不在前端提前判断"有没有子节点"来禁用删除按钮？提示：想想前端缓存的数据可能不是最新的——另一个管理员刚创建了一个子公司，你的列表还没刷新。后端校验是最终的"真相来源"，前端校验只是"体验优化"。你同意这个观点吗？

踩坑提醒

  1. ID 前缀不可省略：公司节点 ID 格式为 company:{id}，部门节点 ID 格式为 orgUnit:{id}。如果不加前缀，公司 ID 和部门 ID 碰巧相同时会冲突，导致树节点选择和展开逻辑出错。
  2. 两棵树并行加载的部分失败问题：fetchData 用 Promise.all 并行加载公司树和部门树。如果公司树加载成功但部门树失败，页面只显示公司树。这是当前的行为，但可能让用户误以为数据完整。可以考虑用 Promise.allSettled 或在 UI 中明确提示"部门数据加载失败"。
  3. 删除约束由后端裁决：公司下有子公司/岗位、部门下有子部门时后端会拒绝删除。前端不能仅依赖本地数据判断是否可删除（因为数据可能不是最新的），应以后端 API 返回结果为准。
  4. 选中节点在删除后需清除：如果用户选中了某个节点，然后通过右键菜单删除了它，selectedNode 仍指向已删除的节点。右侧面板需要处理"节点已被删除"的边界情况，显示"节点已被删除或不可用"。
