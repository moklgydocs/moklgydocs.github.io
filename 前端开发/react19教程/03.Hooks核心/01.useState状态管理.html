useState 状态管理

useState 深度解析

学习目标

  • 彻底理解 useState 的工作机制
  • 掌握对象和数组状态的正确更新方式
  • 理解批量更新和函数式更新
  • 避开 useState 的所有常见陷阱

useState 基础回顾

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  //      ↑        ↑              ↑
  //   状态值   更新函数        初始值
  
  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}

陷阱一：状态更新是异步的

function Counter() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    setCount(count + 1);
    console.log(count); // ⚠️ 输出 0，不是 1！
    
    setCount(count + 1);
    setCount(count + 1);
    setCount(count + 1);
    // 最终 count 是 1，不是 3！
    // 因为三次调用都基于同一个 count=0
  };

  return <button onClick={handleClick}>{count}</button>;
}

🔬 原理：setCount 不会立即改变 count 的值。它只是告诉 React「请在下次渲染时把 count 设为新值」。在当前这次函数执行中，count 始终是旧值（这次渲染的快照）。

解决方案：函数式更新

const handleClick = () => {
  setCount(prev => prev + 1);  // 基于前一个值 +1
  setCount(prev => prev + 1);  // 基于前一个值 +1
  setCount(prev => prev + 1);  // 基于前一个值 +1
  // 最终 count 是 3！✅
};

💡 经验法则：当新值依赖旧值时，永远使用函数式更新。这不仅能确保正确性，还能避免闭包陷阱。

陷阱二：对象状态的更新

function UserForm() {
  const [user, setUser] = useState({
    name: '张三',
    age: 25,
    address: { city: '北京', district: '朝阳' }
  });

  // ❌ 错误：直接修改对象
  const handleNameChange = (e) => {
    user.name = e.target.value;  // 直接修改不会触发重渲染！
    setUser(user);  // 同一个引用，React 认为没变
  };

  // ✅ 正确：创建新对象
  const handleNameChange = (e) => {
    setUser({ ...user, name: e.target.value });
  };

  // ✅ 正确：嵌套对象也要展开
  const handleCityChange = (e) => {
    setUser({
      ...user,
      address: { ...user.address, city: e.target.value }
    });
  };

  return (
    <div>
      <input value={user.name} onChange={handleNameChange} />
      <input value={user.address.city} onChange={handleCityChange} />
    </div>
  );
}

⚠️ 教训：我曾经在一个复杂表单中直接修改了嵌套对象的属性，结果有些字段的 UI 就是不更新。排查了好久才发现是引用没变。从那以后我的规则是：永远创建新对象，永远展开。

陷阱三：数组状态的更新

function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: '学习', done: false },
    { id: 2, text: '运动', done: false },
  ]);

  // ✅ 添加
  const addTodo = (text) => {
    setTodos([...todos, { id: Date.now(), text, done: false }]);
  };

  // ✅ 删除
  const deleteTodo = (id) => {
    setTodos(todos.filter(t => t.id !== id));
  };

  // ✅ 修改某一项
  const toggleTodo = (id) => {
    setTodos(todos.map(t => 
      t.id === id ? { ...t, done: !t.done } : t
    ));
  };

  // ✅ 排序（注意：sort 会修改原数组！）
  const sortTodos = () => {
    setTodos([...todos].sort((a, b) => a.text.localeCompare(b.text)));
  };

  // ✅ 在指定位置插入
  const insertAt = (index, newTodo) => {
    setTodos([
      ...todos.slice(0, index),
      newTodo,
      ...todos.slice(index),
    ]);
  };
}

数组操作速查表：

操作避免使用（会修改原数组）推荐使用（返回新数组）
添加push, unshift[...arr, item], [item, ...arr]
删除splice, pop, shiftfilter
替换splice, arr[i] = xmap
排序sort, reverse[...arr].sort()

陷阱四：闭包陷阱

这是 React Hooks 中最令人困惑的问题：

function Timer() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const timer = setInterval(() => {
      // ❌ count 永远是 0！闭包捕获了初始值
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(timer);
  }, []); // 空依赖数组，effect 只在挂载时执行一次

  return <p>{count}</p>; // 永远显示 1
}

为什么？因为 setInterval 的回调函数「捕获」了创建时的 count 值（0），之后每次执行都是 0 + 1 = 1。

解决方案：

// 方案一：函数式更新（最推荐）
useEffect(() => {
  const timer = setInterval(() => {
    setCount(prev => prev + 1); // ✅ 基于前一个值
  }, 1000);
  return () => clearInterval(timer);
}, []);

// 方案二：把 count 加入依赖（但会重复创建定时器）
useEffect(() => {
  const timer = setInterval(() => {
    setCount(count + 1);
  }, 1000);
  return () => clearInterval(timer);
}, [count]); // 每次 count 变化都重新设置定时器

// 方案三：用 useRef 保存最新值
const countRef = useRef(count);
countRef.current = count;

useEffect(() => {
  const timer = setInterval(() => {
    setCount(countRef.current + 1);
  }, 1000);
  return () => clearInterval(timer);
}, []);

惰性初始化

如果初始值的计算很昂贵，可以传一个函数给 useState：

// ❌ 每次渲染都会执行 computeExpensiveValue()
const [data, setData] = useState(computeExpensiveValue());

// ✅ 只在首次渲染时执行
const [data, setData] = useState(() => computeExpensiveValue());

// 实际例子：从 localStorage 读取初始值
const [theme, setTheme] = useState(() => {
  const saved = localStorage.getItem('theme');
  return saved ? JSON.parse(saved) : 'light';
});

状态设计原则

1. 最小化状态

// ❌ 冗余状态
const [items, setItems] = useState([]);
const [itemCount, setItemCount] = useState(0); // 多余！

// ✅ itemCount 可以从 items 派生
const [items, setItems] = useState([]);
const itemCount = items.length; // 计算得出

2. 避免状态冗余

// ❌ firstName 和 lastName 已经能推导出 fullName
const [firstName, setFirstName] = useState('');
const [lastName, setLastName] = useState('');
const [fullName, setFullName] = useState(''); // 多余！

// ✅ 用计算值
const [firstName, setFirstName] = useState('');
const [lastName, setLastName] = useState('');
const fullName = `${firstName} ${lastName}`; // 派生

3. 扁平化结构

// ❌ 深层嵌套，更新很痛苦
const [state, setState] = useState({
  user: {
    profile: {
      name: '',
      address: {
        city: '',
        street: '',
      }
    }
  }
});

// ✅ 扁平化
const [name, setName] = useState('');
const [city, setCity] = useState('');
const [street, setStreet] = useState('');

💡 经验：当对象嵌套超过 2 层时，考虑拆分成多个独立的 state，或使用 useReducer。
