虚拟 DOM 与 Diff 算法

虚拟 DOM 与 Diff 算法

虚拟 DOM 是什么？

虚拟 DOM 就是用 JavaScript 对象描述真实 DOM 的数据结构：

// JSX
<div className="container">
  <h1>Hello</h1>
  <p>World</p>
</div>

// 编译后的虚拟 DOM 对象（简化）
{
  type: 'div',
  props: {
    className: 'container',
    children: [
      { type: 'h1', props: { children: 'Hello' } },
      { type: 'p', props: { children: 'World' } }
    ]
  }
}

为什么不直接操作真实 DOM？

不是因为虚拟 DOM「更快」，而是因为：

  1. 声明式编程：开发者描述「结果」，React 计算「变化」
  2. 批量更新：多次状态变化合并为一次 DOM 更新
  3. 跨平台：同一份虚拟 DOM 可以渲染到 DOM、Native、Canvas

Diff 算法：O(n³) → O(n)

理论上对比两棵树需要 O(n³)，React 通过三个假设将其优化为 O(n)：

假设 1：不同类型的元素产生不同的树

// 从 <div> 变成 <span>
// React：直接销毁整个子树，重新创建
// 不会试图「复用」

// 从 <ComponentA> 变成 <ComponentB>
// React：卸载 A 及其子树，挂载 B

假设 2：同级元素通过 key 标识

// 没有 key：按顺序逐个对比
// [A, B, C] → [A, C]
// React: A→A(不变), B→C(更新), C→删除 ❌ 多余操作

// 有 key：按 key 匹配
// [A:1, B:2, C:3] → [A:1, C:3]
// React: A(不变), B(删除), C(不变) ✅ 最小操作

假设 3：同层对比

React 只对比同一层级的节点，不跨层级：

        旧树              新树
        App               App
       /   \            /     \
    Header  Main     Header   Main
              |                 |  \
           Content           Content  Footer(新增)

React 不会尝试把旧树的节点「移动」到新树的不同层级。

对实际开发的指导意义

  1. 保持组件树结构稳定：避免不必要的层级变化
  2. 为列表提供稳定的 key：让 Diff 算法高效工作
  3. 避免在渲染中改变组件类型：condition ? <Input /> : <textarea /> 会导致状态丢失

💡 面试高频题：React 的 Diff 算法和 Vue 的有什么区别？核心区别在于 React 是单向遍历，Vue 2 使用双端对比，Vue 3 使用最长递增子序列算法。
