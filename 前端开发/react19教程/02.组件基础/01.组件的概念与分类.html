组件的概念与分类

组件的概念与分类

学习目标

  • 深入理解什么是组件，为什么组件化是 React 的灵魂
  • 掌握函数组件的写法
  • 了解类组件（知道它的存在，但不需要深入）
  • 建立正确的组件拆分思维

什么是组件？

组件就是一段可复用的 UI 代码。你可以把它想象成乐高积木——每块积木有自己的形状和颜色，你可以用不同的积木拼出各种各样的模型。

在 React 中，组件就是一个返回 JSX 的函数：

// 这就是一个组件！
function Welcome() {
  return <h1>你好，世界！</h1>;
}

就这么简单。但别被简单的外表欺骗了——组件背后有一套完整的设计哲学。

函数组件（现代 React 的标准）

基本写法

// 写法一：函数声明
function Greeting() {
  return <h1>Hello!</h1>;
}

// 写法二：箭头函数
const Greeting = () => {
  return <h1>Hello!</h1>;
};

// 写法三：箭头函数简写（只有一行 JSX 时）
const Greeting = () => <h1>Hello!</h1>;

💡 个人建议：在团队中保持一致就好。我个人偏好箭头函数 + export的组合：

const Greeting = () => {
  return <h1>Hello!</h1>;
};
export default Greeting;

组件命名规则

// ✅ 大写开头（Pascal Case）
function UserProfile() { ... }
function TodoList() { ... }

// ❌ 小写开头（React 会当作 HTML 标签）
function userProfile() { ... }  // React 不认为这是组件！

🔬 原理：JSX 编译时，大写开头的标签被视为组件（<UserProfile /> → React.createElement(UserProfile)），小写开头的被视为 HTML 标签（<div> → React.createElement('div')）。

组件的使用

function App() {
  return (
    <div>
      {/* 组件就像 HTML 标签一样使用 */}
      <Greeting />
      <Greeting />  {/* 可以复用！*/}
      <Greeting />
    </div>
  );
}

类组件（了解即可）

在 React 16.8 之前（2019 年），如果组件需要状态管理，必须用类组件：

// ⚠️ 旧式写法，了解即可
class Welcome extends React.Component {
  constructor(props) {
    super(props);
    this.state = { count: 0 };
  }

  render() {
    return (
      <div>
        <h1>Hello, {this.props.name}</h1>
        <p>Count: {this.state.count}</p>
        <button onClick={() => this.setState({ count: this.state.count + 1 })}>
          +1
        </button>
      </div>
    );
  }
}

为什么不推荐类组件了？

问题说明
this 指向混乱事件处理中 this 经常丢失，需要手动绑定
生命周期分散逻辑相关逻辑被拆散到不同的生命周期方法中
代码量大同样的功能，类组件代码量约是函数组件的 1.5-2 倍
不利于代码压缩类名和方法名无法被压缩工具优化
复用逻辑困难HOC 和 render props 模式复杂且难以维护

⚠️ 实战经验：如果你接手了一个老项目，可能会遇到大量类组件。不用急着重构，但新写的组件一律用函数组件 + Hooks。逐步迁移是最安全的策略。

组件拆分的艺术

什么时候该拆分组件？

这是 React 开发中最重要的技能之一。以下是几个信号：

1. 组件代码超过 200 行

// ❌ 一个组件干了太多事
function UserDashboard() {
  // ...200+ 行代码...
  return (
    <div>
      {/* 个人信息区域 - 50行 */}
      {/* 订单列表区域 - 80行 */}
      {/* 收藏列表区域 - 60行 */}
      {/* 设置面板区域 - 40行 */}
    </div>
  );
}

// ✅ 拆分成职责清晰的子组件
function UserDashboard() {
  return (
    <div>
      <UserProfile />
      <OrderList />
      <FavoriteList />
      <SettingsPanel />
    </div>
  );
}

2. 某段 UI 需要复用

// 如果多个地方都需要展示用户头像+名字
function UserAvatar({ user }) {
  return (
    <div className="avatar-wrapper">
      <img src={user.avatar} alt={user.name} />
      <span>{user.name}</span>
    </div>
  );
}

// 在不同地方复用
<UserAvatar user={currentUser} />
<UserAvatar user={author} />
<UserAvatar user={commenter} />

3. 组件有独立的状态或逻辑

// 搜索框有自己的状态和逻辑，适合独立为组件
function SearchBox({ onSearch }) {
  const [query, setQuery] = useState('');
  
  const handleSubmit = (e) => {
    e.preventDefault();
    onSearch(query);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <button type="submit">搜索</button>
    </form>
  );
}

组件拆分实战

让我们以一个电商商品卡片为例：

// 拆分前：一个大组件
function ProductCard({ product }) {
  return (
    <div className="product-card">
      <img src={product.image} alt={product.name} />
      {product.discount > 0 && (
        <span className="badge">{product.discount}% OFF</span>
      )}
      <h3>{product.name}</h3>
      <div className="rating">
        {[1,2,3,4,5].map(star => (
          <span key={star} className={star <= product.rating ? 'filled' : ''}>
            ⭐
          </span>
        ))}
        <span>({product.reviewCount})</span>
      </div>
      <div className="price">
        {product.discount > 0 && (
          <span className="original-price">¥{product.originalPrice}</span>
        )}
        <span className="current-price">¥{product.price}</span>
      </div>
      <button onClick={() => addToCart(product.id)}>加入购物车</button>
    </div>
  );
}
// 拆分后：每个子组件职责单一
function ProductImage({ image, name, discount }) {
  return (
    <div className="product-image">
      <img src={image} alt={name} />
      {discount > 0 && <DiscountBadge discount={discount} />}
    </div>
  );
}

function DiscountBadge({ discount }) {
  return <span className="badge">{discount}% OFF</span>;
}

function StarRating({ rating, reviewCount }) {
  return (
    <div className="rating">
      {[1,2,3,4,5].map(star => (
        <span key={star} className={star <= rating ? 'filled' : ''}>⭐</span>
      ))}
      <span>({reviewCount})</span>
    </div>
  );
}

function PriceDisplay({ price, originalPrice, discount }) {
  return (
    <div className="price">
      {discount > 0 && <span className="original">¥{originalPrice}</span>}
      <span className="current">¥{price}</span>
    </div>
  );
}

// 主组件变得清晰简洁
function ProductCard({ product }) {
  return (
    <div className="product-card">
      <ProductImage image={product.image} name={product.name} discount={product.discount} />
      <h3>{product.name}</h3>
      <StarRating rating={product.rating} reviewCount={product.reviewCount} />
      <PriceDisplay price={product.price} originalPrice={product.originalPrice} discount={product.discount} />
      <button onClick={() => addToCart(product.id)}>加入购物车</button>
    </div>
  );
}

过度拆分的反面教材

⚠️ 教训：拆分也不能过度！我见过有人把每个 <p> 标签都封装成组件...

// ❌ 过度拆分
function Title({ text }) {
  return <h1>{text}</h1>;  // 这种封装毫无意义
}

function Paragraph({ text }) {
  return <p>{text}</p>;  // 没有任何复用或逻辑
}

组件拆分的经验法则：

  • ✅ 有独立逻辑或状态 → 拆
  • ✅ 会在多处复用 → 拆
  • ✅ 代码太长影响阅读 → 拆
  • ❌ 只是简单的标签包裹 → 不拆
  • ❌ 只在一个地方使用且逻辑简单 → 考虑不拆

组件文件组织

推荐的项目结构

src/
├── components/        # 通用组件
│   ├── Button/
│   │   ├── index.jsx
│   │   └── Button.module.css
│   ├── StarRating/
│   │   ├── index.jsx
│   │   └── StarRating.module.css
│   └── ...
├── pages/             # 页面组件
│   ├── Home/
│   │   ├── index.jsx
│   │   ├── Home.module.css
│   │   └── components/  # 页面专属组件
│   │       └── HeroSection.jsx
│   └── ...
└── App.jsx

💡 经验：通用组件放 components/，页面级组件放 pages/，页面专属的子组件放在页面目录下的 components/ 中。
