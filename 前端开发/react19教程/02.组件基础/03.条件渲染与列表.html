条件渲染与列表

条件渲染与列表渲染

学习目标

  • 掌握 React 中所有条件渲染方式及其适用场景
  • 深入理解列表渲染和 key 的作用
  • 学会处理空列表、加载状态等边界情况

条件渲染

方式一：if/else 提前返回

适合「根据条件渲染完全不同的 UI」：

function UserPage({ user, isLoading, error }) {
  // 加载中
  if (isLoading) {
    return <div className="loading">加载中...</div>;
  }
  
  // 错误状态
  if (error) {
    return <div className="error">出错了：{error.message}</div>;
  }
  
  // 未登录
  if (!user) {
    return <div>请先登录</div>;
  }
  
  // 正常展示
  return (
    <div>
      <h1>{user.name} 的主页</h1>
      <p>{user.bio}</p>
    </div>
  );
}

💡 实战经验：这种「提前返回」（Early Return）模式非常实用。它让你先处理各种异常情况，最后处理正常逻辑，代码层次清晰，不会嵌套很深。

方式二：三元表达式

适合「二选一」：

function StatusIndicator({ isOnline }) {
  return (
    <span className={isOnline ? 'online' : 'offline'}>
      {isOnline ? '🟢 在线' : '🔴 离线'}
    </span>
  );
}

⚠️ 教训：不要嵌套三元表达式！这是可读性的噩梦：

// ❌ 三层嵌套，谁看谁晕
{status === 'loading' ? <Loading /> : status === 'error' ? <Error /> : <Content />}

// ✅ 用 if/else 或 map 来处理多种情况

方式三：&& 短路

适合「显示/隐藏」：

function Notification({ count, message }) {
  return (
    <div>
      {/* 有未读消息时才显示角标 */}
      {count > 0 && <span className="badge">{count}</span>}
      
      {/* 有消息时才显示 */}
      {message && <p className="message">{message}</p>}
    </div>
  );
}

再次提醒 && 的陷阱：

// ❌ count 为 0 时会渲染 "0"
{count && <Badge count={count} />}

// ✅ 安全写法
{count > 0 && <Badge count={count} />}
{Boolean(count) && <Badge count={count} />}

方式四：变量 + if/switch

适合「多种条件，逻辑复杂」：

function OrderStatus({ status }) {
  let content;
  let color;
  
  switch (status) {
    case 'pending':
      content = '⏳ 待支付';
      color = '#faad14';
      break;
    case 'paid':
      content = '✅ 已支付';
      color = '#52c41a';
      break;
    case 'shipped':
      content = '🚚 已发货';
      color = '#1890ff';
      break;
    case 'delivered':
      content = '📦 已送达';
      color = '#52c41a';
      break;
    case 'cancelled':
      content = '❌ 已取消';
      color = '#ff4d4f';
      break;
    default:
      content = '未知状态';
      color = '#999';
  }
  
  return <span style={{ color }}>{content}</span>;
}

方式五：对象映射（优雅方案）

// 用对象替代 switch，更简洁
const STATUS_CONFIG = {
  pending:   { text: '⏳ 待支付', color: '#faad14' },
  paid:      { text: '✅ 已支付', color: '#52c41a' },
  shipped:   { text: '🚚 已发货', color: '#1890ff' },
  delivered: { text: '📦 已送达', color: '#52c41a' },
  cancelled: { text: '❌ 已取消', color: '#ff4d4f' },
};

function OrderStatus({ status }) {
  const config = STATUS_CONFIG[status] || { text: '未知', color: '#999' };
  return <span style={{ color: config.color }}>{config.text}</span>;
}

💡 经验：对象映射比 switch 更灵活，配置可以放在外部文件中，方便维护和扩展。在实际项目中我几乎不用 switch 来做条件渲染。

列表渲染

基本用法

function FruitList() {
  const fruits = ['🍎 苹果', '🍌 香蕉', '🍊 橙子', '🍇 葡萄'];
  
  return (
    <ul>
      {fruits.map((fruit, index) => (
        <li key={index}>{fruit}</li>  // 简单字符串列表用 index 做 key 可以接受
      ))}
    </ul>
  );
}

渲染对象列表

function UserList({ users }) {
  return (
    <div>
      {users.map(user => (
        <div key={user.id} className="user-card">
          <img src={user.avatar} alt={user.name} />
          <h3>{user.name}</h3>
          <p>{user.email}</p>
        </div>
      ))}
    </div>
  );
}

key 深入理解

key 的作用：帮助 React 识别哪些元素发生了变化，从而高效地更新 DOM。

// 场景：列表项从 [A, B, C] 变成 [A, C]（删除了 B）

// 有正确的 key 时：
// React: "key=B 的元素没了，只需要删除这一个 DOM 节点"

// 用 index 做 key 时：
// React: "index=1 从 B 变成了 C，index=2 消失了"
//         → 更新了 B→C 这个 DOM 节点，又删除了原来的 C
//         → 多做了一次无意义的 DOM 更新

什么时候用 index 做 key 是安全的？

  1. 列表不会重新排序
  2. 列表不会有中间插入/删除操作
  3. 列表项没有自己的状态（如 input 值）

为什么带状态的列表用 index 做 key 会出大 Bug？

// ❌ 经典 Bug 演示
function TodoList() {
  const [todos, setTodos] = useState([
    { id: 1, text: '学 React' },
    { id: 2, text: '写项目' },
    { id: 3, text: '部署' },
  ]);

  const deleteFirst = () => setTodos(todos.slice(1));

  return (
    <div>
      <button onClick={deleteFirst}>删除第一个</button>
      {todos.map((todo, index) => (
        // 用 index 做 key
        <div key={index}>
          <input defaultValue={todo.text} />
        </div>
      ))}
    </div>
  );
}
// 点击删除后，输入框里的文字会错位！
// 因为 React 认为 key=0 还在，只是内容变了，但 input 的 DOM 状态没变

⚠️ 这个 Bug 我在生产环境中遇到过，用户反馈表单中删除一行后，其他行的输入内容全错位了。排查了很久才发现是 key 的问题。从那以后，我在 Code Review 时遇到用 index 做 key 都会标为必须修改。

处理边界情况

空列表

function TaskList({ tasks }) {
  if (tasks.length === 0) {
    return (
      <div className="empty-state">
        <p>📋 暂无任务</p>
        <p>点击上方按钮添加你的第一个任务</p>
      </div>
    );
  }

  return (
    <ul>
      {tasks.map(task => (
        <li key={task.id}>{task.title}</li>
      ))}
    </ul>
  );
}

加载 + 空 + 错误 的状态机

function DataList({ data, isLoading, error }) {
  // 加载中
  if (isLoading) {
    return <Skeleton count={5} />;  // 骨架屏
  }
  
  // 错误
  if (error) {
    return (
      <div className="error">
        <p>加载失败：{error.message}</p>
        <button onClick={retry}>重试</button>
      </div>
    );
  }
  
  // 空数据
  if (!data || data.length === 0) {
    return <EmptyState />;
  }
  
  // 正常渲染
  return (
    <ul>
      {data.map(item => (
        <li key={item.id}>{item.name}</li>
      ))}
    </ul>
  );
}

💡 实战经验：在实际项目中，几乎每个列表都需要处理这 4 种状态：加载中、加载失败、空数据、有数据。建议封装一个通用的 AsyncList 组件来处理这些状态。

列表渲染的性能提示

// ❌ 在 map 中定义内联函数和对象（每次渲染都会创建新的引用）
{items.map(item => (
  <ItemCard
    key={item.id}
    style={{ marginBottom: '10px' }}  // 每次渲染都是新对象
    onClick={() => handleClick(item.id)}  // 每次渲染都是新函数
  />
))}

// 对于短列表，这没什么问题
// 对于长列表 + 使用了 React.memo 的子组件，这会导致 memo 失效
