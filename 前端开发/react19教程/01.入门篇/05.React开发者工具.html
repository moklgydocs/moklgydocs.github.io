React 开发者工具

React 开发者工具

学习目标

  • 安装和使用 React DevTools
  • 学会用工具观察组件树和状态变化
  • 掌握 React 应用的调试技巧

安装 React DevTools

React DevTools 是 React 官方的浏览器调试插件，是每个 React 开发者的必备工具。

安装方式

  • Chrome：在 Chrome 网上应用店搜索 "React Developer Tools"
  • Firefox：在 Firefox 附加组件搜索安装
  • Edge：在 Edge 插件商店搜索安装

安装后，打开一个 React 应用，在浏览器 DevTools 中会多出两个 Tab：

  • ⚛️ Components：查看组件树
  • ⚛️ Profiler：性能分析

Components 面板

查看组件树

Components 面板以树形结构展示所有 React 组件：

App
├── Header
│   └── Navigation
├── NoteApp
│   ├── input
│   ├── input
│   ├── p
│   └── ul
│       ├── li (key="1712345678901")
│       └── li (key="1712345678950")
└── Footer

查看和修改 Props/State

点击任意组件，右侧面板会显示：

  • Props：父组件传入的属性
  • State：组件自身的状态（Hooks）
  • Context：组件使用的上下文

你可以实时修改这些值，立即看到 UI 变化。这在调试时非常有用！

💡 实战技巧：当你不确定某个 UI 问题是状态问题还是渲染问题时，在 DevTools 中手动修改状态值。如果 UI 正确了，说明是状态计算的问题；如果 UI 还是不对，说明是渲染逻辑的问题。

Highlight Updates

打开 DevTools 面板的设置，勾选 「Highlight updates when components render」。

开启后，每次组件重新渲染时，该组件会闪烁高亮：

  • 🟢 绿色闪烁 = 渲染频率低（正常）
  • 🟡 黄色闪烁 = 渲染频率中等（注意）
  • 🔴 红色闪烁 = 渲染频率高（需要优化！）

⚠️ 教训：有一次我们的应用列表页面特别卡，用 Highlight Updates 一看，每次滚动整个列表的每一项都在重新渲染。后来用 React.memo 优化后，性能提升了 10 倍。这个工具直接指出了问题所在。

Profiler 面板

Profiler 用于分析组件的渲染性能。

使用步骤

  1. 切换到 Profiler Tab
  2. 点击 🔴 录制按钮
  3. 在应用中执行操作
  4. 点击 ⬛ 停止录制
  5. 查看录制结果

看懂 Profiler 数据

Profiler 会显示：

  • Commit 列表：每次 React 更新 DOM 就是一次 Commit
  • 火焰图：每个组件的渲染耗时
  • 排名图：按渲染耗时排序
渲染耗时参考：
< 1ms   → 极快，不用关心
1-5ms   → 正常
5-16ms  → 注意（可能导致卡顿）
> 16ms  → 需要优化（超过一帧的时间）

🔬 原理：浏览器的刷新率是 60fps，意味着每帧约 16.6ms。如果一次渲染超过 16ms，用户就会感知到卡顿。

console.log 调试技巧

虽然听起来很基础，但 console.log 在 React 中有一些特殊的用法：

追踪渲染

function MyComponent({ name }) {
  console.log('MyComponent 渲染了', { name });
  
  return <div>{name}</div>;
}

追踪状态变化

function Counter() {
  const [count, setCount] = useState(0);
  
  console.log('Counter 渲染，当前 count =', count);
  
  const increment = () => {
    console.log('点击前 count =', count);
    setCount(count + 1);
    console.log('setCount 后 count =', count); // ⚠️ 还是旧值！
  };
  
  return <button onClick={increment}>{count}</button>;
}

⚠️ 踩坑警告：setCount 后面的 console.log 打印的还是旧值！因为 React 的状态更新是异步的。新值要到下一次渲染才会生效。这是初学者最常见的困惑之一。

格式化输出

// 表格形式查看数组
console.table(notes);

// 分组输出
console.group('组件渲染');
console.log('props:', props);
console.log('state:', count);
console.groupEnd();

// 带样式
console.log('%c 重新渲染!', 'color: red; font-size: 20px;');

常见调试场景

场景一：组件不更新

症状：修改了状态，但 UI 没变

排查步骤：

  1. 在 DevTools 中检查状态是否真的变了
  2. 检查是否直接修改了对象/数组（违反不可变原则）
  3. 检查条件渲染的逻辑是否正确
// ❌ 常见错误：直接修改数组
const addItem = () => {
  items.push(newItem);  // 直接修改，React 检测不到！
  setItems(items);      // 同一个引用，React 认为没变
};

// ✅ 正确：创建新数组
const addItem = () => {
  setItems([...items, newItem]);
};

场景二：无限循环

症状：控制台疯狂打印，页面卡死

排查步骤：

  1. 看 console 输出，确认哪个组件在循环渲染
  2. 检查 useEffect 的依赖数组
  3. 检查是否在渲染时直接调用了 setState
// ❌ 无限循环：每次渲染都执行 setCount
function Bad() {
  const [count, setCount] = useState(0);
  setCount(count + 1); // 渲染时设置状态 → 触发新渲染 → 又设置状态...
  return <p>{count}</p>;
}

// ❌ 无限循环：useEffect 缺少正确的依赖
function AlsoBad() {
  const [data, setData] = useState(null);
  useEffect(() => {
    setData({ value: 1 }); // 每次都创建新对象 → 触发重渲染 → useEffect 再执行
  }); // 没有依赖数组！
  return <p>{data?.value}</p>;
}

场景三：闭包陷阱

症状：状态值「卡住」了，总是旧值

function Timer() {
  const [count, setCount] = useState(0);
  
  const startTimer = () => {
    setInterval(() => {
      // ❌ count 永远是 0！因为闭包捕获了初始值
      console.log(count);
      setCount(count + 1);  // 永远是 0 + 1 = 1
    }, 1000);
  };
  
  return (
    <div>
      <p>{count}</p>
      <button onClick={startTimer}>开始计时</button>
    </div>
  );
}

调试清单

当你的 React 应用出问题时，按这个顺序排查：

  1. ✅ 打开 React DevTools，检查组件树是否正确
  2. ✅ 检查 Props 和 State 的值是否符合预期
  3. ✅ 开启 Highlight Updates，看哪些组件在不必要地重渲染
  4. ✅ 查看浏览器 Console 有没有报错或警告
  5. ✅ 用 Profiler 分析性能瓶颈
  6. ✅ 在关键位置添加 console.log 追踪数据流

  1. 为什么 React DevTools 能看到组件名称？如果组件是匿名的会怎样？
  2. StrictMode 会导致组件渲染两次，这会影响 Profiler 的性能分析结果吗？
  3. 你能想到除了 console.log 和 DevTools 之外的调试方法吗？
