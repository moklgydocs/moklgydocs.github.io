开发环境搭建

开发环境搭建

学习目标

  • 搭建一个 React 19 开发环境
  • 理解项目结构中每个文件的作用
  • 能区分不同脚手架工具的适用场景

前置准备

安装 Node.js

React 开发需要 Node.js 环境。打开终端检查：

node -v  # 需要 >= 18.0
npm -v   # 随 Node 一起安装

如果没有安装，去 Node.js 官网 下载 LTS 版本。

💡 建议：使用 nvm（Node Version Manager）管理 Node 版本，方便在不同项目间切换。

安装包管理器

推荐使用 pnpm，它比 npm 更快、更省磁盘空间：

npm install -g pnpm
pnpm -v

创建 React 19 项目

方式一：Vite（推荐）

Vite 是目前最快的前端构建工具，启动速度是 webpack 的几十倍：

# 创建项目
pnpm create vite my-react-app --template react

# 进入项目
cd my-react-app

# 安装依赖
pnpm install

# 启动开发服务器
pnpm dev

如果需要 TypeScript 支持（强烈推荐）：

pnpm create vite my-react-app --template react-ts

方式二：Next.js（适合实际项目）

如果你的项目需要 SSR、路由、API 等完整功能：

npx create-next-app@latest my-next-app

方式三：Create React App（不推荐了）

CRA 曾经是官方推荐的脚手架，但现在已经不再维护：

# ❌ 不推荐，已经停止维护
npx create-react-app my-app

⚠️ 教训：我们项目组曾经用 CRA 搭建了一个大型项目，后来要迁移到 Vite 花了整整一周。如果是新项目，直接用 Vite 或 Next.js。

工具选择指南

场景推荐工具理由
学习 ReactVite最简单，干扰最少
SPA 应用Vite快速、轻量
企业级应用Next.jsSSR、路由、API 一体化
组件库开发Vite + Library Mode打包灵活

项目结构解析

用 Vite 创建的 React 项目结构如下：

my-react-app/
├── node_modules/        # 依赖包（不需要关心）
├── public/              # 静态资源（不会被编译）
│   └── vite.svg
├── src/                 # 源代码（你写代码的地方）
│   ├── assets/          # 静态资源（会被编译处理）
│   │   └── react.svg
│   ├── App.css          # App 组件的样式
│   ├── App.jsx          # App 根组件 ⭐
│   ├── index.css        # 全局样式
│   └── main.jsx         # 应用入口文件 ⭐⭐
├── index.html           # HTML 模板 ⭐
├── package.json         # 项目配置
├── vite.config.js       # Vite 配置
└── eslint.config.js     # 代码规范配置

关键文件详解

index.html —— 整个应用的 HTML 骨架：

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>Vite + React</title>
  </head>
  <body>
    <!-- React 会把整个应用渲染到这个 div 里 -->
    <div id="root"></div>
    <!-- Vite 会自动注入 JS -->
    <script type="module" src="/src/main.jsx"></script>
  </body>
</html>

src/main.jsx —— 应用的 JavaScript 入口：

import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App.jsx'
import './index.css'

// 创建根节点并渲染 App 组件
ReactDOM.createRoot(document.getElementById('root')).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
)

🔬 原理解释：

  • ReactDOM.createRoot() 创建一个 React 渲染根节点
  • .render() 把 React 组件树渲染到真实 DOM 中
  • <React.StrictMode> 是一个开发工具，它会帮你发现潜在问题（比如不安全的生命周期、过时的 API），但不会影响生产环境

src/App.jsx —— 根组件：

import { useState } from 'react'
import './App.css'

function App() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <h1>Hello React 19!</h1>
      <button onClick={() => setCount(count + 1)}>
        点击次数: {count}
      </button>
    </div>
  )
}

export default App

确保使用 React 19

检查 package.json 中的 React 版本：

{
  "dependencies": {
    "react": "^19.0.0",
    "react-dom": "^19.0.0"
  }
}

如果不是 19，手动升级：

pnpm add react@latest react-dom@latest

第一次修改

现在，试试修改 App.jsx：

function App() {
  return (
    <div>
      <h1>🚀 我的 React 之旅开始了！</h1>
      <p>如果你看到这行字，说明环境搭建成功了。</p>
    </div>
  )
}

export default App

保存文件，浏览器会自动刷新（HMR 热更新）。

💡 HMR（Hot Module Replacement） 是 Vite 的杀手级特性。它能在你修改代码后，不刷新整个页面，只替换修改的模块，甚至保留组件的状态。这让开发体验极其流畅。

🤔 思考题

  1. 为什么 React 需要 ReactDOM.createRoot() 而不是直接操作 #root 元素？
  2. <React.StrictMode> 会导致组件渲染两次，你知道为什么吗？（提示：开发模式下的行为）
  3. Vite 为什么比 Webpack 快那么多？（提示：ESM vs Bundle）
