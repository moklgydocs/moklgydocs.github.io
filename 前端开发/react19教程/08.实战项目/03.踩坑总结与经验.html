React 踩坑总结与经验

这些都是我和团队在实际项目中踩过的坑，每一个都是时间换来的教训。

🔴 高频踩坑 Top 10

1. 直接修改 state 对象

// ❌ 页面不更新！
const handleChange = () => {
  user.name = '新名字';
  setUser(user); // 同一个引用，React 认为没变
};

// ✅ 创建新对象
const handleChange = () => {
  setUser({ ...user, name: '新名字' });
};

发生频率：⭐⭐⭐⭐⭐（几乎每个新人都会犯）

2. useEffect 无限循环

// ❌ 死循环
useEffect(() => {
  setData({ value: 1 }); // 设置新对象 → 重新渲染 → 又执行 effect
});

// ❌ 对象依赖
const options = { page: 1 };
useEffect(() => {
  fetchData(options);
}, [options]); // 每次渲染 options 都是新引用

// ✅ 加上依赖或放在 effect 内部
useEffect(() => {
  const options = { page: 1 };
  fetchData(options);
}, []);

发生频率：⭐⭐⭐⭐⭐

3. 闭包陷阱

// ❌ count 永远是旧值
const handleClick = () => {
  setTimeout(() => {
    console.log(count); // 捕获了点击时的 count
  }, 3000);
};

// ✅ 用 ref 获取最新值
const countRef = useRef(count);
countRef.current = count;
const handleClick = () => {
  setTimeout(() => {
    console.log(countRef.current); // 最新值
  }, 3000);
};

发生频率：⭐⭐⭐⭐

4. key 导致的列表 Bug

// ❌ 用 index 做 key，删除/重排时 UI 错乱
{items.map((item, idx) => <Input key={idx} defaultValue={item.name} />)}

// ✅ 用唯一 ID
{items.map(item => <Input key={item.id} defaultValue={item.name} />)}

发生频率：⭐⭐⭐⭐

5. 条件渲染中 0 的显示

// ❌ 当 count 为 0 时，页面会显示 "0"
{count && <Badge count={count} />}

// ✅
{count > 0 && <Badge count={count} />}

发生频率：⭐⭐⭐

6. 忘记清理 useEffect

// ❌ 内存泄漏
useEffect(() => {
  const timer = setInterval(doSomething, 1000);
  // 忘记 return 清理函数！
}, []);

// ✅
useEffect(() => {
  const timer = setInterval(doSomething, 1000);
  return () => clearInterval(timer);
}, []);

发生频率：⭐⭐⭐

7. setState 后立即读取新值

// ❌
setCount(count + 1);
console.log(count); // 还是旧值！

// ✅ 在下次渲染中读取，或用 useEffect
useEffect(() => {
  console.log('count 变了:', count);
}, [count]);

8. 在循环/条件中使用 Hooks

// ❌ 必定报错
if (isLoggedIn) {
  const [user, setUser] = useState(null);
}

// ✅ Hook 放顶层，条件放里面
const [user, setUser] = useState(null);
// 在 useEffect 里判断条件

9. 过度使用 useEffect

// ❌ 不需要 effect 来计算派生值
useEffect(() => {
  setFullName(firstName + ' ' + lastName);
}, [firstName, lastName]);

// ✅ 直接计算
const fullName = firstName + ' ' + lastName;

10. 组件过度拆分或拆分不足

// ❌ 2000 行的超级组件
// ❌ 每个 <p> 都封装成组件

// ✅ 合理粒度：
// - 有独立逻辑/状态 → 拆
// - 需要复用 → 拆
// - 简单标签 → 不拆

💡 工作中的最佳实践

代码规范

  1. 启用 ESLint + eslint-plugin-react-hooks：自动检测 Hook 规则问题
  2. 使用 Prettier：统一代码风格
  3. TypeScript 严格模式：strict: true

团队协作

  1. 组件文档：用 Storybook 维护组件库
  2. Code Review 关注点：key 使用、effect 清理、状态设计
  3. 性能预算：首屏 LCP < 2.5s，交互 INP < 200ms

调试技巧

  1. React DevTools 是第一工具
  2. console.log 在渲染函数顶部追踪重渲染
  3. git bisect 定位引入 Bug 的 commit
  4. React Profiler 定位性能瓶颈

🎓 学习路线建议

├── 理解 Fiber、Scheduler、Reconciler
│
专家阶段     → 贡献开源 + 技术分享  
├── 封装组件库、写技术博客、做 Code Review
