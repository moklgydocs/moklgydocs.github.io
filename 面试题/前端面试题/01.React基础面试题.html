React 基础面试题

React 基础面试题

适合初级/实习岗位，这些题基本每场面试都会问到。

Q1: React 是什么？它和 Vue 有什么区别？

难度：⭐ | 频率：🔥🔥🔥🔥🔥

💡 满分回答要点：

React 是一个用于构建用户界面的 JavaScript 库（不是框架）。核心理念是：

  • 声明式：描述 UI 应该是什么样，而不是怎么操作 DOM
  • 组件化：用可复用的组件构建 UI
  • 单向数据流：数据从父组件流向子组件

与 Vue 的区别：

维度ReactVue
模板JSX（JS 中写 HTML）template（HTML 中写指令）
数据流单向 + 回调双向绑定（v-model）
状态更新不可变（创建新对象）可变（Proxy 响应式）
生态灵活自选官方全家桶

⚠️ 常见错误：说「React 比 Vue 快」——这是错的，两者性能各有优劣，取决于场景。

🔗 追问：那你觉得什么时候该选 React，什么时候选 Vue？

Q2: JSX 是什么？为什么 React 要用 JSX？

难度：⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

JSX 是 JavaScript 的语法扩展，允许在 JS 中写类似 HTML 的结构。它不是模板语言，而是 React.createElement() 的语法糖。

// JSX
const element = <h1 className="title">Hello</h1>;

// 编译后
const element = React.createElement('h1', { className: 'title' }, 'Hello');

为什么用 JSX：

  1. 直观：UI 结构一目了然
  2. 类型安全：可以被 TypeScript 检查
  3. JS 的全部能力：可以用 map、条件表达式等

🔗 追问：JSX 中为什么用 className 而不是 class？

Q3: 什么是受控组件和非受控组件？

难度：⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答要点：

受控组件：表单数据由 React state 驱动，input 的值完全受 React 控制。

function Controlled() {
  const [value, setValue] = useState('');
  return <input value={value} onChange={e => setValue(e.target.value)} />;
}

非受控组件：表单数据由 DOM 自身维护，用 ref 读取。

function Uncontrolled() {
  const ref = useRef(null);
  const handleSubmit = () => console.log(ref.current.value);
  return <input ref={ref} defaultValue="" />;
}
方面受控非受控
数据源React stateDOM
实时验证✅❌
代码量多少
推荐度⭐⭐⭐⭐⭐⭐⭐

⚠️ 踩坑经验：受控组件忘写 onChange 会导致输入框无法输入——这是新人最常遇到的 Bug。

Q4: React 中的 key 有什么作用？为什么不能用 index？

难度：⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答要点：

key 帮助 React 在 Diff 时识别列表中哪些元素发生了变化。React 用 key 来匹配新旧虚拟 DOM 树中的节点。

不能用 index 的原因：当列表发生删除、插入、重排时，index 会变化，导致 React 错误地复用 DOM 节点。

// 场景：删除第一项
// 数据：[A, B, C] → [B, C]

// 用 index 做 key：
// key=0: A→B (更新内容)，key=1: B→C (更新内容)，key=2: C→删除
// 做了 2 次更新 + 1 次删除 = 3 次操作 ❌

// 用 id 做 key：
// key=a: 删除，key=b: 不变，key=c: 不变
// 只做了 1 次删除 = 1 次操作 ✅

⚠️ 真实 Bug：用 index 做 key 时，如果列表项有 input，删除中间一项后输入框内容会错位。我在项目中遇到过这个问题，排查了很长时间。

🔗 追问：什么情况下用 index 做 key 是安全的？

Q5: setState 是同步的还是异步的？

难度：⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答要点：

在 React 18+ 中，setState 默认都是异步（批量）的。

const handleClick = () => {
  setCount(count + 1);
  console.log(count); // 还是旧值！
  
  setCount(count + 1);
  setCount(count + 1);
  // 结果是 1，不是 3（因为都基于同一个快照）
};

函数式更新 可以解决连续更新的问题：

setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
// 结果是 3 ✅

💡 加分回答：React 18 引入了自动批量更新（Automatic Batching），即使在 setTimeout、Promise 中的 setState 也会批量处理。在 React 17 及之前，只有合成事件和生命周期中是批量的。

🔗 追问：如果一定要同步更新怎么办？（答：flushSync）

Q6: React 的事件和原生 DOM 事件有什么区别？

难度：⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

React 使用合成事件（SyntheticEvent）系统：

  1. 事件委托：所有事件统一绑定在 root 容器上，而不是每个 DOM 元素
  2. 跨浏览器兼容：抹平浏览器差异
  3. 命名差异：onClick vs onclick，camelCase
  4. 默认行为：不能用 return false 阻止，要用 e.preventDefault()

Q7: React 组件的生命周期是什么？函数组件有生命周期吗？

难度：⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

类组件有明确的生命周期方法（componentDidMount 等），函数组件通过 useEffect 模拟：

类组件函数组件 (Hooks)
componentDidMountuseEffect(() => {}, [])
componentDidUpdateuseEffect(() => {}, [deps])
componentWillUnmountuseEffect 的返回清理函数
shouldComponentUpdateReact.memo

💡 加分回答：严格来说函数组件没有「生命周期」概念。useEffect 是同步到外部系统的机制，不应该把它当作「生命周期钩子」来使用。React 官方文档也强调了这一点。

Q8: 什么是 Props Drilling？怎么解决？

难度：⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

Props Drilling 是指数据需要经过多层不需要它的组件传递。

解决方案：

  1. Context API：跨层传递数据
  2. 状态管理库：Redux / Zustand
  3. 组件组合：用 children 减少层级
  4. 自定义 Hook：封装数据获取逻辑
// 组合方式避免 drilling
function Page() {
  const user = useUser();
  return (
    <Layout>
      <Header user={user} />  {/* 直接传给需要的组件 */}
      <Content>
        <UserProfile user={user} />
      </Content>
    </Layout>
  );
}

Q9: React.Fragment 是什么？什么时候用？

难度：⭐ | 频率：🔥🔥🔥

💡 回答要点：

Fragment 让你返回多个元素而不添加额外的 DOM 节点。

// 简写
<>
  <h1>标题</h1>
  <p>内容</p>
</>

// 需要 key 时用完整写法
{items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.term}</dt>
    <dd>{item.description}</dd>
  </React.Fragment>
))}

Q10: React 中如何实现条件渲染？

难度：⭐ | 频率：🔥🔥🔥

💡 回答要点：

5 种常用方式：

// 1. 三元
{isLoggedIn ? <Dashboard /> : <Login />}

// 2. && 短路
{hasError && <ErrorMessage />}

// 3. if 提前返回
if (loading) return <Spinner />;

// 4. switch / 对象映射
const components = { admin: AdminPanel, user: UserPanel };
const Panel = components[role];

// 5. 变量
let content;
if (condition) content = <A />;
else content = <B />;

⚠️ 陷阱：{0 && <Component />} 会渲染出 0，要用 {count > 0 && ...}。
