React 进阶面试题

React 进阶面试题

适合 1-3 年经验，中级前端岗位。重点考察 Hooks 深入理解和性能优化。

Q1: useEffect 的依赖数组原理是什么？

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答要点：

React 在每次渲染后，用 Object.is 逐一对比依赖数组中每个值是否和上次相同：

  • 全部相同 → 跳过 effect
  • 有任一不同 → 执行清理函数，再执行新 effect
// 空数组：只在挂载/卸载时执行
useEffect(() => { ... }, []);

// 无数组：每次渲染都执行
useEffect(() => { ... });

// 有依赖：依赖变化时执行
useEffect(() => { fetchUser(id); }, [id]);

关键陷阱：对象和数组传入依赖时，即使内容相同，引用不同也会触发 effect：

// ❌ 每次渲染 options 都是新对象
const options = { page: 1 };
useEffect(() => { fetch(options); }, [options]); // 无限循环！

// ✅ 放到 effect 内部或用 useMemo
useEffect(() => {
  const options = { page: 1 };
  fetch(options);
}, []);

🔗 追问：useEffect 和 useLayoutEffect 有什么区别？

Q2: useMemo 和 useCallback 有什么区别？什么时候该用？

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答要点：

  • useMemo(() => value, deps) → 缓存计算结果
  • useCallback(fn, deps) → 缓存函数引用
  • useCallback(fn, deps) 等价于 useMemo(() => fn, deps)

什么时候该用：
✅ 传给 React.memo 子组件的回调 → useCallback
✅ 昂贵的计算（排序、过滤大数组）→ useMemo
✅ 作为其他 Hook 的依赖 → useMemo

什么时候不该用：
❌ 简单的字符串拼接、数字计算
❌ 子组件没用 React.memo
❌ 为了「优化」把所有函数都包一层

⚠️ 踩坑经验：过度使用 useMemo/useCallback 反而降低可读性且增加内存开销。先 Profile，发现问题再优化。

Q3: 说说 React 中的闭包陷阱及解决方案

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

闭包陷阱是指 Hook 回调中捕获的 state 值是创建时的快照，而不是最新值。

function Timer() {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    const timer = setInterval(() => {
      console.log(count);     // 永远是 0
      setCount(count + 1);    // 永远是 0 + 1 = 1
    }, 1000);
    return () => clearInterval(timer);
  }, []);
}

解决方案：

// 方案一：函数式更新（最推荐）
setCount(prev => prev + 1);

// 方案二：useRef 保存最新值
const countRef = useRef(count);
countRef.current = count;
setInterval(() => setCount(countRef.current + 1), 1000);

// 方案三：将值加入依赖数组（但会重建定时器）
useEffect(() => { ... }, [count]);

Q4: React.memo、useMemo、useCallback 三者的关系？

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

它们是配合使用的三件套：

React.memo(Component)    → 跳过 Props 未变的子组件渲染
useMemo(() => value)     → 确保传给子组件的对象/数组引用稳定
useCallback(fn)          → 确保传给子组件的函数引用稳定

三者缺一不可：

  • 只用 React.memo，但传了内联函数 → memo 失效
  • 只用 useCallback，但子组件没 memo → useCallback 白费
  • 只用 useMemo 缓存值，但父组件其他 state 变了 → 子组件还是重渲染（需要 memo）

Q5: 自定义 Hook 和普通函数有什么区别？

难度：⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

自定义 Hook 是以 use 开头、内部调用了其他 Hooks 的函数。

与普通函数的区别：

  1. 可以使用 Hooks：useState、useEffect 等
  2. 遵循 Hook 规则：不能在条件/循环中调用
  3. 状态隔离：每个组件使用同一个自定义 Hook，状态是独立的
  4. 命名约束：必须以 use 开头（ESLint 规则会检查）

Q6: useRef 和 useState 的区别？useRef 的两个用途？

难度：⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

特性useRefuseState
修改触发渲染❌✅
值在渲染间保持✅✅
获取最新值同步 (.current)异步（下次渲染）

两个用途：

  1. 引用 DOM 元素：<input ref={inputRef} />
  2. 保存可变值：定时器 ID、上一次的值、是否已挂载等

Q7: Context 有什么性能问题？怎么优化？

难度：⭐⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

问题：Context 值变化时，所有消费该 Context 的组件都会重渲染，不管它是否用到了变化的部分。

优化方案：

  1. 拆分 Context：theme、user、locale 各自独立
  2. 分离状态和 dispatch：dispatch 引用稳定，放单独 Context
  3. useMemo 包裹 value：避免每次渲染创建新对象
  4. 组件用 React.memo 包裹：减少子组件不必要渲染
// ❌ 
<AppContext.Provider value={{ user, theme, setUser, setTheme }}>

// ✅ 拆分
<UserContext.Provider value={user}>
  <ThemeContext.Provider value={theme}>

Q8: React 19 的 useActionState 和传统表单处理有什么区别？

难度：⭐⭐⭐ | 频率：🔥🔥🔥（新题，面试官考察学习新技术的能力）

💡 回答要点：

传统方式需要手动管理 loading、error、成功状态，代码量大。React 19 的 useActionState + <form action> 让表单处理更简洁：

  • 自动管理 pending 状态
  • 不需要 e.preventDefault()
  • 用 FormData 获取值，不需要受控组件
  • 配合 useFormStatus 子组件可自动获取提交状态

💡 加分项：提到 useOptimistic 可以做乐观更新，提升用户体验。
