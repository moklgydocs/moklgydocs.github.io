中高级岗位必考，考察你对全局架构和工程化的理解。

Q1: React 项目中如何做性能优化？

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥🔥

💡 回答框架（分层回答）：

组件层面：

  • React.memo 避免不必要重渲染
  • useMemo / useCallback 缓存计算和函数
  • 合理拆分组件粒度

列表层面：

  • 正确使用 key
  • 虚拟列表（react-window）
  • 分页加载

加载层面：

  • React.lazy + Suspense 按需加载
  • 路由级代码分割
  • 图片懒加载

渲染层面：

  • startTransition 标记非紧急更新
  • useDeferredValue 延迟渲染
  • 避免在渲染中创建对象/函数

构建层面：

  • Tree Shaking
  • 代码压缩
  • CDN 部署静态资源

⚠️ 面试技巧：不要直接列清单，而是说「我在项目中遇到过什么性能问题 → 用 Profiler 定位到哪里 → 用什么方案解决 → 效果如何」。

Q2: Redux 和 Context 怎么选？什么时候用 Zustand？

难度：⭐⭐⭐ | 频率：🔥🔥🔥🔥

💡 回答要点：

方案适用场景优点缺点
useState组件内部状态简单直接无法跨组件
Context主题、语言等低频全局内置，无依赖性能差（全部重渲染）
Zustand中型项目全局状态轻量、简单生态不如 Redux
Redux Toolkit大型项目生态最全、DevTools学习成本高
TanStack Query服务端数据缓存、同步只管服务端状态

💡 真实项目分享：我们项目用 Zustand 管客户端状态 + TanStack Query 管服务端数据，两者配合非常好，代码量比纯 Redux 少了 60%。

Q3: 前端项目如何做错误监控？

难度：⭐⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

  1. React Error Boundary：捕获渲染时错误
  2. window.onerror / addEventListener('error')：捕获 JS 运行时错误
  3. window.addEventListener('unhandledrejection')：捕获未处理的 Promise 错误
  4. 接入 Sentry / 自研平台：收集、聚合、告警
  5. SourceMap：生产环境的错误堆栈还原
// Error Boundary + 上报
componentDidCatch(error, errorInfo) {
  Sentry.captureException(error, {
    extra: { componentStack: errorInfo.componentStack }
  });
}

Q4: 如何设计一个前端项目的目录结构？

难度：⭐⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

推荐 Feature-based 结构：

src/
├── components/       # 通用 UI 组件
├── features/         # 按功能模块划分
│   ├── auth/         # 认证模块
│   │   ├── components/
│   │   ├── hooks/
│   │   ├── api.ts
│   │   └── types.ts
│   └── dashboard/    # 仪表盘模块
├── hooks/            # 全局 Hook
├── lib/              # 工具函数
├── stores/           # 全局状态
└── types/            # 全局类型

好处：功能内聚，删除一个功能 = 删除一个文件夹。

Q5: SSR 和 CSR 的区别？什么时候用 SSR？

难度：⭐⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

方面CSR（客户端渲染）SSR（服务端渲染）
首屏速度慢（需下载 JS 再渲染）快（服务器直出 HTML）
SEO差好
服务器成本低（静态文件）高（需运行 Node）
交互体验首屏后极好水合后一样
适用场景后台管理、SPA营销页、电商、内容站

React SSR 方案：Next.js（App Router 支持 RSC）

Q6: 前端如何做单元测试？测试策略是什么？

难度：⭐⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

测试金字塔：单元测试（多）→ 集成测试（中）→ E2E 测试（少）

工具栈：Vitest + React Testing Library + MSW + Playwright

原则：

  • 测试行为而非实现：用 getByRole 而非 querySelector
  • 不要追求 100% 覆盖率：80% 够用，关键路径必测
  • Mock 最少化：尽量使用真实组件
test('提交表单后显示成功提示', async () => {
  render(<ContactForm />);
  await userEvent.type(screen.getByLabelText('邮箱'), 'test@test.com');
  await userEvent.click(screen.getByRole('button', { name: '提交' }));
  expect(await screen.findByText('提交成功')).toBeInTheDocument();
});

Q7: Webpack 和 Vite 有什么区别？为什么 Vite 更快？

难度：⭐⭐ | 频率：🔥🔥🔥

💡 回答要点：

方面WebpackVite
开发启动打包所有文件后启动（慢）按需编译（ESM），秒启
热更新重新打包受影响模块基于 ESM，只更新单个模块
生产构建Webpack 自身使用 Rollup
生态最成熟快速增长
配置复杂简洁

Vite 快的原因：

  1. 开发时不打包，利用浏览器原生 ESM
  2. 用 esbuild（Go 写的）做预构建，比 JS 快 10-100 倍
  3. 热更新只传输变更的模块
