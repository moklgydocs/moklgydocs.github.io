应收账款 AR (Accounts Receivable)

概述

应收账款（AR）子系统管理企业因销售商品或提供服务而产生的客户欠款。它与销售模块紧密集成，负责从销售发票生成到客户回款确认的完整应收管理流程，并提供账龄分析和坏账管理能力。

一、核心业务流程

1.1 应收全流程

销售发票 ──▶ 生成应收单 ──▶ 客户确认 ──▶ 回款登记 ──▶ 核销匹配 ──▶ 清账
    │                                        │
    │                              ┌─────────┴──────────┐
    │                              ▼                    ▼
    │                        全额回款               部分回款
    │                        (自动清账)              (部分核销)
    │
    ▼
逾期未收 ──▶ 催收管理 ──▶ 计提坏账准备 ──▶ 坏账核销/收回

1.2 应收单状态机

┌────────┐    ┌───────────┐    ┌───────────┐    ┌──────────┐
│ Open    │───▶│ PartPaid  │───▶│ Paid      │    │ WrittenOff│
│ 待收款   │    │ 部分收款   │    │ 已收款    │    │ 已核销    │
└────────┘    └───────────┘    └───────────┘    └──────────┘
    │                                                ▲
    │              ┌──────────┐                      │
    └─────────────▶│ Overdue  │──────────────────────┘
                   │ 已逾期    │
                   └──────────┘

状态流转:
  Open → PartPaid      : 收到部分款项
  Open → Paid          : 收到全部款项
  Open → Overdue       : 超过约定付款期限（系统自动标记）
  PartPaid → Paid      : 剩余款项收齐
  PartPaid → Overdue   : 部分回款后超期
  Overdue → Paid       : 逾期后全额收回
  Overdue → WrittenOff : 确认无法收回，核销坏账

二、核心实体

2.1 应收单

Receivable (应收单)
├── Id: Guid
├── TenantId: Guid
├── ReceivableNo: string(30)          # 应收单号 AR-{YYYYMMDD}-{SEQ}
├── CustomerId: Guid                  # 客户ID
├── CustomerName: string(200)         # 客户名称（冗余）
├── SourceType: ReceivableSource      # 来源类型
├── SourceDocumentId: Guid?           # 来源单据ID
├── SourceDocumentNo: string(50)?     # 来源单据号 (销售发票号)
├── CurrencyCode: string(3)          # 币种
├── ExchangeRate: decimal(18,6)      # 汇率
├── OriginalAmount: decimal(18,2)    # 原币金额
├── Amount: decimal(18,2)            # 本位币金额
├── PaidAmount: decimal(18,2)        # 已收金额
├── RemainingAmount: decimal(18,2)   # 未收金额 (Amount - PaidAmount)
├── DueDate: DateTime                # 到期日
├── ReceivableDate: DateTime         # 应收日期 (发票日期)
├── Status: ReceivableStatus         # 状态
├── OverdueDays: int                 # 逾期天数
├── VoucherId: Guid?                 # 关联凭证ID
├── Remark: string(500)             # 备注
└── Receipts: List<ReceiptAllocation> # 回款分配记录

枚举:
  ReceivableSource: SalesInvoice=1, ServiceInvoice=2, OtherReceivable=3, ManualEntry=9
  ReceivableStatus: Open=0, PartPaid=1, Paid=2, Overdue=3, WrittenOff=4

2.2 回款单

Receipt (回款单)
├── Id: Guid
├── TenantId: Guid
├── ReceiptNo: string(30)            # 回款单号 REC-{YYYYMMDD}-{SEQ}
├── CustomerId: Guid                  # 客户ID
├── CustomerName: string(200)
├── ReceiptDate: DateTime             # 回款日期
├── ReceiptMethod: PaymentMethod      # 收款方式
├── BankAccountId: Guid?              # 收款银行账户
├── CurrencyCode: string(3)
├── ExchangeRate: decimal(18,6)
├── OriginalAmount: decimal(18,2)    # 原币收款金额
├── Amount: decimal(18,2)            # 本位币收款金额
├── AllocatedAmount: decimal(18,2)   # 已分配金额
├── UnallocatedAmount: decimal(18,2) # 未分配金额
├── Status: ReceiptStatus            # 状态
├── VoucherId: Guid?                 # 关联凭证ID
├── Remark: string(500)
└── Allocations: List<ReceiptAllocation>

ReceiptAllocation (回款分配)
├── Id: Guid
├── ReceiptId: Guid                  # 回款单ID
├── ReceivableId: Guid               # 应收单ID
├── ReceivableNo: string(30)         # 应收单号
├── AllocatedAmount: decimal(18,2)   # 分配金额
├── DiscountAmount: decimal(18,2)    # 折扣金额（现金折扣）
└── WriteOffAmount: decimal(18,2)    # 核销金额

枚举:
  PaymentMethod: BankTransfer=1, Cash=2, Check=3, CommercialBill=4, Other=9
  ReceiptStatus: Draft=0, Confirmed=1, Cancelled=-1

2.3 坏账管理

BadDebtProvision (坏账准备)
├── Id: Guid
├── TenantId: Guid
├── FiscalPeriodId: Guid              # 计提期间
├── ProvisionDate: DateTime           # 计提日期
├── Method: BadDebtMethod             # 计提方法
├── TotalReceivable: decimal(18,2)   # 应收账款总额
├── ProvisionRate: decimal(5,2)      # 计提比例 (%)
├── ProvisionAmount: decimal(18,2)   # 计提金额
├── PreviousBalance: decimal(18,2)   # 上期坏账准备余额
├── AdjustmentAmount: decimal(18,2)  # 本期调整金额（补提或冲回）
├── ClosingBalance: decimal(18,2)    # 期末坏账准备余额
├── VoucherId: Guid?
└── Details: List<BadDebtDetail>

BadDebtDetail (坏账明细)
├── Id: Guid
├── ProvisionId: Guid
├── CustomerId: Guid
├── AgingBucket: string(20)           # 账龄区间
├── ReceivableAmount: decimal(18,2)  # 应收金额
├── ProvisionRate: decimal(5,2)      # 计提比例
└── ProvisionAmount: decimal(18,2)   # 计提金额

BadDebtWriteOff (坏账核销)
├── Id: Guid
├── TenantId: Guid
├── WriteOffNo: string(30)
├── WriteOffDate: DateTime
├── CustomerId: Guid
├── ReceivableId: Guid                # 被核销的应收单
├── Amount: decimal(18,2)            # 核销金额
├── Reason: string(500)              # 核销原因
├── ApprovalStatus: ApprovalStatus
├── ApprovedBy: Guid?
├── ApprovedAt: DateTime?
└── VoucherId: Guid?

枚举:
  BadDebtMethod: Percentage=1(余额百分比法), Aging=2(账龄分析法), Individual=3(个别认定法)
  ApprovalStatus: Pending=0, Approved=1, Rejected=-1

三、账龄分析

3.1 账龄区间配置

3.2 账龄计算

逾期天数 = 当前日期 - 到期日
如果 逾期天数 ≤ 0，归入"未到期"
如果 逾期天数 > 0，根据天数归入对应区间

3.3 坏账计提会计分录

余额百分比法（按应收余额的5%计提）:

摘要科目借方贷方
计提坏账准备5711 资产减值损失11,500.00
计提坏账准备1231 坏账准备11,500.00

账龄分析法（按不同账龄比例计提）:

坏账准备 = Σ(各账龄区间应收金额 × 对应比例)
= 130,000×0% + 50,000×5% + 30,000×10% + 15,000×20% + 5,000×50%
= 0 + 2,500 + 3,000 + 3,000 + 2,500 = 11,000

本期应补提 = 应有余额 - 已有余额

四、信用管理

4.1 客户信用

CustomerCredit (客户信用)
├── Id: Guid
├── TenantId: Guid
├── CustomerId: Guid
├── CreditLimit: decimal(18,2)        # 信用额度
├── UsedCredit: decimal(18,2)         # 已用额度（未清应收 + 未发货订单）
├── AvailableCredit: decimal(18,2)    # 可用额度
├── PaymentTermDays: int              # 账期天数
├── CreditRating: CreditRating       # 信用等级
├── LastReviewDate: DateTime?         # 最近评审日期
└── IsBlocked: bool                   # 是否冻结（超信用额度）

枚举:
  CreditRating: A=1(优), B=2(良), C=3(中), D=4(差), E=5(黑名单)

4.2 信用检查时机

检查点动作
创建销售订单检查可用额度 ≥ 订单金额
发货前再次检查信用额度
回款后释放已用额度
逾期自动降低信用等级，可能冻结客户

五、回款核销

5.1 核销规则

规则说明
先进先出默认按应收单日期从早到晚核销
手动指定允许手动选择核销哪些应收单
跨币种不同币种需按汇率折算，差额计入汇兑损益
预收款客户多付金额作为预收账款处理
现金折扣约定期限内付款给予折扣（如 2/10, n/30）

八、业务规则与约束

规则描述
应收来源追溯每笔应收必须关联来源单据（销售发票/其他）
回款不超应收分配给某应收单的回款不得超过其未收余额
逾期自动标记系统每日检查，超过到期日自动标记为 Overdue
坏账审批坏账核销必须经过审批流程
信用额度实时信用额度在订单确认和发货时实时检查
回款确认生成凭证回款确认后自动生成收款凭证
预收款处理客户多付款自动生成预收账款
对账单支持按客户生成对账单，供双方核对
核销审计回款核销操作全程留痕，支持审计追溯
跨期间限制已关闭期间的应收单不可修改
