应付账款 AP (Accounts Payable)

概述

应付账款（AP）子系统管理企业因采购商品或接受服务而产生的对供应商的欠款。它与采购模块紧密集成，通过三单匹配（采购订单-收货单-发票）确保付款的准确性，并提供付款计划和供应商对账能力。

一、核心业务流程

1.1 应付全流程

采购发票 ──▶ 生成应付单 ──▶ 三单匹配 ──▶ 匹配通过 ──▶ 创建付款申请
                                │                           │
                                ▼                           ▼
                          匹配异常处理              付款审批 ──▶ 执行付款 ──▶ 清账
                          (差异调整/退回)                         │
                                                               ▼
                                                        银行付款 → 凭证

1.2 三单匹配流程

┌────────────────┐
│ 采购订单 (PO)   │──┐
│ 数量、单价、金额  │  │
└────────────────┘  │
                    │    ┌────────────────┐    ┌──────────────┐
                    ├───▶│ 三单匹配引擎    │───▶│ 匹配结果      │
                    │    │                │    │              │
┌────────────────┐  │    │ 数量匹配       │    │ ✅ 完全匹配    │
│ 收货单 (GRN)    │──┤    │ 价格匹配       │    │ ⚠️ 容差内匹配  │
│ 实收数量         │  │    │ 金额匹配       │    │ ❌ 匹配失败    │
└────────────────┘  │    └────────────────┘    └──────────────┘
                    │
┌────────────────┐  │
│ 采购发票 (INV)  │──┘
│ 开票数量、金额   │
└────────────────┘

匹配规则:
  数量容差: ±5% (可配置)
  价格容差: ±2% (可配置)
  金额容差: ±100元 (可配置)

二、核心实体

2.1 应付单

Payable (应付单)
├── Id: Guid
├── TenantId: Guid
├── PayableNo: string(30)             # 应付单号 AP-{YYYYMMDD}-{SEQ}
├── SupplierId: Guid                  # 供应商ID
├── SupplierName: string(200)
├── SourceType: PayableSource         # 来源类型
├── SourceDocumentId: Guid?           # 来源单据ID (采购发票ID)
├── SourceDocumentNo: string(50)?     # 来源单据号
├── PurchaseOrderId: Guid?            # 关联采购订单
├── PurchaseOrderNo: string(50)?
├── GoodsReceiptId: Guid?             # 关联收货单
├── GoodsReceiptNo: string(50)?
├── InvoiceNo: string(50)             # 供应商发票号
├── InvoiceDate: DateTime             # 发票日期
├── CurrencyCode: string(3)
├── ExchangeRate: decimal(18,6)
├── TaxRate: decimal(5,2)             # 税率 (如 13%)
├── Amount: decimal(18,2)             # 不含税金额
├── TaxAmount: decimal(18,2)          # 税额
├── TotalAmount: decimal(18,2)        # 含税总额
├── PaidAmount: decimal(18,2)         # 已付金额
├── RemainingAmount: decimal(18,2)    # 未付金额
├── DueDate: DateTime                 # 到期日
├── PaymentTermDays: int              # 账期天数
├── MatchStatus: MatchStatus          # 三单匹配状态
├── Status: PayableStatus             # 应付单状态
├── VoucherId: Guid?
└── Remark: string(500)

枚举:
  PayableSource: PurchaseInvoice=1, ServiceInvoice=2, ExpenseReimbursement=3, ManualEntry=9
  PayableStatus: Open=0, Matched=1, Approved=2, PartPaid=3, Paid=4, Dispute=5
  MatchStatus: Unmatched=0, PartMatched=1, FullMatched=2, Exception=3

2.2 三单匹配

ThreeWayMatch (三单匹配记录)
├── Id: Guid
├── TenantId: Guid
├── PayableId: Guid                    # 应付单ID
├── PurchaseOrderId: Guid              # 采购订单ID
├── PurchaseOrderNo: string(50)
├── GoodsReceiptId: Guid               # 收货单ID
├── GoodsReceiptNo: string(50)
├── InvoiceId: Guid                    # 发票ID
├── InvoiceNo: string(50)
├── MatchDate: DateTime                # 匹配日期
├── Result: MatchResult                # 匹配结果
├── QuantityVariance: decimal(18,4)   # 数量差异
├── PriceVariance: decimal(18,2)      # 价格差异
├── AmountVariance: decimal(18,2)     # 金额差异
├── HandledBy: Guid?                   # 差异处理人
├── HandledAt: DateTime?
├── HandlingNote: string(500)          # 差异处理说明
└── Details: List<MatchDetail>

MatchDetail (匹配明细)
├── Id: Guid
├── MatchId: Guid
├── ItemCode: string(50)              # 物料编码
├── ItemName: string(200)
├── POQuantity: decimal(18,4)         # 订单数量
├── GRNQuantity: decimal(18,4)        # 收货数量
├── InvoiceQuantity: decimal(18,4)    # 发票数量
├── POUnitPrice: decimal(18,6)        # 订单单价
├── InvoiceUnitPrice: decimal(18,6)   # 发票单价
├── QuantityMatch: bool               # 数量是否匹配
├── PriceMatch: bool                  # 价格是否匹配
└── Remark: string(200)

枚举:
  MatchResult: FullMatch=1, WithinTolerance=2, Exception=3

2.3 付款单

├── Id: Guid
├── TenantId: Guid
├── PaymentNo: string(30)             # 付款单号 PAY-{YYYYMMDD}-{SEQ}

├── SupplierName: string(200)
├── PaymentDate: DateTime              # 付款日期
├── PaymentMethod: PaymentMethod       # 付款方式
├── BankAccountId: Guid                # 付款银行账户

├── OriginalAmount: decimal(18,2)
├── Amount: decimal(18,2)             # 本位币金额
├── Status: PaymentStatus

├── ApprovedBy: Guid?
├── ApprovedAt: DateTime?
├── VoucherId: Guid?

├── Id: Guid

├── DueDate: DateTime                  # 到期日
├── PayableAmount: decimal(18,2)      # 应付金额

枚举:

五、供应商对账

5.1 对账流程

① 获取供应商对账单 (供应商提供)
          │
          ▼
② 系统生成内部应付明细
          │
          ▼
③ 逐笔比对
   ├── 金额一致 → ✅ 已核对
   ├── 金额不一致 → ⚠️ 差异调查
   └── 对方有我方无 → 📋 补录
          │
          ▼
④ 差异处理
   ├── 时间差异(在途) → 标记，下期核对
   ├── 金额差异 → 调整或退回
   └── 单据遗漏 → 补录应付
          │
          ▼
⑤ 确认对账结果，双方签字

八、业务规则与约束

规则描述
三单必匹配采购类应付必须完成三单匹配后才能付款
容差可配置数量/价格/金额的匹配容差由管理员配置
付款不超应付付款分配不得超过应付单未付余额
审批金额分级不同金额的付款需要不同级别的审批
重复发票检查同一供应商同一发票号不可重复录入
付款日期限制付款日期不得早于发票日期
预付款追踪预付款必须在后续采购中冲抵
跨期间限制已关闭期间的应付数据不可修改
供应商余额实时供应商应付余额实时更新
付款确认生成凭证付款执行后自动生成付款凭证
