入库管理

入库管理

概述

入库管理处理所有增加库存的业务操作，包括采购入库、生产完工入库、销售退货入库、仓库调拨接收等。系统通过入库单统一管理各类入库事务，支持质量检验、上架推荐、条码扫描等功能，确保物料准确、高效地进入库存。

一、入库类型总览

入库类型触发来源来源单据是否质检财务影响
采购入库PO 收货确认采购订单/收货单可配置原材料增加，暂估/确认入账
完工入库WO 完工报告生产工单可配置产成品增加，生产成本结转
销售退货入库退货收货销售退货单必须库存商品增加，收入冲回
调拨接收入库调拨单发出调拨单否仓库间转移
其他入库手工创建-否库存增加
期初入库系统初始化-否期初余额

三、核心实体

3.1 入库单

ReceiptOrder (入库单)
├── Id: Guid
├── TenantId: Guid
├── ReceiptNo: string(30)              # 编号 RO-{YYYYMMDD}-{SEQ}
├── ReceiptType: ReceiptType           # 入库类型
├── ReceiptDate: DateTime              # 入库日期
│
├── SourceDocumentType: string(20)     # 来源类型 (PO/WO/SalesReturn/TO)
├── SourceDocumentId: Guid?
├── SourceDocumentNo: string(50)?
│
├── WarehouseId: Guid                  # 目标仓库
├── SupplierId: Guid?                  # 供应商 (采购入库)
├── WorkOrderId: Guid?                 # 工单 (完工入库)
├── TransferOrderId: Guid?             # 调拨单 (调拨入库)
│
├── ExpectedDate: DateTime?            # 预计到货日
├── ActualDate: DateTime?              # 实际到货日
├── InspectionRequired: bool           # 是否需要质检
│
├── Status: ReceiptStatus
├── OperatorId: Guid                   # 收货员
├── ConfirmedBy: Guid?                 # 确认人
├── ConfirmedAt: DateTime?
├── VoucherId: Guid?                   # 关联财务凭证
├── Remark: string(500)
└── Lines: List<ReceiptOrderLine>

枚举:
  ReceiptType:
    PurchaseReceipt=1(采购入库), ProductionReceipt=2(完工入库),
    SalesReturnReceipt=3(销售退货入库), TransferReceipt=4(调拨入库),
    OtherReceipt=5(其他入库), InitialStock=6(期初入库)
  ReceiptStatus:
    Draft=0(草稿), Receiving=1(收货中), PendingInspection=2(待质检),
    Inspecting=3(质检中), PendingPutaway=4(待上架),
    PutawayInProgress=5(上架中), Completed=6(已完成),
    PartialCompleted=7(部分完成), Cancelled=8(已取消)

3.2 入库单行

ReceiptOrderLine (入库单行)
├── Id: Guid
├── ReceiptOrderId: Guid
├── LineNo: int                        # 行号
├── ItemId: Guid
├── ItemCode: string(50)
├── ItemName: string(200)
├── UnitOfMeasure: string(20)
│
├── ExpectedQuantity: decimal(18,4)   # 预期数量
├── ReceivedQuantity: decimal(18,4)   # 实收数量
├── AcceptedQuantity: decimal(18,4)   # 合格数量
├── RejectedQuantity: decimal(18,4)   # 不合格数量
│
├── LocationId: Guid?                  # 目标库位
├── BatchNo: string(50)?              # 批次号
├── SerialNumbers: string?             # 序列号列表 (JSON)
├── ManufactureDate: DateTime?         # 生产日期
├── ExpiryDate: DateTime?              # 有效期
│
├── UnitCost: decimal(18,6)           # 单位成本
├── Amount: decimal(18,2)             # 金额
│
├── InspectionResult: InspectionResult? # 质检结果
├── PutawayLocationId: Guid?           # 实际上架库位
├── PutawayStatus: PutawayLineStatus?
└── Remark: string(200)

枚举:
  InspectionResult:
    Pending=0(待检), Passed=1(合格), Failed=2(不合格),
    ConditionalAccept=3(条件接受), Rework=4(返工)
  PutawayLineStatus:
    Pending=0(待上架), InProgress=1(上架中), Completed=2(已上架)

3.3 质检单

QualityInspection (质检单)
├── Id: Guid
├── TenantId: Guid
├── InspectionNo: string(30)           # 编号 QI-{YYYYMMDD}-{SEQ}
├── ReceiptOrderId: Guid
├── ReceiptLineId: Guid
│
├── ItemId: Guid
├── ItemCode: string(50)
├── ItemName: string(200)
├── BatchNo: string(50)?
│
├── InspectionType: InspectionType     # 检验类型
├── InspectedQuantity: decimal(18,4)  # 送检数量
├── SampleSize: int?                   # 抽检样本量
│
├── PassedQuantity: decimal(18,4)     # 合格数量
├── FailedQuantity: decimal(18,4)     # 不合格数量
├── PassRate: decimal(5,2)?           # 合格率 (%)
│
├── Result: InspectionResult           # 检验结论
├── DefectType: string(50)?            # 缺陷类型
├── DefectDescription: string(500)?    # 缺陷描述
├── Disposition: InspectionDisposition # 处置方式
│
├── InspectorId: Guid                  # 检验员
├── InspectionDate: DateTime           # 检验日期
├── CompletedDate: DateTime?
├── Status: InspectionStatus
└── Remark: string(500)

枚举:
  InspectionType:
    FullInspection=1(全检), Sampling=2(抽检), Skip=3(免检)
  InspectionDisposition:
    Accept=1(接受入库), Reject=2(退回供应商), Scrap=3(报废),
    Rework=4(返工), ConditionalAccept=5(让步接受), Sort=6(挑选)
  InspectionStatus:
    Pending=0(待检), InProgress=1(检验中), Completed=2(已完成),
    Cancelled=3(已取消)

3.4 上架任务

PutawayTask (上架任务)
├── Id: Guid

├── ItemId: Guid

枚举:

    Completed=3(已完成), Cancelled=4(已取消)

五、质检工作流

5.1 质检触发规则

条件质检类型说明
新供应商首次到货全检首批必检
合格供应商常规到货抽检按 AQL 标准抽检
免检供应商免检历史合格率 > 99%
关键物料全检无论供应商等级
退货入库全检确认退货品质
完工入库可配置按工艺要求

5.2 质检处置流程

质检结论
    │
    ├── 合格 (PassRate ≥ 合格线)
    │   └── Accept → 进入上架流程
    │
    ├── 条件接受 (有轻微缺陷但可接受)
    │   └── ConditionalAccept → 降级处理 → 进入上架流程
    │
    ├── 需挑选 (批次内有不合格品)
    │   └── Sort → 分离合格/不合格 → 合格品上架，不合格品处置
    │
    ├── 需返工
    │   └── Rework → 退回产线/供应商返工 → 重新质检
    │
    └── 不合格
        ├── Reject → 退回供应商 (采购入库)
        └── Scrap → 报废处理 → 生成报废凭证

六、入库成本计算

6.1 各类入库成本来源

入库类型单位成本来源说明
采购入库PO 单价 (暂估) 或 发票单价 (确认)暂估入账后发票到账调整
完工入库生产成本归集 ÷ 完工数量料+工+费
销售退货原出库成本按原出库单价回冲
调拨入库出库方成本成本随物料转移
其他入库手工输入需审批确认
期初入库手工输入初始化成本

6.2 暂估入账

采购入库暂估流程:

① PO收货 → 按PO单价暂估入库
   借: 原材料          10,000
     贷: 应付账款-暂估    10,000

② 发票到达 → 实际金额 10,500
   冲回暂估:
   借: 应付账款-暂估    10,000
     贷: 原材料          10,000
   
   按发票金额入账:
   借: 原材料          10,500
     借: 应交税费-进项税  1,365
       贷: 应付账款        11,865

九、业务规则

规则描述
实收不超预期实收数量不得超过预期数量的 110% (可配置容差)
质检必达配置为必检的物料，未质检不可上架
批次强制启用批次管理的物料必须录入批次号
序列号唯一序列号管理物料每件必须有唯一序列号
保质期校验入库时剩余保质期不得低于配置的最低百分比
存储类别匹配上架库位的存储类别必须兼容物料要求
库位容量校验上架不可超过库位的重量/体积限制
来源单据关联采购/完工/退货入库必须关联来源单据
重复入库防止同一来源单据行不可重复创建入库单行
确认不可逆已确认的入库单不可修改，只能通过出库冲销
暂估自动化采购入库无发票时自动按PO价暂估入账
事务原子性入库确认、库存更新、财务凭证在同一事务内完成
