# IL 性能优化

> 从 IL 层面审视性能，能看到 C# 层面看不到的开销。一次隐式装箱、一个多余的 callvirt、一段可内联却未内联的方法——这些微小的差异在热路径上会被放大百万倍。

## 一、避免不必要的装箱

### 1.1 识别装箱

`box` 指令将值类型转换为对象引用，导致堆分配：

```csharp
// C#
int x = 42;
object obj = x;       // 装箱
int y = (int)obj;     // 拆箱
```

```il
// IL
ldc.i4.s     42
stloc.0
ldloc.0
box          [System.Runtime]System.Int32    // 装箱！堆分配
stloc.1
ldloc.1
unbox.any    [System.Runtime]System.Int32   // 拆箱
stloc.2
```

### 1.2 常见隐式装箱场景

| 场景 | C# 代码 | IL 表现 |
|------|---------|---------|
| 值类型赋给 object | `object o = 42;` | box Int32 |
| 非泛型集合 | `ArrayList list; list.Add(42);` | box Int32 |
| string.Format 值类型 | `string.Format("{0}", 42);` | box Int32 |
| 枚举转 object | `object o = DayOfWeek.Monday;` | box Enum |
| 接口调用值类型 | `IComparable c = 42;` | box Int32 |

### 1.3 用泛型消除装箱

```csharp
// 有装箱
public static void PrintValue(object value)  // int → box → object
{
    Console.WriteLine(value);
}

// 无装箱
public static void PrintValue<T>(T value)    // int 直接使用，无 box
{
    Console.WriteLine(value);
}
```

```il
// 泛型版本 IL（T = int 时）
ldarg.0
box          [System.Runtime]System.Int32    // Console.WriteLine 仍需装箱
call         void [System.Console]System.Console::WriteLine(object)
```

::: warning 泛型不是万能的
上例中，即使使用泛型参数 `T`，调用 `Console.WriteLine(value)` 仍会装箱（因为 `Console.WriteLine(object)` 接受 object）。要真正消除装箱，应使用 `Console.WriteLine(value)` 的泛型重载或避免转为 object。
:::

## 二、避免 callvirt 对非虚方法

### 2.1 C# 编译器的 callvirt 偏好

C# 编译器对**实例方法调用**默认生成 `callvirt`（即使方法非虚），以获得免费的 null 检查：

```csharp
// C#
string s = "hello";
int len = s.Length;   // Length 是非虚属性
```

```il
// IL
ldloc.0
callvirt    instance int32 [System.Runtime]System.String::get_Length()
;                           ^^^^^^^^ 非虚方法用了 callvirt
```

### 2.2 JIT 的去虚化

JIT 编译器在以下条件下会将 `callvirt` 去虚化为直接调用：

| 条件 | 去虚化 |
|------|--------|
| 方法非虚且类型密封（sealed） | 是 |
| 方法非虚且 JIT 能确定类型 | 是 |
| 方法非虚但类型可派生 | 可能 |
| 方法是虚方法 | 需要内联守卫（Guarded Devirtualization） |

::: tip sealed 关键字的性能意义
密封类（`sealed class`）让 JIT 确定没有派生类，可以更积极地做去虚化和内联。热路径上的关键类型考虑标记 `sealed`。
:::

## 三、栈友好代码

### 3.1 减少不必要的局部变量

JIT 优化器会尽量将局部变量分配到寄存器，但过多的局部变量可能增加寄存器压力：

```csharp
// 冗余局部变量
int a = x + y;
int b = a * 2;
return b + 1;

// 栈友好
return (x + y) * 2 + 1;
```

```il
// 冗余版 IL
ldarg.0     ; x
ldarg.1     ; y
add
stloc.0     ; a = x + y
ldloc.0
ldc.i4.2
mul
stloc.1     ; b = a * 2
ldloc.1
ldc.i4.1
add
ret

// 栈友好版 IL
ldarg.0     ; x
ldarg.1     ; y
add
ldc.i4.2
mul
ldc.i4.1
add
ret
; 无 stloc/ldloc，纯栈操作
```

::: important 信任 JIT
现代 RyuJIT 优化器非常强大，Debug 模式的 IL 和 Release 模式的 IL 可能相同，但 JIT 优化结果差异巨大。**始终以 Release 构建 + 启用优化为基准做性能分析。**
:::

## 四、内联提示

### 4.1 MethodImplOptions.AggressiveInlining

```csharp
[MethodImpl(MethodImplOptions.AggressiveInlining)]
static int Square(int x) => x * x;
```

| 选项 | 行为 |
|------|------|
| 无标记 | JIT 自行决定是否内联（默认阈值约 32 字节 IL） |
| `AggressiveInlining` | 强烈建议内联（降低阈值） |
| `NoInlining` | 禁止内联 |
| `AggressiveOptimization` | 优化但不内联 |

### 4.2 内联的 IL 条件

JIT 拒绝内联的情况：

| 情况 | 原因 |
|------|------|
| 方法体过大 | 超过内联阈值 |
| 虚方法调用 | 运行时才能确定目标 |
| 含 try/catch | 异常处理增加复杂度 |
| 含循环（某些 JIT 版本） | 控制流复杂 |
| 递归方法 | 无限展开 |
| 方法标记 NoInlining | 显式禁止 |

## 五、Span\<T\> 与 MemoryMarshal

### 5.1 Span\<T\> 避免边界检查

```csharp
// 普通数组访问：每次有边界检查
int Sum(int[] arr)
{
    int sum = 0;
    for (int i = 0; i < arr.Length; i++)
        sum += arr[i];  // ldelem + 边界检查
    return sum;
}

// Span 访问：JIT 可消除边界检查
int Sum(ReadOnlySpan<int> span)
{
    int sum = 0;
    for (int i = 0; i < span.Length; i++)
        sum += span[i];  // call instance int32 Span`1::get_Item(int32)
    return sum;
}
```

### 5.2 MemoryMarshal 直接访问

```csharp
using System.Runtime.InteropServices;

// 将 int[] 视为 byte[]，零拷贝
int[] ints = new int[100];
Span<byte> bytes = MemoryMarshal.AsBytes(ints.AsSpan());
```

## 六、ref struct 与 byref

### 6.1 零分配模式

```csharp
// 使用 ref 返回避免拷贝
[MethodImpl(MethodImplOptions.AggressiveInlining)]
public ref readonly T GetItemRef(int index) => ref _items[index];
```

```il
; ref return IL
ldarg.0                             ; this
ldfld      int64[] MyList::_items   ; _items
ldarg.1                             ; index
ldelem     int64                    ; _items[index]（返回托管指针）
ret
; 注意：返回的是托管指针（&），不是值拷贝
```

| byref 形式 | IL 指令 | 说明 |
|-----------|---------|------|
| `ref T` 参数 | `ldarg` + `ldind` | 间接加载 |
| `ref T` 返回 | `ldarg` + `ldelem` → 返回指针 | 零拷贝 |
| `in T` 参数 | 同 `ref T` | 只读语义，IL 层相同 |
| `out T` 参数 | 同 `ref T` | 写入语义，IL 层相同 |

## 七、字符串插值 vs 拼接

### 7.1 string.Concat

```csharp
// C#
string s = "Hello, " + name + "!";
```

```il
; 编译器优化为 string.Concat
ldstr      "Hello, "
ldarg.1
ldstr      "!"
call       string [System.Runtime]System.String::Concat(string, string, string)
```

### 7.2 字符串插值

```csharp
// C#
string s = $"Hello, {name}!";
```

```il
; .NET 6+ 使用 DefaultInterpolatedStringHandler
ldloca.s   handler
ldstr      "Hello, "
ldstr      "!"
call       instance void [System.Runtime]System.Runtime.CompilerServices.DefaultInterpolatedStringHandler::AppendLiteral(string)
ldarg.1
call       instance void [System.Runtime]System.Runtime.CompilerServices.DefaultInterpolatedStringHandler::AppendFormatted(string)
; ... 最终调用 ToString()
```

::: tip 性能选择
- **少量拼接（2-3 段）**：`string.Concat`（`+` 运算符编译为此）最快
- **复杂插值**：`$""` 在 .NET 6+ 使用 `DefaultInterpolatedStringHandler`，可避免中间字符串分配
- **大量拼接**：`StringBuilder` 或 `string.Create`
- **已知长度**：`string.Create` + `Span<char>` 最优
:::

## 八、LINQ 的 IL 开销

### 8.1 LINQ 链 vs 手写循环

```csharp
// LINQ
var result = numbers.Where(x => x > 10).Select(x => x * 2).Sum();

// 手写循环
int sum = 0;
foreach (int x in numbers)
    if (x > 10) sum += x * 2;
```

```il
; LINQ 版 IL（简化）
; 1. new WhereEnumerableIterator
newobj      instance class [System.Linq]System.Linq.Enumerable::Where(...)
; 2. new SelectEnumerableIterator
newobj      instance class [System.Linq]System.Linq.Enumerable::Select(...)
; 3. Sum 遍历
call        int32 [System.Linq]System.Linq.Enumerable::Sum(...)

; 手写循环版 IL
; 无任何分配，直接 ldelem + brtrue + add
```

| 方面 | LINQ | 手写循环 |
|------|------|---------|
| 堆分配 | 迭代器对象 + 委托 | 无 |
| 方法调用 | 每元素多次虚调用 | 内联的分支 |
| IL 指令数 | 多（间接调用） | 少（直接操作） |
| 可读性 | 高 | 中 |
| 热路径适用 | 不推荐 | 推荐 |

## 九、优化总结表

| 优化 | IL 模式 | 预期收益 |
|------|---------|---------|
| 避免装箱 | 消除 `box`/`unbox` | 减少堆分配，降低 GC 压力 |
| sealed + callvirt 去虚化 | `callvirt` → 直接调用 | 消除虚方法分派，启用内联 |
| 减少局部变量 | 减少 `stloc`/`ldloc` | 减少寄存器压力 |
| AggressiveInlining | 方法体内联到调用处 | 消除调用开销，暴露更多优化机会 |
| Span\<T\> | 消除 `ldelem` 边界检查 | 减少分支判断 |
| ref struct | `ldind`/`stind` 间接访问 | 零拷贝，零分配 |
| string.Concat vs 插值 | `Concat` vs `DefaultInterpolatedStringHandler` | 减少中间字符串分配 |
| 手写循环替代 LINQ | 直接 `ldelem` + 分支 | 消除迭代器分配和虚调用 |

## 十、BenchmarkDotNet 示例

```csharp
using BenchmarkDotNet.Attributes;
using BenchmarkDotNet.Running;

[MemoryDiagnoser]
public class BoxingBenchmark
{
    private readonly int[] _data = Enumerable.Range(0, 1000).ToArray();

    [Benchmark(Baseline = true)]
    public int LinqSum() => _data.Where(x => x > 500).Sum();

    [Benchmark]
    public int ForLoopSum()
    {
        int sum = 0;
        for (int i = 0; i < _data.Length; i++)
            if (_data[i] > 500) sum += _data[i];
        return sum;
    }

    [Benchmark]
    public int SpanSum()
    {
        int sum = 0;
        ReadOnlySpan<int> span = _data;
        for (int i = 0; i < span.Length; i++)
            if (span[i] > 500) sum += span[i];
        return sum;
    }
}

// 运行
BenchmarkRunner.Run<BoxingBenchmark>();
```

::: important 始终分析 Release 构建
Debug 构建禁用 JIT 优化，IL 不会内联、不会去虚化、不会消除边界检查。性能分析**必须**在 Release 模式下进行：
```
dotnet run -c Release
```
:::

## 面试要点

1. **如何从 IL 层识别装箱？** 查找 `box` 指令。值类型赋给 `object`、非泛型集合添加值类型、`string.Format` 传值类型参数都会产生 `box`。

2. **C# 为什么默认使用 callvirt 调用实例方法？** 为了获得免费的 null 检查。如果引用为 null，`callvirt` 会抛出 `NullReferenceException`，而 `call` 不会检查。JIT 会对非虚方法做去虚化优化。

3. **AggressiveInlining 一定能内联吗？** 不一定。它只是降低内联阈值，强烈建议 JIT 内联。如果方法体过大、含异常处理或递归调用，JIT 仍可能拒绝内联。

4. **Span\<T\> 为什么比数组访问快？** JIT 可以证明 Span 的索引在循环范围内，从而消除边界检查（`ldelem` 的隐式检查）。数组访问在每次索引时都有边界检查。

5. **LINQ 在 IL 层有什么开销？** 每个 LINQ 操作符创建一个迭代器对象（堆分配），每次 `MoveNext` 是虚方法调用，委托闭包产生额外分配。热路径应避免 LINQ。

6. **如何正确做 IL 级性能分析？** 必须在 Release 构建 + 启用优化的环境下分析。Debug 模式下 JIT 不做内联、不去虚化、不消除边界检查，IL 分析结论不可靠。
