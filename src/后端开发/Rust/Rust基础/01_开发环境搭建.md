# 01 · 开发环境搭建

## 一、【PM】为什么要花时间配好工具链？

C# 开发者已经熟悉 Visual Studio 一键安装 .NET SDK + NuGet + 格式化的体验。Rust 的工具链同样高度集成，但默认不随系统安装，需要手动配置。

好消息是：Rust 的 `cargo` 是目前所有系统编程语言中**工具链最完善**的之一，一个工具搞定依赖管理、编译、测试、文档、格式化、Lint，对比 C# 需要组合 `dotnet` + Roslyn 分析器 + EditorConfig，Rust 的约定更统一。

## 二、安装 Rustup

`rustup` 是 Rust 的版本管理器，类比 `.NET SDK` 管理器（nvm for Node，pyenv for Python）。

### Windows

```powershell
# 下载并运行安装器
winget install Rustlang.Rustup
# 或手动下载 https://rustup.rs 的 rustup-init.exe
```

安装完成后**重启终端**，然后验证：

```bash
rustup show
# 应输出：
# Default host: x86_64-pc-windows-msvc
# stable-x86_64-pc-windows-msvc (default)
# rustc 1.xx.x (...)
```

### 必装组件

```bash
rustup default stable              # 固定使用 stable 频道
rustup component add clippy        # 静态分析（比 Roslyn 分析器更严格）
rustup component add rustfmt       # 代码格式化（类比 dotnet format）
rustup component add rust-src      # 源码，IDE 跳转必需
rustup component add rust-analyzer # Language Server（VS Code 扩展用）
```

### 推荐安装的 cargo 工具

```bash
cargo install cargo-watch   # 监听文件变更自动重编译（类比 dotnet watch）
cargo install cargo-expand  # 展开宏，调试时查看宏展开结果
cargo install cargo-audit   # 扫描依赖的安全漏洞
cargo install cargo-nextest # 更快的测试运行器（替代 cargo test）
```

## 三、VS Code 配置

安装扩展：

| 扩展 | 作用 | C# 对比 |
|------|------|---------|
| `rust-analyzer` | 智能提示、跳转定义、内联类型 | C# Dev Kit / OmniSharp |
| `Even Better TOML` | Cargo.toml 语法高亮 | 无直接对比 |
| `CodeLLDB` 或 `C/C++` | 断点调试 | VS 调试器 |
| `Error Lens` | 行内显示错误 | VS 错误波浪线 |

`.vscode/settings.json` 推荐配置：

```json
{
  "rust-analyzer.checkOnSave.command": "clippy",
  "rust-analyzer.inlayHints.typeHints.enable": true,
  "editor.formatOnSave": true,
  "[rust]": {
    "editor.defaultFormatter": "rust-lang.rust-analyzer"
  }
}
```

## 四、Cargo 命令速查（对比 dotnet）

| dotnet 命令 | cargo 等价 | 说明 |
|------------|-----------|------|
| `dotnet new console -n Foo` | `cargo new foo` | 新建二进制项目 |
| `dotnet new classlib -n Foo` | `cargo new foo --lib` | 新建库项目 |
| `dotnet run` | `cargo run` | 编译并运行 |
| `dotnet build` | `cargo build` | 仅编译（debug 模式） |
| `dotnet build -c Release` | `cargo build --release` | 优化编译 |
| `dotnet test` | `cargo test` | 运行所有测试 |
| `dotnet add package Foo` | `cargo add foo` | 添加依赖 |
| `dotnet format` | `cargo fmt` | 格式化代码 |
| 无 | `cargo clippy` | 静态 Lint 检查 |
| `dotnet publish` | `cargo build --release` | 发布二进制 |
| `dotnet doc` | `cargo doc --open` | 生成文档并打开浏览器 |

## 五、第一个 Fizz Buzz（用 match）

```bash
cargo new fizzbuzz
cd fizzbuzz
```

编辑 `src/main.rs`：

```rust
fn main() {
    for i in 1..=100 {
        // match 替代 if/else if 链，每个模式必须穷举
        // 元组（tuple）匹配：同时匹配两个条件
        let output = match (i % 3, i % 5) {
            (0, 0) => "FizzBuzz".to_string(), // 同时整除3和5
            (0, _) => "Fizz".to_string(),     // 仅整除3，_ 表示忽略
            (_, 0) => "Buzz".to_string(),     // 仅整除5
            _       => i.to_string(),          // 其他情况转字符串
        };
        println!("{output}");
    }
}
```

运行：

```bash
cargo run
# 输出 1 2 Fizz 4 Buzz Fizz ... FizzBuzz ...
```

通过 Clippy 检查：

```bash
cargo clippy --deny warnings
# Finished ... 无警告
```

## 六、【QA】常见安装问题

| 问题 | 原因 | 解决 |
|------|------|------|
| `'rustc' 不是内部或外部命令` | 环境变量未生效 | 重启终端；确认 `~/.cargo/bin` 在 PATH |
| `error: linker 'link.exe' not found` | 缺少 MSVC 构建工具 | 安装 VS Build Tools（勾选 C++）|
| `cargo clippy` 提示未安装 | 组件未添加 | `rustup component add clippy` |
| `rust-analyzer` 不工作 | 项目根目录无 `Cargo.toml` | 确保在项目根目录打开 VS Code |

## 七、【QA】自测题

**Q1**：`cargo build` 和 `cargo build --release` 的主要区别是什么？

A. `--release` 跳过测试  
B. `--release` 开启编译优化，生成更小/更快的二进制，但编译时间更长  
C. `--release` 将代码部署到服务器  
D. `--release` 和 `cargo run` 等价

<details><summary>答案</summary>

**B**。`cargo build` 默认是 debug 模式（含调试信息，不优化），编译快，适合开发。`--release` 开启 LLVM 全量优化，生成生产用的二进制，编译慢约 2-3 倍，但运行性能差异可达 10x。类比 C# 的 Debug vs Release 编译配置。

</details>

**Q2**：`rustup component add clippy` 安装的是什么？

A. 一个 IDE 插件  
B. Rust 的格式化工具  
C. 一个静态代码分析工具，会给出比编译器更多的代码质量建议  
D. Rust 的单元测试框架

<details><summary>答案</summary>

**C**。Clippy 是 Rust 官方的 Lint 工具，内置 700+ 条规则，涵盖性能、正确性、惯用法检查。类比 C# 的 Roslyn 分析器，但规则更严格。`cargo clippy --deny warnings` 会把所有 Lint 警告视为错误。

</details>
