# MoNode · 立项文档

> **角色**：【PM】主导  
> **目标**：Phase 4 嵌入式项目，Embassy on RP2040，no_std async Rust，温湿度采集 + UART JSON 上报，Flash < 80KB

---

## 一、背景与动机

### 从 C# 到裸机 Rust：三代范式的跃迁

| 阶段 | 运行环境 | 特征 |
|------|---------|------|
| Phase 2 MoCLI | Rust + OS + tokio | 有 OS 调度，有堆（HashMap），无 GC |
| Phase 3 Restrel | Rust + OS + tokio | 有 OS，零拷贝，全异步 |
| **Phase 4 MoNode** | **Rust + 裸机 + Embassy** | **无 OS，无堆，确定性时序** |

C# 开发者进入嵌入式世界的类比路径：

```
.NET nanoFramework（C# on Cortex-M）
    ↓ 去掉 GC + CLR 运行时
RTOS（FreeRTOS / Zephyr）
    ↓ 去掉操作系统调度器
bare-metal + Embassy（async on Cortex-M）← 我们选这条路
```

### 为什么选 Embassy 而非更简单的 RTOS？

Embassy 将 Rust 的 async/await 机制直接运行在裸机上：

- **零堆需求**：Future 状态机在编译期确定大小，分配在 `.bss` 段静态存储区
- **确定性时序**：没有 OS 调度抖动，中断延迟固定（Cortex-M0+ NVIC）
- **类型安全的外设单例**：同一外设不可能被两个任务同时持有，编译期防止竞争
- **现代异步写法**：与 tokio 相同的 `.await` 语法，无认知断层

### 真实需求场景

Mo 工厂车间部署了 20 个 RP2040 传感器节点，采集温湿度数据：

- 每 10 秒通过 UART 上报一条 JSON 数据到上位机（PC / 树莓派）
- 上位机汇总后写入 PostgreSQL，Grafana 展示看板
- 节点 7×24 不间断运行，Flash 占用 < 80KB（预留 OTA 升级空间）

## 二、项目定义

**项目代号**：MoNode  
**硬件平台**：Raspberry Pi Pico（RP2040，Cortex-M0+，2MB Flash，264KB SRAM）  
**传感器**：AHT20（I²C，±0.3°C 温度精度，±2%RH 湿度精度）  
**通信方式**：UART0，9600 bps，JSON 格式，每 10 秒一条  
**调试方式**：defmt + RTT（Real-Time Transfer，通过 SWD 调试器）

### 功能范围（In Scope）

- AHT20 初始化序列（`0xBE 0x08 0x00`）+ 校准状态检查
- 周期性温湿度采集（80ms 测量等待 + 状态轮询）
- UART JSON 数据上报（格式：`{"ts":N,"temp":T.t,"hum":H.h}`）
- Embassy async 双任务架构（main task + sensor_loop task）
- defmt RTT 调试输出（开发期）

### 不在范围内（Out of Scope）

- OTA 固件更新（需要 Flash Write + Bootloader）
- WiFi / BLE 无线通信
- 多传感器并发采集
- 本地数据缓存（Flash 写入）

## 三、用户故事

**US-1（核心上报）**：作为 Mo 工厂运维，我需要传感器节点每 10 秒通过串口输出一条 JSON 温湿度读数，以便上位机程序解析并写入数据库。

**US-2（开发调试）**：作为 Mo 固件开发者，我需要在开发阶段通过 RTT 看到 defmt 格式的调试日志（传感器原始值、转换结果、错误码），以便不占用 UART 数据通道的情况下定位问题。

**US-3（故障容忍）**：作为 Mo 运维，我需要节点在 AHT20 测量忙（Busy bit = 1）的情况下自动等待重试，而不是 panic 或进入死循环，以保证 24/7 持续运行。

**US-4（Flash 预算）**：作为 Mo 固件开发者，我需要 Release 固件的 `.text` 段小于 80KB，以便为未来 OTA 升级预留足够的 Flash 空间。

## 四、技术选型

### MCU + 开发板

| 项目 | 选型 | 理由 |
|------|------|------|
| MCU | RP2040 | 双核 Cortex-M0+，Embassy 官方一级支持，成本低（¥3） |
| 开发板 | Raspberry Pi Pico | 标准引脚布局，USB UF2 烧录无需调试器 |
| Flash | 2MB (W25Q16JVSSIQ) | 板载 SPI Flash，充足 OTA 空间 |

### 软件栈

| 组件 | 版本 | 选择理由 | 为什么不选 X |
|------|------|---------|------------|
| `embassy-rp` | 0.9.0 | RP2040 HAL，async I²C/UART/Timer | RTIC：无 async 支持，心智负担高 |
| `embassy-executor` | 0.9.0 | Cortex-M 裸机 async executor | bare-metal 手写：不可维护 |
| `embassy-time` | 0.4.0 | 软件定时器，Timer::after_millis() | RTC：RP2040 无内置 RTC |
| `heapless` | 0.9.2 | no_std 固定容量 String，JSON 格式化 | `format!`：需要 allocator，禁止 |
| `defmt` + `defmt-rtt` | 0.3.8 / 0.4.0 | 高效 RTT 调试日志，不占 UART | `log` crate：不适合 no_std 裸机 |
| `panic-probe` | 0.3.2 | 调试模式 panic 通过 RTT 输出位置 | `panic-halt`：生产模式使用 |

### I²C 引脚分配（RP2040 Pico）

```
GPIO0 → UART0 TX（上报数据，输出）
GPIO1 → UART0 RX（保留，输入）
GPIO4 → I2C0 SDA（AHT20 数据线，上拉 4.7kΩ）
GPIO5 → I2C0 SCL（AHT20 时钟线，上拉 4.7kΩ）
```

## 五、验收标准

| AC | 标准 | 验证方式 |
|----|------|---------|
| AC1 | `cargo size --release` 显示 `.text` < 80KB | `cargo size --release -- -A` |
| AC2 | UART 每 10 秒输出一条 `{"ts":N,"temp":T.t,"hum":H.h}\r\n` | 串口监视器（minicom / PuTTY）抓包 |
| AC3 | AHT20 初始化序列正确（`0xBE 0x08 0x00`），校准标志检查，测量等待 80ms | 代码审查 + 逻辑分析仪验证 I²C 时序 |
| AC4 | 全程无堆分配：无 `extern crate alloc`，`nm` 输出无 `__malloc`/`__free` 符号 | `cargo nm --release \| grep malloc` |
| AC5 | 上电后 3 秒内第一条 JSON 出现在串口 | 串口时间戳验证（`ts` 字段 < 3000ms） |
| AC6 | AHT20 Busy 状态下等待后重试，不 panic / 不死循环 | 代码审查：`SensorError::Busy` 返回给调用方，上层 loop 处理 |
| AC7 | `cargo clippy --target thumbv6m-none-eabi --deny warnings` 零警告 | CI 输出 |

## 六、C# IoT → Embassy 核心概念映射

| C# / .NET 概念 | Embassy / Rust 等价 | 关键区别 |
|---------------|---------------------|---------|
| `async Task<T>` / `Task.Run` | `#[embassy_executor::task]` | 无线程池，编译期确定 Future 大小，栈或静态分配 |
| `System.Device.I2c.I2cDevice.WriteReadPartial` | `I2c::write/read/write_read().await` | 异步 I²C，在等待期间 CPU 可执行其他任务（无自旋等待） |
| `System.IO.Ports.SerialPort.Write(bytes)` | `uart_tx.blocking_write(&buf)` | 无 OS 驱动层，直接操作 UART FIFO 寄存器 |
| `await Task.Delay(TimeSpan.FromMilliseconds(80))` | `Timer::after_millis(80).await` | 零栈占用，Future 等待期间 executor 可切换到其他任务 |
| `string` / `StringBuilder` | `heapless::String<N>` | 容量 N 编译期固定，栈分配，无 GC，无 panic（满了返回 Err） |
| `Debug.WriteLine` / `ILogger` | `defmt::info!("{:?}", val)` | 通过 RTT（JTAG/SWD）高效传输，不占 UART 带宽 |
| `Console.WriteLine` | `uart.blocking_write(buf.as_bytes())` | UART TX FIFO 直写，阻塞直到发送完成 |
| `using (var handle = ...)` | RAII + `Drop` trait | 外设句柄在作用域结束自动释放，无需手动 close |
| `AppDomain.UnhandledException` | `#[panic_handler]` | 全局 panic 处理，嵌入式选 `panic-halt`（halt CPU，不展开栈） |
| `Environment.GetEnvironmentVariable` | 不存在 | 嵌入式配置在编译期通过 `const` 或 `build.rs` 注入 |

## 七、Phase 4 学习目标

完成 MoNode 后，掌握以下核心嵌入式 Rust 工程能力：

| 知识点 | 具体体现 |
|--------|---------|
| `#![no_std]` 工程结构 | 无 OS / 无堆的 Cargo 项目配置（`memory.x`、`.cargo/config.toml`） |
| Embassy 外设初始化 | `bind_interrupts!` 宏、`Peripheral` 移动语义、外设单例安全性 |
| Embassy 任务约束 | `#[embassy_executor::task]` 不允许泛型参数，原因与解决方案 |
| I²C 异步驱动 | AHT20 初始化/测量协议、6字节响应解析、整数算术替代浮点 |
| no_std 字符串格式化 | `heapless::String<N>` + `core::fmt::Write` 的 `write!` 宏用法 |
| Flash 尺寸控制 | `opt-level = "z"`、`lto = true`、`codegen-units = 1`、`panic-halt` |
| 调试工具链 | `defmt` + `probe-rs`（RTT 实时日志），`cargo size` 分析 Flash 占用 |
