# ASP.NET Core 依赖注入（DI）系统：源码级深入

---

## 一、先建立核心认知

> **ASP.NET Core 的 DI 容器本质上就是一个"类型字典"：你告诉它"当别人要 IA 接口时，给他 A 类的实例"，它帮你管理创建和生命周期。**

```
你注册：  services.AddSingleton<IServer, KestrelServer>();
         ───────── ─────── ──────────────
          生命周期   接口        实现

你使用：  var server = serviceProvider.GetService<IServer>();
         // 得到 KestrelServer 实例
```

## 三、注册阶段：IServiceCollection 和 ServiceDescriptor

### IServiceCollection 的本质

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection.Abstractions/
//              src/IServiceCollection.cs

// 它就是一个 List！没有任何魔法
public interface IServiceCollection : IList<ServiceDescriptor>
{
    // 没有额外方法，就是继承了 IList<ServiceDescriptor>
}

// 默认实现
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceCollection.cs
public class ServiceCollection : IServiceCollection
{
    private readonly List<ServiceDescriptor> _descriptors = new();

    public int Count => _descriptors.Count;

    // 就是操作一个 List
    public ServiceDescriptor this[int index]
    {
        get => _descriptors[index];
        set => _descriptors[index] = value;
    }

    public void Add(ServiceDescriptor item) => _descriptors.Add(item);
    public bool Remove(ServiceDescriptor item) => _descriptors.Remove(item);
    public void Clear() => _descriptors.Clear();
    // ... 其他 IList 方法
}
```

> **IServiceCollection 就是 `List<ServiceDescriptor>`，这是理解DI系统的第一个关键。** 所有的 `AddSingleton`、`AddScoped`、`AddTransient` 都只是往这个列表里添加元素。

### ServiceDescriptor 的结构

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection.Abstractions/
//              src/ServiceDescriptor.cs

public class ServiceDescriptor
{
    // ========= 核心三要素 =========
    
    public ServiceLifetime Lifetime { get; }     // 生命周期
    public Type ServiceType { get; }             // 服务类型（通常是接口）
    
    // 以下三种方式，三选一，用来描述"怎么创建实例"
    public Type? ImplementationType { get; }     // 方式1：实现类型
    public Func<IServiceProvider, object>? ImplementationFactory { get; }  // 方式2：工厂
    public object? ImplementationInstance { get; }  // 方式3：现成的实例
    
    // 还有一个 .NET 8 新增的
    public object? KeyedImplementationInstance { get; }  // Keyed Services
}

public enum ServiceLifetime
{
    Singleton = 0,  // 整个应用一个实例
    Scoped = 1,     // 每个Scope（每个请求）一个实例
    Transient = 2   // 每次注入都是新实例
}
```

### 三选一的注册方式详解

```csharp
// ========= 方式1：类型注册（最常用）=========
services.AddSingleton<IServer, KestrelServer>();

// 等价于：
services.Add(new ServiceDescriptor(
    serviceType: typeof(IServer),
    implementationType: typeof(KestrelServer),  // 👈 类型
    lifetime: ServiceLifetime.Singleton
));
// DI容器在需要时通过反射调用KestrelServer的构造函数


// ========= 方式2：工厂注册 =========
services.AddScoped<IUserService>(sp =>
{
    var config = sp.GetRequiredService<IConfiguration>();
    var connStr = config.GetConnectionString("Default");
    return new UserService(connStr);
});

// 等价于：
services.Add(new ServiceDescriptor(
    serviceType: typeof(IUserService),
    factory: sp => new UserService(sp.GetRequiredService<IConfiguration>()  // 👈 工厂
                                     .GetConnectionString("Default")),
    lifetime: ServiceLifetime.Scoped
));


// ========= 方式3：实例注册（仅Singleton）=========
var myService = new MyService();
services.AddSingleton<IMyService>(myService);

// 等价于：
services.Add(new ServiceDescriptor(
    serviceType: typeof(IMyService),
    instance: myService   // 👈 已有实例
));
// 生命周期必定是 Singleton，因为实例已经存在
```

### 扩展方法的真面目

你每天调用的 `AddSingleton`、`AddScoped`、`AddTransient` 都只是语法糖：

### Add vs TryAdd vs Replace

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection.Abstractions/
//              src/Extensions/ServiceCollectionDescriptorExtensions.cs

// ========= Add：直接添加，可能重复 =========
services.AddSingleton<IFoo, Foo1>();
services.AddSingleton<IFoo, Foo2>();
// IServiceCollection 现在有两个 IFoo 注册！
// GetService<IFoo>() → 返回 Foo2（最后一个）
// GetServices<IFoo>() → 返回 [Foo1, Foo2]（全部）

// ========= TryAdd：如果已存在就不添加 =========
public static void TryAddSingleton<TService, TImplementation>(
    this IServiceCollection collection)
{
    var descriptor = ServiceDescriptor.Singleton<TService, TImplementation>();
    TryAdd(collection, descriptor);
}

public static void TryAdd(IServiceCollection collection, ServiceDescriptor descriptor)
{
    // 🔥 检查是否已经注册了相同的 ServiceType
    if (!collection.Any(d => d.ServiceType == descriptor.ServiceType))
    {
        collection.Add(descriptor);
    }
    // 如果已存在，什么都不做
}

// ========= Replace：替换第一个匹配的注册 =========
public static IServiceCollection Replace(
    this IServiceCollection collection, ServiceDescriptor descriptor)
{
    var registeredServiceDescriptor = collection.FirstOrDefault(
        s => s.ServiceType == descriptor.ServiceType);
    
    if (registeredServiceDescriptor != null)
    {
        collection.Remove(registeredServiceDescriptor);  // 移除旧的
    }
    
    collection.Add(descriptor);  // 添加新的
    return collection;
}
```

**这三者的区别在框架设计中非常重要：**

```
┌────────────────────────────────────────────────────────────────────┐
│ 场景                              用哪个                           │
├────────────────────────────────────────────────────────────────────┤
│ 框架内部注册默认实现               TryAdd                          │
│ (这样用户可以在之前注册自己的)      如果用户已注册，框架就不覆盖      │
│                                                                    │
│ 注册多个实现（如多个认证Handler）  Add                              │
│ (需要通过GetServices获取全部)      允许重复                         │
│                                                                    │
│ 用户想替换框架的默认实现           Replace                          │
│ (比如替换默认的ILogger实现)        移除旧的，添加新的               │
└────────────────────────────────────────────────────────────────────┘
```

### ServiceProvider 构造函数核心逻辑

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceProvider.cs

public sealed class ServiceProvider : IServiceProvider, IDisposable, IAsyncDisposable
{
    // 🔥 核心数据结构：服务调用站点的字典
    internal ConcurrentDictionary<ServiceIdentifier, ServiceAccessor> _serviceAccessors;

    // 根Scope（Singleton服务存在这里）
    internal ServiceProviderEngineScope Root { get; }

    internal ServiceProvider(IServiceCollection serviceDescriptors, ServiceProviderOptions options)
    {
        Root = new ServiceProviderEngineScope(this, isRootScope: true);

        // 🔥 核心：创建 CallSiteFactory
        // 它负责分析所有 ServiceDescriptor，
        // 为每个服务生成一个"调用站点"（CallSite）
        // CallSite 描述了"如何创建这个服务的实例"
        _callSiteFactory = new CallSiteFactory(serviceDescriptors);

        // 注册自身
        _callSiteFactory.Add(ServiceIdentifier.FromServiceType(typeof(IServiceProvider)),
            new ServiceProviderCallSite());
        _callSiteFactory.Add(ServiceIdentifier.FromServiceType(typeof(IServiceScopeFactory)),
            new ConstantCallSite(typeof(IServiceScopeFactory), Root));

        // 🔥 验证（如果开启了ValidateScopes和ValidateOnBuild）
        if (options.ValidateScopes)
        {
            _callSiteValidator = new CallSiteValidator();
        }

        if (options.ValidateOnBuild)
        {
            // 在Build时就尝试创建所有服务，提前发现问题
            foreach (var serviceDescriptor in serviceDescriptors)
            {
                try
                {
                    ValidateService(serviceDescriptor);
                }
                catch (Exception ex)
                {
                    exceptions ??= new List<Exception>();
                    exceptions.Add(ex);
                }
            }
            if (exceptions != null)
                throw new AggregateException("...", exceptions);
        }
    }
}
```

### CallSite —— DI 系统的核心概念

```
CallSite 是什么？

它是一个"服务创建方案"。DI容器在 Build 时为每个注册的服务
分析出一个 CallSite，描述"这个服务怎么创建"。

运行时解析服务就是"执行CallSite"。
```

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceLookup/ServiceCallSite.cs

internal abstract class ServiceCallSite
{
    public abstract CallSiteKind Kind { get; }
    public ServiceIdentifier ServiceIdentifier { get; }
    public ResultCache Cache { get; }  // 缓存策略（对应生命周期）
}

// CallSite 的种类
internal enum CallSiteKind
{
    Factory,       // 工厂创建     services.AddXxx(sp => new Foo())
    Constructor,   // 构造函数创建  services.AddXxx<IFoo, Foo>()
    Constant,      // 常量         services.AddSingleton(instance)
    IEnumerable,   // 集合         GetServices<IFoo>() → 多个
    ServiceProvider, // IServiceProvider 自身
    Scope,         // IServiceScope
    ServiceScopeFactory  // IServiceScopeFactory
}
```

### 构造函数 CallSite 的创建过程（最常见的情况）

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceLookup/CallSiteFactory.cs

internal sealed class CallSiteFactory : IServiceProviderIsService
{
    private ServiceCallSite CreateConstructorCallSite(
        ResultCache lifetime,
        ServiceIdentifier serviceIdentifier,
        Type implementationType,
        CallSiteChain callSiteChain)
    {
        // 🔥 第1步：找到构造函数
        var constructors = implementationType.GetConstructors();

        ServiceCallSite[] parameterCallSites;

        if (constructors.Length == 0)
        {
            throw new InvalidOperationException(
                $"No constructor for type '{implementationType}'");
        }
        else if (constructors.Length == 1)
        {
            // 只有一个构造函数 → 直接用
            var constructor = constructors[0];
            var parameters = constructor.GetParameters();
            
            // 🔥 第2步：递归地为每个构造函数参数创建 CallSite
            parameterCallSites = new ServiceCallSite[parameters.Length];
            for (var index = 0; index < parameters.Length; index++)
            {
                var parameterType = parameters[index].ParameterType;
                
                // 递归！为参数类型也创建 CallSite
                var callSite = GetCallSite(
                    ServiceIdentifier.FromServiceType(parameterType),
                    callSiteChain);

                if (callSite == null)
                {
                    // 参数类型在DI中没注册 → 检查是否有默认值
                    if (ParameterDefaultValue.TryGetDefaultValue(
                            parameters[index], out var defaultValue))
                    {
                        callSite = new ConstantCallSite(parameterType, defaultValue);
                    }
                    else
                    {
                        throw new InvalidOperationException(
                            $"Unable to resolve service for type '{parameterType}' " +
                            $"while attempting to activate '{implementationType}'.");
                        // 👆 你经常看到的错误信息！
                    }
                }

                parameterCallSites[index] = callSite;
            }

            return new ConstructorCallSite(
                lifetime, serviceIdentifier, constructor, parameterCallSites);
        }
        else
        {
            // 多个构造函数 → 选择"DI容器能满足最多参数"的那个
            // （贪婪匹配策略）
            // ... 详细的选择算法 ...
        }
    }
}
```

## 五、运行阶段：GetService() 的执行过程

### 解析入口

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceProvider.cs

public sealed class ServiceProvider : IServiceProvider
{
    public object? GetService(Type serviceType)
    {
        // 如果容器已经释放，抛异常
        if (_disposed)
            ThrowHelper.ThrowObjectDisposedException();

        var serviceIdentifier = ServiceIdentifier.FromServiceType(serviceType);
        
        // 🔥 获取或创建 ServiceAccessor
        var serviceAccessor = _serviceAccessors.GetOrAdd(
            serviceIdentifier, 
            _createServiceAccessor);  // 延迟创建 CallSite
        
        // 🔥 执行访问器，获取服务实例
        return serviceAccessor(Root);  // Root 是根 Scope
    }
}
```

### ServiceProviderEngineScope —— Scope 的实现

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceLookup/ServiceProviderEngineScope.cs

internal sealed class ServiceProviderEngineScope : 
    IServiceScope, 
    IServiceProvider, 
    IAsyncDisposable,
    IDisposable
{
    // 🔥 Scoped 服务的缓存
    internal Dictionary<ServiceCacheKey, object?> ResolvedServices { get; }
    
    // 🔥 需要 Dispose 的服务列表
    private List<object> _disposables;
    
    // 所属的 ServiceProvider
    internal ServiceProvider RootProvider { get; }
    
    // 是否是根 Scope
    internal bool IsRootScope { get; }

    public object? GetService(Type serviceType)
    {
        // 🔥 关键：通过根 ServiceProvider 解析，但传入当前 Scope
        return RootProvider.GetService(
            ServiceIdentifier.FromServiceType(serviceType), 
            this);  // 👈 传入当前Scope，让Scoped服务缓存在正确的位置
    }

    public void Dispose()
    {
        // 🔥 释放此Scope中所有实现了IDisposable的Scoped/Transient服务
        if (_disposables != null)
        {
            for (var i = _disposables.Count - 1; i >= 0; i--)
            {
                var disposable = _disposables[i];
                if (disposable is IDisposable d)
                {
                    d.Dispose();
                }
            }
        }
        
        // 清空 Scoped 缓存
        ResolvedServices.Clear();
    }
}
```

## 六、三种生命周期的实现原理

### 源码中的缓存逻辑

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceLookup/CallSiteRuntimeResolver.cs

internal sealed class CallSiteRuntimeResolver : CallSiteVisitor<RuntimeResolverContext, object?>
{
    // 🔥 解析 ConstructorCallSite
    protected override object? VisitConstructor(
        ConstructorCallSite callSite, RuntimeResolverContext context)
    {
        // 先解析所有构造函数参数
        object?[] parameterValues;
        if (callSite.ParameterCallSites.Length == 0)
        {
            parameterValues = Array.Empty<object?>();
        }
        else
        {
            parameterValues = new object?[callSite.ParameterCallSites.Length];
            for (var index = 0; index < parameterValues.Length; index++)
            {
                // 递归解析每个参数
                parameterValues[index] = VisitCallSite(
                    callSite.ParameterCallSites[index], context);
            }
        }

        // 🔥 调用构造函数创建实例
        return callSite.ConstructorInfo.Invoke(
            BindingFlags.Default, null, parameterValues, null);
    }

    // 🔥🔥🔥 核心：根据生命周期决定缓存策略
    protected override object? VisitCallSiteMain(
        ServiceCallSite callSite, RuntimeResolverContext context)
    {
        switch (callSite.Cache.Location)
        {
            // ============ Singleton ============
            case CallSiteResultCacheLocation.Root:
                return VisitRootCache(callSite, context);
            
            // ============ Scoped ============
            case CallSiteResultCacheLocation.Scope:
                return VisitScopeCache(callSite, context);
            
            // ============ Transient ============
            case CallSiteResultCacheLocation.Dispose:
                return VisitDisposeCache(callSite, context);
            
            // ============ 无缓存（常量等）============
            case CallSiteResultCacheLocation.None:
                return VisitCallSite(callSite, context);
            
            default:
                throw new ArgumentOutOfRangeException();
        }
    }
}
```

### Singleton 的实现

```csharp
private object? VisitRootCache(ServiceCallSite callSite, RuntimeResolverContext context)
{
    // Singleton = 缓存在 Root Scope 的字典中
    var lockObj = Root; // 用Root Scope作为锁对象
    
    // 🔥 先检查Root Scope的缓存
    if (Root.ResolvedServices.TryGetValue(callSite.Cache.Key, out var resolved))
    {
        return resolved;  // 已经创建过了，直接返回
    }

    lock (lockObj)
    {
        // 双重检查锁
        if (Root.ResolvedServices.TryGetValue(callSite.Cache.Key, out resolved))
        {
            return resolved;
        }

        // 🔥 第一次：创建实例
        resolved = VisitCallSiteMain(callSite, new RuntimeResolverContext
        {
            Scope = Root  // 在Root Scope中创建
        });

        // 🔥 缓存到 Root Scope
        Root.ResolvedServices[callSite.Cache.Key] = resolved;
        
        // 如果实现了 IDisposable，加入Root的释放列表
        if (resolved is IDisposable disposable)
        {
            Root.CaptureDisposable(disposable);
        }
    }

    return resolved;
}
```

### Scoped 的实现

```csharp
private object? VisitScopeCache(ServiceCallSite callSite, RuntimeResolverContext context)
{
    // Scoped = 缓存在当前 Scope 的字典中
    var resolvedServices = context.Scope.ResolvedServices;  // 👈 当前请求的Scope
    
    // 🔥 先检查当前 Scope 的缓存
    if (resolvedServices.TryGetValue(callSite.Cache.Key, out var resolved))
    {
        return resolved;  // 这个请求中已经创建过了，返回同一个实例
    }

    lock (resolvedServices)
    {
        if (resolvedServices.TryGetValue(callSite.Cache.Key, out resolved))
        {
            return resolved;
        }

        // 🔥 第一次（在这个Scope中）：创建实例
        resolved = VisitCallSiteMain(callSite, context);

        // 🔥 缓存到当前 Scope
        resolvedServices[callSite.Cache.Key] = resolved;
        
        // 注册到 Scope 的释放列表
        context.Scope.CaptureDisposable(resolved);
    }

    return resolved;
}
```

### Transient 的实现

```csharp
private object? VisitDisposeCache(ServiceCallSite callSite, RuntimeResolverContext context)
{
    // Transient = 每次都创建新实例，不缓存
    // 🔥 直接创建
    var resolved = VisitCallSiteMain(callSite, context);

    // 但如果实现了 IDisposable，仍然需要在 Scope 释放时释放它
    context.Scope.CaptureDisposable(resolved);

    return resolved;
    // ⚠️ 注意：Transient 服务如果实现了 IDisposable，
    // 它的 Dispose 会在 Scope 释放时被调用
    // 这就是为什么 Transient+IDisposable 可能造成内存泄漏
    // （每个请求都创建新的，但都要等Scope释放才能释放）
}
```

## 八、Scope 验证 —— 防止常见错误

### 什么是 Captive Dependency（俘获依赖）问题

```csharp
// ⚠️ 危险代码！
services.AddSingleton<MySingletonService>();  // Singleton
services.AddScoped<MyScopedService>();         // Scoped

public class MySingletonService
{
    private readonly MyScopedService _scopedService;  // ⚠️ 灾难！
    
    public MySingletonService(MyScopedService scopedService)
    {
        _scopedService = scopedService;
        // Singleton 持有了 Scoped 服务的引用
        // 这个 Scoped 服务永远不会被释放！
        // 而且所有请求共享同一个"Scoped"实例，违反了Scoped语义
    }
}
```

```
正常的 Scoped 行为：
  请求1 → Scoped实例A → 请求结束 → A被释放 ✅
  请求2 → Scoped实例B → 请求结束 → B被释放 ✅

Captive Dependency：
  应用启动 → Singleton创建 → 注入Scoped实例A
  请求1 → 使用Singleton → 里面的A是启动时创建的，不是请求1的 ❌
  请求2 → 使用Singleton → 里面的A还是那个，不是请求2的 ❌
  请求N → 同上 ❌
  
  Scoped实例A 永远不会被释放，变成了事实上的 Singleton
  如果是 DbContext，意味着所有请求共享同一个数据库连接！💀
```

### ValidateScopes 的源码实现

```csharp
}
```

```csharp
private ServiceCallSite? TryCreateOpenGeneric(ServiceIdentifier serviceIdentifier)
{
    var serviceType = serviceIdentifier.ServiceType;
    
    if (serviceType.IsConstructedGenericType)
    {
        // 获取开放泛型定义：IRepository<User> → IRepository<>
        var genericDefinition = serviceType.GetGenericTypeDefinition();
        
        // 在注册表中查找开放泛型注册

            d.ServiceType == genericDefinition);
        
        if (descriptor != null)
        {
            // 关闭泛型：Repository<> + User → Repository<User>
            var closedType = descriptor.ImplementationType!
                .MakeGenericType(serviceType.GetGenericArguments());
            
            // 为 Repository<User> 创建 CallSite
            return CreateConstructorCallSite(
                lifetime, serviceIdentifier, closedType, callSiteChain);
        }
    }
    return null;
}
```

## 十、DI 性能优化 —— Compiled Expressions 和 IL Emit

默认的 `CallSiteRuntimeResolver` 使用反射创建实例，**性能不够好**。

ASP.NET Core 实际使用了两种优化策略：

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection/
//              src/ServiceProvider.cs

// 根据 CallSite 的模式选择不同的引擎
private ServiceAccessor CreateServiceAccessor(ServiceIdentifier serviceIdentifier)
{
    var callSite = _callSiteFactory.GetCallSite(serviceIdentifier, ...);
    
    if (callSite != null)
    {
        // 🔥 对于热路径，使用 IL Emit 或 Expression Tree 编译
        // 避免每次都通过反射调用构造函数
        
        if (_mode == ServiceProviderMode.Dynamic)
        {
            // 第一次使用反射，之后编译成委托
            return scope =>
            {
                var resolved = CallSiteRuntimeResolver.Instance.Resolve(callSite, scope);
                
                // 异步编译优化版本
                ReplaceServiceAccessor(serviceIdentifier, compiledAccessor);
                
                return resolved;
            };
        }
        
        if (_mode == ServiceProviderMode.Expressions)
        {
            // 使用 Expression Tree 编译
            var expression = ExpressionResolverBuilder.Build(callSite);
            return expression.Compile();
        }
        
        if (_mode == ServiceProviderMode.ILEmit)
        {
            // 使用 IL Emit（最快）
            var method = ILEmitResolverBuilder.Build(callSite);
            return method.CreateDelegate<ServiceAccessor>();
        }
    }
    
    return _ => null;
}
```

```
方式               首次解析        后续解析        适用场景
────────────────────────────────────────────────────────────
反射 (Runtime)     慢              慢             调试/开发
Expression Tree    慢(编译)         快             默认模式
IL Emit            慢(编译)         最快           性能关键

Dynamic模式 = 首次用反射（快启动），后台异步编译成IL Emit（后续快执行）
这就是默认的模式 ✅
```

## 十二、自己实现一个极简 DI 容器

为了彻底理解本质，50行代码实现核心机制：

```csharp
// ========== 极简DI容器 ==========
enum Lifetime { Singleton, Scoped, Transient }

record Registration(Type ServiceType, Type ImplType, Lifetime Lifetime);

class MiniContainer : IDisposable
{
    private readonly List<Registration> _registrations = new();
    private readonly Dictionary<Type, object> _singletons = new();
    private readonly Dictionary<Type, object> _scopedInstances = new();
    private readonly MiniContainer? _root;

    public MiniContainer() => _root = null;  // Root容器
    private MiniContainer(MiniContainer root) => (_root, _registrations) = (root, root._registrations);

    // 注册
    public void Register<TService, TImpl>(Lifetime lifetime) where TImpl : TService
        => _registrations.Add(new(typeof(TService), typeof(TImpl), lifetime));

    // 创建Scope
    public MiniContainer CreateScope() => new MiniContainer(this);

    // 解析
    public T Resolve<T>() => (T)Resolve(typeof(T));

    public object Resolve(Type serviceType)
    {
        var reg = _registrations.LastOrDefault(r => r.ServiceType == serviceType)
            ?? throw new Exception($"Service {serviceType.Name} not registered");

        var root = _root ?? this;

        switch (reg.Lifetime)
        {
            case Lifetime.Singleton:
                if (!root._singletons.TryGetValue(serviceType, out var singleton))
                {
                    singleton = CreateInstance(reg.ImplType);
                    root._singletons[serviceType] = singleton;
                }
                return singleton;

            case Lifetime.Scoped:
                if (!_scopedInstances.TryGetValue(serviceType, out var scoped))
                {
                    scoped = CreateInstance(reg.ImplType);
                    _scopedInstances[serviceType] = scoped;
                }
                return scoped;

            case Lifetime.Transient:
                return CreateInstance(reg.ImplType);

            default: throw new NotSupportedException();
        }
    }

    private object CreateInstance(Type type)
    {
        // 找到构造函数
        var ctor = type.GetConstructors().First();
        // 递归解析构造函数参数
        var parameters = ctor.GetParameters()
            .Select(p => Resolve(p.ParameterType))
            .ToArray();
        return ctor.Invoke(parameters);
    }

    public void Dispose()
    {
        foreach (var instance in _scopedInstances.Values.OfType<IDisposable>())
            instance.Dispose();
        _scopedInstances.Clear();

        if (_root == null) // 只有Root容器释放Singleton
        {
            foreach (var instance in _singletons.Values.OfType<IDisposable>())
                instance.Dispose();
        }
    }
}
```

## 十三、常见的 DI 陷阱和最佳实践

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          DI 陷阱速查表                                      │
├──────────────────────┬──────────────────────────────────────────────────────┤
│ 陷阱                  │ 说明                                                │
├──────────────────────┼──────────────────────────────────────────────────────┤
│ Captive Dependency   │ Singleton 注入 Scoped → Scoped变成事实上的Singleton  │
│                      │ 开发环境会抛异常，生产环境默认不检查！⚠️              │
│                      │                                                     │
│ Transient + Dispose  │ Transient服务如果实现IDisposable                     │
│                      │ 每次注入创建新实例，但都等Scope结束才释放              │
│                      │ → 请求期间可能累积大量未释放的实例                     │
│                      │                                                     │
│ 从Root解析Scoped     │ 在Singleton中通过IServiceProvider.GetService          │
│                      │ 获取Scoped服务 → 实际使用Root Scope → 永不释放        │
│                      │ 正确做法：注入IServiceScopeFactory，手动创建Scope     │
│                      │                                                     │
│ 构造函数参数过多      │ 一个类注入10+个服务 → 违反单一职责原则                │
│                      │ 如果构造函数>4个参数，考虑重构                        │
│                      │                                                     │
│ 服务定位器反模式      │ 到处注入IServiceProvider然后GetService               │
│                      │ 隐藏了真实的依赖关系，难以测试                        │
│                      │ 应该直接注入需要的接口                                │
└──────────────────────┴──────────────────────────────────────────────────────┘
```

### 正确处理 Singleton 中需要 Scoped 服务的场景

```csharp
// ❌ 错误：直接注入
public class MySingletonService
{
    private readonly IUserRepository _repo; // Scoped → 💀
    public MySingletonService(IUserRepository repo) => _repo = repo;
}

// ✅ 正确：注入 IServiceScopeFactory
public class MySingletonService
{
    private readonly IServiceScopeFactory _scopeFactory;
    
    public MySingletonService(IServiceScopeFactory scopeFactory)
        => _scopeFactory = scopeFactory;
    
    public async Task DoWork()
    {
        // 手动创建 Scope
        using var scope = _scopeFactory.CreateScope();
        var repo = scope.ServiceProvider.GetRequiredService<IUserRepository>();
        // 使用 repo...
    }
    // scope.Dispose() → repo被正确释放 ✅
}
```

## 十四、检验你的理解

1. **`IServiceCollection` 的本质是什么？**
   （答案：就是 `List<ServiceDescriptor>`，所有 AddXxx 都是往列表里添加元素）

2. **DI容器在 Build 时为每个服务生成了什么？运行时解析服务就是在做什么？**
   （答案：生成 CallSite 树。运行时就是遍历 CallSite 树，根据生命周期决定是创建新实例还是返回缓存实例）

3. **Scoped 服务是缓存在哪里的？什么时候被释放？**
   （答案：缓存在 ServiceProviderEngineScope.ResolvedServices 字典中。在 Scope.Dispose() 时释放。对于HTTP请求，就是在 HostingApplication.DisposeContext() 中）

4. **为什么 ASP.NET Core 的 DI 不支持属性注入？**
   （答案：设计选择。构造函数注入使依赖关系显式可见、不可变、编译时可检查。属性注入隐藏依赖、允许部分初始化的对象存在、容易遗漏。这是有意为之。如果需要属性注入，可以替换为 Autofac 等第三方容器）

5. **OpenIddict 的 Manager 和 Store 为什么必须是 Scoped？如果注册为 Singleton 会怎样？**
   （答案：因为它们依赖 EF Core 的 DbContext（Scoped）。如果注册为 Singleton，就会形成 Captive Dependency —— 所有请求共享同一个 DbContext 实例，导致并发问题、数据不一致、连接泄漏。开发环境 ValidateScopes=true 会直接抛异常）

6. **注册了多个同类型服务时，GetService 和 GetServices 分别返回什么？**
   （答案：GetService 返回最后注册的那个。GetServices 返回所有注册的实例集合。OpenIddict 利用 GetServices 来获取所有 Handler 并按顺序执行）
