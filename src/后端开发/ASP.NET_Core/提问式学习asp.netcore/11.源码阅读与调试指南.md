# ASP.NET Core 源码阅读与调试指南

---

## 一、核心认知

> **阅读源码不是"从头读到尾"，而是"带着问题，沿着执行路径，逐层深入"。你不需要读懂每一行，只需要理解关键路径上的关键决策。**

```
源码阅读的三个层次：

┌──────────────────────────────────────────────────────────────────────────┐
│                                                                          │
│  Level 1：知道"入口在哪"                                                 │
│  → 能找到某个功能的起始代码                                               │
│  → 例如：认证中间件的入口是 AuthenticationMiddleware.Invoke()            │
│                                                                          │
│  Level 2：理解"关键路径"                                                 │
│  → 能追踪一个请求经过的核心代码路径                                       │
│  → 例如：Token请求从Kestrel到OpenIddict处理的完整链路                    │
│                                                                          │
│  Level 3：掌握"设计决策"                                                 │
│  → 能理解为什么这样设计，有什么替代方案                                   │
│  → 例如：为什么DFA而不是正则匹配路由                                     │
│                                                                          │
│  目标：达到 Level 2，核心模块达到 Level 3                                │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

## 四、调试技巧 —— 追踪框架内部执行

### 4.1 关键断点位置

```csharp
// ═══════════════════════════════════════════════════
// 🎯 追踪一个HTTP请求的完整生命周期
// 在以下位置设置断点
// ═══════════════════════════════════════════════════

// ── 1. 请求进入应用 ──
// 📁 HostingApplication.cs
public Context CreateContext(IFeatureCollection contextFeatures)
// 🎯 断点：看到每个请求的起点
// 检查：contextFeatures 中有哪些 Feature
//       Request 的 Method, Path, Headers

// ── 2. 中间件管道执行 ──
// 📁 AuthenticationMiddleware.cs
public async Task Invoke(HttpContext context)
// 🎯 断点：认证开始
// 检查：context.Request.Path
//       context.User（认证前应该是空的）

// ── 3. 认证Handler选择 ──
// 📁 AuthenticationService.cs
public async Task<AuthenticateResult> AuthenticateAsync(
    HttpContext context, string? scheme)
// 🎯 断点：看选择了哪个认证方案
// 检查：scheme 值是什么
//       handler 是什么类型

// ── 4. OpenIddict请求拦截 ──
// 📁 OpenIddictServerAspNetCoreHandler.cs
public async Task<bool> HandleRequestAsync()
// 🎯 断点：OpenIddict是否拦截了此请求
// 检查：返回值 true=拦截，false=不拦截
//       _transaction 中的请求信息

// ── 5. OpenIddict事件分发 ──
// 📁 OpenIddictServerDispatcher.cs
public async ValueTask DispatchAsync<TContext>(TContext context)
// 🎯 断点：事件处理链的入口
// 检查：TContext 的类型（是Token请求还是Authorize请求）
//       handlers 列表中有哪些处理器
//       每个handler执行后context的状态变化

// ── 6. Token签发 ──
// 📁 OpenIddictServerHandlers.Exchange.cs
// 类名: HandleAuthorizationCodeExchange
public async ValueTask HandleAsync(HandleTokenRequestContext context)
// 🎯 断点：授权码换Token的核心逻辑
// 检查：context.Request（请求参数）
//       context.Principal（用户信息）
//       生成的Token内容

// ── 7. 路由匹配 ──
// 📁 EndpointRoutingMiddleware.cs → DfaMatcher.cs
public Task Invoke(HttpContext httpContext)
// 🎯 断点：路由匹配过程
// 检查：匹配到的Endpoint
//       RouteValues

// ── 8. 授权检查 ──
// 📁 AuthorizationMiddleware.cs
public async Task Invoke(HttpContext context)
// 🎯 断点：授权过程
// 检查：endpoint 的 Metadata
//       authorizeData
//       授权结果

// ── 9. 请求结束 ──
// 📁 HostingApplication.cs
public void DisposeContext(Context context, Exception? exception)
// 🎯 断点：请求清理
// 检查：exception 是否有异常
//       context.HttpContext.Response.StatusCode
//       耗时
```

### 4.2 条件断点

```csharp
// 在框架代码中设置条件断点，只在特定条件下命中
// 避免被大量不相关的请求打断

// ═══════════ Visual Studio / Rider ═══════════

// 在 AuthenticationMiddleware.Invoke() 设置断点
// 右键断点 → Conditions:
context.Request.Path.StartsWithSegments("/connect/token")
// 只有 Token 请求才命中

// 在 HostingApplication.CreateContext() 设置断点
// 条件:
contextFeatures.Get<IHttpRequestFeature>()?.Path == "/connect/authorize"
// 只有授权请求才命中

// 在 OpenIddictServerDispatcher.DispatchAsync() 设置断点
// 条件:
typeof(TContext).Name.Contains("ValidateTokenRequest")
// 只有验证Token请求事件才命中

// ═══════════ Hit Count ═══════════
// 右键断点 → Hit Count → "break when hit count equals 3"
// 第3次命中时才断下来
// 用于跳过前几次不相关的调用

// ═══════════ Action (Tracepoint) ═══════════
// 右键断点 → Actions → "Log a message"
// 消息: "Auth middleware: Path={context.Request.Path}, User={context.User?.Identity?.Name}"
// ✅ Continue execution（不暂停，只打印）
// 🔥 比修改源码加日志更方便！
```

### 4.3 Watch 窗口的高级用法

```csharp
// ═══════════ 调试时在 Watch 窗口中查看复杂对象 ═══════════

// 查看当前请求的所有信息
context.Request.Method
context.Request.Path.Value
context.Request.Headers["Authorization"].ToString()
context.Request.ContentType
context.Connection.RemoteIpAddress?.ToString()

// 查看认证结果
context.User?.Identity?.IsAuthenticated
context.User?.Identity?.AuthenticationType
context.User?.Claims.Select(c => $"{c.Type}={c.Value}").ToArray()

// 查看路由匹配结果
context.GetEndpoint()?.DisplayName
context.GetEndpoint()?.Metadata.Select(m => m.GetType().Name).ToArray()
context.Request.RouteValues.Select(kv => $"{kv.Key}={kv.Value}").ToArray()

// 查看 DI Scope
context.RequestServices.GetType().Name
((ServiceProvider)context.RequestServices)._disposed

// 查看 OpenIddict 上下文
context.Features.Get<OpenIddictServerAspNetCoreFeature>()?.Transaction?.Request

// 查看 Feature 集合中有哪些 Feature
context.Features.Select(f => f.Key.Name).ToArray()

// ═══════════ Immediate Window（即时窗口）═══════════
// 在调试暂停时，在即时窗口中执行代码

// 查看所有已注册的认证方案
? context.RequestServices
    .GetRequiredService<IAuthenticationSchemeProvider>()
    .GetAllSchemesAsync().Result
    .Select(s => $"{s.Name} → {s.HandlerType.Name}")
    .ToArray()

// 查看所有已注册的服务
? ((ServiceProvider)context.RequestServices)
    .GetType()
    .GetField("_descriptors", BindingFlags.NonPublic | BindingFlags.Instance)
    ?.GetValue(context.RequestServices)

// 手动调用认证
? await context.AuthenticateAsync("Bearer")
```

### 4.4 调用栈分析

```
当断点命中时，Call Stack 窗口是最重要的工具

一个 Token 请求的典型调用栈（从上到下）：

你的代码：
  AuthorizationController.Exchange()                    ← 你的Controller
  
ASP.NET Core MVC：
  ControllerActionInvoker.InvokeActionMethodAsync()     ← Action执行
  ControllerActionInvoker.InvokeNextActionFilterAsync()  ← Filter管道
  ResourceInvoker.InvokeAsync()                          ← 资源调用器
  
ASP.NET Core 路由/端点：
  EndpointMiddleware.Invoke()                            ← 端点执行
  AuthorizationMiddleware.Invoke()                       ← 授权检查
  AuthenticationMiddleware.Invoke()                      ← 认证检查
  EndpointRoutingMiddleware.Invoke()                     ← 路由匹配
  ExceptionHandlerMiddlewareImpl.Invoke()                ← 异常处理
  ForwardedHeadersMiddleware.Invoke()                    ← 转发头
  
Hosting 层：
  HostingApplication.ProcessRequestAsync()               ← 管道入口
  
Kestrel HTTP层：
  Http1Connection.ProcessRequestsAsync()                 ← HTTP/1.1处理循环
  HttpConnection.ProcessRequestsAsync()                  ← HTTP协议分发
  HttpConnectionMiddleware.OnConnectionAsync()            ← 连接中间件
  
Kestrel 传输层：
  SocketConnection.DoReceive()                           ← Socket读取
  
.NET Runtime：
  ThreadPool.WorkerThread()                              ← 线程池

🔥 从调用栈可以看到：
  - 请求经过了哪些中间件
  - 中间件的执行顺序
  - 当前代码在整个管道中的位置
  - 是否经过了认证/授权
```

```csharp
// 创建一个诊断中间件，在开发环境中记录所有关键信息

public class DiagnosticMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<DiagnosticMiddleware> _logger;

    public DiagnosticMiddleware(RequestDelegate next, ILogger<DiagnosticMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task Invoke(HttpContext context)
    {
        var requestId = Activity.Current?.Id ?? context.TraceIdentifier;
        
        // ══════════ 请求开始 ══════════
        _logger.LogDebug(
            "[{RequestId}] ══ REQUEST ══ {Method} {Path}{Query}",
            requestId,
            context.Request.Method,
            context.Request.Path,
            context.Request.QueryString);
        
        // 记录关键请求头
        if (context.Request.Headers.TryGetValue("Authorization", out var auth))
        {
            var authValue = auth.ToString();
            // 只显示前20个字符，不暴露完整Token
            var truncated = authValue.Length > 30 
                ? authValue[..30] + "..." 
                : authValue;
            _logger.LogDebug("[{RequestId}] Authorization: {Auth}", requestId, truncated);
        }
        
        // 记录Content-Type（对OAuth请求很重要）
        if (context.Request.ContentType != null)
        {
            _logger.LogDebug("[{RequestId}] Content-Type: {CT}", 
                requestId, context.Request.ContentType);
        }

        var sw = Stopwatch.StartNew();
        
        try
        {
            await _next(context);
        }
        finally
        {
            sw.Stop();
            
            // ══════════ 请求结束 ══════════
            
            // Endpoint 信息
            var endpoint = context.GetEndpoint();
            _logger.LogDebug(
                "[{RequestId}] Endpoint: {Endpoint}",
                requestId,
                endpoint?.DisplayName ?? "(none)");
            
            // 认证信息
            _logger.LogDebug(
                "[{RequestId}] User: Authenticated={IsAuth}, Name={Name}, Claims={Claims}",
                requestId,
                context.User?.Identity?.IsAuthenticated ?? false,
                context.User?.Identity?.Name ?? "(anonymous)",
                context.User?.Claims?.Count() ?? 0);
            
            // 响应信息
            var level = context.Response.StatusCode >= 400 
                ? LogLevel.Warning 
                : LogLevel.Debug;
            
            _logger.Log(level,
                "[{RequestId}] ══ RESPONSE ══ {StatusCode} in {Elapsed}ms",
                requestId,
                context.Response.StatusCode,
                sw.ElapsedMilliseconds);
        }
    }
```

```csharp
// 📁 src/Security/Authentication/Core/src/AuthenticationMiddleware.cs

public class AuthenticationMiddleware
{
    public async Task Invoke(HttpContext context)
    {
        context.Features.Set<IAuthenticationFeature>(new AuthenticationFeature
        {
            OriginalPath = context.Request.Path,
            OriginalPathBase = context.Request.PathBase
        });

        // 🔍 获取默认认证方案
        var defaultAuthenticate = await Schemes.GetDefaultAuthenticateSchemeAsync();
        // defaultAuthenticate = null 或 "Cookies" 或你配置的默认方案

        if (defaultAuthenticate != null)
        {
            var result = await context.AuthenticateAsync(defaultAuthenticate.Name);
            if (result?.Principal != null)
            {
                context.User = result.Principal;
            }
            if (result?.Succeeded ?? false)
            {
                // ...
            }
        }

        // 🔍 遍历所有 IAuthenticationRequestHandler
        var handlers = context.RequestServices
            .GetRequiredService<IAuthenticationHandlerProvider>();
        
        foreach (var scheme in await Schemes.GetRequestHandlerSchemesAsync())
        // 🔍 这里返回所有实现了 IAuthenticationRequestHandler 的方案
        // OpenIddict.Server.AspNetCore 就是其中一个
        {
            var handler = await handlers.GetHandlerAsync(context, scheme.Name)
                as IAuthenticationRequestHandler;
            
            if (handler != null && await handler.HandleRequestAsync())
            // 🔍 如果返回 true → 短路，不调用 _next
            // OpenIddict 在处理 /connect/token 时返回 true
            {
                return;  // ← 短路！不再执行后续中间件
            }
        }

        await _next(context);  // 如果没有Handler短路，继续管道
    }
}
```

```csharp
// ══════════════════════════════════════════════════════════════
// 第2步：进入 OpenIddictServerAspNetCoreHandler
// ══════════════════════════════════════════════════════════════

// 📁 openiddict-core/src/OpenIddict.Server.AspNetCore/
//    OpenIddictServerAspNetCoreHandler.cs

public sealed class OpenIddictServerAspNetCoreHandler : AuthenticationHandler<OpenIddictServerAspNetCoreOptions>,
    IAuthenticationRequestHandler
{
    public async Task<bool> HandleRequestAsync()
    {
        // 🔍 创建一个 Transaction（事务）来跟踪此请求
        var transaction = await CreateTransactionAsync();
        // transaction 包含了整个请求的上下文

        try
        {
            // 🔍 判断请求路径是否匹配 OpenIddict 端点
            var context = new ProcessRequestContext(transaction);
            await _dispatcher.DispatchAsync(context);
            // 内部会匹配路径：
            // /connect/token → Token Endpoint
            // /connect/authorize → Authorization Endpoint
            // /.well-known/openid-configuration → Configuration Endpoint
            // /connect/userinfo → Userinfo Endpoint
            // etc.

            if (context.IsRequestHandled)
            {
                return true;   // 🔍 OpenIddict 处理了此请求
            }

            if (context.IsRequestSkipped)
            {
                return false;  // 🔍 Passthrough 模式，交给后续中间件
            }

            if (context.IsRejected)
            {
                // 🔍 请求被拒绝，需要返回错误响应
                var notification = new ProcessErrorContext(transaction)
                {
                    Error = context.Error ?? "server_error",
                    ErrorDescription = context.ErrorDescription
                };
                await _dispatcher.DispatchAsync(notification);
                return true;
            }

            return false;
        }
        finally
        {
            // 🔍 将 transaction 存到 HttpContext 的 Feature 中
            // 后续的 Controller 可以通过 
            // HttpContext.GetOpenIddictServerRequest() 访问
            Context.Features.Set(new OpenIddictServerAspNetCoreFeature
            {
                Transaction = transaction
            });
        }
    }
}
```

```csharp
// ══════════════════════════════════════════════════════════════
// 第4步：Token 签发
// ══════════════════════════════════════════════════════════════

// ── 事件4: HandleTokenRequestContext ──

// 🔍 有两种模式：

// 模式A: 非Passthrough（OpenIddict自己处理）
// OpenIddict 内置 Handler 自动签发 Token
// HandleAuthorizationCodeExchange:
//   → 从授权码恢复 ClaimsPrincipal
//   → 创建 Access Token
//   → 创建 ID Token
//   → 创建 Refresh Token（如果配置了）

// 模式B: Passthrough（交给你的Controller处理）
// 如果配置了 options.UseAspNetCore().EnableTokenEndpointPassthrough()
// → context.SkipRequest()
// → Handler 返回 false
// → AuthenticationMiddleware 继续执行 _next
// → 路由匹配到你的 Controller
// → 你在 Controller 中自定义 Token 签发逻辑

// 📁 OpenIddictServerHandlers.Exchange.cs（非Passthrough模式）

public sealed class HandleAuthorizationCodeExchange : IOpenIddictServerHandler<HandleTokenRequestContext>
{
    public async ValueTask HandleAsync(HandleTokenRequestContext context)
    {
        if (context.EndpointType != OpenIddictServerEndpointType.Token)
            return;
        
        if (!context.Request.IsAuthorizationCodeGrantType())
            return;
        
        // 🔍 从验证阶段恢复的 Principal
        var principal = context.Principal!;
        
        // 🔍 签发 Access Token
        // 内部使用 SecurityTokenHandler 创建 JWT
        // 使用配置的 SigningCredentials 签名
        // 设置 Claims: sub, aud, iss, exp, scope, ...
        
        // 🔍 签发 ID Token（如果请求了 openid scope）
        // 包含用户身份信息
        
        // 🔍 签发 Refresh Token（如果配置了）
        // 生成引用Token或自包含Token
        // 存入数据库

        context.HandleRequest();
        // → 标记请求已处理，终止Handler链
    }
}
```

```csharp
// 📁 DefaultAuthorizationService.cs

public async Task<AuthorizationResult> AuthorizeAsync(
    ClaimsPrincipal user, object? resource, IEnumerable<IAuthorizationRequirement> requirements)
{
    var authContext = new AuthorizationHandlerContext(requirements, user, resource);
    
    foreach (var handler in _handlers)
    {
        await handler.HandleAsync(authContext);
        // 🔍 断点：每个Handler执行后
        //   - authContext.HasSucceeded?
        //   - authContext.PendingRequirements → 哪些Requirement还没被满足？
        //   - authContext.HasFailed?
    }
    
    // 🔍 断点：最终结果
    if (authContext.HasSucceeded)
        return AuthorizationResult.Success();
    else
        return AuthorizationResult.Failed(
            AuthorizationFailure.Failed(authContext.PendingRequirements));
    // PendingRequirements 告诉你哪些需求没被满足
}

// 步骤4：检查 Claims
// 在 Watch 窗口中：
context.User.Claims.Select(c => $"{c.Type} = {c.Value}").ToArray()
// 常见问题：
// - Role claim 的类型不匹配（ClaimTypes.Role vs "role"）
// - Scope claim 缺失
// - 用户没有所需的 claim
```

```csharp

// 例如：AddAuthentication() 注册了什么？

public static AuthenticationBuilder AddAuthentication(
    this IServiceCollection services)
{
    services.AddAuthenticationCore();           // 核心服务
    services.AddDataProtection();               // 数据保护（Cookie加密等）
    services.AddWebEncoders();                  // URL/HTML编码
    
    services.TryAddSingleton<ISystemClock, SystemClock>();
    
    return new AuthenticationBuilder(services); // 返回Builder继续链式配置
}

public static IServiceCollection AddAuthenticationCore(
    this IServiceCollection services)
{
    services.TryAddScoped<IAuthenticationService, DefaultAuthenticationService>();
    services.TryAddSingleton<IClaimsTransformation, NoopClaimsTransformation>();
    services.TryAddScoped<IAuthenticationHandlerProvider, AuthenticationHandlerProvider>();
    services.TryAddSingleton<IAuthenticationSchemeProvider, AuthenticationSchemeProvider>();
    
    return services;
}

// 例如：AddOpenIddict() 注册了什么？
// 📁 openiddict-core/src/OpenIddict.Server/OpenIddictServerBuilder.cs

public static OpenIddictBuilder AddServer(this OpenIddictBuilder builder, 
    Action<OpenIddictServerBuilder> configuration)
{
    // 注册核心服务
    builder.Services.TryAddScoped<IOpenIddictServerDispatcher, OpenIddictServerDispatcher>();
    builder.Services.TryAddScoped<IOpenIddictServerFactory, OpenIddictServerFactory>();

    {

    }
    
    // 注册 Options
    builder.Services.TryAddSingleton(
        new OptionsWrapper<OpenIddictServerOptions>(new OpenIddictServerOptions()));
    
    // 执行用户配置
    var serverBuilder = new OpenIddictServerBuilder(builder.Services);
    configuration(serverBuilder);
    
    return builder;
}
```

```csharp
// 在 OpenIddict 事件处理中创建自定义 Span

public class OpenIddictTracingHandler<TContext> : IOpenIddictServerHandler<TContext>
    where TContext : BaseContext
{
    private static readonly ActivitySource _activitySource = 
        new("OpenIddict.Server");

    public async ValueTask HandleAsync(TContext context)
    {
        using var activity = _activitySource.StartActivity(
            $"openiddict.{typeof(TContext).Name}",
            ActivityKind.Internal);
        
        if (activity != null)
        {
            // 添加标签
            activity.SetTag("openiddict.event_type", typeof(TContext).Name);
            
            if (context is BaseRequestContext requestContext)
            {
                activity.SetTag("openiddict.client_id", 
                    requestContext.Transaction?.Request?.ClientId);
                activity.SetTag("openiddict.grant_type", 
                    requestContext.Transaction?.Request?.GrantType);
                activity.SetTag("openiddict.is_rejected", 
                    requestContext.IsRejected);
            }

            if (context is BaseRequestContext { IsRejected: true } rejected)
            {
                activity.SetStatus(ActivityStatusCode.Error);
                activity.SetTag("openiddict.error", 
                    rejected.Transaction?.Response?.Error);
                activity.SetTag("openiddict.error_description", 
                    rejected.Transaction?.Response?.ErrorDescription);
            }
        }
    }
}
```

```csharp
// SSO 的授权流程依赖 Cookie
// Cookie 问题会导致登录循环、状态丢失

// ═══════ Cookie 调试中间件 ═══════

app.Use(async (context, next) =>
{
    // 记录请求中的所有Cookie
    var requestCookies = context.Request.Cookies
        .Select(c => $"{c.Key}={c.Value[..Math.Min(20, c.Value.Length)]}...")
        .ToList();
    
    Console.WriteLine($"Request Cookies: [{string.Join(", ", requestCookies)}]");
    
    await next(context);
    
    // 记录响应中设置的Cookie
    var responseCookies = context.Response.Headers
        .Where(h => h.Key.Equals("Set-Cookie", StringComparison.OrdinalIgnoreCase))
        .SelectMany(h => h.Value.Select(v => v))
        .ToList();
    
    foreach (var cookie in responseCookies)
    {
        Console.WriteLine($"Set-Cookie: {cookie}");
    }
});

// ═══════ 常见 Cookie 问题 ═══════
//
// 1. SameSite 问题（跨域SSO最常见）
//    症状: 浏览器不发送Cookie，登录循环
//    原因: SameSite=Lax 阻止了跨站POST请求携带Cookie
//    解决: 
//    options.Cookie.SameSite = SameSiteMode.None;
//    options.Cookie.SecurePolicy = CookieSecurePolicy.Always;
//    // SameSite=None 必须配合 Secure
//
// 2. Domain 问题
//    症状: 子域名之间Cookie不共享
//    原因: Cookie 默认只对设置它的域名有效
//    解决: options.Cookie.Domain = ".example.com";
//    // 前缀点表示所有子域名共享
//
// 3. Path 问题
//    症状: 某些路径下Cookie丢失
//    原因: Cookie 的 Path 设置不正确
//    解决: options.Cookie.Path = "/";
//
// 4. Secure 问题
//    症状: HTTP环境下Cookie不工作
//    原因: Secure=true 的Cookie只在HTTPS下发送
//    解决: 开发环境用 CookieSecurePolicy.SameAsRequest
//
// 5. 反向代理 + Cookie
//    症状: Nginx → Kestrel，Cookie Secure 标志不对
//    原因: Kestrel 看到的是 HTTP（代理后的）
//    解决: UseForwardedHeaders() 让 Kestrel 知道原始协议是 HTTPS
```

```csharp
            StatusCode = response.StatusCode,
            Body = await response.Content.ReadAsStringAsync()
        };
    });

    var results = await Task.WhenAll(tasks);

    // 所有请求都应该成功
    var failures = results.Where(r => r.StatusCode != HttpStatusCode.OK).ToList();
    
    if (failures.Any())
    {
        var details = string.Join("\n", failures.Select(f => 
            $"Request {f.Index}: {f.StatusCode} - {f.Body}"));
        Assert.Fail($"Concurrent failures:\n{details}");
    }
}

// ═══════ 模拟授权码重放攻击 ═══════

[Fact]
public async Task AuthorizationCode_Cannot_Be_Used_Twice()
{
    var authCode = await GetAuthorizationCodeAsync();

    // 并发使用同一个授权码
    var task1 = ExchangeCodeAsync(authCode);
    var task2 = ExchangeCodeAsync(authCode);

    var results = await Task.WhenAll(task1, task2);

    // 应该只有一个成功
    var successes = results.Count(r => r.StatusCode == HttpStatusCode.OK);
    var failures = results.Count(r => r.StatusCode != HttpStatusCode.OK);
    
    successes.Should().Be(1, "授权码只能使用一次");
    failures.Should().Be(1, "第二次使用应该失败");
    
    // 失败的那个应该返回 invalid_grant
    var failedResult = results.First(r => r.StatusCode != HttpStatusCode.OK);
    var error = await failedResult.Content.ReadFromJsonAsync<JsonElement>();
    error.GetProperty("error").GetString().Should().Be("invalid_grant");
}
```

## 十六、检验你的理解

**1. 你正在调试一个问题：POST /connect/token 返回 401。你会在哪些地方设置断点？按什么顺序排查？**

（答案：① `AuthenticationMiddleware.Invoke()` — 确认中间件被执行，检查请求路径和头部。② `OpenIddictServerAspNetCoreHandler.HandleRequestAsync()` — 确认 OpenIddict 是否拦截了此请求，如果返回 false 说明路径不匹配。③ `OpenIddictServerDispatcher.DispatchAsync()` — 追踪事件链，看是哪个 Validate Handler 拒绝了请求。④ 具体的 Validate Handler（如 `ValidateClientId`, `ValidateClientSecret`）— 看具体的验证失败原因。⑤ 检查请求的 Content-Type 是否是 `application/x-www-form-urlencoded`（常被忽略）。⑥ 检查 ForwardedHeaders 是否正确配置（Issuer 不匹配可能导致 Token 验证失败）。）

**2. Source Link 调试的原理是什么？为什么你可以步进到 NuGet 包的源码？**

（答案：Source Link 在 NuGet 包的 PDB（调试符号）文件中嵌入了源码的 Git 仓库 URL 和 commit hash。当调试器需要显示某个方法的源码时：① 从 PDB 中读取源码位置信息（`https://github.com/dotnet/aspnetcore/blob/{commit}/src/...`）。② 从 Microsoft Symbol Servers 下载对应的 PDB。③ 从 GitHub 下载对应 commit 的源码文件。④ 调试器将断点位置映射到下载的源码上。所以你不需要克隆整个仓库，调试器按需下载。前提是 NuGet 包在编译时启用了 Source Link，ASP.NET Core 和 OpenIddict 都已启用。）

**3. 在生产环境中，ThreadPool Queue Length 持续 > 0 意味着什么？对 SSO 服务有什么影响？如何排查？**

（答案：ThreadPool Queue Length > 0 说明线程池所有线程都在忙，新的工作项必须排队等待。对SSO的影响：① Token 请求延迟急剧增加（等队列）。② 授权码可能过期（等待时间超过授权码有效期）。③ 客户端超时重试导致雪崩。排查：① `dotnet-trace` 采集 CPU profile，看线程在做什么。② 最常见原因是同步阻塞调用（`.Result`、`.Wait()`、`Thread.Sleep`）——在异步代码中阻塞会占用线程池线程。③ CPU 密集操作（如 BCrypt 高 cost factor、大量 RSA 签名）。④ 连接池耗尽（数据库连接、HttpClient 连接）导致线程等待。解决：消除同步阻塞、降低加密强度、增加连接池大小、横向扩展。）

**4. 如何在不重启应用的情况下，验证 OpenIddict 注册了哪些事件处理器？**

（答案：① 在运行中的应用添加一个诊断端点：通过 DI 获取所有 `IOpenIddictServerHandler<T>` 实例并列出。② 在调试器的即时窗口中执行：`context.RequestServices.GetServices<IOpenIddictServerHandler<ValidateTokenRequestContext>>().Select(h => h.GetType().Name).ToArray()`。③ 启用 OpenIddict Trace 日志：`"OpenIddict.Server": "Trace"`，日志会输出每个被调用的 Handler 名称和顺序。④ 使用 OpenTelemetry 自定义 Span 追踪每个 Handler 的执行。）

**5. 多实例部署 SSO 服务器时，签名密钥不一致会导致什么问题？如何排查和解决？**

（答案：问题：实例A用密钥1签发Token，请求被负载均衡到实例B，实例B用密钥2验证 → 签名不匹配 → 401。排查：① 检查 `/.well-known/jwks` 端点在不同实例上的返回值是否一致。② 在Token中检查 `kid`（Key ID）是否在所有实例的 JWKS 中。③ 解密 Token 看 header 中的 `kid` 和 `alg`。解决：① 将签名密钥存储在共享位置（数据库、Redis、Azure Key Vault）。② OpenIddict 支持 `AddEncryptionCertificate` / `AddSigningCertificate` 从文件或证书库加载。③ 在 Kubernetes 中使用 Secret 挂载相同的证书文件。④ 密钥轮换时，JWKS 端点同时包含新旧密钥，给客户端缓存刷新的时间。）
