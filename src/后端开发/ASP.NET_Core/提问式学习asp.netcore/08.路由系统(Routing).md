# ASP.NET Core 路由系统（Routing）：源码级深入

---

## 一、核心认知

> **路由系统的本质就是一个"URL模式匹配器"：把请求的URL路径映射到一个具体的处理函数（Endpoint）。**
>
> 但ASP.NET Core的路由不只是匹配URL，它还把匹配结果（Endpoint）作为元数据载体，让认证、授权等中间件可以在执行前就知道"这个请求要到哪里去"。

```
请求: GET /api/users/123

路由表中注册的模式：
  /api/users/{id}        → UsersController.GetUser(int id)
  /api/users             → UsersController.GetAll()
  /api/articles/{id}     → ArticlesController.GetArticle(int id)
  /connect/token         → OpenIddict Token Endpoint
  /connect/authorize     → AuthorizationController.Authorize()

路由匹配：
  /api/users/123 匹配 /api/users/{id}  ✅
  路由参数: id = "123"
  
  Endpoint = {
      RequestDelegate: UsersController.GetUser(123),
      Metadata: [ [Authorize(Policy="read:users")], [HttpGet] ]
  }
```

**Endpoint = RequestDelegate + Metadata，这是理解路由系统的关键。**

```
一个 RouteEndpoint 的完整结构：

RouteEndpoint
├── RoutePattern: "/api/users/{id:int}"
├── Order: 0
├── DisplayName: "UsersController.GetUser (MyApp)"
├── RequestDelegate: (HttpContext ctx) => { /* 调用Controller Action */ }
└── Metadata:
    ├── [HttpGetAttribute]                    → HTTP方法约束
    ├── [AuthorizeAttribute(Policy="read:users")]  → 授权要求
    ├── [ProducesResponseType(200)]           → Swagger信息
    ├── ControllerActionDescriptor            → MVC描述信息
    │   ├── ControllerName: "Users"
    │   ├── ActionName: "GetUser"
    │   ├── Parameters: [{ Name: "id", Type: int }]
    │   └── Filters: [...]
    └── RouteNameMetadata("GetUserById")      → 路由名称
```

## 四、UseRouting() 和 UseEndpoints() —— 两步机制

### 4.1 为什么要分成两步？

```
❌ 如果路由匹配和执行合在一起：

请求 → UseRouting+Execute → 已经开始执行Controller了
                            认证和授权根本来不及检查！

✅ 分成两步：

请求 → UseRouting()     → 只匹配，不执行
           │                把 Endpoint 存入 HttpContext
           ▼
       UseAuthentication() → 读取 Endpoint 的 [Authorize] Metadata
           │                  知道这个端点需要什么认证方案
           ▼
       UseAuthorization()  → 读取 Endpoint 的 [Authorize] Metadata
           │                  检查用户是否满足授权要求
           ▼
       UseEndpoints()      → 执行 Endpoint.RequestDelegate
                              这时候认证授权已经完成了

这就是为什么中间件顺序如此重要：
  UseRouting()         ← 必须在最前面
  UseAuthentication()  ← 在 Routing 之后
  UseAuthorization()   ← 在 Authentication 之后
  MapControllers()     ← 在最后面
```

### 4.3 EndpointRoutingMiddleware —— 路由匹配中间件

```csharp
// 📁 源码位置: src/Http/Routing/src/EndpointRoutingMiddleware.cs

internal sealed class EndpointRoutingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly EndpointDataSource _endpointDataSource;
    private Task<Matcher>? _initializationTask;

    public EndpointRoutingMiddleware(
        RequestDelegate next,
        IEndpointRouteBuilder endpointRouteBuilder)
    {
        _next = next;
        _endpointDataSource = new CompositeEndpointDataSource(
            endpointRouteBuilder.DataSources);
    }

    public Task Invoke(HttpContext httpContext)
    {
        // 🔥 第1步：检查是否已经有 Endpoint（某些中间件可能已经设置了）
        var endpoint = httpContext.GetEndpoint();
        if (endpoint != null)
        {
            // 已经有了 → 跳过匹配
            Log.MatchSkipped(_logger, endpoint);
            return _next(httpContext);
        }

        // 🔥 第2步：确保 Matcher 已初始化
        var matcherTask = InitializeAsync();
        
        if (!matcherTask.IsCompletedSuccessfully)
        {
            return AwaitMatcher(this, httpContext, matcherTask);
        }

        var matcher = matcherTask.Result;
        
        // 🔥 第3步：执行匹配
        var matchTask = matcher.MatchAsync(httpContext);
        
        if (!matchTask.IsCompletedSuccessfully)
        {
            return AwaitMatch(this, httpContext, matchTask);
        }

        // 🔥 匹配完成后，Endpoint 已经存入 HttpContext
        // 由 Matcher 内部调用 httpContext.SetEndpoint(endpoint)
        
        return SetRoutingAndContinue(httpContext);
    }

    private Task SetRoutingAndContinue(HttpContext httpContext)
    {
        // 获取匹配结果
        var endpoint = httpContext.GetEndpoint();
        
        if (endpoint != null)
        {
            // 🔥 同时设置路由参数值
            // httpContext.Request.RouteValues 已经被 Matcher 填充
            // 比如 { "id": "123", "controller": "Users", "action": "GetUser" }
            
            Log.MatchSuccess(_logger, endpoint);
        }
        else
        {
            Log.MatchFailure(_logger);
        }

        // 🔥 继续管道（不执行 Endpoint，只是匹配完了）
        return _next(httpContext);
    }

    // 延迟初始化 Matcher（只在第一个请求时构建DFA）
    private Task<Matcher> InitializeAsync()
    {
        if (_initializationTask != null)
            return _initializationTask;

        return InitializeCoreAsync();
    }

    private Task<Matcher> InitializeCoreAsync()
    {
        var task = _matcherFactory.CreateMatcherAsync(_endpointDataSource);
        // 🔥🔥🔥 这里会构建 DFA 路由图
        // 将所有注册的路由模式编译成一个高效的状态机
        
        _initializationTask = task;
        return task;
    }
}
```

### 4.5 EndpointMiddleware —— 端点执行中间件

```csharp
// 📁 源码位置: src/Http/Routing/src/EndpointMiddleware.cs

internal sealed class EndpointMiddleware
{
    private readonly RequestDelegate _next;

    public async Task Invoke(HttpContext httpContext)
    {
        // 🔥 获取 UseRouting() 匹配到的 Endpoint
        var endpoint = httpContext.GetEndpoint();
        
        if (endpoint != null)
        {
            // 检查是否需要复制路由参数到 Feature
            if (!httpContext.Items.ContainsKey(EndpointRouteValuesKey))
            {
                httpContext.Items[EndpointRouteValuesKey] = true;
            }

            try
            {
                var requestTask = endpoint.RequestDelegate!(httpContext);
                // 🔥🔥🔥 执行 Endpoint 的 RequestDelegate
                // 
                // 对于 Controller：
                //   → ControllerActionInvoker.InvokeAsync()
                //     → 执行 Filters
                //     → 模型绑定
                //     → 执行 Action 方法
                //     → 格式化结果
                //
                // 对于 Minimal API：
                //   → 直接执行 lambda/方法
                //
                // 对于 OpenIddict（Passthrough模式）：
                //   → Controller Action

                if (!requestTask.IsCompletedSuccessfully)
                {
                    await requestTask;
                }
            }
            finally
            {
                Log.ExecutedEndpoint(_logger, endpoint);
            }
        }
        else
        {
            // 没有匹配到 Endpoint → 继续管道
            // 最终会到达管道末尾的404中间件
            await _next(httpContext);
        }
    }
}
```

## 六、RoutePattern —— 路由模式解析

### 6.1 路由模式语法

```
路由模式语法：

字面量：        /api/users              → 精确匹配
路由参数：      /api/users/{id}         → 捕获参数值
可选参数：      /api/users/{id?}        → id可选
默认值：        /api/users/{id=1}       → 默认id=1
通配符：        /api/{**rest}           → 匹配剩余所有路径段
约束：          /api/users/{id:int}     → id必须是整数
组合约束：      /api/users/{id:int:min(1)}  → 整数且≥1
复杂模式：      /api/{controller}/{action}/{id?}
```

### 6.3 路由模式解析过程

```csharp
// 📁 源码位置: src/Http/Routing/src/Patterns/RoutePatternParser.cs

internal static class RoutePatternParser
{
    // 将字符串解析为 RoutePattern
    public static RoutePattern Parse(string pattern)
    {
        // "/api/users/{id:int}" 
        //
        // 第1步：按 "/" 分割成段
        // ["api", "users", "{id:int}"]
        //
        // 第2步：解析每个段
        // "api"      → RoutePatternLiteralPart { Content: "api" }
        // "users"    → RoutePatternLiteralPart { Content: "users" }
        // "{id:int}" → RoutePatternParameterPart { 
        //                Name: "id",
        //                Constraints: [IntRouteConstraint],
        //                ParameterKind: Standard
        //              }
        //
        // 第3步：构建 RoutePattern
        
        var segments = new List<RoutePatternPathSegment>();
        var span = pattern.AsSpan();
        
        // 跳过开头的 "/"
        if (span.Length > 0 && span[0] == '/')
            span = span.Slice(1);
        
        while (span.Length > 0)
        {
            // 找到下一个 "/"
            var slashIndex = span.IndexOf('/');
            ReadOnlySpan<char> segmentSpan;
            
            if (slashIndex == -1)
            {
                segmentSpan = span;
                span = ReadOnlySpan<char>.Empty;
            }
            else
            {
                segmentSpan = span.Slice(0, slashIndex);
                span = span.Slice(slashIndex + 1);
            }
            
            // 解析段内容
            var segment = ParseSegment(segmentSpan);
            segments.Add(segment);
        }
        
        return new RoutePattern(/* ... */);
    }

    private static RoutePatternPathSegment ParseSegment(ReadOnlySpan<char> segment)
    {
        var parts = new List<RoutePatternPart>();
        
        if (segment.Length > 0 && segment[0] == '{')
        {
            // 参数段：{id:int}
            var parameterPart = ParseParameter(segment);
            parts.Add(parameterPart);
        }
        else
        {
            // 字面量段：api, users
            parts.Add(RoutePatternFactory.LiteralPart(segment.ToString()));
        }
        
        return new RoutePatternPathSegment(parts);
    }

    private static RoutePatternParameterPart ParseParameter(ReadOnlySpan<char> text)
    {
        // "{id:int:min(1)}"
        // 去掉 { }
        text = text.Slice(1, text.Length - 2);
        // "id:int:min(1)"
        
        // 按 ":" 分割
        // "id" → 参数名
        // "int" → 约束
        // "min(1)" → 带参数的约束
        
        var colonIndex = text.IndexOf(':');
        string name;
        List<RoutePatternConstraintReference> constraints = new();
        
        if (colonIndex == -1)
        {
            name = text.ToString();
        }
        else
        {
            name = text.Slice(0, colonIndex).ToString();
            var constraintText = text.Slice(colonIndex + 1);
            constraints = ParseConstraints(constraintText);
        }
        
        // 检查是否可选 (名字以 ? 结尾)
        bool isOptional = name.EndsWith('?');
        if (isOptional)
            name = name.TrimEnd('?');
        
        return new RoutePatternParameterPart(
            name, 
            defaultValue: null,
            parameterKind: isOptional 
                ? RoutePatternParameterKind.Optional 
                : RoutePatternParameterKind.Standard,
            constraints);
    }
}
```

### 6.4 路由约束

```csharp
// 📁 源码位置: src/Http/Routing/src/Constraints/

// 约束接口
public interface IRouteConstraint
{
    bool Match(HttpContext? httpContext, IRouter? route, string routeKey,
        RouteValueDictionary values, RouteDirection routeDirection);
}

// 常用内置约束：

// {id:int}
public class IntRouteConstraint : IRouteConstraint
{
    public bool Match(/*...*/ RouteValueDictionary values, /*...*/)
    {
        var value = values[routeKey];
        return int.TryParse(value?.ToString(), out _);
    }
}

// {id:guid}
public class GuidRouteConstraint : IRouteConstraint
{
    public bool Match(/*...*/)
    {
        return Guid.TryParse(values[routeKey]?.ToString(), out _);
    }
}

// {name:minlength(3)}
public class MinLengthRouteConstraint : IRouteConstraint
{
    private readonly int _minLength;
    public MinLengthRouteConstraint(int minLength) => _minLength = minLength;
    
    public bool Match(/*...*/)
    {
        var value = values[routeKey]?.ToString();
        return value != null && value.Length >= _minLength;
    }
}

// {name:regex(^[a-z]+$)}
public class RegexRouteConstraint : IRouteConstraint
{
    private readonly Regex _regex;
    public RegexRouteConstraint(string regexPattern)
        => _regex = new Regex(regexPattern, RegexOptions.Compiled);
    
    public bool Match(/*...*/)
    {
        var value = values[routeKey]?.ToString();
        return value != null && _regex.IsMatch(value);
    }
}
```

## 七、DFA Matcher —— 路由匹配的核心算法

### 7.1 什么是DFA路由

```
传统的路由匹配（线性扫描）：
  路由1: /api/users/{id}        → 检查... 不匹配
  路由2: /api/articles/{id}     → 检查... 不匹配
  路由3: /api/users/{id}/posts  → 检查... 不匹配
  路由4: /connect/token         → 检查... 匹配！✅
  
  复杂度：O(n)，路由越多越慢

DFA路由匹配（确定性有限自动机）：
  将所有路由模式编译成一棵树/图
  顺着请求URL的每一段走下去，到达叶节点就是匹配结果
  
  复杂度：O(路径段数)，与路由数量无关！
```

### 7.2 DFA路由图的构建

```
路由表：
  /api/users                    → Endpoint A
```

### 7.3 DfaMatcher 源码

```csharp
// 📁 源码位置: src/Http/Routing/src/Matching/DfaMatcher.cs

internal sealed class DfaMatcher : Matcher
{
    // 🔥 DFA 的状态转换表
    private readonly DfaState[] _states;
    
    // 每个状态包含：
    // - 字面量转换表（"api" → 下一个状态）
    // - 参数转换（{id} → 下一个状态）
    // - 通配符转换（{**rest} → 下一个状态）
    // - 匹配的 Endpoint 候选列表

    public override Task MatchAsync(HttpContext httpContext)
    {
        // 🔥 第1步：获取请求路径
        var path = httpContext.Request.Path.Value!;
        
        // 🔥 第2步：分割路径段
        Span<PathSegment> segments = stackalloc PathSegment[MaxSegmentCount];
        var segmentCount = Tokenize(path, segments);
        // "/api/users/123" → ["api", "users", "123"]

        // 🔥 第3步：遍历DFA
        var currentState = 0; // 从根状态开始
        var candidates = Array.Empty<CandidateState>();

        for (var i = 0; i < segmentCount; i++)
        {
            var segment = path.AsSpan(segments[i].Start, segments[i].Length);
            var state = _states[currentState];
            
            // 尝试字面量匹配
            currentState = state.PathTransitions.GetDestination(
                path, segments[i].Start, segments[i].Length);
            
            if (currentState == -1)
            {
                // 字面量不匹配 → 尝试参数匹配
                currentState = state.ParameterTransition;
            }
            
            if (currentState == -1)
            {
                // 参数也不匹配 → 尝试通配符
                currentState = state.CatchAllTransition;
            }
            
            if (currentState == -1)
            {
                // 完全不匹配 → 404
                return Task.CompletedTask;
            }
        }

        // 🔥 第4步：获取当前状态的候选 Endpoint
        candidates = _states[currentState].Candidates;

        if (candidates.Length == 0)
        {
            // 路径走完了但当前状态没有 Endpoint → 404
            return Task.CompletedTask;
        }

        // 🔥 第5步：从候选中选择最佳匹配
        // 考虑：路由约束、HTTP方法、优先级
        return SelectEndpointAsync(httpContext, candidates, path, segments, segmentCount);
    }

    private Task SelectEndpointAsync(
        HttpContext httpContext,
        CandidateState[] candidates,
        string path,
        Span<PathSegment> segments,
        int segmentCount)
    {
        // 对每个候选：
        for (var i = 0; i < candidates.Length; i++)
        {
            ref var candidate = ref candidates[i];
            
            // 🔥 验证路由约束
            // 比如 {id:int}，检查 "123" 是否是整数
            if (candidate.Constraints != null)
            {
                foreach (var constraint in candidate.Constraints)
                {
                    if (!constraint.Match(httpContext, /* ... */))
                    {
                        candidate.IsValid = false;
                        break;
                    }
                }
            }
            
            // 🔥 提取路由参数值
            if (candidate.IsValid)
            {
                ExtractRouteValues(candidate, path, segments, 
                    httpContext.Request.RouteValues);
                // RouteValues["id"] = "123"
                // RouteValues["controller"] = "Users"
                // RouteValues["action"] = "GetUser"
            }
        }

        // 选择第一个有效的候选（按优先级排序）
        var selectedCandidate = candidates.FirstOrDefault(c => c.IsValid);
        
        if (selectedCandidate.Endpoint != null)
        {
            // 🔥 设置匹配到的 Endpoint
            httpContext.SetEndpoint(selectedCandidate.Endpoint);
            
            // 设置路由参数
            httpContext.Request.RouteValues = selectedCandidate.Values;
        }
        
        return Task.CompletedTask;
    }
}
```

```csharp
// 📁 简化版的扫描逻辑

public class ControllerActionEndpointDataSource : EndpointDataSource
{
    public override IReadOnlyList<Endpoint> Endpoints
    {
        get
        {
            Initialize();
            return _endpoints;
        }
    }

    private void Initialize()
    {
        var endpoints = new List<Endpoint>();
        
        // 🔥 获取所有 Controller Action 描述
        var actions = _actionDescriptorProvider.ActionDescriptors.Items;
        
        foreach (var action in actions)
        {
            // 例如: UsersController.GetUser(int id)
            // ActionDescriptor 包含了：
            //   - ControllerName: "Users"
            //   - ActionName: "GetUser"
            //   - RouteValues: { controller: "Users", action: "GetUser" }
            //   - AttributeRouteInfo: { Template: "api/users/{id}" }
            //   - FilterDescriptors: [AuthorizeFilter, ...]
            //   - Parameters: [{ Name: "id", Type: typeof(int) }]
            
            // 🔥 构建路由模式
            RoutePattern pattern;
            
            if (action.AttributeRouteInfo != null)
            {
                // Attribute路由: [Route("api/users/{id}")]
                pattern = RoutePatternFactory.Parse(
                    action.AttributeRouteInfo.Template);
            }
            else
            {
                // 传统路由: {controller}/{action}/{id?}
                pattern = ConventionalRoutePattern(action);
            }

            // 🔥 收集元数据
            var metadata = new List<object>();
            
            // 添加 [Authorize] 信息
            foreach (var filter in action.FilterDescriptors)
            {
                if (filter.Filter is IAuthorizeData authorizeData)
                {
                    metadata.Add(authorizeData);
                }
                if (filter.Filter is IAllowAnonymous allowAnon)
                {
                    metadata.Add(allowAnon);
                }
            }
            
            // 添加 HTTP 方法约束
            var httpMethods = action.ActionConstraints?
                .OfType<HttpMethodActionConstraint>()
                .FirstOrDefault()?.HttpMethods;
            if (httpMethods != null)
            {
                metadata.Add(new HttpMethodMetadata(httpMethods));
            }
            
            // 添加 Action 描述本身
            metadata.Add(action);

            // 🔥 创建 RequestDelegate（调用Controller Action的委托）
            RequestDelegate requestDelegate = async context =>
            {
                // MVC框架的请求处理管道
                var invoker = _invokerFactory.CreateInvoker(action);
                await invoker.InvokeAsync();
                // → Filter管道 → 模型绑定 → Action执行 → 结果格式化
            };

            // 🔥 创建 RouteEndpoint
            var endpoint = new RouteEndpoint(
                requestDelegate,
                pattern,
                order: action.AttributeRouteInfo?.Order ?? 0,
                new EndpointMetadataCollection(metadata),
                displayName: $"{action.ControllerName}.{action.ActionName}");

            endpoints.Add(endpoint);
        }
        
        _endpoints = endpoints;
    }
}
```

```csharp
// 📁 源码位置: src/Http/Routing/src/Builder/EndpointRouteBuilderExtensions.cs

public static class EndpointRouteBuilderExtensions
{
    public static RouteHandlerBuilder MapGet(
        this IEndpointRouteBuilder endpoints,
        string pattern,
        Delegate handler)
    {
        return Map(endpoints, RoutePatternFactory.Parse(pattern), handler, 
            httpMethods: new[] { "GET" });
    }

    public static RouteHandlerBuilder MapPost(
        this IEndpointRouteBuilder endpoints,
        string pattern,
        Delegate handler)
    {
        return Map(endpoints, RoutePatternFactory.Parse(pattern), handler, 
            httpMethods: new[] { "POST" });
    }

    private static RouteHandlerBuilder Map(
        IEndpointRouteBuilder endpoints,
        RoutePattern pattern,
        Delegate handler,
        IEnumerable<string>? httpMethods)
    {
        // 🔥 将 Delegate 包装成 RequestDelegate
        var requestDelegate = RequestDelegateFactory.Create(handler, new RequestDelegateFactoryOptions
        {
            ServiceProvider = endpoints.ServiceProvider,
            RouteParameterNames = pattern.Parameters.Select(p => p.Name),
        });

        // 🔥 创建 RouteEndpoint
        var builder = new RouteEndpointBuilder(requestDelegate, pattern, order: 0);
        
        // 添加 HTTP 方法元数据
        if (httpMethods != null)
        {
            builder.Metadata.Add(new HttpMethodMetadata(httpMethods));
        }

        // 🔥 添加到 DataSource
        var dataSource = endpoints.DataSources
            .OfType<RouteEndpointDataSource>()
            .FirstOrDefault();
        dataSource ??= new RouteEndpointDataSource();
        
        dataSource.AddEndpoint(builder.Build());

        return new RouteHandlerBuilder(builder);
    }
}
```

## 九、HTTP 方法匹配 —— EndpointSelector

```csharp
// 当DFA匹配到多个候选Endpoint时，需要进一步选择

// 例如：
app.MapGet("/api/users/{id}", GetUser);     // Endpoint A
app.MapPut("/api/users/{id}", UpdateUser);  // Endpoint B
app.MapDelete("/api/users/{id}", DeleteUser); // Endpoint C

// 这三个Endpoint的路由模式完全相同："/api/users/{id}"
// DFA匹配时会同时匹配到三个

// 区分它们的是 HttpMethodMetadata

// EndpointSelector 的工作：
// 请求: PUT /api/users/123
// DFA匹配: [A, B, C]
// 按HTTP方法过滤: B (PUT)
// 最终选择: Endpoint B
```

```csharp
// 📁 源码位置: src/Http/Routing/src/Matching/HttpMethodMatcherPolicy.cs

internal sealed class HttpMethodMatcherPolicy : MatcherPolicy, IEndpointSelectorPolicy
{
    public Task ApplyAsync(HttpContext httpContext, CandidateSet candidates)
    {
        var method = httpContext.Request.Method;
        
        for (var i = 0; i < candidates.Count; i++)
        {
            if (!candidates.IsValidCandidate(i))
                continue;

            var endpoint = candidates[i].Endpoint;
            var httpMethodMetadata = endpoint.Metadata.GetMetadata<IHttpMethodMetadata>();

            if (httpMethodMetadata?.HttpMethods != null)
            {
                // 🔥 检查HTTP方法是否匹配
                var matched = false;
                foreach (var httpMethod in httpMethodMetadata.HttpMethods)
                {
                    if (string.Equals(httpMethod, method, StringComparison.OrdinalIgnoreCase))
                    {
                        matched = true;
                        break;
                    }
                }

                if (!matched)
                {
                    // HTTP方法不匹配 → 标记为无效候选
                    candidates.SetValidity(i, false);
                }
            }
        }

        // 如果所有候选都因HTTP方法不匹配而无效
        // → 返回 405 Method Not Allowed（而不是404）
        if (AllCandidatesInvalid(candidates) && HasMethodMismatch(candidates, method))
        {
            httpContext.Response.StatusCode = 405;
            httpContext.SetEndpoint(CreateRejectedEndpoint());
        }

        return Task.CompletedTask;
    }
}
```

## 十、路由优先级规则

```csharp
// 当多个路由模式都能匹配URL时，优先级规则：

// 📁 源码位置: src/Http/Routing/src/Patterns/RoutePatternFactory.cs

// 优先级计算（值越小越优先）：
// 1. 字面量段 > 参数段 > 通配符段
// 2. 有约束的参数 > 无约束的参数
// 3. 先注册的 > 后注册的（同等优先级时）
```

```
匹配 /api/users/admin 时：

路由1: /api/users/admin      字面量完全匹配     → 优先级最高 ✅
路由2: /api/users/{name}     参数匹配           → 优先级次之
路由3: /api/users/{id:int}   参数+约束匹配      → "admin"不是int → 不匹配
路由4: /api/{**rest}         通配符匹配          → 优先级最低

匹配 /api/users/123 时：

路由1: /api/users/admin      字面量不匹配
路由2: /api/users/{name}     参数匹配           → 优先级较高（无约束也能匹配）
路由3: /api/users/{id:int}   参数+约束匹配      → 123是int ✅
                                                
🔥 路由2和路由3都匹配，怎么选？
答：有约束的优先 → 路由3 胜出

如果路由2是 {name:alpha}（字母约束），
那"123"不满足alpha约束 → 只有路由3匹配
```

```
优先级完整排序（从高到低）：

1. /api/users/admin              纯字面量
2. /api/users/{id:int}           参数+约束
3. /api/users/{name}             参数无约束
4. /api/users/{name?}            可选参数
5. /api/users/{name=default}     带默认值的参数
6. /api/{controller}/{action}    多段参数
7. /api/{**rest}                 通配符
```

## 十三、OpenIddict 与路由系统的关系

```
OpenIddict 的端点有两种路由机制：

方式1：OpenIddict Handler 直接在认证中间件层拦截
═══════════════════════════════════════════════════

请求: POST /connect/token
│
├── UseRouting() → DFA匹配 → 可能匹配到 Controller 的 Endpoint
│                            也可能匹配不到（如果没有 MapControllers）
│
├── UseAuthentication()
│   │
│   └── OpenIddictServerHandler.HandleRequestAsync()
│       │ 检查 Request.Path
│       │ "/connect/token" 匹配 Token 端点配置 ✅
│       │ 
│       │ 🔥 OpenIddict 不依赖 ASP.NET Core 路由系统来识别端点！
│       │ 🔥 它自己比较 Request.Path 和配置的端点路径
│       │
│       │ 处理请求 → 返回 Token → return true
│       └── 短路！UseAuthorization 和 UseEndpoints 都不执行

这种方式：Token端点甚至不需要有对应的Controller
OpenIddict 完全自己处理


方式2：Passthrough模式 → 需要 Controller 路由
═══════════════════════════════════════════════════

请求: GET /connect/authorize?client_id=web-app&...
│
├── UseRouting() → DFA匹配 → 匹配到 AuthorizationController.Authorize()
│                            Endpoint 设置到 HttpContext
│
├── UseAuthentication()
│   │
│   └── OpenIddictServerHandler.HandleRequestAsync()
│       │ 检查 Request.Path → "/connect/authorize" 匹配授权端点
│       │ 验证请求参数（client_id, redirect_uri等）
│       │ 
│       │ 因为开启了 Passthrough → return false
│       │ 🔥 请求继续流向 Controller
│
├── UseAuthorization()
│   │ 读取 Endpoint 的 [Authorize] Metadata
│   │ 检查用户是否已认证
│
└── UseEndpoints()
    │ 执行 AuthorizationController.Authorize()
    │ Controller 获取 OpenIddict 请求信息
    │ 展示登录页/同意页/签发授权码
```

## 十五、自定义 Endpoint Metadata 和 MatcherPolicy

```csharp
// 场景：根据请求头中的API版本选择不同的Endpoint

// ========== 自定义 Metadata ==========
[AttributeUsage(AttributeTargets.Method)]
public class ApiVersionAttribute : Attribute
{
    public string Version { get; }
    public ApiVersionAttribute(string version) => Version = version;
}

// ========== 自定义 MatcherPolicy ==========
public class ApiVersionMatcherPolicy : MatcherPolicy, IEndpointSelectorPolicy
{
    // 优先级（数字越小越先执行）
    public override int Order => 100; // 在 HttpMethodMatcherPolicy 之后

    public bool AppliesToEndpoints(IReadOnlyList<Endpoint> endpoints)
    {
        // 只有当候选Endpoint中有 ApiVersion Metadata 时才生效
        return endpoints.Any(e => e.Metadata.GetMetadata<ApiVersionAttribute>() != null);
    }

    public Task ApplyAsync(HttpContext httpContext, CandidateSet candidates)
    {
        // 从请求头获取API版本
        var requestVersion = httpContext.Request.Headers["api-version"].FirstOrDefault()
            ?? "1.0";

        for (var i = 0; i < candidates.Count; i++)
        {
            if (!candidates.IsValidCandidate(i))
                continue;

            var versionAttr = candidates[i].Endpoint
                .Metadata.GetMetadata<ApiVersionAttribute>();

            if (versionAttr != null && versionAttr.Version != requestVersion)
            {
                // 版本不匹配 → 标记为无效
                candidates.SetValidity(i, false);
            }
        }

        return Task.CompletedTask;
    }
}

// ========== 注册 ==========
builder.Services.AddSingleton<MatcherPolicy, ApiVersionMatcherPolicy>();

// ========== 使用 ==========
[ApiController]
[Route("api/users")]
public class UsersController : ControllerBase
{
    [HttpGet]
    [ApiVersion("1.0")]
    public IActionResult GetUsersV1() => Ok(new { version = "1.0", users = new[] { "a", "b" } });

    [HttpGet]
    [ApiVersion("2.0")]
    public IActionResult GetUsersV2() => Ok(new { version = "2.0", data = new { users = new[] { "a", "b" }, total = 2 } });
}

// GET /api/users  (api-version: 1.0)  → GetUsersV1
// GET /api/users  (api-version: 2.0)  → GetUsersV2
```

## 十六、检验你的理解

1. **为什么 UseRouting() 和 UseEndpoints() 要分开？如果合在一起会有什么问题？**
   （答案：分开是为了让 UseAuthentication 和 UseAuthorization 中间件能在路由匹配后、执行前读取 Endpoint 的 Metadata（如 [Authorize]）。如果合在一起，认证授权就无法在执行前知道目标端点需要什么认证方案和授权策略。这可能导致：① 匿名请求到达需要认证的 Controller 才被拒绝（体验差）。② 无法根据 Endpoint 的 [Authorize(Schemes="Bearer")] 来选择不同的认证方案。）

2. **DFA 路由匹配的复杂度是什么？为什么比线性扫描快？**
   （答案：DFA 匹配的复杂度是 O(路径段数)，通常 3-5 步。线性扫描是 O(路由数量)，路由越多越慢。DFA 将所有路由模式预编译成一个状态机，每个请求只需要顺着路径段走状态转换，与注册的路由数量无关。代价是启动时需要构建 DFA 图，占用额外内存。）

3. **OpenIddict 的 Token 端点（/connect/token）是通过 ASP.NET Core 路由系统匹配到的吗？**
   （答案：不是。OpenIddict Server Handler 是 IAuthenticationRequestHandler，在 UseAuthentication 层工作。它自己比较 Request.Path 和配置的端点路径来识别请求，不依赖 ASP.NET Core 路由系统。所以即使没有对应的 Controller 路由，Token 端点也能正常工作。只有开启了 Passthrough 的端点（如 Authorization 端点）才需要有对应的 Controller 路由，因为请求会继续流向 UseEndpoints。）

4. **Minimal API 的参数绑定是在什么时候完成的？与 Controller 的模型绑定有什么区别？**
   （答案：Minimal API 的参数绑定在 `RequestDelegateFactory.Create()` 时就生成了绑定代码（编译时/注册时）。Controller 的模型绑定在请求运行时由 ModelBinder 执行。Minimal API 的绑定是静态分析参数类型后生成的优化代码（Source Generator 或 Expression Tree），性能更好。Controller 的绑定更灵活（支持自定义 ModelBinder），但有更多运行时开销。）

5. **GET /api/users/admin 同时匹配 /api/users/admin（字面量）和 /api/users/{name}（参数），选哪个？为什么？**
   （答案：选字面量 /api/users/admin。路由优先级规则：字面量 > 有约束的参数 > 无约束的参数 > 通配符。字面量是精确匹配，总是优先于参数匹配。这是因为在 DFA 图中，字面量边的优先级高于参数转换。）

6. **如果你在 SSO 项目中需要同时支持 MVC 页面（登录页）和 API（Token验证），路由应该怎么设计？**
   （答案：MVC 页面用 Attribute Routing 或 Conventional Routing（`app.MapControllerRoute("default", "{controller=Home}/{action=Index}/{id?}")`）。API 用 Attribute Routing（`[Route("api/[controller]")]`）。OpenIddict 端点路径在 AddOpenIddict() 中配置（`SetTokenEndpointUris("/connect/token")`），不需要额外路由配置。Passthrough 端点用 Attribute Routing（`[Route("connect")]`）。确保 `UseRouting() → UseAuthentication() → UseAuthorization() → MapControllers()` 的中间件顺序正确。）
