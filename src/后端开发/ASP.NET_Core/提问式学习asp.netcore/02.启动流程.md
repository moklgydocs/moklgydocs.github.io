# ASP.NET Core 启动流程：源码级深入

---

## 一、先看你每天写的这三行代码

```csharp
var builder = WebApplication.CreateBuilder(args);  // 第1步：准备
var app = builder.Build();                          // 第2步：构建
app.Run();                                          // 第3步：运行
```

这三行代码背后，框架做了**几百个操作**。我们逐行拆解。

---

## 二、全景时间线

```
时间轴 ──────────────────────────────────────────────────────────────►

 CreateBuilder(args)              Build()                    Run()
      │                            │                          │
      ▼                            ▼                          ▼
┌──────────────┐  你注册服务  ┌──────────────┐  你配管道  ┌──────────────┐
│              │  的时间窗口  │              │  的时间窗口 │              │
│  准备阶段     │ ◄────────► │  构建阶段     │ ◄───────► │  运行阶段     │
│              │             │              │            │              │
│ ·创建配置    │             │ ·冻结DI容器   │            │ ·启动Kestrel  │
│ ·创建DI注册表│             │ ·构建管道     │            │ ·开始监听     │
│ ·注册核心服务│             │ ·创建Host    │            │ ·处理请求     │

     可变阶段                     冻结点                    不可变运行时
```

## 三、第1步：`WebApplication.CreateBuilder(args)` 深度拆解

### 源码入口

```csharp
// 📁 源码位置: src/DefaultBuilder/src/WebApplication.cs
public sealed class WebApplication : IHost, IApplicationBuilder, IEndpointRouteBuilder
{
    public static WebApplicationBuilder CreateBuilder(string[] args) =>
        new WebApplicationBuilder(new WebApplicationOptions { Args = args });
}
```

所以关键在 **`WebApplicationBuilder`** 的构造函数：

### WebApplicationBuilder 构造函数源码

```csharp
// 📁 源码位置: src/DefaultBuilder/src/WebApplicationBuilder.cs
public sealed class WebApplicationBuilder
{
    // 这些就是你在外面能访问的属性
    public IServiceCollection Services { get; }
    public ConfigurationManager Configuration { get; }
    public ILoggingBuilder Logging { get; }
    public IWebHostEnvironment Environment { get; }

    internal WebApplicationBuilder(WebApplicationOptions options)
    {
        // ============================
        // 🔥 第一步：创建配置系统
        // ============================
        Configuration = new ConfigurationManager();
        
        // ============================
        // 🔥 第二步：创建 HostBuilder（幕后老板）
        // ============================
        _hostApplicationBuilder = new HostApplicationBuilder(new HostApplicationBuilderSettings
        {
            Args = options.Args,
            Configuration = Configuration,
        });
        
        // ============================
        // 🔥 第三步：配置默认值
        // ============================
        
        // 3a. 配置 Kestrel 作为默认服务器
        _hostApplicationBuilder.Services.AddSingleton<IServer, KestrelServer>();
        
        // 3b. 加载配置源（按优先级从低到高）
        // appsettings.json
        // appsettings.{Environment}.json
        // 环境变量
        // 命令行参数
        // User Secrets（开发环境）
        
        // 3c. 配置日志
        // Console、Debug、EventSource 等日志提供程序
        
        // 3d. 注册核心框架服务
        ConfigureWebHost();  // 👈 这是关键方法
    }
}
```

### 配置加载的完整顺序和优先级

```
优先级（从低到高，后面的覆盖前面的）：
    
    ┌─────────────────────────────────────────┐
    │  1. ChainedConfigurationSource          │  最低
    │  2. appsettings.json                    │
    │  3. appsettings.{Environment}.json      │
    │  4. User Secrets (仅Development)         │
    │  5. 环境变量                             │
    │  6. 命令行参数                           │  最高
    └─────────────────────────────────────────┘
```

**源码验证：**


### CreateBuilder 完成后，你手里拿到了什么

```
WebApplicationBuilder
    │
    ├── .Configuration ──── ConfigurationManager（可以继续添加配置源）
    │                        已包含: appsettings.json, 环境变量等
    │
    ├── .Services ────────── IServiceCollection（DI注册表，还是空白画布）
    │                        已注册: Kestrel, Routing, Logging等核心服务
    │                        你可以继续: services.AddDbContext<>()
    │                                    services.AddAuthentication()
    │                                    services.AddOpenIddict() 👈 你的SSO
    │
    ├── .Logging ─────────── ILoggingBuilder（日志配置）
    │
    ├── .Environment ─────── IWebHostEnvironment
    │                        .EnvironmentName = "Development"/"Production"
    │                        .ContentRootPath = 项目根目录
    │                        .WebRootPath = wwwroot
    │
    └── .Host ────────────── IHostBuilder（底层宿主构建器）
```

**在这个阶段，一切都是"可变的"** —— 你可以随意添加服务、修改配置。

```csharp
// 你在这个阶段做的事情：
var builder = WebApplication.CreateBuilder(args);

// 👇 利用"可变窗口"注册你的服务
builder.Services.AddControllers();
builder.Services.AddAuthentication()
    .AddCookie()
    .AddJwtBearer();
builder.Services.AddOpenIddict()        // 你的SSO
    .AddCore()
    .AddServer()
    .AddValidation();
builder.Services.AddDbContext<AppDbContext>();

// 到这里为止，所有的"注册"都只是往 IServiceCollection 里添加 ServiceDescriptor
// 还没有真正创建任何服务实例！
```

## 四、第2步：`builder.Build()` 深度拆解

**这是最关键的"冻结点"。**

### 源码

```csharp
// 📁 源码位置: src/DefaultBuilder/src/WebApplicationBuilder.cs
public WebApplication Build()
{
    // 🔥 第一步：构建 Host
    _hostApplicationBuilder.Services.Add(_services);  // 合并所有服务注册
    
    Host = _hostApplicationBuilder.Build();  // 👈 最关键的一步
    
    // 🔥 第二步：创建 WebApplication 实例
    return new WebApplication(Host);
}
```

### `_hostApplicationBuilder.Build()` 内部做了什么

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.Hosting/src/HostApplicationBuilder.cs
public IHost Build()
{
    // ================================
    // 🔥 核心操作1：冻结 DI 容器
    // ================================
    // 将 IServiceCollection（注册表）编译成 IServiceProvider（运行时容器）
    _serviceProvider = _services.BuildServiceProvider();
    
    // 从这一刻开始，你不能再往DI容器里添加服务了！
    // 这就是为什么 builder.Services.AddXxx() 必须在 Build() 之前调用
    
    // ================================
    // 🔥 核心操作2：创建 IHost 实例
    // ================================
    return _serviceProvider.GetRequiredService<IHost>();
    // IHost 的默认实现是 Internal.Host
}
```

### ServiceCollection → ServiceProvider 的编译过程

```
IServiceCollection（注册阶段）          IServiceProvider（运行阶段）
┌─────────────────────────┐           ┌─────────────────────────┐
│ List<ServiceDescriptor>  │   Build   │  编译后的查找表           │
│                          │ ────────► │  (快速解析服务实例)       │
│ {ILogger, ConsoleLogger, │           │                          │
│  Singleton}              │           │  根据注册信息，按需创建    │
│ {IServer, KestrelServer, │           │  Singleton → 全局缓存    │
│  Singleton}              │           │  Scoped → 每Scope一个    │
│ {MyService, MyService,   │           │  Transient → 每次新建    │
│  Transient}              │           │                          │
│ ...数百个注册...          │           │                          │
└─────────────────────────┘           └─────────────────────────┘
        可变（List）                         不可变（优化后的数据结构）
```

**源码中的 ServiceDescriptor 结构：**

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.DependencyInjection.Abstractions/
//              src/ServiceDescriptor.cs
public class ServiceDescriptor
{
    public Type ServiceType { get; }          // 接口类型 (如 IServer)
    public Type? ImplementationType { get; }  // 实现类型 (如 KestrelServer)
    public ServiceLifetime Lifetime { get; }  // 生命周期
    public object? ImplementationInstance { get; }    // 直接实例
    public Func<IServiceProvider, object>? ImplementationFactory { get; } // 工厂
}

public enum ServiceLifetime
{
    Singleton,  // 整个应用生命周期只有一个实例
    Scoped,     // 每个请求（Scope）一个实例
    Transient   // 每次注入都是新实例
}
```

### Build() 完成后，中间件管道的构建

当 `new WebApplication(Host)` 被创建后，你开始配置中间件：

```csharp
var app = builder.Build();

// 现在 app 既是 IHost，也是 IApplicationBuilder
// 以下每一行都是往中间件列表里添加一个函数

app.UseExceptionHandler("/Error");     // _components.Add(异常处理中间件)
app.UseHttpsRedirection();             // _components.Add(HTTPS重定向中间件)
app.UseStaticFiles();                  // _components.Add(静态文件中间件)
app.UseAuthentication();               // _components.Add(认证中间件)  👈 SSO关键
app.UseAuthorization();                // _components.Add(授权中间件)
app.MapControllers();                  // 注册路由Endpoint

// 此时管道还没有被 Build，只是在收集中间件
```

## 五、第3步：`app.Run()` 深度拆解

### 调用链路

```csharp
// 📁 源码位置: src/DefaultBuilder/src/WebApplication.cs
public void Run(string? url = null)
{
    // ...
    RunAsync(url).GetAwaiter().GetResult();  // 同步阻塞
}

public async Task RunAsync(string? url = null)
{
    // ...
    await StartAsync();   // 启动
    await _host.WaitForShutdownAsync();  // 阻塞等待关闭信号（Ctrl+C）
}

public async Task StartAsync(CancellationToken cancellationToken = default)
{
    // 🔥 这里触发 IHost.StartAsync()
    await _host.StartAsync(cancellationToken);
}
```

### IHost.StartAsync() 内部

```csharp
// 📁 源码位置: src/libraries/Microsoft.Extensions.Hosting/src/Internal/Host.cs
internal sealed class Host : IHost
{
    private readonly IServiceProvider _services;
    private readonly IEnumerable<IHostedService> _hostedServices;
    
    public async Task StartAsync(CancellationToken cancellationToken)
    {
        // 🔥 第一步：启动所有 IHostedService
        foreach (var hostedService in _hostedServices)
        {
            await hostedService.StartAsync(cancellationToken);
            
            if (hostedService is BackgroundService)
            {
                // 后台服务异步运行，不阻塞启动流程
                _ = hostedService.ExecuteAsync(cancellationToken);
            }
        }
        
        // 🔥 第二步：触发 IHostApplicationLifetime.ApplicationStarted
        _applicationLifetime.NotifyStarted();
    }
}
```

### 关键！GenericWebHostService —— 真正启动 Server 的地方

```csharp
// 📁 源码位置: src/Hosting/Hosting/src/GenericHost/GenericWebHostService.cs
// 这是一个 IHostedService，在 Host.StartAsync() 中被启动

internal sealed class GenericWebHostService : IHostedService
{
    private readonly IServer _server;               // Kestrel
    private readonly IOptions<GenericWebHostServiceOptions> _options;
    
    public async Task StartAsync(CancellationToken cancellationToken)
    {
        // ================================
        // 🔥🔥🔥 核心操作1：构建中间件管道
        // ================================
        var builderFactory = _services.GetRequiredService<IApplicationBuilderFactory>();
        var builder = builderFactory.CreateBuilder(_server.Features);
        
        // 执行你写的 Configure 逻辑（app.UseXxx 的部分）
        var configure = _options.Value.ConfigureApplication;
        configure(builder);  // 👈 这里执行了你的中间件注册代码
        
        // 🔥🔥🔥 构建最终的 RequestDelegate！
        var application = builder.Build();
        // 现在 application 就是那个套娃后的 RequestDelegate
        // A( B( C( D( 404 ) ) ) )
        
        // ================================
        // 🔥🔥🔥 核心操作2：创建 HostingApplication
        // ================================
        _application = new HostingApplication(
            application,             // 中间件管道
            _logger,
            _diagnosticSource,
            _activitySource,
            _httpContextFactory      // HttpContext 工厂
        );
        
        // ================================
        // 🔥🔥🔥 核心操作3：启动 Kestrel 服务器！
        // ================================
        await _server.StartAsync(_application, cancellationToken);
        // 从这一刻开始，Kestrel 开始监听端口，接收请求
        // 每收到一个请求，就调用 _application.ProcessRequestAsync()
    }
}
```

### HostingApplication —— 每个请求的入口

```csharp
// 📁 源码位置: src/Hosting/Hosting/src/Internal/HostingApplication.cs
internal sealed class HostingApplication : IHttpApplication<HostingApplication.Context>
{
    private readonly RequestDelegate _application;  // 你的中间件管道
    private readonly IHttpContextFactory _httpContextFactory;
    
    // 🔥 每个HTTP请求都会调用这个方法
    public Task ProcessRequestAsync(Context context)
    {
        // 直接执行中间件管道！
        return _application(context.HttpContext);
        // 就这一行！把 HttpContext 扔进管道，让中间件们依次处理
    }
    
    // 创建请求上下文
    public Context CreateContext(IFeatureCollection contextFeatures)
    {
        // 1. 创建 HttpContext
        var httpContext = _httpContextFactory.Create(contextFeatures);
        
        // 2. 创建 DI Scope（每个请求一个 Scope）
        // 这就是为什么 Scoped 服务是"每请求一个实例"
        var scope = _serviceScopeFactory.CreateScope();
        httpContext.RequestServices = scope.ServiceProvider;  // 👈 关键！
        
        // 3. 开始诊断/日志记录
        // ...
        
        return new Context { HttpContext = httpContext, Scope = scope };
    }
    
    // 请求结束后清理
    public void DisposeContext(Context context, Exception? exception)
    {
        // 释放 DI Scope → 所有 Scoped 服务被释放
        context.Scope?.Dispose();
        
        // 回收 HttpContext（对象池）
        _httpContextFactory.Dispose(context.HttpContext);
    }
}
```

> **这段源码揭示了一个极其重要的事实**：每个请求的 DI Scope 是在 `HostingApplication.CreateContext()` 中创建的，在 `DisposeContext()` 中释放的。这就是 Scoped 生命周期的实现原理。

```
Program.Main()
│
├── WebApplication.CreateBuilder(args)
│   └── new WebApplicationBuilder(options)

│       │   └── 加载配置源(json/env/cmdline)          // 填充配置

│           ├── services.AddRouting()
│           ├── services.AddSingleton<IHttpContextFactory>()

│

│

│
└── app.Run()
    └── Host.StartAsync()
        ├── 遍历所有 IHostedService

        │           ├── 绑定端口 (默认5000/5001)
        │           └── 开始接受TCP连接
        │
```

## 七、三个时代的演变（帮你理解为什么现在是这样）

```
┌─────────────────────────────────────────────────────────────────────┐
│                        ASP.NET Core 启动方式的演变                    │
├───────────┬─────────────────────────────────────────────────────────┤
│ .NET Core │  两个文件：Program.cs + Startup.cs                       │
│ 1.0 ~ 3.1 │                                                        │
│           │  Program.cs:                                            │
│           │    Host.CreateDefaultBuilder(args)                      │
│           │        .ConfigureWebHostDefaults(webBuilder =>          │
│           │            webBuilder.UseStartup<Startup>())            │
│           │        .Build()                                         │
│           │        .Run();                                          │
│           │                                                        │
│           │  Startup.cs:                                            │
│           │    ConfigureServices(IServiceCollection services)       │
│           │    Configure(IApplicationBuilder app)                   │
├───────────┼─────────────────────────────────────────────────────────┤
│ .NET 5~6  │  过渡期：还是两种写法都支持                               │
│           │  引入了 Host → WebHost → Generic Host 的统一             │
├───────────┼─────────────────────────────────────────────────────────┤
│ .NET 6+   │  Minimal Hosting Model（最简模式）                       │
│ (现在)     │                                                        │
│           │  var builder = WebApplication.CreateBuilder(args);      │
│           │  // 注册服务                                             │
│           │  var app = builder.Build();                              │
│           │  // 配置管道                                             │
│           │  app.Run();                                              │
│           │                                                        │
│           │  去掉了Startup类，一个文件搞定                            │
│           │  但底层原理完全一样！                                      │
└───────────┴─────────────────────────────────────────────────────────┘
```

### Host 的三代关系

```
第1代：WebHost（ASP.NET Core 1.0~2.2）
  │     专门为 Web 应用设计
  │     不支持非HTTP的后台任务
  │
  ▼
第2代：Generic Host（ASP.NET Core 3.0+）
  │     通用宿主，不仅仅是 Web
  │     Web 只是 Host 的一个 HostedService
  │     支持 Worker Service、gRPC 等
  │
  ▼
第3代：WebApplication（.NET 6+）
  │     语法糖，底层还是 Generic Host
  │     简化了 API，但原理不变
  │
  ▼
  现在你用的就是第3代
```

**用源码证明 WebApplication 底层就是 Generic Host：**

```csharp
// 📁 src/DefaultBuilder/src/WebApplication.cs
public sealed class WebApplication : IHost, IApplicationBuilder, IEndpointRouteBuilder
{
    internal readonly IHost _host;  // 👈 底层就是一个 IHost

    // 所有操作都是委托给 _host
    public IServiceProvider Services => _host.Services;
    
    public Task StartAsync(CancellationToken cancellationToken = default)
        => _host.StartAsync(cancellationToken);
    
    public Task StopAsync(CancellationToken cancellationToken = default)
        => _host.StopAsync(cancellationToken);
}
```

## 八、一个请求的完整生命周期（把启动流程和运行时串起来）

当 `app.Run()` 完成后，Kestrel 开始工作。现在一个请求进来了：

```
用户浏览器发送: GET /api/users HTTP/1.1
                         │
                         ▼
┌──────────────────────────────────────────────────────────────┐
│                     Kestrel 内部                              │
│                                                              │
│  1. TCP连接层：接受Socket连接                                  │
│  2. HTTP协议层：解析HTTP请求头和Body                            │
│  3. 生成 IFeatureCollection（请求的原始特征集合）               │
│  4. 调用 IHttpApplication.CreateContext(features)             │
│                         │                                    │
└─────────────────────────┼────────────────────────────────────┘
                          ▼
┌──────────────────────────────────────────────────────────────┐
│              HostingApplication.CreateContext()                │
│                                                              │
│  1. 从特征集合创建 HttpContext                                  │
│     HttpContext.Request  ← 请求信息                           │
│     HttpContext.Response ← 响应（待填充）                      │
│                                                              │
│  2. 创建 DI Scope                                            │
│     var scope = _scopeFactory.CreateScope();                 │
│     httpContext.RequestServices = scope.ServiceProvider; 🔥   │
│                                                              │
```

## 九、对你SSO项目的启示

理解了启动流程后，你应该知道：

```csharp
var builder = WebApplication.CreateBuilder(args);

// ==========================================
// 🔥 服务注册阶段（Build之前）
// ==========================================

// 1. EF Core - OpenIddict 需要数据存储
builder.Services.AddDbContext<ApplicationDbContext>(options =>
{
    options.UseSqlServer(builder.Configuration.GetConnectionString("Default"));
    options.UseOpenIddict();  // 👈 告诉EF注册OpenIddict的实体
});

// 2. ASP.NET Core Identity（用户管理）
builder.Services.AddIdentity<ApplicationUser, IdentityRole>()
    .AddEntityFrameworkStores<ApplicationDbContext>()
    .AddDefaultTokenProviders();

// 3. OpenIddict（SSO核心）
builder.Services.AddOpenIddict()
    .AddCore(options =>
    {
        // 使用EF Core存储（Applications、Authorizations、Scopes、Tokens）
        options.UseEntityFrameworkCore()
               .UseDbContext<ApplicationDbContext>();
    })
    .AddServer(options =>
    {
        // 注册OAuth2.0/OIDC端点 → 这些会变成 Endpoint
        options.SetAuthorizationEndpointUris("connect/authorize")
               .SetTokenEndpointUris("connect/token")
               .SetLogoutEndpointUris("connect/logout")
               .SetUserinfoEndpointUris("connect/userinfo");
        
        // 启用授权码流程（SSO最常用的流程）
        options.AllowAuthorizationCodeFlow();
        
        // 注册加密证书
        options.AddDevelopmentEncryptionCertificate()
               .AddDevelopmentSigningCertificate();
        
        // 使用ASP.NET Core的请求处理器
        options.UseAspNetCore()  // 👈 这是OpenIddict嵌入ASP.NET Core管道的入口
               .EnableAuthorizationEndpointPassthrough()
               .EnableTokenEndpointPassthrough()
               .EnableLogoutEndpointPassthrough();
    })
    .AddValidation(options =>
    {
        options.UseLocalServer();
        options.UseAspNetCore();
    });

// 所有这些 AddXxx() 都只是往 IServiceCollection 里添加 ServiceDescriptor
// 此时没有任何实例被创建

// ==========================================
var app = builder.Build();  // 🔥 DI容器冻结！
// ==========================================

// ==========================================
// 🔥 中间件配置阶段（Build之后、Run之前）
// ==========================================
app.UseHttpsRedirection();
app.UseStaticFiles();

app.UseAuthentication();   // 👈 OpenIddict的Handler在这里被调用
app.UseAuthorization();

app.MapControllers();      // 👈 你的登录页面Controller等

// ==========================================
app.Run();  // 🔥 构建管道 → 启动Kestrel → 开始接受请求
// ==========================================
```

**关键理解：**
- `AddOpenIddict()` → 往DI注册服务（Handler、Store、Manager等）
- `UseAspNetCore()` → 注册 `IAuthenticationHandler`，让认证中间件能找到它
- `UseAuthentication()` → 中间件在运行时调用 OpenIddict 注册的 Handler
- 三者分别对应 **注册阶段、配置阶段、运行阶段**

## 十、检验你的理解

1. **`builder.Build()` 之后再调用 `builder.Services.AddXxx()` 会怎样？**
   （答案：服务不会被注册到已构建的容器中，等于无效操作）

2. **为什么 `GenericWebHostService` 是以 `IHostedService` 的形式启动 Kestrel？**
   （答案：因为在 Generic Host 架构下，Web服务器只是Host上运行的"一个后台服务"，和你自己写的 BackgroundService 地位相同）

3. **HttpContext.RequestServices 的 DI Scope 是在哪里创建的？在哪里释放的？**
   （答案：`HostingApplication.CreateContext()` 创建，`DisposeContext()` 释放）

4. **中间件管道是在 `app.Run()` 时才真正构建的，还是在 `builder.Build()` 时？**
   （答案：在 `app.Run()` → `GenericWebHostService.StartAsync()` → `ApplicationBuilder.Build()` 时才真正构建）

5. **为什么传统的 `Startup.cs` 被取消了？**
   （答案：它只是语法组织方式的变化，底层原理完全一样。`ConfigureServices` 对应 Build 前的服务注册，`Configure` 对应 Build 后的中间件配置）
