# 基建篇：手写 EFConfigurationProvider

## 表结构设计：两种方案

将配置存到数据库，表结构设计有两种流派。

### 方案一：标准键值对模式（Key-Value / EAV）

配置系统底层本质就是扁平字典，键值对模式最直接。

```sql
CREATE TABLE [dbo].[SysConfig] (
    [Id] INT IDENTITY(1,1) PRIMARY KEY,
    [Key] NVARCHAR(255) NOT NULL,
    [Value] NVARCHAR(MAX) NULL,
    [Description] NVARCHAR(500) NULL,
    [ValueType] VARCHAR(50) DEFAULT 'string',
    [IsActive] BIT DEFAULT 1,
    [LastModifiedTime] DATETIME2 DEFAULT GETDATE(),
    [LastModifiedBy] NVARCHAR(100) NULL
);

CREATE UNIQUE NONCLUSTERED INDEX [IX_SysConfig_Key] ON [dbo].[SysConfig]([Key]);
```

- **优点**：极度灵活，新增配置项不需要改表结构，直接 INSERT 一行就行。
- **缺点**：没有类型安全，后台管理界面需要把带冒号的扁平列表反解成树形。

### 方案二：树形邻接表模式（推荐）

用 `ParentId` 构建真正的树形结构，后台管理界面直接用 Tree 组件展示，更直观。

```sql
CREATE TABLE [dbo].[SysConfig] (
    [Id] INT IDENTITY(1,1) PRIMARY KEY,
    [ParentId] INT NULL,               -- 父节点ID，NULL表示根节点
    [NodeName] NVARCHAR(100) NOT NULL,  -- 只存当前节点名
    [Value] NVARCHAR(MAX) NULL,            
    [Description] NVARCHAR(500) NULL,
    
    CONSTRAINT [FK_SysConfig_Parent] FOREIGN KEY ([ParentId]) 
        REFERENCES [dbo].[SysConfig]([Id])
);

-- 数据示例：
-- Id: 1, ParentId: NULL, NodeName: 'JwtSettings', Value: NULL
-- Id: 2, ParentId: 1,    NodeName: 'ExpireDays',  Value: '7'
-- Id: 3, ParentId: 1,    NodeName: 'SecretKey',   Value: 'my-super-secret'
```

代码在 `Load()` 时通过递归把树拼回带冒号的扁平 Key（`JwtSettings:ExpireDays`），对上层完全透明。

## 核心实现：EFConfigurationProvider

配置源 (`ConfigurationProvider`) 的执行时机非常早——在 DI 容器构建之前。这意味着拿不到通过 DI 注入的 `DbContext`，必须手动传入 `DbContextOptions` 来实例化数据库上下文。

```csharp
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Configuration;

public class EFConfigurationProvider : ConfigurationProvider
{
    private readonly Action<DbContextOptionsBuilder> _optionsAction;

    public EFConfigurationProvider(Action<DbContextOptionsBuilder> optionsAction)
    {
        _optionsAction = optionsAction;
    }

    public override void Load()
    {
        var builder = new DbContextOptionsBuilder<MyDbContext>();
        _optionsAction(builder);
        using var dbContext = new MyDbContext(builder.Options);
        
        // 全表拉到内存（配置表通常不大）
        var allConfigs = dbContext.SysConfigs.ToList();
        
        var dataDictionary = new Dictionary<string, string>(StringComparer.OrdinalIgnoreCase);

        // 遍历所有有值的叶子节点
        var leafNodes = allConfigs.Where(c => c.Value != null);
        foreach (var leaf in leafNodes)
        {
            string fullKey = BuildKeyPath(leaf, allConfigs);
            dataDictionary[fullKey] = leaf.Value;
        }

        Data = dataDictionary;
    }

    /// <summary>
    /// 递归方法：从当前节点向上找父节点，用冒号拼接完整路径
    /// </summary>
    private string BuildKeyPath(SysConfig current, List<SysConfig> allNodes)
    {
        if (current.ParentId == null)
            return current.NodeName;

        var parent = allNodes.FirstOrDefault(n => n.Id == current.ParentId);
        if (parent != null)
            return $"{BuildKeyPath(parent, allNodes)}:{current.NodeName}";

        return current.NodeName;
    }

    /// <summary>
    /// 供外部触发热更新
    /// </summary>
    public void ReloadFromDatabase()
    {
        Load();      // 重新查库，覆盖 Data 字典
        OnReload();  // 触发底层 ReloadToken，通知所有 IOptionsMonitor 更新
    }
}
```

不管数据库里存了几层父子关系，最终进入内存的都是标准的 `JwtSettings:ExpireDays` 格式，`IOptions<T>` 绑定逻辑不需要任何修改。

## 封装 ConfigurationSource 与扩展方法

```csharp
public class EFConfigurationSource : IConfigurationSource
{
    private readonly Action<DbContextOptionsBuilder> _optionsAction;
    
    // 暴露 Provider 实例，供后续热更新使用
    public EFConfigurationProvider Provider { get; private set; }

    public EFConfigurationSource(Action<DbContextOptionsBuilder> optionsAction)
    {
        _optionsAction = optionsAction;
    }

    public IConfigurationProvider Build(IConfigurationBuilder builder)
    {
        Provider = new EFConfigurationProvider(_optionsAction);
        return Provider;
    }
}

// 扩展方法
public static class EntityFrameworkExtensions
{
    public static IConfigurationBuilder AddEFConfiguration(
        this IConfigurationBuilder builder, 
        Action<DbContextOptionsBuilder> optionsAction,
        out EFConfigurationSource source)
    {
        source = new EFConfigurationSource(optionsAction);
        return builder.Add(source);
    }
}
```

## 集成 `[DefaultConnectionName]` 特性

`Mok.SqlFactory` 基础库通过自定义特性标记 DbContext 的连接信息。在配置加载阶段，用反射提取特性信息，动态构建 `DbContextOptions`：

```csharp
public static class ConfigurationBuilderExtensions
{
    public static IConfigurationBuilder AddMokDatabaseConfiguration<TContext>(
        this IConfigurationBuilder builder, 
        out EFConfigurationSource<TContext> source) where TContext : DbContext
    {
        // 配置构建阶段只能用 Build() 拿临时配置读 appsettings.json
        var tempConfig = builder.Build();

        // 反射获取 DbContext 上的特性
        var dbContextType = typeof(TContext);
        var attribute = dbContextType.GetCustomAttribute<DefaultConnectionNameAttribute>();
        if (attribute == null)
            throw new InvalidOperationException(
                $"DbContext类型 {dbContextType.Name} 缺少 [DefaultConnectionName] 特性标记");

        var connectionString = tempConfig.GetConnectionString(attribute.ConnectionName);
        if (string.IsNullOrEmpty(connectionString))
            throw new ArgumentException(
                $"配置文件中未找到 ConnectionStrings:{attribute.ConnectionName}");

        // 通过工厂管理器适配不同数据库驱动
        var factory = DatabaseFactoryManager.GetFactory(attribute.DatabaseType);

        Action<DbContextOptionsBuilder> optionsAction = options =>
        {
            factory.Configure(options, connectionString);
        };

        source = new EFConfigurationSource<TContext>(optionsAction);
        return builder.Add(source);
    }
}
```

## PostgreSQL 实体与建表

### C# 实体类

```csharp
using System.ComponentModel.DataAnnotations;
using System.ComponentModel.DataAnnotations.Schema;

namespace Mok.SqlFactory.Models
{
    [Table("app_settings")] 
    public class AppSettings
    {
        [Key]
        [Column("id")]
        public int Id { get; set; }

        [Column("parent_id")]
        public int? ParentId { get; set; }

        [Required]
        [MaxLength(100)]
        [Column("node_name")]
        public string NodeName { get; set; }

        [Column("value")]
        public string Value { get; set; }

        [MaxLength(500)]
        [Column("description")]
        public string Description { get; set; }

        [Column("created_at")]
        public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
    }
}
```

### SSODbContext 注册

```csharp
[DefaultConnectionName("Default", Mok.SqlFactory.Enums.DatabaseType.PostgreSQL)]
public partial class SSODbContext : DbContext
{
    public SSODbContext(DbContextOptions<SSODbContext> options) : base(options) { }

    public DbSet<AppSettings> AppSettings { get; set; }

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        base.OnModelCreating(modelBuilder);

        modelBuilder.Entity<AppSettings>(entity =>
        {
            entity.HasOne<AppSettings>()
                  .WithMany()
                  .HasForeignKey(e => e.ParentId)
                  .OnDelete(DeleteBehavior.Cascade);
        });
    }
}
```

### PostgreSQL 建表脚本

```sql
CREATE TABLE app_settings (
    id SERIAL PRIMARY KEY,
    parent_id INTEGER NULL,
    node_name VARCHAR(100) NOT NULL,
    value TEXT NULL,
    description VARCHAR(500) NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    
    CONSTRAINT fk_app_settings_parent FOREIGN KEY (parent_id) 
        REFERENCES app_settings(id) ON DELETE CASCADE
);

CREATE INDEX idx_app_settings_parent_id ON app_settings(parent_id);

-- 防止同父节点下出现同名子节点
CREATE UNIQUE INDEX idx_app_settings_unique_node ON app_settings(parent_id, node_name) 
    WHERE parent_id IS NOT NULL;
```

## Options 绑定

数据库数据进入内存后，绑定方式和读 JSON 完全一样：

```csharp
// 现代写法
builder.Services.AddOptions<JwtSettings>()
    .BindConfiguration(JwtSettings.SectionName)
    .ValidateDataAnnotations()
    .ValidateOnStart();

// 传统写法
builder.Services.Configure<JwtSettings>(
    builder.Configuration.GetSection("JwtSettings"));
```

::: warning 常见坑：GetSection 不能省
`Configuration.Get<JwtSettings>()` 会去根节点找属性名，找不到 `JwtSettings:SecretKey`。必须先用 `GetSection("JwtSettings")` 定位到对应层级再绑定。
:::

::: warning 常见坑：属性必须有 `set`
`ConfigurationBinder` 通过反射赋值，属性必须是 `public get; set;`，`get; private set;` 或只读属性都绑定不上。
:::
