# 进阶篇：基于 `[AppOption]` 特性的全自动批量服务注册

## 泛型封装：从写死 SSODbContext 到通用组件

要把配置源封装成 `Mok.SqlFactory` 基础类库里的通用组件，需要将硬编码的 `SSODbContext` 替换为泛型 `TContext`。

两个核心难题：

1. **如何实例化未知的 `TContext`？** 不能 `new TContext()`，因为必须传入 `DbContextOptions`，要靠 `Activator.CreateInstance`。
2. **如何获取配置表？** 不能写死 `dbContext.AppSettings`（编译器不认），靠 `dbContext.Set<AppSettings>()` 按实体类型查找。

### EFConfigurationProvider\<TContext\>

```csharp
namespace Mok.SqlFactory.DbAppsettings
{
    public class EFConfigurationProvider<TContext> : ConfigurationProvider 
        where TContext : DbContext 
    {
        private readonly Action<DbContextOptionsBuilder> _optionsAction;

        public EFConfigurationProvider(Action<DbContextOptionsBuilder> optionsAction)
        {
            _optionsAction = optionsAction;
        }

        public override void Load()
        {
            var builder = new DbContextOptionsBuilder<TContext>();
            _optionsAction(builder);

            var dataDictionary = new Dictionary<string, string>(
                StringComparer.OrdinalIgnoreCase);

            try
            {
                // 反射实例化 DbContext
                using var dbContext = (TContext)Activator.CreateInstance(
                    typeof(TContext), builder.Options);

                // Set<T>() 按实体类型查找，不依赖硬编码的属性名
                var allConfigs = dbContext.Set<AppSettings>().ToList();
                var leafNodes = allConfigs.Where(c => c.Value != null);

                foreach (var leaf in leafNodes)
                {
                    string fullKey = BuildKeyPath(leaf, allConfigs);
                    dataDictionary[fullKey] = leaf.Value;
                }
            }
            catch (Exception ex)
            {
                Console.WriteLine(
                    $"[警告] 无法从 {typeof(TContext).Name} 加载配置: {ex.Message}");
            }

            Data = dataDictionary;
        }

        private string BuildKeyPath(AppSettings current, List<AppSettings> allNodes)
        {
            if (current.ParentId == null) return current.NodeName;
            var parent = allNodes.FirstOrDefault(n => n.Id == current.ParentId);
            if (parent != null)
                return $"{BuildKeyPath(parent, allNodes)}:{current.NodeName}";
            return current.NodeName;
        }

        public void ReloadFromDatabase()
        {
            Load();
            OnReload();
        }
    }
}
```

### EFConfigurationSource\<TContext\>

```csharp
namespace Mok.SqlFactory.DbAppsettings
{
    public class EFConfigurationSource<TContext> : IConfigurationSource 
        where TContext : DbContext
    {
        private readonly Action<DbContextOptionsBuilder> _optionsAction;
        public EFConfigurationProvider<TContext> Provider { get; private set; }

        public EFConfigurationSource(Action<DbContextOptionsBuilder> optionsAction)
        {
            _optionsAction = optionsAction;
        }

        public IConfigurationProvider Build(IConfigurationBuilder builder)
        {
            Provider = new EFConfigurationProvider<TContext>(_optionsAction);
            return Provider;
        }
    }
}
```

::: warning 泛型正常运行的前提
`AppSettings` 实体必须在传入的 DbContext 里注册过——声明 `DbSet<AppSettings>` 属性，或在 `OnModelCreating` 中调用 `modelBuilder.Entity<AppSettings>()`。`dbContext.Set<AppSettings>()` 会去当前上下文中寻找这个实体的映射。
:::

## 避开 `BuildServiceProvider` 的陷阱

在 `IServiceCollection` 配置阶段手动调用 `services.BuildServiceProvider()` 是微软明确警告的行为（编译器报 ASP0000 警告），会导致"单例撕裂"和内存泄漏——临时容器里的单例和正式容器里的是两个不同的实例。

正确做法：直接把 `IConfiguration` 当作参数传进扩展方法。

```csharp
// ✅ 正确：从外部传入 IConfiguration
public static IServiceCollection AddDefaultDbContext<TContext>(
    this IServiceCollection services, 
    IConfiguration configuration) where TContext : DbContext
{
    var connectionString = configuration.GetConnectionString(attribute.ConnectionName);
    // ...
}

// ❌ 错误：在内部偷建容器
public static IServiceCollection AddDefaultDbContext<TContext>(
    this IServiceCollection services) where TContext : DbContext
{
    using var sp = services.BuildServiceProvider(); // ASP0000 警告！
    var config = sp.GetService<IConfiguration>();
    // ...
}
```

## 批量 Options 注册：告别手写 AddOptions

当 Options 类超过 3 个，就应该考虑通过反射批量注册。

### 第一步：定义 `[AppOption]` 特性

```csharp
namespace Mok.SqlFactory.Options
{
    [AttributeUsage(AttributeTargets.Class, AllowMultiple = false)]
    public class AppOptionAttribute : Attribute
    {
        public string SectionName { get; }

        public AppOptionAttribute(string sectionName)
        {
            SectionName = sectionName;
        }
    }
}
```

### 第二步：给 Options 类打标签

```csharp
[AppOption("JwtSettings")]
public class JwtSettingsOption
{
    [Required]
    public string SecretKey { get; set; }
    public string Issuer { get; set; }
    public string Audience { get; set; }
    public int ExpireMinutes { get; set; }
}

[AppOption("EmailSettings")]
public class EmailSettingsOption
{
    public string SmtpServer { get; set; }
    public int Port { get; set; }
}
```

以后新增 Options 类，只需要打上 `[AppOption("xxx")]`，注册代码一行都不用改。

### 第三步：反射扫描 + 泛型跳板

`AddOptions<T>()` 是泛型方法，直接反射调用其链式方法很痛苦。技巧是写一个私有泛型辅助方法（"泛型跳板"），再用反射调用它：

```csharp
using System.Reflection;
using Microsoft.Extensions.Configuration;
using Microsoft.Extensions.DependencyInjection;

namespace Mok.SqlFactory.Extensions
{
    public static class OptionsServiceCollectionExtensions
    {
        public static IServiceCollection AddDefaultOptions(
            this IServiceCollection services)
        {
            // 扫描当前程序集，找所有有 [AppOption] 的类
            var assembly = Assembly.GetExecutingAssembly();
            var optionTypes = assembly.GetTypes()
                .Where(t => t.IsClass && !t.IsAbstract 
                    && t.IsDefined(typeof(AppOptionAttribute), false));

            // 拿到私有泛型辅助方法的 MethodInfo
            var registerMethod = typeof(OptionsServiceCollectionExtensions)
                .GetMethod(nameof(RegisterSingleOption), 
                    BindingFlags.NonPublic | BindingFlags.Static);

            foreach (var type in optionTypes)
            {
                var attribute = type.GetCustomAttribute<AppOptionAttribute>();

                // 把 <T> 替换成具体类型，如 <JwtSettingsOption>
                var genericMethod = registerMethod.MakeGenericMethod(type);

                // 执行：等同于 RegisterSingleOption<JwtSettingsOption>(services, "JwtSettings")
                genericMethod.Invoke(null, new object[] { services, attribute.SectionName });
            }

            return services;
        }

        /// <summary>
        /// 泛型跳板方法，封装 AddOptions 链式调用
        /// </summary>
        private static void RegisterSingleOption<TOption>(
            IServiceCollection services, string sectionName) 
            where TOption : class
        {
            services.AddOptions<TOption>()
                .BindConfiguration(sectionName)
                .ValidateDataAnnotations()
                .ValidateOnStart();
        }
    }
}
```

## 反射调用原理拆解

```csharp
genericMethod.Invoke(null, new object[] { services, attribute.SectionName });
```

这行代码等价于直接写 `RegisterSingleOption<JwtSettingsOption>(services, "JwtSettings")`。拆解如下：

| 普通 C# 调用 | 反射对应 |
| :-- | :-- |
| `RegisterSingleOption` | `registerMethod`（MethodInfo） |
| `<JwtSettingsOption>` | `.MakeGenericMethod(typeof(JwtSettingsOption))` |
| 第一个参数 `null` | 因为是 `static` 方法，不属于任何实例 |
| `services, "JwtSettings"` | `new object[] { services, "JwtSettings" }` |

之所以不能写 `RegisterSingleOption<type>(...)`，是因为 C# 的尖括号里只能放编译期确定的类型名，不能放运行时的 `Type` 变量。`MakeGenericMethod` 就是解决这个问题的。

## 最终的 Program.cs

经过五章的架构演进，`Program.cs` 已经简化到极致：

```csharp
using Mok.SqlFactory.Extensions;

var builder = WebApplication.CreateBuilder(args);

// 一行：加载数据库配置 + 注入 DbContext + 开启热更新轮询
builder.AddDefaultDbAndAppSettings<SSODbContext>();

// 一行：批量注册所有带 [AppOption] 的 Options 类
builder.Services.AddDefaultOptions();

builder.Services.AddControllers();

var app = builder.Build();
app.MapControllers();
app.Run();
```

新增一个 Options 类只需要两步：

1. 写一个类，打上 `[AppOption("xxx")]`。
2. 在数据库 `app_settings` 表中插入对应的配置节点数据。

不需要改 `Program.cs`，不需要改扩展方法，不需要重启服务（热更新会自动生效）。
