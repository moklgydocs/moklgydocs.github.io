# 第六章：解题思路方法论

> **SQL 高手和新手最大的差距不是语法，而是"看到题目后的思考路径"。** 这一章教你系统化的解题方法。

---

## 一、五步解题法

```
遇到任何 SQL 题目，按这 5 步走：

Step 1: 确定结果表长什么样
  → 画出最终结果的列名和示例数据
  → 先不管怎么写，只想"我要什么"

Step 2: 确定数据来源
  → 需要哪些表？
  → 表之间什么关系？
  → 需要多表JOIN还是单表就够？

Step 3: 先写最简单版本
  → 不考虑性能
  → 不考虑边界情况
  → 用最笨的方法先出结果

Step 4: 优化SQL
  → 子查询改JOIN？
  → GROUP BY 改窗口函数？
  → 有没有更好的写法？

Step 5: 考虑性能和边界
  → 数据量大时能不能跑？
  → NULL值怎么处理？
  → 有没有除以零的风险？
```

## 二、案例演示：五步法实战

### 题目：找出每个部门薪资排名前3且高于部门平均薪资的员工

```
Step 1: 结果表长什么样？
┌──────────┬──────┬────────┬─────────┬────┐
│ DeptName │ Name │ Salary │ DeptAvg │ Rn │
├──────────┼──────┼────────┼─────────┼────┤
│ IT       │ 张三 │ 15000  │ 12000   │ 1  │
│ IT       │ 王五 │ 13000  │ 12000   │ 2  │
│ HR       │ 钱七 │ 14000  │ 11000   │ 1  │
└──────────┴──────┴────────┴─────────┴────┘

Step 2: 数据来源
  → Employees 表（Name, Salary, DepartmentId）
  → Departments 表（DeptName）
  → 需要 JOIN

Step 3: 先写最简单版本
```

```sql
-- Step 3: 基础版
SELECT 
    d.DeptName, e.Name, e.Salary,
    AVG(e.Salary) OVER(PARTITION BY e.DepartmentId) AS DeptAvg,
    ROW_NUMBER() OVER(PARTITION BY e.DepartmentId ORDER BY e.Salary DESC) AS Rn
FROM Employees e
INNER JOIN Departments d ON e.DepartmentId = d.DepartmentId;

-- 这给了我们所有数据 + 部门平均 + 排名
-- 但还需要过滤
```

```sql
-- Step 4: 加过滤
;WITH Ranked AS (
    SELECT 
        d.DeptName, e.Name, e.Salary,
        AVG(e.Salary) OVER(PARTITION BY e.DepartmentId) AS DeptAvg,
        DENSE_RANK() OVER(PARTITION BY e.DepartmentId ORDER BY e.Salary DESC) AS Rn
    FROM Employees e
    INNER JOIN Departments d ON e.DepartmentId = d.DepartmentId
)
SELECT DeptName, Name, Salary, DeptAvg, Rn
FROM Ranked
WHERE Rn <= 3 AND Salary > DeptAvg
ORDER BY DeptName, Rn;
```

```sql
-- Step 5: 考虑边界
-- Q: 用 ROW_NUMBER 还是 DENSE_RANK？
--   如果两人薪资相同都算第3→ DENSE_RANK
--   如果严格只要3个人→ ROW_NUMBER
-- Q: 部门没有人怎么办？→ INNER JOIN 自然排除
-- Q: Salary 为 NULL？→ 加 WHERE e.Salary IS NOT NULL
```

## 三、中间结果可视化法

```
核心思想：把复杂查询拆成多个CTE，每一步看中间结果

拆分原则：
  1. 每个CTE只做一件事
  2. CTE的名字要有含义
  3. 可以单独SELECT每个CTE验证
```

```sql
-- 题目：计算每个用户的消费等级
--   月消费 > 10000: 钻石
--   月消费 > 5000:  黄金
--   月消费 > 1000:  白银
--   其他:           普通
-- 并统计每个等级的人数和占比

-- Step 1: 算每人月消费
;WITH MonthlySpend AS (
    SELECT UserId, 
           YEAR(OrderDate) AS Y, MONTH(OrderDate) AS M,
           SUM(TotalAmount) AS MonthAmount
    FROM Orders
    WHERE OrderDate >= '2024-01-01' AND OrderDate < '2024-02-01'
    GROUP BY UserId, YEAR(OrderDate), MONTH(OrderDate)
),
-- 验证：SELECT * FROM MonthlySpend ORDER BY MonthAmount DESC;

-- Step 2: 打等级标签
Graded AS (
    SELECT *,
        CASE 
            WHEN MonthAmount > 10000 THEN '钻石'
            WHEN MonthAmount > 5000 THEN '黄金'
            WHEN MonthAmount > 1000 THEN '白银'
            ELSE '普通'
        END AS Grade
    FROM MonthlySpend
),
-- 验证：SELECT * FROM Graded;

-- Step 3: 统计每级人数
Summary AS (
    SELECT Grade, COUNT(*) AS UserCount
    FROM Graded
    GROUP BY Grade
)
-- 验证：SELECT * FROM Summary;

-- Step 4: 算占比
SELECT 
    Grade, UserCount,
    SUM(UserCount) OVER() AS TotalUsers,
    CAST(UserCount * 100.0 / SUM(UserCount) OVER() AS DECIMAL(5,2)) AS Percent
FROM Summary
ORDER BY 
    CASE Grade WHEN '钻石' THEN 1 WHEN '黄金' THEN 2 WHEN '白银' THEN 3 ELSE 4 END;
```

## 四、常见解题模式速查

```
┌──────────────────────┬─────────────────────────────────────┐
│ 题目模式              │ 解法                                 │
├──────────────────────┼─────────────────────────────────────┤
│ 每组取第一条/Top N    │ ROW_NUMBER + 子查询过滤               │
│ 排名（允许并列）      │ DENSE_RANK                           │
│ 累计求和              │ SUM OVER(ORDER BY)                   │
│ 环比/同比             │ LAG / LEAD                           │
│ 连续问题（天数等）    │ 日期 - ROW_NUMBER = 分组              │
│ 行转列               │ PIVOT 或 CASE WHEN                    │
│ 列转行               │ UNPIVOT 或 CROSS APPLY VALUES        │
│ 日期补零              │ 递归CTE生成日期 + LEFT JOIN            │
│ 树形结构              │ 递归CTE                               │
│ 去重保留最新          │ ROW_NUMBER + Rn=1                     │
│ 分组内占比            │ 值/SUM OVER(PARTITION BY)              │
│ 条件聚合              │ SUM(CASE WHEN ... THEN 1 ELSE 0 END)  │
│ 存在/不存在           │ EXISTS / NOT EXISTS（优于IN）          │
│ 第N高/低              │ DENSE_RANK 或 OFFSET                  │
│ 中位数               │ PERCENTILE_CONT(0.5) 或 ROW_NUMBER    │
│ 移动平均              │ AVG OVER(ROWS BETWEEN N PRECEDING)    │
│ 去重计数              │ COUNT(DISTINCT ...)                    │
│ 多条件搜索            │ 动态SQL 或 OR IS NULL + RECOMPILE     │
└──────────────────────┴─────────────────────────────────────┘
```

## 五、多解法对比训练

### 题目：找出没有下过单的客户

```sql
-- 方法1：NOT EXISTS（推荐）
SELECT c.*
FROM Customers c
WHERE NOT EXISTS (
    SELECT 1 FROM Orders o WHERE o.CustomerId = c.CustomerId
);

-- 方法2：LEFT JOIN + IS NULL
SELECT c.*
FROM Customers c
LEFT JOIN Orders o ON c.CustomerId = o.CustomerId
WHERE o.OrderId IS NULL;

-- 方法3：NOT IN（注意NULL陷阱）
SELECT * FROM Customers
WHERE CustomerId NOT IN (
    SELECT CustomerId FROM Orders WHERE CustomerId IS NOT NULL
);
-- ⚠️ 如果子查询结果有NULL，NOT IN 会返回空集！

-- 方法4：EXCEPT
SELECT CustomerId FROM Customers
EXCEPT
SELECT CustomerId FROM Orders;
```

```
性能对比：
  NOT EXISTS  ✅ 推荐，短路求值，遇到第一个匹配就停
  LEFT JOIN   ✅ 性能好，适合大数据量
  NOT IN      ⚠️ 有NULL陷阱，且子查询结果大时性能差
  EXCEPT      ✅ 语义清晰，但只返回指定列
```

## 六、思维训练 —— 倒推法

```
正向思维：从表出发 → JOIN → WHERE → 得到结果
倒推思维：从结果出发 → 需要什么中间数据 → 需要什么原始数据

倒推法步骤：
  1. 画出最终结果
  2. 这个结果需要什么列？
  3. 这些列从哪来？
  4. 需要什么计算/聚合？
  5. 需要什么过滤条件？
  6. 反向组装SQL

这在复杂报表SQL中特别有用。
```

### 示例：部门月度人效报表

```
最终结果长这样：
┌──────┬──────┬──────────┬──────────┬──────────┬────────────┐
│ 部门 │ 月份 │ 人数     │ 总产出   │ 人均产出 │ 环比增长   │
├──────┼──────┼──────────┼──────────┼──────────┼────────────┤
│ IT   │ 3月  │ 15       │ 500000   │ 33333    │ 5.2%       │
│ IT   │ 2月  │ 14       │ 450000   │ 32142    │ -2.1%      │

倒推：
  环比增长 ← 需要本月和上月的人均产出 ← LAG
  人均产出 ← 总产出/人数
  总产出 ← SUM(产出表.Amount) GROUP BY 部门, 月
  人数 ← COUNT(DISTINCT 在职员工) GROUP BY 部门, 月
  部门 ← Departments 表
  月份 ← 可以从产出表的日期提取
```

```sql
;WITH MonthlyOutput AS (
    SELECT DepartmentId,
           YEAR(WorkDate) AS Y, MONTH(WorkDate) AS M,
           COUNT(DISTINCT EmployeeId) AS HeadCount,
           SUM(OutputAmount) AS TotalOutput
    FROM EmployeeOutputs
    GROUP BY DepartmentId, YEAR(WorkDate), MONTH(WorkDate)
)
SELECT 
    d.DeptName AS 部门,
    CONCAT(mo.Y, '年', mo.M, '月') AS 月份,
    mo.HeadCount AS 人数,
    mo.TotalOutput AS 总产出,
    mo.TotalOutput / NULLIF(mo.HeadCount, 0) AS 人均产出,
    CAST(
        (mo.TotalOutput * 1.0 / NULLIF(mo.HeadCount, 0) - 
         LAG(mo.TotalOutput * 1.0 / NULLIF(mo.HeadCount, 0)) OVER(PARTITION BY mo.DepartmentId ORDER BY mo.Y, mo.M))
        * 100.0 / NULLIF(LAG(mo.TotalOutput * 1.0 / NULLIF(mo.HeadCount, 0)) OVER(PARTITION BY mo.DepartmentId ORDER BY mo.Y, mo.M), 0)
    AS DECIMAL(5,2)) AS 环比增长
FROM MonthlyOutput mo
INNER JOIN Departments d ON mo.DepartmentId = d.DepartmentId
ORDER BY d.DeptName, mo.Y DESC, mo.M DESC;
```
