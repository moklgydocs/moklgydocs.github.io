# 响应压缩与缓存

> 压缩减少传输体积，缓存减少重复计算。两者配合，可以显著降低响应时间和带宽成本。压缩解决"传得慢"的问题，缓存解决"算得慢"的问题。理解它们的原理和适用场景，是构建高性能API的关键。

---

## 一、响应压缩中间件

### 1.1 压缩算法对比

| 算法 | 压缩比 | 压缩速度 | 浏览器支持 | 适用场景 |
|------|--------|----------|------------|----------|
| Brotli | 最高（比Gzip高15-25%） | 较慢 | 现代浏览器（95%+） | 静态资源、文本响应 |
| Gzip | 高 | 快 | 几乎100% | 通用压缩 |
| Deflate | 中 | 快 | 几乎100% | 兼容性场景 |

```
Accept-Encoding协商流程：

客户端 → Accept-Encoding: br, gzip, deflate
                                    ↓
服务端 → 选择最优算法（优先Brotli > Gzip > Deflate）
                                    ↓
       Content-Encoding: br
       [压缩后的响应体]
```

### 1.2 Accept-Encoding协商

浏览器通过 `Accept-Encoding` 请求头告知服务端支持的压缩算法。服务端从中选择一种进行压缩，并通过 `Content-Encoding` 响应头告知客户端使用的算法。

```
Accept-Encoding: br, gzip, deflate;q=0.8

含义：
- 支持 br（Brotli）
- 支持 gzip
- 支持 deflate，优先级0.8（较低）
- 未列出的算法不支持
```

### 1.3 MIME类型过滤

不是所有响应都应该压缩。图片、视频等已经是压缩格式的文件，再次压缩不仅不会减小体积，反而可能增大，且浪费CPU。

**应该压缩的MIME类型**：
- `text/html`、`text/plain`、`text/css`、`text/xml`
- `application/json`、`application/xml`
- `application/javascript`、`text/javascript`
- `application/protobuf`（Protobuf本身不一定需要，看数据特征）
- `application/graphql+json`

**不应压缩的MIME类型**：
- `image/jpeg`、`image/png`、`image/webp`（已压缩）
- `video/mp4`、`video/webm`（已压缩）
- `application/pdf`（已压缩）
- `application/zip`、`application/gzip`（已压缩）
- `application/octet-stream`（二进制，效果不确定）

### 1.4 自定义压缩中间件

```csharp
/// <summary>
/// 响应压缩中间件配置
/// </summary>
public class ResponseCompressionOptions
{
    /// <summary>启用的压缩算法，按优先级排序</summary>
    public List<string> Encoders { get; set; } = new() { "br", "gzip" };

    /// <summary>需要压缩的MIME类型</summary>
    public List<string> MimeTypes { get; set; } = new()
    {
        "text/html",
        "text/plain",
        "text/css",
        "text/xml",
        "application/json",
        "application/xml",
        "application/javascript",
        "text/javascript"
    };

    /// <summary>小于此大小（字节）不压缩，默认1KB</summary>
    public int MinimumSize { get; set; } = 1024;

    /// <summary>压缩级别（1-9，越高压缩比越大但越慢）</summary>
    public int CompressionLevel { get; set; } = 6;
}

/// <summary>
/// 自定义响应压缩中间件
/// </summary>
public class CustomResponseCompressionMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ResponseCompressionOptions _options;
    private readonly ILogger<CustomResponseCompressionMiddleware> _logger;

    public CustomResponseCompressionMiddleware(
        RequestDelegate next,
        IOptions<ResponseCompressionOptions> options,
        ILogger<CustomResponseCompressionMiddleware> logger)
    {
        _next = next;
        _options = options.Value;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var acceptEncoding = context.Request.Headers.AcceptEncoding.ToString();

        // 客户端不支持压缩，直接放行
        if (string.IsNullOrEmpty(acceptEncoding))
        {
            await _next(context);
            return;
        }

        // 选择最优编码
        var selectedEncoding = SelectEncoding(acceptEncoding);
        if (selectedEncoding == null)
        {
            await _next(context);
            return;
        }

        // 保存原始响应体
        var originalBody = context.Response.Body;

        try
        {
            // 使用内存流捕获原始响应
            using var memoryStream = new MemoryStream();
            context.Response.Body = memoryStream;

            await _next(context);

            // 检查是否应该压缩
            if (!ShouldCompress(context, memoryStream.Length))
            {
                memoryStream.Seek(0, SeekOrigin.Begin);
                await memoryStream.CopyToAsync(originalBody);
                return;
            }

            // 执行压缩
            context.Response.Headers.ContentEncoding = selectedEncoding;
            context.Response.Headers.Vary = "Accept-Encoding";

            // 移除Content-Length（压缩后长度变化）
            context.Response.Headers.ContentLength = null;

            memoryStream.Seek(0, SeekOrigin.Begin);

            await using var compressionStream = CreateCompressionStream(
                originalBody, selectedEncoding);

            await memoryStream.CopyToAsync(compressionStream);
            await compressionStream.FlushAsync();
        }
        finally
        {
            context.Response.Body = originalBody;
        }
    }

    /// <summary>
    /// 选择最优编码
    /// </summary>
    private string? SelectEncoding(string acceptEncoding)
    {
        foreach (var encoder in _options.Encoders)
        {
            if (acceptEncoding.Contains(encoder, StringComparison.OrdinalIgnoreCase))
            {
                return encoder;
            }
        }
        return null;
    }

    /// <summary>
    /// 判断是否应该压缩
    /// </summary>
    private bool ShouldCompress(HttpContext context, long bodyLength)
    {
        // 检查响应状态码（只压缩成功响应）
        if (context.Response.StatusCode != StatusCodes.Status200OK)
            return false;

        // 检查Content-Type
        var contentType = context.Response.ContentType;
        if (string.IsNullOrEmpty(contentType))
            return false;

        var mimeType = contentType.Split(';')[0].Trim();
        if (!_options.MimeTypes.Any(mt =>
            mt.Equals(mimeType, StringComparison.OrdinalIgnoreCase)))
            return false;

        // 检查大小阈值
        if (bodyLength < _options.MinimumSize)
            return false;

        // 已经压缩过的不再压缩
        if (context.Response.Headers.ContainsKey("Content-Encoding"))
            return false;

        return true;
    }

    /// <summary>
    /// 创建压缩流
    /// </summary>
    private Stream CreateCompressionStream(Stream output, string encoding)
    {
        return encoding.ToLowerInvariant() switch
        {
            "br" => new BrotliStream(output,
                GetCompressionLevel(_options.CompressionLevel), leaveOpen: true),
            "gzip" => new GZipStream(output,
                GetCompressionLevel(_options.CompressionLevel), leaveOpen: true),
            "deflate" => new DeflateStream(output,
                GetCompressionLevel(_options.CompressionLevel), leaveOpen: true),
            _ => output
        };
    }

    private static CompressionLevel GetCompressionLevel(int level) => level switch
    {
        <= 1 => CompressionLevel.Fastest,
        >= 8 => CompressionLevel.SmallestSize,
        _ => CompressionLevel.Optimal
    };
}
```

### 1.5 业务场景：API响应体压缩

一个报表API返回大量JSON数据，单次响应可能达到几百KB：

```csharp
// 开启Brotli + Gzip双压缩
builder.Services.Configure<ResponseCompressionOptions>(options =>
{
    options.Encoders = new List<string> { "br", "gzip" };
    options.MimeTypes = new List<string>
    {
        "application/json",
        "application/grpc"
    };
    options.MinimumSize = 512;  // 512字节以上才压缩
    options.CompressionLevel = 4;  // 中等压缩级别，平衡CPU和压缩比
});
```

实际效果对比：

| API端点 | 原始大小 | Brotli压缩后 | Gzip压缩后 | 节省 |
|---------|----------|-------------|-----------|------|
| GET /api/reports/monthly | 256KB | 28KB | 35KB | 86-89% |
| GET /api/products | 128KB | 15KB | 19KB | 85-88% |
| GET /api/users/list | 64KB | 8KB | 10KB | 84-87% |

## 二、ASP.NET Core内置压缩

### 2.1 基本使用

```csharp
// 注册服务
builder.Services.AddResponseCompression(options =>
{
    options.EnableForHttps = true;  // HTTPS也启用压缩
    options.Providers.Add<BrotliCompressionProvider>();
    options.Providers.Add<GzipCompressionProvider>();
    options.MimeTypes = ResponseCompressionDefaults.MimeTypes.Concat(new[]
    {
        "application/json",
        "application/graphql+json"
    });
});

// 配置压缩级别
builder.Services.Configure<BrotliCompressionProviderOptions>(options =>
{
    options.Level = CompressionLevel.Optimal;
});

builder.Services.Configure<GzipCompressionProviderOptions>(options =>
{
    options.Level = CompressionLevel.Optimal;
});

// 注册中间件
var app = builder.Build();
app.UseResponseCompression();
```

### 2.2 BrotliCompressionProvider

Brotli是Google开发的压缩算法，压缩比比Gzip高15-25%，是现代Web应用的首选压缩算法：

```csharp
builder.Services.Configure<BrotliCompressionProviderOptions>(options =>
{
    // Fastest: 最快压缩，压缩比最低
    // Optimal: 平衡速度和压缩比（推荐）
    // SmallestSize: 最慢压缩，压缩比最高
    options.Level = CompressionLevel.Optimal;
});
```

### 2.3 自定义压缩级别

根据场景选择压缩级别：

| 场景 | 推荐级别 | 理由 |
|------|----------|------|
| 实时API（延迟敏感） | Fastest | CPU时间更重要 |
| 一般API | Optimal | 平衡CPU和带宽 |
| 静态文件预压缩 | SmallestSize | 只压缩一次，长期收益 |
| 移动端API | SmallestSize | 带宽更贵，值得多花CPU |

### 2.4 与自定义实现对比

| 维度 | 内置中间件 | 自定义中间件 |
|------|-----------|-------------|
| 流式压缩 | 支持（不缓冲整个响应） | 需要 |
| 小响应自动跳过 | 支持 | 需手动实现 |
| 自定义Provider | 支持 | 需手动实现 |
| 配置方式 | 声明式 | 命令式 |
| 维护成本 | 无 | 自行维护 |

**建议**：绝大多数场景使用内置中间件即可。自定义实现仅在需要特殊压缩逻辑（如根据用户等级动态选择压缩级别、特定路径的压缩策略）时才有必要。

## 三、响应缓存中间件

### 3.1 基于路径+查询参数的缓存键

缓存键决定"哪些请求共享同一份缓存"。最常用的缓存键是请求路径 + 查询参数：

```
GET /api/products?page=1&size=20
缓存键：GET:/api/products?page=1&size=20

GET /api/products?page=2&size=20
缓存键：GET:/api/products?page=2&size=20

两个不同的缓存键，两份独立的缓存
```

### 3.2 完整响应缓存中间件

```csharp
/// <summary>
/// 响应缓存中间件配置
/// </summary>
public class ResponseCacheMiddlewareOptions
{
    /// <summary>默认缓存过期时间</summary>
    public TimeSpan DefaultExpiration { get; set; } = TimeSpan.FromMinutes(5);

    /// <summary>最大缓存条目数</summary>
    public int MaxCacheEntries { get; set; } = 1000;

    /// <summary>最大缓存体大小（字节）</summary>
    public long MaxResponseBodySize { get; set; } = 1024 * 1024;  // 1MB

    /// <summary>需要缓存的路径模式（支持通配符）</summary>
    public List<string> CachedPaths { get; set; } = new();

    /// <summary>排除缓存的路径</summary>
    public List<string> ExcludedPaths { get; set; } = new();

    /// <summary>VaryBy头部列表（这些头部不同则缓存不同）</summary>
    public List<string> VaryByHeaders { get; set; } = new();

    /// <summary>是否仅缓存GET请求</summary>
    public bool CacheGetOnly { get; set; } = true;

    /// <summary>是否缓存200以外的状态码</summary>
    public bool CacheNon200Responses { get; set; } = false;
}

/// <summary>
/// 响应缓存条目
/// </summary>
public class CachedResponse
{
    public byte[] Body { get; set; } = Array.Empty<byte>();
    public int StatusCode { get; set; }
    public Dictionary<string, string> Headers { get; set; } = new();
    public DateTime ExpiresAt { get; set; }
    public string CacheKey { get; set; } = string.Empty;
}

/// <summary>
/// 响应缓存中间件
/// </summary>
public class ResponseCacheMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ResponseCacheMiddlewareOptions _options;
    private readonly ConcurrentDictionary<string, CachedResponse> _cache = new();
    private readonly ILogger<ResponseCacheMiddleware> _logger;
    private readonly SemaphoreSlim _lock = new(1, 1);

    public ResponseCacheMiddleware(
        RequestDelegate next,
        IOptions<ResponseCacheMiddlewareOptions> options,
        ILogger<ResponseCacheMiddleware> logger)
    {
        _next = next;
        _options = options.Value;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 仅缓存GET请求（可配置）
        if (_options.CacheGetOnly &&
            !HttpMethods.IsGet(context.Request.Method))
        {
            await _next(context);
            return;
        }

        // 检查是否排除路径
        if (IsExcludedPath(context.Request.Path))
        {
            await _next(context);
            return;
        }

        // 检查是否在缓存路径中
        if (_options.CachedPaths.Any() &&
            !IsCachedPath(context.Request.Path))
        {
            await _next(context);
            return;
        }

        // 生成缓存键
        var cacheKey = GenerateCacheKey(context);

        // 尝试从缓存获取
        if (_cache.TryGetValue(cacheKey, out var cached) &&
            cached.ExpiresAt > DateTime.UtcNow)
        {
            await ServeFromCache(context, cached);
            return;
        }

        // 缓存未命中或已过期
        // 使用锁防止缓存穿透时的并发请求全部打到后端
        var acquired = await _lock.WaitAsync(TimeSpan.FromSeconds(5));
        if (!acquired)
        {
            await _next(context);
            return;
        }

        try
        {
            // 双重检查
            if (_cache.TryGetValue(cacheKey, out cached) &&
                cached.ExpiresAt > DateTime.UtcNow)
            {
                await ServeFromCache(context, cached);
                return;
            }

            // 捕获响应
            var originalBody = context.Response.Body;
            using var memoryStream = new MemoryStream();
            context.Response.Body = memoryStream;

            await _next(context);

            // 判断是否应该缓存
            if (ShouldCache(context, memoryStream.Length))
            {
                var entry = new CachedResponse
                {
                    Body = memoryStream.ToArray(),
                    StatusCode = context.Response.StatusCode,
                    Headers = context.Response.Headers
                        .ToDictionary(h => h.Key, h => h.Value.ToString()),
                    ExpiresAt = DateTime.UtcNow.Add(_options.DefaultExpiration),
                    CacheKey = cacheKey
                };

                _cache.TryAdd(cacheKey, entry);

                // 检查缓存数量限制
                if (_cache.Count > _options.MaxCacheEntries)
                {
                    EvictExpiredEntries();
                }
            }

            memoryStream.Seek(0, SeekOrigin.Begin);
            await memoryStream.CopyToAsync(originalBody);
            context.Response.Body = originalBody;
        }
        finally
        {
            _lock.Release();
        }
    }

    /// <summary>
    /// 生成缓存键
    /// </summary>
    private string GenerateCacheKey(HttpContext context)
    {
        var keyBuilder = new StringBuilder();
        keyBuilder.Append(context.Request.Method);
        keyBuilder.Append(':');
        keyBuilder.Append(context.Request.Path);
        keyBuilder.Append('?');
        keyBuilder.Append(context.Request.QueryString);

        // VaryBy Headers
        foreach (var header in _options.VaryByHeaders)
        {
            var value = context.Request.Headers[header].FirstOrDefault();
            keyBuilder.Append($"&{header}={value}");
        }

        return keyBuilder.ToString();
    }

    /// <summary>
    /// 从缓存返回响应
    /// </summary>
    private async Task ServeFromCache(HttpContext context, CachedResponse cached)
    {
        _logger.LogDebug("缓存命中：{Key}", cached.CacheKey);

        context.Response.StatusCode = cached.StatusCode;

        foreach (var header in cached.Headers)
        {
            if (!header.Key.Equals("Content-Length", StringComparison.OrdinalIgnoreCase))
            {
                context.Response.Headers[header.Key] = header.Value;
            }
        }

        context.Response.Headers["X-Cache"] = "HIT";
        await context.Response.Body.WriteAsync(cached.Body);
    }

    private bool ShouldCache(HttpContext context, long bodyLength)
    {
        if (!_options.CacheNon200Responses &&
            context.Response.StatusCode != StatusCodes.Status200OK)
            return false;

        if (bodyLength > _options.MaxResponseBodySize)
            return false;

        // 有Cache-Control: no-cache 或 private 的不缓存
        var cacheControl = context.Response.Headers.CacheControl.ToString();
        if (cacheControl.Contains("no-cache") ||
            cacheControl.Contains("no-store") ||
            cacheControl.Contains("private"))
            return false;

        return true;
    }

    private bool IsExcludedPath(PathString path) =>
        _options.ExcludedPaths.Any(p =>
            path.StartsWithSegments(p, StringComparison.OrdinalIgnoreCase));

    private bool IsCachedPath(PathString path) =>
        _options.CachedPaths.Any(p =>
            path.StartsWithSegments(p, StringComparison.OrdinalIgnoreCase));

    private void EvictExpiredEntries()
    {
        var now = DateTime.UtcNow;
        foreach (var kvp in _cache)
        {
            if (kvp.Value.ExpiresAt <= now)
            {
                _cache.TryRemove(kvp.Key, out _);
            }
        }

        // 如果仍然超限，删除最早过期的
        if (_cache.Count > _options.MaxCacheEntries)
        {
            var toRemove = _cache
                .OrderBy(kvp => kvp.Value.ExpiresAt)
                .Take(_cache.Count - _options.MaxCacheEntries)
                .Select(kvp => kvp.Key)
                .ToList();

            foreach (var key in toRemove)
            {
                _cache.TryRemove(key, out _);
            }
        }
    }
}
```

### 3.3 VaryByHeaders

`VaryByHeaders` 允许根据请求头的不同值缓存不同版本：

```csharp
// 根据Accept-Language缓存不同语言版本
options.VaryByHeaders = new List<string> { "Accept-Language" };

// 请求1: Accept-Language: zh-CN → 缓存版本A
// 请求2: Accept-Language: en-US → 缓存版本B
// 请求3: Accept-Language: zh-CN → 命中版本A
```

### 3.4 缓存过期策略

```csharp
// 不同路径不同过期时间
builder.Services.Configure<ResponseCacheMiddlewareOptions>(options =>
{
    options.CachedPaths = new List<string>
    {
        "/api/dictionaries",      // 字典数据：10分钟
        "/api/reports",           // 报表数据：5分钟
        "/api/config"             // 配置数据：30分钟
    };
    options.DefaultExpiration = TimeSpan.FromMinutes(5);
});
```

### 3.5 缓存穿透/雪崩/击穿防护

| 问题 | 描述 | 防护方案 |
|------|------|----------|
| 缓存穿透 | 查询不存在的数据，缓存永远不命中，请求全部打到后端 | 布隆过滤器 / 缓存空值 |
| 缓存雪崩 | 大量缓存同时过期，瞬间大量请求打到后端 | 过期时间加随机偏移 |
| 缓存击穿 | 热点Key过期瞬间，大量并发请求同时打到后端 | 互斥锁（上面的SemaphoreSlim） |

**缓存空值防护穿透**：

```csharp
// 在ShouldCache中允许缓存404响应
if (_options.CacheNon200Responses == false &&
    context.Response.StatusCode == StatusCodes.Status404NotFound)
{
    // 缓存空值，短过期时间（防止穿透）
    entry.ExpiresAt = DateTime.UtcNow.Add(TimeSpan.FromMinutes(1));
    _cache.TryAdd(cacheKey, entry);
}
```

**随机过期防护雪崩**：

```csharp
// 在设置过期时间时加入随机偏移
var jitter = Random.Shared.Next(0, 60);  // 0-60秒随机偏移
entry.ExpiresAt = DateTime.UtcNow
    .Add(_options.DefaultExpiration)
    .AddSeconds(jitter);
```

### 3.6 业务场景

**场景一：字典数据缓存**

```csharp
options.CachedPaths = new List<string> { "/api/dictionaries" };
options.DefaultExpiration = TimeSpan.FromMinutes(10);
```

字典数据（省份列表、行业分类、银行列表等）更新频率极低，缓存10分钟可以大幅减少数据库查询。

**场景二：报表缓存**

```csharp
options.CachedPaths = new List<string> { "/api/reports" };
options.DefaultExpiration = TimeSpan.FromMinutes(5);
options.MaxResponseBodySize = 5 * 1024 * 1024;  // 5MB
```

月度报表查询耗时可能达到数秒，缓存5分钟让大部分用户命中缓存。

## 四、ASP.NET Core内置缓存

### 4.1 UseResponseCaching

ASP.NET Core 内置了响应缓存中间件，遵循 HTTP 缓存规范（RFC 7234）：

```csharp
// 注册服务
builder.Services.AddResponseCaching();

// 注册中间件
var app = builder.Build();
app.UseResponseCaching();
```

内置中间件的行为：

1. 读取响应的 `Cache-Control` 头
2. 根据 `Cache-Control` 的指令决定是否缓存
3. 后续相同请求直接返回缓存
4. 支持 `Vary` 头区分缓存版本

### 4.2 [ResponseCache] 特性

在 Controller 或 Action 上使用 `ResponseCache` 特性控制缓存行为：

```csharp
[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    // 缓存60秒
    [HttpGet]
    [ResponseCache(Duration = 60)]
    public async Task<IActionResult> GetProducts()
    {
        var products = await _productService.GetAllAsync();
        return Ok(products);
    }

    // 不缓存（私有数据）
    [HttpGet("{id}/orders")]
    [ResponseCache(NoStore = true, Location = ResponseCacheLocation.None)]
    public async Task<IActionResult> GetUserOrders(int id)
    {
        var orders = await _orderService.GetByUserAsync(id);
        return Ok(orders);
    }

    // 按VaryByQueryKeys区分缓存
    [HttpGet("search")]
    [ResponseCache(Duration = 120, VaryByQueryKeys = new[] { "q", "page" })]
    public async Task<IActionResult> Search(string q, int page = 1)
    {
        var results = await _searchService.SearchAsync(q, page);
        return Ok(results);
    }
}
```

`ResponseCache` 参数说明：

| 参数 | 说明 | 示例 |
|------|------|------|
| `Duration` | 缓存时间（秒） | `Duration = 60` |
| `Location` | 缓存位置 | `Any`（默认）、`Client`、`None` |
| `NoStore` | 是否禁用缓存 | `NoStore = true` |
| `VaryByHeader` | 按请求头区分缓存 | `VaryByHeader = "Accept-Language"` |
| `VaryByQueryKeys` | 按查询参数区分缓存 | `VaryByQueryKeys = new[] { "page" }` |
| `CacheProfileName` | 使用命名的缓存配置文件 | `CacheProfileName = "Default30"` |

**缓存配置文件**：在全局定义缓存策略，避免每个Action重复配置：

```csharp
builder.Services.AddControllers(options =>
{
    options.CacheProfiles.Add("Default30", new CacheProfile
    {
        Duration = 30
    });
    options.CacheProfiles.Add("LongCache", new CacheProfile
    {
        Duration = 300,
        Location = ResponseCacheLocation.Any
    });
    options.CacheProfiles.Add("NoCache", new CacheProfile
    {
        NoStore = true
    });
});

// 使用
[HttpGet]
[ResponseCache(CacheProfileName = "Default30")]
public IActionResult GetProducts() => Ok(_products);
```

### 4.3 分布式缓存（Redis）

内存缓存在多实例部署时各实例缓存不共享。使用 Redis 作为分布式缓存可以解决这个问题：

```csharp
// 注册Redis分布式缓存
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = builder.Configuration.GetConnectionString("Redis");
    options.InstanceName = "myapp:cache:";
});
```

**自定义Redis响应缓存**：

```csharp
/// <summary>
/// Redis响应缓存中间件
/// </summary>
public class RedisResponseCacheMiddleware
{
    private readonly RequestDelegate _next;
    private readonly IDistributedCache _cache;
    private readonly ILogger<RedisResponseCacheMiddleware> _logger;
    private readonly TimeSpan _defaultExpiration;

    public RedisResponseCacheMiddleware(
        RequestDelegate next,
        IDistributedCache cache,
        ILogger<RedisResponseCacheMiddleware> logger,
        TimeSpan? defaultExpiration = null)
    {
        _next = next;
        _cache = cache;
        _logger = logger;
        _defaultExpiration = defaultExpiration ?? TimeSpan.FromMinutes(5);
    }

    public async Task InvokeAsync(HttpContext context)
    {
        if (!HttpMethods.IsGet(context.Request.Method))
        {
            await _next(context);
            return;
        }

        var cacheKey = GenerateCacheKey(context);

        // 尝试从Redis获取
        var cachedBytes = await _cache.GetAsync(cacheKey);
        if (cachedBytes != null)
        {
            _logger.LogDebug("Redis缓存命中：{Key}", cacheKey);
            var cached = Deserialize(cachedBytes);
            await ServeFromCache(context, cached);
            return;
        }

        // 捕获响应
        var originalBody = context.Response.Body;
        using var memoryStream = new MemoryStream();
        context.Response.Body = memoryStream;

        await _next(context);

        // 缓存响应
        if (context.Response.StatusCode == StatusCodes.Status200OK)
        {
            var entry = new CachedResponse
            {
                Body = memoryStream.ToArray(),
                StatusCode = context.Response.StatusCode,
                Headers = context.Response.Headers
                    .ToDictionary(h => h.Key, h => h.Value.ToString()),
                ExpiresAt = DateTime.UtcNow.Add(_defaultExpiration),
                CacheKey = cacheKey
            };

            var serialized = Serialize(entry);
            await _cache.SetAsync(cacheKey, serialized,
                new DistributedCacheEntryOptions
                {
                    AbsoluteExpirationRelativeToNow = _defaultExpiration
                });
        }

        memoryStream.Seek(0, SeekOrigin.Begin);
        await memoryStream.CopyToAsync(originalBody);
        context.Response.Body = originalBody;
    }

    private static string GenerateCacheKey(HttpContext context)
    {
        return $"resp:{context.Request.Method}:{context.Request.Path}{context.Request.QueryString}";
    }

    private static async Task ServeFromCache(HttpContext context, CachedResponse cached)
    {
        context.Response.StatusCode = cached.StatusCode;
        foreach (var header in cached.Headers)
        {
            if (!header.Key.Equals("Content-Length", StringComparison.OrdinalIgnoreCase))
            {
                context.Response.Headers[header.Key] = header.Value;
            }
        }
        context.Response.Headers["X-Cache"] = "HIT";
        await context.Response.Body.WriteAsync(cached.Body);
    }

    private static byte[] Serialize(CachedResponse entry) =>
        JsonSerializer.SerializeToUtf8Bytes(entry);

    private static CachedResponse Deserialize(byte[] data) =>
        JsonSerializer.Deserialize<CachedResponse>(data)!;
}
```

### 4.4 缓存策略选择

```
是否需要缓存？
├── 否 → 不使用缓存
└── 是 → 单实例还是多实例？
    ├── 单实例 → 内存缓存（内置ResponseCaching或自定义）
    └── 多实例 → 数据一致性要求？
        ├── 严格一致 → Redis分布式缓存
        └── 最终一致即可 → 内存缓存（各实例独立）
```

| 维度 | 内存缓存 | Redis缓存 |
|------|----------|-----------|
| 性能 | 最快（无网络开销） | 快（Redis通常<1ms） |
| 多实例一致 | 不一致 | 一致 |
| 重启后持久化 | 丢失 | 保留 |
| 内存开销 | 应用内存 | Redis内存 |
| 运维成本 | 无 | Redis运维 |
| 适用场景 | 单实例、非关键缓存 | 多实例、关键缓存 |

## 五、压缩与缓存配合

### 5.1 注册顺序

压缩和缓存中间件的顺序非常重要：

```csharp
var app = builder.Build();

// 1. 响应缓存（先检查缓存）
app.UseResponseCaching();

// 2. 响应压缩（缓存未命中时压缩响应）
app.UseResponseCompression();

app.UseRouting();
app.UseAuthorization();
app.MapControllers();
app.Run();
```

### 5.2 缓存压缩后的响应

缓存压缩后的响应有一个问题：不同客户端支持的压缩算法不同，缓存了Brotli压缩的响应给只支持Gzip的客户端会导致乱码。

解决方案：将 `Accept-Encoding` 纳入缓存键的 `Vary` 头：

```csharp
// 方式1：在响应中设置Vary头
[ResponseCache(Duration = 60, VaryByHeader = "Accept-Encoding")]

// 方式2：在中间件中设置
context.Response.Headers.Vary = "Accept-Encoding";
```

这样，`Accept-Encoding: br` 和 `Accept-Encoding: gzip` 会缓存为两个不同的条目。

### 5.3 性能优化建议

1. **静态文件预压缩**：构建时生成 `.br` 和 `.gz` 文件，运行时直接返回，避免动态压缩的CPU开销
2. **API响应分级缓存**：频繁访问的端点缓存时间长，不频繁的端点缓存时间短
3. **缓存预热**：应用启动时主动请求热点API填充缓存
4. **缓存主动失效**：数据变更时主动删除相关缓存，而不是等过期
