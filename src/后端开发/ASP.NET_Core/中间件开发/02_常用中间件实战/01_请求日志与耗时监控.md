# 请求日志与耗时监控

请求日志和耗时监控是生产环境中最基础也最重要的中间件。它们能帮助你追踪请求、定位性能瓶颈、排查线上问题。本章将从简单实现出发，逐步增强到生产级方案。

## 一、请求日志中间件

### 选项配置

```csharp
/// <summary>
/// 请求日志中间件配置选项
/// </summary>
public class RequestLoggingOptions
{
    /// <summary>
    /// 是否记录请求体
    /// </summary>
    public bool LogRequestBody { get; set; } = false;

    /// <summary>
    /// 是否记录响应体
    /// </summary>
    public bool LogResponseBody { get; set; } = false;

    /// <summary>
    /// 请求体/响应体最大记录字节数
    /// </summary>
    public int MaxBodyLogSize { get; set; } = 4096;

    /// <summary>
    /// 排除的路径（不记录日志）
    /// </summary>
    public HashSet<string> ExcludedPaths { get; set; } = new()
    {
        "/health",
        "/metrics",
        "/favicon.ico"
    };

    /// <summary>
    /// 是否记录用户信息
    /// </summary>
    public bool LogUserInfo { get; set; } = true;
}
```

### 中间件实现

```csharp
/// <summary>
/// 请求日志中间件
/// 记录每个请求的方法、路径、状态码、用户信息等
/// </summary>
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;
    private readonly RequestLoggingOptions _options;

    public RequestLoggingMiddleware(
        RequestDelegate next,
        ILogger<RequestLoggingMiddleware> logger,
        IOptions<RequestLoggingOptions> options)
    {
        _next = next;
        _logger = logger;
        _options = options.Value;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 排除不需要记录的路径
        if (_options.ExcludedPaths.Contains(context.Request.Path.Value))
        {
            await _next(context);
            return;
        }

        // 生成请求ID
        var requestId = Guid.NewGuid().ToString("N")[..8];
        var startTime = DateTime.UtcNow;

        using (_logger.BeginScope(
            "RequestId:{RequestId} Method:{Method} Path:{Path}",
            requestId, context.Request.Method, context.Request.Path))
        {
            // 记录请求信息
            LogRequest(context, requestId);

            try
            {
                await _next(context);
            }
            finally
            {
                var elapsed = DateTime.UtcNow - startTime;

                // 记录响应信息
                LogResponse(context, requestId, elapsed);
            }
        }
    }

    private void LogRequest(HttpContext context, string requestId)
    {
        var userInfo = _options.LogUserInfo ? GetUserInfo(context) : "N/A";

        _logger.LogInformation(
            "请求开始 | ID:{RequestId} | {Method} {Path}{QueryString} | " +
            "用户:{User} | IP:{IP} | Agent:{Agent}",
            requestId,
            context.Request.Method,
            context.Request.Path,
            context.Request.QueryString,
            userInfo,
            GetClientIp(context),
            context.Request.Headers.UserAgent);
    }

    private void LogResponse(HttpContext context, string requestId, TimeSpan elapsed)
    {
        _logger.LogInformation(
            "请求完成 | ID:{RequestId} | 状态码:{StatusCode} | 耗时:{Elapsed}ms",
            requestId,
            context.Response.StatusCode,
            elapsed.TotalMilliseconds);
    }

    private static string GetUserInfo(HttpContext context)
    {
        if (context.User.Identity?.IsAuthenticated == true)
        {
            var name = context.User.Identity.Name ?? "Unknown";
            var userId = context.User.FindFirst(ClaimTypes.NameIdentifier)?.Value ?? "N/A";
            return $"{name}({userId})";
        }
        return "Anonymous";
    }

    private static string GetClientIp(HttpContext context)
    {
        // 优先检查代理转发的真实IP
        var forwardedFor = context.Request.Headers["X-Forwarded-For"].FirstOrDefault();
        if (!string.IsNullOrEmpty(forwardedFor))
        {
            return forwardedFor.Split(',').First().Trim();
        }

        var realIp = context.Request.Headers["X-Real-IP"].FirstOrDefault();
        if (!string.IsNullOrEmpty(realIp))
        {
            return realIp;
        }

        return context.Connection.RemoteIpAddress?.ToString() ?? "Unknown";
    }
}
```

### 扩展方法

```csharp
public static class RequestLoggingMiddlewareExtensions
{
    public static IApplicationBuilder UseRequestLogging(
        this IApplicationBuilder app,
        Action<RequestLoggingOptions>? configure = null)
    {
        var options = new RequestLoggingOptions();
        configure?.Invoke(options);
        return app.UseMiddleware<RequestLoggingMiddleware>(Options.Create(options));
    }
}
```

### 注册使用

```csharp
// Program.cs
builder.Services.Configure<RequestLoggingOptions>(
    builder.Configuration.GetSection("RequestLogging"));

app.UseRequestLogging();
```

### 业务场景：生产环境请求追踪

当用户反馈"我的操作失败了"时，通过请求日志可以：

1. 根据时间范围和用户ID筛选请求
2. 通过 RequestId 追踪完整的请求链路
3. 查看请求的状态码和耗时
4. 关联下游服务的调用日志

## 二、请求耗时监控中间件

### 选项配置

```csharp
/// <summary>
/// 请求耗时监控配置选项
/// </summary>
public class PerformanceMonitorOptions
{
    /// <summary>
    /// 慢请求告警阈值（毫秒）
    /// </summary>
    public double SlowRequestThresholdMs { get; set; } = 3000;

    /// <summary>
    /// 极慢请求告警阈值（毫秒）
    /// </summary>
    public double VerySlowRequestThresholdMs { get; set; } = 10000;

    /// <summary>
    /// 排除的路径
    /// </summary>
    public HashSet<string> ExcludedPaths { get; set; } = new()
    {
        "/health"
    };

    /// <summary>
    /// 是否在响应头中添加耗时信息
    /// </summary>
    public bool AddResponseHeader { get; set; } = false;

    /// <summary>
    /// 响应头名称
    /// </summary>
    public string ResponseHeaderName { get; set; } = "X-Response-Duration";
}
```

### 中间件实现

```csharp
/// <summary>
/// 请求耗时监控中间件
/// 使用 Stopwatch 精确计时，支持慢请求告警
/// </summary>
public class PerformanceMonitorMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<PerformanceMonitorMiddleware> _logger;
    private readonly PerformanceMonitorOptions _options;

    public PerformanceMonitorMiddleware(
        RequestDelegate next,
        ILogger<PerformanceMonitorMiddleware> logger,
        IOptions<PerformanceMonitorOptions> options)
    {
        _next = next;
        _logger = logger;
        _options = options.Value;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 排除不需要监控的路径
        if (_options.ExcludedPaths.Contains(context.Request.Path.Value))
        {
            await _next(context);
            return;
        }

        var stopwatch = Stopwatch.StartNew();

        try
        {
            await _next(context);
        }
        finally
        {
            stopwatch.Stop();
            var elapsedMs = stopwatch.Elapsed.TotalMilliseconds;

            // 记录耗时
            _logger.LogInformation(
                "请求耗时 | {Method} {Path} | {Elapsed:F2}ms | 状态码:{StatusCode}",
                context.Request.Method,
                context.Request.Path,
                elapsedMs,
                context.Response.StatusCode);

            // 慢请求告警
            if (elapsedMs > _options.VerySlowRequestThresholdMs)
            {
                _logger.LogError(
                    "极慢请求告警 | {Method} {Path} | 耗时 {Elapsed:F2}ms " +
                    "超过阈值 {Threshold}ms | 状态码:{StatusCode}",
                    context.Request.Method,
                    context.Request.Path,
                    elapsedMs,
                    _options.VerySlowRequestThresholdMs,
                    context.Response.StatusCode);
            }
            else if (elapsedMs > _options.SlowRequestThresholdMs)
            {
                _logger.LogWarning(
                    "慢请求告警 | {Method} {Path} | 耗时 {Elapsed:F2}ms " +
                    "超过阈值 {Threshold}ms | 状态码:{StatusCode}",
                    context.Request.Method,
                    context.Request.Path,
                    elapsedMs,
                    _options.SlowRequestThresholdMs,
                    context.Response.StatusCode);
            }

            // 在响应头中添加耗时信息（调试用）
            if (_options.AddResponseHeader && !context.Response.HasStarted)
            {
                context.Response.Headers[_options.ResponseHeaderName] =
                    $"{elapsedMs:F2}ms";
            }
        }
    }
}
```

### 业务场景：性能瓶颈定位

当系统响应变慢时，耗时监控中间件可以帮助：

1. **识别慢接口**：通过日志筛选耗时超过阈值的请求
2. **定位瓶颈时段**：结合时间维度分析慢请求的分布
3. **趋势分析**：对比不同时间段的平均耗时变化

```
// 典型告警输出
WARN  请求耗时 | GET /api/reports/monthly | 3500.00ms | 状态码:200
WARN  慢请求告警 | GET /api/reports/monthly | 耗时 3500.00ms 超过阈值 3000ms | 状态码:200
ERROR 极慢请求告警 | POST /api/reports/generate | 耗时 12000.00ms 超过阈值 10000ms | 状态码:200
```

## 三、增强版：请求日志 + 耗时 + 响应体记录

将日志、耗时监控和响应体记录合并为一个增强版中间件，适用于需要完整请求追踪的场景。

### 增强版选项

```csharp
public class EnhancedRequestLoggingOptions
{
    public bool LogRequestBody { get; set; } = false;
    public bool LogResponseBody { get; set; } = false;
    public int MaxBodyLogSize { get; set; } = 4096;
    public double SlowRequestThresholdMs { get; set; } = 3000;
    public HashSet<string> ExcludedPaths { get; set; } = new() { "/health", "/metrics" };
    public HashSet<string> SensitivePaths { get; set; } = new()
    {
        "/api/auth/login",
        "/api/auth/register",
        "/api/users/password"
    };
}
```

### 增强版实现

```csharp
/// <summary>
/// 增强版请求日志中间件
/// 集成请求日志、耗时监控、响应体记录
/// </summary>
public class EnhancedRequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<EnhancedRequestLoggingMiddleware> _logger;
    private readonly EnhancedRequestLoggingOptions _options;

    public EnhancedRequestLoggingMiddleware(
        RequestDelegate next,
        ILogger<EnhancedRequestLoggingMiddleware> logger,
        IOptions<EnhancedRequestLoggingOptions> options)
    {
        _next = next;
        _logger = logger;
        _options = options.Value;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 排除路径
        if (_options.ExcludedPaths.Contains(context.Request.Path.Value))
        {
            await _next(context);
            return;
        }

        var requestId = Guid.NewGuid().ToString("N")[..8];
        var startTime = DateTime.UtcNow;
        var stopwatch = Stopwatch.StartNew();
        var isSensitivePath = _options.SensitivePaths.Any(p =>
            context.Request.Path.StartsWithSegments(p));

        // 如果需要记录请求体，替换请求流
        string? requestBody = null;
        if (_options.LogRequestBody && !isSensitivePath)
        {
            context.Request.EnableBuffering();
            requestBody = await ReadBodyAsync(
                context.Request.Body, _options.MaxBodyLogSize);
            context.Request.Body.Position = 0;
        }

        // 如果需要记录响应体，替换响应流
        Stream? originalResponseBody = null;
        MemoryStream? responseBodyStream = null;
        if (_options.LogResponseBody && !isSensitivePath)
        {
            originalResponseBody = context.Response.Body;
            responseBodyStream = new MemoryStream();
            context.Response.Body = responseBodyStream;
        }

        using (_logger.BeginScope("RequestId:{RequestId}", requestId))
        {
            // 记录请求开始
            _logger.LogInformation(
                "请求开始 | {RequestId} | {Method} {Path}{QueryString} | " +
                "IP:{IP}{RequestBody}",
                requestId,
                context.Request.Method,
                context.Request.Path,
                context.Request.QueryString,
                GetClientIp(context),
                requestBody != null ? $" | Body:{Truncate(requestBody, 500)}" : "");

            try
            {
                await _next(context);
            }
            finally
            {
                stopwatch.Stop();
                var elapsedMs = stopwatch.Elapsed.TotalMilliseconds;

                // 读取响应体
                string? responseBody = null;
                if (responseBodyStream != null && originalResponseBody != null)
                {
                    responseBodyStream.Position = 0;
                    responseBody = await ReadBodyAsync(
                        responseBodyStream, _options.MaxBodyLogSize);
                    responseBodyStream.Position = 0;
                    await responseBodyStream.CopyToAsync(originalResponseBody);
                    context.Response.Body = originalResponseBody;
                    responseBodyStream.Dispose();
                }

                // 构建日志消息
                var logLevel = elapsedMs > _options.SlowRequestThresholdMs
                    ? LogLevel.Warning
                    : LogLevel.Information;

                _logger.Log(logLevel,
                    "请求完成 | {RequestId} | 状态码:{StatusCode} | " +
                    "耗时:{Elapsed:F2}ms{ResponseBody}",
                    requestId,
                    context.Response.StatusCode,
                    elapsedMs,
                    responseBody != null
                        ? $" | Body:{Truncate(responseBody, 500)}"
                        : "");
            }
        }
    }

    /// <summary>
    /// 读取流内容，限制最大字节数
    /// </summary>
    private static async Task<string> ReadBodyAsync(Stream stream, int maxBytes)
    {
        var buffer = new byte[maxBytes];
        var bytesRead = await stream.ReadAsync(buffer, 0, buffer.Length);
        return Encoding.UTF8.GetString(buffer, 0, bytesRead);
    }

    /// <summary>
    /// 截断过长字符串
    /// </summary>
    private static string Truncate(string value, int maxLength)
    {
        if (value.Length <= maxLength) return value;
        return value[..maxLength] + "...(truncated)";
    }

    private static string GetClientIp(HttpContext context)
    {
        var forwardedFor = context.Request.Headers["X-Forwarded-For"].FirstOrDefault();
        if (!string.IsNullOrEmpty(forwardedFor))
            return forwardedFor.Split(',').First().Trim();
        return context.Connection.RemoteIpAddress?.ToString() ?? "Unknown";
    }
}
```

### 敏感路径排除

增强版中间件对敏感路径（登录、注册、修改密码等）自动跳过请求体和响应体记录，避免在日志中泄露密码等敏感信息：

```csharp
public HashSet<string> SensitivePaths { get; set; } = new()
{
    "/api/auth/login",       // 登录接口——包含密码
    "/api/auth/register",    // 注册接口——包含密码
    "/api/users/password",   // 修改密码——包含新旧密码
    "/api/payment/charge",   // 支付接口——包含支付信息
};
```

### 响应体大小限制

记录响应体时务必设置大小限制，原因：

1. **内存占用**：大响应体（如文件下载）会占用大量内存
2. **日志膨胀**：大响应体写入日志导致日志文件急剧增长
3. **性能影响**：复制大流需要额外的 CPU 和 I/O

```csharp
// 合理的配置
options.LogResponseBody = true;
options.MaxBodyLogSize = 4096; // 只记录前4KB

// 不要这样做
options.MaxBodyLogSize = int.MaxValue; // 可能导致OOM
```

### 注意事项：响应体记录的性能影响

记录响应体需要将原始响应流替换为 `MemoryStream`，这会带来性能开销：

| 场景 | 是否记录响应体 | 原因 |
|------|-------------|------|
| API 接口（JSON，通常 < 10KB） | 建议 | 响应体小，方便排查问题 |
| 文件下载接口 | 不建议 | 响应体大，内存占用高 |
| 流式响应（SSE） | 不建议 | 流无法缓冲 |
| 图片/视频接口 | 不建议 | 二进制内容无日志价值 |

```csharp
// 针对不同路径的精细化配置
app.UseEnhancedRequestLogging(options =>
{
    // 全局不记录响应体
    options.LogResponseBody = false;

    // 仅对 API 接口记录响应体（在中间件内通过路径判断）
    options.ResponseBodyPaths = new HashSet<string>
    {
        "/api"
    };
});
```

## 四、与内置日志的对比

ASP.NET Core 提供了内置的 `UseHttpLogging()` 中间件，与自定义实现各有优劣。

### 内置 HttpLogging 中间件

```csharp
// 注册服务
builder.Services.AddHttpLogging(options =>
{
    options.LoggingFields = HttpLoggingFields.RequestMethod
        | HttpLoggingFields.RequestPath
        | HttpLoggingFields.ResponseStatusCode
        | HttpLoggingFields.ElapsedTime;
    options.RequestBodyLogLimit = 4096;
    options.ResponseBodyLogLimit = 4096;
});

// 注册中间件
app.UseHttpLogging();
```

### 对比表

| 维度 | `app.UseHttpLogging()` | 自定义中间件 |
|------|----------------------|-------------|
| **请求ID** | 不支持 | 自定义生成 |
| **用户信息** | 不支持 | 可记录认证用户 |
| **客户端IP** | 不支持 | 可记录真实IP |
| **耗时** | 支持 | 支持（Stopwatch 更精确） |
| **慢请求告警** | 不支持 | 自定义阈值告警 |
| **请求体记录** | 支持 | 支持 |
| **响应体记录** | 支持 | 支持 |
| **敏感路径排除** | 不支持 | 自定义排除列表 |
| **结构化日志** | 有限 | 完全自定义 |
| **配置灵活性** | 有限 | 完全自定义 |
| **代码量** | 零 | 较多 |
| **维护成本** | 零（框架维护） | 需自行维护 |
| **性能开销** | 较低 | 略高（功能更多） |

### 何时用内置

- 快速原型或小项目，不需要复杂日志
- 只需要基本的请求/响应信息
- 不需要用户信息、IP、慢请求告警等功能
- 团队希望减少自定义代码

### 何时自定义

- 生产环境需要完整的请求追踪（RequestID + 用户 + IP）
- 需要慢请求告警和性能监控
- 需要敏感路径排除
- 需要与 ELK、Jaeger 等可观测性系统集成
- 需要自定义日志格式和字段

### 混合方案

```csharp
// 开发环境：使用内置 HttpLogging（简单快速）
if (app.Environment.IsDevelopment())
{
    app.UseHttpLogging();
}
// 生产环境：使用自定义中间件（完整追踪）
else
{
    app.UseRequestLogging();
    app.UsePerformanceMonitor();
}
```

## 小结

- 请求日志中间件记录方法、路径、状态码、用户信息、IP等，是生产环境问题排查的基础
- 耗时监控中间件使用 Stopwatch 计时，配合阈值告警，帮助定位性能瓶颈
- 增强版合并日志+耗时+响应体记录，需注意敏感路径排除和响应体大小限制
- 内置 `UseHttpLogging()` 适合简单场景，自定义中间件适合需要完整追踪的生产环境
- 生产环境推荐混合方案：开发用内置，生产用自定义
