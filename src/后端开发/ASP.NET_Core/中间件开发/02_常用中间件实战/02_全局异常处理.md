# 全局异常处理

全局异常处理是生产环境 API 的必备中间件。没有全局异常处理时，未捕获的异常会导致 500 错误和堆栈信息泄露，既不安全也不友好。本章将从基础实现出发，逐步增强到支持自定义异常映射、ProblemDetails 格式和环境区分的生产级方案。

## 一、为什么需要全局异常处理

### 未处理异常的后果

当 API 抛出未处理的异常时，ASP.NET Core 的默认行为：

```json
// 开发环境默认响应——泄露堆栈信息
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.6.1",
  "title": "Internal Server Error",
  "status": 500,
  "detail": "Sequence contains no elements",
  "exception": {
    "type": "System.InvalidOperationException",
    "message": "Sequence contains no elements",
    "stackTrace": "at System.Linq.Enumerable.First[TSource]...\nat MyApp.Services.OrderService.GetOrder...\nat MyApp.Controllers.OrderController.Get..."
  }
}
```

问题：

1. **安全风险**：堆栈信息暴露了技术栈、代码结构、文件路径
2. **用户体验差**：前端无法从错误响应中提取有用信息
3. **响应格式不统一**：不同接口的异常响应格式可能不同
4. **无法追踪**：没有请求ID，难以关联日志

### 统一错误响应格式的价值

```json
// 统一错误响应格式
{
  "type": "https://httpstatuses.com/404",
  "title": "Not Found",
  "status": 404,
  "detail": "订单 ORD-12345 不存在",
  "traceId": "00-a1b2c3d4e5f6-7g8h9i0j-01"
}
```

价值：

- 前端可以统一解析错误响应
- 不泄露技术细节
- 包含追踪ID，方便排查
- 符合 RFC 7807 ProblemDetails 标准

## 二、基础实现

### 最简单的全局异常处理中间件

```csharp
/// <summary>
/// 基础全局异常处理中间件
/// 捕获所有未处理异常，返回统一格式的错误响应
/// </summary>
public class ExceptionHandlerMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<ExceptionHandlerMiddleware> _logger;

    public ExceptionHandlerMiddleware(
        RequestDelegate next,
        ILogger<ExceptionHandlerMiddleware> _logger)
    {
        _next = next;
        this._logger = _logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            await HandleExceptionAsync(context, ex);
        }
    }

    private async Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        // 记录异常日志
        _logger.LogError(exception,
            "未处理异常 | 路径:{Path} | 方法:{Method} | 异常:{ExceptionType}",
            context.Request.Path,
            context.Request.Method,
            exception.GetType().Name);

        // 检查响应是否已开始
        if (context.Response.HasStarted)
        {
            _logger.LogWarning("响应已开始发送，无法修改错误响应");
            return;
        }

        // 设置响应
        context.Response.StatusCode = 500;
        context.Response.ContentType = "application/problem+json";

        var problemDetails = new
        {
            type = "https://httpstatuses.com/500",
            title = "Internal Server Error",
            status = 500,
            detail = "服务器内部错误，请稍后重试",
            traceId = context.TraceIdentifier
        };

        await context.Response.WriteAsJsonAsync(problemDetails);
    }
}
```

### 关键点：Response.HasStarted 检查

`Response.HasStarted` 是异常处理中间件中最重要的安全检查。当响应已经开始发送（状态码和头部已写入网络流），就不能再修改状态码或头部：

```csharp
if (context.Response.HasStarted)
{
    // 只能记录日志，无法修改响应
    _logger.LogWarning(exception,
        "响应已开始发送，无法修改。路径:{Path}", context.Request.Path);
    return; // 必须 return，不能再写响应
}
```

这个检查在以下场景中尤为重要：

- 中间件在写入响应体过程中抛出异常
- 流式响应（SSE）中途发生错误
- 文件下载过程中断开连接

### 异常类型到 HTTP 状态码映射

基础映射关系：

| 异常类型 | HTTP 状态码 | 说明 |
|---------|-----------|------|
| `ArgumentException` | 400 | 参数验证失败 |
| `ArgumentNullException` | 400 | 必需参数为空 |
| `KeyNotFoundException` | 404 | 资源不存在 |
| `UnauthorizedAccessException` | 401 | 未授权访问 |
| `InvalidOperationException` | 409 | 操作冲突或无效 |
| `TimeoutException` | 504 | 请求超时 |
| 其他异常 | 500 | 未知服务器错误 |

```csharp
private static int GetStatusCode(Exception exception)
{
    return exception switch
    {
        ArgumentException => 400,
        ArgumentNullException => 400,
        KeyNotFoundException => 404,
        UnauthorizedAccessException => 401,
        InvalidOperationException => 409,
        TimeoutException => 504,
        _ => 500
    };
}
```

## 三、增强版实现

### 自定义异常类型

首先定义业务异常类型，方便中间件识别和处理：

```csharp
/// <summary>
/// 业务异常基类
/// </summary>
public class BusinessException : Exception
{
    public int StatusCode { get; }
    public string Code { get; }

    public BusinessException(
        string message,

        string code = "BUSINESS_ERROR") : base(message)
    {
        StatusCode = statusCode;
        Code = code;
    }

/// <summary>
/// 验证异常
/// </summary>
public class ValidationException : BusinessException
{
    public IDictionary<string, string[]> Errors { get; }

        Errors = errors;
    }
}

/// <summary>
/// 资源未找到异常
/// </summary>
public class NotFoundException : BusinessException
{
    public NotFoundException(string resource, object key)
        : base($"{resource} '{key}' 不存在", 404, "NOT_FOUND")
    {
    }
}

/// <summary>
/// 未授权异常
/// </summary>
public class UnauthorizedException : BusinessException
{
    public UnauthorizedException(string message = "未授权访问")
        : base(message, 401, "UNAUTHORIZED")
    {
    }
}

/// <summary>
/// 禁止访问异常
/// </summary>
public class ForbiddenException : BusinessException
{
    public ForbiddenException(string message = "无权执行此操作")
        : base(message, 403, "FORBIDDEN")
    {
    }
}
```

### 自定义异常处理器注册

增强版的核心是支持注册自定义的异常处理器，每种异常类型可以有独立的处理逻辑：

```csharp
/// <summary>
/// 异常处理器委托
/// </summary>
public delegate Task ExceptionHandlerDelegate(
    HttpContext context, Exception exception);

/// <summary>
/// 增强版异常处理中间件配置
/// </summary>
public class ExceptionHandlerOptions
{
    /// <summary>
    /// 异常类型 → 处理器 映射
    /// </summary>
    public Dictionary<Type, ExceptionHandlerDelegate> ExceptionHandlers { get; }
        = new();

    /// <summary>
    /// 默认处理器（处理未注册的异常类型）
    /// </summary>
    public ExceptionHandlerDelegate DefaultHandler { get; set; } = null!;

    /// <summary>
    /// 是否在生产环境隐藏异常详情
    /// </summary>
    public bool HideDetailsInProduction { get; set; } = true;
}
```

### 增强版中间件实现

```csharp
/// <summary>
/// 增强版全局异常处理中间件
/// 支持自定义异常处理器、环境区分、ProblemDetails格式
/// </summary>
public class EnhancedExceptionHandlerMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<EnhancedExceptionHandlerMiddleware> _logger;
    private readonly ExceptionHandlerOptions _options;

    public EnhancedExceptionHandlerMiddleware(
        RequestDelegate next,
        ILogger<EnhancedExceptionHandlerMiddleware> logger,
        IOptions<ExceptionHandlerOptions> options)
    {
        _next = next;
        _logger = logger;
        _options = options.Value;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        try
        {
            await _next(context);
        }
        catch (Exception ex)
        {
            await HandleExceptionAsync(context, ex);
        }
    }

    private async Task HandleExceptionAsync(HttpContext context, Exception exception)
    {
        // 记录异常日志
        _logger.LogError(exception,
            "未处理异常 | 路径:{Path} | 方法:{Method} | 异常类型:{ExceptionType}",
            context.Request.Path,
            context.Request.Method,
            exception.GetType().Name);

        // 检查响应是否已开始
        if (context.Response.HasStarted)
        {
            _logger.LogWarning("响应已开始发送，无法修改错误响应");
            return;
        }

        // 查找匹配的异常处理器
        var handler = FindHandler(exception.GetType());

        if (handler != null)
        {
            await handler(context, exception);
            return;
        }

        // 使用默认处理器
        await _options.DefaultHandler(context, exception);
    }

    /// <summary>
    /// 查找异常处理器（支持异常继承层次）
    /// </summary>
    private ExceptionHandlerDelegate? FindHandler(Type exceptionType)
    {
        var type = exceptionType;
        while (type != null && type != typeof(object))
        {
            if (_options.ExceptionHandlers.TryGetValue(type, out var handler))
            {
                return handler;
            }
            type = type.BaseType;
        }
        return null;
    }
}
```

### 开发/生产环境区分

```csharp
public static class ExceptionHandlerExtensions
{
    public static IApplicationBuilder UseEnhancedExceptionHandler(
        this IApplicationBuilder app,
        Action<ExceptionHandlerOptions>? configure = null)
    {
        var options = new ExceptionHandlerOptions();

        // 注册业务异常处理器
        options.ExceptionHandlers[typeof(ValidationException)] =
            async (ctx, ex) => await HandleValidationException(ctx, (ValidationException)ex);

        options.ExceptionHandlers[typeof(NotFoundException)] =
            async (ctx, ex) => await HandleNotFoundException(ctx, (NotFoundException)ex);

        options.ExceptionHandlers[typeof(UnauthorizedException)] =
            async (ctx, ex) => await HandleUnauthorizedException(ctx, (UnauthorizedException)ex);

        options.ExceptionHandlers[typeof(ForbiddenException)] =
            async (ctx, ex) => await HandleForbiddenException(ctx, (ForbiddenException)ex);

        options.ExceptionHandlers[typeof(BusinessException)] =
            async (ctx, ex) => await HandleBusinessException(ctx, (BusinessException)ex);

        // 根据环境设置默认处理器
        var env = app.ApplicationServices.GetRequiredService<IHostEnvironment>();
        if (env.IsDevelopment())
        {
            options.DefaultHandler = HandleDevelopmentException;
        }
        else
        {
            options.DefaultHandler = HandleProductionException;
        }

        configure?.Invoke(options);

        return app.UseMiddleware<EnhancedExceptionHandlerMiddleware>(
            Options.Create(options));
    }

    // 验证异常 → 400
    private static async Task HandleValidationException(
        HttpContext context, ValidationException exception)
    {
        context.Response.StatusCode = exception.StatusCode;
        context.Response.ContentType = "application/problem+json";

        var problem = new ValidationProblemDetails(exception.Errors)
        {
            Type = "https://httpstatuses.com/400",
            Title = "验证失败",
            Status = 400,
            Detail = "请求参数验证未通过",
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["code"] = exception.Code
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 资源未找到 → 404
    private static async Task HandleNotFoundException(
        HttpContext context, NotFoundException exception)
    {
        context.Response.StatusCode = exception.StatusCode;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/404",
            Title = "资源未找到",
            Status = 404,
            Detail = exception.Message,
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["code"] = exception.Code
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 未授权 → 401
    private static async Task HandleUnauthorizedException(
        HttpContext context, UnauthorizedException exception)
    {
        context.Response.StatusCode = exception.StatusCode;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/401",
            Title = "未授权",
            Status = 401,
            Detail = exception.Message,
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["code"] = exception.Code
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 禁止访问 → 403
    private static async Task HandleForbiddenException(
        HttpContext context, ForbiddenException exception)
    {
        context.Response.StatusCode = exception.StatusCode;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/403",
            Title = "禁止访问",
            Status = 403,
            Detail = exception.Message,
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["code"] = exception.Code
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 业务异常 → 422
    private static async Task HandleBusinessException(
        HttpContext context, BusinessException exception)
    {
        context.Response.StatusCode = exception.StatusCode;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/422",
            Title = "业务错误",
            Status = exception.StatusCode,
            Detail = exception.Message,
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["code"] = exception.Code
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 开发环境：包含异常详情
    private static async Task HandleDevelopmentException(
        HttpContext context, Exception exception)
    {
        context.Response.StatusCode = 500;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/500",
            Title = "Internal Server Error",
            Status = 500,
            Detail = exception.Message,
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier,
                ["stackTrace"] = exception.StackTrace,
                ["exceptionType"] = exception.GetType().Name
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }

    // 生产环境：隐藏异常详情
    private static async Task HandleProductionException(
        HttpContext context, Exception exception)
    {
        context.Response.StatusCode = 500;
        context.Response.ContentType = "application/problem+json";

        var problem = new ProblemDetails
        {
            Type = "https://httpstatuses.com/500",
            Title = "Internal Server Error",
            Status = 500,
            Detail = "服务器内部错误，请稍后重试",
            Instance = context.Request.Path,
            Extensions =
            {
                ["traceId"] = context.TraceIdentifier
            }
        };

        await context.Response.WriteAsJsonAsync(problem);
    }
}
```

## 四、与 ASP.NET Core 内置方案对比

### UseExceptionHandler

ASP.NET Core 内置了 `UseExceptionHandler` 中间件：

```csharp
// 重定向到错误页面（MVC场景）
app.UseExceptionHandler("/Error");

// 使用lambda处理器
app.UseExceptionHandler(appBuilder =>
{
    appBuilder.Run(async context =>
    {
        var exceptionHandlerFeature = context.Features
            .Get<IExceptionHandlerFeature>();
        var exception = exceptionHandlerFeature?.Error;

        context.Response.StatusCode = 500;
        context.Response.ContentType = "application/problem+json";

        await context.Response.WriteAsJsonAsync(new ProblemDetails
        {
            Title = "Internal Server Error",
            Status = 500,
            Detail = exception?.Message
        });
    });
});
```

### UseDeveloperExceptionPage

开发环境专用的异常页面：

```csharp
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}
```

### 对比表

| 维度 | `UseExceptionHandler` | `UseDeveloperExceptionPage` | 自定义中间件 |
|------|----------------------|---------------------------|-------------|
| **异常类型映射** | 手动判断 | 自动展示 | 注册表自动映射 |
| **ProblemDetails** | 手动构造 | 不支持 | 自动生成 |
| **环境区分** | 需手动 | 仅开发环境 | 内置支持 |
| **自定义异常** | 手动判断 | 不支持 | 按类型自动分发 |
| **响应已开始** | 不检查 | 不检查 | 检查 HasStarted |
| **结构化日志** | 需手动 | 不支持 | 自动记录 |
| **代码量** | 较少 | 一行 | 较多 |
| **灵活性** | 中等 | 低 | 最高 |

### 何时用内置

- 简单的 MVC/Razor Pages 应用，重定向到错误页面即可
- 只需要基本的异常捕获，不需要区分异常类型
- 快速原型

### 何时自定义

- API 应用，需要统一的 JSON 错误响应格式
- 需要区分不同异常类型并返回不同状态码
- 需要 ProblemDetails 标准格式
- 需要与日志系统集成
- 需要请求ID关联

### 混合方案

```csharp
// 开发环境：详细错误页面
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}
// 生产环境：自定义异常处理
else
{
    app.UseEnhancedExceptionHandler();
}
```

## 五、业务场景

### 场景1：API 统一错误响应格式

所有 API 接口返回统一的错误格式，前端只需一套错误处理逻辑：

```csharp
// 控制器抛出业务异常
[HttpGet("{id}")]
public async Task<OrderDto> GetOrder(int id)
{
    var order = await _orderService.GetByIdAsync(id);
    if (order == null)
        throw new NotFoundException("订单", id);

    return order;
}

// 响应
// HTTP 404
{
    "type": "https://httpstatuses.com/404",
    "title": "资源未找到",
    "status": 404,
    "detail": "订单 '123' 不存在",
    "instance": "/api/orders/123",
    "traceId": "00-a1b2c3d4-567890-01",
    "code": "NOT_FOUND"
}
```

前端统一处理：

```typescript
// Axios 拦截器
axios.interceptors.response.use(
    response => response,
    error => {
        const problem = error.response.data;
        switch (problem.status) {
            case 400:
                // 验证错误，展示字段级错误
                showValidationErrors(problem.errors);
                break;
            case 401:
                // 跳转登录
                router.push('/login');
                break;
            case 403:
                // 显示无权限提示
                showForbiddenMessage(problem.detail);
                break;
            case 404:
                // 显示资源不存在
                showNotFoundMessage(problem.detail);
                break;
            case 422:
                // 业务错误
                showBusinessError(problem.detail);
                break;
            default:
                // 未知错误
                showGenericError('操作失败，请稍后重试');
        }
        // 所有错误都有 traceId，可以展示给用户用于反馈
        console.error(`错误追踪ID: ${problem.traceId}`);
        return Promise.reject(error);
    }
);
```

### 场景3：业务异常自动返回 422

```csharp
// 业务规则检查
public class OrderService
{
    public async Task CancelOrder(int orderId)
    {
        var order = await _repository.GetByIdAsync(orderId)
            ?? throw new NotFoundException("订单", orderId);

        // 业务规则：已发货的订单不能取消
        if (order.Status == OrderStatus.Shipped)
            throw new BusinessException(
                "已发货的订单不能取消",
                422,
                "ORDER_ALREADY_SHIPPED");

        // 业务规则：超过30天的订单不能取消
        if (order.CreatedAt < DateTime.UtcNow.AddDays(-30))
            throw new BusinessException(
                "超过30天的订单不能取消",
                422,
                "ORDER_TOO_OLD_TO_CANCEL");

        order.Status = OrderStatus.Cancelled;
        await _repository.UpdateAsync(order);
    }
}

// 响应
// HTTP 422
{
    "type": "https://httpstatuses.com/422",
    "title": "业务错误",
    "status": 422,
    "detail": "已发货的订单不能取消",
    "instance": "/api/orders/123/cancel",
    "traceId": "00-12345678-abcdef-01",
    "code": "ORDER_ALREADY_SHIPPED"
}
```

## 完整注册模板

```csharp
// Program.cs
var builder = WebApplication.CreateBuilder(args);

// 注册服务
builder.Services.AddControllers();
builder.Services.AddProblemDetails(); // 启用 ProblemDetails 支持

var app = builder.Build();

// 异常处理中间件（必须第一个注册）
app.UseEnhancedExceptionHandler(options =>
{
    // 可选：注册自定义异常处理器
    options.ExceptionHandlers[typeof(DbUpdateConcurrencyException)] =
        async (ctx, ex) =>
        {
            ctx.Response.StatusCode = 409;
            ctx.Response.ContentType = "application/problem+json";
            await ctx.Response.WriteAsJsonAsync(new ProblemDetails
            {
                Type = "https://httpstatuses.com/409",
                Title = "并发冲突",
                Status = 409,
                Detail = "数据已被其他用户修改，请刷新后重试",
                Instance = ctx.Request.Path,
                Extensions = { ["traceId"] = ctx.TraceIdentifier }
            });
        };
});

// 其他中间件...
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();

app.MapControllers();

app.Run();
```

## 小结

- 全局异常处理是生产 API 的必备组件，防止堆栈信息泄露并提供统一错误格式
- 基础实现：try-catch 包装 + `Response.HasStarted` 检查 + 状态码映射
- 增强版：自定义异常处理器注册 + 环境区分 + ProblemDetails 格式 + 请求ID关联
- 内置 `UseExceptionHandler` 适合简单场景，自定义中间件适合需要精细控制的 API
- 推荐使用 `BusinessException` 体系：验证异常→400、未找到→404、未授权→401、禁止→403、业务错误→422
