# 编写中间件的三种方式

ASP.NET Core 提供了三种编写中间件的方式，各有适用场景。本章将从最简单的内联中间件出发，逐步介绍约定式类和 `IMiddleware` 接口，最后进行对比与选型指导。

## 方式1：内联中间件（app.Use）

内联中间件是最简单的编写方式，直接在 `Program.cs` 中使用 `app.Use` 注册一个匿名委托：

```csharp
app.Use(async (context, next) =>
{
    // 前处理
    var startTime = DateTime.UtcNow;
    Console.WriteLine($"[{startTime:HH:mm:ss}] 请求开始: {context.Request.Path}");

    // 调用下一个中间件
    await next(context);

    // 后处理
    var elapsed = DateTime.UtcNow - startTime;
    Console.WriteLine($"请求耗时: {elapsed.TotalMilliseconds}ms");
});
```

### 在 .NET 6+ 中的简化写法

.NET 6 引入了不带 `next` 参数的重载，此时无法调用后续中间件，相当于终端中间件：

```csharp
// .NET 6+ 简化写法——无法调用 next
app.Use(async context =>
{
    await context.Response.WriteAsync("Hello from inline middleware");
});
```

::: warning 注意区分
`app.Use(async (context, next) => { ... })` 有 `next` 参数，可以调用后续中间件。`app.Use(async context => { ... })` 没有 `next` 参数，无法调用后续中间件。两者签名不同，行为也不同。
:::

### 内联中间件的局限

- 无法通过依赖注入获取服务（只能从 `context.RequestServices` 解析）
- 无法在构造函数中注入配置
- 逻辑复杂时会让 `Program.cs` 变得臃肿
- 不利于测试和复用

## 方式2：约定式中间件类

约定式中间件是最常用的方式。它遵循特定的约定，不需要实现任何接口，ASP.NET Core 会通过反射来识别和激活。

### 约定规则

1. 类必须有公开的构造函数，构造函数的第一个参数必须是 `RequestDelegate`
2. 类必须有公开的 `InvokeAsync` 方法，第一个参数必须是 `HttpContext`
3. `InvokeAsync` 方法的后续参数会通过依赖注入自动解析

### 基本实现

```csharp
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestLoggingMiddleware> _logger;

    // 构造函数：第一个参数是下一个中间件，其余通过DI注入
    public RequestLoggingMiddleware(
        RequestDelegate next,
        ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    // InvokeAsync：第一个参数是 HttpContext，其余通过DI注入
    public async Task InvokeAsync(HttpContext context)
    {
        var startTime = DateTime.UtcNow;
        var requestId = Guid.NewGuid().ToString("N")[..8];

        using (_logger.BeginScope("RequestId: {RequestId}", requestId))
        {
            _logger.LogInformation(
                "请求开始: {Method} {Path}",
                context.Request.Method,
                context.Request.Path);

            try
            {
                await _next(context);
            }
            finally
            {
                var elapsed = DateTime.UtcNow - startTime;
                _logger.LogInformation(
                    "请求完成: {StatusCode} 耗时 {Elapsed}ms",
                    context.Response.StatusCode,
                    elapsed.TotalMilliseconds);
            }
        }
    }
}
```

### 注册方式

```csharp
// 方式1：直接使用 UseMiddleware
app.UseMiddleware<RequestLoggingMiddleware>();

// 方式2：通过扩展方法（推荐）
```

### 扩展方法封装

推荐为中间件创建扩展方法，使注册更简洁、更符合 ASP.NET Core 风格：

```csharp
public static class RequestLoggingMiddlewareExtensions
{
    public static IApplicationBuilder UseRequestLogging(
        this IApplicationBuilder builder)
    {
        return builder.UseMiddleware<RequestLoggingMiddleware>();
    }

    // 支持配置选项
    public static IApplicationBuilder UseRequestLogging(
        this IApplicationBuilder builder,
        Action<RequestLoggingOptions> configureOptions)
    {
        var options = new RequestLoggingOptions();
        configureOptions(options);

        return builder.UseMiddleware<RequestLoggingMiddleware>(options);
    }
}

// 使用
app.UseRequestLogging();
// 或者带配置
app.UseRequestLogging(options =>
{
    options.LogRequestBody = true;
    options.MaxBodyLogSize = 4096;
});
```

### 构造函数注入 vs InvokeAsync 注入

约定式中间件有两种注入点：构造函数和 `InvokeAsync` 方法参数。

```csharp
public class MyMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ISingletonService _singletonService; // 构造函数注入

    public MyMiddleware(
        RequestDelegate next,
        ISingletonService singletonService) // 构造函数：Singleton 服务
    {
        _next = next;
        _singletonService = singletonService;
    }

    public async Task InvokeAsync(
        HttpContext context,
        IScopedService scopedService,      // InvokeAsync：Scoped 服务
        ITransientService transientService) // InvokeAsync：Transient 服务
    {
        // 使用注入的服务
        await _next(context);
    }
}
```

::: important 注入选择原则
- **构造函数**：注入 Singleton 服务。中间件本身是 Singleton，构造函数中只能安全地注入 Singleton 服务
- **InvokeAsync 参数**：注入 Scoped / Transient 服务。因为 `InvokeAsync` 在每次请求时调用，此时存在有效的 Scoped 容器
- 如果在构造函数中注入 Scoped 服务，会抛出异常：`Cannot consume scoped service from singleton`
:::

## 方式3：IMiddleware 接口（工厂激活）

`IMiddleware` 是一种更正式的中间件编写方式，通过 `IMiddlewareFactory` 激活，支持完整的依赖注入生命周期。

### 接口定义

```csharp
public interface IMiddleware
{
    Task InvokeAsync(HttpContext context, RequestDelegate next);
}
```

### 实现

```csharp
public class ApiKeyMiddleware : IMiddleware
{
    private readonly IConfiguration _configuration;
    private readonly ILogger<ApiKeyMiddleware> _logger;

    // 构造函数可以自由注入任何生命周期的服务
    public ApiKeyMiddleware(
        IConfiguration configuration,
        ILogger<ApiKeyMiddleware> logger)
    {
        _configuration = configuration;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context, RequestDelegate next)
    {
        if (!context.Request.Headers.TryGetValue("X-Api-Key", out var apiKey))
        {
            context.Response.StatusCode = 401;
            await context.Response.WriteAsJsonAsync(new { error = "缺少 API 密钥" });
            return;
        }

        var validKey = _configuration["ApiKey"];
        if (apiKey != validKey)
        {
            _logger.LogWarning("无效的 API 密钥: {ApiKey}", apiKey);
            context.Response.StatusCode = 403;
            await context.Response.WriteAsJsonAsync(new { error = "API 密钥无效" });
            return;
        }

        await next(context);
    }
}
```

### 必须注册服务

`IMiddleware` 方式有一个关键要求：**必须在 DI 容器中注册中间件类**。

```csharp
// 必须注册！否则运行时抛出异常
builder.Services.AddScoped<ApiKeyMiddleware>();

// 然后注册中间件
app.UseMiddleware<ApiKeyMiddleware>();
```

::: warning 不注册会报错
忘记注册 `IMiddleware` 实现类时，运行时会抛出异常：
`No service for type 'ApiKeyMiddleware' has been registered.`
这是 `IMiddleware` 方式最常见的坑。
:::

### IMiddleware 的生命周期

由于 `IMiddleware` 是通过 DI 容器激活的，它的生命周期由注册时决定：

```csharp
// Scoped 生命周期——每个请求创建新实例
builder.Services.AddScoped<ApiKeyMiddleware>();

// Transient 生命周期——每次解析创建新实例
builder.Services.AddTransient<ApiKeyMiddleware>();

// Singleton 生命周期——应用启动时创建，所有请求共享
builder.Services.AddSingleton<ApiKeyMiddleware>();
```

推荐使用 **Scoped** 生命周期，这样每个请求有独立的中间件实例，可以在中间件内部安全地使用 Scoped 服务而不必放到 `InvokeAsync` 参数中。

## 三种方式对比

| 维度 | 内联中间件 | 约定式类 | IMiddleware |
|------|-----------|---------|------------|
| **代码位置** | Program.cs 内联 | 独立类文件 | 独立类文件 |
| **DI 支持** | 仅 RequestServices | 构造函数 + InvokeAsync | 完整 DI（构造函数） |
| **Scoped 服务注入** | 需手动从 RequestServices 解析 | InvokeAsync 参数 | 构造函数直接注入 |
| **需要注册服务** | 否 | 否 | 是 |
| **生命周期控制** | 无（始终 Singleton） | 无（始终 Singleton） | 可选 Scoped/Transient/Singleton |
| **配置选项** | 闭包捕获 | 构造函数传入 | 构造函数注入 |
| **可测试性** | 差 | 好 | 最好 |
| **复用性** | 差 | 好 | 好 |
| **性能** | 最好 | 好 | 略差（工厂激活） |
| **复杂度** | 最低 | 中等 | 中等 |
| **适用场景** | 简单逻辑、原型验证 | 生产环境通用 | 需要 Scoped 生命周期 |

### 性能差异说明

- **内联中间件**：无反射开销，直接调用委托
- **约定式中间件**：首次激活时使用反射，后续缓存，运行时性能接近内联
- **IMiddleware 中间件**：每次请求通过 DI 容器激活，有轻微的容器解析开销

对于绝大多数应用，这个性能差异可以忽略不计。只有在极端高吞吐场景（百万级 QPS）下才需要考虑。

## 扩展方法封装模式

无论使用哪种方式，都推荐通过扩展方法封装中间件的注册：

```csharp
public static class MiddlewareExtensions
{
    // 约定式中间件的扩展方法
    public static IApplicationBuilder UseRequestLogging(
        this IApplicationBuilder app,
        Action<RequestLoggingOptions>? configure = null)
    {
        var options = new RequestLoggingOptions();
        configure?.Invoke(options);
        return app.UseMiddleware<RequestLoggingMiddleware>(options);
    }

    // IMiddleware 中间件的扩展方法
    public static IApplicationBuilder UseApiKeyAuth(
        this IApplicationBuilder app)
    {
        return app.UseMiddleware<ApiKeyMiddleware>();
    }

    // 对应的服务注册扩展方法
    public static IServiceCollection AddApiKeyAuth(
        this IServiceCollection services)
    {
        services.AddScoped<ApiKeyMiddleware>();
        return services;
    }
}
```

在 `Program.cs` 中使用：

```csharp
// 注册服务
builder.Services.AddApiKeyAuth();

// 注册中间件
app.UseRequestLogging(options =>
{
    options.LogRequestBody = true;
});
app.UseApiKeyAuth();
```

### 选项模式集成

对于需要配置的中间件，推荐使用 `IOptions<T>` 模式：

```csharp
public class RequestLoggingOptions
{
    public bool LogRequestBody { get; set; } = false;
    public bool LogResponseBody { get; set; } = false;
    public int MaxBodyLogSize { get; set; } = 4096;
    public HashSet<string> ExcludedPaths { get; set; } = new() { "/health", "/metrics" };
}

// 约定式中间件通过构造函数接收
public class RequestLoggingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly RequestLoggingOptions _options;
    private readonly ILogger<RequestLoggingMiddleware> _logger;

    public RequestLoggingMiddleware(
        RequestDelegate next,
        IOptions<RequestLoggingOptions> options,
        ILogger<RequestLoggingMiddleware> logger)
    {
        _next = next;
        _options = options.Value;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        // 使用 _options 配置
        if (_options.ExcludedPaths.Contains(context.Request.Path))
        {
            await _next(context);
            return;
        }
        // ... 日志逻辑
    }
}

// 注册
builder.Services.Configure<RequestLoggingOptions>(
    builder.Configuration.GetSection("RequestLogging"));
app.UseMiddleware<RequestLoggingMiddleware>();
```

## 何时用哪种

### 选择内联中间件

- 逻辑极其简单（1-5 行代码）
- 快速原型验证
- 不需要 DI 和配置
- 一次性使用的特殊逻辑

```csharp
// 示例：简单的维护模式
app.Use(async (context, next) =>
{
    if (builder.Configuration["MaintenanceMode"] == "true"
        && !context.Request.Path.StartsWithSegments("/admin"))
    {
        context.Response.StatusCode = 503;
        return;
    }
    await next(context);
});
```

### 选择约定式中间件

- 大多数生产环境场景
- 需要通过 `InvokeAsync` 参数注入 Scoped 服务
- 中间件逻辑较复杂
- 性能敏感场景

### 选择 IMiddleware

- 中间件内部需要大量 Scoped 服务
- 想利用 DI 容器的完整生命周期管理
- 中间件需要实现 `IDisposable` 清理资源
- 团队偏好显式接口约束

```csharp
// IMiddleware 配合 IDisposable 的典型场景
public class DbAuditMiddleware : IMiddleware, IDisposable
{
    private readonly AuditDbContext _dbContext;

    public DbAuditMiddleware(AuditDbContext dbContext)
    {
        _dbContext = dbContext;
    }

    public async Task InvokeAsync(HttpContext context, RequestDelegate next)
    {
        await next(context);

        // 请求结束后记录审计日志
        _dbContext.AuditLogs.Add(new AuditLog
        {
            Path = context.Request.Path,
            Method = context.Request.Method,
            StatusCode = context.Response.StatusCode,
            Timestamp = DateTime.UtcNow
        });
        await _dbContext.SaveChangesAsync();
    }

    public void Dispose()
    {
        _dbContext?.Dispose();
    }
}
```

## 小结

- **内联中间件**最简单，适合简单逻辑和原型，但不利于复用和测试
- **约定式中间件**最常用，支持构造函数和 `InvokeAsync` 双注入点，性能好
- **IMiddleware** 方式支持完整 DI 生命周期管理，适合需要 Scoped 服务或资源清理的场景
- 务必通过扩展方法封装中间件注册，保持 `Program.cs` 简洁
- 选型原则：简单用内联，通用用约定式，需要 Scoped 生命周期用 IMiddleware
