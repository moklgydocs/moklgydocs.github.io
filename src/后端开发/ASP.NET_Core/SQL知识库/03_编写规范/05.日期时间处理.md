# 日期时间处理

日期查询是线上 Bug 的重灾区。"查 1 月份的数据少了最后一天""时间比较差了 8 小时""闰年 2 月 29 日报错"——全是日期处理不规范导致的。

## 日期类型选哪个

| 类型 | 范围 | 精度 | 存储 | 推荐 |
|------|------|------|------|------|
| DATE | 0001-01-01 ~ 9999-12-31 | 天 | 3 字节 | ✅ 只存日期 |
| TIME | 00:00:00 ~ 23:59:59.9999999 | 100ns | 3-5 字节 | 只存时间 |
| DATETIME | 1753-01-01 ~ 9999-12-31 | 3.33ms | 8 字节 | ⚠️ 老项目常用 |
| DATETIME2 | 0001-01-01 ~ 9999-12-31 | 100ns | 6-8 字节 | ✅ 推荐 |
| DATETIMEOFFSET | 同上 + 时区偏移 | 100ns | 8-10 字节 | 跨时区场景 |
| SMALLDATETIME | 1900-01-01 ~ 2079-06-06 | 分钟 | 4 字节 | 不推荐 |

**新项目统一用 `DATETIME2(3)`**（精确到毫秒，够用了），别用 DATETIME。

```sql
-- DATETIME2(3) = 精确到毫秒，7 字节
CREATE TABLE Orders (
    CreateTime DATETIME2(3) NOT NULL DEFAULT SYSDATETIME()
);
```

为什么不用 DATETIME？
- DATETIME 精度只到 3.33 毫秒（会四舍五入到 .000/.003/.007）
- `'2024-01-01 23:59:59.999'` 用 DATETIME 存会被四舍五入到 `2024-01-02 00:00:00`

## 日期查询的正确写法

### 查某一天的数据

```sql
-- ❌ 有时间部分的数据可能漏掉
SELECT * FROM Orders WHERE CreateTime = '2024-01-15';

-- ❌ CONVERT 包函数，索引失效
SELECT * FROM Orders WHERE CONVERT(DATE, CreateTime) = '2024-01-15';

-- ✅ 用范围查询
SELECT * FROM Orders
WHERE CreateTime >= '2024-01-15'
  AND CreateTime < '2024-01-16';
```

### 查某个月的数据

```sql
-- ❌
SELECT * FROM Orders WHERE YEAR(CreateTime) = 2024 AND MONTH(CreateTime) = 1;

-- ✅
SELECT * FROM Orders
WHERE CreateTime >= '2024-01-01'
  AND CreateTime < '2024-02-01';
```

### 查某一年的数据

```sql
SELECT * FROM Orders
WHERE CreateTime >= '2024-01-01'
  AND CreateTime < '2025-01-01';
```

**核心原则**：永远用 **`>= 开始 AND < 结束`** 的半开区间。不要用 `BETWEEN`，不要用 `<=`。

为什么不用 BETWEEN：
```sql
-- BETWEEN 包含两端
WHERE CreateTime BETWEEN '2024-01-01' AND '2024-01-31'
-- 这漏掉了 1 月 31 日有时间部分的数据（比如 2024-01-31 10:30:00）
-- 而且你还得算每个月有几天（2月 28/29？）
```

## 常用日期函数

### 获取当前时间

```sql
GETDATE()        -- DATETIME 类型
SYSDATETIME()    -- DATETIME2 类型，精度更高
GETUTCDATE()     -- UTC 时间
SYSUTCDATETIME() -- UTC DATETIME2
```

### DATEADD：日期加减

```sql
DATEADD(DAY, 7, GETDATE())      -- 7 天后
DATEADD(MONTH, -1, GETDATE())   -- 1 个月前
DATEADD(HOUR, 8, GETUTCDATE())  -- UTC + 8 小时
```

### DATEDIFF：日期差

```sql
DATEDIFF(DAY, '2024-01-01', '2024-03-15')    -- 相差 74 天
DATEDIFF(MONTH, '2024-01-15', '2024-03-10')  -- 相差 2 个月（只看月份差，不看天）
DATEDIFF(YEAR, BirthDate, GETDATE())         -- 年龄（粗略）
```

::: warning DATEDIFF 的坑
DATEDIFF(MONTH, '2024-01-31', '2024-02-01') = 1。它只看月份变了，不管实际只差了 1 天。
:::

### FORMAT：格式化（慎用）

```sql
FORMAT(GETDATE(), 'yyyy-MM-dd')         -- '2024-01-15'
FORMAT(GETDATE(), 'yyyy年MM月dd日')      -- '2024年01月15日'
```

**FORMAT 性能很差**，比 CONVERT 慢 10-50 倍。报表里偶尔用用行，大批量查询里不要用。

### CONVERT：格式化（推荐）

```sql
CONVERT(VARCHAR(10), GETDATE(), 23)   -- '2024-01-15' (yyyy-mm-dd)
CONVERT(VARCHAR(19), GETDATE(), 120)  -- '2024-01-15 10:30:45'
CONVERT(VARCHAR(8), GETDATE(), 112)   -- '20240115' (yyyymmdd)
```

## 常见场景

### 算年龄

```sql
-- 准确算法（考虑是否过了生日）
SELECT
    DATEDIFF(YEAR, BirthDate, GETDATE())
    - CASE WHEN DATEADD(YEAR, DATEDIFF(YEAR, BirthDate, GETDATE()), BirthDate) > GETDATE()
           THEN 1 ELSE 0 END AS Age
FROM Employees;
```

### 取月初/月末

```sql
-- 本月第一天
SELECT DATEADD(DAY, 1 - DAY(GETDATE()), CAST(GETDATE() AS DATE));

-- 本月最后一天
SELECT EOMONTH(GETDATE());  -- SQL Server 2012+

-- 上月最后一天
SELECT EOMONTH(GETDATE(), -1);
```

### 取本周一

```sql
SELECT DATEADD(DAY, 1 - DATEPART(WEEKDAY, GETDATE()), CAST(GETDATE() AS DATE));
-- 注意：受 SET DATEFIRST 设置影响
```

### 判断工作日

```sql
-- 简单判断（不含法定假日）
SELECT CASE WHEN DATEPART(WEEKDAY, @Date) IN (1, 7) THEN '周末' ELSE '工作日' END;
-- 要准确判断需要维护一张假日表
```

## .NET 和 SQL Server 的时间类型对应

| C# 类型 | SQL Server 类型 |
|---------|----------------|
| DateTime | DATETIME / DATETIME2 |
| DateOnly (.NET 6+) | DATE |
| TimeOnly (.NET 6+) | TIME |
| DateTimeOffset | DATETIMEOFFSET |

用 Dapper 传参时，C# 的 `DateTime` 默认映射到 SQL Server 的 `DATETIME2`，不会有精度问题。但如果表字段是 `DATETIME`，可能有微小的精度差异。

## 时区处理

如果系统只在国内用，服务器时区统一设成北京时间，不需要特别处理。

如果是全球化系统：
- 数据库存 **UTC 时间**
- 应用层转换为用户本地时间
- 用 DATETIMEOFFSET 或者在应用层处理时区转换

```sql
-- 存 UTC
INSERT INTO Orders (CreateTime) VALUES (SYSUTCDATETIME());

-- 查询时转换为北京时间（+8）
SELECT CreateTime AT TIME ZONE 'China Standard Time' AS BeijingTime
FROM Orders;
```
