# 树形结构查询

组织架构、分类目录、评论回复、菜单权限——都是树形结构。SQL Server 里怎么存、怎么查？

## 邻接表模型（最常用）

```sql
CREATE TABLE Departments (
    DeptId INT PRIMARY KEY,
    DeptName NVARCHAR(50),
    ParentId INT NULL  -- 指向父节点，根节点为 NULL
);
```

数据示例：
```
1  总公司      NULL
2  技术部      1
3  销售部      1
4  前端组      2
5  后端组      2
6  华东区      3
```

### 递归 CTE 查所有下级

```sql
;WITH Tree AS (
    -- 锚点：从指定节点开始
    SELECT DeptId, DeptName, ParentId, 0 AS Level,
        CAST(DeptName AS NVARCHAR(MAX)) AS Path
    FROM Departments WHERE DeptId = 1  -- 从总公司开始
    
    UNION ALL
    
    -- 递归：找子节点
    SELECT d.DeptId, d.DeptName, d.ParentId, t.Level + 1,
        t.Path + ' > ' + d.DeptName
    FROM Departments d
    JOIN Tree t ON d.ParentId = t.DeptId
)
SELECT * FROM Tree ORDER BY Path;
```

结果：
```
1  总公司    0  总公司
2  技术部    1  总公司 > 技术部
4  前端组    2  总公司 > 技术部 > 前端组
5  后端组    2  总公司 > 技术部 > 后端组
3  销售部    1  总公司 > 销售部
6  华东区    2  总公司 > 销售部 > 华东区
```

### 查所有上级（向上追溯）

```sql
;WITH Tree AS (
    SELECT DeptId, DeptName, ParentId, 0 AS Level
    FROM Departments WHERE DeptId = 5  -- 从后端组开始

    UNION ALL

    SELECT d.DeptId, d.DeptName, d.ParentId, t.Level + 1
    FROM Departments d
    JOIN Tree t ON d.DeptId = t.ParentId  -- 注意方向反了
)
SELECT * FROM Tree;
-- 后端组 → 技术部 → 总公司
```

### 查某节点的所有叶子节点

```sql
;WITH Tree AS (
    SELECT DeptId FROM Departments WHERE DeptId = 1
    UNION ALL
    SELECT d.DeptId FROM Departments d JOIN Tree t ON d.ParentId = t.DeptId
)
SELECT d.* FROM Tree t
JOIN Departments d ON t.DeptId = d.DeptId
WHERE NOT EXISTS (SELECT 1 FROM Departments c WHERE c.ParentId = d.DeptId);
```

### 递归深度限制

```sql
-- 默认最大递归 100 层，超过会报错
-- 如果树很深，加 OPTION
;WITH Tree AS (...)
SELECT * FROM Tree
OPTION (MAXRECURSION 500);  -- 最大 500 层

-- 设为 0 表示不限制（谨慎使用，死循环会跑死）
OPTION (MAXRECURSION 0);
```

## 统计每个节点的下级数量

```sql
;WITH Tree AS (
    SELECT DeptId, DeptName, ParentId, DeptId AS RootId
    FROM Departments
    UNION ALL
    SELECT d.DeptId, d.DeptName, d.ParentId, t.RootId
    FROM Departments d JOIN Tree t ON d.ParentId = t.DeptId
)
SELECT RootId, d.DeptName, COUNT(*) - 1 AS DescendantCount
FROM Tree t JOIN Departments d ON t.RootId = d.DeptId
GROUP BY RootId, d.DeptName;
```

## 菜单/权限树的常见查询

### 构建用户权限菜单

```sql
-- 查某个角色能看到的所有菜单（包含父菜单）
;WITH UserMenus AS (
    -- 先找角色直接拥有的菜单
    SELECT m.MenuId, m.ParentId, m.MenuName, m.SortOrder
    FROM RoleMenus rm
    JOIN Menus m ON rm.MenuId = m.MenuId
    WHERE rm.RoleId = @RoleId

    UNION

    -- 递归上溯找父菜单（保证父菜单也显示）
    SELECT p.MenuId, p.ParentId, p.MenuName, p.SortOrder
    FROM Menus p
    JOIN UserMenus um ON p.MenuId = um.ParentId
)
SELECT DISTINCT * FROM UserMenus ORDER BY ParentId, SortOrder;
```

## 性能注意

递归 CTE 数据量大时会慢。优化手段：

1. **ParentId 加索引**：`CREATE INDEX IX ON Departments(ParentId)`
2. **物化路径**：存一个 Path 列如 `/1/2/5/`，查下级用 `LIKE '/1/2/%'`
3. **HierarchyId 类型**：SQL Server 内置的层级类型，查询效率高

```sql
-- 物化路径示例
ALTER TABLE Departments ADD Path VARCHAR(500);
-- Path = '/1/2/5/' 表示 总公司/技术部/后端组

-- 查所有下级
SELECT * FROM Departments WHERE Path LIKE '/1/2/%';
-- 走索引，比递归快很多
```
