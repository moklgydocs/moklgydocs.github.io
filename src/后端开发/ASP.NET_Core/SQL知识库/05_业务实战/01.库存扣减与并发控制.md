# 库存扣减与并发控制

库存扣减是最经典的并发问题——两个人同时下单买最后一件商品，怎么保证不超卖？

## 方案一：UPDATE + WHERE 条件判断

```sql
-- 最简单的方案：在 UPDATE 的 WHERE 里加数量判断
UPDATE Products
SET Stock = Stock - @Qty
WHERE ProductId = @ProductId AND Stock >= @Qty;

IF @@ROWCOUNT = 0
    RAISERROR('库存不足', 16, 1);
```

**原理**：UPDATE 是原子操作，SQL Server 会自动加排他锁。两个并发请求到来时，一个先拿到锁成功更新，另一个等锁释放后再执行——此时 `Stock >= @Qty` 已经不满足了，`@@ROWCOUNT = 0`。

**优点**：简单、高效、一条语句搞定。
**缺点**：只能知道"失败了"，不能知道当前还剩多少库存。

## 方案二：SELECT + UPDATE 事务（带 UPDLOCK）

```sql
BEGIN TRANSACTION;

DECLARE @currentStock INT;

SELECT @currentStock = Stock
FROM Products WITH (UPDLOCK)
WHERE ProductId = @ProductId;

IF @currentStock < @Qty
BEGIN
    ROLLBACK;
    RAISERROR('库存不足，当前库存: %d', 16, 1, @currentStock);
    RETURN;
END

UPDATE Products SET Stock = Stock - @Qty WHERE ProductId = @ProductId;

-- 写入订单...
INSERT INTO OrderDetails (...) VALUES (...);

COMMIT;
```

**关键**：`WITH (UPDLOCK)` 在 SELECT 时就加更新锁，防止两个事务同时读到相同的库存值然后都扣减成功。

## 方案三：乐观锁（版本号）

```sql
-- 表里加个 Version 列
-- Products: ProductId, Stock, Version

DECLARE @version INT, @stock INT;
SELECT @version = Version, @stock = Stock 
FROM Products WHERE ProductId = @ProductId;

IF @stock < @Qty
BEGIN
    RAISERROR('库存不足', 16, 1);
    RETURN;
END

UPDATE Products
SET Stock = Stock - @Qty, Version = Version + 1
WHERE ProductId = @ProductId AND Version = @version;

IF @@ROWCOUNT = 0
    -- 被别人改过了，重试或返回失败
    RAISERROR('操作冲突，请重试', 16, 1);
```

**适用场景**：并发冲突概率低的时候。无需长时间持锁，性能好。

## 方案对比

| 方案 | 并发安全 | 性能 | 复杂度 | 适用场景 |
|------|---------|------|--------|---------|
| UPDATE + WHERE | ✅ | 最高 | 低 | 简单扣减 |
| UPDLOCK 事务 | ✅ | 高 | 中 | 需要先检查再操作 |
| 乐观锁 | ✅ | 高 | 中 | 冲突率低 |
| 应用层分布式锁 | ✅ | 中 | 高 | 分库分表场景 |

**多数场景用方案一就够了**。KISS 原则。

## 批量扣减

一个订单买了多种商品，要一次扣减多个：

```sql
BEGIN TRANSACTION;

-- 用表值参数传入 (ProductId, Qty) 的列表
-- 或者用临时表

-- 检查所有商品库存是否充足
IF EXISTS (
    SELECT 1 FROM @items i
    JOIN Products p ON i.ProductId = p.ProductId
    WHERE p.Stock < i.Qty
)
BEGIN
    ROLLBACK;
    RAISERROR('部分商品库存不足', 16, 1);
    RETURN;
END

-- 批量扣减
UPDATE p SET p.Stock = p.Stock - i.Qty
FROM Products p
JOIN @items i ON p.ProductId = i.ProductId;

COMMIT;
```

## 防止负库存的终极保障

在表上加 CHECK 约束：

```sql
ALTER TABLE Products ADD CONSTRAINT CK_Stock_NonNeg CHECK (Stock >= 0);
```

即使代码有 Bug，数据库层面也不会让库存变成负数。
