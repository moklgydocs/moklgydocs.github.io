# 数据迁移与 ETL

系统升级要迁数据、新旧系统并行要同步数据、定期从业务库抽到报表库——都是 ETL（Extract-Transform-Load）的场景。

## MERGE 语句：增量同步神器

```sql
-- 把源表的数据同步到目标表：新增插入、已有更新、多余删除
MERGE INTO TargetTable AS t
USING SourceTable AS s ON t.Id = s.Id
WHEN MATCHED AND (t.Name <> s.Name OR t.Amount <> s.Amount) THEN
    UPDATE SET t.Name = s.Name, t.Amount = s.Amount, t.UpdateTime = GETDATE()
WHEN NOT MATCHED BY TARGET THEN
    INSERT (Id, Name, Amount, CreateTime)
    VALUES (s.Id, s.Name, s.Amount, GETDATE())
WHEN NOT MATCHED BY SOURCE THEN
    DELETE;
-- 可以用 OUTPUT 子句记录变更日志
```

MERGE 一条语句完成 INSERT + UPDATE + DELETE，适合维度表同步。

::: warning MERGE 的坑
- 必须以分号结尾
- 并发下可能有死锁问题，建议加 HOLDLOCK
- 大数据量时分批处理
:::

## 增量抽取模式

### 基于时间戳

```sql
-- 记录上次同步时间
DECLARE @LastSync DATETIME2 = (SELECT LastSyncTime FROM SyncLog WHERE TableName = 'Orders');

-- 抽取变更数据
INSERT INTO DataWarehouse.dbo.Orders
SELECT * FROM OLTP.dbo.Orders
WHERE UpdateTime > @LastSync;

-- 更新同步时间
UPDATE SyncLog SET LastSyncTime = GETDATE() WHERE TableName = 'Orders';
```

**前提**：源表必须有 `UpdateTime` 列，且每次修改都会更新。

### 基于 CDC（变更数据捕获）

```sql
-- 开启 CDC
EXEC sys.sp_cdc_enable_db;
EXEC sys.sp_cdc_enable_table @source_schema = 'dbo', @source_name = 'Orders',
    @role_name = NULL;

-- 查询变更
SELECT * FROM cdc.fn_cdc_get_all_changes_dbo_Orders(@from_lsn, @to_lsn, 'all');
```

CDC 记录所有 INSERT/UPDATE/DELETE 操作，不用改业务代码。

## 大表数据迁移

### 分批迁移

```sql
DECLARE @BatchSize INT = 10000;
DECLARE @LastId INT = 0;

WHILE 1 = 1
BEGIN
    INSERT INTO NewDB.dbo.Orders
    SELECT TOP (@BatchSize) *
    FROM OldDB.dbo.Orders
    WHERE OrderId > @LastId
    ORDER BY OrderId;

    IF @@ROWCOUNT < @BatchSize BREAK;

    SELECT @LastId = MAX(OrderId) FROM NewDB.dbo.Orders;

    -- 可选：控制速度
    WAITFOR DELAY '00:00:01';
END
```

### BCP 导出导入

```bash
# 导出
bcp OldDB.dbo.Orders out C:\data\orders.bcp -S localhost -T -N

# 导入
bcp NewDB.dbo.Orders in C:\data\orders.bcp -S localhost -T -N
```

BCP 是最快的批量导入导出工具。

## 数据清洗常用操作

```sql
-- 去除空格
UPDATE Customers SET Name = LTRIM(RTRIM(Name));

-- 统一大小写
UPDATE Customers SET Email = LOWER(Email);

-- 去重（保留最新的一条）
;WITH dup AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY Phone ORDER BY CreateTime DESC) AS rn
    FROM Customers
)
DELETE FROM dup WHERE rn > 1;

-- 填充缺失值
UPDATE Orders SET Status = 0 WHERE Status IS NULL;

-- 数据类型修正
UPDATE temp SET Amount = TRY_CAST(AmountStr AS DECIMAL(10,2));
```

## ETL 存储过程模板

```sql
CREATE PROCEDURE usp_ETL_SyncOrders
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;

    DECLARE @StartTime DATETIME2 = SYSDATETIME();
    DECLARE @RowsInserted INT = 0, @RowsUpdated INT = 0;

    BEGIN TRY
        BEGIN TRANSACTION;

        -- 增量更新
        MERGE INTO DW.dbo.DimCustomer AS t
        USING OLTP.dbo.Customers AS s ON t.CustomerId = s.CustomerId
        WHEN MATCHED AND t.UpdateTime < s.UpdateTime THEN
            UPDATE SET t.Name = s.Name, t.Phone = s.Phone, t.UpdateTime = s.UpdateTime
        WHEN NOT MATCHED THEN
            INSERT (CustomerId, Name, Phone, UpdateTime)
            VALUES (s.CustomerId, s.Name, s.Phone, s.UpdateTime);

        SET @RowsUpdated = @@ROWCOUNT;

        COMMIT;

        -- 记录日志
        INSERT INTO ETLLog (ProcName, StartTime, EndTime, RowsAffected, Status)
        VALUES ('usp_ETL_SyncOrders', @StartTime, SYSDATETIME(), @RowsUpdated, 'Success');

    END TRY
    BEGIN CATCH
        IF @@TRANCOUNT > 0 ROLLBACK;

        INSERT INTO ETLLog (ProcName, StartTime, EndTime, ErrorMessage, Status)
        VALUES ('usp_ETL_SyncOrders', @StartTime, SYSDATETIME(), ERROR_MESSAGE(), 'Failed');

        THROW;
    END CATCH;
END;
```
