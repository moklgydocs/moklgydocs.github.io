# 需求分析到 SQL 的转化

拿到一个数据需求，怎么一步一步变成能跑的 SQL？很多人不是不会写 SQL，而是**看到需求不知道从哪下手**。这篇给一个通用的转化流程。

## 五步转化法

### 第一步：明确输出

先搞清楚**最终要看到什么**。

需求描述："统计每个部门 2024 年的月度销售额，并标注同比增长率"

输出长什么样？先画个表：

| 部门 | 月份 | 销售额 | 去年同月 | 同比增长率 |
|------|------|--------|----------|-----------|
| 销售一部 | 2024-01 | 150000 | 120000 | 25% |

确认输出的列 → 这就是你 SELECT 的内容。

### 第二步：找数据源

这些数据从哪些表来？

- 销售额 → `Orders` 表
- 部门名 → `Departments` 表
- 可能还要 `Employees` 表关联部门

FROM 哪些表、怎么 JOIN，基本就定了。

### 第三步：定过滤条件

什么数据要？什么不要？

- 2024 年 + 2023 年（因为要同比）
- 订单状态 = 已完成（排除取消的）

这就是 WHERE 条件。

### 第四步：定分组维度

需求说"每个部门""月度" → GROUP BY 部门 + 月份

### 第五步：组装

```sql
;WITH MonthSales AS (
    SELECT
        d.DeptName,
        FORMAT(o.OrderDate, 'yyyy-MM') AS Month,
        YEAR(o.OrderDate) AS Y,
        MONTH(o.OrderDate) AS M,
        SUM(o.Amount) AS Total
    FROM Orders o
    JOIN Employees e ON o.SalesEmpId = e.EmpId
    JOIN Departments d ON e.DeptId = d.DeptId
    WHERE o.Status = 1
        AND o.OrderDate >= '2023-01-01' AND o.OrderDate < '2025-01-01'
    GROUP BY d.DeptName, YEAR(o.OrderDate), MONTH(o.OrderDate),
             FORMAT(o.OrderDate, 'yyyy-MM')
)
SELECT
    cur.DeptName,
    cur.Month,
    cur.Total AS Sales2024,
    prev.Total AS Sales2023,
    CASE WHEN prev.Total > 0
         THEN CAST((cur.Total - prev.Total) * 100.0 / prev.Total AS DECIMAL(5,1))
         ELSE NULL END AS GrowthRate
FROM MonthSales cur
LEFT JOIN MonthSales prev ON cur.DeptName = prev.DeptName
    AND cur.M = prev.M AND prev.Y = 2023
WHERE cur.Y = 2024
ORDER BY cur.DeptName, cur.M;
```

## 常见需求模式

遇到下面这些关键词，直接套路：

| 需求关键词 | SQL 套路 |
|-----------|---------|
| "每个XX的" | GROUP BY XX |
| "前N名" | ROW_NUMBER + WHERE rn <= N |
| "最新的一条" | ROW_NUMBER + WHERE rn = 1 |
| "连续N天" | 差值分组法 |
| "同比/环比" | 自 JOIN 或 LAG |
| "占比/百分比" | SUM() OVER() 窗口函数 |
| "存在/不存在" | EXISTS / NOT EXISTS |
| "交叉表/透视" | PIVOT 或 CASE WHEN |
| "累计" | SUM() OVER(ORDER BY) |
| "去重" | DISTINCT 或 GROUP BY |
| "排名" | RANK / DENSE_RANK |

## 从自然语言提取关键信息

**需求**："找出最近 3 个月下单金额超过 1 万的客户，按总金额降序排列，显示客户名、订单数、总金额"

拆解：
- **输出**：客户名、订单数、总金额 → SELECT
- **数据源**：客户表 + 订单表 → FROM + JOIN
- **过滤**：最近 3 个月 → WHERE 日期条件
- **分组**：按客户 → GROUP BY
- **分组后过滤**：总金额 > 1 万 → HAVING
- **排序**：总金额降序 → ORDER BY DESC

```sql
SELECT c.CustomerName,
    COUNT(*) AS OrderCount,
    SUM(o.Amount) AS TotalAmount
FROM Orders o
JOIN Customers c ON o.CustomerId = c.CustomerId
WHERE o.OrderDate >= DATEADD(MONTH, -3, CAST(GETDATE() AS DATE))
GROUP BY c.CustomerName
HAVING SUM(o.Amount) > 10000
ORDER BY TotalAmount DESC;
```

## 复杂需求的分步策略

如果一条 SQL 写不出来，**先分步想，再看能不能合成一条**。

**需求**："每个部门工资排名前 3 的员工，以及他们的工资占部门总工资的百分比"

分步思考：
1. 先算每人在部门的排名 → ROW_NUMBER
2. 再算部门总工资 → SUM OVER
3. 最后取 Top 3 + 算百分比

```sql
;WITH ranked AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY DeptId ORDER BY Salary DESC) AS rn,
        SUM(Salary) OVER (PARTITION BY DeptId) AS DeptTotal
    FROM Employees
)
SELECT DeptId, Name, Salary,
    CAST(Salary * 100.0 / DeptTotal AS DECIMAL(5,2)) AS Pct
FROM ranked
WHERE rn <= 3;
```

**先想清楚步骤，再写 SQL。不要一上来就从 SELECT 开始写。**

## 验证思路的方法

写完 SQL 后别急着交差，先自我验证：

1. **边界值**：空表会怎样？只有一行呢？全是 NULL 呢？
2. **结果行数**：GROUP BY 后应该有多少组？和预期匹配吗？
3. **手动算一组**：挑一个组手动验算，和 SQL 结果对得上吗？
4. **特殊情况**：除以 0 了吗？日期跨年了吗？一对多 JOIN 会不会膨胀？
