# 事务隔离级别深入

面试经常问："说说事务隔离级别？MVCC 了解吗？"这篇从并发问题出发，讲清楚每个隔离级别解决了什么问题。

## 三种并发问题

### 脏读（Dirty Read）

事务 A 修改了一行**还没提交**，事务 B 就读到了这个修改。如果 A 回滚了，B 读到的就是不存在的数据。

### 不可重复读（Non-Repeatable Read）

事务 A 读了一行，事务 B **修改并提交**了这行，事务 A 再读同一行——两次读的值不一样。

### 幻读（Phantom Read）

事务 A 用 WHERE 条件查出 10 行，事务 B **插入**了一行新数据满足这个条件并提交。事务 A 再查——变成 11 行了，多出一个"幻影"。

## 四个标准隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 | 实现方式 |
|------|------|-----------|------|---------|
| READ UNCOMMITTED | 有 | 有 | 有 | 不加共享锁 |
| READ COMMITTED | 无 | 有 | 有 | 读时加共享锁，读完立刻释放 |
| REPEATABLE READ | 无 | 无 | 有 | 读时加共享锁，持有到事务结束 |
| SERIALIZABLE | 无 | 无 | 无 | 加范围锁（Key-Range Lock） |

## SQL Server 的锁实现

### READ COMMITTED（默认）

```sql
-- 事务 A
BEGIN TRANSACTION;
SELECT * FROM Accounts WHERE Id = 1;  -- 加共享锁，读完立刻释放
-- 此时其他事务可以修改这行
SELECT * FROM Accounts WHERE Id = 1;  -- 可能读到不同的值
COMMIT;
```

### REPEATABLE READ

```sql
SET TRANSACTION ISOLATION LEVEL REPEATABLE READ;
BEGIN TRANSACTION;
SELECT * FROM Accounts WHERE Id = 1;  -- 加共享锁，一直持有到 COMMIT
-- 其他事务不能修改这行（被共享锁挡住了）
SELECT * FROM Accounts WHERE Id = 1;  -- 保证读到一样的值
COMMIT;
```

### SERIALIZABLE

```sql
SET TRANSACTION ISOLATION LEVEL SERIALIZABLE;
BEGIN TRANSACTION;
SELECT * FROM Accounts WHERE Balance > 1000;  -- 加范围锁
-- 其他事务不能在这个范围内插入/删除行
COMMIT;
```

## 快照隔离（MVCC）

SQL Server 的快照隔离不用锁来解决并发问题，而是用**行版本控制**（类似 MySQL 的 MVCC）。

### READ COMMITTED SNAPSHOT ISOLATION (RCSI)

```sql
-- 数据库级别开启（一次性操作）
ALTER DATABASE MyDB SET READ_COMMITTED_SNAPSHOT ON;
```

开启后，SELECT 读的是行的**快照版本**（事务开始时的版本），不加共享锁。写操作还是正常加排他锁。

**效果**：读不阻塞写，写不阻塞读。99% 的场景推荐开启。

### SNAPSHOT ISOLATION

```sql
ALTER DATABASE MyDB SET ALLOW_SNAPSHOT_ISOLATION ON;

SET TRANSACTION ISOLATION LEVEL SNAPSHOT;
BEGIN TRANSACTION;
-- 读到的是事务开始时的数据快照
-- 整个事务期间都是一致的（比 RCSI 更强）
COMMIT;
```

区别：RCSI 是**语句级**快照（每条 SELECT 看到的是语句开始时的版本），SNAPSHOT 是**事务级**快照（整个事务看到的都是事务开始时的版本）。

### 快照隔离的代价

- TempDB 使用增加（行版本存在 TempDB 里）
- 写冲突时可能报错（两个事务同时改同一行，后提交的会失败）

## 什么时候用什么

| 场景 | 推荐 |
|------|------|
| 一般 OLTP 系统 | RCSI（开启 READ_COMMITTED_SNAPSHOT） |
| 报表查询不想被业务锁阻塞 | RCSI 或 SNAPSHOT |
| 需要事务级一致性读 | SNAPSHOT |
| 对数据精确度要求不高 | READ UNCOMMITTED（NOLOCK） |
| 需要绝对串行 | SERIALIZABLE（但性能差，慎用） |

## 面试回答模板

> 问：说说事务隔离级别？

三种并发问题：脏读、不可重复读、幻读。四个标准隔离级别：READ UNCOMMITTED、READ COMMITTED、REPEATABLE READ、SERIALIZABLE，从低到高分别解决这些问题。SQL Server 默认 READ COMMITTED。

SQL Server 还支持基于行版本的快照隔离（RCSI 和 SNAPSHOT），类似 MySQL 的 MVCC，读不阻塞写、写不阻塞读。实际项目中推荐开启 RCSI，性能好又安全。
