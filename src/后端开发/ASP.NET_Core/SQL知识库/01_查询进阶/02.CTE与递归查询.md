# CTE 与递归查询

CTE（Common Table Expression，公用表表达式）说白了就是给子查询起个名字，让 SQL 更好读。但它真正厉害的地方在于递归——处理树形结构数据的时候，没有比它更方便的了。

## 基本 CTE

### 语法

```sql
;WITH cte名 AS (
    SELECT ...
)
SELECT * FROM cte名;
```

那个开头的分号是个好习惯——避免前面的语句没写分号导致语法报错。

### 和子查询有什么区别

功能上没区别，CTE 就是让 SQL 更好看。对比一下：

```sql
-- 子查询写法：嵌套一层套一层，看着头疼
SELECT d.DeptName, t.AvgSalary
FROM (
    SELECT DeptId, AVG(Salary) AS AvgSalary
    FROM Employees
    GROUP BY DeptId
) t
JOIN Departments d ON d.Id = t.DeptId
WHERE t.AvgSalary > 10000;

-- CTE 写法：逻辑一块一块的，清清楚楚
;WITH DeptAvg AS (
    SELECT DeptId, AVG(Salary) AS AvgSalary
    FROM Employees
    GROUP BY DeptId
)
SELECT d.DeptName, da.AvgSalary
FROM DeptAvg da
JOIN Departments d ON d.Id = da.DeptId
WHERE da.AvgSalary > 10000;
```

### 多个 CTE 串联

一个 WITH 后面可以跟多个 CTE，用逗号隔开：

```sql
;WITH
Step1 AS (
    SELECT DeptId, COUNT(*) AS EmpCount
    FROM Employees
    GROUP BY DeptId
),
Step2 AS (
    SELECT DeptId, SUM(Amount) AS TotalSales
    FROM Sales
    GROUP BY DeptId
)
SELECT s1.DeptId, s1.EmpCount, s2.TotalSales,
    s2.TotalSales / s1.EmpCount AS SalesPerPerson
FROM Step1 s1
JOIN Step2 s2 ON s1.DeptId = s2.DeptId;
```

把复杂查询拆成几步，每步一个 CTE，最后组装。比嵌套三四层子查询好理解太多了。

### CTE 能做 DML

这是很多人不知道的——CTE 可以直接 UPDATE、DELETE：

```sql
-- 删除每个部门工资最低的人
;WITH cte AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY DeptId ORDER BY Salary) AS rn
    FROM Employees
)
DELETE FROM cte WHERE rn = 1;

-- 更新也行
;WITH cte AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY Phone ORDER BY Id DESC) AS rn
    FROM Customers
)
UPDATE cte SET IsLatest = 1 WHERE rn = 1;
```

## 递归 CTE

递归 CTE 是处理树形/层级数据的利器。组织架构、菜单树、分类层级、BOM 物料清单，全靠它。

### 结构

```sql
;WITH cte AS (
    -- 锚点（初始行，起点）
    SELECT Id, ParentId, Name, 0 AS Level
    FROM Categories
    WHERE ParentId IS NULL

    UNION ALL

    -- 递归部分（每次拿上一层的结果，去找下一层）
    SELECT c.Id, c.ParentId, c.Name, cte.Level + 1
    FROM Categories c
    JOIN cte ON c.ParentId = cte.Id
)
SELECT * FROM cte;
```

**执行过程**：
1. 先跑锚点查询，拿到根节点
2. 用根节点的结果去跑递归部分，找到下一层子节点
3. 再用子节点的结果继续递归，找到孙节点
4. 直到递归部分查不出新行为止

### 实战：组织架构树

```sql
-- 建表
CREATE TABLE #Org (
    Id INT PRIMARY KEY,
    Name NVARCHAR(50),
    ParentId INT,
    Position NVARCHAR(50)
);
INSERT INTO #Org VALUES
(1, '张总', NULL, 'CEO'),
(2, '李副总', 1, 'VP'),
(3, '王经理', 1, 'VP'),
(4, '赵主管', 2, '主管'),
(5, '钱主管', 2, '主管'),
(6, '孙组长', 4, '组长'),
(7, '周员工', 6, '开发'),
(8, '吴员工', 6, '开发'),
(9, '郑经理', 3, '主管');

-- 查整棵树，带层级和路径
;WITH OrgTree AS (
    SELECT Id, Name, ParentId, Position,
        0 AS Level,
        CAST(Name AS NVARCHAR(500)) AS Path
    FROM #Org
    WHERE ParentId IS NULL

    UNION ALL

    SELECT o.Id, o.Name, o.ParentId, o.Position,
        t.Level + 1,
        CAST(t.Path + ' > ' + o.Name AS NVARCHAR(500))
    FROM #Org o
    JOIN OrgTree t ON o.ParentId = t.Id
)
SELECT
    REPLICATE('  ', Level) + Name AS OrgChart,
    Position, Level, Path
FROM OrgTree
ORDER BY Path;
```

结果大概长这样：

```
张总              CEO    0  张总
  李副总          VP     1  张总 > 李副总
    赵主管        主管   2  张总 > 李副总 > 赵主管
      孙组长      组长   3  张总 > 李副总 > 赵主管 > 孙组长
        周员工    开发   4  张总 > 李副总 > 赵主管 > 孙组长 > 周员工
        吴员工    开发   4  张总 > 李副总 > 赵主管 > 孙组长 > 吴员工
    钱主管        主管   2  张总 > 李副总 > 钱主管
  王经理          VP     1  张总 > 王经理
    郑经理        主管   2  张总 > 王经理 > 郑经理
```

### 实战：查某个节点的所有上级

反过来查也行——从子节点往上找：

```sql
-- 查 "周员工" 的所有上级
;WITH UpTree AS (
    SELECT Id, Name, ParentId, 0 AS Level
    FROM #Org
    WHERE Name = N'周员工'

    UNION ALL

    SELECT o.Id, o.Name, o.ParentId, t.Level + 1
    FROM #Org o
    JOIN UpTree t ON o.Id = t.ParentId
)
SELECT * FROM UpTree;
-- 周员工 → 孙组长 → 赵主管 → 李副总 → 张总
```

### 实战：查某个节点的所有下属

```sql
-- 查 "李副总" 下面所有人
;WITH DownTree AS (
    SELECT Id, Name, ParentId
    FROM #Org WHERE Name = N'李副总'

    UNION ALL

    SELECT o.Id, o.Name, o.ParentId
    FROM #Org o
    JOIN DownTree t ON o.ParentId = t.Id
)
SELECT * FROM DownTree;
-- 李副总、赵主管、钱主管、孙组长、周员工、吴员工
```

### 实战：生成连续日期

递归 CTE 不只是做树形查询，生成序列也好用：

```sql
-- 生成 2024 年 1 月的每一天
;WITH Dates AS (
    SELECT CAST('2024-01-01' AS DATE) AS dt
    UNION ALL
    SELECT DATEADD(DAY, 1, dt)
    FROM Dates
    WHERE dt < '2024-01-31'
)
SELECT dt FROM Dates
OPTION (MAXRECURSION 31);
```

用来填充日历表、补全缺失日期都很方便。

### 实战：数字序列

```sql
-- 生成 1 到 100
;WITH Nums AS (
    SELECT 1 AS n
    UNION ALL
    SELECT n + 1 FROM Nums WHERE n < 100
)
SELECT n FROM Nums
OPTION (MAXRECURSION 100);
```

## MAXRECURSION 防无限循环

递归 CTE 默认最多递归 100 次。超过了就报错，防止你写了个死循环把服务器搞挂：

```sql
-- 改成最多 500 次
SELECT * FROM cte OPTION (MAXRECURSION 500);

-- 不限制（慎用！）
SELECT * FROM cte OPTION (MAXRECURSION 0);
```

如果你的树超过 100 层（什么架构能有这么深？），要么是数据有环（A 的父节点是 B，B 的父节点又是 A），要么是你在生成序列忘了设限制。

### 检测数据有没有环

```sql
;WITH cte AS (
    SELECT Id, ParentId, CAST(Id AS VARCHAR(MAX)) AS Path
    FROM Categories WHERE ParentId IS NULL

    UNION ALL

    SELECT c.Id, c.ParentId,
        cte.Path + ',' + CAST(c.Id AS VARCHAR(10))
    FROM Categories c
    JOIN cte ON c.ParentId = cte.Id
    WHERE cte.Path NOT LIKE '%' + CAST(c.Id AS VARCHAR(10)) + '%'  -- 已经在路径里了就不再走
)
SELECT * FROM cte OPTION (MAXRECURSION 0);
```

## CTE vs 临时表 vs 表变量

| | CTE | 临时表 #t | 表变量 @t |
|---|---|---|---|
| 作用范围 | 紧跟着的 **一条** 语句 | 整个连接/存储过程 | 整个批次/存储过程 |
| 能建索引 | ❌ | ✅ | 有限（只有主键/唯一约束） |
| 物化（先算好存起来） | ❌ 每次引用都重算 | ✅ | ✅ |
| 适合 | 一次性取数、递归 | 大量中间数据、多次使用 | 小量数据、简单传递 |

**关键点**：CTE 不会把结果存起来。如果你在后面的查询里引用了同一个 CTE 两次，它会算两遍。数据量大的话，用临时表先存一下再用。

```sql
-- CTE 引用两次 = 算两遍
;WITH cte AS (SELECT ... 一个很重的查询 ...)
SELECT * FROM cte a JOIN cte b ON a.Id = b.ParentId;
-- 这里 cte 被执行了两次！

-- 改成临时表：只算一次
SELECT ... 一个很重的查询 ...
INTO #temp;
SELECT * FROM #temp a JOIN #temp b ON a.Id = b.ParentId;
```

---

## 几个注意的点

1. CTE 后面必须紧跟一条 SELECT/INSERT/UPDATE/DELETE/MERGE，不能跟其他东西
2. CTE 里不能用 ORDER BY（除非配合 TOP/OFFSET-FETCH）
3. 递归 CTE 的递归部分不能用 TOP、DISTINCT、GROUP BY、HAVING
4. 递归 CTE 里只能有一个 UNION ALL（锚点和递归之间），不能是 UNION
5. 同一个 WITH 里的多个 CTE，后面的可以引用前面的，但不能反过来
