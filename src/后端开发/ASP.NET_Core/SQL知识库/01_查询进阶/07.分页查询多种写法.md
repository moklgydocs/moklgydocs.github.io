# 分页查询多种写法

后端开发避不开分页。前端传 pageIndex 和 pageSize，你得返回对应的那一页数据。SQL Server 有好几种分页写法，性能差异很大，尤其是翻到后面几千页的时候。

## 写法一：OFFSET-FETCH（标准写法）

SQL Server 2012 开始支持，也是目前最推荐的写法：

```sql
-- 第 3 页，每页 20 条
DECLARE @PageIndex INT = 3, @PageSize INT = 20;

SELECT *
FROM Orders
ORDER BY OrderId
OFFSET (@PageIndex - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;
```

简洁明了。`OFFSET` 跳过前面的行，`FETCH NEXT` 取接下来的 N 行。

必须配合 `ORDER BY` 使用，不能单独写。

### 带总条数

```sql
-- 一次查询拿到数据 + 总数
SELECT *, COUNT(*) OVER () AS TotalCount
FROM Orders
ORDER BY OrderId
OFFSET (@PageIndex - 1) * @PageSize ROWS
FETCH NEXT @PageSize ROWS ONLY;
```

`COUNT(*) OVER()` 是窗口函数，返回不分组的总行数。每行都会带上这个总数，有点冗余但省了一次查询。

如果你不想每行都带总数（觉得浪费带宽），就分两次查：

```sql
-- 查总数
SELECT @TotalCount = COUNT(*) FROM Orders WHERE ...;

-- 查数据
SELECT * FROM Orders WHERE ...
ORDER BY OrderId
OFFSET ... ROWS FETCH NEXT ... ROWS ONLY;
```

## 写法二：ROW_NUMBER（兼容老版本）

SQL Server 2005-2008 没有 OFFSET-FETCH，只能用 ROW_NUMBER：

```sql
DECLARE @PageIndex INT = 3, @PageSize INT = 20;

;WITH cte AS (
    SELECT *,
        ROW_NUMBER() OVER (ORDER BY OrderId) AS RowNum
    FROM Orders
)
SELECT *
FROM cte
WHERE RowNum BETWEEN (@PageIndex - 1) * @PageSize + 1 AND @PageIndex * @PageSize;
```

写起来多几行，但效果一样。SQL Server 2012+ 直接用 OFFSET-FETCH，别用这个了。

---

## 写法三：键集分页（Keyset Pagination）

前两种写法有个共同问题：**翻页越深越慢**。

OFFSET 100000 的时候，SQL Server 要先扫描前 10 万行然后跳过。页码越大，跳的越多，越慢。

键集分页的思路完全不同——不用 OFFSET，用上一页最后一条记录的主键作为起点：

```sql
-- 第一页
SELECT TOP 20 * FROM Orders ORDER BY OrderId;

-- 第二页（第一页最后一条 OrderId = 20）
SELECT TOP 20 * FROM Orders WHERE OrderId > 20 ORDER BY OrderId;

-- 第三页（第二页最后一条 OrderId = 40）
SELECT TOP 20 * FROM Orders WHERE OrderId > 40 ORDER BY OrderId;
```

**优点**：不管第几页，都是走索引 Seek，性能恒定。第 1 页和第 10000 页一样快。

**缺点**：
- 只能"上一页/下一页"，不能直接跳到第 N 页
- 需要前端传上一页的最后一个 ID（或排序字段值）
- 排序字段必须唯一且有索引

### 多字段排序的键集分页

如果排序不是只按主键，比如按创建时间倒序：

```sql
-- 第一页
SELECT TOP 20 * FROM Orders ORDER BY CreateTime DESC, OrderId DESC;

-- 下一页（传入上一页最后一条的 CreateTime 和 OrderId）
SELECT TOP 20 * FROM Orders
WHERE (CreateTime < @LastCreateTime)
   OR (CreateTime = @LastCreateTime AND OrderId < @LastOrderId)
ORDER BY CreateTime DESC, OrderId DESC;
```

这里要注意 **tie-breaking**：CreateTime 可能重复，所以需要配一个唯一字段（OrderId）来保证顺序确定。

## 写法四：TOP + NOT IN（古老写法，别用了）

```sql
-- 第 3 页
SELECT TOP 20 *
FROM Orders
WHERE OrderId NOT IN (
    SELECT TOP 40 OrderId FROM Orders ORDER BY OrderId
)
ORDER BY OrderId;
```

思路是"取前 40 条的 ID，然后排除掉取前 20 条"。性能很差，随着页码增大 NOT IN 的子查询越来越大。纯属历史遗留，见到了就改掉。

---

## 性能对比

| 写法 | 第 1 页 | 第 100 页 | 第 10000 页 |
|------|---------|-----------|-------------|
| OFFSET-FETCH | 快 | 还行 | 慢 |
| ROW_NUMBER | 快 | 还行 | 慢 |
| 键集分页 | 快 | 快 | 快 |
| TOP + NOT IN | 还行 | 慢 | 非常慢 |

OFFSET-FETCH 和 ROW_NUMBER 在深分页时性能一样差，因为本质上都是先排序再跳过。

**实际建议**：
- 后台管理系统：OFFSET-FETCH 够用了，一般没人翻几千页
- 移动端"加载更多"：天然适合键集分页，每次传上一页最后的 ID
- 大数据导出：别分页了，用游标或流式读取

## 实际封装（配合 .NET）

后端一般会封装一个通用的分页方法，传入 SQL 和分页参数：

```sql
-- 通用分页存储过程
CREATE PROCEDURE [dbo].[sp_PageQuery]
    @TableName NVARCHAR(256),
    @Fields NVARCHAR(MAX) = '*',
    @Where NVARCHAR(MAX) = '',
    @OrderBy NVARCHAR(256),
    @PageIndex INT = 1,
    @PageSize INT = 20,
    @TotalCount INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @sql NVARCHAR(MAX), @countSql NVARCHAR(MAX);

    -- 总条数
    SET @countSql = N'SELECT @cnt = COUNT(*) FROM ' + @TableName
        + CASE WHEN @Where <> '' THEN ' WHERE ' + @Where ELSE '' END;
    EXEC sp_executesql @countSql, N'@cnt INT OUTPUT', @cnt = @TotalCount OUTPUT;

    -- 分页数据
    SET @sql = N'SELECT ' + @Fields + ' FROM ' + @TableName
        + CASE WHEN @Where <> '' THEN ' WHERE ' + @Where ELSE '' END
        + ' ORDER BY ' + @OrderBy
        + ' OFFSET ' + CAST((@PageIndex - 1) * @PageSize AS VARCHAR) + ' ROWS'
        + ' FETCH NEXT ' + CAST(@PageSize AS VARCHAR) + ' ROWS ONLY';
    EXEC sp_executesql @sql;
END;
```

::: warning 拼 SQL 有注入风险
上面的写法拼了表名和 WHERE 条件，如果输入来自用户就有 SQL 注入风险。在存储过程里用要小心，确保参数是程序内部传的，不是用户直接输入的。
:::

更好的做法是在 .NET 层用 Dapper 或 EF Core 构建分页查询，不拼 SQL：

```csharp
// Dapper
var offset = (pageIndex - 1) * pageSize;
var sql = @"SELECT * FROM Orders WHERE Status = @Status
            ORDER BY OrderId
            OFFSET @Offset ROWS FETCH NEXT @PageSize ROWS ONLY";
var data = conn.Query<Order>(sql, new { Status = 1, Offset = offset, PageSize = pageSize });
```

## 几个注意点

1. **ORDER BY 必须有**。OFFSET-FETCH 和 ROW_NUMBER 都要求有明确的排序，不然结果不确定
2. **排序字段要有索引**。分页的性能瓶颈在排序，没索引就全表排序
3. **排序要有唯一性**。如果 ORDER BY 的字段有重复值，分页结果可能出现重复或遗漏。加个主键做 tie-breaker
4. **深分页尽量避免**。如果业务允许，限制最大页码（比如只允许翻到 100 页），或者用键集分页
5. **数据实时变化时分页不稳定**。两次查询之间有新数据插入，可能导致某条数据出现在两页上或被跳过。业务上通常能接受
