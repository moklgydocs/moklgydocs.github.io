# 窗口函数完全指南

窗口函数是 SQL 里最值得学的东西，没有之一。学会了它，你会发现之前很多写了十几行的子查询，一行就搞定了。

## 窗口函数和 GROUP BY 到底有啥区别

一句话：**GROUP BY 会把多行合并成一行，窗口函数不会，它算完了原来多少行还是多少行。**

举个例子，有张销售表：

```sql
CREATE TABLE #Sales (
    Id INT IDENTITY(1,1),
    SalesMan NVARCHAR(20),
    Amount DECIMAL(10,2),
    SaleDate DATE
);
INSERT INTO #Sales (SalesMan, Amount, SaleDate) VALUES
('张三', 100, '2024-01-01'), ('张三', 200, '2024-01-02'), ('张三', 150, '2024-01-03'),
('李四', 300, '2024-01-01'), ('李四', 250, '2024-01-02'),
('王五', 180, '2024-01-01'), ('王五', 220, '2024-01-02'), ('王五', 190, '2024-01-03');
```

用 GROUP BY 求每人的总销售额：

```sql
SELECT SalesMan, SUM(Amount) AS TotalAmount
FROM #Sales
GROUP BY SalesMan;
-- 结果只有 3 行，每人一行，明细没了
```

用窗口函数：

```sql
SELECT *, SUM(Amount) OVER (PARTITION BY SalesMan) AS TotalAmount
FROM #Sales;
-- 结果还是 8 行，每行都多了一列"这个人的总额"
```

**区别就在这里**：窗口函数能让你在保留每行明细的同时，拿到聚合结果。这在做报表的时候太好用了——既要明细又要汇总，不用再 JOIN 一个子查询了。

## 语法结构

```sql
函数名(参数) OVER (
    PARTITION BY 分组列    -- 可选，不写就是全表当一组
    ORDER BY 排序列        -- 有些函数必须写，有些可选
    ROWS/RANGE 窗口范围    -- 可选，控制计算范围
)
```

三块内容：
- **PARTITION BY**：按什么分组。类似 GROUP BY，但不会合并行
- **ORDER BY**：组内怎么排序。排名函数、LAG/LEAD 必须写
- **ROWS/RANGE**：框架子句。控制"往前看几行往后看几行"，后面细说

## 排名函数（用得最多）

### ROW_NUMBER() — 行号，不管并列

```sql
SELECT SalesMan, Amount,
    ROW_NUMBER() OVER (PARTITION BY SalesMan ORDER BY Amount DESC) AS rn
FROM #Sales;
```

| SalesMan | Amount | rn |
|----------|--------|----|
| 张三 | 200 | 1 |
| 张三 | 150 | 2 |
| 张三 | 100 | 3 |
| 李四 | 300 | 1 |
| 李四 | 250 | 2 |

**用途**：分组取 TopN、去重取最新一条，ROW_NUMBER 是你最好的朋友。

### RANK() — 有并列，会跳号

```sql
-- 假设有两个人都是 200 分
-- RANK: 1, 2, 2, 4  (跳过了 3)
```

### DENSE_RANK() — 有并列，不跳号

```sql
-- DENSE_RANK: 1, 2, 2, 3  (紧跟着)
```

### NTILE(n) — 分成 n 个桶

```sql
SELECT SalesMan, Amount,
    NTILE(3) OVER (ORDER BY Amount DESC) AS Bucket
FROM #Sales;
-- 把所有记录分成 3 组，用于做分位数分析
```

**三兄弟怎么选**：
- 取每组前 N 条（去重/分页）→ ROW_NUMBER
- 排名允许并列，结果要连续 → DENSE_RANK
- 排名允许并列，结果可以跳号 → RANK
- 分桶/百分位 → NTILE

## 偏移函数

### LAG() / LEAD() — 往前/往后看

```sql
SELECT SalesMan, SaleDate, Amount,
    LAG(Amount, 1, 0) OVER (PARTITION BY SalesMan ORDER BY SaleDate) AS PrevAmount,
    LEAD(Amount, 1, 0) OVER (PARTITION BY SalesMan ORDER BY SaleDate) AS NextAmount
FROM #Sales;
```

| SalesMan | SaleDate | Amount | PrevAmount | NextAmount |
|----------|----------|--------|------------|------------|
| 张三 | 01-01 | 100 | 0 | 200 |
| 张三 | 01-02 | 200 | 100 | 150 |
| 张三 | 01-03 | 150 | 200 | 0 |

三个参数：`LAG(列, 偏移几行, 默认值)`

**典型场景**：
- 环比计算：本月销售额 vs 上月销售额
- 连续问题：当前值和前一个值比较

### FIRST_VALUE() / LAST_VALUE() — 组内第一个/最后一个

```sql
SELECT SalesMan, SaleDate, Amount,
    FIRST_VALUE(Amount) OVER (PARTITION BY SalesMan ORDER BY SaleDate) AS FirstDayAmount
FROM #Sales;
-- 拿到每人第一天的销售额
```

::: warning LAST_VALUE 的坑
LAST_VALUE 默认的窗口范围是 `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`，也就是说它只能看到当前行及之前的行，所以你拿到的"最后一个值"其实就是当前行自己。

要真拿最后一个值，得写：
```sql
LAST_VALUE(Amount) OVER (
    PARTITION BY SalesMan ORDER BY SaleDate
    ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
)
```
:::

## 聚合窗口函数

所有聚合函数都能当窗口函数用：SUM、AVG、COUNT、MIN、MAX。

### 累计求和（跑步总计）

```sql
SELECT SalesMan, SaleDate, Amount,
    SUM(Amount) OVER (PARTITION BY SalesMan ORDER BY SaleDate) AS RunningTotal
FROM #Sales;
```

| SalesMan | SaleDate | Amount | RunningTotal |
|----------|----------|--------|--------------|
| 张三 | 01-01 | 100 | 100 |
| 张三 | 01-02 | 200 | 300 |
| 张三 | 01-03 | 150 | 450 |

为啥加了 ORDER BY 就变累计了？因为默认窗口范围是 `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`，表示从"组的第一行到当前行"。

### 移动平均

```sql
-- 最近 3 天的移动平均销售额
SELECT SalesMan, SaleDate, Amount,
    AVG(Amount) OVER (
        PARTITION BY SalesMan ORDER BY SaleDate
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS MovingAvg3
FROM #Sales;
```

### 占比计算

```sql
-- 每笔销售占该人总销售额的百分比
SELECT SalesMan, Amount,
    CAST(Amount * 100.0 / SUM(Amount) OVER (PARTITION BY SalesMan) AS DECIMAL(5,2)) AS Pct
FROM #Sales;
```

## 框架子句（ROWS vs RANGE）

框架子句控制窗口计算的行范围，格式：

```sql
ROWS|RANGE BETWEEN 起点 AND 终点
```

起点/终点的写法：
- `UNBOUNDED PRECEDING` — 从组的第一行开始
- `n PRECEDING` — 往前 n 行
- `CURRENT ROW` — 当前行
- `n FOLLOWING` — 往后 n 行
- `UNBOUNDED FOLLOWING` — 到组的最后一行

ROWS 和 RANGE 的区别：
- **ROWS**：物理行。`1 PRECEDING` 就是上一行，精确控制
- **RANGE**：逻辑范围。如果有相同值（ORDER BY 列重复），它会把相同值的行都算进来

实际开发中 **ROWS 用得多**，行为更可预测。

```sql
-- 前后各 1 行的移动平均（共 3 行）
AVG(Amount) OVER (ORDER BY SaleDate ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)

-- 截至当前行的累计最大值
MAX(Amount) OVER (ORDER BY SaleDate ROWS UNBOUNDED PRECEDING)

-- 整个分组的总计（不受 ORDER BY 影响）
SUM(Amount) OVER (PARTITION BY SalesMan)  -- 不写 ORDER BY，就是全组
```

## 实战套路

### 1. 每组取最新/最大的那条记录

这是面试和工作里最常见的窗口函数用法：

```sql
-- 每个客户最新的一笔订单
;WITH cte AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY CustomerId ORDER BY OrderDate DESC) AS rn
    FROM Orders
)
SELECT * FROM cte WHERE rn = 1;
```

### 2. 去重（保留最新一条）

```sql
;WITH cte AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY Phone ORDER BY CreateTime DESC) AS rn
    FROM Customers
)
DELETE FROM cte WHERE rn > 1;
-- 直接在 CTE 上 DELETE，每个手机号只保留最新的
```

### 3. 环比增长率

```sql
SELECT SaleDate, Amount,
    LAG(Amount) OVER (ORDER BY SaleDate) AS PrevAmount,
    CASE
        WHEN LAG(Amount) OVER (ORDER BY SaleDate) IS NULL THEN NULL
        WHEN LAG(Amount) OVER (ORDER BY SaleDate) = 0 THEN NULL
        ELSE CAST((Amount - LAG(Amount) OVER (ORDER BY SaleDate)) * 100.0
             / LAG(Amount) OVER (ORDER BY SaleDate) AS DECIMAL(10,2))
    END AS GrowthPct
FROM DailySales;
```

### 4. 累计占比（帕累托分析/二八定律）

```sql
SELECT ProductName, TotalSales,
    SUM(TotalSales) OVER (ORDER BY TotalSales DESC) AS RunningTotal,
    CAST(SUM(TotalSales) OVER (ORDER BY TotalSales DESC) * 100.0
         / SUM(TotalSales) OVER () AS DECIMAL(5,2)) AS RunningPct
FROM ProductSalesSummary
ORDER BY TotalSales DESC;
-- 找出贡献了 80% 销售额的那些产品
```

## 性能注意

1. **窗口函数会排序**。OVER 里有 ORDER BY 就会排序，数据量大的时候注意索引覆盖
2. **多个窗口函数共享同一个 OVER 定义时**，SQL Server 只排序一次，所以尽量让 PARTITION BY + ORDER BY 保持一致
3. **ROW_NUMBER + WHERE rn = 1** 的写法在大数据量下比 `GROUP BY + 子查询关联` 快得多，因为只需要一次扫描
4. 如果只是要 TopN，考虑用 `TOP n WITH TIES` 配合 `ORDER BY` 代替窗口函数，可能更简单
5. 窗口函数不能出现在 WHERE 里，只能在 SELECT 和 ORDER BY 里。想在 WHERE 里过滤，得用 CTE 或子查询包一层

## 速查表

| 函数 | 需要 ORDER BY | 用途 |
|------|:---:|------|
| ROW_NUMBER() | ✅ | 行号/去重/TopN |
| RANK() | ✅ | 排名（跳号） |
| DENSE_RANK() | ✅ | 排名（不跳号） |
| NTILE(n) | ✅ | 分桶 |
| LAG(col, n, default) | ✅ | 取前 n 行的值 |
| LEAD(col, n, default) | ✅ | 取后 n 行的值 |
| FIRST_VALUE(col) | ✅ | 窗口内第一个值 |
| LAST_VALUE(col) | ✅ | 窗口内最后一个值（注意框架） |
| SUM/AVG/COUNT/MIN/MAX | ❌ | 不加 ORDER BY = 全组聚合；加了 = 累计 |
