# 路由守卫

> **这一步解决什么问题？**
>
> 不是所有页面都应该对所有人开放——未登录用户不应该看到管理后台，多租户用户没选租户时不应该进入业务页面。路由守卫就是前端的"门禁系统"：在路由跳转前检查认证状态和租户选择，不满足条件的重定向到对应页面。这类似 ASP.NET Core 中 `[Authorize]` 过滤器——请求到达 Controller 之前先检查认证状态。

---

## 前置知识

| 概念 | 你需要知道的 | ASP.NET Core 类比 |
|------|------------|-----------------|
| React Router v6 | 声明式路由库，`<Routes>` + `<Route>` 定义路由表 | 类似 `Program.cs` 中的 `app.MapControllerRoute()` |
| `<Navigate>` 组件 | 声明式跳转，在渲染函数中使用 | 类似 `RedirectResult` |
| `navigate()` 函数 | 命令式跳转，在事件处理器中使用 | 类似手动修改 `HttpContext.Response` |
| Layout Route | 没有 `path` 的 Route，只提供布局包裹，子路由通过 `<Outlet />` 渲染 | 类似 `_Layout.cshtml` + `@RenderBody()` |
| `lazy()` + `Suspense` | 按需加载组件，减小首屏 bundle 体积 | 类似按需加载 Assembly |

```tsx
// src/components/layout/protected-route.tsx
import { Navigate, useLocation } from "react-router-dom"
import { useAuthStore } from "@/stores/auth-store"

/**
 * 路由保护组件
 *
 * 包裹需要认证才能访问的路由，未登录用户会被重定向到登录页。
 * 对于多租户用户，若尚未选择租户，则引导至租户选择页。
 *
 * @param children - 受保护的子组件
 */
export function ProtectedRoute({ children }: { children: React.ReactNode }) {
  const isAuthenticated = useAuthStore((s) => s.isAuthenticated)
  const currentTenantId = useAuthStore((s) => s.currentTenantId)
  const availableTenants = useAuthStore((s) => s.availableTenants)
  const location = useLocation()

  // 未认证 → 跳转登录页，保留来源路径以便登录后回跳
  if (!isAuthenticated) {
    return <Navigate to="/login" state={{ from: location }} replace />
  }

  // 多租户用户尚未选择租户 → 引导到租户选择页
  if (availableTenants && availableTenants.length > 1 && !currentTenantId) {
    return <Navigate to="/select-tenant" replace />
  }

  return <>{children}</>
}
```

## 三条件守卫逻辑

```
用户访问 /perm/users
       │
       ▼
  ┌─────────────────────────────────────────────┐
  │ 条件1：isAuthenticated === false ?           │
  │                                           │
  │   是 → <Navigate to="/login"               │
  │          state={{ from: location }} />     │
  │          保存来源路径，登录后可回跳             │
  ├─────────────────────────────────────────────┤
  │ 条件2：多租户 && 未选择租户 ?                  │
  │                                           │
  │   是 → <Navigate to="/select-tenant" />   │
  │          引导用户选择租户上下文                 │
  ├─────────────────────────────────────────────┤
  │ 条件3：通过守卫 ✅                            │
  │                                           │
  │   - 平台管理员（无租户上下文）                  │
  │   - 单租户用户（自动选中）                     │
  │   - 已选租户的多租户用户                       │
  │   → 渲染 children（目标页面）                 │
  └─────────────────────────────────────────────┘
```

> **🤔 导师提问**：为什么认证检查（条件1）在租户检查（条件2）之前？如果反过来先检查租户，会发生什么？

### 条件1：`!isAuthenticated` — 未登录

- 跳转 `/login`
- `state={{ from: location }}`：保存用户原本想访问的路径，登录后可以回跳
- `replace`：替换浏览器历史记录

> **后端类比**：类似 `[Authorize]` 特性。未认证用户自动重定向到登录页，`ReturnUrl` 参数保存来源路径。

### 条件2：多租户未选择

- 用户已登录，但属于多个租户且尚未选择当前租户
- 引导到 `/select-tenant`

> **后端类比**：类似自定义授权策略 `[Authorize(Policy = "RequireTenantSelection")]`。

### 条件3：放行

- 平台管理员（无租户上下文）
- 单租户用户（自动选中）
- 已选租户的多租户用户

## 登录回跳

```tsx
<Navigate to="/login" state={{ from: location }} replace />
```

`state.from` 保存了用户原本想访问的路径。登录成功后回跳的设计意图如下：

```tsx
const from = location.state?.from?.pathname || "/"
navigate(from, { replace: true })
```

**回跳流程**：

```
1. 用户直接访问 /perm/users（未登录）
2. ProtectedRoute 重定向到 /login，state.from = "/perm/users"
3. 用户输入密码登录成功
4. login 回调中 navigate(from, { replace: true })
5. 用户到达 /perm/users（原本想访问的页面）
```

> **后端类比**：ASP.NET Core 的 `[Authorize]` 自动将来源 URL 放入 `ReturnUrl` 参数，登录页通过 `Redirect(returnUrl)` 回跳。

> **【待实现】** `ProtectedRoute` 已经通过 `state={{ from: location }}` 保存了来源路径，但当前 `useAuth` 的 `login()` 函数并未读取 `location.state?.from`，登录成功后固定跳转到 `"/"` 或 `"/select-tenant"`。回跳功能需要后续在 `useAuth` 中补充读取 `from` 逻辑，目前登录后不会回到原页面。

### 【易错点】state.from 保存的是完整 location 对象

`state={{ from: location }}` 中的 `location` 是 React Router 的 Location 对象，包含 `pathname`、`search`、`hash` 等。回跳时通常只用 `pathname`，但如果目标页面需要 query 参数，应该也保存 `search`：

```typescript
// 当前写法：只回跳路径，丢失 query 参数
const from = location.state?.from?.pathname || "/"

// 更完整的写法：保留 query 和 hash
const from = location.state?.from?.pathname + (location.state?.from?.search || "") || "/"
```

## 在 App.tsx 中的使用

```tsx
// src/App.tsx
import { BrowserRouter, Routes, Route, Navigate } from "react-router-dom"
import { Toaster } from "sonner"
import { lazy, Suspense } from "react"
import { AppLayout } from "@/components/layout/app-layout"
import { ProtectedRoute } from "@/components/layout/protected-route"

// ─── 公共页面（首屏需要，保持静态导入） ─────────────────────
import LoginPage from "@/pages/login"
import SelectTenantPage from "@/pages/select-tenant"

// ─── 路由级懒加载（按模块拆分 chunk） ─────────────────────────
const DashboardPage = lazy(() => import("@/pages/dashboard"))

// SSO 认证中心
const AuthUsersPage = lazy(() => import("@/pages/auth/users"))
const AuthClientsPage = lazy(() => import("@/pages/auth/clients"))
const AuthScopesPage = lazy(() => import("@/pages/auth/scopes"))
const AuthRolesPage = lazy(() => import("@/pages/auth/roles"))

// 权限中心
const PermAppsPage = lazy(() => import("@/pages/perm/apps"))
const PermPermissionsPage = lazy(() => import("@/pages/perm/permissions"))
const PermRolesPage = lazy(() => import("@/pages/perm/roles"))
const PermTenantsPage = lazy(() => import("@/pages/perm/tenants"))
const PermUserRolesPage = lazy(() => import("@/pages/perm/user-roles"))
const PermOrganizationPage = lazy(() => import("@/pages/perm/organization"))
const PermPositionsPage = lazy(() => import("@/pages/perm/positions"))
const PermMembersPage = lazy(() => import("@/pages/perm/members"))

// ... 更多懒加载页面 ...

/** 页面懒加载 fallback */
function PageLoader() {
  return (
    <div className="flex h-full items-center justify-center text-muted-foreground">
      加载中...
    </div>
  )
}

/** 包裹懒加载组件，统一 Suspense */
function Lazy({ children }: { children: React.ReactNode }) {
  return <Suspense fallback={<PageLoader />}>{children}</Suspense>
}

export default function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* ── 公共路由（不需要认证）── */}
        <Route path="/login" element={<LoginPage />} />
        <Route path="/select-tenant" element={<SelectTenantPage />} />

        {/* ── 受保护路由（需要认证 + AppLayout 侧边栏布局）── */}
        <Route
          element={
            <ProtectedRoute>
              <AppLayout />
            </ProtectedRoute>
          }
        >
          {/* 主仪表盘 */}
          <Route index element={<Lazy><DashboardPage /></Lazy>} />

          {/* SSO 认证中心 /auth/* */}
          <Route path="auth">
            <Route index element={<Navigate to="/auth/users" replace />} />
            <Route path="users" element={<Lazy><AuthUsersPage /></Lazy>} />
            <Route path="clients" element={<Lazy><AuthClientsPage /></Lazy>} />
            <Route path="scopes" element={<Lazy><AuthScopesPage /></Lazy>} />
            <Route path="roles" element={<Lazy><AuthRolesPage /></Lazy>} />
          </Route>

          {/* 权限中心 /perm/* */}
          <Route path="perm">
            <Route index element={<Navigate to="/perm/apps" replace />} />
            <Route path="apps" element={<Lazy><PermAppsPage /></Lazy>} />
            {/* ... 更多子路由 ... */}
          </Route>

          {/* ... 更多模块路由 ... */}
        </Route>

        {/* 未匹配路由 → 重定向到主页 */}
        <Route path="*" element={<Navigate to="/" replace />} />
      </Routes>

      <Toaster position="top-right" richColors closeButton />
    </BrowserRouter>
  )
}
```

### 路由结构总览

```
/ (App)
├── /login               ← 公共路由（LoginPage）
├── /select-tenant       ← 公共路由（SelectTenantPage）
│
├── / (ProtectedRoute + AppLayout)
│   ├── /                ← 仪表盘（DashboardPage）
│   ├── /auth/*          ← SSO 认证中心
│   ├── /perm/*          ← 权限中心
│   ├── /gateway/*       ← 网关管理
│   ├── /file/*          ← 文件服务
│   ├── /notifications/* ← 通知中心
│   ├── /print/*         ← 打印服务
│   ├── /config/*        ← 配置中心
│   └── /ops/*           ← 租户运营中心
│
└── /*                    ← 兜底：重定向到 /
```

### 公共路由 vs 受保护路由

| 路由 | 类型 | 是否需要认证 | 是否有侧边栏布局 |
|------|------|------------|---------------|
| `/login` | 公共 | ❌ | ❌ |
| `/select-tenant` | 公共 | ✅（但不在 ProtectedRoute 内） | ❌ |
| `/` 及所有子路由 | 受保护 | ✅ | ✅（AppLayout） |

### 【易错点】/select-tenant 不在 ProtectedRoute 内

`/select-tenant` 路由放在公共路由区，但它需要认证才能使用。之所以不放在 `ProtectedRoute` 内，是因为 `ProtectedRoute` 会检测"多租户未选择"并重定向到 `/select-tenant`——如果 `/select-tenant` 也在 ProtectedRoute 内，就会产生无限重定向：

```
用户访问 /select-tenant
  → ProtectedRoute 检查：多租户未选择
  → 重定向到 /select-tenant
  → ProtectedRoute 检查：多租户未选择
  → 无限循环！
```

所以 `/select-tenant` 页面自己内部实现了认证守卫（通过 `useAuthStore` 判断），不走 `ProtectedRoute`。

## 集中式守卫的好处

```tsx
<Route
  element={
    <ProtectedRoute>
      <AppLayout />
    </ProtectedRoute>
  }
>
  {/* 所有子路由都需要通过守卫 */}
</Route>
```

1. **不会遗漏**：新增页面不需要记得加守卫
2. **代码简洁**：不需要每个路由都写 `<ProtectedRoute>`
3. **逻辑统一**：守卫条件只在一个地方维护

> **后端类比**：类似全局授权过滤器 vs 控制器级别的 `[Authorize]`。全局过滤器确保所有 API 默认需要认证。

### 【设计取舍】集中式守卫 vs 逐路由守卫

| 方案 | 优点 | 缺点 |
|------|------|------|
| 集中式（AdminWeb 选择） | 不会遗漏、维护简单 | 所有路由统一规则，灵活性低 |
| 逐路由守卫 | 灵活，每个路由可自定义 | 容易遗漏，维护成本高 |
| 混合（集中 + 局部覆盖） | 兼顾安全和灵活 | 规则复杂，容易混乱 |

AdminWeb 选择集中式守卫，因为所有管理后台页面的认证规则是一致的——都需要登录、多租户需要选租户。

## 使用 `<Navigate>` 而不是 `navigate()`

```tsx
// ✅ 推荐：声明式
if (!isAuthenticated) {
  return <Navigate to="/login" replace />
}

// ❌ 不推荐：命令式
if (!isAuthenticated) {
  navigate("/login", { replace: true })  // React 18+ 并发模式下可能产生副作用
  return null
}
```

在 React 18+ 的并发模式下，渲染函数可能被多次调用，`navigate()` 会产生副作用。`<Navigate>` 是声明式的，React 会在合适的时机处理跳转。

### Navigate vs navigate() 对比

| 维度 | `<Navigate>` 组件 | `navigate()` 函数 |
|------|-----------------|------------------|
| 范式 | 声明式 | 命令式 |
| React 18 并发模式 | ✅ 安全 | ⚠️ 可能重复执行 |
| 使用场景 | 渲染函数中的条件跳转 | 事件处理器中的跳转 |
| 返回值 | React 元素 | 无 |
| 副作用 | 无（React 管理时机） | 有（立即执行） |

> **后端类比**：声明式导航类似 `RedirectResult`，命令式类似手动修改 `HttpContext.Response`。前者更安全。

### 【易错点】事件处理器中应该用 navigate()

> **🤔 导师提问**：`SelectTenantPage` 的守卫用了 `navigate()` 而不是 `<Navigate>`，上一章提到这是有风险的。为什么还没修复？它实际带来了什么隐患？

```tsx
// ✅ 事件处理器中用 navigate()（命令式跳转是正确的）
const handleSubmit = async () => {
  await login(username, password)
  navigate("/")  // 登录成功后跳转
}

// ✅ 渲染函数中用 <Navigate>（声明式跳转）
if (!isAuthenticated) {
  return <Navigate to="/login" replace />
}
```

规则很简单：**渲染函数中用 `<Navigate>`，事件处理器中用 `navigate()`**。

## 懒加载与 Suspense

```tsx
const DashboardPage = lazy(() => import("@/pages/dashboard"))

function Lazy({ children }: { children: React.ReactNode }) {
  return <Suspense fallback={<PageLoader />}>{children}</Suspense>
}

// 使用
<Route index element={<Lazy><DashboardPage /></Lazy>} />
```

### 懒加载工作流程

```
用户首次访问 /perm/users
  │
  ├─ 1. ProtectedRoute 检查通过
  ├─ 2. AppLayout 渲染侧边栏和头部
  ├─ 3. Lazy 组件触发 import("@/pages/perm/permissions")
  │     → 网络加载 chunk 文件（如 perm-Dk3x.js）
  │     → Suspense 显示 <PageLoader>（"加载中..."）
  ├─ 4. chunk 加载完成，渲染 PermPermissionsPage
  └─ 5. PageLoader 消失，用户看到完整页面
```

### 【性能陷阱】Suspense fallback 的闪烁问题

如果 chunk 很小（< 50KB），加载可能只需 10-50ms，`PageLoader` 会短暂闪烁。解决方案：

1. **最小延迟**：给 PageLoader 加 `min-display-time`，至少显示 200ms
2. **Skeleton 屏**：用和目标页面结构相似的骨架屏替代简单的"加载中..."
3. **预加载**：在用户 hover 侧边栏菜单时提前 `import()` 对应 chunk

AdminWeb 当前使用简单的"加载中..."文字，因为管理后台的 chunk 加载通常很快。

### 懒加载为什么只用于子路由

注意 `LoginPage` 和 `SelectTenantPage` 是静态导入，不走 `lazy()`：

```typescript
// ─── 公共页面（首屏需要，保持静态导入） ─────────────────────
import LoginPage from "@/pages/login"
import SelectTenantPage from "@/pages/select-tenant"

// ─── 路由级懒加载（按模块拆分 chunk） ─────────────────────────
const DashboardPage = lazy(() => import("@/pages/dashboard"))
```

**原因**：登录页和租户选择页是用户进入应用的第一个页面，必须立即可见。懒加载反而会增加首次渲染延迟。而管理后台的子页面（权限、网关、文件等）不是首屏必需的，懒加载可以减小首屏 bundle 体积。

### 【设计取舍】首屏静态导入 vs 全部懒加载

| 方案 | 首屏加载速度 | 后续页面加载 |
|------|-----------|-----------|
| 关键页面静态导入 + 其余懒加载 | 快（关键代码在主 bundle 中） | 按需加载 |
| 全部懒加载 | 略慢（每个页面都要额外请求） | 按需加载 |
| 全部静态导入 | 快 | 快，但主 bundle 很大 |

AdminWeb 选择"关键页面静态导入 + 其余懒加载"，这是最常见的折中方案。

> **🤔 导师提问**：懒加载在首次访问时会多一个网络请求。什么时候这个代价不值得？哪些页面应该静态导入？

### React Router v6 的 Layout Route 模式

```tsx
<Route element={<ProtectedRoute><AppLayout /></ProtectedRoute>}>
  <Route path="auth">...</Route>
  <Route path="perm">...</Route>
</Route>
```

这个 `<Route element={...}>` 没有 `path` 属性——它是一个 **Layout Route**。它不会匹配任何 URL 路径，只会在子路由匹配时渲染。子路由的组件通过 `<Outlet />` 渲染在 `AppLayout` 内部。

```
URL: /perm/users

渲染层级：
  <ProtectedRoute>        ← 守卫检查
    <AppLayout>           ← 侧边栏 + 头部 + <Outlet />
      <PermUsersPage />   ← 通过 <Outlet /> 渲染
    </AppLayout>
  </ProtectedRoute>
```

> **后端类比**：类似 ASP.NET Core 中 `_Layout.cshtml` + `@RenderBody()`。Layout Route 是前端的母版页，子路由的内容通过 `<Outlet />`（相当于 `@RenderBody()`）插入。

## 踩坑提醒

1. **`/select-tenant` 不能放在 `ProtectedRoute` 内**：`ProtectedRoute` 会检测"多租户未选择"并重定向到 `/select-tenant`，如果 `/select-tenant` 也在 ProtectedRoute 内，会产生无限重定向循环
2. **渲染函数中用 `<Navigate>`，事件处理器中用 `navigate()`**：React 18+ 并发模式下渲染函数可能被多次调用，`navigate()` 会产生副作用
3. **`state={{ from: location }}` 保存的是完整 location 对象**：回跳时通常只用 `pathname`，但如果目标页面需要 query 参数，应该也保存 `search`
4. **登录回跳功能当前未完整实现**：`ProtectedRoute` 保存了来源路径，但 `useAuth` 的 `login()` 固定跳转 `"/"` 或 `"/select-tenant"`，未读取 `from`
