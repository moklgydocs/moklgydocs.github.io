# 登录页面 — 从 _Login.cshtml 到 React 组件

## 这一步解决什么问题？

在 ASP.NET Core MVC 里，登录页面是一个 Razor 视图（`_Login.cshtml`），表单提交到 `/Account/Login` Action，后端处理完认证后重定向。页面是服务端渲染的，CSRF 靠 `__RequestVerificationToken` 保护，状态靠 Session/Cookie 维持。

在 React SPA 里，登录页是一个**纯前端组件**——没有表单的 POST-back，没有服务端渲染，没有 `__RequestVerificationToken`。用户输入用户名密码，前端调 API 拿 Token，存到 localStorage，然后 `navigate("/")` 跳转。

| ASP.NET Core MVC | React SPA (AdminWeb) |
|---|---|
| `_Login.cshtml` + `AccountController.Login()` | `LoginPage` 组件 + `useAuth().login()` |
| `<form method="post">` 全页提交 | `<form onSubmit={handleSubmit}>` 阻止默认 |
| `__RequestVerificationToken` 防 CSRF | Bearer Token 无 CSRF 风险 |
| `ModelState.IsValid` 后端校验 | 前端 `if (!username || !password) return` |
| `RedirectToLocal(returnUrl)` | `navigate(from.pathname)` |
| 服务端渲染 HTML | 客户端渲染 + framer-motion 动画 |

> 💡 核心转变：登录不再是"提交表单给后端"，而是"前端拿 Token 做客户端路由跳转"。表单只是收集用户输入的 UI 容器。

---

## 概念：React 表单 vs HTML 表单

在传统 HTML 里，`<form>` 的默认行为是：

```
用户点击"登录" → 浏览器把 input 值打包 → POST 到 action URL → 页面刷新
```

React SPA 里，**页面不刷新**。我们需要阻止这个默认行为：

```
┌───────────────────────────────────────────────────────────┐
│             HTML 表单 vs React 表单                          │
├──────────────────┬────────────────────────────────────────┤
│                  │ HTML 原生表单     │ React 受控表单        │
├──────────────────┼──────────────────┼─────────────────────┤
│ 数据源           │ DOM（input.value）│ React state         │
│ 读取值           │ form.get()       │ useState 变量        │
│ 提交方式         │ 浏览器默认 POST   │ e.preventDefault()  │
│                  │                  │ + 手动调 API         │
│ 校验时机         │ submit 后后端校验 │ submit 前前端校验    │
│                  │                  │ + submit 后后端校验  │
│ CSRF 保护        │ __RequestVerificationToken│ Bearer Token 无 CSRF │
│ ASP.NET 类比     │ Razor 表单       │ AJAX + SPA          │
└──────────────────┴──────────────────┴─────────────────────┘
```

⚠️ **为什么 Bearer Token 不需要 CSRF 保护？** CSRF 攻击的原理是：恶意网站利用浏览器自动携带 Cookie 的特性，替用户发送请求。但 Bearer Token 不会自动携带——必须由 JS 代码手动从 localStorage 读取并注入 `Authorization` 头。恶意网站无法读取你的 localStorage（跨域限制），所以无法伪造请求。

## 完整代码：LoginPage

以下是 AdminWeb `src/pages/login/index.tsx` 的完整源码（227行）：

```typescript
/** 状态管理：useState */
import { useState } from "react"
/** 动画库：framer-motion */
import { motion } from "framer-motion"
/** 认证钩子：提供 login 方法 */
import { useAuth } from "@/hooks/use-auth"
/** UI 组件：按钮、输入框、标签 */
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"
import { Label } from "@/components/ui/label"
/** 图标：加载指示器、密码可见性切换 */
import { Loader2, Eye, EyeOff } from "lucide-react"
/** 品牌组件：Logo 与 LogoMark */
import { Logo, LogoMark } from "@/components/brand/logo"
/** 动画变体：交错容器与子项 */
import { staggerContainer, staggerItem } from "@/lib/motion"

/**
 * 登录页面组件
 *
 * 提供管理员账号登录功能，左侧展示品牌信息和平台介绍，
 * 右侧为登录表单。支持密码显示/隐藏切换。
 *
 * 核心功能：
 * - 用户名/密码表单登录
 * - 密码明文/密文切换显示
 * - 登录过程中禁用按钮并显示加载动画
 * - 左侧品牌面板含浮动装饰动画（仅桌面端可见）
 */
export default function LoginPage() {
  /** 认证上下文，解构出 login 方法用于提交登录 */
  const { login } = useAuth()
  /** 用户名输入值 */
  const [username, setUsername] = useState("")
  /** 密码输入值 */
  const [password, setPassword] = useState("")
  /** 登录请求加载状态，为 true 时禁用提交按钮 */
  const [loading, setLoading] = useState(false)
  /** 是否明文显示密码 */
  const [showPassword, setShowPassword] = useState(false)

  /**
   * 提交登录表单
   *
   * 阻止表单默认提交行为，校验用户名和密码非空后调用 login 方法。
   * 无论登录成功或失败，最终都会关闭 loading 状态。
   * 错误由 useAuth hook 内部统一处理（如 toast 提示）。
   *
   * @param e - 表单提交事件
   */
  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault()
    // 用户名或密码为空时不提交
    if (!username || !password) return

    setLoading(true)
    try {
      await login(username, password)
    } catch {
      // error handled in hook
    } finally {
      setLoading(false)
    }
  }

  return (
    <div className="flex min-h-screen">
      {/* 品牌展示面板 — 左侧（移动端隐藏） */}
      <div className="hidden lg:flex lg:w-1/2 relative overflow-hidden bg-primary">
        {/* 多层渐变背景增加深度感 */}
        <div className="absolute inset-0 bg-gradient-to-br from-primary via-primary/90 to-primary/70" />
        <div className="absolute inset-0 bg-[radial-gradient(ellipse_at_top_right,_rgba(255,255,255,0.08)_0%,_transparent_60%)]" />

        {/* 浮动装饰形状 — 四个不同大小的圆形，使用不同的动画延迟营造层次感 */}
        <motion.div
          className="absolute -top-20 -left-20 h-80 w-80 rounded-full bg-white/[0.04]"
          animate={{ y: [0, 20, 0], x: [0, 10, 0] }}
          transition={{ duration: 8, repeat: Infinity, ease: "easeInOut" }}
        />
        <motion.div
          className="absolute top-1/3 right-10 h-48 w-48 rounded-full bg-white/[0.04]"
          animate={{ y: [0, -15, 0], x: [0, -8, 0] }}
          transition={{ duration: 6, repeat: Infinity, ease: "easeInOut", delay: 1 }}
        />
        <motion.div
          className="absolute bottom-20 left-1/4 h-64 w-64 rounded-full bg-white/[0.04]"
          animate={{ y: [0, 12, 0] }}
          transition={{ duration: 7, repeat: Infinity, ease: "easeInOut", delay: 2 }}
        />
        <motion.div
          className="absolute -bottom-10 -right-10 h-96 w-96 rounded-full bg-white/[0.02]"
          animate={{ scale: [1, 1.05, 1] }}
          transition={{ duration: 10, repeat: Infinity, ease: "easeInOut" }}
        />

        {/* 微弱网格背景 — 48px 间距的白色细线 */}
        <div className="absolute inset-0 opacity-[0.025]"
          style={{
            backgroundImage: "linear-gradient(rgba(255,255,255,0.15) 1px, transparent 1px), linear-gradient(90deg, rgba(255,255,255,0.15) 1px, transparent 1px)",
            backgroundSize: "48px 48px",
          }}
        />

        {/* 品牌内容区 — 垂直排列 Logo、标语、统计数据 */}
        <div className="relative z-10 flex flex-col justify-between py-12 px-16 h-full">
          {/* 顶部：白色 Logo，带淡入上移动画 */}
          <motion.div
            initial={{ opacity: 0, y: 16 }}
            animate={{ opacity: 1, y: 0 }}
            transition={{ duration: 0.5, delay: 0.1 }}
          >
            <Logo variant="white" size="lg" />
          </motion.div>

          {/* 中部：平台标语与功能描述 */}
          <motion.div
            initial={{ opacity: 0, y: 20 }}
            animate={{ opacity: 1, y: 0 }}
            transition={{ duration: 0.6, delay: 0.3 }}
            className="space-y-4"
          >
            <h1 className="text-4xl font-bold tracking-tight text-white leading-tight">
              企业级 SaaS<br />基座管理平台
            </h1>
            <p className="text-base text-white/60 leading-relaxed max-w-sm">
              统一身份认证 / 权限管理 / API 网关 / 文件服务 / 打印服务 — 一站式企业数字化底座
            </p>
          </motion.div>

          {/* 底部：平台关键数据指标展示 */}
          <motion.div
            initial={{ opacity: 0 }}
            animate={{ opacity: 1 }}
            transition={{ duration: 0.6, delay: 0.7 }}
            className="flex gap-8"
          >
            {[
              { number: "5", label: "微服务集成" },
              { number: "20+", label: "管理模块" },
              { number: "RBAC", label: "权限模型" },
            ].map((stat) => (
              <div key={stat.label}>
                <p className="text-2xl font-bold text-white">{stat.number}</p>
                <p className="text-xs text-white/40 mt-0.5">{stat.label}</p>
              </div>
            ))}
          </motion.div>
        </div>
      </div>

      {/* 登录表单面板 — 右侧，垂直居中 */}
      <div className="flex w-full lg:w-1/2 items-center justify-center p-8 bg-background">
        {/* 交错动画容器：子元素依次入场 */}
        <motion.div
          variants={staggerContainer}
          initial="initial"
          animate="animate"
          className="w-full max-w-sm"
        >
          {/* 移动端 Logo（桌面端不显示）及欢迎标题 */}
          <motion.div variants={staggerItem} className="mb-8">
            <div className="lg:hidden mb-6">
              <Logo size="lg" />
            </div>
            <h2 className="text-2xl font-bold tracking-tight">欢迎回来</h2>
            <p className="text-sm text-muted-foreground mt-1">请登录您的管理员账号</p>
          </motion.div>

          {/* 登录表单 */}
          <form onSubmit={handleSubmit}>
            {/* 用户名输入框 */}
            <motion.div variants={staggerItem} className="space-y-2 mb-4">
              <Label htmlFor="username">用户名</Label>
              <Input
                id="username"
                placeholder="请输入用户名"
                value={username}
                onChange={(e) => setUsername(e.target.value)}
                autoComplete="username"
                autoFocus
                className="h-10"
              />
            </motion.div>

            {/* 密码输入框（支持明文/密文切换） */}
            <motion.div variants={staggerItem} className="space-y-2 mb-6">
              <Label htmlFor="password">密码</Label>
              <div className="relative">
                <Input
                  id="password"
                  type={showPassword ? "text" : "password"}
                  placeholder="请输入密码"
                  value={password}
                  onChange={(e) => setPassword(e.target.value)}
                  autoComplete="current-password"
                  className="h-10 pr-10"
                />
                {/* 密码可见性切换按钮 — 点击切换 Eye/EyeOff 图标 */}
                <button
                  type="button"
                  onClick={() => setShowPassword(!showPassword)}
                  className="absolute right-3 top-1/2 -translate-y-1/2 text-muted-foreground hover:text-foreground transition-colors"

                  {showPassword ? <EyeOff className="h-4 w-4" /> : <Eye className="h-4 w-4" />}

              </div>
            </motion.div>

            {/* 登录按钮 — loading 时显示旋转图标并禁用 */}
            <motion.div variants={staggerItem}>
              <Button type="submit" className="w-full h-10" disabled={loading}>
                {loading && <Loader2 className="mr-2 h-4 w-4 animate-spin" />}
                登录
              </Button>
            </motion.div>
          </form>

          {/* 底部版权信息 */}
          <motion.div variants={staggerItem} className="mt-8 flex items-center justify-center gap-2 text-xs text-muted-foreground/50">

        </motion.div>
      </div>
    </div>
  )
}
```

## 逐行解读：10个关键点

### 1️⃣ e.preventDefault() — 阻止表单默认提交

```typescript
const handleSubmit = async (e: React.FormEvent) => {
  e.preventDefault()
  if (!username || !password) return
  // ...
}
```

💡 这是 React 表单最关键的一行。没有它，点击"登录"按钮后浏览器会执行原生表单提交：页面刷新，URL 变成 `?username=xxx&password=xxx`，你的 JS 代码根本不会执行。

类比 ASP.NET Core：就像在 MVC 里不写 `return View()` 而写 `return Json()`——你不想让框架按默认行为渲染页面，而是自己控制响应。

### 2️⃣ 受控组件 — useState 绑定 input

```typescript
const [username, setUsername] = useState("")
// ...
<Input
  value={username}
  onChange={(e) => setUsername(e.target.value)}
/>
```

💡 这种模式叫**受控组件**（Controlled Component）：`value` 由 React state 驱动，`onChange` 更新 state，state 变化又触发重新渲染——数据流是单向的：

```
用户输入 → onChange → setState → 重新渲染 → value 更新
```

类比 ASP.NET Core：就像 `@Html.TextBoxFor(m => m.UserName)` —— Model 绑定驱动 input 的值，post-back 后 Model 更新又驱动页面重新渲染。只不过 React 是客户端即时更新，不需要往返服务器。

⚠️ 如果只写 `value={username}` 不写 `onChange`，input 会变成只读——React 不允许你修改 state 却不提供修改方法。

### 3️⃣ useAuth() — 认证逻辑外置到 Hook

```typescript
const { login } = useAuth()
// ...
await login(username, password)
```

💡 LoginPage 组件**只负责 UI**：收集用户名密码、显示加载状态。真正的认证逻辑（获取 Token、解析 JWT、加载用户信息、获取租户列表、决定跳转目标）全部封装在 `useAuth` Hook 里。

这是 React 的核心设计原则：**UI 与逻辑分离**。组件管渲染，Hook 管逻辑。

类比 ASP.NET Core：
- LoginPage ≈ `_Login.cshtml`（纯视图）
- `useAuth` ≈ `AccountController` + `SignInManager`（认证逻辑）
- `authApi` ≈ `HttpClient` 调用 SSO 服务（网络请求）

### 4️⃣ loading 状态 — 防止重复提交

```typescript
const [loading, setLoading] = useState(false)
// ...
setLoading(true)
try {
  await login(username, password)
} catch {
  // error handled in hook
} finally {
  setLoading(false)
}
```

💡 `loading` 有两个作用：
1. **UI 层**：按钮显示旋转图标 + `disabled` 变灰
2. **逻辑层**：`disabled` 后用户无法再次点击，防止重复提交

`finally` 确保 loading 一定被关闭——无论 `login` 成功还是失败。注意 `login` 成功后会 `navigate("/")` 跳走，组件卸载，但 `finally` 仍会执行（Promise resolve 后 finally 在微任务中执行）。

类比 ASP.NET Core：就像按钮加 `disabled="disabled"` + 后端幂等性校验的双重保护。

### 5️⃣ 密码可见性切换 — 声明式 UI

```typescript
const [showPassword, setShowPassword] = useState(false)
// ...
<Input type={showPassword ? "text" : "password"} />
<button type="button" onClick={() => setShowPassword(!showPassword)}>
  {showPassword ? <EyeOff /> : <Eye />}
</button>
```

💡 整个密码切换逻辑只需要一个布尔 state。React 的声明式特性让你不需要手动操作 DOM（比如 `input.type = "text"`），只需改变 state，React 自动更新 UI。

⚠️ 切换按钮的 `type="button"` 非常重要！默认 `type="submit"`，点击会触发表单提交。加了 `type="button"` 后，点击只切换密码可见性，不提交表单。

### 6️⃣ 响应式布局 — Tailwind 断点

```typescript
{/* 左侧品牌面板：移动端隐藏，lg(1024px)以上显示 */}
<div className="hidden lg:flex lg:w-1/2">

{/* 右侧登录面板：移动端全宽，lg 以上半宽 */}
<div className="flex w-full lg:w-1/2">

{/* 移动端 Logo：lg 以上隐藏 */}
<div className="lg:hidden mb-6">
  <Logo size="lg" />
</div>
```

💡 Tailwind 的断点系统：
- `hidden` = `display: none`
- `lg:flex` = 屏幕 >= 1024px 时 `display: flex`
- `lg:w-1/2` = 屏幕 >= 1024px 时 `width: 50%`
- `lg:hidden` = 屏幕 >= 1024px 时 `display: none`

效果：手机上只显示右侧登录表单（全屏），桌面端左右各占 50%。

类比 ASP.NET Core：就像 `_Layout.cshtml` 里的 `@if (Request.Browser.IsMobileDevice)` 条件渲染，但 Tailwind 用 CSS 媒体查询实现，不需要服务端判断。

### 7️⃣ framer-motion 交错动画 — staggerContainer + staggerItem

```typescript
<motion.div
  variants={staggerContainer}
  initial="initial"
  animate="animate"
  className="w-full max-w-sm"
>
  <motion.div variants={staggerItem}>标题</motion.div>
  <motion.div variants={staggerItem}>用户名</motion.div>
  <motion.div variants={staggerItem}>密码</motion.div>
  <motion.div variants={staggerItem}>按钮</motion.div>
  <motion.div variants={staggerItem}>版权</motion.div>
</motion.div>
```

💡 `staggerContainer` 和 `staggerItem` 定义在 `src/lib/motion.ts` 中：

```typescript
export const staggerContainer: Variants = {
  initial: {},
  animate: {
    transition: { staggerChildren: 0.05 },
  },
}

export const staggerItem: Variants = {
  initial: { opacity: 0, y: 8 },
  animate: { opacity: 1, y: 0, transition: { duration: 0.2 } },
}
```

效果：5个子元素不是同时出现，而是依次延迟 0.05s 淡入上移——像瀑布流一样，视觉上很有节奏感。

类比：CSS `animation-delay` 可以实现类似效果，但 framer-motion 的 `staggerChildren` 更声明式——你只需要标记"这个容器交错出现"，不需要给每个子元素手动算 delay。

### 8️⃣ 左侧面板浮动装饰 — motion.div 无限循环

```typescript
<motion.div
  className="absolute -top-20 -left-20 h-80 w-80 rounded-full bg-white/[0.04]"
  animate={{ y: [0, 20, 0], x: [0, 10, 0] }}
  transition={{ duration: 8, repeat: Infinity, ease: "easeInOut" }}
/>
```

💡 这是一个**无限循环的关键帧动画**：
- `animate={{ y: [0, 20, 0] }}`：y 轴 0→20→0 往复
- `repeat: Infinity`：无限循环
- 4个装饰圆形使用不同的 `duration`（6-10s）和 `delay`（0-2s），营造层次感

⚠️ `bg-white/[0.04]`：白色，4% 不透明度——几乎看不见，但在深色背景上制造出"有东西在动"的微妙感觉。这是高端 SaaS 产品常用的视觉手法。

类比 ASP.NET Core：纯 UI 效果，后端没有对应概念。如果用 Blazor，可以用相同的 framer-motion 或 CSS 动画实现。

### 9️⃣ Button disabled — 交互防御

```typescript
<Button type="submit" className="w-full h-10" disabled={loading}>
  {loading && <Loader2 className="mr-2 h-4 w-4 animate-spin" />}
  登录
</Button>
```

💡 `disabled={loading}` 的效果：
1. 按钮变灰，视觉上告诉用户"不可点击"
2. 原生 `<button disabled>` 会阻止 `onClick` 和 `onSubmit` 事件
3. 无障碍：屏幕阅读器会播报"按钮已禁用"

`Loader2` 是 lucide-react 的加载图标，`animate-spin` 是 Tailwind 的旋转动画类。

类比 ASP.NET Core：
```csharp
// 后端等价
if (isSubmitting) return; // 防止重复提交
```

### 🔟 autoComplete 属性 — 浏览器密码管理器

```typescript
<Input autoComplete="username" />
<Input autoComplete="current-password" />
```

💡 这两个属性告诉浏览器密码管理器："这是用户名字段，这是当前密码字段"。浏览器可以：
1. 自动填充已保存的用户名密码
2. 提示用户保存新密码
3. 与生物识别（指纹、Face ID）集成

如果不加，浏览器可能无法正确识别登录表单，用户每次都要手动输入。

类比 ASP.NET Core：就像 `<input type="email">` 让浏览器显示邮箱键盘——标准属性让浏览器提供更好的用户体验。

## 登录按钮点击后的完整时序

点击"登录"后，不仅仅是发一个 HTTP 请求那么简单。AdminWeb 的登录流程有三步：

```
用户点击"登录"按钮
        │
        ▼
┌─── LoginPage: handleSubmit ────────────────────────────────┐
│  1. e.preventDefault()  阻止默认提交                         │
│  2. if (!username || !password) return  前端校验             │
│  3. setLoading(true)  显示加载状态                          │
│  4. await login(username, password)  调用 useAuth           │
│     │                                                      │
│     ▼                                                      │
│  ┌─── useAuth.login ──────────────────────────────────┐     │
│  │  步骤1: authApi.getToken(username, password)        │     │
│  │  → POST /connect/token grant_type=password         │     │
│  │  ← { access_token, refresh_token }                 │     │
│  │  → setTokens(access_token, refresh_token)          │     │
│  │                                                     │     │
│  │  步骤2: authApi.getCurrentUser()                    │     │
│  │  → GET /api/account/current                        │     │
│  │  ← { id, userName, email, ... }                    │     │
│  │  → 合并 JWT claims + API 数据 → setUser(...)       │     │
│  │                                                     │     │
│  │  步骤3: authApi.getMyTenants()                      │     │
│  │  → GET /api/account/my-tenants                     │     │
│  │  ← [{ tenantId, tenantName, tenantIdentifier }]    │     │
│  │                                                     │     │
│  │  判断租户数量:                                       │     │
│  │  ├── 0个 → navigate("/")     平台管理员              │     │
│  │  ├── 1个 → setCurrentTenant → navigate("/")  自动选 │     │
│  │  └── N个 → navigate("/select-tenant")  手动选       │     │
│  └─────────────────────────────────────────────────────┘     │
│                                                              │
│  5. finally: setLoading(false)  无论成功失败都关闭加载       │
└──────────────────────────────────────────────────────────────┘
```

## 🤔 思考题

### 概念级（理解是什么）

1. LoginPage 组件里没有 `useEffect`，也没有生命周期方法。它是怎么在页面加载时自动聚焦到用户名输入框的？提示：看 `autoFocus` 属性。

2. `handleSubmit` 里的 `catch {}` 是空的，错误真的被"吞掉"了吗？`useAuth.login` 内部是怎么处理错误的？

### 推理级（为什么这样设计）

3. 左侧品牌面板用了 `hidden lg:flex`，移动端完全不渲染。如果改用 `lg:block` 配合 `opacity-0 lg:opacity-100`，用户在移动端会有什么体验差异？考虑 DOM 节点数和 CSS 性能。

4. 密码切换按钮用了 `type="button"` 而不是默认的 `type="submit"`。如果忘记加 `type="button"`，用户点击眼睛图标会发生什么？

5. `loading` 状态在组件内部用 `useState` 管理，而不是放在 Zustand store 里。为什么登录的 loading 不需要全局共享？

### 实践级（动手验证）

6. 打开浏览器 DevTools → Network，执行一次登录。观察网络请求的顺序：先发 `/connect/token`（获取 Token），再发 `/api/account/current`（获取用户信息），最后发 `/api/account/my-tenants`（获取租户列表）。验证这个三步时序。

7. 在 Network 面板中，查看 `/connect/token` 请求的 Payload（Form Data）。注意 `grant_type=password` 和 `scope=openid profile email roles api offline_access`。试着删除 `offline_access`，看看还会不会返回 `refresh_token`。
