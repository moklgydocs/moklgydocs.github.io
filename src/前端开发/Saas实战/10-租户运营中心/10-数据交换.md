# 数据交换

> **这一步解决什么问题？**
> 运营中心需要将平台数据导出为文件（供审计、分析），也需要从文件批量导入租户数据。这涉及浏览器原生的文件处理——Blob 导出和 FormData 导入。本节我们从 API 到页面，完整理解数据交换的前端实现。
>
> **ASP.NET Core 开发者的直觉**：Blob 导出就像 `FileContentResult`（返回二进制流），FormData 导入就像 `IFormFile` 参数（接收上传文件）。前端用 `URL.createObjectURL` 触发下载，对应后端的 `Content-Disposition: attachment`；前端用 `FormData` 封装上传，对应后端的 `multipart/form-data` 绑定。

## 一、数据交换 API 层

### 1.1 完整 API 代码

```typescript
// src/api/ops/data-exchange.ts
import opsHttpInstance from "./http"

export const dataExchangeApi = {
  exportOperations: (params: { tenantId?: string; operationType?: string; from?: string; to?: string; format?: string }) =>
    opsHttpInstance.get("/api/tenant-ops/data/export/operations", { params, responseType: "blob" }),
  exportInvoices: (params: { tenantId?: string; year?: number; month?: number; format?: string }) =>
    opsHttpInstance.get("/api/tenant-ops/data/export/invoices", { params, responseType: "blob" }),
  exportUsage: (params: { tenantId?: string; year?: number; month?: number; format?: string }) =>
    opsHttpInstance.get("/api/tenant-ops/data/export/usage", { params, responseType: "blob" }),
  importTenants: (file: File) => {
    const formData = new FormData()
    formData.append("file", file)
    return opsHttpInstance.post("/api/tenant-ops/data/import/tenants", formData, {
      headers: { "Content-Type": "multipart/form-data" },
    })
  },
}
```

### 1.2 4 个方法解读

| 方法 | HTTP | 路径 | 说明 |
|------|------|------|------|
| `exportOperations` | GET | `/api/tenant-ops/data/export/operations` | 导出操作日志（支持筛选） |
| `exportInvoices` | GET | `/api/tenant-ops/data/export/invoices` | 导出发票数据（按年月筛选） |
| `exportUsage` | GET | `/api/tenant-ops/data/export/usage` | 导出使用量数据 |
| `importTenants` | POST | `/api/tenant-ops/data/import/tenants` | 批量导入租户（上传文件） |

### 1.3 关键技术细节

【易错点】 **responseType: "blob"**：导出 API 必须设置 `responseType: "blob"`。Axios 默认 `responseType` 是 `"json"`，如果不改，二进制文件数据会被当作文本解析，导致乱码。注意这里用的是 `opsHttpInstance`（axios 实例）而非 `get` 方法，因为 `get` 方法的签名不支持 `responseType` 配置。

【易错点】 **FormData 上传的 Content-Type**：`importTenants` 中手动设置了 `Content-Type: "multipart/form-data"`。实际上，浏览器在发送 FormData 时会自动设置正确的 `Content-Type`（包含 boundary），手动设置反而可能导致 boundary 丢失。不过 axios 通常能正确处理这种情况。

🤔 **导师提问**：为什么导出 API 用 GET 而不是 POST？因为导出是"读"操作，不修改服务器状态。GET 请求可以被浏览器缓存、被书签收藏。但大量筛选参数放在 URL 中可能超过长度限制——这时候应该用 POST + body 传参。

## 四、Blob 导出关键逻辑

### 4.1 下载 Blob 文件

```typescript
async function handleExport(
  apiFn: () => Promise<{ data: Blob }>,
  filename: string,
  setBusy: (v: boolean) => void,
) {
  setBusy(true)
  try {
    const res = await apiFn()
    const blob = res.data instanceof Blob ? res.data : new Blob([res.data as BlobPart])
    const url = URL.createObjectURL(blob)
    const a = document.createElement("a")
    a.href = url
    a.download = filename
    document.body.appendChild(a)
    a.click()
    document.body.removeChild(a)
    URL.revokeObjectURL(url)
    toast.success(`${filename} 导出成功`)
  } catch (err) {
    toast.error("导出失败", { description: err instanceof Error ? err.message : String(err) })
  } finally {
    setBusy(false)
  }
}
```

> **后端类比**：Blob 导出就像 ASP.NET Core 的 `FileContentResult`——后端返回二进制流，前端用 `URL.createObjectURL` 创建临时链接触发下载。`URL.revokeObjectURL` 对应 `Dispose()`——用完必须释放。

### 4.2 Blob 类型安全检查

```typescript
const blob = res.data instanceof Blob ? res.data : new Blob([res.data as BlobPart])
```

这行代码做了防御性处理：如果 `res.data` 已经是 `Blob`，直接使用；否则包装成 `Blob`。这是因为 axios 在某些配置下可能返回 `ArrayBuffer` 而非 `Blob`。

### 4.3 内存回收

```typescript
URL.revokeObjectURL(url) // 必须！释放内存
```

【易错点】 `URL.createObjectURL` 创建的临时 URL 会占用浏览器内存。如果不调用 `revokeObjectURL`，内存会一直被占用，直到页面卸载（`beforeunload`）。在频繁导出的场景下，这可能导致内存泄漏。必须在下载完成后立即释放。

🤔 **导师提问**：为什么用 `document.createElement("a").click()` 而不是 `window.open(url)`？因为 `window.open` 会被浏览器弹窗拦截器阻止，而 `<a>` 标签的 `download` 属性是浏览器允许的下载行为，不会被拦截。

## 五、FormData 导入关键逻辑

### 5.1 文件上传

```typescript
export function importTenants(file: File) {
  const formData = new FormData()
  formData.append("file", file)
  return opsHttpInstance.post("/api/tenant-ops/data/import/tenants", formData, {
    headers: { "Content-Type": "multipart/form-data" },
  })
}
```

> **后端类比**：FormData 导入就像 ASP.NET Core 的 `IFormFile` 参数——`[FromForm]` 绑定上传文件。前端用 `FormData.append` 封装文件，浏览器自动处理 `multipart/form-data` 编码。

### 5.2 隐藏的 file input

```tsx
<input
  ref={fileInputRef}
  type="file"
  accept=".xlsx,.csv"
  className="hidden"
  onChange={e => {
    const file = e.target.files?.[0]
    if (file) handleImport(file)
  }}
/>
<Button onClick={() => fileInputRef.current?.click()} disabled={importing}>
  <Upload className="h-4 w-4 mr-1.5" />
  {importing ? "导入中..." : "选择文件并导入"}
</Button>
```

这是一个常见的"美化文件选择按钮"模式：原生的 `<input type="file">` 样式难以自定义，所以用 CSS 隐藏它，用 Button 触发它的 `click()` 方法。

【易错点】 **大文件导入超时**：如果导入文件包含数千条租户数据，后端处理可能需要几十秒甚至几分钟。Axios 的默认超时时间可能不够。需要在 `opsHttpInstance` 的配置中为导入请求设置更长的超时时间，或使用后端的异步任务模式（上传→返回任务ID→轮询进度）。

【易错点】 **文件编码问题**：CSV 文件的编码可能不一致（UTF-8、GBK、Latin-1）。如果后端期望 UTF-8 但收到了 GBK 编码的文件，中文会变成乱码。前端可以在上传前用 `FileReader.readAsText(file)` 检测编码，或者后端做编码自动检测。

## 六、设计取舍

【设计取舍】 CSV vs JSON vs Excel——三种数据交换格式的对比：

| 维度 | CSV | JSON | Excel (XLSX) |
|------|-----|------|-------------|
| **结构化程度** | 扁平表格 | 嵌套对象 | 扁平+多 Sheet |
| **可读性** | 高（纯文本） | 中（需要格式化） | 高（电子表格打开） |
| **数据类型** | 全部是字符串 | 保留原始类型 | 保留原始类型 |
| **大文件处理** | 流式读取 | 需要全部加载 | 需要全部加载 |
| **国际化** | 编码问题（GBK vs UTF-8） | UTF-8 无问题 | 无问题 |
| **前端实现** | `responseType: "blob"` | `responseType: "json"` | `responseType: "blob"` |
| **导入校验** | 简单（行分隔） | 复杂（嵌套结构） | 中等（Sheet 结构） |
| **非技术用户** | 可用 Excel 打开 | 需要转换 | 直接打开 |

**本项目选择 Excel (XLSX) 为默认格式**：运营人员习惯用 Excel 处理数据，XLSX 保留数据类型（数字不会被误判为字符串），且支持多 Sheet。CSV 作为备选格式，适合程序间的数据交换。

【性能陷阱】 **批量数据处理的性能**：导入数千条租户数据时，后端通常需要：
1. 解析文件（几秒）
2. 逐行校验（几秒~几十秒）
3. 批量写入数据库（几秒~几分钟）

如果第 3 步很慢，应该使用批量 INSERT 而非逐行 INSERT。前端目前是同步等待（按钮显示"导入中..."），如果超时需要改为异步任务模式。

🤔 **导师提问**：如果导入文件有 10000 行，其中 100 行数据有错误（格式不对、缺少必填字段），应该怎么处理？全部失败？跳过错误行继续导入？还是导入正确的行并返回错误报告？提示：考虑"部分成功"模式——导入成功的写入数据库，失败的行收集在响应中返回。

## 七、导出参数的空值处理

三种导出 API 的参数都有可选字段。前端用 `||` 运算符将空字符串转为 `undefined`：

```typescript
tenantId: opsTenantId || undefined,   // 空字符串 → undefined → 不传
operationType: opsType || undefined,
from: opsFrom || undefined,
```

【易错点】 这里用 `||` 而非 `??` 是故意的。因为表单的空值是 `""`（空字符串），不是 `null`。`??` 只处理 `null`/`undefined`，对空字符串无效。`||` 处理所有 falsy 值（包括 `""`），正好把空字符串过滤为 `undefined`。

但数字字段需要额外处理：

```typescript
year: invYear ? Number(invYear) : undefined,  // 空字符串 → undefined
month: invMonth ? Number(invMonth) : undefined,
```

因为 `<Input type="number">` 的 `value` 仍然是字符串类型，需要 `Number()` 转换。

## ⚠️ 踩坑提醒

1. **`responseType: "blob"` 必须设置**：Axios 默认 `responseType` 是 `"json"`，如果不改，二进制文件数据会被当作文本解析，导致乱码。
2. **`URL.revokeObjectURL` 必须调用**：`URL.createObjectURL` 创建的临时 URL 会占用浏览器内存。如果不释放，频繁导出可能导致内存泄漏。
3. **用 `<a>.click()` 而非 `window.open()`**：`window.open` 会被浏览器弹窗拦截器阻止，而 `<a>` 标签的 `download` 属性不会被拦截。
4. **CSV 文件编码问题**：CSV 文件的编码可能不一致（UTF-8、GBK）。如果后端期望 UTF-8 但收到了 GBK 编码的文件，中文会变成乱码。
5. **大文件导入可能超时**：如果导入文件包含数千条数据，后端处理可能需要很长时间。需要设置更长的超时时间，或使用异步任务模式。
