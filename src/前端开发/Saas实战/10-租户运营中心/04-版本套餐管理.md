# 04 - 版本套餐管理：动态行表单与 CRUD 交互

> **这一步解决什么问题？**
> 版本（Edition）定义了 SaaS 产品的定价、可用模块和配额策略。本节实现版本列表页、版本表单对话框（含动态模块行和配额行），以及删除确认。核心难点是**动态行**的增删改——模块列表和配额列表都是可增删的数组，前端用展开更新模式保证不可变性。
>
> **ASP.NET Core 开发者的直觉**：版本表单 ≈ 一个复杂的 `EditContext` + 集合导航属性编辑。动态行的增删改就像 EF Core 的 `Collection.Add/Remove`，展开运算符 `[...modules]` 就是 `AsNoTracking()` 的深拷贝。

---

## 前置知识

- **模块 10-01** 中的 `EditionDto` 类型定义和版本代码不可变性
- **模块 10-02** 中的 `editionsApi` 五个 CRUD 方法
- React 受控组件 + `useState` 管理表单状态
- 数组不可变更新模式：`[...arr]` 展开 + `filter` 删除 + 索引替换更新

### 版本表单对话框（含动态行）

```tsx
// src/pages/ops/editions/edition-form-dialog.tsx
import { useEffect, useState } from "react"
import {
  Dialog, DialogContent, DialogHeader, DialogTitle, DialogFooter,
} from "@/components/ui/dialog"
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"
import { Label } from "@/components/ui/label"
import { Switch } from "@/components/ui/switch"
import { Checkbox } from "@/components/ui/checkbox"
import { editionsApi } from "@/api/ops/editions"
import { toast } from "sonner"
import { Loader2, Plus, X } from "lucide-react"
import type { EditionDto, CreateEditionModuleRequest, CreateEditionQuotaRequest } from "@/types"

interface EditionFormDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  item: EditionDto | null
  onSuccess: () => void
}

interface ModuleRow {
  moduleCode: string
  moduleDisplayName: string
  isIncluded: boolean
  isDefault: boolean
}

interface QuotaRow {
  resourceType: string
  resourceName: string
  defaultValue: number
  unit: string
  isAdjustable: boolean
  sortOrder: number
}

export function EditionFormDialog({ open, onOpenChange, item, onSuccess }: EditionFormDialogProps) {
  const isEdit = !!item
  const [loading, setLoading] = useState(false)
  const [form, setForm] = useState({
    code: "", displayName: "", description: "",
    monthlyPrice: 0, yearlyPrice: 0, isActive: true, sortOrder: 0, featuresJson: "",
  })
  const [modules, setModules] = useState<ModuleRow[]>([])
  const [quotas, setQuotas] = useState<QuotaRow[]>([])

  useEffect(() => {
    if (open) {
      setForm({
        code: item?.code ?? "", displayName: item?.displayName ?? "",
        description: item?.description ?? "", monthlyPrice: item?.monthlyPrice ?? 0,
        yearlyPrice: item?.yearlyPrice ?? 0, isActive: item?.isActive ?? true,
        sortOrder: item?.sortOrder ?? 0, featuresJson: item?.featuresJson ?? "",
      })
      setModules(item?.modules?.map((m) => ({
        moduleCode: m.moduleCode, moduleDisplayName: m.moduleDisplayName ?? "",
        isIncluded: m.isIncluded, isDefault: m.isDefault,
      })) ?? [])
      setQuotas(item?.quotaDefaults?.map((q) => ({
        resourceType: q.resourceType, resourceName: q.resourceName,
        defaultValue: q.defaultValue, unit: q.unit ?? "",
        isAdjustable: q.isAdjustable, sortOrder: q.sortOrder,
      })) ?? [])
    }
  }, [open, item])

  const addModule = () => setModules([...modules, { moduleCode: "", moduleDisplayName: "", isIncluded: true, isDefault: false }])
  const removeModule = (index: number) => setModules(modules.filter((_, i) => i !== index))
  const updateModule = (index: number, field: keyof ModuleRow, value: string | boolean) => {
    const updated = [...modules]
    updated[index] = { ...updated[index], [field]: value }
    setModules(updated)
  }

  const addQuota = () => setQuotas([...quotas, { resourceType: "", resourceName: "", defaultValue: 0, unit: "", isAdjustable: true, sortOrder: 0 }])
  const removeQuota = (index: number) => setQuotas(quotas.filter((_, i) => i !== index))
  const updateQuota = (index: number, field: keyof QuotaRow, value: string | number | boolean) => {
    const updated = [...quotas]
    updated[index] = { ...updated[index], [field]: value }
    setQuotas(updated)
  }

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault()
    if (!form.code || !form.displayName) { toast.error("版本代码和显示名称不能为空"); return }

    const modulePayload: CreateEditionModuleRequest[] = modules
      .filter((m) => m.moduleCode)
      .map((m) => ({
        moduleCode: m.moduleCode, moduleDisplayName: m.moduleDisplayName || undefined,
        isIncluded: m.isIncluded, isDefault: m.isDefault,
      }))

    const quotaPayload: CreateEditionQuotaRequest[] = quotas
      .filter((q) => q.resourceType && q.resourceName)
      .map((q) => ({
        resourceType: q.resourceType, resourceName: q.resourceName,
        defaultValue: q.defaultValue, unit: q.unit || undefined,
        isAdjustable: q.isAdjustable, sortOrder: q.sortOrder,
      }))

    setLoading(true)
    try {
      if (isEdit) {
        await editionsApi.update(item.id, {
          displayName: form.displayName, description: form.description || undefined,
          monthlyPrice: form.monthlyPrice, yearlyPrice: form.yearlyPrice,
          isActive: form.isActive, sortOrder: form.sortOrder,
          featuresJson: form.featuresJson || undefined,
          modules: modulePayload, quotaDefaults: quotaPayload,
        })
        toast.success("版本已更新")
      } else {
        await editionsApi.create({
          code: form.code, displayName: form.displayName, description: form.description || undefined,
          monthlyPrice: form.monthlyPrice, yearlyPrice: form.yearlyPrice,
          sortOrder: form.sortOrder, featuresJson: form.featuresJson || undefined,
          modules: modulePayload, quotaDefaults: quotaPayload,
        })
        toast.success("版本已创建")
      }
      onSuccess()
      onOpenChange(false)
    } catch {
      toast.error(isEdit ? "更新失败" : "创建失败")
    } finally {
      setLoading(false)
    }
  }

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="sm:max-w-xl max-h-[85vh] overflow-y-auto">
        <DialogHeader>
          <DialogTitle>{isEdit ? "编辑版本" : "新建版本"}</DialogTitle>
        </DialogHeader>
        <form onSubmit={handleSubmit} className="space-y-4 py-2">
          {/* 基础字段、模块列表、配额列表...（完整表单见源码） */}
        </form>
      </DialogContent>
    </Dialog>
  )
}
```

## 代码讲解

### 动态行的增删改模式

模块和配额都使用**数组 + 展开更新**模式：

```typescript
// 添加：展开原数组，追加新行
const addModule = () => setModules([...modules, { moduleCode: "", ... }])

// 删除：filter 过滤掉目标索引
const removeModule = (index: number) => setModules(modules.filter((_, i) => i !== index))

// 更新：展开目标索引行，覆盖单个字段
const updateModule = (index: number, field: keyof ModuleRow, value: string | boolean) => {
  const updated = [...modules]
  updated[index] = { ...updated[index], [field]: value }
  setModules(updated)
}
```

💡 **ASP.NET Core 类比**：动态行操作就像 EF Core 的集合导航属性——`addModule` 对应 `Edition.Modules.Add()`，`removeModule` 对应 `Edition.Modules.Remove()`，`updateModule` 对应修改导航属性中某个实体的字段。展开运算符 `[...modules]` 就是 `AsNoTracking()` 的深拷贝。

> 🤔 **导师提问**：动态行的"展开更新"模式 `const updated = [...modules]; updated[i] = { ...updated[i], [field]: value }` 保证了不可变性（immutable update）。在后端 EF Core 中，你修改导航属性直接赋值即可，ChangeTracker 会自动追踪。为什么前端必须用不可变更新？如果直接 `modules[i].moduleCode = "new"`，React 会感知到变化吗？

### 版本代码的创建/编辑差异

```typescript
// 创建时：code 可编辑
<Input value={form.code} onChange={...} disabled={isEdit} />

// 提交时：编辑模式不发送 code
if (isEdit) {
  await editionsApi.update(item.id, { displayName: form.displayName, ... }) // 不含 code
} else {
  await editionsApi.create({ code: form.code, ... }) // 含 code
}
```

⚠️ **【易错点】** 版本代码创建后不可修改，Input 设置了 `disabled={isEdit}`。但 `disabled` 只是 UI 层面的约束——如果有人绕过前端直接调 API 修改 code，后端的 `UpdateEditionRequest` 不包含 code 字段，所以后端也做了防护。前后端各承担一层安全保障。

💡 **ASP.NET Core 类比**：`code` 是版本的自然键，对应数据库的 `UNIQUE` 约束。`CreateEditionRequest` 包含 `code`，`UpdateEditionRequest` 不包含 `code`——这就像主键不可修改的通用做法。

> 🤔 **导师提问**：版本代码（code）创建后不可修改，前端用 `disabled` 禁用输入框，后端在 UpdateDTO 中排除 code。前后端各承担什么层级的防护？如果只靠前端 `disabled`，攻击者可以绕过 UI 直接调 API——后端不包含 code 的 DTO 设计就是最后一道防线。这种"纵深防御"思路在后端安全设计中很常见。

### 提交前的数据清理

```typescript
// 过滤掉空行，空字段设为 undefined（不发送给后端）
const modulePayload = modules
  .filter((m) => m.moduleCode)               // 过滤空行
  .map((m) => ({
    moduleCode: m.moduleCode,
    moduleDisplayName: m.moduleDisplayName || undefined,  // 空字符串 → 不发送
    isIncluded: m.isIncluded,
    isDefault: m.isDefault,
  }))
```

⚠️ **【易错点】** `filter(m => m.moduleCode)` 会把 `moduleCode` 为空字符串的行过滤掉。这是合理的——用户可能点了"添加模块"但没填就提交，空行不应发送给后端。但这也意味着如果用户填了一半（如只填了 moduleDisplayName 没填 moduleCode），整行都会被丢弃。更好的做法是在前端做行级验证，提示用户必填项。

⚠️ **【易错点】** `m.moduleDisplayName || undefined` 用 `||` 而非 `??`。因为空字符串 `""` 是 falsy，`||` 会将其转为 `undefined`（不发送），而 `??` 不会。这里我们希望空字符串不传给后端，所以用 `||` 是正确的。

💡 **ASP.NET Core 类比**：`filter` 空行就像后端的 `ModelState` 验证——`[Required]` 字段为空时跳过。`|| undefined` 就像 `[JsonProperty(NullValueHandling = NullValueHandling.Ignore)]`——空值不序列化。

> 🤔 **导师提问**：提交前用 `.filter(m => m.moduleCode)` 过滤空行，用 `|| undefined` 将空字符串转为 undefined。后端的 `[Required]` 验证会在 Model Binding 阶段拒绝空值，而前端是主动过滤掉。这两种策略在用户体验上有什么差异？如果前端不过滤空行直接提交，后端返回 400 验证错误，用户会看到什么？

### 删除确认的设计

删除使用 `ConfirmDialog` + loading 状态，阻止误操作：

```typescript
<ConfirmDialog
  open={deleteOpen}
  onOpenChange={setDeleteOpen}
  title="删除版本"
  description={`确定要删除版本「${deleteTarget?.displayName}」吗？关联的模块和配额配置也会一并删除。`}
  onConfirm={handleDelete}
  loading={deleteLoading}
/>
```

⚠️ **【设计取舍】** 删除版本会级联删除关联的模块和配额。描述文案明确告知了这一点——"关联的模块和配额配置也会一并删除"。这和后端的 `CASCADE DELETE` 行为一致，但前端必须让用户知晓级联影响。

> 🤔 **导师提问**：删除确认用 `ConfirmDialog`，但版本编辑却直接在表单对话框中完成，没有额外的确认步骤。什么类型的操作需要确认，什么不需要？这和后端写操作需要审计日志的思路有什么对应关系？提示：不可逆操作需要确认（删除、终止），可逆操作不需要（编辑、暂停）。

## 踩坑提醒

1. **动态行的 key 不要用 index**：当前模块和配额行用了 `key={i}`（索引作为 key）。如果删除中间某行再添加，React 可能复用错误的 DOM 状态。更安全的做法是用唯一 ID（如 `crypto.randomUUID()`）。不过在简单场景下，index 作为 key 足够用，因为行内没有复杂的内部状态（如 autofocus）。

2. **`parseFloat(e.target.value) || 0` 的陷阱**：价格输入用 `parseFloat` 解析，空字符串 `""` 会返回 `NaN`，`NaN || 0` 回退为 0。但如果用户输入 `"1."`（正在输入小数），`parseFloat("1.")` 返回 `1`，小数点被"吃掉"了——用户无法输入小数。解决方案：用 `type="number"` 的 `step` 属性限制，或在 `onChange` 中保留原始字符串，提交时才转数字。
