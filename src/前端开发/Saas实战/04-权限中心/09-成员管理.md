# 09 - 成员管理

> **这一步解决什么问题？** 成员管理是权限中心的"最后一块拼图"——把 SSO 用户拉入租户，管理成员档案，同步最新数据。这一步涉及两个页面：**成员管理**（租户维度的成员增删同步）和**租户管理**（租户的 CRUD + 启用/禁用）。两个页面都涉及 SSO 集成——从 AuthServer 搜索用户并批量添加到租户。

---

## 代码讲解

### ASP.NET Core 类比：成员管理 = 租户级用户表

在 ASP.NET Core Identity 里：

```csharp
// ASP.NET Core: 用户属于全局的 AspNetUsers 表
var user = await _userManager.FindByIdAsync(userId);
var isActive = user.IsActive;
var email = user.Email;

// 多租户场景下，用户与租户的关联通常通过中间表实现
// TenantUser 表: TenantId | UserId | JoinedAt
```

权限中心的成员管理就是这种"中间表 + 档案"的组合：

```
ASP.NET Core Identity             →    权限中心成员管理
─────────────────────            →    ────────────────
全局 AspNetUsers 表               →    租户级 TenantMembers 表
用户信息在一张表中                 →    档案来自 SSO 同步 + 本地扩展
手动创建用户                      →    从 SSO 搜索添加 + 自动同步
用户永久存在                      →    可从租户移除（账号不删除）
```

### 成员管理的数据流

```
┌──────────┐                   ┌──────────────┐
│ AuthServer│  SSO 用户池       │  PermCenter  │
│ (用户源)  │                   │  (成员管理)  │
│          │                   │              │
│  用户 A  │ ─── searchSso ──► │  搜索结果     │
│  用户 B  │                   │              │
│  用户 C  │                   │  batchAdd ──►│ 添加到租户
│          │                   │              │
│          │ ◄── sync ──────── │  同步成员信息  │
│          │                   │              │
└──────────┘                   └──────────────┘
                                       │
                                       ▼
                                ┌──────────────┐
                                │  租户成员表   │
                                │ TenantMember │
                                │   + 成员档案  │
                                │ MemberProfile│
                                └──────────────┘
```

**关键概念**：
- **TenantMember**：租户-用户关联记录，包含 `tenantId`、`userId`、`joinedAt`
- **MemberProfile**：成员档案，包含 `displayName`、`employeeNo`、`phoneNumber` 等
- **SSO 同步**：从 AuthServer 拉取最新用户信息，更新 MemberProfile

> **🤔 导师提问**：成员管理涉及两个概念——`TenantMember`（租户-用户关联）和 `MemberProfile`（成员档案）。在 ASP.NET Core 中，`AspNetUserRoles` 表也有关联记录，但没有"档案"的概念。为什么权限中心需要额外的 MemberProfile？提示：想想 SSO 用户的 `displayName` 可能随时在 AuthServer 中修改，权限中心需要同步最新信息——MemberProfile 就是"本地缓存的用户信息"。如果不需要 Profile，移除成员时还需要调用 SSO 吗？

⚠️ **【易错点】** `TenantMemberDto.id` 是记录 ID（租户-用户关联表的 PK），不是用户 ID！要获取用户 ID 需用 `userId` 字段。在调用 `tenantMembersApi.remove(id)` 时，传的是记录 ID 而非用户 ID。

> **🤔 导师提问**：`TenantMemberDto.id` 不是用户 ID，而是关联表的 PK。在 ASP.NET Core 中，`IdentityUserRole<string>` 也有类似问题——它是复合主键（UserId + RoleId），没有独立的 ID 字段。权限中心选择给关联表加独立 PK 的原因是什么？提示：想想 RESTful API 的删除操作 `DELETE /api/tenant-members/{id}`——如果用复合主键，URL 会变成什么样？

### API 层

#### 租户成员 API

```typescript
// src/api/perm/tenant-members.ts
import { get, post, del } from "./http"
import type { PagedResult, TenantMemberDto } from "@/types"

/** 租户成员 API */
export const tenantMembersApi = {
  /** 获取当前租户的成员列表（分页） */
  getList(params?: {
    keyword?: string
    isActive?: boolean
    page?: number
    pageSize?: number
  }) {
    return get<PagedResult<TenantMemberDto>>("/api/tenant-members", params as Record<string, unknown>)
  },

  /** 添加成员到当前租户 */
  add(data: { userId: string; employeeNo?: string }) {
    return post<TenantMemberDto>("/api/tenant-members", data)
  },

  /** 批量添加成员到当前租户 */
  batchAdd(userIds: string[]) {
    return post<{ added: number; items: TenantMemberDto[] }>("/api/tenant-members/batch", { userIds })
  },

  /** 从当前租户移除成员 */
  remove(id: string) {
    return del<void>(`/api/tenant-members/${id}`)
  },

  /** 同步当前租户所有成员的 Profile（从 SSO 拉取最新信息） */
  sync() {
    return post<{ total: number; created: number; removed: number }>("/api/tenant-members/sync")
  },
}
```

#### 成员档案 API（SSO 搜索代理）

```typescript
// src/api/perm/members.ts
import { get, post } from "./http"
import type { MemberProfileDto, UpsertMemberProfileRequest, PagedResult, SsoUserSearchResult } from "@/types"

/** 成员管理 API，用于管理租户内的成员档案及与 SSO 的同步 */
export const membersApi = {
  /** 获取成员列表（分页） */
  getList(params?: { keyword?: string; isActive?: boolean; page?: number; pageSize?: number }) {
    return get<PagedResult<MemberProfileDto>>("/api/members", params as Record<string, unknown>)
  },

  /** 根据 SSO 用户 ID 获取成员档案 */
  getByUserId(userId: string) {
    return get<MemberProfileDto>(`/api/members/by-user/${userId}`)
  },

  /** 创建或更新成员档案（Upsert 操作） */
  upsert(data: UpsertMemberProfileRequest) {
    return post<MemberProfileDto>("/api/members", data)
  },

  /** 批量同步成员档案 */
  batchSync(data: { members: UpsertMemberProfileRequest[] }) {
    return post<{ syncedCount: number; newCount: number }>("/api/members/batch-sync", data)
  },

  /** 搜索 SSO 用户（代理调用 AuthServer） */
  searchSso(params?: { keyword?: string; pageSize?: number }) {
    return get<{ items: SsoUserSearchResult[]; totalCount: number }>(
      "/api/members/search-sso",
      params as Record<string, unknown>,
    )
  },

  /** 从 SSO 全量同步用户到 MemberProfile */
  syncFromSso() {
    return post<{ totalSynced: number; newCount: number }>("/api/members/sync-from-sso")
  },
}
```

💡 **【设计取舍】** 为什么 SSO 搜索不是前端直接调用 AuthServer，而是通过 PermCenter 代理？因为 AuthServer 可能部署在内网，前端无法直接访问。PermCenter 作为后端服务，可以安全地调用 AuthServer 的内部 API。

> **🤔 导师提问**：`membersApi.searchSso` 通过 PermCenter 代理调用 AuthServer，而不是前端直接调 AuthServer。这种"后端代理"模式在 ASP.NET Core 中叫 BFF（Backend For Frontend）。BFF 的好处是前端不需要知道 AuthServer 的地址和认证方式。但 BFF 也有代价——多了一层网络跳转，延迟增加。什么场景下应该让前端直接调 AuthServer，什么场景必须用 BFF？

#### 完整页面代码

```typescript
// src/pages/perm/members/index.tsx
import { useState, useEffect, useCallback } from "react"
import { toast } from "sonner"
import { User, UserPlus, Mail, Phone, Hash, UserX, RefreshCw, Building2, CloudDownload } from "lucide-react"
import {
  Select,
  SelectContent,
  SelectItem,
  SelectTrigger,
  SelectValue,
} from "@/components/ui/select"
import { PageToolbar, ToolbarButton } from "@/components/shared/page-toolbar"
import { AgTable, type AgColumn } from "@/components/shared/ag-table"
import { QueryFilter } from "@/components/shared/query-filter"
import { Button } from "@/components/ui/button"
import { Badge } from "@/components/ui/badge"
import { AlertDialog, AlertDialogAction, AlertDialogCancel, AlertDialogContent, AlertDialogDescription, AlertDialogFooter, AlertDialogHeader, AlertDialogMedia, AlertDialogTitle } from "@/components/ui/alert-dialog"
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"
import { tenantMembersApi } from "@/api/perm/tenant-members"
import { tenantsApi } from "@/api/perm/tenants"
import { useAuthStore } from "@/stores/auth-store"
import type { TenantDto, TenantMemberDto } from "@/types"
import AddMemberDialog from "./add-member-dialog"

/**
 * 成员管理页面
 * 管理当前租户下的成员列表，支持添加、移除和同步成员信息。
 * 平台管理员可切换租户查看不同租户的成员数据。
 */
export default function PermMembersPage() {
  const currentTenantId = useAuthStore((s) => s.currentTenantId)
  const currentTenantName = useAuthStore((s) => s.currentTenantName)
  const setCurrentTenant = useAuthStore((s) => s.setCurrentTenant)

  // 租户列表
  const [tenants, setTenants] = useState<TenantDto[]>([])
  const [loadingTenants, setLoadingTenants] = useState(false)

  // 成员列表数据与筛选状态
  const [members, setMembers] = useState<TenantMemberDto[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [pageSize, setPageSize] = useState(20)
  const [keyword, setKeyword] = useState("")
  const [keywordInput, setKeywordInput] = useState("")
  const [statusFilter, setStatusFilter] = useState("")
  const [loading, setLoading] = useState(false)

  // 对话框状态
  const [addOpen, setAddOpen] = useState(false)
  const [removeTarget, setRemoveTarget] = useState<TenantMemberDto | null>(null)
  const [removing, setRemoving] = useState(false)
  /** 同步成员信息中的加载状态 */
  const [syncing, setSyncing] = useState(false)

  // 始终加载租户列表（平台管理员切换租户用）
  useEffect(() => {
    let cancelled = false
    setLoadingTenants(true)
    tenantsApi.getList({ isActive: true }).then((res) => {
      if (cancelled) return
      if (res.success) setTenants(res.data ?? [])
    }).finally(() => {
      if (!cancelled) setLoadingTenants(false)
    })
    return () => { cancelled = true }
  }, [])

  /** 切换租户，重置筛选条件和分页 */
  const handleTenantChange = (tenantId: string) => {
    const t = tenants.find((x) => x.id === tenantId)
    if (t) {
      setCurrentTenant(t.id, t.name)
      setMembers([])
      setTotal(0)
      setPage(1)
      setKeyword("")
      setKeywordInput("")
      setStatusFilter("")
    }
  }

  /** 加载当前租户的成员列表 */
  const loadData = useCallback(async () => {
    if (!currentTenantId) return
    setLoading(true)
    try {
      const res = await tenantMembersApi.getList({
        keyword: keyword || undefined,
        isActive: statusFilter === "active" ? true : statusFilter === "disabled" ? false : undefined,
        page,
        pageSize,
      })
      if (res.success && res.data) {
        setMembers(res.data.items ?? [])
        setTotal(Number(res.data.totalCount) || 0)
      } else {
        toast.error(res.message || "加载成员列表失败")
      }
    } catch {
      toast.error("加载成员列表失败")
    } finally {
      setLoading(false)
    }
  }, [currentTenantId, keyword, statusFilter, page, pageSize])

  useEffect(() => { loadData() }, [loadData])

  /** 从当前租户移除成员 */
  const handleRemove = async () => {
    if (!removeTarget) return
    setRemoving(true)
    try {
      const res = await tenantMembersApi.remove(removeTarget.id)
      if (res.success) {
        toast.success(`已移除成员: ${removeTarget.displayName || removeTarget.userName}`)
        setRemoveTarget(null)
        loadData()
      } else {
        toast.error(res.message || "移除失败")
      }
    } catch {
      toast.error("移除失败")
    } finally {
      setRemoving(false)
    }
  }

  /** 同步成员信息（从 SSO 系统同步最新的用户档案） */
  const handleSync = async () => {
    setSyncing(true)
    try {
      const res = await tenantMembersApi.sync()
      if (res.success && res.data) {
        const { total, created, removed } = res.data as { total: number; created: number; removed: number }
        const parts = [`共 ${total} 位成员`]
        if (created > 0) parts.push(`新建 ${created} 个档案`)
        if (removed > 0) parts.push(`清理 ${removed} 个失效用户`)
        toast.success(`同步完成：${parts.join("，")}`)
        loadData()
      } else {
        toast.error(res.message || "同步失败")
      }
    } catch {
      toast.error("同步失败")
    } finally {
      setSyncing(false)
    }
  }

  /** 表格列定义 */
  const columns: AgColumn<TenantMemberDto>[] = [
    {
      field: "displayName",
      headerName: "成员信息",
      minWidth: 200,
      flex: 1,
      // 成员头像、姓名和邮箱
      cellRenderer: ({ data: record }) => (
        <div className="flex items-center gap-3">
          <div className="w-8 h-8 rounded-full bg-muted flex items-center justify-center shrink-0">
            <User className="h-4 w-4 text-muted-foreground" />
          </div>
          <div className="min-w-0">
            <p className="text-sm font-medium truncate">
              {record.displayName || record.userName}
            </p>
            {record.email && (
              <p className="text-xs text-muted-foreground flex items-center gap-1">
                <Mail className="h-3 w-3" />
                {record.email}
              </p>
            )}
          </div>
        </div>
      ),
    },
    {
      field: "employeeNo",
      headerName: "员工号",
      width: 100,
      cellRenderer: ({ data: record }) =>
        record.employeeNo ? (
          <span className="text-sm font-mono flex items-center gap-1">
            <Hash className="h-3 w-3 text-muted-foreground" />
            {record.employeeNo}
          </span>
        ) : (
          <span className="text-sm text-muted-foreground">-</span>
        ),
    },
    {
      field: "phoneNumber",
      headerName: "联系方式",
      width: 120,
      cellRenderer: ({ data: record }) =>
        record.phoneNumber ? (
          <span className="text-sm flex items-center gap-1">
            <Phone className="h-3 w-3 text-muted-foreground" />
            {record.phoneNumber}
          </span>
        ) : (
          <span className="text-sm text-muted-foreground">-</span>
        ),
    },
    {
      field: "isActive",
      headerName: "状态",
      width: 80,
      // 启用/禁用状态显示
      cellRenderer: ({ data: record }) =>
        record.isActive ? (
          <Badge variant="outline" className="text-success border-success/30 bg-success/10">
            已启用
          </Badge>
        ) : (
          <Badge variant="outline" className="text-muted-foreground">
            已禁用
          </Badge>
        ),
    },
    {
      field: "joinedAt",
      headerName: "加入时间",
      width: 140,
      cellRenderer: ({ data: record }) => (
        <span className="text-sm text-muted-foreground">
          {new Date(record.joinedAt).toLocaleDateString("zh-CN")}
        </span>
      ),
    },
    {
      field: "__actions__",
      headerName: "操作",
      width: 80,
      pinned: "right",
      // 操作列：移除成员
      cellRenderer: ({ data: record }) => (
        <Tooltip>
          <TooltipTrigger asChild>
            <Button
              variant="ghost"
              size="sm"
              className="text-destructive hover:text-destructive"
              onClick={() => setRemoveTarget(record)}
            >
              <UserX className="h-3.5 w-3.5 mr-1" />
              移除
            </Button>
          </TooltipTrigger>
          <TooltipContent>从当前租户移除此成员</TooltipContent>
        </Tooltip>
      ),
    },
  ]

  return (
    <div className="flex flex-col h-full">
      {/* 页面工具栏 */}
      <PageToolbar
        title="成员管理"
        actions={
          <>
            <ToolbarButton icon={UserPlus} variant="primary" onClick={() => setAddOpen(true)} disabled={!currentTenantId}>
              添加成员
            </ToolbarButton>
            <ToolbarButton icon={CloudDownload} onClick={handleSync} disabled={!currentTenantId || syncing}>
              {syncing ? "同步中..." : "同步成员信息"}
            </ToolbarButton>
            <ToolbarButton icon={RefreshCw} onClick={loadData} disabled={!currentTenantId}>
              刷新
            </ToolbarButton>
          </>
        }
        extra={
          currentTenantId && !loading ? (
            <span className="text-xs text-muted-foreground">{total} 位成员</span>
          ) : undefined
        }
      />

      {/* 租户选择器 */}
      <div className="flex items-center gap-3 px-2 py-2">
        <span className="text-sm font-medium whitespace-nowrap">选择租户：</span>
        {loadingTenants ? (
          <span className="text-sm text-muted-foreground">加载中...</span>
        ) : (
          <Select value={currentTenantId ?? ""} onValueChange={handleTenantChange}>
            <SelectTrigger className="w-64">
              <Building2 className="h-4 w-4 mr-1.5 text-muted-foreground" />
              <SelectValue placeholder="请选择租户" />
            </SelectTrigger>
            <SelectContent>
              {tenants.map((t) => (
                <SelectItem key={t.id} value={t.id}>
                  {t.name}
                  <span className="ml-2 text-muted-foreground text-xs">{t.identifier}</span>
                </SelectItem>
              ))}
              {/* 如果当前有租户但不在列表中（普通租户用户），也显示 */}
              {currentTenantId && !tenants.find((t) => t.id === currentTenantId) && (
                <SelectItem value={currentTenantId}>
                  {currentTenantName ?? currentTenantId}
                </SelectItem>
              )}
            </SelectContent>
          </Select>
        )}
      </div>

      {/* 搜索筛选栏 */}
      <QueryFilter
        fields={[
          { key: "keyword", label: "关键词", type: "input", placeholder: "搜索姓名、用户名或员工号..." },
          { key: "status", label: "状态", type: "select", options: [
            { value: "active", label: "已启用" },
            { value: "disabled", label: "已禁用" },
          ] },
        ]}
        values={{ keyword: keywordInput, status: statusFilter }}
        onValuesChange={(v) => { setKeywordInput(v.keyword ?? ""); if (v.status !== statusFilter) { setStatusFilter(v.status ?? ""); setPage(1) } }}
        onSearch={() => { setKeyword(keywordInput); setPage(1) }}
        onReset={() => { setKeywordInput(""); setKeyword(""); setStatusFilter(""); setPage(1) }}
      />

      {/* 成员数据表格 */}
      <AgTable
        columns={columns}
        data={members}
        total={total}
        page={page}
```

#### useEffect 的取消机制


⚠️ **【易错点】** 这是 React 经典的"内存泄漏"问题。如果组件在异步请求完成前卸载，`setTenants` 会尝试更新已卸载组件的状态。用 `cancelled` 标志位避免这个问题。

#### 为什么用 Map 而不是 Set 存储已选用户？

```typescript
const [selectedUsers, setSelectedUsers] = useState<Map<string, SsoUserSearchResult>>(new Map())
```

💡 `Set<string>` 只能存用户 ID，但我们在底部的已选标签中需要显示用户名。`Map<string, SsoUserSearchResult>` 既存 ID（快速查找）又存完整用户信息（显示用），一举两得。

⚠️ **【易错点】** `new Map()` 的比较是引用比较。每次 `setSelectedUsers` 必须创建新的 Map 实例，否则 React 检测不到变化：

```typescript
// 正确：创建新 Map
setSelectedUsers(prev => {
  const next = new Map(prev)  // 复制旧 Map
  next.set(user.id, user)     // 添加新项
  return next                 // 返回新引用
})

// 错误：修改原 Map（React 不会重新渲染）
prev.set(user.id, user)
return prev  // 同一引用，React 认为没变化
```

#### 全选逻辑的"当前页"语义

```typescript
const toggleAll = () => {
  const allSelected = users.every(u => selectedUsers.has(u.id))
  if (allSelected) {
    // 取消当前页所有
    setSelectedUsers(prev => {
      const next = new Map(prev)

    })
  } else {
    // 选中当前页所有

      const next = new Map(prev)
      users.forEach(u => next.set(u.id, u))
      return next
    })
  }
}
```

⚠️ **【易错点】** 全选只操作"当前搜索结果"（`users`），不影响之前搜索已选的用户。如果用户搜索两次，第一次选了 A、B，第二次全选 C、D，最终 `selectedUsers` 包含 A、B、C、D。这是正确的行为——跨搜索结果累积选择。

💡 **【性能陷阱】** 每次调用 `new Map(prev)` 都会浅拷贝整个 Map。如果已选用户很多（比如 100+），频繁调用 `toggleUser` 可能有性能问题。在实际项目中可以考虑用 `useReducer` 代替 `useState`，或者用 immutable 库优化。

```typescript
    setFormOpen(true)
  }

  /** 打开编辑租户对话框 */
  const handleEdit = (tenant: TenantDto) => {
    setEditingTenant(tenant)
    setFormOpen(true)
  }

  /** 确认切换租户启用/禁用状态 */
  const confirmToggle = async () => {
    if (!toggleTarget) return
    const action = toggleTarget.isActive ? "禁用" : "启用"
    setToggleLoading(true)
    try {
      const res = await tenantsApi.toggleStatus(toggleTarget.id)
      if (res.success) {
        toast.success(`租户已${action}`)
        setToggleTarget(null)
        await fetchTenants()
      } else {
        toast.error(res.message)
      }
    } catch {
      toast.error(`${action}失败`)
    } finally {
      setToggleLoading(false)
    }
  }

  /** 确认删除租户 */
  const confirmDelete = async () => {
    if (!deleteTarget) return
    setDeleteLoading(true)
    try {
      const res = await tenantsApi.delete(deleteTarget.id)
      if (res.success) {
        toast.success("删除成功")
        setDeleteTarget(null)
        await fetchTenants()
      } else {
        toast.error(res.message)
      }
    } catch {
      toast.error("删除失败")
    } finally {
      setDeleteLoading(false)
    }
  }

  /** 表格列定义 */
  const columns: AgColumn<TenantDto>[] = [
    {
      field: "name",
      headerName: "租户名称",
      minWidth: 150,
      flex: 1,
      cellRenderer: ({ data: r }) => (
        <div>
          <div className="font-medium">{r.name}</div>
        </div>
      ),
    },
    {
      field: "identifier",
      headerName: "标识符（Slug）",
      width: 160,
      cellRenderer: ({ data: r }) => (
        <span className="font-mono text-sm px-1.5 py-0.5 rounded bg-muted">{r.identifier}</span>
      ),
    },
    {
      field: "connectionString",
      headerName: "数据库",
      width: 120,
      // 有独立连接串显示"独立库"，否则显示"共享库"
      cellRenderer: ({ data: r }) => (
        r.connectionString
          ? <Badge variant="outline" className="text-xs font-normal">独立库</Badge>
          : <span className="text-muted-foreground text-xs">共享库</span>
      ),
    },
    {
      field: "isActive",
      headerName: "状态",
      width: 90,
      cellRenderer: ({ data: r }) => (
        r.isActive
          ? <Badge className="bg-success/10 text-success hover:bg-success/10">启用</Badge>
          : <Badge variant="destructive">禁用</Badge>
      ),
    },
    {
      field: "creationTime",
      headerName: "创建时间",
      width: 160,
      cellRenderer: ({ data: r }) => (
        <span className="text-muted-foreground text-sm">
          {new Date(r.creationTime).toLocaleDateString("zh-CN")}
        </span>
      ),
    },
    {
      field: "__actions__",
      headerName: "操作",
      width: 70,
      pinned: "right",
      cellRenderer: ({ data: r }) => (
        <DropdownMenu>
          <DropdownMenuTrigger asChild>
            <Button variant="ghost" size="icon" className="h-8 w-8">
              <MoreHorizontal className="h-4 w-4" />
            </Button>
          </DropdownMenuTrigger>
          <DropdownMenuContent align="end">
            <DropdownMenuItem onClick={() => handleEdit(r)}>
              <Pencil className="mr-2 h-4 w-4" />编辑
            </DropdownMenuItem>
            <DropdownMenuItem onClick={() => handleToggle(r)}>
              <Power className="mr-2 h-4 w-4" />
              {r.isActive ? "禁用租户" : "启用租户"}
            </DropdownMenuItem>
            <DropdownMenuSeparator />
            <DropdownMenuItem
              onClick={() => handleDelete(r)}
              className="text-destructive focus:text-destructive"
            >
              <Trash2 className="mr-2 h-4 w-4" />删除
            </DropdownMenuItem>
          </DropdownMenuContent>
        </DropdownMenu>
      ),
    },
  ]

  return (
    <div className="flex flex-col h-full">
      <PageToolbar
        title="租户管理"
        actions={
          <>
            <ToolbarButton icon={Plus} variant="primary" onClick={handleCreate}>
              新建租户
            </ToolbarButton>
            <ToolbarButton icon={RefreshCw} onClick={fetchTenants}>
              刷新
            </ToolbarButton>
          </>
        }
      />

      <QueryFilter
        fields={[
          { key: "keyword", label: "关键词", type: "input", placeholder: "按名称或标识符搜索..." },
        ]}
        values={filterValues}
        onValuesChange={setFilterValues}
        onSearch={() => { setSearch(filterValues.keyword ?? "") }}
        onReset={() => { setFilterValues({ keyword: "" }); setSearch("") }}
      />

      <AgTable
        columns={columns}
        data={data}
        total={data.length}
        loading={loading}
        rowKey="id"
      />

      <TenantFormDialog
        open={formOpen}
        onOpenChange={setFormOpen}
        tenant={editingTenant}
        onSuccess={fetchTenants}
      />
      {/* 启用/禁用确认对话框 */}
      <ConfirmDialog
        open={!!toggleTarget}
        onOpenChange={(open) => { if (!open) setToggleTarget(null) }}
        title={toggleTarget?.isActive ? "禁用租户" : "启用租户"}
        description={
          toggleTarget?.isActive
            ? `确定禁用租户 "${toggleTarget?.name}" 吗？禁用后该租户所有请求将收到 403。`
            : `确定启用租户 "${toggleTarget?.name}" 吗？`
        }
        onConfirm={confirmToggle}
        loading={toggleLoading}
        variant={toggleTarget?.isActive ? "destructive" : "default"}
        type={toggleTarget?.isActive ? "warning" : "info"}
        confirmLabel={toggleTarget?.isActive ? "禁用" : "启用"}
      />
      {/* 删除确认对话框 */}
      <ConfirmDialog
        open={!!deleteTarget}
        onOpenChange={(open) => { if (!open) setDeleteTarget(null) }}
        title="删除租户"
        description={`确定永久删除租户 "${deleteTarget?.name}" 吗？此操作不可逆。如果该租户下有用户角色数据，删除将被拒绝。`}
        onConfirm={confirmDelete}
        loading={deleteLoading}
        variant="destructive"
        type="danger"
        confirmLabel="删除"
      />
    </div>
  )
}
```

### 租户管理的关键设计

#### 独立库 vs 共享库

```typescript
// 数据库列的渲染
cellRenderer: ({ data: r }) => (
  r.connectionString
    ? <Badge variant="outline" className="text-xs font-normal">独立库</Badge>
    : <span className="text-muted-foreground text-xs">共享库</span>
```

💡 SaaS 平台支持两种数据隔离模式：
- **独立库**：租户有专属数据库，`connectionString` 非空
- **共享库**：所有租户共享数据库，通过 `X-Tenant-Id` Header 区分数据

⚠️ **【设计取舍】** `connectionString` 字段直接显示在表格中会很丑（连接串很长），所以只显示"独立库/共享库"标签。完整连接串在编辑弹窗中查看。

#### 启用/禁用的差异化确认

```typescript
// 禁用租户确认
description={`确定禁用租户 "${toggleTarget?.name}" 吗？禁用后该租户所有请求将收到 403。`}
variant="destructive"
type="warning"

// 启用租户确认
description={`确定启用租户 "${toggleTarget?.name}" 吗？`}
variant="default"
type="info"
```

💡 **用户体验**：禁用是危险操作（影响所有用户），用红色警告风格；启用是安全操作，用普通信息风格。这种差异化提示让管理员在禁用操作时更加谨慎。

### 跨系统集成调用链路总结

```
成员管理页面 → membersApi.searchSso() → PermCenter API → AuthServer SSO
                                          (代理调用)        (用户池)

成员管理页面 → tenantMembersApi.sync() → PermCenter API → AuthServer SSO
                                          (同步触发)        (拉取最新数据)

成员管理页面 → tenantMembersApi.batchAdd() → PermCenter API → 写入 TenantMember 表
                                              (直接操作)

租户管理页面 → tenantsApi.create() → PermCenter API → 写入 Tenant 表 + Gateway 配置
                                       (直接操作)        (需要重启 Gateway 生效)
```

💡 **ASP.NET Core 类比**：`membersApi.searchSso()` 的"代理调用"模式，就像 ASP.NET Core 中的 BFF（Backend For Frontend）——前端不直接调用内部服务，而是通过一个中间层（PermCenter）转发请求。这样做的好处：前端不需要知道 AuthServer 的地址、认证方式；PermCenter 可以对请求做缓存、限流等处理。

> **🤔 导师提问**：回顾整个成员管理的数据流：SSO 搜索 → 批量添加 → 同步档案。在 ASP.NET Core 中，类似的流程可能是：从 LDAP 查用户 → 写入本地用户表 → 定期同步。权限中心的 `batchAdd` 和 `sync` 操作有什么区别？`batchAdd` 是"手动选人添加"，`sync` 是"自动全量同步"。如果管理员用 `batchAdd` 添加了一个已被 `sync` 标记为"应移除"的用户，下一次 `sync` 会怎样处理这个冲突？

## 踩坑提醒

1. **TenantMemberDto.id 是记录 ID 不是用户 ID**：调用 `tenantMembersApi.remove(id)` 时传的是关联表的 PK 而非用户 ID。混淆两者会删除错误的记录或导致 404。
2. **Map 的新引用问题**：`useState<Map<string, T>>` 的更新必须创建新 Map 实例（`new Map(prev)`），直接修改原 Map 不会触发 React 重新渲染。这是 React 不可变数据的基本原则，但对 Map 对象尤其容易犯错。
3. **keywordInput 和 keyword 必须分离**：如果只用一个 `keyword` 绑定输入框，每次输入字符都会触发 `loadData`（因为 `keyword` 是 `useCallback` 的依赖项），导致每个按键都发起 API 请求。分离两个状态后，只有点击"搜索"按钮时才会将 `keywordInput` 赋给 `keyword`。
4. **useEffect 的取消机制**：如果组件在异步请求完成前卸载，`setTenants` 会尝试更新已卸载组件的状态，导致 React 警告。用 `cancelled` 标志位避免这个问题，类似 ASP.NET Core 中的 `CancellationToken`。
5. **租户标识符创建后不可修改**：`identifier` 字段与 Gateway 路由和 `X-Tenant-Id` Header 绑定，修改标识符需要同步更新 Gateway 配置并重启服务。创建时务必确保填写正确。
