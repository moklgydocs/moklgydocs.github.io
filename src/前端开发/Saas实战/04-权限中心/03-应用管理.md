# 03 - 应用管理

> **这一步解决什么问题？** 应用（App）是权限中心的"根"——所有权限定义、角色、菜单都挂在应用下面。就像 ASP.NET Core 里一个项目对应一套 `[Authorize]` 策略，权限中心里一个应用对应一套权限体系。我们要实现应用的 CRUD 管理页面，并理解 `code` 字段与 OAuth2 Client ID 的绑定关系。

---

阅读本文档前，你需要了解：

## 一、ASP.NET Core 类比：应用 = 一套权限体系

在单体 ASP.NET Core 应用里，你只有一个项目，一套权限策略：

```csharp
// 单体应用：所有 Controller 共享同一套 [Authorize] 策略
[Authorize(Policy = "Purchase.Approve")]
public class PurchaseController { ... }

[Authorize(Policy = "Inventory.View")]
public class InventoryController { ... }
```

但在 SaaS 平台里，有多个业务系统（ERP、WMS、报表系统……），每个系统有自己的权限定义。**应用（App）就是隔离这些权限体系的边界**：

```
应用: mok-erp-service
├── 权限组: Purchase → Purchase.View, Purchase.Create, Purchase.Approve
├── 权限组: Inventory → Inventory.View, Inventory.Adjust
└── 角色: 采购经理, 仓库管理员

应用: mok-wms-service
├── 权限组: Inbound → Inbound.View, Inbound.Create
├── 权限组: Outbound → Outbound.View, Outbound.Create
└── 角色: 入库员, 出库员
```

## 二、应用数据模型

```typescript
// src/types/index.ts
export interface AppDto {
  id: string
  code: string           // ⚠️ 必须与 OAuth2 Client ID 一致，创建后不可修改
  name: string           // 显示名称
  description: string | null
  logoUrl: string | null
  isEnabled: boolean     // 启用/禁用
  sort: number           // 排序号
}
```

### 2.1 code 字段的特殊含义

`code` 不是普通的字符串——它必须与 AuthServer 中的 OAuth2 `client_id` 完全一致：

```
用户登录 → JWT Token 中包含 client_id = "mok-erp-service"
                                    │
                                    ▼
           权限中心按 appCode = "mok-erp-service" 查询角色和权限
```

⚠️ **如果 `code` 和 `client_id` 不一致，权限查询就会失败！**

而且 `code` 一旦创建就不可修改（因为已被角色、权限、菜单大量引用）。所以**必须确保第一次就填对**。

      minWidth: 120,
      flex: 1,
    },
    {

## 四、表单对话框：创建与编辑

### 4.1 创建 vs 编辑的区别

| 字段 | 创建模式 | 编辑模式 |
|------|---------|---------|
| code | 必填，可输入 | 只读，灰色显示 |
| name | 必填，可输入 | 可修改 |
| description | 可选 | 可修改 |
| sort | 默认 1 | 可修改 |
| isEnabled | 不显示（默认启用） | 显示 Switch 开关 |

### 4.2 完整表单代码

```typescript
// src/pages/perm/apps/app-form-dialog.tsx
import { useEffect, useState } from "react"
import {
  Dialog, DialogContent, DialogHeader, DialogTitle, DialogFooter,
} from "@/components/ui/dialog"
import { Button } from "@/components/ui/button"
import { Input } from "@/components/ui/input"
import { Label } from "@/components/ui/label"
import { Switch } from "@/components/ui/switch"
import { appsApi } from "@/api/perm/apps"
import { toast } from "sonner"
import { Loader2 } from "lucide-react"
import type { AppDto } from "@/types"

interface AppFormDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  app: AppDto | null       // null = 创建模式, 非 null = 编辑模式
  onSuccess: () => void
}

> **🤔 导师提问**：`AppFormDialogProps` 中 `app` 为 `null` 表示创建模式，非 `null` 表示编辑模式。这种"用数据是否存在来判断模式"的设计，在 ASP.NET Core 中你见过类似的模式吗？想想 `UpdateDto` 中的 `id` 字段——如果 `id` 为空是新建，非空是更新，和这里的 `app` 参数有什么异同？

export function AppFormDialog({ open, onOpenChange, app, onSuccess }: AppFormDialogProps) {
  const isEdit = !!app
  const [loading, setLoading] = useState(false)
  const [form, setForm] = useState({
    code: "",
    name: "",
    description: "",
    sort: 1,
    isEnabled: true,
  })

  // 对话框打开时初始化表单数据
  useEffect(() => {
    if (open) {
      setForm({
        code: app?.code ?? "",
        name: app?.name ?? "",
        description: app?.description ?? "",
        sort: app?.sort ?? 1,
        isEnabled: app?.isEnabled ?? true,
      })
    }
  }, [open, app])

> **🤔 导师提问**：这个 `useEffect` 的依赖数组是 `[open, app]`——当 `open` 或 `app` 变化时，会重新初始化表单。如果忘记把 `app` 加入依赖数组，只在对话框首次打开时初始化，编辑不同应用时会发生什么？在 ASP.NET Core 中，Razor 页面的 `OnGet` 每次请求都会执行——React 的 `useEffect` 和它有什么本质区别？

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault()
    if (!form.code || !form.name) {
      toast.error("应用代码和名称不能为空")
      return
    }
    setLoading(true)
    try {
      if (isEdit) {
        // 编辑模式：不传 code，不可修改
        await appsApi.update(app.id, {
          name: form.name,
          description: form.description,
          isEnabled: form.isEnabled,
          sort: form.sort,
        })
        toast.success("应用已更新")
      } else {
        // 创建模式：包含 code
        await appsApi.create({
          code: form.code,
          name: form.name,
          description: form.description,
          sort: form.sort,
        })
        toast.success("应用已创建")
      }
      onSuccess()
      onOpenChange(false)
    } catch {
      toast.error(isEdit ? "更新失败" : "创建失败")
    } finally {
      setLoading(false)
    }
  }

> **🤔 导师提问**：`handleSubmit` 中，编辑模式调用 `appsApi.update` 时不传 `code`，创建模式调用 `appsApi.create` 时包含 `code`。在 ASP.NET Core 的 `UpdateAppRequest` DTO 中，你会把 `code` 标记为 `[Required]` 吗？如果不标记，前端不传 `code` 时后端怎么知道"这是不需要更新的字段"而不是"前端忘了传"？

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="sm:max-w-md">
        <DialogHeader>
          <DialogTitle>{isEdit ? "编辑应用" : "新建应用"}</DialogTitle>
        </DialogHeader>
        <form onSubmit={handleSubmit} className="space-y-4 py-2">
          {/* 应用代码：创建时必填，编辑时不可修改 */}
          <div className="space-y-2">
            <Label htmlFor="code">应用代码 *</Label>
            <Input id="code" placeholder="如: mok-erp-service"
              value={form.code}
              onChange={(e) => setForm({ ...form, code: e.target.value })}
              disabled={isEdit} />
            {!isEdit && (
              <p className="text-xs text-muted-foreground">必须与 OAuth2 Client ID 一致</p>
            )}
          </div>
          {/* 应用名称 */}
          <div className="space-y-2">
            <Label htmlFor="name">应用名称 *</Label>
            <Input id="name" placeholder="如: ERP 系统"
              value={form.name}
              onChange={(e) => setForm({ ...form, name: e.target.value })} />
          </div>
          {/* 描述 */}
          <div className="space-y-2">
            <Label htmlFor="desc">描述</Label>
            <Input id="desc" placeholder="可选"
              value={form.description}
              onChange={(e) => setForm({ ...form, description: e.target.value })} />
          </div>
          {/* 排序 */}
          <div className="space-y-2">
            <Label htmlFor="sort">排序</Label>
            <Input id="sort" type="number" value={form.sort}
              onChange={(e) => setForm({ ...form, sort: parseInt(e.target.value) || 1 })} />
          </div>
          {/* 启用开关：仅编辑模式下显示 */}
          {isEdit && (
            <div className="flex items-center gap-3">
              <Switch id="enabled" checked={form.isEnabled}
                onCheckedChange={(v: boolean) => setForm({ ...form, isEnabled: v })} />
              <Label htmlFor="enabled">启用</Label>
            </div>
          )}
          <DialogFooter>
            <Button type="button" variant="outline"
              onClick={() => onOpenChange(false)} disabled={loading}>
              取消
            </Button>
            <Button type="submit" disabled={loading}>
              {loading && <Loader2 className="mr-2 h-4 w-4 animate-spin" />}
              {isEdit ? "保存" : "创建"}
            </Button>
          </DialogFooter>
        </form>
      </DialogContent>
    </Dialog>
  )
}
```

## 五、关键设计决策解析

### 5.1 为什么 code 创建后不可修改？

```
应用 code: "mok-erp-service"
    │
    ├── 被角色表引用（WHERE appId = (SELECT id FROM Apps WHERE code = 'mok-erp-service')）
    ├── 被权限定义表引用
    ├── 被菜单表引用
    └── 被用户角色关联表引用
```

如果允许修改 code，就需要级联更新所有引用表。而且 AuthServer 的 `client_id` 也是不可变的。所以**安全做法是创建后禁止修改**。

💡 **ASP.NET Core 类比**：这就像 `Migration` 的名称——一旦应用了迁移，名称就不能再改，因为 `__EFMigrationsHistory` 表里已经记录了。

### 5.2 为什么创建时不显示"启用"开关？

新建应用默认是启用的（`isEnabled: true`）。如果创建时就允许禁用，那么刚创建的应用就无法使用，这是不合常理的。只有在运行一段时间后，需要临时停用某个应用时，才需要禁用开关。

### 5.3 删除时的级联影响

删除应用会级联删除：
- 该应用下的所有权限组和权限定义
- 该应用下的所有角色
- 该应用下的所有菜单
- 所有用户在该应用下的角色分配

所以删除确认对话框的描述文案要特别提醒：

> "确定要删除应用「ERP 系统」吗？关联的权限定义和角色也会一并删除。"

## 六、组件协作关系

```
AppsPage
├── PageToolbar          → 页面标题 + 操作按钮
├── AgTable<AppDto>      → 数据表格（列定义 + 数据源）
├── AppFormDialog        → 创建/编辑表单弹窗
└── ConfirmDialog        → 删除确认弹窗
```

**状态管理**：所有状态都在 `AppsPage` 组件内（`useState`），不使用全局 store。这是因为应用管理页面是独立的，不需要跨页面共享状态。

💡 **ASP.NET Core 类比**：这就像你在一个 Controller 里管理 View 的 ViewModel——每个页面有自己的状态，不需要放到 `TempData` 或 `Session` 里。

> **🤔 导师提问**：`AppsPage` 的所有状态都用 `useState` 管理，没有使用全局 store。但注意 `fetchData` 被传给了 `AppFormDialog` 的 `onSuccess` 回调——子组件保存成功后，父组件重新拉取列表。在 ASP.NET Core 中，如果 Controller A 修改了数据，Controller B 怎么知道数据变了？前端的"回调刷新"模式和后端的"缓存失效"有什么本质区别？

## 踩坑提醒

1. **应用 code 创建后不可修改**：`code` 字段与 AuthServer 的 OAuth2 `client_id` 绑定，且已被角色、权限、菜单大量引用。创建时务必确保填写正确，创建后无法修改。如果确实需要更改，只能删除旧应用重建，但级联删除影响范围极大。
2. **删除应用是级联操作**：删除应用会级联删除该应用下的所有权限组、权限定义、角色、菜单和用户角色分配。删除确认对话框的描述文案要明确提示级联影响，防止管理员误操作。
3. **新建应用时不需要"启用"开关**：新建应用默认启用，创建时允许禁用不合常理。只有在运行一段时间后需要临时停用时才需要禁用开关，因此"启用"开关仅在编辑模式下显示。
