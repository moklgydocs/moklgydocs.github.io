# 文件上传

[← 上一篇：文件管理器](03-文件管理器.md) | [下一篇：文件预览 →](05-文件预览.md)

---

## 这一步解决什么问题？

文件管理器能展示和操作文件了，但用户还需要**上传**文件。这不是简单的 `<input type="file">`——SaaS 场景下的文件上传需要处理：

1. **秒传**：同一文件不重复上传（SHA-256 哈希匹配）
2. **并发控制**：不能 100 个文件同时上传占满带宽
3. **进度反馈**：每个文件独立进度 + 总进度
4. **拖拽上传**：现代 Web 应用的标配

类比后端：你可能用 `IFormFile` 接收上传，用 `MD5` 做去重。前端的逻辑类似，但要变成**用户可交互的异步流程**。

> **🤔 导师提问**：后端去重通常用 MD5，前端秒传却用了 SHA-256。从安全角度看，SHA-256 比 MD5 更抗碰撞——为什么秒传场景需要关心哈希碰撞？如果两个不同文件算出相同 MD5，秒传会导致什么后果？

---

## 秒传原理

```
用户选择文件
    │
    ▼
计算 SHA-256 哈希 (crypto.subtle.digest)
    │
    ▼
调用 instantUpload API
    │
    ├── 200 + isInstantUpload=true → 秒传命中，跳过上传
    │
    └── 404 → 未命中，走普通上传
```

类比 ASP.NET Core 的 `EF Core` 去重检查：先查数据库有没有同哈希的记录，有就直接返回引用，没有才真正存储。

## 完整代码

来源：`src/pages/file/upload-dialog.tsx`

```typescript
import { useState, useCallback, useRef } from "react"
import { toast } from "sonner"
import { CloudUpload, X, CheckCircle2, AlertCircle, Loader2, File } from "lucide-react"
import {
  Dialog, DialogContent, DialogHeader, DialogTitle, DialogFooter,
} from "@/components/ui/dialog"
import { Button } from "@/components/ui/button"
import { Progress } from "@/components/ui/progress"
import { Card, CardContent } from "@/components/ui/card"
import { Tooltip, TooltipContent, TooltipTrigger } from "@/components/ui/tooltip"
import { filesApi } from "@/api/file/files"
import { formatBytes } from "@/lib/file-utils"

interface UploadItem {
  id: string
  file: File
  progress: number
  status: "pending" | "uploading" | "done" | "error"
  errorMsg?: string
}

interface UploadDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  folderId: string
  onSuccess: () => void
}

export default function UploadDialog({
  open,
  onOpenChange,
  folderId,
  onSuccess,
}: UploadDialogProps) {
  const [items, setItems] = useState<UploadItem[]>([])
  const [uploading, setUploading] = useState(false)
  const [isDragging, setIsDragging] = useState(false)
  const inputRef = useRef<HTMLInputElement>(null)

> **🤔 导师提问**：`UploadItem` 的 `status` 是联合类型 `"pending" | "uploading" | "done" | "error"`，这和后端用枚举 `enum UploadStatus` 有什么区别？TypeScript 的联合类型相比 C# 枚举，在模式匹配（switch/if）时有什么优势？

  /** 将 File 列表加入待上传队列，跳过超出大小限制的文件 */
  const addFiles = useCallback((files: FileList | File[]) => {
    const fileArray = Array.from(files)
    const validFiles = fileArray.filter((f) => {
      if (f.size > MAX_FILE_SIZE) {
        toast.error(`文件 ${f.name} (${formatBytes(f.size)}) 超过最大限制 (${formatBytes(MAX_FILE_SIZE)})`)
        return false
      }
      return true
    })
    const newItems: UploadItem[] = validFiles.map((f) => ({
      id: `${f.name}-${f.size}-${Date.now()}-${Math.random()}`,
      file: f,
      progress: 0,
      status: "pending",
    }))
    setItems((prev) => [...prev, ...newItems])
  }, [])

  /** 移除单个待上传文件 */
  const removeItem = (id: string) => {
    setItems((prev) => prev.filter((it) => it.id !== id))
  }

  /** 更新单条记录状态 */
  const updateItem = (id: string, patch: Partial<UploadItem>) => {
    setItems((prev) => prev.map((it) => (it.id === id ? { ...it, ...patch } : it)))
  }

  /** 上传单个文件（先秒传，不命中再正常上传） */
  const uploadOne = async (item: UploadItem): Promise<boolean> => {
    updateItem(item.id, { status: "uploading", progress: 0 })

    try {
      // ── 秒传检测（计算 SHA-256）─────────────────────────────
      const sha256 = await computeFileHash(item.file)
      const instantRes = await filesApi.instantUpload({
        fileName: item.file.name,
        hashSha256: sha256,
        sizeBytes: item.file.size,
        folderId: folderId || null,
      })

      if (instantRes.success && instantRes.data?.isInstantUpload) {
        // 秒传命中
        updateItem(item.id, { status: "done", progress: 100 })
        return true
      }

      // ── 普通上传 ─────────────────────────────────────────────
      await filesApi.upload(item.file, {
        folderId,
        onUploadProgress: (percent) => {
          updateItem(item.id, { progress: percent })
        },
      })
      updateItem(item.id, { status: "done", progress: 100 })
      return true
    } catch (err: unknown) {
      const msg = err instanceof Error ? err.message : "上传失败"
      updateItem(item.id, { status: "error", errorMsg: msg })
      return false
    }
  }

  /** 带并发限制的上传（最大同时 MAX_CONCURRENT 个） */
  const MAX_CONCURRENT = 3
  const MAX_FILE_SIZE = 100 * 1024 * 1024 // 100MB

> **🤔 导师提问**：并发池用 `nextIndex++` 分配任务给 N 个 Worker，类比 C# 的 `SemaphoreSlim(3)` 限流或 `Channel<T>` 生产者-消费者模型。为什么这里不用更简单的 `Promise.all` 直接启动所有上传？如果 100 个文件同时发出 HTTP 请求，浏览器和服务器分别会遇到什么问题？

  const startUpload = async () => {
    const pendingItems = items.filter((it) => it.status === "pending")
    if (pendingItems.length === 0) {
      toast.error("没有待上传的文件")
      return
    }

    setUploading(true)
    try {
      let nextIndex = 0
      let failedCount = 0

      // 并发池：最多同时运行 MAX_CONCURRENT 个任务
      const workers = Array.from({ length: Math.min(MAX_CONCURRENT, pendingItems.length) }, async () => {
        while (nextIndex < pendingItems.length) {
          const item = pendingItems[nextIndex++]
          const ok = await uploadOne(item)
          if (!ok) failedCount++
        }
      })

      await Promise.all(workers)

      if (failedCount === 0) {
        toast.success("全部文件上传完成")
        onSuccess?.()
        setItems([])
        onOpenChange(false)
      } else {
        toast.error(`${failedCount} 个文件上传失败`)
      }
    } finally {
      setUploading(false)
    }
  }

  /** 关闭对话框，重置状态 */
  const handleClose = () => {
    if (uploading) return
    setItems([])
    onOpenChange(false)
  }

  // ── 拖拽处理 ──
  const handleDragOver = (e: React.DragEvent) => {
    e.preventDefault()
    setIsDragging(true)
  }

  const handleDragLeave = () => {
    setIsDragging(false)
  }

  const handleDrop = (e: React.DragEvent) => {
    e.preventDefault()
    setIsDragging(false)
    if (e.dataTransfer.files.length > 0) {
      addFiles(e.dataTransfer.files)
    }
  }

  return (
    <Dialog open={open} onOpenChange={handleClose}>
      <DialogContent className="max-w-lg">
        <DialogHeader>
          <DialogTitle>上传文件</DialogTitle>
        </DialogHeader>

        {/* 拖拽区域 */}
        <div
          className={`min-h-[200px] rounded-lg border-dashed border-2 p-8 text-center cursor-pointer transition-colors flex flex-col items-center justify-center ${
            isDragging
              ? "border-primary bg-primary/5"
              : "border-muted-foreground/25 hover:border-primary/50"
          }`}
          onDragOver={handleDragOver}
          onDragLeave={handleDragLeave}
          onDrop={handleDrop}
          onClick={() => inputRef.current?.click()}
        >
          <CloudUpload className="mx-auto h-12 w-12 text-muted-foreground mb-3" />
          <p className="text-sm font-medium">拖拽文件到此处，或点击选择</p>
          <p className="text-xs text-muted-foreground mt-1">单文件最大 {formatBytes(MAX_FILE_SIZE)}，支持批量上传</p>
          <input
            ref={inputRef}
            type="file"
            multiple
            className="hidden"
            onChange={(e) => {
              if (e.target.files) {
                addFiles(e.target.files)
                e.target.value = ""
              }
            }}
          />
        </div>

        {/* 文件列表 */}
        {items.length > 0 && (
          <div className="max-h-60 overflow-y-auto space-y-2 mt-2">
            {items.map((item) => (
              <Card key={item.id} className="p-3">
                <CardContent className="p-0">
                  <div className="flex items-center gap-2.5">
                    <File className="h-5 w-5 text-muted-foreground shrink-0" />
                    <div className="flex-1 min-w-0">
                      <Tooltip>
                        <TooltipTrigger asChild>
                          <span className="text-sm font-medium truncate block">{item.file.name}</span>
                        </TooltipTrigger>
                        <TooltipContent>{item.file.name}</TooltipContent>
                      </Tooltip>
                      <span className="text-xs text-muted-foreground">{formatBytes(item.file.size)}</span>
                    </div>
                    <StatusIcon status={item.status} />
                    {item.status === "pending" && (
                      <Tooltip>
                        <TooltipTrigger asChild>
                          <button
                            onClick={() => removeItem(item.id)}
                            className="text-muted-foreground hover:text-destructive shrink-0"
                          >
                            <X className="h-4 w-4" />
                          </button>
                        </TooltipTrigger>
                        <TooltipContent>移除</TooltipContent>
                      </Tooltip>
                    )}
                  </div>
                  {(item.status === "uploading" || item.status === "done") && (
                    <Progress value={item.progress} className="h-1.5 mt-2" />
                  )}
                  {item.status === "error" && (
                    <p className="text-xs text-destructive mt-1.5">{item.errorMsg}</p>
                  )}
                </CardContent>
              </Card>
            ))}
          </div>
        )}

        <DialogFooter className="flex-col gap-3 sm:flex-col">
          {items.some((it) => it.status === "uploading" || it.status === "done") && (
            <div className="w-full space-y-1">
              <Progress
                value={items.length > 0
                  ? Math.round(items.reduce((sum, it) => sum + it.progress, 0) / items.length)
                  : 0
                }
                className="h-2"
              />
              <p className="text-xs text-muted-foreground text-center">
                {items.filter((it) => it.status === "done").length}/{items.length} 个已完成
              </p>
            </div>
          )}

          <div className="flex items-center justify-between w-full text-sm">
            <span className="text-muted-foreground">
              共 {items.length} 个文件 · 总计 {formatBytes(items.reduce((sum, it) => sum + it.file.size, 0))}
            </span>
            <div className="flex gap-2">
              <Button variant="outline" onClick={handleClose} disabled={uploading} size="sm">
                {items.every((it) => it.status === "done" || it.status === "error") && items.length > 0
                  ? "关闭"
                  : "取消"}
              </Button>
              <Button
                onClick={startUpload}
                disabled={uploading || items.filter((it) => it.status === "pending").length === 0}
                size="sm"
              >
                {uploading ? (
                  <>
                    <Loader2 className="mr-1.5 h-4 w-4 animate-spin" />
                    上传中...
                  </>
                ) : (
                  `开始上传`
                )}
              </Button>
            </div>
          </div>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  )
}

/** 状态图标小组件 */
function StatusIcon({ status }: { status: UploadItem["status"] }) {
  if (status === "uploading") return <Loader2 className="h-4 w-4 animate-spin text-primary" />
  if (status === "done") return <CheckCircle2 className="h-4 w-4 text-success" />
  if (status === "error") return <AlertCircle className="h-4 w-4 text-destructive" />
  return null
}

/** 使用 SubtleCrypto 计算 SHA-256 文件哈希 */
async function computeFileHash(file: File): Promise<string> {
  try {
    const buffer = await file.arrayBuffer()
    const hashBuffer = await crypto.subtle.digest("SHA-256", buffer)
    const hashArray = Array.from(new Uint8Array(hashBuffer))
    return hashArray.map((b) => b.toString(16).padStart(2, "0")).join("")
  } catch {
    return `${file.name}-${file.size}`
  }
}
```

## 逐行讲解

### `computeFileHash` — SHA-256 哈希计算

```typescript
async function computeFileHash(file: File): Promise<string> {
  try {
    const buffer = await file.arrayBuffer()
    const hashBuffer = await crypto.subtle.digest("SHA-256", buffer)
    const hashArray = Array.from(new Uint8Array(hashBuffer))
    return hashArray.map((b) => b.toString(16).padStart(2, "0")).join("")
  } catch {
    return `${file.name}-${file.size}`
  }
}
```

- **`crypto.subtle.digest("SHA-256", buffer)`**：浏览器原生 Web Crypto API，在主线程计算哈希。类比后端的 `System.Security.Cryptography.SHA256.HashData()`。【性能陷阱】大文件（>100MB）会阻塞主线程，生产环境应切到 Web Worker 计算。
- **降级策略**：`catch` 里返回 `file.name-file.size` 作为伪哈希。【易错点】这不是真正的哈希，同名同大小但内容不同的文件会错误命中秒传。生产环境应报告错误而非降级。

> **🤔 导师提问**：`computeFileHash` 的 `catch` 分支返回 `${file.name}-${file.size}` 作为降级哈希，这可能导致同名同大小但内容不同的文件错误命中秒传。类比后端，这就像缓存 key 不够精确导致脏读。在生产环境中，你会如何处理这种降级——是报错让用户重试，还是允许降级但加标记？

### 并发池设计

```typescript
const MAX_CONCURRENT = 3
const MAX_FILE_SIZE = 100 * 1024 * 1024 // 100MB

const workers = Array.from({ length: Math.min(MAX_CONCURRENT, pendingItems.length) }, async () => {
  while (nextIndex < pendingItems.length) {
    const item = pendingItems[nextIndex++]
    const ok = await uploadOne(item)
    if (!ok) failedCount++
  }
})

await Promise.all(workers)
```

- **Worker 池模式**：创建 N 个"工人"，每个工人从队列中取任务执行。类比 C# 的 `SemaphoreSlim(3)` 限流，但这里用 `nextIndex++` 的原子递增代替了锁。【设计取舍】不用 `Promise.allSettled` 一次性启动所有上传然后限流，因为那会瞬间创建所有 HTTP 连接。
- **`nextIndex++`**：JS 是单线程的，`nextIndex++` 之间不会有竞态条件。如果在多线程环境（如 Go），需要 `atomic.AddInt64`。

### `uploadOne` — 秒传 → 普通上传的决策

```typescript
const uploadOne = async (item: UploadItem): Promise<boolean> => {
  updateItem(item.id, { status: "uploading", progress: 0 })
  try {
    const sha256 = await computeFileHash(item.file)
    const instantRes = await filesApi.instantUpload({ ... })

    if (instantRes.success && instantRes.data?.isInstantUpload) {
      updateItem(item.id, { status: "done", progress: 100 })
      return true
    }

    await filesApi.upload(item.file, { folderId, onUploadProgress: ... })
    updateItem(item.id, { status: "done", progress: 100 })
    return true
  } catch (err: unknown) {
    // ...
    return false
  }
}
```

- **先秒传再上传**：即使秒传失败也不影响——404 只是"未命中"，不是错误。【易错点】不能在秒传失败时直接 `throw`，要继续走普通上传。

> **🤔 导师提问**：`uploadOne` 中秒传检测和普通上传是串行的：先算哈希 → 调秒传 API → 不命中再上传。如果网络延迟很高，用户要等两轮 RTT 才开始真正上传。你能想到什么优化策略来减少这个等待时间？（提示：参考"乐观执行"或"预计算"的思路）

### `e.target.value = ""` — 重置 file input

```typescript
onChange={(e) => {
  if (e.target.files) {
    addFiles(e.target.files)
    e.target.value = ""  // ← 重置
  }
}}
```

- **必须重置**：如果用户选了 A 文件上传，再选 A 文件，`onChange` 不会触发（值没变）。【易错点】`e.target.value = null` 在某些浏览器不生效，用空字符串更安全。
