# 05 - 通知列表页：分页、筛选与详情弹窗

> **这一步解决什么问题？**
> 铃铛下拉只展示最近 10 条通知。如果用户要查看历史通知、按渠道或状态筛选、查看通知详情，需要一个完整的通知列表页。
>
> **ASP.NET Core 开发者的直觉**：通知列表页 ≈ 后端的 `NotificationsController.GetList()`，分页查询 + 筛选条件 + 详情查看。前端的 AgTable ≈ 后端的 DataTables/PagedList 返回。

## 三、打印任务数据解析

```typescript
/** 解析 dataJson，提取打印任务信息 */
function parsePrintJobData(dataJson?: string) {
  if (!dataJson) return null
  try {
    const data = JSON.parse(dataJson)
    if (data.jobId) return data as { jobId: string; status: string; downloadUrl?: string }
  } catch { /* ignore */ }
  return null
}
```

⚠️ **【易错点】** 返回类型中有 `downloadUrl` 但实际不使用它。下载走 `jobsApi.download(jobId)` 而非直接打开 URL（因为需要 Authorization header）。

## 四、完整页面代码

以下代码完全来自 `src/pages/notifications/index.tsx`：

```typescript

import { toast } from "sonner"
import { RefreshCw, CheckCheck, Download } from "lucide-react"

  SelectTrigger,
  SelectValue,
} from "@/components/ui/select"
import { getNotifications, markAsRead, markAllAsRead } from "@/api/notify/notifications"
import { jobsApi } from "@/api/print/jobs"
import {
  NotificationStatus,
  NotificationChannel,
  NotificationPriority,
} from "@/types/notification"
import type { NotificationDto } from "@/types/notification"
```

### 页面主体

```typescript
export default function NotificationsPage() {
  const [data, setData] = useState<NotificationDto[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [pageSize, setPageSize] = useState(20)
  const [loading, setLoading] = useState(false)
  const [statusFilter, setStatusFilter] = useState<string>("all")
  const [channelFilter, setChannelFilter] = useState<string>("all")

  // 详情弹窗
  const [detailItem, setDetailItem] = useState<NotificationDto | null>(null)
  const [downloading, setDownloading] = useState(false)

  const fetchData = useCallback(async () => {
    setLoading(true)
    try {
      const params: Record<string, unknown> = { page, pageSize }
      if (statusFilter !== "all") params.status = statusFilter
      if (channelFilter !== "all") params.channel = channelFilter

      const res = await getNotifications(params as never)
      setData(res.data?.items ?? [])
      setTotal(res.data?.totalCount ?? 0)
    } catch {
      toast.error("获取通知列表失败")
    } finally {
      setLoading(false)
    }
  }, [page, pageSize, statusFilter, channelFilter])

  useEffect(() => { fetchData() }, [fetchData])
```

逐行精讲：

| 标记 | 代码 | 解读 |
|------|------|------|
| **【重要】** | `useCallback` + `[page, pageSize, statusFilter, channelFilter]` | 筛选条件变化时重新创建函数，触发 `useEffect` 重新获取数据 |
| **【易错点】** | `params as never` | TypeScript 类型断言。后端 API 参数类型与实际传参不完全匹配（如 `status` 后端期望 number，前端用 string），用 `never` 绕过类型检查 |

> **🤔 导师提问**：`useCallback` 的依赖数组是 `[page, pageSize, statusFilter, channelFilter]`。如果漏掉 `statusFilter`，切换筛选条件后数据会更新吗？这和 ASP.NET Core 中 `OnParametersSetAsync` 的自动触发机制有什么区别？

### 行点击处理

```typescript
  const handleRowClick = async (row: NotificationDto) => {
    // 未读则标记已读
    if (row.status === NotificationStatus.Sent) {
      try {
        await markAsRead(row.id)
        setData((prev) =>
          prev.map((r) => r.id === row.id ? { ...r, status: NotificationStatus.Read } : r)
        )
      } catch { /* 静默 */ }
    }
    setDetailItem({ ...row, status: row.status === NotificationStatus.Sent ? NotificationStatus.Read : row.status })
  }
```

| 标记 | 代码 | 解读 |
|------|------|------|
| **【设计取舍】** | 点击行自动标记已读 | 语义上"用户看了这条通知 = 已读"。这是大多数邮件客户端的交互模式 |
| **【易错点】** | `setDetailItem({ ...row, status: Read })` | 弹窗中显示的状态应该是已读的，即使 API 调用失败。因为用户已经点击了，应该展示"已看" |

> **🤔 导师提问**：`handleRowClick` 先调 `markAsRead` API，成功后才更新本地状态。如果 API 调用失败（catch 中静默处理），列表中这条通知还是"未读"，但弹窗里已经显示为"已读"。这种不一致你会怎么处理？对比第 2 节的"乐观更新"，哪种方案更适合这个场景？

### 全部已读和下载

```typescript
  const handleMarkAllRead = async () => {
    try {
      await markAllAsRead()
      toast.success("已全部标记为已读")
      fetchData()
    } catch {
      toast.error("操作失败")
    }
  }

  const handleDownload = async (jobId: string) => {
    setDownloading(true)
    try {
      const res = await jobsApi.download(jobId)
      const blob = new Blob([res.data as BlobPart])
      const url = URL.createObjectURL(blob)
      const a = document.createElement("a")
      a.href = url
      a.download = `report_${jobId.slice(0, 8)}.pdf`
      a.click()
      URL.revokeObjectURL(url)
    } catch {
      toast.error("下载失败")
    } finally {
      setDownloading(false)
    }
  }
```

逐行精讲：

| 标记 | 代码 | 解读 |
|------|------|------|
| **【设计取舍】** | 未读标题 `font-medium`，已读标题 `text-muted-foreground` | 视觉区分已读/未读，类似邮件客户端的加粗效果 |

### 筛选器 + 表格 + 详情弹窗

```tsx

            </Select>
            <Select value={channelFilter} onValueChange={(v) => { setChannelFilter(v); setPage(1) }}>
              <SelectTrigger className="h-6 w-24 text-xs">
                <SelectValue placeholder="渠道" />
              </SelectTrigger>
              <SelectContent>
                <SelectItem value="all">全部渠道</SelectItem>

          </div>
        }
      />

      <AgTable
        columns={columns}
        data={data}
        total={total}

        loading={loading}

        onPageSizeChange={setPageSize}

      />
```

| 标记 | 代码 | 解读 |
|------|------|------|
| **【重要】** | `setPage(1)` 在筛选变化时 | 切换筛选条件后必须重置页码到第 1 页，否则可能请求一个不存在的页码 |
| **【设计取舍】** | 渠道筛选只列 3 个 | 微信和移动推送尚不可用，从筛选器中排除避免用户困惑 |

> **🤔 导师提问**：筛选器变化时调用 `setPage(1)` 重置页码。如果不重置，用户在第 5 页切换筛选条件，可能请求到不存在的页码。在 ASP.NET Core 的分页查询中，你有没有遇到过类似"总页数变了但页码没重置"的 bug？

### 详情弹窗

```tsx
      {/* 通知详情弹窗 */}
      <Dialog open={!!detailItem} onOpenChange={(open) => { if (!open) setDetailItem(null) }}>
        <DialogContent className="max-w-lg">
          <DialogHeader>
            <DialogTitle>{detailItem?.title ?? "通知详情"}</DialogTitle>
          </DialogHeader>

          {detailItem && (
            <div className="space-y-4">
              {/* 元信息 */}
              <div className="flex flex-wrap gap-3 text-xs text-muted-foreground">
                <span>{statusConfig[detailItem.status]?.label ?? "未知"}</span>
                <span>{channelLabels[detailItem.channel] ?? "未知"}</span>
                {priorityLabels[detailItem.priority] && (
                  <span className={priorityLabels[detailItem.priority].color}>
                    {priorityLabels[detailItem.priority].label}
                  </span>
                )}
                <span>{new Date(detailItem.creationTime).toLocaleString("zh-CN")}</span>
                {detailItem.readAt && (
                  <span>已读于 {new Date(detailItem.readAt).toLocaleString("zh-CN")}</span>
                )}
              </div>

              {/* 正文 */}
              {detailItem.body && (
                <div className="text-sm whitespace-pre-wrap border rounded-md p-3 bg-muted/30">
                  {detailItem.body}
                </div>
              )}

              {/* 打印任务操作 */}
              {printData && (
                <div className="border rounded-md p-3 space-y-2">
                  <div className="text-sm font-medium">
                    打印任务
                    <span className="ml-2 text-xs text-muted-foreground">
                      {printData.jobId.slice(0, 8)}...
                    </span>
                  </div>
                  <div className="flex items-center gap-2">
                    <Badge variant={printData.status === "completed" ? "default" : "destructive"}>
                      {printData.status === "completed" ? "已完成" : "失败"}
                    </Badge>
                    {printData.status === "completed" && (
                      <Button
                        size="sm"
                        variant="outline"
                        disabled={downloading}
                        onClick={() => handleDownload(printData.jobId)}
                      >
                        <Download className="h-3.5 w-3.5 mr-1" />
                        {downloading ? "下载中..." : "下载文件"}
                      </Button>
                    )}
                  </div>
                </div>
              )}

              {/* 原始数据（可折叠，开发调试用） */}
              {detailItem.dataJson && !printData && (
                <details className="text-xs">
                  <summary className="cursor-pointer text-muted-foreground hover:text-foreground">
                    附加数据
                  </summary>
                  <pre className="mt-1 p-2 bg-muted/30 rounded text-xs overflow-auto max-h-32">
                    {(() => { try { return JSON.stringify(JSON.parse(detailItem.dataJson), null, 2) } catch { return detailItem.dataJson } })()}
                  </pre>
                </details>
              )}
            </div>
          )}
        </DialogContent>
      </Dialog>
    </AnimatedPage>
  )
}
```

逐行精讲详情弹窗：

| 标记 | 代码 | 解读 |
|------|------|------|
| **【设计取舍】** | `whitespace-pre-wrap` | 通知正文保留换行和空格，类似邮件客户端的正文展示 |
| **【易错点】** | `detailItem.readAt` | 已读时间可能为空（未读通知），渲染前必须判空 |
