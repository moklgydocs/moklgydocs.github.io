# 工具函数

> **这一步解决什么问题？**
> 没有工具函数，整个项目寸步难行——`cn()` 是 shadcn/ui 每个组件的依赖，`createHttp()` 是所有 API 调用的入口。本文将实现这两个基石函数，并建立前端 HTTP 通信的心智模型。
>
> 对于 ASP.NET Core 开发者来说，`cn()` 就像 TagHelper 中的属性合并器，`createHttp()` 就像 HttpClient 工厂 + DelegatingHandler 管道——理解了这两个类比，就掌握了本文的核心。

## 前置知识

### cn() — 为什么需要类名合并？

在 .NET 中，拼接字符串用 `string.Format()` 或插值 `$"{class1} {class2}"`。但 Tailwind CSS 有一个特殊问题：**同类属性冲突**。`"px-2"` 和 `"px-4"` 同时存在时，最终结果取决于 CSS 加载顺序而非代码顺序，这是不确定的。

`cn()` 用两步解决这个问题：
1. `clsx`（类似条件三元运算符）——根据条件动态拼接类名
2. `twMerge`（类似冲突解决器）——同类属性后者覆盖前者

### createHttp() — .NET 类比

`createHttp` 类似 ASP.NET Core 的 **HttpClient 工厂 + DelegatingHandler 管道**：

```csharp
// .NET 中为不同微服务注册不同命名的 HttpClient
builder.Services.AddHttpClient("sso-api", c => c.BaseAddress = new Uri("http://sso-service"));
builder.Services.AddHttpClient("perm-api", c => c.BaseAddress = new Uri("http://perm-service"));

// 添加 DelegatingHandler（等价于 axios 拦截器）
builder.Services.AddHttpClient("perm-api")
    .AddHttpMessageHandler<AuthHeaderHandler>()    // 请求拦截：注入 Bearer Token
    .AddHttpMessageHandler<TenantIdHandler>()       // 请求拦截：注入 X-Tenant-Id
    .AddHttpMessageHandler<TokenRefreshHandler>();  // 响应拦截：401 自动刷新
```

前端用 `createHttp` 工厂函数 + axios 拦截器实现了完全相同的效果。

## 代码实现

### src/lib/utils.ts

```typescript
import { clsx, type ClassValue } from "clsx"
import { twMerge } from "tailwind-merge"

/**
 * 合并 CSS 类名工具函数。
 * 先用 clsx 处理条件类名，再用 twMerge 去除 Tailwind CSS 冲突类名。
 *
 * @param inputs 类名列表，支持字符串、对象、数组等 ClassValue 格式
 * @returns 合并后的类名字符串
 *
 * @example
 * cn("px-2", "px-4") // "px-4"（twMerge 保留后者）
 * cn("text-red-500", false && "hidden") // "text-red-500"
 */
export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs))
}
```

### src/lib/create-http.ts

```typescript
import axios, { type AxiosError, type AxiosRequestConfig, type InternalAxiosRequestConfig } from "axios"
import type { ApiResult } from "@/types"
import { useAuthStore } from "@/stores/auth-store"

/** 创建 HTTP 实例的选项 */
interface CreateHttpOptions {
  /** 是否自动注入 X-Tenant-Id（默认 true）。SSO 等跨服务 API 不共享租户库，应设为 false */
  sendTenantId?: boolean
}

/**
 * 创建一个绑定到特定后端前缀的 axios 实例（含 Token 自动注入 & 刷新逻辑）。
 *
 * @param basePrefix  Vite proxy 的路径前缀，例如 '/sso-api'、'/perm-api'、'/gw-api'
 * @param options     可选配置项，如是否发送租户 ID
 * @returns 封装了 get/post/put/del/postForm 的 HTTP 客户端对象
 */
export function createHttp(basePrefix: string, options?: CreateHttpOptions) {
  // 解构选项，默认发送租户 ID
  const { sendTenantId = true } = options ?? {}

  // 创建 axios 实例，配置基础路径、超时时间和默认请求头
  const http = axios.create({
    baseURL: basePrefix,
    timeout: 15000,
    withCredentials: true,
    headers: { "Content-Type": "application/json" },
  })

  // 请求拦截：自动挂 Bearer Token + 租户 ID
  http.interceptors.request.use((config) => {
    const { accessToken, currentTenantId } = useAuthStore.getState()
    if (accessToken) {
      config.headers.Authorization = `Bearer ${accessToken}`
    }
    if (sendTenantId && currentTenantId) {
      config.headers["X-Tenant-Id"] = currentTenantId
    }
    return config
  })

  /** 是否正在刷新 Token（防止并发刷新） */
  let isRefreshing = false
  /** Token 刷新期间被挂起的请求队列 */
  let failedQueue: { resolve: (token: string) => void; reject: (error: unknown) => void }[] = []

  /**
   * 处理挂起的请求队列：刷新成功时重发所有请求，失败时全部拒绝
   * @param error 刷新错误，不为 null 表示刷新失败
   * @param token 刷新成功后的新 access_token
   */
  function processQueue(error: unknown, token: string | null = null) {
    failedQueue.forEach((p) => (error ? p.reject(error) : p.resolve(token!)))
    failedQueue = []
  }

  // 响应拦截：非 ApiResult 响应自动包裹（跳过 /connect/* OIDC 端点）+ 401 自动刷新
  http.interceptors.response.use(
    (response) => {
      const data = response.data
      const url = response.config.url ?? ""
      // Blob / ArrayBuffer 响应：检测后端是否返回了 JSON 错误（如 200 但 body 是错误 JSON）
      if (data instanceof Blob) {
        if (data.type && data.type.includes('application/json')) {
          // 后端返回了 JSON 而非文件，解析为错误
          return data.text().then((text) => {
            try {
              const json = JSON.parse(text)
              const err = new Error(json.message || json.error_description || json.title || '请求失败')
              ;(err as any).response = { data: json, status: response.status }
              return Promise.reject(err)
            } catch {
              // JSON 解析失败，当作正常 blob 处理
              return response
            }
          })
        }
        return response
      }
      if (data instanceof ArrayBuffer) {
        return response
      }
      // 跳过 OIDC/OAuth2 端点（/connect/*），这些端点返回原生格式，不应包裹 ApiResult
      if (data !== null && typeof data === 'object' && !('success' in data) && !url.includes("/connect/")) {
        // 将非标准响应自动包裹为 ApiResult 格式，统一前端处理
        response.data = { success: true, code: 0, message: 'ok', data } as ApiResult<unknown>
      }
      return response
    },
    async (error: AxiosError) => {
      const originalRequest = error.config as InternalAxiosRequestConfig & { _retry?: boolean }

      if (error.response?.status === 401) {
        // /connect/token 本身 401 不触发刷新（说明 refresh_token 也已过期）
        const url = originalRequest?.url ?? ""
        if (url.includes("/connect/token")) return Promise.reject(error)

        const { refreshToken, isAuthenticated } = useAuthStore.getState()

        // 无 refresh_token 或未认证状态，直接跳转登录页
        if (!refreshToken || !isAuthenticated) {
          useAuthStore.getState().logout()
          window.location.href = "/login"
          return Promise.reject(error)
        }

        // 已经重试过一次仍 401，说明新 token 也无效，跳转登录页
        if (originalRequest._retry) {
          useAuthStore.getState().logout()
          window.location.href = "/login"
          return Promise.reject(error)
        }

        // 正在刷新中，将当前请求加入等待队列，刷新成功后自动重发
        if (isRefreshing) {
          return new Promise<string>((resolve, reject) => {
            failedQueue.push({ resolve, reject })
          }).then((newToken) => {
            originalRequest.headers.Authorization = `Bearer ${newToken}`
            return http(originalRequest)
          })
        }

        // 标记为重试请求，开始刷新
        originalRequest._retry = true
        isRefreshing = true

        try {
          // 刷新 token 直接走 /connect/token（走 Vite proxy，不带 basePrefix）
          const res = await axios.post<{ access_token: string; refresh_token?: string }>(
            "/connect/token",
            new URLSearchParams({
              grant_type: "refresh_token",
              client_id: "mok-web-app",
              refresh_token: refreshToken,
            }),
            { headers: { "Content-Type": "application/x-www-form-urlencoded" } }
          )

          // 更新 store 中的 token
          const { access_token, refresh_token } = res.data
          useAuthStore.getState().setTokens(access_token, refresh_token)
          // 用新 token 重发原请求
          originalRequest.headers.Authorization = `Bearer ${access_token}`
          // 唤醒所有等待中的请求
          processQueue(null, access_token)
          return http(originalRequest)
        } catch (refreshError) {
          // 刷新失败，所有等待中的请求全部拒绝
          processQueue(refreshError, null)
          useAuthStore.getState().logout()
          window.location.href = "/login"
          return Promise.reject(refreshError)
        } finally {
          isRefreshing = false
        }
      }

      return Promise.reject(error)
    }
  )

  return {
    /** 底层 axios 实例（特殊场景可直接使用） */
    instance: http,

    /**
     * GET 请求
     * @param url 请求路径（不含 basePrefix）
     * @param params 查询参数对象
     * @returns ApiResult<T> 格式的响应数据
     */
    async get<T>(url: string, params?: Record<string, unknown>): Promise<ApiResult<T>> {
      const res = await http.get<ApiResult<T>>(url, { params })
      return res.data
    },

    /**
     * POST 请求
     * @param url 请求路径（不含 basePrefix）
     * @param data 请求体数据
     * @returns ApiResult<T> 格式的响应数据
     */
    async post<T>(url: string, data?: unknown): Promise<ApiResult<T>> {
      const res = await http.post<ApiResult<T>>(url, data)
      return res.data
    },

    /**
     * PUT 请求
     * @param url 请求路径（不含 basePrefix）
     * @param data 请求体数据
     * @returns ApiResult<T> 格式的响应数据
     */
    async put<T>(url: string, data?: unknown): Promise<ApiResult<T>> {
      const res = await http.put<ApiResult<T>>(url, data)
      return res.data
    },

    /**
     * DELETE 请求
     * @param url 请求路径（不含 basePrefix）
     * @param config 额外的 axios 请求配置
     * @returns ApiResult<T> 格式的响应数据
     */
    async del<T>(url: string, config?: AxiosRequestConfig): Promise<ApiResult<T>> {
      const res = await http.delete<ApiResult<T>>(url, config)
      return res.data
    },

    /**
     * 表单 POST 请求（application/x-www-form-urlencoded 格式）
     * 用于 OAuth2 等需要表单提交的接口
     *
     * @param url 请求路径
     * @param data 表单键值对
     * @returns 原始响应数据（不包裹 ApiResult）
     */
    async postForm<T>(url: string, data: Record<string, string>): Promise<T> {
      const res = await http.post<T>(url, new URLSearchParams(data), {
        headers: { "Content-Type": "application/x-www-form-urlencoded" },
      })
      return res.data
    },
  }
}
```

## 代码讲解

### cn() 的工作原理

`cn()` 是两步管道：

```
输入: cn("px-2", false && "hidden", "px-4")
  │
  ├─ Step 1: clsx() → "px-2 px-4"（过滤掉 falsy 值，拼接字符串）
  │
  └─ Step 2: twMerge() → "px-4"（同类属性后者覆盖前者）
  │
输出: "px-4"
```

在组件中的实际用法：

```typescript
cn(
  "inline-flex items-center justify-center rounded-md text-sm font-medium",
  variant === "default" && "bg-primary text-white",
  variant === "outline" && "border border-input bg-background",
  size === "sm" && "h-8 px-3",
  size === "lg" && "h-12 px-8",
  className  // 外部传入的类名可以覆盖前面的默认值
)
```

> **.NET 类比**：这就像 ASP.NET Core 的 `TagHelper` 中合并 HTML 属性——子组件可以覆盖父组件的默认 CSS 类。`cn()` 保证了覆盖是确定性的。

### createHttp() 的五大能力

`createHttp` 不是简单的 axios 封装，它处理了五个关键问题：

| 能力 | 实现位置 | .NET 类比 |
|------|---------|----------|
| Bearer Token 自动注入 | 请求拦截器 | `AuthHeaderHandler : DelegatingHandler` |
| X-Tenant-Id 自动注入 | 请求拦截器 | `TenantIdHandler : DelegatingHandler` |
| 401 自动刷新 + 请求排队 | 响应拦截器 | `TokenRefreshHandler` + `SemaphoreSlim(1,1)` |
| 非标准响应包裹为 ApiResult | 响应拦截器（成功分支） | Result\<T\> 统一包装 |
| Blob 响应中的 JSON 错误检测 | 响应拦截器（成功分支） | 流式响应的错误检测 |

> **【易错点】** `useAuthStore.getState()` 不是 `useAuthStore()`。在拦截器中不能使用 React Hook，因为拦截器不在 React 组件内执行。`getState()` 是 Zustand 的非 React API，直接返回当前状态快照。如果误用 Hook 写法，运行时会报 "Invalid hook call" 错误。

> **【性能陷阱】** `cn()` 在每次组件渲染时都会执行 `clsx()` + `twMerge()`。如果一个组件树中有 100 个使用了 `cn()` 的按钮，每次状态变化都会触发 100 次 `twMerge` 解析。在正常场景下这不是问题（`twMerge` 单次执行 < 0.1ms），但如果在列表渲染中对每一项都调用 `cn()` 拼接复杂的类名组合，可能成为瓶颈。解决方案：用 `useMemo` 缓存计算结果，或把静态类名提取到常量中。

> **🤔 导师提问**：`createHttp` 返回的是对象而不是 class 实例。如果你用 class 来实现（如 `class HttpClient { get() {...} post() {...} }`），和当前工厂函数相比有什么区别？提示：想想 .NET 中 `HttpClient` 是 class，但官方推荐用 `IHttpClientFactory` 创建——为什么不直接 `new HttpClient()`？

### sendTenantId 参数的设计考量

SSO 认证服务是**跨租户**的——用户登录时还没有选择租户，甚至可能不属于任何租户。如果 SSO 请求带了 `X-Tenant-Id`，后端会报错。所以 SSO 的 HTTP 实例需要 `sendTenantId: false`。

而权限中心、文件服务、打印服务等都是**租户隔离**的——所有数据都属于当前租户，后端根据 `X-Tenant-Id` 过滤数据。这些服务使用默认的 `sendTenantId: true`。

> **.NET 类比**：就像某些 HttpClient 需要加 `X-Tenant-Id` Header，而 SSO 的不需要。在 .NET 中你可能会注册两种不同的 `HttpMessageHandler`；在前端，我们用 `createHttp` 的 `sendTenantId` 选项来区分。

> **【设计取舍】** `sendTenantId` 为什么是 `createHttp` 的选项而不是一个全局配置？因为每个服务的 HTTP 实例是独立的——SSO 不发租户 ID，权限中心要发，这是实例级别的决策，不是全局策略。如果做成全局配置，当某个新服务需要不同行为时，就得添加例外规则，反而更复杂。

### 为什么返回的是对象而不是 axios 实例？

`createHttp` 返回的对象包含 `get`、`post`、`put`、`del`、`postForm` 五个方法，以及一个 `instance` 属性。这样设计有两个好处：

1. **类型安全**：返回值有明确的 `ApiResult<T>` 泛型约束，调用方不会忘记解包 `res.data`。
2. **最小暴露**：大部分场景只需 `get/post/put/del`，不需要知道 axios 实例的存在。只有文件上传（需要 `onUploadProgress`）或 Blob 下载（需要 `responseType: 'blob'`）时才通过 `instance` 使用底层 axios。

> **🤔 导师提问**：假设你正在开发文件上传功能，需要 `onUploadProgress` 回调显示进度条。你只能通过 `instance` 属性访问底层 axios——这意味着你要自己处理 `res.data` 的解包和 `ApiResult` 格式。这会不会破坏 `createHttp` 统一返回 `ApiResult<T>` 的一致性？你会怎么设计？

## 踩坑提醒

1. **`useAuthStore.getState()` 不是 `useAuthStore()`**。在拦截器中不能使用 React Hook，因为拦截器不在 React 组件内执行。`getState()` 是 Zustand 的非 React API，直接返回当前状态快照。

2. **`processQueue` 必须在 `finally` 之前调用**。`processQueue` 在 `try` 中成功时传入新 token，在 `catch` 中失败时传入 error。如果在 `finally` 中才处理队列，所有等待中的请求已经超时了。

3. **Blob 响应的 JSON 错误检测是文件服务特有的问题**。后端返回文件下载时 HTTP 状态码是 200，但如果文件不存在或权限不足，后端可能返回 JSON 错误体（Content-Type 仍是 `application/json`）。axios 会把 JSON 解析成 Blob，导致前端无法读取错误信息。这段代码通过 `data.type.includes('application/json')` 检测并转换。

4. **`postForm` 返回的是原始类型 `T`，不是 `ApiResult<T>`**。这是因为 OAuth2 的 `/connect/token` 端点返回的是 `{ access_token, refresh_token }` 格式，不是 `{ success, code, data }` 格式。
