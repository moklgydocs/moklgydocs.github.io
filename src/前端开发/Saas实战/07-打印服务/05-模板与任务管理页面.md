# 05 - 模板与任务管理页面

> **这一步解决什么问题？** 我们要完成打印服务最后两个核心页面 —— 模板管理（功能最丰富的 CRUD+ 发布归档+ 导入导出+ 渲染预览）和任务管理（最轻量的渲染+ 轮询+ 下载）。理解渲染预览中 Blob 错误检测、`cancelled` 竞态保护、`React.memo` 防循环闪烁，以及任务轮询中 `setInterval` 的清理机制，是这一步的重点。

---

## 开篇引导

上一节我们完成了数据源管理页面，学会了根据数据源类型动态渲染表单字段。这一节我们进入打印服务的**核心业务页面**。

模板管理页面是整个打印服务中**功能最丰富**的页面 —— 除了标准 CRUD，它还有 7 个操作按钮：

```
操作列按钮（按状态动态显示）:
┌──────┬──────┬──────┬──────┬──────┬──────┬──────┐
│ 编辑 │ 预览 │设计器│发布/ │ 导出 │ 删除 │      │
│      │      │      │归档  │ .frx │      │      │
└──────┴──────┴──────┴──────┴──────┴──────┴──────┘
  始终   始终   始终  条件    始终   始终
                     草稿→发布
                     已发布→归档
```

任务管理页面则恰恰相反 —— **最轻量**，核心只有一个渲染对话框 + 状态轮询。

**ASP.NET Core 类比**：

| 模板管理 | 任务管理 |
|---|---|
| 类似 CMS 的内容管理 | 类似 Hangfire Dashboard |
| 管理模板生命周期（Draft→Published→Archived） | 监控任务生命周期（Queued→Processing→Completed/Failed） |
| 富操作：编辑、发布、导入、预览 | 简单操作：渲染、下载 |

## 概念讲解

### 1. 模板管理页面的组件结构

模板管理页面包含三个子组件，远比数据源页面复杂：

```
TemplatesPage（主页面）
├── PageToolbar + QueryFilter + AgTable
├── TemplateFormDialog（创建/编辑模板）
│   └── 加载数据源列表供选择（关联默认数据源）
├── RenderPreviewDialog（渲染预览对话框）← 最复杂！
│   ├── 数据源选择（无/直传JSON/关联数据源）
│   ├── 运行时参数输入
│   ├── XML 数据输入（仅 XML 类型数据源）
│   └── 导出格式选择 + 渲染逻辑（同步/异步）
└── ConfirmDialog × 3（删除、发布、归档确认）
```

> **🤔 导师提问**：模板管理页面的操作列有 7 个按钮，远比数据源页面的 4 个按钮复杂。操作列的按钮还根据模板状态动态显示（草稿显示"发布"，已发布显示"归档"）。在 ASP.NET Core 中，这种"根据状态限制操作"通常用 `Authorize` 特性或业务层校验。前端用条件渲染实现同样的约束 —— 但前端约束可以被用户绕过（直接调 API）。如果用户在控制台调用 `templatesApi.publish()` 去发布一个已归档的模板，会发生什么？这说明前端状态约束的本质是什么？

### 2. 渲染预览 —— 同步 vs 异步的前端处理

渲染预览对话框是最核心的交互。它需要处理两种渲染模式的**完全不同的响应**：

```
异步模式（async=true）:
  请求 → POST /api/print/jobs/render { async: true }
  响应 → { jobId: "abc123...", status: 1 }
  后续 → 站内通知（SignalR）告知渲染完成

同步模式（async=false/undefined）:
  请求 → POST /api/print/jobs/render { responseType: "blob" }
  响应 → Blob（二进制文件流）
  处理 → PDF/HTML/PNG 在新标签页打开；XLSX/DOCX/CSV 触发下载
```

> 【易错点】**Blob 响应的特殊处理**：后端可能返回 HTTP 200 但 body 是 JSON 错误（比如渲染失败但没抛异常）。前端必须检测 Blob 类型：

```
收到 Blob → 检查 size < 100 且 type 包含 "json" → 解析为 JSON → 提取错误信息
         → 否则 → 正常处理文件
```

这类似 ASP.NET Core 中 `HttpClient` 调用返回 `200 OK` 但 body 是错误 JSON 的场景 —— 你不能只看 HTTP 状态码，还要检查 Content-Type。

### 3. `cancelled` 标志防止竞态条件

在 `RenderPreviewDialog` 中，当用户快速切换不同模板时，前一个模板的数据源请求可能还没返回，后一个请求已经发出。这会导致**竞态条件**：

```
时间线:
  t0: 点击模板A → 发起 datasourcesApi.list()
  t1: 点击模板B → 发起 datasourcesApi.list()
  t2: 模板A的请求返回 → setDatasources(A的数据) ← 错误！应该用B的数据
  t3: 模板B的请求返回 → setDatasources(B的数据) ← 覆盖了，但中间态已经错误
```

解决方案是 `cancelled` 标志：

```
useEffect(() => {
  let cancelled = false          // 1. 创建标志
  datasourcesApi.list(...).then((res) => {
    if (cancelled) return        // 2. 检查标志，过时的响应直接丢弃
    setDatasources(...)
  })
  return () => { cancelled = true }  // 3. 清理时置标志
}, [templateId])                 // 4. templateId 变化时重新执行
```

**ASP.NET Core 类比**：这类似 `CancellationToken` 在异步方法中的用法。`useEffect` 的清理函数相当于 `CancellationTokenSource.Cancel()`。

> **🤔 导师提问**：`cancelled` 标志是 React 处理竞态的经典方案。但还有另一种方案：用 `AbortController` 真正取消网络请求（axios 支持 `signal` 参数）。`cancelled` 标志只是"丢弃结果"，请求本身还是发出了；`AbortController` 则可以从浏览器层面取消请求。在什么场景下，"只丢弃结果"不够用，必须真正取消请求？

### 4. React.memo 防止渲染循环

> 【性能陷阱】`RenderPreviewDialog` 用 `React.memo` 包裹，原因如下：

```
父组件 TemplatesPage 重渲染（如列表加载完成）
    ↓
所有子组件默认重渲染（包括 RenderPreviewDialog）
    ↓
Dialog 的 onOpenChange 触发 → 又重渲染 → 循环
    ↓
React.memo 打断循环：props 没变就不重渲染
```

但光用 `React.memo` 还不够 —— 如果 `onOpenChange` 每次渲染都是新函数引用，memo 会失效。所以还需要 `useCallback`：

```tsx
const handlePreviewOpenChange = useCallback((open: boolean) => {
  if (!open) setPreviewTemplate(null)
}, [])
```

### 5. 任务轮询机制

任务管理页面实现了简单的**前端轮询**来追踪异步任务：

```
创建异步渲染任务
    ↓
setPollingJobId(jobId)
    ↓
useEffect 启动 setInterval(3s)
    ↓
GET /api/print/jobs/{id} → 检查 status
    ↓
status === Completed → toast.success + 刷新列表
status === Failed → toast.error + 显示 errorMessage
status === Queued/Processing → 继续轮询
```

**ASP.NET Core 类比**：这类似 `IHostedService` 中 `while (!token.IsCancellationRequested) { await Task.Delay(3000); ... }` 的轮询模式。生产环境中更推荐用 SignalR 推送，但轮询作为兜底方案始终存在。

> **🤔 导师提问**：任务轮询的 `setInterval` 在 `useEffect` 中创建，清理函数中 `clearInterval`。但如果用户在轮询期间切换到其他页面（组件卸载），`clearInterval` 会在清理函数中执行。这和 ASP.NET Core 中 `IHostedService.StopAsync` 被调用的场景类似。想想看：如果 `clearInterval` 没有在清理函数中调用，组件卸载后会发生什么？`setJobs()` 还能执行吗？

> 【设计取舍】3 秒是轮询频率的经验值。太短（<1s）给后端造成压力，太长（>10s）用户体验差。如果后端是 Kubernetes 集群，频繁轮询还可能影响 HPA 的 CPU 阈值判定。

### 6. 延迟释放 Object URL

> 【性能陷阱】PDF 预览时，`URL.createObjectURL` 创建的 URL 不能立即释放：

```tsx
window.open(url, "_blank")
// ❌ URL.revokeObjectURL(url)   ← 立即释放，新标签页加载失败！
setTimeout(() => URL.revokeObjectURL(url), 60000)  // ← 延迟 60s 释放
```

因为 `window.open` 只是打开新标签页，PDF 加载是异步的。如果立即调用 `revokeObjectURL`，浏览器还没来得及读取 Blob 数据，URL 就失效了。60 秒是经验值 —— 一般 PDF 加载不会超过 60 秒，加载完成后释放也不影响已加载的内容。

而对于 XLSX/DOCX/CSV 等下载文件，`a.click()` 是同步触发下载，可以立即释放：

```tsx
a.click()
URL.revokeObjectURL(url)  // ✅ 下载已触发，可以立即释放
```

> **🤔 导师提问**：`URL.createObjectURL` 创建的 Blob URL 占用浏览器内存，直到 `revokeObjectURL` 才释放。PDF 预览场景延迟 60s 释放是经验值，但如果用户连续预览 10 个 PDF，就会创建 10 个未释放的 Blob URL。在大数据量场景下，你会如何优化这个内存管理策略？（提示：考虑引用计数或全局 Blob URL 管理器）

/**

/**
 * 打印模板表单对话框组件
 * 用于新建或编辑打印模板，支持配置模板名称、编码、分类、纸张大小、方向和默认数据源。
 */
function TemplateFormDialog({ open, onOpenChange, template, onSuccess }: TemplateFormDialogProps) {
  const [loading, setLoading] = useState(false)
  const [datasources, setDatasources] = useState<DataSourceConfigDto[]>([])
  const [form, setForm] = useState<CreateTemplateInput & UpdateTemplateInput>({
    name: "",
    code: "",
    description: "",
    category: "",
    tags: "",
    paperSize: "A4",
    orientation: "Portrait",
    defaultDataSourceConfigId: null,
  })

  useEffect(() => {
    if (open) {
      datasourcesApi.list({ isActive: true, maxResultCount: 100 }).then((res) => {
        setDatasources(res.data?.items ?? [])
      }).catch(() => {})
    }
  }, [open])

  useEffect(() => {
    if (template) {
      setForm({
        name: template.name,
        code: template.code ?? "",
        description: template.description ?? "",
        category: template.category ?? "",
        tags: template.tags ?? "",
        paperSize: template.paperSize ?? "A4",
        orientation: template.orientation ?? "Portrait",
        defaultDataSourceConfigId: template.defaultDataSourceConfigId ?? null,
      })
    } else {
      setForm({
        name: "",
        code: "",
        description: "",
        category: "",
        tags: "",
        paperSize: "A4",
        orientation: "Portrait",
        defaultDataSourceConfigId: null,
      })
    }
  }, [template, open])

  const handleSubmit = async () => {
    if (!form.name.trim()) {
      toast.error("请输入模板名称")
      return
    }
    setLoading(true)
    try {
      if (template) {
        const updateData: UpdateTemplateInput = { name: form.name }
        if (form.code) updateData.code = form.code
        if (form.description) updateData.description = form.description
        if (form.category) updateData.category = form.category
        if (form.tags) updateData.tags = form.tags
        if (form.paperSize) updateData.paperSize = form.paperSize
        if (form.orientation) updateData.orientation = form.orientation
        updateData.defaultDataSourceConfigId = form.defaultDataSourceConfigId || null
        await templatesApi.update(template.id, updateData)
        toast.success("模板已更新")
      } else {
        const createData: CreateTemplateInput = { name: form.name }
        if (form.code) createData.code = form.code
        if (form.description) createData.description = form.description
        if (form.category) createData.category = form.category
        if (form.tags) createData.tags = form.tags
        if (form.paperSize) createData.paperSize = form.paperSize
        if (form.orientation) createData.orientation = form.orientation
        await templatesApi.create(createData)
        toast.success("模板已创建")
      }
      onSuccess()
      onOpenChange(false)
    } catch {
      toast.error(template ? "更新模板失败" : "创建模板失败")
    } finally {
      setLoading(false)
    }
  }

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="max-w-lg">
        <DialogHeader>
          <DialogTitle>{template ? "编辑模板" : "创建模板"}</DialogTitle>
        </DialogHeader>
        <div className="space-y-4 py-2">
          <div className="space-y-2">
            <Label>模板名称 *</Label>
            <Input
              value={form.name}
              onChange={(e) => setForm({ ...form, name: e.target.value })}
              placeholder="如：采购订单"
            />
          </div>
          <div className="space-y-2">
            <Label>模板编码</Label>
            <Input
              value={form.code}
              onChange={(e) => setForm({ ...form, code: e.target.value })}
              placeholder="唯一标识，如 PO-001"
            />
          </div>
          <div className="space-y-2">
            <Label>分类</Label>
            <Input
              value={form.category}
              onChange={(e) => setForm({ ...form, category: e.target.value })}
              placeholder="如：采购、销售、财务"
            />
          </div>
          <div className="space-y-2">

// ── 渲染预览对话框 ────────────────────────────────────────────────────────

interface RenderPreviewDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  template: ReportTemplateListDto | null
}

function RenderPreviewDialog({ open, onOpenChange, template }: RenderPreviewDialogProps) {
  const [loading, setLoading] = useState(false)
  const [datasources, setDatasources] = useState<DataSourceConfigDto[]>([])
  const [selectedDsId, setSelectedDsId] = useState<string>("__none__")
  const [format, setFormat] = useState<ExportFormat>(EXPORT_FORMAT.PDF)
  const [directData, setDirectData] = useState("")
  const [xmlData, setXmlData] = useState("")
  const [params, setParams] = useState<Record<string, string>>({})
  const [paramDefs, setParamDefs] = useState<Array<{ name: string; type?: string; required?: boolean; defaultValue?: string }>>([])

  const templateId = open ? template?.id : null
  useEffect(() => {
    if (!templateId || !template) return

    let cancelled = false
    datasourcesApi.list({ isActive: true, maxResultCount: 100 }).then((res) => {
      if (cancelled) return
      const list = res.data?.items ?? []
      setDatasources(list)
      // 自动选中模板的默认数据源
      if (template.defaultDataSourceConfigId) {
        setSelectedDsId(template.defaultDataSourceConfigId)
        const ds = list.find((d) => d.id === template.defaultDataSourceConfigId)
        if (ds?.parameterDefinitions) {
          try {
            const defs = JSON.parse(ds.parameterDefinitions)
            setParamDefs(defs)
            const initial: Record<string, string> = {}
            for (const p of defs) initial[p.name] = p.defaultValue ?? ""
            setParams(initial)
          } catch { setParamDefs([]) }
        }
      }
    }).catch(() => {})

    return () => { cancelled = true }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [templateId])

  const handleDsChange = (dsId: string) => {
    setSelectedDsId(dsId)
    if (dsId === "__none__" || dsId === "__direct__") {
      setParamDefs([])
      setParams({})
      return
    }
    const ds = datasources.find((d) => d.id === dsId)
    if (ds?.parameterDefinitions) {
      try {
        const defs = JSON.parse(ds.parameterDefinitions)
        setParamDefs(defs)
        const initial: Record<string, string> = {}
        for (const p of defs) initial[p.name] = p.defaultValue ?? ""
        setParams(initial)
      } catch { setParamDefs([]); setParams({}) }
    } else {
      setParamDefs([])
      setParams({})
    }
  }

  // Check if the selected datasource is XML type
  const selectedDs = datasources.find((d) => d.id === selectedDsId)
  const isXmlDs = selectedDs?.type === DATA_SOURCE_TYPE.Xml

  const handleRender = async () => {
    if (!template) return
    setLoading(true)
    try {
      const input: Record<string, unknown> = {
        templateId: template.id,
        format,
        async: true,
      }
      if (selectedDsId === "__direct__") {
        if (directData.trim()) {
          try {
            input.directData = JSON.parse(directData)
          } catch {
            toast.error("直传数据 JSON 格式错误")
            setLoading(false)
            return
          }
        }
      } else if (selectedDsId !== "__none__") {
        input.dataSourceConfigId = selectedDsId
        const mergedParams: Record<string, string> = { ...params }
        // For XML data sources, inject __xml_data into parameters
        if (isXmlDs && xmlData.trim()) {
          mergedParams["__xml_data"] = xmlData
        }
        if (Object.keys(mergedParams).length > 0) {
          input.parameters = mergedParams
        }
      }

      const res = await jobsApi.render(input as unknown as import("@/types").RenderReportInput)

      // 异步模式：返回 { jobId, status }，渲染完成后站内通知
      if (input.async) {
        const jobId = (res.data as { jobId?: string })?.jobId
        toast.success(`渲染任务已提交${jobId ? `（${jobId.slice(0, 8)}...）` : ""}，完成后将通知您`)
        onOpenChange?.(false)
        return
      }

      // 同步模式：blob download / preview（backward compat）
      const rawBlob = res.data as BlobPart
      // 如果返回的 Blob 太小或类型为 JSON，可能是后端错误响应
      if (rawBlob instanceof Blob && rawBlob.size < 100 && rawBlob.type?.includes('json')) {
        const text = await rawBlob.text()
        try {
          const json = JSON.parse(text)
          throw new Error(json.message || json.title || '渲染失败')
        } catch (e) {
          if (e instanceof SyntaxError) throw new Error('渲染返回异常数据')
          throw e
        }
      }
      const mimeMap: Record<number, string> = {
        [EXPORT_FORMAT.PDF]: "application/pdf",
        [EXPORT_FORMAT.XLSX]: "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        [EXPORT_FORMAT.DOCX]: "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
        [EXPORT_FORMAT.HTML]: "text/html",
        [EXPORT_FORMAT.PNG]: "image/png",
        [EXPORT_FORMAT.CSV]: "text/csv",
      }
      const blob = new Blob([res.data as BlobPart], { type: mimeMap[format] ?? "application/octet-stream" })
      const url = URL.createObjectURL(blob)

      if (format === EXPORT_FORMAT.PDF || format === EXPORT_FORMAT.HTML || format === EXPORT_FORMAT.PNG) {
        // Open in new tab for preview
        window.open(url, "_blank")
        // 延迟释放 Object URL，给新标签页足够时间加载
        setTimeout(() => URL.revokeObjectURL(url), 60000)
      } else {
        // Download
        const a = document.createElement("a")
        const extMap: Record<number, string> = {
          [EXPORT_FORMAT.PDF]: "pdf",
          [EXPORT_FORMAT.XLSX]: "xlsx",
          [EXPORT_FORMAT.DOCX]: "docx",
          [EXPORT_FORMAT.HTML]: "html",
          [EXPORT_FORMAT.PNG]: "png",
          [EXPORT_FORMAT.CSV]: "csv",
        }
        const ext = extMap[format] ?? "pdf"
        a.href = url
        a.download = `${template.name}.${ext}`
        a.click()
        URL.revokeObjectURL(url)
      }
      toast.success("渲染完成")
    } catch (err: any) {
      const msg = err?.response?.data?.message || err?.message || "渲染预览失败"
      toast.error(msg)
    } finally {
      setLoading(false)
    }
  }

  return (
    <Dialog key={template?.id ?? 'empty'} open={open} onOpenChange={onOpenChange}>
      <DialogContent className="max-w-lg max-h-[85vh] overflow-y-auto">
        <DialogHeader>
          <DialogTitle>渲染预览 — {template?.name}</DialogTitle>
        </DialogHeader>
        <div className="space-y-4 py-2">
          <div className="space-y-2">
            <Label>数据源</Label>
            <Select value={selectedDsId} onValueChange={handleDsChange}>
              <SelectTrigger>
                <SelectValue placeholder="选择数据源" />
              </SelectTrigger>
              <SelectContent>
                <SelectItem value="__none__">无数据（空渲染）</SelectItem>
                <SelectItem value="__direct__">直传 JSON 数据</SelectItem>
                {datasources.map((ds) => (

/**
 * 打印任务管理页面
 * 展示打印渲染任务列表，支持创建新渲染任务、轮询异步任务状态、下载已完成的报表文件。
 */
export default function JobsPage() {
  const [jobs, setJobs] = useState<PrintJobDto[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [pageSize, setPageSize] = useState(20)
  const [loading, setLoading] = useState(false)
  const [statusFilter, setStatusFilter] = useState<string>("")
  const [filterValues, setFilterValues] = useState<Record<string, string>>({ status: "all" })

  const [renderOpen, setRenderOpen] = useState(false)
  const [pollingJobId, setPollingJobId] = useState<string | null>(null)

  const loadJobs = useCallback(async () => {
    setLoading(true)
    try {
      const res = await jobsApi.list({
        status: statusFilter ? Number(statusFilter) : undefined,
        skipCount: (page - 1) * pageSize,
        maxResultCount: pageSize,
      })
      setJobs(res.data?.items ?? [])
      setTotal(res.data?.totalCount ?? 0)
    } catch {
      toast.error("加载任务列表失败")
    } finally {
      setLoading(false)
    }
  }, [statusFilter, page, pageSize])

  useEffect(() => {
    loadJobs()
  }, [loadJobs])

  // 轮询处理中的异步任务
  useEffect(() => {
    if (!pollingJobId) return
    const timer = setInterval(async () => {
      try {
        const res = await jobsApi.detail(pollingJobId)
        const job = res.data
        if (job && job.status !== PRINT_JOB_STATUS.Processing && job.status !== PRINT_JOB_STATUS.Queued) {
          setPollingJobId(null)
          loadJobs()
          if (job.status === PRINT_JOB_STATUS.Completed) {
            toast.success(`任务 ${pollingJobId.slice(0, 8)}... 渲染完成`)
          } else if (job.status === PRINT_JOB_STATUS.Failed) {
            toast.error(`任务 ${pollingJobId.slice(0, 8)}... 渲染失败: ${job.errorMessage}`)
          }
        }
      } catch {
        setPollingJobId(null)
      }
    }, 3000)
    return () => clearInterval(timer)
  }, [pollingJobId, loadJobs])

  const handleDownload = async (job: PrintJobDto) => {
    if (job.status !== PRINT_JOB_STATUS.Completed) {
      toast.error("任务尚未完成，无法下载")
      return
    }
    try {
      const res = await jobsApi.download(job.id)
      const rawBlob = res.data as BlobPart
      if (rawBlob instanceof Blob && rawBlob.type?.includes('json')) {
        const text = await rawBlob.text()
        try {
          const json = JSON.parse(text)
          throw new Error(json.message || json.title || '下载失败')
        } catch (e) {
          if (e instanceof SyntaxError) throw new Error('下载返回异常数据')
          throw e
        }
      }
      const blob = new Blob([rawBlob])
      const url = URL.createObjectURL(blob)
      const a = document.createElement("a")
      a.href = url
      const ext = EXPORT_FORMAT_LABELS[job.exportFormat]?.toLowerCase() ?? "pdf"
      a.download = `${job.templateName}.${ext}`
      a.click()
      URL.revokeObjectURL(url)
    } catch (err: any) {
      const msg = err?.message || "下载失败"
      toast.error(msg)
    }
  }

  const statusBadge = (status: number) => {
    const label = PRINT_JOB_STATUS_LABELS[status as keyof typeof PRINT_JOB_STATUS_LABELS] ?? "未知"
    let variant: "default" | "secondary" | "outline" | "destructive" = "secondary"
    if (status === PRINT_JOB_STATUS.Completed) variant = "default"
    else if (status === PRINT_JOB_STATUS.Failed) variant = "destructive"
    else if (status === PRINT_JOB_STATUS.Processing) variant = "outline"
    return <Badge variant={variant}>{label}</Badge>
  }

  const columns: AgColumn<PrintJobDto>[] = [
    {
      field: "templateName",
      headerName: "模板名称",
      flex: 1,
      minWidth: 140,
      cellRenderer: ({ data: record }) => (
        <div className="font-medium">{record.templateName}</div>
      ),
    },
    {
      field: "exportFormat",
      headerName: "格式",
      width: 80,
      cellRenderer: ({ data: record }) =>
        <>{EXPORT_FORMAT_LABELS[record.exportFormat as ExportFormat] ?? record.exportFormat}</>,
    },
    {
      field: "status",
      headerName: "状态",
      width: 100,
      cellRenderer: ({ data: record }) => statusBadge(record.status),
    },
    {
      field: "outputSizeBytes",
      headerName: "文件大小",
      width: 100,
      cellRenderer: ({ data: record }) =>
        <>{record.outputSizeBytes != null ? formatBytes(record.outputSizeBytes) : "-"}</>,
    },
    {
      field: "creationTime",
      headerName: "创建时间",
      width: 160,
      cellRenderer: ({ data: record }) =>
        <>{new Date(record.creationTime).toLocaleString("zh-CN")}</>,
    },
    {
      field: "completedAt",
      headerName: "完成时间",
      width: 160,
      cellRenderer: ({ data: record }) =>
        <>{record.completedAt ? new Date(record.completedAt).toLocaleString("zh-CN") : "-"}</>,
    },
    {
      field: "errorMessage",
      headerName: "错误信息",
      width: 200,
      cellRenderer: ({ data: record }) =>
        record.errorMessage ? (
          <span className="text-destructive text-sm" title={record.errorMessage}>
            {record.errorMessage.length > 30 ? record.errorMessage.slice(0, 30) + "..." : record.errorMessage}
          </span>
        ) : <>-</>,
    },
    {
      field: "__actions__",
      headerName: "操作",
      width: 100,
      pinned: "right",
      cellRenderer: ({ data: record }) => (
        <div className="flex items-center gap-1">
          {(record.status === PRINT_JOB_STATUS.Processing || record.status === PRINT_JOB_STATUS.Queued) && (
            <Button
              variant="ghost"
              size="sm"
              onClick={() => setPollingJobId(record.id)}
              title="轮询状态"
            >
              <RefreshCw className="h-3.5 w-3.5" />
            </Button>
          )}
          {record.status === PRINT_JOB_STATUS.Completed && (
            <Button
              variant="ghost"
              size="sm"
              onClick={() => handleDownload(record)}
              title="下载"
            >
              <Download className="h-3.5 w-3.5" />
            </Button>
          )}
        </div>
      ),
    },
  ]

  return (
    <div className="flex flex-col h-full">
      <PageToolbar
        title="打印任务"
        actions={
          <>
            <ToolbarButton icon={Play} variant="primary" onClick={() => setRenderOpen(true)}>
              渲染报表
            </ToolbarButton>
            <ToolbarButton icon={RefreshCw} onClick={loadJobs}>
              刷新
            </ToolbarButton>
          </>
        }
      />

      {/* 筛选栏 */}
      <QueryFilter
        fields={[
          {
            key: "status",
            label: "状态",
            type: "select",
            options: [
              { value: String(PRINT_JOB_STATUS.Queued), label: "排队中" },
              { value: String(PRINT_JOB_STATUS.Processing), label: "处理中" },
              { value: String(PRINT_JOB_STATUS.Completed), label: "已完成" },
              { value: String(PRINT_JOB_STATUS.Failed), label: "失败" },
            ],
          },
        ]}
        values={filterValues}
        onValuesChange={setFilterValues}
        onSearch={() => { setStatusFilter(filterValues.status ?? "all"); setPage(1) }}
        onReset={() => { setFilterValues({ status: "all" }); setStatusFilter("all"); setPage(1) }}
      />

      {/* 数据表格 */}
      <AgTable
        columns={columns}
        data={jobs}
        total={total}
        page={page}
        pageSize={pageSize}
        onPageChange={setPage}
        onPageSizeChange={(s) => { setPageSize(s); setPage(1) }}
        loading={loading}
        rowKey="id"
      />

      {/* 渲染对话框 */}
      <RenderDialog
        open={renderOpen}
        onOpenChange={setRenderOpen}
        onSuccess={loadJobs}
      />
    </div>
  )
}

### TemplatesPage 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `const fileInputRef = useRef<HTMLInputElement>(null)` | 隐藏文件上传 input 的引用 | 文件上传用隐藏 `<input type="file">` + `ref.click()` 触发，而非直接展示 input。这是 React 文件上传的通用模式，ASP.NET Core 中类似 `IFormFile` 的隐藏字段 |
| `if (fileInputRef.current) fileInputRef.current.value = ""` | 导入后重置 input | 【易错点】选择同一文件时 `onChange` 不会触发！必须重置 `value` 才能再次选择。这是浏览器 `<input type="file">` 的已知行为 |
| `window.open(\`/_fr/designer.index?reportId=${record.id}\`, "_blank")` | 跳转设计器 | FastReport 在线设计器是独立部署的 Web 应用，通过 `/_fr/` 前缀访问。前端只负责跳转，不嵌入设计器 |
| `{record.status !== TEMPLATE_STATUS.Published && ... Send ...}` | 条件操作按钮 | 【易错点】草稿和已归档状态显示"发布"按钮；已发布状态显示"归档"按钮。通过条件渲染实现状态机的 UI 约束，类似 ASP.NET Core 中 `Authorize` 特性约束操作权限 |
| `await templatesApi.import(file)` | 导入 .frx 文件 | 模板导入发送 `FormData`（含 .frx 文件），这需要 axios 实例的 `responseType` 配置。所以 API 层需要用 `printHttp.instance` 而非封装的 `post` 方法 |
| `await templatesApi.publish(publishConfirm.id)` | 发布模板 | 发布操作触发后端状态机流转：`Draft → Published`。已发布模板才能被任务引用渲染 |
| `await templatesApi.archive(archiveConfirm.id)` | 归档模板 | 归档触发：`Published → Archived`。归档后模板不可用于新任务，但已有任务不受影响 |

### TemplateFormDialog 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `datasourcesApi.list({ isActive: true, maxResultCount: 100 })` | 加载活跃数据源 | 对话框打开时加载，只取启用状态的数据源供选择。`maxResultCount: 100` 是上限值，实际项目中数据源数量通常不超过这个范围 |
| `value={form.defaultDataSourceConfigId ?? "__none__"}` | Select 哨兵值 | 【易错点】`Select` 组件不接受 `null` 作为 value，必须用 `"__none__"` 哨兵值代替。在 `onValueChange` 中转换回 `null`：`v === "__none__" ? null : v` |
| `updateData.defaultDataSourceConfigId = form.defaultDataSourceConfigId \|\| null` | 空字符串转 null | 【易错点】空字符串 `""` 在 JavaScript 中是 falsy，但后端期望 `null` 表示"未关联"。用 `\|\|` 确保 falsy 值统一转为 `null` |

### RenderPreviewDialog 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `const templateId = open ? template?.id : null` | 条件取 ID | 【性能陷阱】只在对话框打开时取 templateId 作为 useEffect 依赖。关闭时设为 null，避免不必要的 API 调用 |
| `let cancelled = false; ... return () => { cancelled = true }` | 竞态条件保护 | 【易错点】快速切换模板时，前一个请求可能后返回。`cancelled` 标志确保过时的响应不会更新状态。这是 React useEffect + 异步请求的标准模式，相当于 ASP.NET Core 的 `CancellationToken` |
| `if (rawBlob instanceof Blob && rawBlob.size < 100 && rawBlob.type?.includes('json'))` | Blob 错误检测 | 【易错点】后端可能返回 HTTP 200 但 body 是 JSON 错误。检测方式：Blob 体积过小 + Content-Type 是 JSON → 解析为错误 |
| `setTimeout(() => URL.revokeObjectURL(url), 60000)` | 延迟释放 Object URL | 【性能陷阱】新标签页打开 PDF 需要时间加载。如果立即 `revokeObjectURL`，PDF 无法显示。60s 延迟是经验值，确保加载完成后再释放内存 |
| `const RenderPreviewDialogMemo = React.memo(RenderPreviewDialog)` | 记忆化组件 | 【性能陷阱】不使用 memo 会导致：列表数据更新 → 父组件重渲染 → Dialog props 引用变化（即使值没变）→ Dialog 重渲染 → onOpenChange 触发 → 无限循环 |
| `const handlePreviewOpenChange = useCallback(...)` | 回调记忆化 | 必须配合 `React.memo` 使用。如果 `onOpenChange` 每次都是新函数引用，memo 的浅比较会判定 props 变化，导致 memo 失效 |

### JobsPage 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `const timer = setInterval(async () => { ... }, 3000)` | 轮询间隔 3 秒 | 【设计取舍】3 秒是轮询频率的经验值。太短（<1s）给后端造成压力，太长（>10s）用户体验差。生产环境建议用 SignalR 推送替代 |
| `return () => clearInterval(timer)` | 清理定时器 | 【易错点】useEffect 返回的清理函数在组件卸载或依赖变化时执行。必须清理 setInterval，否则组件卸载后定时器仍在执行，造成内存泄漏和状态更新错误 |
| `if (job && job.status !== PRINT_JOB_STATUS.Processing && job.status !== PRINT_JOB_STATUS.Queued)` | 终止轮询条件 | 任务离开"进行中"状态（完成或失败）就停止轮询。如果后端返回 null（任务不存在），也停止轮询 |
| `setPollingJobId(null); loadJobs()` | 先停轮询再刷新 | 先将 `pollingJobId` 置 null 触发 useEffect 清理（停止 setInterval），再调用 `loadJobs()` 刷新列表。顺序不能反 —— 否则新数据加载后轮询可能重置 |
| `{record.outputSizeBytes != null ? formatBytes(record.outputSizeBytes) : "-"}` | 文件大小格式化 | `!= null` 同时排除 `null` 和 `undefined`（双等号的唯一合理用途）。0 字节时显示 `0 B` 而非 `-` |
| `templatesApi.list({ status: TEMPLATE_STATUS.Published, ... })` | 只加载已发布模板 | RenderDialog 中的模板列表只包含 `Published` 状态的模板。草稿和已归档的模板不能用于渲染 —— 这是后端业务规则，前端通过筛选 API 参数配合 |

### RenderDialog vs RenderPreviewDialog 的区别

| 维度 | RenderDialog（任务页） | RenderPreviewDialog（模板页） |
|---|---|---|
| 模板选择 | 下拉选择已发布模板 | 从模板列表直接传入，不可切换 |
| 数据源选择 | 无 | 三种模式：无/直传JSON/关联数据源 |
| 参数输入 | 无 | 动态参数表单 |
| 异步开关 | 有（checkbox） | 默认 async=true，无开关 |
| 文件处理 | 全部下载 | PDF/HTML/PNG 新标签预览，其他下载 |

> **🔍 验证步骤**
