# 04 - 数据源管理页面

> **这一步解决什么问题？** 我们要实现打印服务中交互最复杂的页面——数据源管理。它需要根据四种数据源类型（JSON / HTTP API / Database / XML）动态渲染不同的表单字段，还提供连接测试和数据预览两个独特操作。这是 React 条件渲染的经典实战场景。

---

## 前置知识

- React 条件渲染（`{condition && <Component />}`）
- `useState` + `useEffect` + `useCallback` 的组合模式
- `AgTable`、`PageToolbar`、`QueryFilter`、`ConfirmDialog` 共享组件的用法
- 数据源四种类型（JSON / HTTP API / Database / XML）的业务含义
- `datasourcesApi` 的方法列表（上一节已实现）

---

interface PreviewDialogProps {
  open: boolean
  onOpenChange: (open: boolean) => void
  datasource: DataSourceConfigDto | null
}

/**
 * 数据预览对话框组件
 * 预览数据源的数据输出，支持输入运行时参数和 XML 数据。
 */
function PreviewDataDialog({ open, onOpenChange, datasource }: PreviewDialogProps) {
  const [loading, setLoading] = useState(false)
  const [data, setData] = useState<unknown>(null)
  const [error, setError] = useState<string | null>(null)
  const [params, setParams] = useState<Record<string, string>>({})
  const [xmlData, setXmlData] = useState("")

  const isXml = datasource?.type === DATA_SOURCE_TYPE.Xml

  // 解析参数定义
  const paramDefs = (() => {
    if (!datasource?.parameterDefinitions) return []
    try {
      return JSON.parse(datasource.parameterDefinitions) as Array<{
        name: string
        type?: string
        required?: boolean
        defaultValue?: string
      }>
    } catch {
      return []
    }
  })()

  useEffect(() => {
    if (open) {
      setData(null)
      setError(null)
      setXmlData("")
      const initial: Record<string, string> = {}
      for (const p of paramDefs) {
        initial[p.name] = p.defaultValue ?? ""
      }
      setParams(initial)
    }
    // eslint-disable-next-line react-hooks/exhaustive-deps
  }, [open, datasource?.id])

  const handlePreview = async () => {
    if (!datasource) return
    setLoading(true)
    setError(null)
    try {
      const mergedParams: Record<string, string> = { ...params }
      // Inject __xml_data for XML data sources
      if (isXml && xmlData.trim()) {
        mergedParams["__xml_data"] = xmlData
      }
      const res = await datasourcesApi.previewData(
        datasource.id,
        Object.keys(mergedParams).length > 0 ? mergedParams : undefined
      )
      setData(res.data)
    } catch {
      setError("预览数据失败")
    } finally {
      setLoading(false)
    }
  }

  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent className="max-w-3xl max-h-[85vh] overflow-y-auto">
        <DialogHeader>
          <DialogTitle>数据预览 — {datasource?.name}</DialogTitle>
        </DialogHeader>
        <div className="space-y-4 py-2">
          {isXml && (
            <div className="space-y-2">
              <Label>XML 数据</Label>
              <Textarea
                value={xmlData}
                onChange={(e) => setXmlData(e.target.value)}
                placeholder={'<Orders>\n  <Order>\n    <Id>PO-001</Id>\n    <Amount>1000</Amount>\n  </Order>\n</Orders>'}
                rows={6}
                className="font-mono text-sm"
              />
              <p className="text-xs text-muted-foreground">输入 XML 数据进行预览，留空则返回空数据集</p>
            </div>
          )}
          {paramDefs.length > 0 && (
            <div className="space-y-3">
              <Label className="text-muted-foreground">运行时参数</Label>
              <div className="grid grid-cols-2 gap-3">
                {paramDefs.map((p) => (
                  <div key={p.name} className="space-y-1">
                    <Label className="text-sm">
                      {p.name}
                      {p.required && <span className="text-destructive"> *</span>}
                    </Label>
                    <Input
                      value={params[p.name] ?? ""}
                      onChange={(e) =>
                        setParams((prev) => ({ ...prev, [p.name]: e.target.value }))
                      }
                      placeholder={p.type ?? "string"}
                    />
                  </div>
                ))}
              </div>
            </div>
          )}
          <Button onClick={handlePreview} disabled={loading}>
            {loading ? "加载中..." : "获取数据"}
          </Button>
          {error && <p className="text-sm text-destructive">{error}</p>}
          {data !== null && (
            <pre className="bg-muted rounded-md p-4 text-sm overflow-auto max-h-96 font-mono">
              {typeof data === "string" ? data : JSON.stringify(data, null, 2)}
            </pre>
          )}
        </div>
        <DialogFooter>
          <Button variant="outline" onClick={() => onOpenChange(false)}>
            关闭
          </Button>
        </DialogFooter>
      </DialogContent>
    </Dialog>
  )
}

/**
 * 数据源管理页面
 * 管理打印报表的数据源配置，支持 JSON、HTTP API、Database、XML 四种类型。
 * 提供数据源的创建、编辑、删除、连接测试和数据预览功能。
 */
export default function DatasourcesPage() {
  const [datasources, setDatasources] = useState<DataSourceConfigDto[]>([])
  const [total, setTotal] = useState(0)
  const [page, setPage] = useState(1)
  const [pageSize, setPageSize] = useState(20)
  const [loading, setLoading] = useState(false)
  const [keyword, setKeyword] = useState("")
  const [typeFilter, setTypeFilter] = useState<string>("")
  const [activeFilter, setActiveFilter] = useState<string>("")
  const [filterValues, setFilterValues] = useState<Record<string, string>>({ keyword: "", type: "all", status: "all" })

  // 对话框状态
  const [formOpen, setFormOpen] = useState(false)
  const [editingDs, setEditingDs] = useState<DataSourceConfigDto | null>(null)
  const [deleteConfirm, setDeleteConfirm] = useState<DataSourceConfigDto | null>(null)

  // 测试连接
  const [testOpen, setTestOpen] = useState(false)
  const [testLoading, setTestLoading] = useState(false)
  const [testResult, setTestResult] = useState<{ success: boolean; message: string } | null>(null)

  // 数据预览
  const [previewOpen, setPreviewOpen] = useState(false)
  const [previewDs, setPreviewDs] = useState<DataSourceConfigDto | null>(null)

  const loadDatasources = useCallback(async () => {
    setLoading(true)
    try {
      const res = await datasourcesApi.list({
        keyword: keyword || undefined,
        type: typeFilter ? Number(typeFilter) : undefined,
        isActive: activeFilter === "" ? undefined : activeFilter === "true",
        skipCount: (page - 1) * pageSize,
        maxResultCount: pageSize,
      })
      setDatasources(res.data?.items ?? [])
      setTotal(res.data?.totalCount ?? 0)
    } catch {
      toast.error("加载数据源列表失败")
    } finally {
      setLoading(false)
    }
  }, [keyword, typeFilter, activeFilter, page, pageSize])

  useEffect(() => {
    loadDatasources()
  }, [loadDatasources])

  const handleCreate = () => {
    setEditingDs(null)
    setFormOpen(true)
  }

  const handleEdit = (ds: DataSourceConfigDto) => {
    setEditingDs(ds)
    setFormOpen(true)
  }

  const handleDelete = async () => {
    if (!deleteConfirm) return
    try {
      await datasourcesApi.delete(deleteConfirm.id)
      toast.success("数据源已删除")
      loadDatasources()
    } catch {
      toast.error("删除数据源失败")
    } finally {
      setDeleteConfirm(null)
    }
  }

  const handleTestConnection = async (ds: DataSourceConfigDto) => {
    setTestResult(null)
    setTestLoading(true)
    setTestOpen(true)
    try {
      const res = await datasourcesApi.testConnection(ds.id)
      setTestResult(res.data ?? { success: false, message: "无响应" })
    } catch {
      setTestResult({ success: false, message: "请求失败" })
    } finally {
      setTestLoading(false)
    }
  }

  const handlePreview = (ds: DataSourceConfigDto) => {
    setPreviewDs(ds)
    setPreviewOpen(true)

## 代码讲解

数据源管理页面是打印服务中**交互最复杂**的页面 —— 因为它要处理四种不同类型的数据源，每种类型有不同的配置字段。

在 ASP.NET Core 中，这种情况通常用 **策略模式** 处理：定义 `IDataSourceStrategy` 接口，每种类型一个实现类。React 中我们用**条件渲染**（Conditional Rendering）来实现类似效果：

```
ASP.NET Core 策略模式:              React 条件渲染:
IDataSourceStrategy                 {form.type === DATA_SOURCE_TYPE.Json && <JsonFields />}
├── JsonDataSourceStrategy          {form.type === DATA_SOURCE_TYPE.HttpApi && <HttpFields />}
├── HttpApiDataSourceStrategy       {form.type === DATA_SOURCE_TYPE.Database && <DbFields />}
├── DatabaseDataSourceStrategy      {form.type === DATA_SOURCE_TYPE.Xml && <XmlFields />}
└── XmlDataSourceStrategy
```

> **核心区别**：策略模式在运行时通过多态选择实现；React 条件渲染通过 JSX 的 `&&` 运算符选择渲染哪个子树。本质相同 —— **根据类型选择不同行为**。

> **🤔 导师提问**：ASP.NET Core 中，`IDataSourceStrategy` 的每个实现类是独立的，修改一种数据源的逻辑不会影响其他类型。但当前页面把四种类型的条件渲染都写在同一个 `DatasourceFormDialog` 里。如果未来新增第 5 种数据源类型，你需要改哪些地方？这和策略模式的"开闭原则"有什么差距？

### 页面结构

数据源管理页面由四个组件组成：

```
DatasourcesPage（主页面）
├── PageToolbar + QueryFilter（工具栏 + 筛选）
├── AgTable（数据表格）
├── DatasourceFormDialog（创建/编辑表单对话框）
│   ├── 通用字段（name, code, type, isActive, parameterDefinitions）
│   └── 条件字段（根据 type 切换）
├── TestResultDialog（连接测试结果对话框）
└── PreviewDataDialog（数据预览对话框）
```

### 表单状态管理

这个页面的表单状态比之前的模块更复杂，因为**不同类型需要不同的字段集合**：

```
FormState = {
  // 通用字段
  name, code, description, type, isActive, parameterDefinitions,
  // JSON 专属
  jsonSchema,
  // HTTP API 专属
  httpUrl, httpMethod, httpHeaders, httpAuthType, httpAuthConfig,
  // Database 专属
  dbProviderName, dbConnectionString, dbQuery,
  // XML 专属
  xmlRootElement, xmlSchema,
}
```

所有字段都放在同一个 `FormState` 中，渲染时根据 `type` 选择性显示。这种方式简单直接，适合字段不太多的场景。

> **🤔 导师提问**：所有字段都在一个 `FormState` 中意味着切换数据源类型时，旧类型的字段数据不会被清除。比如填了 HTTP URL 后切换到 JSON 类型，URL 还保留在状态里。文章后面说"提交时根据 `form.type` 只取对应字段，旧数据会被忽略"——但这种"脏数据留在内存中"的做法，在什么场景下可能引发 bug？你会在 `type` 切换时主动清理旧字段吗？

### 连接测试与数据预览

这是数据源独有的两个操作：

- **连接测试**（testConnection）：类似 ASP.NET Core 的 `IHealthCheck`，验证数据源配置是否正确
- **数据预览**（previewData）：类似 SQL Server Management Studio 的"执行查询"，返回样本数据

```
连接测试流程:                    数据预览流程:
点击"测试连接"按钮               点击"预览数据"按钮
    ↓                              ↓
POST /datasources/{id}/test    POST /datasources/{id}/preview-data
    ↓                              ↓
{ success, message }           { 未知 JSON 结构 }
    ↓                              ↓
显示成功/失败对话框              JSON.stringify 格式化展示
```

> **安全注意**：`DataSourceConfigDto` 中敏感字段（`dbConnectionString`、`httpAuthConfig`）已被后端**脱敏**，前端只能看到 `***`。编辑时如果留空，后端保持原值不变。

> **🤔 导师提问**：`testConnection` 的流程是"先保存再测试"还是"先测试再保存"？看看代码：`handleTestConnection` 接收的是已保存的数据源 `DataSourceConfigDto`，说明连接测试只能在保存后进行。但在 ASP.NET Core 中，用户通常希望"先测试连接字符串，再保存"。如果要支持"未保存时也能测试连接"，API 和前端各需要怎么改？

### DatasourceFormDialog 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `interface FormState extends CreateDataSourceInput { isActive: boolean }` | 扩展 Create 输入类型，加上 `isActive` 开关 | **【易错点】** `CreateDataSourceInput` 里没有 `isActive`，但前端表单需要这个字段。通过 `extends` 扩展而不是修改原始类型，保持 API 层和页面层解耦 |

> **🤔 导师提问**：`FormState extends CreateDataSourceInput` 继承了所有字段，包括各类型专属字段（`httpUrl`、`dbQuery` 等）。当表单处于 JSON 模式时，HTTP 和 Database 的字段仍存在于 FormState 中。相比 ASP.NET Core 中 `CreateDataSourceInput` 是后端契约、不能随意加字段，前端 `FormState` 这样"全量持有"的做法是合理的吗？如果要严格区分，你会用什么 TypeScript 技巧实现"联合类型表单"？

| `const set = (patch) => setForm((prev) => ({ ...prev, ...patch }))` | 表单局部更新辅助函数 | 避免每次都写 `setForm({ ...form, field: value })`，用对象展开（类似 C# 的 `with` 表达式）实现局部更新 |
| `{form.type === DATA_SOURCE_TYPE.Json && <JsonFields />}` | 条件渲染 | **【易错点】** 切换类型时，旧类型的表单数据不会被清除。比如填了 HTTP URL 后切换到 JSON 类型，URL 还保留在 form 状态中。但因为提交时根据 `form.type` 只取对应字段，旧数据会被忽略，不会发送到后端 |
| `if (form.dbConnectionString) data.dbConnectionString = form.dbConnectionString` | 编辑时连接字符串可选 | **【设计取舍】** 编辑模式下连接字符串可以为空，表示"保持不变"。后端只在接收到非空值时更新，空值跳过。这是脱敏字段的常见处理模式 |

### PreviewDataDialog 关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `const paramDefs = (() => { ... })()` | IIFE 解析参数定义 | 将 `parameterDefinitions`（JSON 字符串）解析为数组。使用 IIFE 而非 `useMemo` 是因为这个计算在每次渲染时都依赖 `datasource` 引用，`useMemo` 的依赖比较成本反而更高 |
| `mergedParams["__xml_data"] = xmlData` | XML 数据注入 | **【易错点】** `__xml_data` 是双下划线前缀的约定参数名。后端通过这个特殊键识别"这是 XML 数据"而非普通参数。类似 ASP.NET 的 `__RequestVerificationToken` |
| `JSON.stringify(data, null, 2)` | 格式化展示 | 返回类型是 `unknown`，直接用 `JSON.stringify` 展示最通用 |

### 主页面关键行

| 行 | 代码 | 解析 |
|---|---|---|
| `handleTestConnection` | 测试连接流程 | 先清空结果 → 设置 loading → 打开对话框 → 发请求 → 设置结果。整个流程在同一个函数中，避免状态不一致 |
| `typeBadge(type: number)` | 类型徽章渲染 | **【设计取舍】** 不同类型用不同 Badge variant，视觉上区分：HTTP API（default/实心）、Database（secondary/灰色）、其他（outline/空心） |

## 踩坑提醒

1. **切换数据源类型不会清除旧字段数据**：比如填了 HTTP URL 后切换到 JSON 类型，URL 还保留在 form 状态中。提交时根据 `form.type` 只取对应字段，旧数据会被忽略，不会发送到后端。
2. **编辑时连接字符串可以为空**：`dbConnectionString` 编辑模式下可不填，表示"保持不变"。后端只在接收到非空值时更新，空值跳过。这是脱敏字段的常见处理模式。
3. **`Select` 组件不接受 `null` 作为 value**：`isActive` 等 Switch 和 Select 控件的 value 必须是有效的字符串，不能用 `null`。
4. **`__xml_data` 是约定参数名**：双下划线前缀，后端通过这个特殊键识别 XML 数据，类似 ASP.NET 的 `__RequestVerificationToken`。
