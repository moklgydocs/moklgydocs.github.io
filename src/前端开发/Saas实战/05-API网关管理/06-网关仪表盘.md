## 这一步解决什么问题？

运维人员需要一个全局视角：网关当前有多少活跃路由？多少集群？每个集群有多少目标地址？最重要的是——修改配置后需要一个"发布"按钮让变更生效。仪表盘页面就是网关管理的"驾驶舱"。

> **后端类比**：仪表盘 ≈ ASP.NET Core 的 `/health` + `/diagnostics` 端点的可视化，"发布配置" ≈ `IOptionsMonitor<T>.Reload()` 或 K8s 的 `kubectl rollout restart`。

---

## 核心概念：配置生效的生命周期

YARP 的配置变更**不会立即生效**。完整的生命周期是：

```
1. 前端修改路由/集群/限流策略
   → 写入数据库（此时 YARP 运行时还是旧配置）

2. 运维点击"发布配置"
   → 调用 gatewayApi.reload()
   → 后端将数据库配置推送到 YARP 运行时
   → YARP 热重载，新配置生效（无需重启进程）

3. 仪表盘刷新状态
   → 调用 gatewayApi.status()
   → 显示最新的路由数、集群数
```

> **后端类比**：这和 ASP.NET Core 的 `reloadOnChange: true` 类似，只不过触发方式不同——文件监控是自动触发，我们的"发布配置"是手动触发。手动触发更可控——运维人员可以先批量修改多条配置，最后一次发布。

⚠️ **【易错点】** 忘记点"发布配置"是最常见的运维失误——改了路由但没发布，请求还是走旧路径。仪表盘用醒目的"发布配置"按钮缓解这个问题。

## 网关运行时 API

```typescript
// src/api/gateway/gateway.ts
import { post, get } from "./http"
import type { GatewayStatus } from "@/types"

/** 网关运行时管理 API，提供配置重载和状态查询功能 */
export const gatewayApi = {
  /** 重新加载网关配置（使修改的集群/路由/限流策略生效） */
  reload: () => post<object>("/api/gateway/reload"),

  /** 获取网关当前运行状态 */
  status: () => get<GatewayStatus>("/api/gateway/status"),
}
```

**后端类比**：

| 前端 API | 后端实现 | 作用 |
|----------|----------|------|
| `gatewayApi.reload()` | `IProxyConfigProvider.Reload()` | 从数据库读取最新配置，推送到 YARP 运行时 |
| `gatewayApi.status()` | 读取 YARP 的 `IProxyState` | 获取当前活跃的路由和集群信息 |

## GatewayStatus 类型详解

```typescript
/** 网关状态概览 */
export interface GatewayStatus {
  /** 当前活跃路由数 */
  routeCount: number
  /** 当前活跃集群数 */
  clusterCount: number
  /** 路由摘要列表 */
  routes: { routeId: string; clusterId: string; path: string }[]
  /** 集群摘要列表 */
  clusters: { clusterId: string; destinationCount: number }[]
}
```

**逐行理解**：

- **`routeCount` / `clusterCount`**：大数字展示在页面顶部，一眼看到网关规模。
- **`routes[]`**：不是完整的 `RouteDto`，而是精简的摘要（只有 ID、集群、路径）。【性能陷阱】不需要返回完整的 Transforms、限流策略等——仪表盘只需要概览信息。
- **`clusters[]`**：同理，精简为集群 ID + 目标数量。不返回每个 Destination 的地址和健康状态。

> **后端类比**：这和 ASP.NET Core 的 `DiagnosticListener` 返回的摘要信息一样——只返回关键指标，不返回全量数据。

## 仪表盘页面

```tsx
// src/pages/gateway/dashboard/index.tsx
import { useEffect, useState, useCallback } from "react"
import { PageHeader } from "@/components/shared/page-header"
import { AnimatedPage } from "@/components/shared/animated-page"
import { Button } from "@/components/ui/button"
import { gatewayApi } from "@/api/gateway/gateway"
import { toast } from "sonner"
import type { GatewayStatus } from "@/types"

export default function DashboardPage() {
  const [status, setStatus] = useState<GatewayStatus | null>(null)
  const [loading, setLoading] = useState(false)
  const [reloading, setReloading] = useState(false)

  /** 获取网关运行状态 */
  const fetchStatus = useCallback(async () => {
    setLoading(true)
    try {
      const res = await gatewayApi.status()
      if (res.success) setStatus(res.data ?? null)
    } catch {
      toast.error("获取网关状态失败")
    } finally {
      setLoading(false)
    }
  }, [])

  useEffect(() => { fetchStatus() }, [fetchStatus])

  /** 手动重载网关配置，将最新的集群和路由配置推送到 YARP 运行时 */
  const handleReload = async () => {
    setReloading(true)
    try {
      const res = await gatewayApi.reload()
      if (res.success) {
        toast.success("配置已重载")
        await fetchStatus() // 重载后刷新状态
      } else {
        toast.error(res.message)
      }
    } catch {
      toast.error("重载失败")
    } finally {
      setReloading(false)
    }
  }

  return (
    <AnimatedPage>
      <div className="space-y-6">
        <PageHeader title="网关仪表盘" description="查看当前 YARP 网关运行状态">
          <Button onClick={handleReload} disabled={reloading}>
            {reloading ? "重载中..." : "发布配置"}
          </Button>
        </PageHeader>

        {loading ? (
          <p className="text-muted-foreground">加载中...</p>
        ) : status ? (
          <div className="grid grid-cols-1 md:grid-cols-2 gap-6">
            {/* 活跃路由卡片 */}
            <div className="rounded-lg border p-6">
              <h3 className="text-lg font-semibold mb-2">活跃路由</h3>
              <p className="text-4xl font-bold text-primary">{status.routeCount}</p>
              <div className="mt-4 space-y-2">
                {status.routes.map((r) => (
                  <div key={r.routeId} className="flex justify-between text-sm border-b pb-1">
                    <span className="font-mono text-xs">{r.path}</span>
                    <span className="text-muted-foreground">{r.clusterId}</span>
                  </div>
                ))}
              </div>
            </div>

            {/* 集群概览卡片 */}
            <div className="rounded-lg border p-6">
              <h3 className="text-lg font-semibold mb-2">集群</h3>
              <p className="text-4xl font-bold text-primary">{status.clusterCount}</p>
              <div className="mt-4 space-y-2">
                {status.clusters.map((c) => (
                  <div key={c.clusterId} className="flex justify-between text-sm border-b pb-1">
                    <span className="font-medium">{c.clusterId}</span>
                    <span className="text-muted-foreground">{c.destinationCount} 个目标</span>
                  </div>
                ))}
              </div>
            </div>
          </div>
        ) : (
          <p className="text-muted-foreground">暂无配置数据，请先添加集群和路由后发布配置。</p>
        )}
      </div>
    </AnimatedPage>
  )
}
```

## 逐行解析

| 行 | 代码 | 解读 |
|---|---|---|
| `const [reloading, setReloading] = useState(false)` | 重载按钮防重复点击 | ⚠️ 【易错点】重载操作可能耗时数秒，期间禁用按钮防止重复请求 |
| `await fetchStatus()` after `handleReload` | 重载后立即刷新 | 💡 重载成功后刷新状态，让用户看到最新的路由/集群数量 |
| `status.routeCount` + `status.clusterCount` | 大数字卡片 | 💡 运维一眼看到网关规模——"哦，我有 15 条路由和 4 个集群" |
| `status.routes.map(r => <div>...<span>{r.path}</span><span>{r.clusterId}</span></div>)` | 路由摘要列表 | 💡 左侧路径、右侧集群 ID，快速浏览路由→集群的映射关系 |
| `{status.clusters.map(c => ...{c.destinationCount} 个目标...)}` | 集群目标数 | 💡 显示每个集群有多少后端实例，快速发现"这个集群只有一个目标？" |
| `暂无配置数据...` | 空状态提示 | 💡 新部署的网关可能没有配置，给出明确的引导文字 |

## 仪表盘的信息架构

```
┌─────────────────────────────────────────────────┐
│ 网关仪表盘                    [发布配置] 按钮     │
├─────────────────────┬───────────────────────────┤
│                     │                           │
│   活跃路由           │   集群                     │
│                     │                           │
│      15             │       4                   │
│                     │                           │
│  /api/auth/{**}     │   authserver  → 3 个目标   │
│    → authserver     │   permcenter  → 2 个目标   │
│  /api/perm/{**}     │   notifycenter→ 1 个目标   │
│    → permcenter     │   gateway     → 1 个目标   │
│  /api/notify/{**}   │                           │
│    → notifycenter   │                           │
│  ...                │                           │
│                     │                           │
└─────────────────────┴───────────────────────────┘
```

两栏布局的意图：
- **左栏**：路由视角——"每个 URL 路径转发到哪里？"
- **右栏**：集群视角——"每个集群有几个后端实例？"

运维人员可以快速发现两类问题：
1. 路由指向了错误的集群（左栏）
2. 集群只有一个目标地址，没有高可用（右栏）

## "发布配置"按钮的工作原理

```
前端点击"发布配置"
  │
  ▼
POST /gw-api/api/gateway/reload
  │
  ▼
Gateway Admin API（ASP.NET Core）
  │
  │ 1. 从数据库读取所有 Cluster、Route、RateLimitPolicy
  │ 2. 转换为 YARP 的 IProxyConfig 格式
  │ 3. 调用 IChangeToken.TriggerChange() 通知 YARP 运行时
  │
  ▼
YARP 运行时
  │
  │ 4. 收到变更通知
  │ 5. 原子替换路由表（旧请求用旧配置，新请求用新配置）
  │ 6. 无需重启进程，无停机时间
  │
  ▼
新配置生效 ✅
```

> **后端类比**：YARP 的热重载机制和 ASP.NET Core 的 `IOptionsMonitor<T>` + `reloadOnChange` 是同一套机制——`IChangeToken`。区别是触发源从"文件变更"变成了"API 调用"。

⚠️ **【易错点】** 热重载是**原子替换**——不会出现"一半路由用新配置，一半用旧配置"的情况。YARP 在替换路由表时使用 Copy-on-Write，确保并发安全。

## 监控指标（扩展方向）

当前仪表盘只展示静态概览。生产环境通常还需要以下监控指标：

| 指标 | 来源 | 后端类比 |
|------|------|----------|
| 每秒请求数（RPS） | YARP 中间件计数 | `DiagnosticListener` |
| 请求延迟 P50/P95/P99 | YARP 转发计时 | Application Insights |
| 429 响应数 | 限流中间件 | `IRateLimiter.Statistics` |
| 后端错误率 | YARP 响应状态码 | Health Check UI |
| 活跃连接数 | YARP 连接池 | `KestrelServer.Options.Limits` |

💡 **【设计取舍】** 这些指标通常用 Prometheus + Grafana 监控，而不是在 Admin UI 中实现。Admin UI 的定位是"配置管理"，监控交给专业工具。

## 🤔 思考题

**Level 1（概念）**：为什么修改路由/集群后需要手动点"发布配置"才生效？为什么不是保存后自动生效？

**Level 2（推理）**：仪表盘的 `status.routes` 只返回摘要（routeId + clusterId + path），不返回完整的 Transforms 和限流策略。为什么后端要做这个精简？如果返回完整数据会有什么问题？

**Level 3（动手）**：给仪表盘添加"最近发布记录"功能——每次点"发布配置"后记录操作人和时间，展示在仪表盘底部。需要新增什么 API 和数据表？
