# 组件组合与复用

## 学习目标

- 理解「组合优于继承」的设计理念
- 掌握 children 和 render props 模式
- 学会设计可复用的组件
- 理解组件的职责分离

## 组合（Composition）：React 的基石

React 官方明确推荐**组合**而非继承来实现代码复用。简单来说就是：**把小组件拼在一起组成大组件**。

### 基本组合

```jsx
function Header() {
  return <header><h1>我的网站</h1></header>;
}

function Sidebar() {
  return <aside><nav>导航菜单</nav></aside>;
}

function Content({ children }) {
  return <main>{children}</main>;
}

function Footer() {
  return <footer>© 2024</footer>;
}

// 通过组合构建页面
function Layout({ children }) {
  return (
    <div className="layout">
      <Header />
      <div className="body">
        <Sidebar />
        <Content>{children}</Content>
      </div>
      <Footer />
    </div>
  );
}

// 不同页面共用布局
function HomePage() {
  return (
    <Layout>
      <h2>首页内容</h2>
      <p>欢迎来到我的网站</p>
    </Layout>
  );
}

function AboutPage() {
  return (
    <Layout>
      <h2>关于我</h2>
      <p>这里是关于页</p>
    </Layout>
  );
}
```

### 插槽模式（Slot Pattern）

类似 Vue 的具名插槽，React 通过 Props 实现：

```jsx
function Dialog({ title, content, footer }) {
  return (
    <div className="dialog-overlay">
      <div className="dialog">
        <div className="dialog-header">{title}</div>
        <div className="dialog-body">{content}</div>
        <div className="dialog-footer">{footer}</div>
      </div>
    </div>
  );
}

// 使用：每个「插槽」都可以传任意 JSX
<Dialog
  title={<h2>确认删除？</h2>}
  content={<p>删除后无法恢复，确定要继续吗？</p>}
  footer={
    <>
      <button onClick={onCancel}>取消</button>
      <button onClick={onConfirm} className="danger">确认删除</button>
    </>
  }
/>
```

> 💡 **经验**：插槽模式是构建 UI 组件库的核心模式。比如 `Card`、`Modal`、`Table` 这类组件，都是通过 Props 提供多个「插槽」让使用者自定义内容。

## 容器组件 vs 展示组件

这是 React 社区最经典的组件分类方式：

### 展示组件（Presentational Component）

- 只负责「长什么样」
- 通过 Props 接收数据
- 不关心数据从哪来

```jsx
// 展示组件：只管展示
function UserCard({ name, avatar, bio, onFollow }) {
  return (
    <div className="user-card">
      <img src={avatar} alt={name} />
      <h3>{name}</h3>
      <p>{bio}</p>
      <button onClick={onFollow}>关注</button>
    </div>
  );
}
```

### 容器组件（Container Component）

- 负责「数据怎么来」
- 处理业务逻辑
- 把数据传给展示组件

```jsx
// 容器组件：管理数据和逻辑
function UserCardContainer({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetchUser(userId).then(data => {
      setUser(data);
      setLoading(false);
    });
  }, [userId]);

  const handleFollow = () => {
    followUser(userId);
  };

  if (loading) return <Skeleton />;
  if (!user) return <div>用户不存在</div>;

  return (
    <UserCard
      name={user.name}
      avatar={user.avatar}
      bio={user.bio}
      onFollow={handleFollow}
    />
  );
}
```

> 💡 **为什么要分离？**
> - 展示组件可以被多个容器组件复用
> - 展示组件容易测试（只需要传 Props）
> - 关注点分离：UI 和逻辑各管各的

> ⚠️ **现代观点**：自从有了 Hooks，这种严格的分离变得不那么必要了。你可以用自定义 Hook 提取逻辑，不一定要用容器组件。但这种**思维方式**依然很重要——始终问自己「这个组件是负责展示还是逻辑？」

## 高阶组件 HOC（了解即可）

HOC 是一个函数，接收一个组件，返回一个「增强」后的新组件：

```jsx
// HOC：给任何组件添加加载状态
function withLoading(WrappedComponent) {
  return function WithLoadingComponent({ isLoading, ...props }) {
    if (isLoading) return <div>加载中...</div>;
    return <WrappedComponent {...props} />;
  };
}

// 使用
const UserListWithLoading = withLoading(UserList);
<UserListWithLoading isLoading={true} users={[]} />
```

> ⚠️ **现实**：HOC 模式在 Hook 出现后已经很少使用了。它有命名冲突、Props 透传麻烦、嵌套地狱等问题。但在老项目中你可能会遇到，需要能看懂。

## 自定义 Hook：现代的逻辑复用方式

> 这个话题我们会在 [自定义 Hook](../03.Hooks核心/06.自定义Hook.md) 中详细讲解。这里先看一个预览：

```jsx
// 自定义 Hook：提取数据获取逻辑
function useUser(userId) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetchUser(userId).then(data => {
      setUser(data);
      setLoading(false);
    });
  }, [userId]);

  return { user, loading };
}

// 在任何组件中使用
function UserProfile({ userId }) {
  const { user, loading } = useUser(userId);
  if (loading) return <Skeleton />;
  return <div>{user.name}</div>;
}

function UserAvatar({ userId }) {
  const { user, loading } = useUser(userId);
  if (loading) return <AvatarSkeleton />;
  return <img src={user.avatar} alt={user.name} />;
}
```

## 组件设计原则

### 1. 单一职责

每个组件只做一件事：

```jsx
// ❌ 一个组件干了太多事
function UserDashboard() {
  // 获取用户数据
  // 获取订单数据
  // 获取通知数据
  // 渲染 3 个不同的区块
}

// ✅ 拆分
function UserDashboard() {
  return (
    <div>
      <UserInfoSection />
      <OrderListSection />
      <NotificationSection />
    </div>
  );
}
```

### 2. 接口最小化

Props 只暴露必要的：

```jsx
// ❌ 暴露了内部实现细节
<DatePicker
  internalState={state}
  _onInternalChange={handler}
  __debugMode={true}
/>

// ✅ 简洁的公共接口
<DatePicker
  value={date}
  onChange={setDate}
  format="YYYY-MM-DD"
/>
```

### 3. 可组合性

组件应该易于与其他组件组合：

```jsx
// ✅ 灵活的组合
<Card>
  <Card.Header>
    <h2>标题</h2>
  </Card.Header>
  <Card.Body>
    <p>内容</p>
  </Card.Body>
  <Card.Footer>
    <Button>操作</Button>
  </Card.Footer>
</Card>
```

## 实战案例：通用列表组件

```jsx
function List({ 
  items, 
  renderItem,     // 自定义渲染每一项
  renderEmpty,    // 自定义空状态
  keyExtractor,   // 自定义 key 提取
  header,         // 列表头部
  footer,         // 列表底部
}) {
  if (items.length === 0) {
    return renderEmpty ? renderEmpty() : <p>暂无数据</p>;
  }

  return (
    <div className="list">
      {header}
      {items.map((item, index) => (
        <div key={keyExtractor ? keyExtractor(item) : index}>
          {renderItem(item, index)}
        </div>
      ))}
      {footer}
    </div>
  );
}

// 使用：用同一个 List 组件渲染不同的列表
<List
  items={users}
  keyExtractor={user => user.id}
  renderItem={user => <UserCard user={user} />}
  renderEmpty={() => <p>还没有用户</p>}
  header={<h2>用户列表</h2>}
/>

<List
  items={products}
  keyExtractor={p => p.sku}
  renderItem={product => <ProductCard product={product} />}
  header={<h2>商品列表</h2>}
  footer={<button>加载更多</button>}
/>
```
