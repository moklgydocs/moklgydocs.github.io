# Hooks 原理与链表

## Hooks 如何存储状态？

每个组件的 Fiber 节点有一个 `memoizedState` 属性，它指向一个**链表**，链表中的每个节点对应一个 Hook：

```
组件中的 Hooks:
useState(0)       → Hook1 { state: 0, next: → }
useState('')      → Hook2 { state: '', next: → }
useEffect(fn)     → Hook3 { effect: fn, next: → }
useRef(null)      → Hook4 { ref: { current: null }, next: null }

Fiber.memoizedState → Hook1 → Hook2 → Hook3 → Hook4
```

## 为什么 Hooks 不能在条件中调用？

因为 React 靠**调用顺序**来匹配 Hook 和状态：

```jsx
// 第一次渲染：
useState(0)    → Hook1 ← 对应 count
useState('')   → Hook2 ← 对应 name
useEffect(fn)  → Hook3

// 第二次渲染（如果顺序不变）：
useState(0)    → Hook1 ✅ 取到 count 的值
useState('')   → Hook2 ✅ 取到 name 的值
useEffect(fn)  → Hook3 ✅

// 如果条件调用导致顺序变化：
// (跳过了第一个 useState)
useState('')   → Hook1 ❌ 错误！取到的是 count 的值
useEffect(fn)  → Hook2 ❌ 错误！取到的是 name 的值
```

> 这就是为什么 React 官方文档说 **「不要在循环、条件或嵌套函数中调用 Hook」**。这不是代码风格建议，是技术限制。

## useState 的更新流程

```
1. setCount(newValue) 被调用
2. React 创建一个 Update 对象 { action: newValue }
3. Update 被添加到 Hook 的更新队列中
4. React 标记组件需要重新渲染
5. 下次渲染时，React 遍历更新队列，计算新状态
6. 新状态存入 Hook.memoizedState
```

## useEffect 的存储

```javascript
// useEffect 在 Fiber 上的存储（简化）
{
  tag: 'Effect',
  create: effectFn,          // effect 函数
  destroy: cleanupFn,        // 清理函数（上一次的返回值）
  deps: [dep1, dep2],        // 依赖数组
  next: nextEffect,          // 链表指针
}
```

React 在 Commit 阶段后，遍历 effect 链表：
1. 执行所有待清理的 `destroy` 函数
2. 执行所有新的 `create` 函数
3. 保存返回的清理函数

## 面试要点总结

| 问题 | 答案 |
|------|------|
| Hooks 状态存在哪？ | Fiber 节点的 memoizedState 链表上 |
| 为什么不能条件调用？ | 依靠调用顺序匹配状态，顺序变了就乱了 |
| 多个 setState 如何合并？ | 更新队列 + 批量处理 |
| useEffect 何时执行？ | Commit 阶段后，浏览器绘制后异步执行 |
