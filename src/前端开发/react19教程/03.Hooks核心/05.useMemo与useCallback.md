# useMemo 与 useCallback

## 学习目标

- 理解 useMemo 和 useCallback 的本质区别
- 知道什么时候该用，什么时候不该用
- 理解 React 19 中编译器自动优化的趋势

## 为什么需要它们？

React 组件每次重渲染时，函数体内的所有代码都会重新执行：

```jsx
function ProductList({ products, category }) {
  // ⚠️ 每次渲染都重新过滤——如果 products 很多，可能很慢
  const filtered = products.filter(p => p.category === category);
  
  // ⚠️ 每次渲染都创建新函数——可能导致子组件不必要地重渲染
  const handleClick = (id) => {
    console.log('clicked', id);
  };
  
  return filtered.map(p => <Product key={p.id} product={p} onClick={handleClick} />);
}
```

## useMemo：缓存计算结果

```jsx
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
//                                 ↑ 计算函数                    ↑ 依赖数组
```

**只有当依赖变化时才重新计算**，否则返回上次的缓存值：

```jsx
function ProductList({ products, category }) {
  // ✅ 只在 products 或 category 变化时才重新过滤
  const filtered = useMemo(() => {
    console.log('重新过滤...');
    return products.filter(p => p.category === category);
  }, [products, category]);
  
  return (
    <ul>
      {filtered.map(p => <li key={p.id}>{p.name}</li>)}
    </ul>
  );
}
```

## useCallback：缓存函数引用

```jsx
const memoizedFn = useCallback((args) => { doSomething(args); }, [deps]);
// 等价于
const memoizedFn = useMemo(() => (args) => { doSomething(args); }, [deps]);
```

**只有当依赖变化时才创建新函数**：

```jsx
function Parent() {
  const [count, setCount] = useState(0);
  
  // ✅ 函数引用稳定，不会导致 Child 不必要的重渲染
  const handleClick = useCallback(() => {
    setCount(c => c + 1);
  }, []);
  
  return <MemoizedChild onClick={handleClick} />;
}

// 配合 React.memo 使用
const MemoizedChild = React.memo(function Child({ onClick }) {
  console.log('Child 渲染了');
  return <button onClick={onClick}>点击</button>;
});
```

## 何时使用 vs 何时不用

### ✅ 应该使用的场景

```jsx
// 1. 昂贵的计算
const sorted = useMemo(() => {
  return [...items].sort((a, b) => a.price - b.price);
}, [items]); // items 可能有上万条

// 2. 传给 memo 子组件的回调
const handleSubmit = useCallback((data) => {
  api.submit(data);
}, []);
// <MemoizedForm onSubmit={handleSubmit} />

// 3. 作为其他 Hook 的依赖
const config = useMemo(() => ({ 
  pageSize: 10, 
  sort: 'desc' 
}), []);
useEffect(() => {
  fetchData(config);
}, [config]); // 如果不用 useMemo，config 每次都是新对象
```

### ❌ 不需要使用的场景

```jsx
// 1. 简单计算
const fullName = useMemo(() => `${first} ${last}`, [first, last]);
// ❌ 字符串拼接不需要 memo，直接写：
const fullName = `${first} ${last}`;

// 2. 没有配合 React.memo 的子组件
const handleClick = useCallback(() => {
  setCount(c => c + 1);
}, []);
// 如果 Child 没有用 React.memo 包裹，useCallback 就没有意义
<Child onClick={handleClick} /> // Child 照样重渲染

// 3. 基础类型值
const double = useMemo(() => count * 2, [count]);
// ❌ 乘法不需要 memo
const double = count * 2;
```

> ⚠️ **教训**：我曾经在一个项目中把所有函数都用 useCallback 包裹，结果代码变得又长又难读，而且性能并没有提升（因为子组件没用 React.memo）。**过早优化是万恶之源**——先 Profile，再优化。

## React.memo：子组件级别的优化

`React.memo` 让组件在 Props 没变时跳过重渲染：

```jsx
// 没有 memo：父组件渲染 → 子组件总是渲染
// 有 memo：父组件渲染 → 如果 props 没变，子组件跳过渲染

const ExpensiveList = React.memo(function ExpensiveList({ items, onItemClick }) {
  console.log('List 渲染了');
  return (
    <ul>
      {items.map(item => (
        <li key={item.id} onClick={() => onItemClick(item.id)}>
          {item.name}
        </li>
      ))}
    </ul>
  );
});

// 父组件
function App() {
  const [count, setCount] = useState(0);
  const [items] = useState([{ id: 1, name: 'Item 1' }]);
  
  // 必须配合 useCallback，否则 memo 失效
  const handleItemClick = useCallback((id) => {
    console.log(id);
  }, []);
  
  return (
    <div>
      <button onClick={() => setCount(c => c + 1)}>Count: {count}</button>
      {/* count 变化时，ExpensiveList 不会重渲染 ✅ */}
      <ExpensiveList items={items} onItemClick={handleItemClick} />
    </div>
  );
}
```

## React 19 与 React Compiler 的未来

React 19 配套的 React Compiler（曾叫 React Forget）可以**自动**进行这些优化：

```jsx
// 未来：你只需要写普通代码
function ProductList({ products, category }) {
  const filtered = products.filter(p => p.category === category);
  const handleClick = (id) => console.log(id);
  
  return filtered.map(p => <Product key={p.id} onClick={handleClick} />);
}
// React Compiler 会自动分析并插入 useMemo/useCallback！
```

> 💡 **趋势**：React 团队的目标是让开发者不需要手动写 useMemo/useCallback。但在 Compiler 完全普及之前，理解这些 API 依然很重要。

## 优化决策流程图

```
组件渲染慢吗？
├── 否 → 不需要优化
└── 是 → 用 Profiler 找到瓶颈
    ├── 是昂贵的计算 → useMemo
    ├── 是子组件不必要的重渲染 → React.memo + useCallback
    └── 是列表太长 → 虚拟列表（react-window）
```
