# useEffect 深度解析

## 学习目标

- 理解什么是「副作用」以及为什么需要 useEffect
- 掌握依赖数组的工作原理
- 学会正确使用清理函数
- 避开 useEffect 的各种坑

## 什么是副作用？

在 React 中，**副作用**是指「渲染 UI 之外的操作」：

- 数据请求（fetch API）
- DOM 操作（修改标题、聚焦输入框）
- 订阅事件（WebSocket、定时器、事件监听）
- 读写本地存储（localStorage）

这些操作不能直接写在组件函数体中（因为会在每次渲染时执行），需要用 `useEffect` 来管理。

## useEffect 基本用法

```jsx
import { useState, useEffect } from 'react';

function Timer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    // 这里的代码在组件渲染后执行
    const timer = setInterval(() => {
      setSeconds(prev => prev + 1);
    }, 1000);

    // 返回清理函数，在组件卸载或依赖变化时执行
    return () => {
      clearInterval(timer);
    };
  }, []); // 空依赖数组 = 只在挂载时执行一次

  return <p>已运行 {seconds} 秒</p>;
}
```

## 依赖数组详解

依赖数组是 useEffect 的**核心控制机制**：

```jsx
// 情况一：没有依赖数组 → 每次渲染后都执行
useEffect(() => {
  console.log('每次渲染后都执行');
});

// 情况二：空依赖数组 → 只在挂载时执行一次
useEffect(() => {
  console.log('只在挂载时执行');
  return () => console.log('只在卸载时执行');
}, []);

// 情况三：有依赖 → 依赖变化时执行
useEffect(() => {
  console.log('userId 变了，重新获取数据');
  fetchUser(userId);
}, [userId]);

// 情况四：多个依赖 → 任一变化就执行
useEffect(() => {
  console.log('任意一个变化就执行');
}, [userId, pageSize, sortBy]);
```

### 依赖数组的判断规则

React 用 `Object.is`（浅比较）来判断依赖是否变化：

```jsx
// 基本类型：值比较
const [count, setCount] = useState(0);
// count 从 0 → 1，依赖变化 ✅

// 对象/数组：引用比较
const [user, setUser] = useState({ name: '张三' });
// setUser({ name: '张三' }) → 新对象，引用变了，依赖变化 ✅
// 即使内容相同！

// ⚠️ 这就是为什么不能在渲染时创建对象作为依赖
useEffect(() => {
  // ...
}, [{ name: '张三' }]); // ❌ 每次渲染都是新对象，每次都会执行！
```

## 常见使用场景

### 场景一：数据请求

```jsx
function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false; // 防止竞态条件

    setLoading(true);
    setError(null);

    fetch(`/api/users/${userId}`)
      .then(res => {
        if (!res.ok) throw new Error('请求失败');
        return res.json();
      })
      .then(data => {
        if (!cancelled) { // 检查是否已取消
          setUser(data);
          setLoading(false);
        }
      })
      .catch(err => {
        if (!cancelled) {
          setError(err.message);
          setLoading(false);
        }
      });

    // 清理：取消过时的请求
    return () => {
      cancelled = true;
    };
  }, [userId]);

  if (loading) return <p>加载中...</p>;
  if (error) return <p>错误：{error}</p>;
  return <div>{user.name}</div>;
}
```

> ⚠️ **竞态条件（Race Condition）** 是 useEffect 中最常见也最隐蔽的 Bug：
> 1. 用户快速点击用户 A → 用户 B
> 2. 请求 A 先发出，请求 B 后发出
> 3. 但请求 B 先返回，页面显示用户 B ✅
> 4. 然后请求 A 才返回，把页面又覆盖成用户 A ❌
> 
> `cancelled` 标志或 AbortController 可以解决这个问题。

### 场景二：事件监听

```jsx
function WindowSize() {
  const [size, setSize] = useState({
    width: window.innerWidth,
    height: window.innerHeight,
  });

  useEffect(() => {
    const handleResize = () => {
      setSize({
        width: window.innerWidth,
        height: window.innerHeight,
      });
    };

    window.addEventListener('resize', handleResize);

    // 清理：移除事件监听
    return () => {
      window.removeEventListener('resize', handleResize);
    };
  }, []); // 空依赖：只在挂载时添加一次

  return <p>窗口大小: {size.width} × {size.height}</p>;
}
```

### 场景三：同步到 localStorage

```jsx
function usePersistentState(key, initialValue) {
  const [value, setValue] = useState(() => {
    const saved = localStorage.getItem(key);
    return saved ? JSON.parse(saved) : initialValue;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}

// 使用
function Settings() {
  const [theme, setTheme] = usePersistentState('theme', 'light');
  return <button onClick={() => setTheme(t => t === 'light' ? 'dark' : 'light')}>{theme}</button>;
}
```

### 场景四：修改文档标题

```jsx
function PageTitle({ title }) {
  useEffect(() => {
    const prevTitle = document.title;
    document.title = title;
    
    return () => {
      document.title = prevTitle; // 恢复之前的标题
    };
  }, [title]);

  return null; // 这个组件不渲染任何东西
}

// 注意：React 19 中可以直接用 <title> 标签了！
function Page() {
  return (
    <>
      <title>我的页面标题</title>
      <div>页面内容</div>
    </>
  );
}
```

## 清理函数的重要性

> ⚠️ **教训**：忘记清理是内存泄漏的头号原因

```jsx
// ❌ 没有清理定时器
useEffect(() => {
  setInterval(() => {
    setCount(c => c + 1);
  }, 1000);
}, []);
// 组件卸载后定时器还在跑！内存泄漏 + 可能报错

// ❌ 没有清理事件监听
useEffect(() => {
  window.addEventListener('scroll', handleScroll);
}, []);
// 组件卸载后还在监听！

// ❌ 没有清理 WebSocket
useEffect(() => {
  const ws = new WebSocket('ws://...');
  ws.onmessage = handleMessage;
}, []);
// 连接永远不会断开！
```

**清理规则**：任何在 useEffect 中创建的「外部连接」都必须在清理函数中销毁。

## useEffect 执行时序

```
组件挂载:
1. 渲染 → 计算 JSX
2. 更新 DOM（提交阶段）
3. 浏览器绘制
4. 执行 useEffect ← 在绘制之后！

组件更新（依赖变化）:
1. 渲染新的 JSX
2. 更新 DOM
3. 浏览器绘制
4. 执行上一次的清理函数 ← 先清理
5. 执行新的 useEffect  ← 再执行

组件卸载:
1. 执行清理函数
```

> 🔬 **原理**：useEffect 是异步的，在浏览器绘制后才执行。这意味着它不会阻塞页面渲染。如果你需要在绘制前执行（比如测量 DOM），应该用 `useLayoutEffect`。

## 常见错误

### 错误一：遗漏依赖

```jsx
// ❌ ESLint 会警告：userId 应该在依赖数组中
useEffect(() => {
  fetchUser(userId);
}, []); // 缺少 userId！当 userId 变化时不会重新请求

// ✅ 
useEffect(() => {
  fetchUser(userId);
}, [userId]);
```

> 💡 **建议**：安装 `eslint-plugin-react-hooks`，它会自动检查依赖数组是否完整。**永远不要忽略它的警告**。

### 错误二：错误的依赖导致无限循环

```jsx
// ❌ 每次都创建新的 options 对象 → 依赖永远在变 → 无限循环
function App() {
  const [data, setData] = useState(null);
  
  const options = { method: 'GET', headers: { 'Content-Type': 'application/json' } };
  
  useEffect(() => {
    fetch('/api/data', options).then(r => r.json()).then(setData);
  }, [options]); // options 每次渲染都是新对象！
}

// ✅ 方案一：把对象移到 useEffect 内部
useEffect(() => {
  const options = { method: 'GET', headers: { 'Content-Type': 'application/json' } };
  fetch('/api/data', options).then(r => r.json()).then(setData);
}, []);

// ✅ 方案二：用 useMemo 缓存
const options = useMemo(() => ({
  method: 'GET',
  headers: { 'Content-Type': 'application/json' }
}), []);
```

## useEffect vs 事件处理

不是所有逻辑都需要 useEffect！

```jsx
// ❌ 过度使用 useEffect
function Form() {
  const [name, setName] = useState('');
  const [greeting, setGreeting] = useState('');
  
  useEffect(() => {
    setGreeting(`Hello, ${name}!`);
  }, [name]); // 没必要用 effect！
  
  return <p>{greeting}</p>;
}

// ✅ 直接在渲染时计算
function Form() {
  const [name, setName] = useState('');
  const greeting = `Hello, ${name}!`; // 派生值
  
  return <p>{greeting}</p>;
}
```

**判断是否需要 useEffect 的标准**：

| 需要 useEffect | 不需要 useEffect |
|---------------|-----------------|
| 数据请求 | 根据 props/state 计算值 |
| 订阅外部数据源 | 响应用户事件（用事件处理） |
| 手动操作 DOM | 转换数据用于渲染 |
| 设置定时器 | 初始化组件状态 |
