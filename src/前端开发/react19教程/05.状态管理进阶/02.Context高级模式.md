# Context 高级模式

## 拆分 Context 避免性能问题

```jsx
// ❌ 一个大 Context → 任何值变化都导致所有消费者重渲染
const AppContext = createContext({ theme: 'light', user: null, locale: 'zh' });

// ✅ 拆分成独立 Context
const ThemeContext = createContext('light');
const UserContext = createContext(null);
const LocaleContext = createContext('zh');
```

## 分离「状态」和「操作」

```jsx
const TodoStateContext = createContext(null);    // 只存数据
const TodoDispatchContext = createContext(null);  // 只存 dispatch

function TodoProvider({ children }) {
  const [state, dispatch] = useReducer(todoReducer, initialState);
  
  return (
    <TodoStateContext.Provider value={state}>
      <TodoDispatchContext.Provider value={dispatch}>
        {children}
      </TodoDispatchContext.Provider>
    </TodoStateContext.Provider>
  );
}

// 只需要显示数据的组件 → 只读 State
function TodoCount() {
  const state = useContext(TodoStateContext);
  return <span>{state.todos.length} 项</span>;
}

// 只需要操作的组件 → 只读 Dispatch（dispatch 引用稳定，不会导致重渲染）
function AddTodoButton() {
  const dispatch = useContext(TodoDispatchContext);
  return <button onClick={() => dispatch({ type: 'ADD' })}>添加</button>;
}
```

> 💡 **为什么分离？** `dispatch` 的引用在组件的整个生命周期中是稳定的，不会变化。把它单独作为一个 Context，使用 dispatch 的组件就不会因为 state 变化而重渲染。

## 组合多个 Provider

```jsx
// 整理多个 Provider 的嵌套
function AppProviders({ children }) {
  return (
    <ThemeProvider>
      <AuthProvider>
        <CartProvider>
          <NotificationProvider>
            {children}
          </NotificationProvider>
        </CartProvider>
      </AuthProvider>
    </ThemeProvider>
  );
}

// 如果 Provider 太多，可以用一个工具函数
function composeProviders(...providers) {
  return ({ children }) =>
    providers.reduceRight(
      (acc, Provider) => <Provider>{acc}</Provider>,
      children
    );
}

const AppProviders = composeProviders(
  ThemeProvider, AuthProvider, CartProvider, NotificationProvider
);
```
