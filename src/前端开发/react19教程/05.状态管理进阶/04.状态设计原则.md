# 状态设计原则

## 六大原则

### 1. 最小化原则

> **能计算出来的值，不要存成状态**

```jsx
// ❌ 冗余
const [items, setItems] = useState([]);
const [selectedItems, setSelectedItems] = useState([]);
const [selectedCount, setSelectedCount] = useState(0); // 多余！

// ✅ 派生
const selectedCount = selectedItems.length;
const total = items.reduce((sum, i) => sum + i.price, 0);
```

### 2. 单一数据源

同一份数据应该只存在一个地方：

```jsx
// ❌ 两个地方存了相同的数据
const [todos, setTodos] = useState([]); // 在 TodoList 组件
const [todos, setTodos] = useState([]); // 在 Dashboard 组件

// ✅ 提升到共同的父组件或全局状态
```

### 3. 状态就近原则

状态应该放在**最小需要范围**的组件中：

```jsx
// ❌ 搜索框的状态放在全局
// 全局 Store: { searchQuery: '' }

// ✅ 搜索框的状态放在搜索组件内部
function SearchBox({ onSearch }) {
  const [query, setQuery] = useState(''); // 局部状态
  return <input value={query} onChange={e => setQuery(e.target.value)} />;
}
```

### 4. 正规化（Normalize）复杂数据

```jsx
// ❌ 嵌套结构，更新困难
const state = {
  posts: [
    { id: 1, title: '...', author: { id: 1, name: '张三' }, comments: [...] }
  ]
};

// ✅ 扁平化、用 ID 关联
const state = {
  posts: { 1: { id: 1, title: '...', authorId: 1 } },
  users: { 1: { id: 1, name: '张三' } },
  comments: { 1: { id: 1, postId: 1, text: '...' } },
};
```

### 5. 区分客户端状态和服务端状态

| 客户端状态 | 服务端状态 |
|-----------|-----------|
| UI 状态（弹窗开关、选中项） | 数据库中的数据 |
| 表单输入值 | 用户列表、商品列表 |
| 主题、语言偏好 | 需要缓存、同步、刷新 |
| 用 useState/useReducer | 用 TanStack Query/SWR |

### 6. 不可变更新

```jsx
// ❌ 直接修改
state.user.name = '新名字';
state.items.push(newItem);

// ✅ 始终创建新引用
setState({ ...state, user: { ...state.user, name: '新名字' } });
setItems([...items, newItem]);
```

## 状态分层架构

```
全局状态（Redux/Zustand）  ← 跨页面共享：用户信息、权限、主题
     ↓
页面级状态（Context）      ← 页面内共享：列表数据、过滤条件
     ↓
组件级状态（useState）     ← 组件内部：表单输入、展开/折叠
```
