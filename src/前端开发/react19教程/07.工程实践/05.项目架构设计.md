# React 项目架构设计

## 推荐的目录结构

```
src/
├── components/          # 通用 UI 组件
│   ├── Button/
│   │   ├── index.tsx
│   │   ├── Button.module.css
│   │   └── Button.test.tsx
│   └── ...
├── features/            # 功能模块（按业务划分）
│   ├── auth/
│   │   ├── components/  # 模块专属组件
│   │   ├── hooks/       # 模块专属 Hook
│   │   ├── api.ts       # 模块 API
│   │   └── types.ts     # 模块类型
│   ├── dashboard/
│   └── settings/
├── hooks/               # 全局自定义 Hook
├── lib/                 # 工具函数
├── stores/              # 全局状态（如果用 Zustand/Redux）
├── styles/              # 全局样式
├── types/               # 全局类型定义
├── App.tsx
└── main.tsx
```

## 架构原则

### 1. 按功能模块组织（Feature-based）

```
// ❌ 按文件类型
src/components/  → 所有组件混在一起
src/hooks/       → 所有 Hook 混在一起
src/styles/      → 所有样式混在一起

// ✅ 按功能模块
src/features/auth/       → 认证相关的一切
src/features/dashboard/  → 仪表盘相关的一切
src/features/settings/   → 设置相关的一切
```

> 💡 **好处**：删除一个功能 = 删除一个文件夹。新人 onboard 时只需要看自己负责的 feature 目录。

### 2. 组件分层

```
页面组件 (pages/)    → 路由入口，组合各功能模块
功能组件 (features/) → 业务逻辑，有状态管理
通用组件 (components/) → 纯 UI，无业务逻辑
```

### 3. 绝对路径导入

```json
// tsconfig.json
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"]
    }
  }
}
```

```tsx
// 整洁的导入
import { Button } from '@/components/Button';
import { useAuth } from '@/features/auth/hooks';
// 替代
import { Button } from '../../../components/Button';
```

## 技术选型清单

| 类别 | 推荐 | 备注 |
|------|------|------|
| 构建工具 | Vite | 快，配置少 |
| 路由 | React Router v7 / TanStack Router | 后者类型更好 |
| 状态管理 | Zustand / Redux Toolkit | 按项目规模选 |
| 服务端状态 | TanStack Query | 缓存+同步 |
| CSS 方案 | CSS Modules / Tailwind | 都好用 |
| 表单 | React Hook Form | 性能好，API 优 |
| UI 库 | Ant Design / shadcn/ui | 按需选 |
| 测试 | Vitest + Testing Library | 现代标配 |
