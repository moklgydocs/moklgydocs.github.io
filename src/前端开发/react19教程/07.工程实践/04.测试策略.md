# React 测试策略

## 测试金字塔

```
         /  E2E 测试  \         ← 少量：关键用户流程
        / 集成测试     \        ← 适量：组件交互
       / 单元测试       \       ← 大量：工具函数、Hooks
```

## 推荐工具栈

| 工具 | 用途 |
|------|------|
| **Vitest** | 测试运行器（比 Jest 更快） |
| **React Testing Library** | 组件测试（推荐） |
| **MSW** | Mock API 请求 |
| **Playwright** | E2E 测试 |

## 组件测试示例

```tsx
// Counter.test.tsx
import { render, screen, fireEvent } from '@testing-library/react';
import { Counter } from './Counter';

describe('Counter', () => {
  test('显示初始值', () => {
    render(<Counter initialCount={5} />);
    expect(screen.getByText('5')).toBeInTheDocument();
  });

  test('点击加号后数字增加', () => {
    render(<Counter initialCount={0} />);
    fireEvent.click(screen.getByRole('button', { name: '+' }));
    expect(screen.getByText('1')).toBeInTheDocument();
  });

  test('重置功能', () => {
    render(<Counter initialCount={0} />);
    fireEvent.click(screen.getByRole('button', { name: '+' }));
    fireEvent.click(screen.getByRole('button', { name: '重置' }));
    expect(screen.getByText('0')).toBeInTheDocument();
  });
});
```

## 自定义 Hook 测试

```tsx
import { renderHook, act } from '@testing-library/react';
import { useCounter } from './useCounter';

test('useCounter', () => {
  const { result } = renderHook(() => useCounter(0));
  
  expect(result.current.count).toBe(0);
  
  act(() => {
    result.current.increment();
  });
  
  expect(result.current.count).toBe(1);
});
```

## 测试原则

1. **测试行为，而不是实现**：不要测试组件内部状态，测试用户看到什么
2. **优先使用 `getByRole`**：模拟真实用户通过语义查找元素
3. **避免过度 Mock**：尽量使用真实的子组件
4. **关注核心路径**：不是每个组件都需要测试

> ⚠️ **教训**：我们曾经追求 100% 的测试覆盖率，结果大量测试脆弱无比（改一点代码就要改一堆测试），维护成本远超收益。**测试覆盖率 80% 就够了，关键是测对东西**。
