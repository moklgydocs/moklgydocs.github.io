# Kestrel 与反向代理架构

ASP.NET Core 内置了 Kestrel Web 服务器，为什么还需要 Nginx？直接暴露 Kestrel 行不行？

---

## 为什么不能直接暴露 Kestrel

```
直接暴露 Kestrel：
  互联网 → :5000 → Kestrel → 你的代码

✅ 开发环境：完全没问题
❌ 生产环境：缺少以下能力
```

| 能力 | Kestrel | Nginx |
|------|---------|-------|
| HTTPS/SSL 卸载 | 能做但不方便 | ✅ 专业 |
| 静态文件服务 | 效率一般 | ✅ 专业 |
| 请求缓冲 | ❌ | ✅ 吸收慢客户端 |
| 多应用统一入口 | ❌ 一个端口一个应用 | ✅ 按域名/路径分发 |
| IP 限制/速率限制 | 需要中间件 | ✅ 原生支持 |
| DDoS 防护 | ❌ | ✅ 基础防护 |
| 负载均衡 | ❌ | ✅ upstream |

---

## 推荐架构

```
生产环境：
  互联网 → :80/:443 → Nginx → :5000 → Kestrel → 你的代码
                        ↓
                    SSL 卸载
                    静态文件
                    请求缓冲
                    多应用分发

Docker 环境：
  互联网 → :80/:443 → Nginx 容器 → :5000 → API 容器(Kestrel)
```

## Nginx 反向代理配置

### 基础配置

```nginx
# /etc/nginx/conf.d/erp.conf
server {
    listen 80;
    server_name erp.company.com;

    # HTTP 跳转 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name erp.company.com;

    # SSL 证书
    ssl_certificate /etc/nginx/ssl/erp.company.com.pem;
    ssl_certificate_key /etc/nginx/ssl/erp.company.com.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    # 请求体大小限制（上传文件）
    client_max_body_size 50m;

    # 反向代理到 Kestrel
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection keep-alive;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;

        # 超时设置
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 静态文件直接由 Nginx 处理（如果有）
    location /static/ {
        alias /opt/apps/erp-api/wwwroot/static/;
        expires 30d;
    }
}
```

### Docker Compose 中的配置

```nginx
# Nginx 里用容器名代替 127.0.0.1
location / {
    proxy_pass http://erp-api:5000;
    # ... 其他 header 同上
}
```

### 多应用分发

```nginx
# 按域名分发
server {
    listen 443 ssl;
    server_name erp.company.com;
    location / {
        proxy_pass http://erp-api:5000;
    }
}

server {
    listen 443 ssl;
    server_name sso.company.com;
    location / {
        proxy_pass http://sso-server:5010;
    }
}

# 按路径分发
server {
    listen 443 ssl;
    server_name api.company.com;

    location /erp/ {
        proxy_pass http://erp-api:5000/;
    }

    location /sso/ {
        proxy_pass http://sso-server:5010/;
    }
}
```

## .NET 端配置

### 转发头（重要）

经过 Nginx 代理后，ASP.NET Core 拿到的客户端 IP 是 Nginx 的 IP。需要配置 Forwarded Headers：

```csharp
// Program.cs
builder.Services.Configure<ForwardedHeadersOptions>(options =>
{
    options.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto;
    options.KnownProxies.Clear();
    options.KnownNetworks.Clear();
});

// 必须在 UseAuthentication/UseAuthorization 之前
app.UseForwardedHeaders();
```

不配这个会导致：
- `HttpContext.Connection.RemoteIpAddress` 拿到的是 Nginx IP
- HTTPS 检测失败（Kestrel 收到的是 HTTP）
- OAuth 回调地址用 http 而不是 https

### Kestrel 配置

```csharp
// Program.cs 或 appsettings.json
builder.WebHost.ConfigureKestrel(options =>
{
    options.ListenAnyIP(5000);  // HTTP
    // 不需要在 Kestrel 配 HTTPS，Nginx 负责
});
```

```json
// appsettings.json
{
  "Kestrel": {
    "Endpoints": {
      "Http": {
        "Url": "http://+:5000"
      }
    },
    "Limits": {
      "MaxRequestBodySize": 52428800,
      "RequestHeadersTimeout": "00:00:30"
    }
  }
}
```

## 架构选型

| 场景 | 推荐 |
|------|------|
| 单台服务器单个应用 | Nginx + Kestrel |
| 单台服务器多个应用 | Nginx 按域名分发 + 多个 Kestrel |
| Docker 部署 | Nginx 容器 + API 容器 |
| 需要 WebSocket | Nginx + 升级头配置 |
| 纯内部 API（不对外） | 可以只用 Kestrel |
