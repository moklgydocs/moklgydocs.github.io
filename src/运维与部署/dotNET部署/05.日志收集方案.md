# 日志收集方案

生产环境出了问题，日志是唯一的线索。Console.WriteLine 不行，得用 Serilog 结构化日志。

---

## 为什么用 Serilog

```
内置 ILogger：
  ✅ 够用
  ❌ 写文件要自己配
  ❌ 结构化日志支持弱
  ❌ 没有日志分割（文件越来越大）

Serilog：
  ✅ 结构化日志（JSON 格式，方便搜索）
  ✅ 多个输出目标（控制台 + 文件 + Seq）
  ✅ 自动按日期/大小分割日志文件
  ✅ .NET 生态最流行的日志库
```

---

## 安装 Serilog

```bash
dotnet add package Serilog.AspNetCore
dotnet add package Serilog.Sinks.File
dotnet add package Serilog.Sinks.Console
dotnet add package Serilog.Expressions           # 过滤和格式化
```

## 基础配置

### 代码配置

```csharp
// Program.cs
using Serilog;

Log.Logger = new LoggerConfiguration()
    .MinimumLevel.Information()
    .MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
    .MinimumLevel.Override("Microsoft.EntityFrameworkCore", LogEventLevel.Warning)
    .WriteTo.Console()
    .WriteTo.File(
        path: "logs/app-.log",
        rollingInterval: RollingInterval.Day,    // 每天一个文件
        retainedFileCountLimit: 30,              // 保留30天
        fileSizeLimitBytes: 100 * 1024 * 1024,   // 单文件最大100MB
        outputTemplate: "{Timestamp:yyyy-MM-dd HH:mm:ss.fff} [{Level:u3}] {Message:lj}{NewLine}{Exception}")
    .CreateLogger();

try
{
    var builder = WebApplication.CreateBuilder(args);
    builder.Host.UseSerilog();

    // ... 其他配置

    var app = builder.Build();

    // 请求日志（一行记录一个请求）
    app.UseSerilogRequestLogging();

    // ... 其他中间件

    app.Run();
}
catch (Exception ex)
{
    Log.Fatal(ex, "应用启动失败");
}
finally
{
    Log.CloseAndFlush();
}
```

### appsettings.json 配置（推荐）

```bash
dotnet add package Serilog.Settings.Configuration
```

```csharp
// Program.cs（简洁版）
Log.Logger = new LoggerConfiguration()
    .ReadFrom.Configuration(builder.Configuration)
    .CreateLogger();

builder.Host.UseSerilog();
```

```json
// appsettings.json
{
  "Serilog": {
    "MinimumLevel": {
      "Default": "Information",
      "Override": {
        "Microsoft": "Warning",
        "Microsoft.EntityFrameworkCore": "Warning",
        "System": "Warning"
      }
    },
    "WriteTo": [
      {
        "Name": "Console"
      },
      {
        "Name": "File",
        "Args": {
          "path": "logs/app-.log",
          "rollingInterval": "Day",
          "retainedFileCountLimit": 30,
          "fileSizeLimitBytes": 104857600
        }
      }
    ]
  }
}
```

```json
// appsettings.Development.json（开发环境多输出）
{
  "Serilog": {
    "MinimumLevel": {
      "Default": "Debug"
    }
  }
}
```

```json
// appsettings.Production.json（生产环境精简）
{
  "Serilog": {
    "MinimumLevel": {
      "Default": "Warning"
    }
  }
}
```

## 结构化日志的正确写法

```csharp
// ❌ 字符串拼接（不能搜索）
_logger.LogInformation($"用户 {userId} 创建了订单 {orderId}");

// ✅ 结构化（可以按 UserId、OrderId 搜索）
_logger.LogInformation("用户 {UserId} 创建了订单 {OrderId}", userId, orderId);

// Serilog 会生成：
// {
//   "Timestamp": "2024-04-14T10:30:00",
//   "Level": "Information",
//   "Message": "用户 1001 创建了订单 ORD-2024-001",
//   "Properties": {
//     "UserId": 1001,
//     "OrderId": "ORD-2024-001"
//   }
// }
```

## 日志输出方案对比

```
方案            适用场景              成本      搜索能力
────────────────────────────────────────────────
写文件           小项目/单机           免费      grep 手动搜
Seq              中小团队             免费/付费  Web UI 搜索
ELK              大型项目             重         最强
Loki + Grafana   云原生/K8s           轻量       Grafana 查询
```

### 写文件（最简单）

就是上面的 `Serilog.Sinks.File`，日志文件在服务器上 `logs/` 目录。

```bash
# 查看日志
tail -f logs/app-20240414.log
grep "OrderId" logs/app-20240414.log
grep -i "error" logs/app-*.log
```

### Seq（推荐中小团队）

Seq 是专为 .NET 日志设计的 Web 查看器。

```bash
# Docker 部署 Seq
docker run -d \
  --name seq \
  --restart=unless-stopped \
  -p 5341:80 \
  -v seq-data:/data \
  -e ACCEPT_EULA=Y \
  datalust/seq:latest
```

```bash
dotnet add package Serilog.Sinks.Seq
```

```json
{
  "Serilog": {
    "WriteTo": [
      { "Name": "Console" },
      { "Name": "File", "Args": { "path": "logs/app-.log", "rollingInterval": "Day" } },
      { "Name": "Seq", "Args": { "serverUrl": "http://seq:5341" } }
    ]
  }
}
```

Seq 的好处：
- Web 界面搜索日志
- 按 `UserId`、`OrderId` 等属性过滤
- 设置告警（错误数超过阈值发通知）
- 免费版够个人/小团队用

## Docker 环境的日志

Docker 容器里不要写文件到容器内部，要么挂载出来，要么输出到 stdout。

```yaml
# docker-compose.yml
services:
  erp-api:
    volumes:
      - erp-logs:/app/logs    # 日志挂载出来
    logging:
      driver: json-file
      options:
        max-size: "50m"
        max-file: "3"
```

```bash
# 看容器 stdout 日志（Serilog Console sink）
docker logs -f erp-api

# 看挂载出来的文件日志
ls /var/lib/docker/volumes/erp-logs/_data/
```

## 最佳实践

```
✅ 用 Serilog 替代内置日志
✅ 结构化写法（_logger.LogInformation("{UserId}", id)）
✅ 用 appsettings 配置，不同环境不同级别
✅ 生产环境 Warning 级别，开发环境 Debug 级别
✅ 文件日志必须配分割和保留天数
✅ Docker 环境日志挂载出来或用 Seq 收集
✅ 不要 Console.WriteLine
```
