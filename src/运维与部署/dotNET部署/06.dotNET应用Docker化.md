# .NET 应用 Docker 化

把 .NET 应用装进 Docker 容器，实现"一次构建，到处运行"。这篇汇总 Dockerfile 编写、构建、部署的完整流程。

---

## 完整的 Dockerfile

```dockerfile
# ===== 第一阶段：构建 =====
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# 先复制 csproj 文件，利用 Docker 缓存
COPY ["ERP.Host/ERP.Host.csproj", "ERP.Host/"]
COPY ["ERP.Application/ERP.Application.csproj", "ERP.Application/"]
COPY ["ERP.Domain/ERP.Domain.csproj", "ERP.Domain/"]
COPY ["ERP.Infrastructure/ERP.Infrastructure.csproj", "ERP.Infrastructure/"]
RUN dotnet restore "ERP.Host/ERP.Host.csproj"

# 再复制全部源码并构建
COPY . .
RUN dotnet publish "ERP.Host/ERP.Host.csproj" \
    -c Release \
    -o /app/publish \
    --no-restore

# ===== 第二阶段：运行 =====
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
WORKDIR /app

# 安装 curl（健康检查需要）
RUN apt-get update && apt-get install -y curl && rm -rf /var/lib/apt/lists/*

# 创建非 root 用户
RUN groupadd -r appuser && useradd -r -g appuser -s /sbin/nologin appuser

# 复制构建产物
COPY --from=build /app/publish .

# 创建日志目录并赋权
RUN mkdir -p /app/logs && chown -R appuser:appuser /app

EXPOSE 5000

ENV ASPNETCORE_URLS=http://+:5000
ENV ASPNETCORE_ENVIRONMENT=Production
ENV TZ=Asia/Shanghai

HEALTHCHECK --interval=30s --timeout=5s --retries=3 --start-period=15s \
    CMD curl -f http://localhost:5000/health || exit 1

USER appuser
ENTRYPOINT ["dotnet", "ERP.Host.dll"]
```

## 镜像选型

```
镜像                                    大小      场景
───────────────────────────────────────────────────
mcr.microsoft.com/dotnet/aspnet:8.0    ~220MB   标准，推荐
mcr.microsoft.com/dotnet/aspnet:8.0-alpine  ~110MB   体积优先
mcr.microsoft.com/dotnet/aspnet:8.0-noble   ~225MB   Ubuntu 24.04
```

```dockerfile
# 追求最小体积
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine AS runtime
# ⚠️ alpine 用 musl libc，SkiaSharp 等库不兼容
# ⚠️ alpine 没有 curl，健康检查用 wget
HEALTHCHECK CMD wget --spider -q http://localhost:5000/health || exit 1
```

## 数据库迁移

### 方案一：应用启动时自动迁移

```csharp
// Program.cs
using (var scope = app.Services.CreateScope())
{
    var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
    db.Database.Migrate();
}
```

简单但有风险：多实例同时迁移可能冲突。

### 方案二：独立迁移容器（推荐）

```yaml
# docker-compose.yml
services:
  migration:
    image: erp-api:v1.0
    command: ["dotnet", "ERP.Host.dll", "--migrate"]
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - app-net

  erp-api:
    image: erp-api:v1.0
    depends_on:
      migration:
        condition: service_completed_successfully
```

## 完整的 CI/CD 构建命令

```bash
# 构建
VERSION=$(git describe --tags --always)
docker build \
  -t registry.company.com/erp-api:${VERSION} \
  -t registry.company.com/erp-api:latest \
  -f ERP.Host/Dockerfile .

# 推送
docker push registry.company.com/erp-api:${VERSION}
docker push registry.company.com/erp-api:latest

# 服务器上更新
ssh deploy@server "cd /opt/apps/erp && \
  sed -i 's/APP_VERSION=.*/APP_VERSION=${VERSION}/' .env && \
  docker compose pull erp-api && \
  docker compose up -d erp-api"
```

## 本地开发用 Docker Compose

```yaml
# docker-compose.override.yml（开发环境）
services:
  erp-api:
    build:
      context: .
      dockerfile: ERP.Host/Dockerfile
    ports:
      - "5000:5000"
    environment:
      - ASPNETCORE_ENVIRONMENT=Development
    volumes:
      # 热重载：挂载源码
      - ./ERP.Host/appsettings.Development.json:/app/appsettings.Development.json
```

```bash
# 开发时构建并启动
docker compose up --build

# 只重建 API
docker compose up --build erp-api
```

## 排错

```bash
# 镜像构建失败？
docker build --no-cache -t erp-api:v1.0 .   # 清除缓存重建
docker build --progress=plain .              # 显示详细输出

# 容器启动失败？
docker run --rm -it erp-api:v1.0 /bin/bash   # 进容器排查
docker logs erp-api                           # 看启动日志

# 容器内测试
docker exec -it erp-api /bin/bash
curl http://localhost:5000/health
dotnet --info
ls -la /app/
cat /app/appsettings.json

# 镜像太大？
docker history erp-api:v1.0                  # 看每一层大小
docker images erp-api                        # 看总大小
```
