# 多环境配置管理

开发用本地数据库，测试用测试库，生产用生产库。密码不能写死在代码里。ASP.NET Core 的配置系统就是解决这个的。

---

## 配置加载顺序

ASP.NET Core 按顺序加载配置，后覆盖前：

```
1. appsettings.json                    ← 基础配置
2. appsettings.{Environment}.json      ← 环境专属配置（覆盖基础）
3. User Secrets（开发环境）              ← 本地密钥
4. 环境变量                             ← 部署时注入
5. 命令行参数                           ← 启动时指定
```

**越后面优先级越高**。所以环境变量 > appsettings 文件。

---

## appsettings 多环境文件

```
项目/
├── appsettings.json                  ← 通用配置（进Git）
├── appsettings.Development.json      ← 开发环境（进Git）
├── appsettings.Staging.json          ← 测试环境（进Git，不含密码）
└── appsettings.Production.json       ← 生产环境（不进Git 或 部署时挂载）
```

**appsettings.json**（基础）：

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information"
    }
  },
  "AllowedHosts": "*"
}
```

**appsettings.Development.json**：

```json
{
  "ConnectionStrings": {
    "Default": "Host=localhost;Port=5432;Database=erp_dev;Username=postgres;Password=dev123"
  },
  "Redis": {
    "Connection": "localhost:6379"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Debug",
      "Microsoft.EntityFrameworkCore": "Information"
    }
  }
}
```

**appsettings.Production.json**：

```json
{
  "ConnectionStrings": {
    "Default": "Host=postgres;Port=5432;Database=erp;Username=postgres;Password=WILL_BE_OVERRIDDEN"
  },
  "Redis": {
    "Connection": "redis:6379,password=WILL_BE_OVERRIDDEN"
  },
  "Logging": {
    "LogLevel": {
      "Default": "Warning"
    }
  }
}
```

## 环境变量覆盖配置

ASP.NET Core 自动读取环境变量，用 `__`（双下划线）表示层级：

```bash
# 覆盖 ConnectionStrings.Default
export ConnectionStrings__Default="Host=prod-db;Port=5432;Database=erp;Password=RealPassword"

# 覆盖 Redis.Connection
export Redis__Connection="prod-redis:6379,password=RealRedisPass"

# 覆盖 Logging.LogLevel.Default
export Logging__LogLevel__Default="Warning"
```

在 Docker Compose 里：

```yaml
services:
  erp-api:
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - ConnectionStrings__Default=Host=postgres;Port=5432;Database=erp;Password=${DB_PASSWORD}
      - Redis__Connection=redis:6379,password=${REDIS_PASSWORD}
```

在 systemd service 文件里：

```ini
[Service]
Environment=ASPNETCORE_ENVIRONMENT=Production
Environment=ConnectionStrings__Default=Host=localhost;Port=5432;Database=erp;Password=ProdPass
```

## 切换环境

通过 `ASPNETCORE_ENVIRONMENT` 环境变量控制：

```bash
# 开发（默认）
export ASPNETCORE_ENVIRONMENT=Development

# 测试
export ASPNETCORE_ENVIRONMENT=Staging

# 生产
export ASPNETCORE_ENVIRONMENT=Production
```

对应加载 `appsettings.{值}.json`。

## User Secrets（开发环境密钥）

本地开发时密码不要写在 appsettings 里（怕提交到 Git）：

```bash
# 初始化（在项目目录）
dotnet user-secrets init

# 设置密钥
dotnet user-secrets set "ConnectionStrings:Default" "Host=localhost;Password=myLocalPassword"
dotnet user-secrets set "Redis:Connection" "localhost:6379"

# 查看
dotnet user-secrets list

# 存在哪？
# Windows: %APPDATA%\Microsoft\UserSecrets\{id}\secrets.json
# Linux: ~/.microsoft/usersecrets/{id}/secrets.json
```

开发环境自动加载，生产环境不加载。

## 在代码中读取配置

```csharp
// 强类型配置
public class RedisOptions
{
    public string Connection { get; set; } = "";
    public int Database { get; set; } = 0;
}

// 注册
builder.Services.Configure<RedisOptions>(builder.Configuration.GetSection("Redis"));

// 使用
public class MyService
{
    private readonly RedisOptions _redis;

    public MyService(IOptions<RedisOptions> options)
    {
        _redis = options.Value;
        // _redis.Connection → 环境变量或appsettings里的值
    }
}
```

## 最佳实践

```
✅ appsettings.json 只放通用配置，不放密码
✅ appsettings.Development.json 可以放开发密码（开发库无所谓）
✅ appsettings.Production.json 的密码通过环境变量覆盖
✅ 生产密码不进 Git（用环境变量 / Docker secret / 挂载文件）
✅ 用 User Secrets 管理本地开发密钥
✅ .gitignore 里加上 appsettings.Production.json（如果含真实密码）
```

```
.gitignore:
appsettings.*.local.json
```
