# 用户与权限管理

别用 root 跑应用。创建一个专门的部署用户，给最小必要权限，出了事好排查，也防误操作。

---

## 用户管理

### 创建部署用户

```bash
# 创建 deploy 用户，指定家目录
useradd -m -s /bin/bash deploy

# 设密码
passwd deploy

# 查看用户信息
id deploy
# uid=1001(deploy) gid=1001(deploy) groups=1001(deploy)

# 查看所有用户
cat /etc/passwd | grep -v nologin | grep -v false
```

### 常用操作

```bash
# 修改用户的 shell
usermod -s /bin/bash deploy

# 把用户加入 docker 组（才能不用 sudo 跑 docker）
usermod -aG docker deploy

# 锁定/解锁账户
usermod -L deploy     # 锁定（离职员工）
usermod -U deploy     # 解锁

# 删除用户（-r 同时删除家目录）
userdel -r testuser
```

### 用户组

```bash
# 创建组
groupadd devops

# 把用户加入组
usermod -aG devops deploy

# 查看组成员
getent group devops

# 查看用户属于哪些组
groups deploy
```

## 文件权限

### 读懂 ls -l

```bash
ls -l /opt/apps/erp-api/
# -rw-r--r-- 1 deploy deploy  4096 Apr 14 10:00 appsettings.json
# drwxr-xr-x 2 deploy deploy  4096 Apr 14 10:00 logs
# -rwxr-xr-x 1 deploy deploy 15360 Apr 14 10:00 ERP.Host.dll

# 拆解：-rwxr-xr-x
#        │└┬┘└┬┘└┬┘
#        │ │  │  └── other（其他人）: r-x = 读+执行
#        │ │  └───── group（组）: r-x = 读+执行
#        │ └──────── user（所有者）: rwx = 读+写+执行
#        └────────── 文件类型：- 普通文件，d 目录，l 软链接
```

### 权限数字表示

```
r = 4    w = 2    x = 1

常用组合：
  755 = rwxr-xr-x  → 目录、可执行文件
  644 = rw-r--r--  → 普通文件（配置文件、日志）
  600 = rw-------  → 敏感文件（私钥、密码配置）
  700 = rwx------  → 私有目录（.ssh）
```

### 修改权限

```bash
# chmod 改权限
chmod 755 deploy.sh            # 给脚本可执行权限
chmod 600 appsettings.Production.json  # 敏感配置只有所有者能读
chmod -R 755 /opt/apps/erp-api/        # -R 递归

# chown 改所有者
chown deploy:deploy /opt/apps/erp-api/ -R   # 把整个目录给 deploy 用户

# 实际场景：用 root 解压了发布包，得改回 deploy
tar -xzf publish.tar.gz -C /opt/apps/erp-api/
chown -R deploy:deploy /opt/apps/erp-api/
```

## sudo 配置

不登 root，用 sudo 提权执行特定命令。

```bash
# 方法一：把用户加入 wheel 组（CentOS）
usermod -aG wheel deploy
# wheel 组的用户可以 sudo 执行任何命令

# 方法二：精细控制（推荐生产环境）
visudo
# 或者创建独立文件
cat > /etc/sudoers.d/deploy << 'EOF'
# deploy 可以免密执行 systemctl 和 docker
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl restart erp-api
deploy ALL=(ALL) NOPASSWD: /usr/bin/systemctl status erp-api
deploy ALL=(ALL) NOPASSWD: /usr/bin/docker *
deploy ALL=(ALL) NOPASSWD: /usr/local/bin/docker-compose *
EOF
chmod 440 /etc/sudoers.d/deploy
```

::: warning
sudoers 文件语法写错会导致 sudo 不可用。始终用 `visudo` 编辑（有语法检查），或编辑完后 `visudo -c` 验证。
:::

## 实际部署的权限规划

```bash
# 1. 创建用户和目录
useradd -m -s /bin/bash deploy
mkdir -p /opt/apps
chown deploy:deploy /opt/apps

# 2. 应用目录权限
# /opt/apps/erp-api/ 755, 归 deploy
# appsettings.Production.json 600（含数据库密码）
# logs/ 755

# 3. sudo 只给需要的命令
# systemctl restart/status 应用服务
# docker/docker-compose 命令

# 4. SSH 密钥登录（不用密码）
su - deploy
mkdir -p ~/.ssh && chmod 700 ~/.ssh
# 把你的公钥放进去
echo "ssh-rsa AAAA..." >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

## 速查表

| 操作 | 命令 |
|------|------|
| 创建用户 | `useradd -m -s /bin/bash 用户名` |
| 设密码 | `passwd 用户名` |
| 加入组 | `usermod -aG 组名 用户名` |
| 改文件权限 | `chmod 755 文件` |
| 改文件所有者 | `chown 用户:组 文件 -R` |
| 配置sudo | `visudo` 或 `/etc/sudoers.d/` |
| 查看用户信息 | `id 用户名` |
| 查看文件权限 | `ls -la` |
