# SSH 配置与安全加固

SSH 是你连服务器的唯一入口。密码登录不安全，被扫到暴力破解是迟早的事。配好密钥登录 + 禁止密码，是服务器上线的第一件事。

---

## 密钥登录（免密登录）

### 本机生成密钥对

```bash
# 在你的开发机上执行（Windows 用 Git Bash 或 PowerShell）
ssh-keygen -t ed25519 -C "deploy@erp-server"
# 提示输入保存位置，默认 ~/.ssh/id_ed25519，直接回车
# 提示输入密码（passphrase），可以为空直接回车

# 会生成两个文件：
# ~/.ssh/id_ed25519      → 私钥（绝不能泄露）
# ~/.ssh/id_ed25519.pub  → 公钥（放到服务器上）
```

### 把公钥放到服务器

```bash
# 方法一：ssh-copy-id（最方便）
ssh-copy-id deploy@192.168.1.100
# 会要求输入密码，输完后公钥就自动放好了

# 方法二：手动复制
# 1. 查看公钥内容
cat ~/.ssh/id_ed25519.pub

# 2. 登录服务器，粘贴到 authorized_keys
ssh deploy@192.168.1.100
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "ssh-ed25519 AAAA... deploy@erp-server" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

### 验证

```bash
# 退出后重新连接，不需要输密码了
ssh deploy@192.168.1.100
```

## SSH 配置文件（客户端）

每次输 `ssh deploy@192.168.1.100` 太长了。配个别名：

```bash
# ~/.ssh/config（本机的 SSH 客户端配置）
Host erp
    HostName 192.168.1.100
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host sso
    HostName 192.168.1.101
    User deploy
    Port 22
    IdentityFile ~/.ssh/id_ed25519

Host gitlab
    HostName 192.168.1.200
    User git
    Port 22
    IdentityFile ~/.ssh/id_ed25519_gitlab
```

```bash
# 现在可以直接用别名连
ssh erp
ssh sso
scp publish.tar.gz erp:/opt/apps/erp-api/
```

## 服务器端安全加固

### 修改 sshd 配置

```bash
sudo vim /etc/ssh/sshd_config
```

关键配置项：

```bash
# 禁止 root 远程登录（用 deploy 登录后 sudo 提权）
PermitRootLogin no

# 禁止密码登录（只允许密钥）
PasswordAuthentication no

# 禁止空密码
PermitEmptyPasswords no

# 修改默认端口（可选，防扫描）
# Port 2222

# 只允许特定用户登录
AllowUsers deploy

# 限制登录尝试次数
MaxAuthTries 3

# 超时断开
ClientAliveInterval 300
ClientAliveCountMax 2
# 300秒无操作发心跳，2次无响应断开 = 10分钟超时

# 禁用 X11 转发和 TCP 转发（不需要就关掉）
X11Forwarding no
AllowTcpForwarding no
```

```bash
# 检查配置语法
sudo sshd -t

# 重启 sshd 使配置生效
sudo systemctl restart sshd
```

::: danger 改 sshd 配置前
1. **保持当前 SSH 会话不要关**
2. **另开一个终端测试新配置能不能登录**
3. 确认能登录后，再关掉旧会话

否则配错了你就锁在外面了。
:::

### fail2ban 防暴力破解

```bash
# 安装
yum install fail2ban    # CentOS
apt install fail2ban    # Ubuntu

# 配置
sudo vim /etc/fail2ban/jail.local
```

```ini
[DEFAULT]
bantime = 3600          # 封禁 1 小时
findtime = 600          # 10 分钟内
maxretry = 5            # 失败 5 次就封

[sshd]
enabled = true
port = ssh              # 如果改了端口，写实际端口号
filter = sshd
logpath = /var/log/secure   # CentOS
# logpath = /var/log/auth.log  # Ubuntu
```

```bash
# 启动
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# 查看被封的 IP
sudo fail2ban-client status sshd

# 手动解封某个 IP
sudo fail2ban-client set sshd unbanip 1.2.3.4
```

## 日常 SSH 操作

```bash
# 端口转发（本地访问远程服务器的数据库）
ssh -L 5432:localhost:5432 erp
# 现在本机的 5432 端口 → 远程服务器的 PostgreSQL

# 反向端口转发（让远程服务器访问你本机的服务）
ssh -R 8080:localhost:5000 erp
# 远程服务器的 8080 → 你本机的 5000

# 保持连接不断（在 ~/.ssh/config 加）
Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3

# 后台运行远程命令
ssh erp "sudo systemctl restart erp-api"

# SCP 传文件
scp publish.tar.gz erp:/opt/apps/
scp erp:/opt/apps/erp-api/logs/app.log ./
```

## 安全加固清单

上线前对照检查：

```
✅ 创建专用部署用户（非 root）
✅ 配置密钥登录
✅ 禁止 root 远程登录（PermitRootLogin no）
✅ 禁止密码登录（PasswordAuthentication no）
✅ 安装 fail2ban
✅ 限制 SSH 登录用户（AllowUsers）
✅ 防火墙只开必要端口
✅ 修改 SSH 默认端口（可选）
✅ 定期检查 /var/log/secure 登录日志
```
