# 健康检查与启动顺序

API 启动了但数据库还没就绪，连接直接报错。`depends_on` 只管启动顺序，不管服务是否真正可用。健康检查 + condition 才能解决这个问题。

---

## 问题场景

```yaml
services:
  erp-api:
    depends_on:
      - postgres     # 只等 postgres 容器启动，不等数据库就绪
```

```
时间线：
  0s   postgres 容器启动
  0s   erp-api 容器也启动了（depends_on 只等容器 start）
  3s   erp-api 尝试连接数据库 → 失败！Connection refused
  5s   postgres 数据库初始化完成，开始接受连接
  8s   erp-api 可能重试成功，也可能已经崩了
```

---

## 正确的做法：healthcheck + condition

```yaml
services:
  erp-api:
    image: erp-api:v1.0
    depends_on:
      postgres:
        condition: service_healthy    # 等健康检查通过
      redis:
        condition: service_healthy

  postgres:
    image: postgres:16
    environment:
      POSTGRES_PASSWORD: secret
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s       # 每5秒检查一次
      timeout: 3s        # 超时3秒算失败
      retries: 10        # 失败10次才判定不健康
      start_period: 10s  # 启动后10秒内不算失败

  redis:
    image: redis:7-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 10
```

```
现在的时间线：
  0s   postgres 容器启动
  0s   redis 容器启动
  5s   healthcheck: pg_isready → 失败（还在初始化）
  10s  healthcheck: pg_isready → 成功 ✓
  10s  healthcheck: redis-cli ping → 成功 ✓
  10s  erp-api 容器启动（数据库已就绪）
  11s  erp-api 连接数据库 → 成功 ✓
```

## 常用服务的健康检查配置

### PostgreSQL

```yaml
healthcheck:
  test: ["CMD-SHELL", "pg_isready -U postgres"]
  interval: 5s
  timeout: 3s
  retries: 10
  start_period: 10s
```

### MySQL

```yaml
healthcheck:
  test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "root", "-p${MYSQL_ROOT_PASSWORD}"]
  interval: 5s
  timeout: 3s
  retries: 10
```

### SQL Server

```yaml
healthcheck:
  test: ["CMD-SHELL", "/opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P '${SA_PASSWORD}' -Q 'SELECT 1' || exit 1"]
  interval: 10s
  timeout: 5s
  retries: 10
  start_period: 30s    # SQL Server 启动比较慢
```

### Redis

```yaml
# 无密码
healthcheck:
  test: ["CMD", "redis-cli", "ping"]
  interval: 5s
  timeout: 3s
  retries: 10

# 有密码
healthcheck:
  test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
  interval: 5s
  timeout: 3s
  retries: 10
```

### .NET 应用

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:5000/health"]
  interval: 30s
  timeout: 5s
  retries: 3
  start_period: 15s

# alpine 镜像没有 curl，用 wget
healthcheck:
  test: ["CMD", "wget", "--spider", "-q", "http://localhost:5000/health"]
  interval: 30s
  timeout: 5s
  retries: 3
```

### Nginx

```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost/nginx-health"]
  interval: 30s
  timeout: 5s
  retries: 3
```

## condition 选项

```yaml
depends_on:
  postgres:
    condition: service_healthy     # 等健康检查通过
  redis:
    condition: service_started     # 等容器启动就行
  migration:
    condition: service_completed_successfully  # 等执行完成（适合一次性任务）
```

### 数据库迁移场景

```yaml
services:
  # 先跑迁移
  migration:
    image: erp-api:v1.0
    command: ["dotnet", "ERP.Host.dll", "--migrate"]
    depends_on:
      postgres:
        condition: service_healthy
    networks:
      - app-net

  # 迁移完了再起 API
  erp-api:
    image: erp-api:v1.0
    depends_on:
      migration:
        condition: service_completed_successfully
      redis:
        condition: service_healthy
    networks:
      - app-net
```

## 查看健康状态

```bash
# 查看所有容器健康状态
docker compose ps
# NAME       STATUS                  PORTS
# postgres   Up 2 minutes (healthy)  5432/tcp
# redis      Up 2 minutes (healthy)  6379/tcp
# erp-api    Up 1 minute (healthy)   0.0.0.0:5000->5000/tcp

# 查看某个容器的健康检查历史
docker inspect postgres --format '{{json .State.Health}}' | python -m json.tool

# 手动执行健康检查
docker exec postgres pg_isready -U postgres
```

## .NET 应用端的健康检查端点

```csharp
// Program.cs
builder.Services.AddHealthChecks()
    .AddNpgSql(builder.Configuration.GetConnectionString("Default")!)
    .AddRedis(builder.Configuration["Redis:Connection"]!);

app.MapHealthChecks("/health");
```

```bash
# 安装 NuGet 包
dotnet add package AspNetCore.HealthChecks.NpgSql
dotnet add package AspNetCore.HealthChecks.Redis
```

返回 200 = 健康，503 = 不健康。Docker healthcheck 据此判断。

## 排错

```
容器一直 starting / unhealthy？

1. 手动进容器执行健康检查命令
   → docker exec postgres pg_isready -U postgres

2. 检查日志
   → docker compose logs postgres

3. start_period 是否够长？
   → SQL Server 首次启动可能要 30-60 秒

4. 检查网络：容器内能访问自己吗？
   → docker exec erp-api curl http://localhost:5000/health
```
