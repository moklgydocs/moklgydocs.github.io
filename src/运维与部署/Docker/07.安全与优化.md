# 安全与优化

Docker 跑在生产环境上，不是能跑就行。安全、资源限制、日志管理、镜像瘦身这些都得管。

---

## 安全加固

### 1. 不用 root 运行容器

```dockerfile
# Dockerfile 里创建非 root 用户
RUN groupadd -r appuser && useradd -r -g appuser -s /sbin/nologin appuser

# 切换到非 root 用户
USER appuser

ENTRYPOINT ["dotnet", "ERP.Host.dll"]
```

```bash
# 或者 docker run 时指定用户
docker run -d --user 1000:1000 --name erp-api erp-api:v1.0
```

::: warning
用非 root 运行时，确保应用目录有读权限，日志目录有写权限。
:::

### 2. 只读文件系统

```bash
# 容器文件系统设为只读，只有挂载的卷可写
docker run -d \
  --name erp-api \
  --read-only \
  -v /opt/apps/erp-api/logs:/app/logs \
  --tmpfs /tmp \
  erp-api:v1.0

# --read-only：容器内不能写任何文件
# 日志通过 -v 挂载写到宿主机
# /tmp 用 tmpfs（内存）处理临时文件
```

### 3. 限制容器权限

```bash
docker run -d \
  --name erp-api \
  --cap-drop=ALL \
  --security-opt=no-new-privileges \
  erp-api:v1.0

# --cap-drop=ALL：移除所有 Linux capabilities
# --security-opt=no-new-privileges：禁止进程获取新权限
# 如果应用需要绑定低端口（<1024），加 --cap-add=NET_BIND_SERVICE
```

### 4. 镜像安全扫描

```bash
# Docker Scout（官方）
docker scout cves erp-api:v1.0

# Trivy（开源，推荐）
# 安装：https://github.com/aquasecurity/trivy
trivy image erp-api:v1.0

# 扫描报告会告诉你镜像里有哪些已知漏洞
# 定期更新基础镜像是最好的修复方式
```

### 5. 不要在镜像里存敏感信息

```dockerfile
# ❌ 错误：密码写在镜像里
ENV ConnectionStrings__Default="Host=db;Password=123456"

# ✅ 正确：运行时通过环境变量或挂载传入
# docker run -e ConnectionStrings__Default="..." ...
# 或挂载配置文件
```

## 资源限制

不限制资源的容器可以吃掉整台机器的 CPU 和内存。

```bash
docker run -d \
  --name erp-api \
  --memory=512m \          # 内存上限 512MB
  --memory-swap=512m \     # 禁用 swap（和 memory 相同 = 不用 swap）
  --cpus=1.5 \             # 最多使用 1.5 核 CPU
  --pids-limit=200 \       # 最多 200 个进程（防 fork 炸弹）
  erp-api:v1.0

# 查看资源使用
docker stats erp-api

# 内存超限会怎样？
# 容器会被 OOM Killer 杀掉
# docker inspect 看 OOMKilled 字段
docker inspect erp-api --format '{{.State.OOMKilled}}'
```

### 推荐的资源限制

```
服务类型                建议内存       建议CPU
────────────────────────────────────────────
.NET Web API            256m-1g       0.5-2
PostgreSQL              512m-2g       1-2
Redis                   128m-512m     0.5-1
Nginx                   64m-256m      0.5-1
```

## 日志管理

容器日志不限制大小，会撑爆磁盘。

### 全局限制（daemon.json）

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "3"
  }
}
```

每个容器最多占 300MB 日志空间（3 个文件 × 100MB）。

### 单容器限制

```bash
docker run -d \
  --name erp-api \
  --log-opt max-size=50m \
  --log-opt max-file=3 \
  erp-api:v1.0
```

### 查看日志文件大小

```bash
# 容器日志存在哪？
docker inspect erp-api --format '{{.LogPath}}'
# /var/lib/docker/containers/abc123.../abc123...-json.log

# 查看大小
ls -lh $(docker inspect erp-api --format '{{.LogPath}}')

# 所有容器日志占了多少空间
du -sh /var/lib/docker/containers/*/
```

## 重启策略

```bash
# no（默认）：不自动重启
docker run -d --restart=no ...

# always：总是重启（包括 docker daemon 重启后）
docker run -d --restart=always ...

# unless-stopped（推荐）：除非手动 stop，否则一直重启
docker run -d --restart=unless-stopped ...

# on-failure:5：异常退出时重启，最多5次
docker run -d --restart=on-failure:5 ...
```

生产环境用 `unless-stopped`。手动 `docker stop` 后不会自动起来，但机器重启、Docker 重启、应用崩溃都会自动恢复。

## 镜像优化清单

```
✅ 多阶段构建（SDK 构建 → Runtime 运行）
✅ .dockerignore 排除无用文件
✅ 合并 RUN 减少层数
✅ 清理 apt/yum 缓存（RUN apt-get update && ... && rm -rf /var/lib/apt/lists/*）
✅ 用 alpine 基础镜像（没兼容问题的话）
✅ 固定基础镜像版本（不要用 :latest）
✅ 非 root 用户运行
✅ 添加 HEALTHCHECK
```

## 生产环境 Docker 检查清单

部署前对照走一遍：

```
容器安全：
  ✅ 非 root 用户运行
  ✅ 敏感信息不在镜像里（通过环境变量/挂载传入）
  ✅ 基础镜像定期更新
  ✅ 镜像做过安全扫描

资源管理：
  ✅ 设置了内存限制
  ✅ 设置了 CPU 限制
  ✅ 日志大小有限制（daemon.json 或容器级别）
  ✅ 定期清理未使用的镜像/容器/卷

可靠性：
  ✅ restart=unless-stopped
  ✅ HEALTHCHECK 配置
  ✅ 数据卷持久化（数据库、日志、上传文件）
  ✅ 定期备份数据卷

网络：
  ✅ 使用自定义 bridge 网络
  ✅ 只暴露必要端口
  ✅ 配置文件只读挂载

运维：
  ✅ Docker 数据目录放在大磁盘分区
  ✅ daemon.json 配了 live-restore
  ✅ 有自动化部署脚本
  ✅ 有监控（docker stats / Prometheus）
```
