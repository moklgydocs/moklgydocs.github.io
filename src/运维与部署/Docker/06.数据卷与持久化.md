# 数据卷与持久化

容器删了，里面的数据就没了。数据库、日志、配置文件这些必须持久化到宿主机上。

---

## 三种挂载方式

```
方式               语法                              数据存哪
──────────────────────────────────────────────────────────────
Volume（命名卷）    -v pgdata:/var/lib/postgresql     Docker 管理（/var/lib/docker/volumes/）
Bind Mount（绑定）  -v /opt/data:/var/lib/postgresql  你指定的宿主机路径
tmpfs              --tmpfs /tmp                      内存（容器停就没了）
```

### Volume（命名卷）—— 推荐数据库用

```bash
# 创建命名卷
docker volume create pgdata

# 使用命名卷
docker run -d \
  --name postgres \
  -v pgdata:/var/lib/postgresql/data \
  postgres:16

# 数据实际存在：/var/lib/docker/volumes/pgdata/_data/
# Docker 自动管理，不用关心宿主机路径
```

### Bind Mount（绑定挂载）—— 推荐配置文件和日志用

```bash
# 挂载配置文件（只读）
docker run -d \
  --name erp-api \
  -v /opt/apps/erp-api/appsettings.Production.json:/app/appsettings.Production.json:ro \
  -v /opt/apps/erp-api/logs:/app/logs \
  erp-api:v1.0

# :ro = 只读（容器不能修改宿主机的配置文件）
# 日志目录不加 :ro，容器要写日志

# ⚠️ 宿主机目录不存在时：
# Docker 会自动创建（作为 root）
# 可能导致权限问题，最好提前创建：
mkdir -p /opt/apps/erp-api/logs
chown deploy:deploy /opt/apps/erp-api/logs
```

## 实际使用场景

### PostgreSQL

```bash
docker run -d \
  --name postgres \
  --restart=unless-stopped \
  -p 5432:5432 \
  -e POSTGRES_PASSWORD=MySecret123 \
  -e POSTGRES_DB=erp \
  -v pgdata:/var/lib/postgresql/data \
  -v /opt/backup/pg-init:/docker-entrypoint-initdb.d \
  postgres:16

# pgdata 卷：数据库文件
# pg-init 目录：初始化 SQL 脚本（首次启动时执行）
```

### Redis

```bash
docker run -d \
  --name redis \
  --restart=unless-stopped \
  -p 6379:6379 \
  -v redis-data:/data \
  -v /opt/apps/redis/redis.conf:/usr/local/etc/redis/redis.conf:ro \
  redis:7-alpine redis-server /usr/local/etc/redis/redis.conf

# redis-data 卷：持久化数据（AOF/RDB）
# redis.conf：自定义配置（密码、内存限制等）
```

### .NET 应用

```bash
docker run -d \
  --name erp-api \
  -p 5000:5000 \
  -v /opt/apps/erp-api/appsettings.Production.json:/app/appsettings.Production.json:ro \
  -v /opt/apps/erp-api/logs:/app/logs \
  -v /opt/apps/erp-api/upload:/app/upload \
  erp-api:v1.0

# 配置文件：只读挂载，修改后重启容器生效
# 日志目录：可写挂载，宿主机能直接看
# 上传文件：可写挂载，持久化用户上传的文件
```

## 卷管理命令

```bash
# 创建卷
docker volume create pgdata

# 查看所有卷
docker volume ls

# 查看卷详情
docker volume inspect pgdata
# "Mountpoint": "/var/lib/docker/volumes/pgdata/_data"

# 删除卷
docker volume rm pgdata

# 清理未使用的卷（⚠️ 确认没有需要的数据）
docker volume prune
```

## 备份与恢复

### 备份 PostgreSQL 数据卷

```bash
# 方法一：pg_dump（推荐，逻辑备份）
docker exec postgres pg_dump -U postgres erp > /opt/backup/erp_$(date +%Y%m%d).sql

# 方法二：备份整个数据卷
docker run --rm \
  -v pgdata:/source:ro \
  -v /opt/backup:/backup \
  alpine tar -czf /backup/pgdata_$(date +%Y%m%d).tar.gz -C /source .
```

### 恢复

```bash
# 方法一：导入 SQL
cat /opt/backup/erp_20240414.sql | docker exec -i postgres psql -U postgres erp

# 方法二：恢复数据卷
docker volume create pgdata-restore
docker run --rm \
  -v pgdata-restore:/target \
  -v /opt/backup:/backup \
  alpine tar -xzf /backup/pgdata_20240414.tar.gz -C /target
```

### 自动备份脚本

```bash
#!/bin/bash
# backup-db.sh
BACKUP_DIR="/opt/backup/postgres"
KEEP_DAYS=7
DATE=$(date +%Y%m%d_%H%M%S)

mkdir -p $BACKUP_DIR

# 备份
docker exec postgres pg_dumpall -U postgres | gzip > "${BACKUP_DIR}/all_${DATE}.sql.gz"

# 清理旧备份
find $BACKUP_DIR -name "*.sql.gz" -mtime +$KEEP_DAYS -delete

echo "备份完成: ${BACKUP_DIR}/all_${DATE}.sql.gz"
```

```bash
# crontab 定时备份
0 2 * * * /opt/scripts/backup-db.sh >> /var/log/backup-db.log 2>&1
```

## 权限问题排查

容器里的用户 ID 和宿主机不一致，经常导致权限问题：

```bash
# 容器里是 appuser (uid=1000)
# 宿主机是 deploy (uid=1001)
# 结果：容器写不了挂载的日志目录

# 解决方案一：宿主机目录改权限
chmod 777 /opt/apps/erp-api/logs    # 简单粗暴（不推荐）

# 解决方案二：指定容器运行用户与宿主机一致
docker run -d --user $(id -u deploy):$(id -g deploy) ...

# 解决方案三：Dockerfile 里建同 UID 用户
RUN groupadd -g 1001 appuser && useradd -u 1001 -g appuser appuser
```

## 选型建议

| 数据类型 | 推荐方式 | 理由 |
|---------|---------|------|
| 数据库文件 | 命名卷 Volume | Docker 管理，性能好 |
| 配置文件 | Bind Mount + :ro | 宿主机可直接编辑 |
| 日志文件 | Bind Mount | 宿主机可直接看和清理 |
| 上传文件 | Bind Mount 或 Volume | 需要持久化 |
| 临时缓存 | tmpfs | 快，不占磁盘 |
