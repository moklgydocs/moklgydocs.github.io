# 凭据与权限管理

密码、SSH 密钥、API Token 不能写在 Jenkinsfile 里。用 Jenkins 凭据管理统一存储，Pipeline 里安全引用。

---

## 凭据类型

```
Jenkins → 系统管理 → Credentials → System → Global credentials

类型：
  Username with password    → GitLab 账号、Docker Registry 账号
  SSH Username with private key → 部署服务器 SSH 密钥
  Secret text              → API Token、Webhook Secret
  Secret file              → 证书文件、配置文件
  Certificate              → PKCS#12 证书
```

---

## 创建凭据

### GitLab 账号（用户名密码）

```
Kind: Username with password
Scope: Global
Username: jenkins
Password: GitLab Personal Access Token
ID: gitlab-cred
Description: GitLab 代码仓库凭据
```

### SSH 部署密钥

```bash
# 先在 Jenkins 服务器上生成 SSH 密钥对
docker exec jenkins ssh-keygen -t ed25519 -C "jenkins@company.com" -f /tmp/deploy_key -N ""

# 把公钥复制到目标服务器
docker exec jenkins cat /tmp/deploy_key.pub
# 在目标服务器: echo "公钥内容" >> /home/deploy/.ssh/authorized_keys

# 把私钥内容复制出来，创建凭据
docker exec jenkins cat /tmp/deploy_key
```

```
Kind: SSH Username with private key
Scope: Global
ID: deploy-ssh-key
Username: deploy
Private Key: Enter directly → 粘贴私钥内容
Description: 部署服务器 SSH 密钥
```

### Docker Registry 凭据

```
Kind: Username with password
ID: docker-registry-cred
Username: jenkins
Password: Registry 密码或 Token
Description: Docker 镜像仓库
```

### API Token

```
Kind: Secret text
ID: feishu-webhook
Secret: https://open.feishu.cn/open-apis/bot/v2/hook/xxx
Description: 飞书通知 Webhook
```

## Pipeline 中使用凭据

### 用户名密码

```groovy
withCredentials([usernamePassword(
    credentialsId: 'gitlab-cred',
    usernameVariable: 'USER',
    passwordVariable: 'PASS')]) {
    sh "git clone http://${USER}:${PASS}@gitlab.company.com/repo.git"
}
```

### SSH 密钥

```groovy
withCredentials([sshUserPrivateKey(
    credentialsId: 'deploy-ssh-key',
    keyFileVariable: 'SSH_KEY',
    usernameVariable: 'SSH_USER')]) {
    sh """
        ssh -i ${SSH_KEY} -o StrictHostKeyChecking=no ${SSH_USER}@server '
            cd /opt/apps && docker compose up -d
        '
    """
}
```

### Secret 文本

```groovy
withCredentials([string(credentialsId: 'feishu-webhook', variable: 'WEBHOOK')]) {
    sh """
        curl -X POST ${WEBHOOK} \
          -H 'Content-Type: application/json' \
          -d '{"msg_type":"text","content":{"text":"构建成功！"}}'
    """
}
```

### environment 方式

```groovy
pipeline {
    environment {
        GITLAB_CRED = credentials('gitlab-cred')
        // 自动生成 GITLAB_CRED_USR 和 GITLAB_CRED_PSW
    }
    stages {
        stage('Clone') {
            steps {
                sh "git clone http://${GITLAB_CRED_USR}:${GITLAB_CRED_PSW}@gitlab.company.com/repo.git"
            }
        }
    }
}
```

## 权限管理

### 基于矩阵的权限

```
系统管理 → 安全配置 → Authorization
→ Matrix-based security

权限矩阵：
  用户/组          Overall  Job    View   SCM   ...
  ─────────────────────────────────────────────
  admin           ✅全部   ✅全部  ✅全部  ✅全部
  developer       Read    Build   Read   ✅
  viewer          Read    Read    Read   ❌
```

### Role-Based（推荐）

安装 **Role-based Authorization Strategy** 插件：

```
系统管理 → 安全配置 → Authorization
→ Role-Based Strategy

系统管理 → Manage and Assign Roles

1. 创建角色：
   Global roles:
     admin → 全部权限
     developer → Overall/Read
     viewer → Overall/Read

   Project roles（按正则匹配项目）:
     erp-dev → Pattern: erp-.* → Build/Read/Workspace
     sso-dev → Pattern: sso-.* → Build/Read/Workspace

2. 分配角色：
   admin → 管理员账号
   erp-dev → 开发者A, 开发者B
   sso-dev → 开发者C
```

### 项目级权限

```
Job → 配置 → Enable project-based security
→ 添加特定用户/组的权限

效果：只有指定的人能看到和操作这个 Job
```

## 安全最佳实践

```
✅ 密码、密钥统一用 Credentials 管理
✅ Pipeline 里用 withCredentials 引用，不硬编码
✅ 关闭匿名访问
✅ 不同项目组用不同的凭据
✅ 定期轮换密钥和 Token
✅ Jenkins 日志里凭据值会自动打码（显示 ****）
✅ 生产部署 Job 限制只有运维/负责人能操作
❌ 不要把密码写在 Jenkinsfile 里
❌ 不要把密码写在环境变量的值里（明文）
```
