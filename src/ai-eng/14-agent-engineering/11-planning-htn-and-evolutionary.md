# HTN 规划与进化搜索

> 符号规划处理"计划可证明正确"的情形,进化代码搜索处理"适应度函数机器可检验"的情形。ChatHTN(2025)和 AlphaEvolve(2025)展示了各自与 LLM 配对时能解锁什么。

**类型:** 动手构建
**编程语言:** Python(标准库)
**前置要求:** 第 14 阶段 · 02(ReWOO 与 Plan-and-Execute)
**预计耗时:** 约 75 分钟

## 学习目标

- 解释层次任务网络(HTN):任务、方法、算子、前置条件、效果。
- 描述 ChatHTN 的混合循环——符号搜索加 LLM 兜底分解。
- 解释 AlphaEvolve 的进化循环,以及为什么它只在有程序化评估器时才有效。
- 用纯标准库实现玩具 HTN 规划器和玩具进化搜索。

## 问题

ReWOO(第 02 课)、Plan-and-Execute 和 ReAct 覆盖了大多数智能体规划。两种情形它们覆盖不好:

1. **要求可证明正确的计划。** 排程、飞行路径、合规工作流——计划必须构造上就是可靠的。一个流畅但偶尔幻觉出一步的 LLM 计划,不可接受。
2. **适应度函数机器可检验的优化。** 矩阵乘法、调度启发式、编译器 pass——目标不是"一个正确计划",而是"最好的计划"。

HTN 规划和 AlphaEvolve 分别解这两个不同的问题。两者都把 LLM 当放大器,而非替代品。

## 概念

### 层次任务网络

HTN 由这些组成:

- **任务** —— 复合的(待分解)与原语的(可直接执行)。
- **方法** —— 把复合任务分解成子任务的方式,带前置条件。
- **算子** —— 带前置条件和效果的原语动作。
- **状态** —— 一组事实。

规划:给定目标任务和初始状态,找出一个到原语算子的分解,使其前置条件按序满足。

HTN 比 LLM 老得多,至今仍是可证明正确计划的参照。

### ChatHTN(Gopalakrishnan 等,2025)

ChatHTN(arXiv:2505.11814)把符号 HTN 与 LLM 查询交织:

1. 先尝试用已有方法分解当前复合任务。
2. 没有方法适用时,问 LLM:"在状态 `s` 下,你会怎么分解 `task`?"
3. 把 LLM 回答翻译成候选子任务。
4. 对照算子 schema 校验;拒绝非法分解。
5. 递归。

论文的核心主张:产出的每个计划都可证明可靠,因为 LLM 的建议只作为候选分解进入,从不直接编辑计划。符号层掌管正确性;LLM 扩充方法库。

在线方法学习(OpenReview `gwYEDY9j2x`,2025 年后续)加了一个学习器,用回归泛化 LLM 产出的分解——LLM 查询频率最多降 75%。

### AlphaEvolve(Novikov 等,2025)

AlphaEvolve(arXiv:2506.13131,DeepMind,2025 年 6 月)是另一头野兽:由 Gemini 2.0 Flash/Pro 集成 orchestrate 的进化代码搜索。

循环:

1. 从种子程序 + 程序化评估器(返回适应度分数)开始。
2. LLM 集成提议变异。
3. 变异过评估器。
4. 留最优;再变异。

已发表成果:

- 56 年来首次改进 4x4 复数矩阵乘法的 Strassen 算法(48 次标量乘法)。
- 通过 Borg 调度启发式,为 Google 回收 0.7% 算力。
- 前沿负载上 FlashAttention 提速 32%。

硬约束:适应度函数必须机器可检验。对散文式答案做进化搜索不会收敛。

### 何时用哪个

| 问题类别 | 用 | 为什么 |
|---------------|-----|-----|
| 带硬约束的排程 | HTN + ChatHTN | 可证明可靠 |
| 编译器优化 | AlphaEvolve | 适应度机器可检验 |
| 多步任务执行 | ReAct / ReWOO | LLM 在环,无形式化保证 |
| 带测试的代码改进 | AlphaEvolve | 测试就是评估器 |
| 政策约束的自动化 | HTN | 前置条件编码政策 |

### 这个模式在哪里出错

- **没有算子的 HTN。** 没有前置条件/效果 schema,可靠性主张就垮了。ChatHTN 的"LLM 提议分解"需要 schema 来拒绝非法走法。
- **没有真评估器的 AlphaEvolve。** "问 LLM 这代码是不是更好"不是适应度函数。评估器必须确定且快。
- **过度工程。** 大多数智能体任务两个都不需要。先够到 ReAct 或 ReWOO。

## 动手构建

`code/main.py` 实现两个玩具:

- 纯标准库 HTN 规划器:算子、方法、前置条件、效果,加一个在没有方法匹配复合任务时介入的 `LLMFallback`。"LLM"是脚本化分解器,规划器可离线运行。
- 纯标准库进化搜索:演化算术表达式,使其输出在测试集上最小化 `|f(x) - target|`。评估器是确定性的。

运行:

```
python3 code/main.py
```

轨迹展示 HTN 规划器分解复合任务(中途一次 LLM 兜底),以及进化循环收敛到目标表达式。

## 投入使用

- **HTN 规划器** —— `pyhop`、`SHOP3`,或为领域特定政策执行自建。
- **ChatHTN** —— 研究代码;这个模式(符号 + LLM 兜底)可干净移植到任何 HTN 规划器。
- **AlphaEvolve** —— DeepMind 论文;模式(集成 + 评估器)可复现。OpenEvolve 等开源复刻正在出现。
- **智能体框架** —— 还没有一家内置一等 HTN 或 AlphaEvolve。作为子智能体或后台 worker 自建。

## 练习

1. 给 HTN 规划器加回溯:算子后置条件运行时失败时,回滚并试下一个方法。
2. 给 ChatHTN 加 LLM 方法缓存:LLM 在状态模式 `P` 下分解任务 `T` 时存下结果;下次调用先查方法库。
3. 把进化搜索的评估器换成真测试套件。进化一个通过 20 个测试用例的排序函数;报告收敛所需代数。
4. 读 AlphaEvolve 的评估器设计说明。为你关心的领域设计一个评估器(SQL 查询优化、测试套件最小化、部署 YAML)。
5. 组合:用 HTN 把复合任务分解成子任务,再对每个子任务的原语算子做进化搜索。哪里出彩,哪里过度工程?

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| HTN | "层次规划器" | 带算子、前置条件、效果的任务分解 |
| 方法 | "分解规则" | 把复合任务拆成子任务的方式 |
| 算子 | "原语动作" | 带前置条件和效果的具体步骤 |
| ChatHTN | "LLM + HTN" | 无方法匹配时,符号规划器问 LLM |
| AlphaEvolve | "进化代码搜索" | LLM 集成变异代码;确定性评估器选择 |
| 适应度函数 | "评估器" | 对输出的确定性、机器可检验打分 |
| 在线方法学习 | "缓存的 LLM 分解" | 存储并泛化 LLM 计划,削减查询成本 |
