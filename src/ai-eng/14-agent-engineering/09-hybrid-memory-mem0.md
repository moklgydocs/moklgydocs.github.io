# 混合记忆:向量 + 图 + KV

> 混合记忆并行跑三种存储——向量管语义相似、KV 管快速事实查找、图管实体关系推理——再用一个打分层在检索时融合。这是外部记忆中广泛使用的生产模式;Mem0(Chhikara 等,2025)是一个参考实现。

**类型:** 动手构建
**编程语言:** Python(标准库)
**前置要求:** 第 14 阶段 · 07(MemGPT)、第 14 阶段 · 08(Letta 块)
**预计耗时:** 约 75 分钟

## 学习目标

- 解释为什么单一存储(只有向量、只有图、只有 KV)对智能体记忆不够用。
- 说出 Mem0 的三个并行存储及各自的优化目标。
- 描述 Mem0 的融合打分——相关性、重要性、新近度——以及为什么是加权求和而非层级。
- 用纯标准库实现玩具三存储记忆:`add()` 写全部三个,`search()` 融合结果。

## 问题

单一存储总有一类查询应付不了:

- **语义相似** —— "上周我们讨论智能体漂移聊了什么?"向量赢;KV 和图抓瞎。
- **事实查找** —— "用户的电话号码是多少?"KV 赢;向量浪费,图杀鸡用牛刀。
- **关系推理** —— "哪些客户共享同一个开票实体?"图赢;向量和 KV 答不了。

生产智能体在一个会话里三类查询都会发。单一存储的记忆注定在其中两类上是错的。Mem0 的贡献,是把三者接到同一个 `add`/`search` 界面后面,配上融合它们的打分函数。

## 概念

### 三存储并行

Mem0(arXiv:2504.19413,2025 年 4 月)在 `add(text, user_id, metadata)` 时:

1. 从文本抽取候选事实(LLM 驱动的一步)。
2. 每条事实写入向量存储(嵌入),供语义搜索。
3. 每条事实以 (user_id, fact_type, entity) 为键写入 KV 存储,O(1) 查找。
4. 每条事实以带类型边写入图存储(Mem0g),供关系查询。

`search(query, user_id)` 时:

1. 向量存储按嵌入余弦返回 top-k。
2. KV 存储按查询推出的 (user_id, type, entity) 返回直接命中。
3. 图存储返回从查询实体可达的子图。
4. 打分层融合三者。

### 融合打分

```
score = w_relevance * relevance(q, record)
      + w_importance * importance(record)
      + w_recency * recency(record)
```

- **相关性** —— 向量余弦、KV 精确匹配、图路径权重。
- **重要性** —— 写入时打标或学习得到(有些事实更重要:姓名、ID、政策)。
- **新近度** —— 距上次写入或读取的时间做指数衰减。

权重按产品调:聊天智能体调高 `w_recency`;合规智能体调高 `w_importance`;检索智能体调高 `w_relevance`。

### Mem0g 与时间推理

Mem0g 加了冲突检测器:新事实与现有边矛盾时,旧边标记为失效但不删除。时间查询("用户 3 月住哪个城市?")遍历"当时有效"的子图。

这就是 Letta 失效模式推广的合规级行为。

### 基准数字

Mem0 论文报告(2025):

- **LoCoMo**(长对话记忆):91.6
- **LongMemEval**(长程情景记忆):93.4
- **BEAM 1M**(100 万 token 记忆基准):64.1

对比基线(全上下文 128k LLM、平向量存储、平 KV)全都落后 10 分以上。光靠基准数字不足以下定论——运行形态才是——但数字说明融合设计不是四舍五入的误差。

### 作用域分类

Mem0 按作用域切分记忆:

- **用户记忆** —— 跨会话持久,以 `user_id` 为键。
- **会话记忆** —— 单线程内持久。
- **智能体记忆** —— 逐智能体实例的状态。

每次写入选定一个作用域。检索可跨作用域查询,带逐作用域权重。不假思索混用作用域,就会出"助手把 Bob 的项目告诉了 Alice"这类事故。

### 这个模式在哪里出错

- **嵌入漂移。** 前一百次查询看着对的向量结果,随语料增长会退化。对最常被用的 top-N 记录定期重新嵌入。
- **KV schema 蔓延。** `(user_id, type, entity)` 看着简单,直到每个团队都加自己的 `type`。每季度审计一次类型集合。
- **图爆炸。** 一个嘈杂的抽取器,每条消息加 50 条边。给每次 `add` 调用的图写入设上限;丢弃低置信边。

## 动手构建

`code/main.py` 用纯标准库实现三存储模式:

- `VectorStore` —— 朴素 token 重叠相似度,充当嵌入替身。
- `KVStore` —— 以 `(user_id, fact_type, entity)` 为键的 dict。
- `GraphStore` —— 带类型的边(subject, relation, object, valid)。
- `Mem0` —— 顶层门面:`add()`、`search()`、融合打分、作用域感知检索。
- 一段多用户、多会话对话的完整轨迹。

运行:

```
python3 code/main.py
```

输出展示三条独立召回路径,外加融合的 top-k。改动 `main()` 顶部的打分权重,看排序如何变化。

## 投入使用

- **Mem0(Apache 2.0)** —— 生产就绪。用 Postgres + Qdrant + Neo4j 自托管,或用托管云。
- **Letta** —— core/recall/archival 三层;向量和图后端自带。
- **Zep** —— 商用替代,带时间知识图谱和事实抽取。
- **自建** —— 需要精确控制抽取器(合规)或融合权重(新近度主导的语音智能体)时。

## 练习

1. 把玩具向量相似度换成真嵌入模型(sentence-transformers、Ollama、OpenAI embeddings)。在合成长对话上测 recall@10。写入 1000 条后排序会漂移吗?
2. 加时间查询:`search(query, as_of=timestamp)`,只返回该时刻及之前有效的记录。哪个存储改动最大?
3. 实现冲突检测器:传入事实与图边矛盾时,作废旧边并两者都记日志。用"user lives in Berlin" → "user lives in Lisbon"测试。
4. 给融合打分器加 `user_feedback` 维度(对检索到的记录点赞)。如何防止被钻空子(智能体只返回它已经点过赞的记录)?
5. 读 Mem0 文档(`docs.mem0.ai`)。把玩具移植到 `mem0` 客户端调用。在同样 20 个测试查询上对比检索质量。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| 混合记忆 | "向量加图加 KV" | 三存储并行写入,检索时融合 |
| 事实抽取 | "记忆摄取" | 把文本拆成 (entity, relation, fact) 元组的 LLM 步骤 |
| 融合打分 | "相关性排序" | 相关性、重要性、新近度的加权求和 |
| 作用域 | "记忆命名空间" | user / session / agent——决定谁看到什么 |
| Mem0g | "记忆图" | 带时间有效期的带类型边,供关系查询 |
| 时间失效 | "软删除" | 被推翻的边标记失效;永不删除 |
| 嵌入漂移 | "检索腐化" | 语料增大,向量质量退化;定期重新嵌入 |
