# Anthropic 的工作流模式:简单先于复杂

> Schluntz 与 Zhang(Anthropic,2024 年 12 月)区分了工作流(预定义路径)与智能体(动态工具使用)。五种工作流模式覆盖大多数情形。从直接 API 调用开始;只有当步骤无法预知时才加智能体。

**类型:** 学习 + 动手构建
**编程语言:** Python(标准库)
**前置要求:** 第 14 阶段 · 01(智能体循环)
**预计耗时:** 约 60 分钟

## 学习目标

- 说出 Anthropic 的五种工作流模式:提示词链、路由、并行化、编排器-工人、评估器-优化器。
- 解释智能体与工作流的区分,以及各自的工程成本。
- 识别何时选工作流、何时选智能体。
- 对着一个脚本化 LLM,用纯标准库实现全部五种模式。

## 问题

很多团队为一个本该是一次函数调用的问题,搬来了多智能体框架。代价是真实的:框架加了一层又一层,掩盖提示词、藏起控制流、招致过早复杂化。Schluntz 与 Zhang 2024 年 12 月的文章是被引最多的业界回击:从简单开始,只在复杂度配得上它的成本时才加。

## 概念

### 工作流 vs 智能体

- **工作流。** LLM 和工具沿预定义代码路径编排。图归工程师所有。
- **智能体。** LLM 动态指挥自己的工具、走自己的步骤。图归模型所有。

两者各有其位。工作流更便宜、更快、更好调试;智能体解锁开放式问题,但失败模式更难推理。

### 增强 LLM

所有五种模式的地基:一个 LLM,接好三种能力——搜索(检索)、工具(动作)、记忆(持久化)。任何 API 调用都能用它们。

### 五种模式

1. **提示词链(prompt chaining)。** 调用 1 的输出是调用 2 的输入。任务有干净的线性分解时用。步骤之间可加程序化闸门。

2. **路由(routing)。** 一个分类器 LLM 决定调用哪个下游 LLM 或工具。类别迥异的输入需要不同处理时用(一线支持 vs 退款 vs bug vs 销售)。

3. **并行化(parallelization)。** 并发跑 N 个 LLM 调用,聚合结果。两种形状:分片(不同块各给一路)和投票(同一提示词跑 N 次,多数决/综合)。

4. **编排器-工人(orchestrator-workers)。** 编排器 LLM 动态决定跑哪些 worker(也是 LLM),并综合它们的输出。类似智能体循环,但编排器不会无限循环。

5. **评估器-优化器(evaluator-optimizer)。** 一个 LLM 提答案,另一个 LLM 评答案,迭代到评估器通过。这就是推广了的 Self-Refine(第 05 课)。

### 工作流胜过智能体的地方

- **可预测的任务。** 步骤能枚举,就该枚举。
- **成本受限的任务。** 工作流步数有界;智能体可能螺旋失控。
- **合规约束的任务。** 审计要读的是图,不是从轨迹里反推。

### 智能体胜过工作流的地方

- **开放式研究。** 下一步取决于上一步返回了什么。
- **变长任务。** 几分钟到几小时的工作,步数事先未知。
- **新领域。** 还不知道正确的工作流是什么——先探索,后固化。

## 动手构建

`code/main.py` 对着一个 `ScriptedLLM` 实现全部五种工作流模式:

- `prompt_chain(input, steps)` —— 顺序。
- `route(input, classifier, handlers)` —— 分类 + 派发。
- `parallel_vote(prompt, n, aggregator)` —— 跑 N 次,聚合。
- `orchestrator_workers(task, workers)` —— 编排器挑 worker。
- `evaluator_optimizer(task, proposer, evaluator, max_iter)` —— 循环直到通过。

运行:

```
python3 code/main.py
```

每个模式打印自己的轨迹。每个模式约 10–15 行代码;框架的成本以千行计。

## 练习

1. 实现带置信度阈值的路由:低于阈值就升级人工。一线支持场景的阈值定在哪?
2. 给 `parallel_vote` 加超时。一个调用挂住会怎样?缺票时如何聚合?
3. 把 `evaluator_optimizer` 改成老虎机式:跨迭代保留 top-2 输出,别让晚到的好结果被晚到的坏结果覆盖。
4. 组合提示词链与路由:路由器在三条链里挑一条。测量 token 成本,与单个大提示词方案对比。
5. 挑你的一个生产功能,画出它的工作流图,数步骤。这里用智能体真的更好吗?

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| 工作流 | "预定义的流" | 工程师拥有的 LLM 与工具调用图 |
| 智能体 | "自主 AI" | 模型拥有的图;动态工具指挥 |
| 增强 LLM | "带工具的 LLM" | LLM + 搜索 + 工具 + 记忆;原子单元 |
| 提示词链 | "顺序调用" | 调用 N 的输出是调用 N+1 的输入 |
| 路由 | "分类派发" | 挑选哪条链/哪个模型处理输入 |
| 并行化 | "扇出" | N 个并发调用;按分片或投票聚合 |
| 编排器-工人 | "派发智能体" | 编排器 LLM 动态挑选专家 LLM |
| 评估器-优化器 | "提议者 + 裁判" | 迭代到评估器通过;推广版 Self-Refine |
