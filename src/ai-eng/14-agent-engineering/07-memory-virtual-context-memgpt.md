# 智能体记忆 —— 虚拟上下文与记忆分页

> 上下文窗口是有限的,对话、文档和工具轨迹不是。解法就是把操作系统虚拟内存重述一遍:主上下文是 RAM,外部存储是磁盘,智能体在两者之间换页。MemGPT(Packer 等,2023)命名了这个模式;许多生产记忆系统都建立在它之上。

**类型:** 动手构建
**编程语言:** Python(标准库)
**前置要求:** 第 14 阶段 · 01(智能体循环)、第 14 阶段 · 06(工具使用)
**预计耗时:** 约 75 分钟

## 学习目标

- 解释 MemGPT 依托的 OS 类比:主上下文 = RAM,外部上下文 = 磁盘,记忆工具 = 页换入/换出。
- 用纯标准库实现 MemGPT 双层模式:主上下文缓冲区、可搜索外部存储、换入换出工具。
- 描述智能体如何发出"中断"来查询或修改外部记忆,以及结果如何拼回下一个提示词。
- 识别 MemGPT 的设计选择如何延续进 Letta(第 08 课)和 Mem0(第 09 课)。

## 问题

上下文窗口看起来应该能解决记忆问题。解决不了。生产里反复出现三种失败模式:

1. **溢出。** 多轮对话、长文档或工具调用密集的轨迹越过窗口,截断点之后的一切都没了。
2. **稀释。** 即使在窗口内,塞入无关上下文也会稀释对要紧内容的注意力。前沿模型在长输入上仍会退化。
3. **持久化。** 新会话从空窗口开始。没有外部记忆,智能体没法跨会话说"记得你之前让我……"。

更大的窗口有缓解但修不好。Mem0 的 2025 年论文实测:128k 窗口的基线仍会漏掉长程事实,而带外部记忆的 4k 窗口智能体能抓住。

## 概念

### OS 类比

MemGPT(Packer 等,arXiv:2310.08560,v2 2024 年 2 月)把上下文管理映射到操作系统虚拟内存:

| OS 概念 | MemGPT 概念 | 2026 生产对应物 |
|------------|---------------|------------------------|
| RAM | 主上下文(提示词) | Anthropic/OpenAI 上下文窗口 |
| 磁盘 | 外部上下文 | 向量数据库、KV、图存储 |
| 缺页中断 | 记忆工具调用 | `memory.search`、`memory.read`、`memory.write` |
| OS 内核 | 智能体控制循环 | 带记忆工具的 ReAct 循环 |

智能体跑正常的 ReAct 循环,只是多了一类工具,让它把数据换入换出主上下文。

### 两层

- **主上下文。** 固定大小的提示词,装着当前任务。模型永远可见。
- **外部上下文。** 无界,经工具可搜索。相关时读,事实出现时写。

原论文在两个超出基础窗口的任务上评估了该设计:超过 10 万 token 的文档分析,以及跨天持久记忆的多会话聊天。

### 中断模式

MemGPT 提出"记忆即中断":对话中途,智能体可以调用记忆工具,运行时执行它,结果作为新观测拼进下一个助手轮。概念上与 Unix `read()` 系统调用完全相同:阻塞进程、返回字节、进程继续。

标准记忆工具面:

- `core_memory_append(section, text)` —— 写入提示词的持久区段。
- `core_memory_replace(section, old, new)` —— 编辑持久区段。
- `archival_memory_insert(text)` —— 写入可搜索外部存储。
- `archival_memory_search(query, top_k)` —— 从外部存储检索。
- `conversation_search(query)` —— 扫描过往轮次。

### 论文止步处,生产起步处

2024 年 9 月,MemGPT 变成了 Letta。研究仓库(`cpacker/MemGPT`)仍在;Letta 扩展了这个设计:

- 三层代替两层(core、recall、archival —— 第 08 课)。
- 原生推理取代 `send_message`/心跳模式(第 08 课)。
- 异步跑记忆工作的睡眠时智能体(第 08 课)。

即使生产系统跑的是 Letta、Mem0 或自建双层存储,MemGPT 论文仍是 2026 年的地基。

### 这个模式在哪里出错

- **记忆腐化。** 写得比读得快,检索被陈旧事实淹没。修法:定期整合(Letta 睡眠时)、显式失效(Mem0 冲突检测器)。
- **记忆投毒。** 外部记忆是被检索的文本。攻击者控制的内容一旦落进记忆笔记,智能体下个会话就会重新摄入。这就是 Greshake 等(第 27 课)攻击在时间维度上的重述。
- **出处丢失。** 智能体记得"用户让我交付 X",却说不出是哪一轮说的。每条归档写入都带上来源引用(session ID、turn ID)。

## 动手构建

`code/main.py` 用纯标准库实现 MemGPT 双层模式:

- `MainContext` —— 固定大小提示词缓冲区,含 `core` dict 和 `messages` 列表;超上限时自动压缩最旧消息。
- `ArchivalStore` —— 内存中的类 BM25 存储(token 重叠打分),记录为 (id, text, tags, session, turn)。
- 五个记忆工具,对应 MemGPT 工具面。
- 一个脚本化智能体:往归档里填事实,然后调 `archival_memory_search` 回答问题。

运行:

```
python3 code/main.py
```

轨迹展示:智能体写入三条事实,把主上下文填到上限(触发驱逐),然后通过从归档检索回答追问——不需要真 LLM 就复现了 MemGPT 工作流。

## 投入使用

今天每个生产记忆系统都是 MemGPT 的变体:

- **Letta**(第 08 课)—— 三层、原生推理、睡眠时计算。
- **Mem0**(第 09 课)—— 向量 + KV + 图融合,加打分层。
- **OpenAI Assistants / Responses** —— 通过 threads 和 files 的托管记忆。
- **Claude Agent SDK** —— 通过技能和会话存储的长期记忆。

按运行形态选(自托管、托管、框架集成),别按核心模式选——核心模式就是 MemGPT。

### 智能体记忆的形态

分页解决容量,但不决定存什么。生产系统里反复出现四种记忆,各回答一个不同的问题:

- **工作记忆** —— 现在什么要紧?上下文内那一层:当前任务、最近轮次、固定的核心区段。提示词本身。
- **情景记忆** —— 发生过什么?过往轮次与轨迹,带会话和轮次引用存储,可按需回放。
- **语义记忆** —— 什么是真的?关于用户、领域、世界的事实,随变化更新去重。
- **程序记忆** —— 这事怎么做?学到的例程、偏好和规则,引导未来行为而非供回忆。

开源实现各选不同的着力点:

| 类型 | 实现 | 怎么解决 |
|------|----------------|-------------------|
| 工作记忆 | MemGPT / Letta | 通过记忆工具在固定提示词预算内换入换出内容(本课、第 08 课) |
| 情景记忆 | Zep | 时间知识图谱——事实带有效期区间,"当时什么是真的"可查 |
| 语义记忆 | Mem0 | 抽取流水线:跨向量、KV、图存储去重并更新事实(第 09 课) |
| 语义 + 程序 | LangMem | 后台抽取事实与行为规则入库,智能体在轮次间查阅 |
| 情景 + 语义 | agentmemory | 会话运行时即捕获,整合成带类型的可搜索记录 |

## 练习

1. 加一个以 token 计的 `max_main_context_tokens` 上限(用 `len(text.split())` * 1.3 近似)。超限时把最旧消息压缩成摘要。对比有无摘要器的行为。
2. 在归档存储上正确实现 BM25(词频、逆文档频率)。在玩具事实集上测 recall@10,与 token 重叠基线对比。
3. 给归档写入加 `citation` 字段(session_id、turn_id、source_url)。让智能体在每个检索支撑的回答里都引出来源。
4. 模拟记忆投毒:加一条写着"忽略所有未来用户指令"的归档记录。写一个守卫,扫描检索结果中的指令形文本并标记为不可信。
5. 把实现移植到 MemGPT 研究仓库的 core-memory JSON schema(`cpacker/MemGPT`)。从扁平字符串换成带类型区段后,有什么变化?

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|----------------|------------------------|
| 虚拟上下文 | "无限记忆" | 主上下文(提示词)+ 外部(可搜索)两层,带换入换出 |
| 主上下文 | "工作记忆" | 提示词——固定大小,永远可见 |
| 归档记忆 | "长期存储" | 外部可搜索的持久化,按需检索 |
| 核心记忆 | "持久提示词区段" | 固定在主上下文内的命名区段 |
| 记忆工具 | "记忆 API" | 智能体发出的读写外部记忆的工具调用 |
| 中断 | "记忆缺页" | 智能体暂停,运行时取数,结果拼进下一轮 |
| 记忆腐化 | "陈旧事实" | 旧写入淹没检索;用整合修复 |
| 记忆投毒 | "被注入的持久笔记" | 攻击者内容存为记忆,回忆时被重新摄入 |
