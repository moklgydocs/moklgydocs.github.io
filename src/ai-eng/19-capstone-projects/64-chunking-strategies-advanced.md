# 分块策略大对比

> 分块决定了你的检索器永远能捞到什么。边界切错了,下游没有任何嵌入模型、重排器、LLM 能修补这个伤害。

**类型:** 动手构建
**编程语言:** Python
**前置要求:** 第 11 阶段第 04 课(嵌入)、06(RAG)、07(高级 RAG);第 19 阶段 Track B 基础(第 20-29 课)
**预计耗时:** 约 90 分钟

## 学习目标
- 从零实现五种分块策略:固定窗口、按句、递归切分、语义聚类、结构化 Markdown 标题。
- 在带金标答案跨度的样本语料上测 recall@k,并解释为什么散文上一种策略赢、技术文档上另一种赢。
- 读懂块长度分布,认出每种策略注入的失效模式:孤儿句、符号中间切断、只有标题的块、语义漂移。
- 不跑基准就为新语料选定默认策略:看三个属性——文档类型、平均段落长度、格式是否带显式结构。

## 问题

每条 RAG 流水线都从切文档开始:切到嵌入模型装得下的尺寸,又大到每块都承载一个自包含的想法。在哪里切不是超参数。它是检索器永远能返回的东西的上界。

一个问"预算中止阈值长什么样"的查询,只有在装着中止阈值的那块可达时才能成功。如果固定窗口切分器把阈值数值和上下文切开了,嵌入就飘到另一个簇,BM25 分数掉下来,重排器看到的是噪声,LLM 生成的答案就是错的。2024 年的论文《LongRAG: Enhancing Retrieval-Augmented Generation with Long-context LLMs》测出,仅分块选择就带来检索召回 35 个百分点的绝对摆幅。2025 年关于上下文块标题的后续工作缩小了差距,但没有抹平。

本课把五种策略并排建出来,在带金标答案跨度的样本语料上跑,让你亲眼读召回数字。

### 固定窗口

暴力基线。每 N 个字符切一刀。可选重叠,让在位置 N 被切断的句子完整出现在从位置 N - overlap 开始的块里。快、确定、边界处理稀烂。把它当对照组用,别当默认。

### 按句

用正则或简单状态机在句子边界切。把一句或多句打包进块,直到目标字符预算。不会在词中间下刀。还是会在段落中间、小节中间下刀。很多早期 RAG 流水线的默认项,对没有其他结构的散文是个合理选择。

### 递归切分

2023 年那批库带火的分层策略。先尝试最强的分隔符(双换行、段落),不行退到下一级(单换行),再退到句子,最后退到字符。块装进预算时递归终止。对结构不一致的文档很强,因为它按区域自适应。

### 语义聚类

给每句做嵌入。把共享主题质心的相邻句子聚成一簇。当对质心的滚动相似度跌破阈值时下刀。边界反映的是意义,不是字符。建得慢,依赖嵌入模型,但对段落内部换主题的文档有韧性。

### 结构化 Markdown 标题

对带显式结构的文档(Markdown、reStructuredText、RFC 式编号小节),在标题边界下刀。每块是标题加它之下到下一个同级或更高级标题为止的所有内容。每个主题拿到最小的块,但只在语料格式良好时可用。

### recall@k 如何度量边界选择

一个金标查询带着答案跨度在源文档里的精确字符偏移。分块之后你问:检索器返回的前 k 块里,有没有任何一块和金标跨度重叠?有,这个查询的 recall@k 就是 1。没有,就是 0。在查询集上求平均。对每种策略跑同样的评估,分布差距告诉你哪种边界策略在你的语料上活得下来。

## 动手构建

`code/main.py` 实现了:

- `fixed_window(text, size, overlap)`——基线。
- `sentence_chunks(text, target)`——简单句子打包器。
- `recursive_split(text, separators, target)`——分层递归。
- `semantic_chunks(text, similarity_threshold)`——在确定性模拟嵌入上做质心聚类。
- `structural_markdown(text)`——标题感知切分器。
- `mock_embed(text, dim)`——基于哈希的嵌入,让循环离线可跑。
- `DenseIndex`——和第 19 阶段 Track B 混合检索课用的同一个形状。
- `eval_recall(strategy, corpus, queries, k)`——对比循环。
- `main()`:在样本语料上跑每种策略,打印 recall@k 表。

运行:

```bash
python3 code/main.py
```

输出是一张小表,每行一个策略,每列一个 k。按句在结构化样本上输。结构化 Markdown 在 Markdown 样本上赢。递归切分在混合样本上站得住,因为递归会自适应。语义聚类在散文样本上赢,那里没有可用的结构线索。

## 表格藏不住的失效模式

**孤儿句。** 按句打包产出的块丢掉了主题句。嵌入随后指向错误的簇。

**符号中间切断。** 固定窗口切进代码或 YAML,会把一个标识符劈成两半。两半各自嵌入成噪声。

**只有标题的块。** 结构化 Markdown 会吐出只含 `## Title` 的块。滤掉它们,或者把下一块的第一段并进来。

**语义漂移。** 语料全在同一主题时,语义聚类切得太少。一个 5000 字符的块把许多具体答案塞进一个弥散的嵌入。语义策略要配一个硬字符上限。

**嵌入过期。** 语义聚类用嵌入模型。你换模型,块也跟着变。把分块模型和检索模型分开钉版本,或者一起重建索引。

## 不跑基准选默认

三个属性决定新语料的默认分块器。

| 属性 | 取值 | 默认 |
|----------|-------|---------|
| 文档类型 | 无结构散文 | 递归切分,目标 800 |
| 文档类型 | Markdown / RFC / API 文档 | 结构化 Markdown |
| 文档类型 | 代码 | AST 感知(超出本课范围;见第 19 阶段第 02 课) |
| 段落长度 | 长、单主题 | 按句,目标 500 |
| 段落长度 | 短、多主题混杂 | 语义,阈值 0.6 |

拿不准就选递归切分。它是最强的单策略基线。

## 投入使用

生产模式:

- 新流水线发布前先跑评估;别信你的库的默认策略。
- 换嵌入模型或语料配比时重跑评估;赢家随语料而变。
- 把策略名写进每块的元数据,之后回归了好归因。

## 练习

1. 加第六种策略:用 `tiktoken` 按 token 窗口而不是字符数。在同一样本上对比固定窗口。
2. 往散文样本里注入 30% 的代码块。重跑表格。解释为什么除结构化 Markdown 外每种策略都掉召回。
3. 把确定性嵌入换成你项目真实供应商的嵌入。测语义聚类的召回差值。报告策略间差距是变宽还是收窄。
4. 给每块加 `summary` 字段:一句质心描述。把 summary 拼到块正文后重跑评估。测召回提升。

## 关键术语

| 术语 | 大家嘴里的说法 | 实际含义 |
|------|-----------------|------------------------|
| Recall@k | "捞对块了吗?" | 前 k 块中有任一块与金标答案跨度重叠的查询占比 |
| 块重叠 | "滑动窗口" | 把上一块的最后 N 个字符重新含进下一块 |
| 结构化切分器 | "标题感知块" | 在 H1/H2/H3 边界下刀;标题文本算块的一部分 |
| 语义分块器 | "主题感知块" | 嵌入句子,按质心相似度聚类,漂移时下刀 |
| 质心漂移 | "换主题" | 滚动均值与下一句的余弦相似度跌破阈值 |
