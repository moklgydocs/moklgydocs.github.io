# Qwen-VL 家族与动态 FPS 视频

> Qwen-VL 家族——Qwen-VL(2023)、Qwen2-VL(2024)、Qwen2.5-VL(2025)、Qwen3-VL(2025)——是 2026 年最有影响力的开放视觉语言模型谱系。每一代都做了一个决定性的架构押注,而开放生态总会在十二个月内跟进:经 M-RoPE 的原生动态分辨率、带绝对时间对齐的动态 FPS 采样、ViT 里的窗口注意力、结构化智能体输出格式。到 Qwen3-VL,配方已经稳定:吃原生宽高比输入的 2D-RoPE-ViT 编码器、一个接入 Qwen3 大语言基座的 MLP 投影器,以及把 OCR、定位和智能体行为当一等公民的训练阶段。本课按时间顺序读完整个家族,让你明白每个旋钮为什么在它现在的位置。

**类型:** 学习
**编程语言:** Python(标准库,M-RoPE 编码器 + 动态 FPS 采样器)
**前置要求:** 第 12 阶段第 06 课(patch-n'-pack)
**预计耗时:** 约 120 分钟

## 学习目标

- 计算 M-RoPE 的三轴旋转(时间、高、宽),并解释为什么三者缺一不可。
- 为一段视频挑选动态 FPS 采样策略,并推理 token/秒 与事件检测准确率的关系。
- 按顺序说出 Qwen-VL 的四代升级及各自解锁了什么。
- 接好 Qwen2.5-VL 式 JSON 智能体输出格式,从 VLM 响应中解析结构化工具调用。

## 问题

2023 年 8 月发布的 Qwen-VL,是对 LLaVA-1.5 和 BLIP-2 的直接回应。Qwen 团队瞄准的差距有三个:分辨率、视频、结构化输出。

**分辨率**:LLaVA-1.5 跑在 336x336。拍照片够用,对中文发票或密集电子表格截图就没用。Qwen-VL 的第一个创新是 448x448 和带定位的边界框输出,让模型能"指东西"。

**视频**:Video-LLaMA 把逐帧编码器堆起来喂给 LLM。短片段能跑通,多分钟视频不行——那里时间轴才是信号。Qwen 团队想要一个理解时间的编码器。

**结构化输出**:LLaVA 输出自由文本,智能体要的是 JSON。Qwen-VL 在显式 JSON 输出格式上训练,包括以文本形式输出的边界框坐标。

此后的每一代 Qwen-VL,都在这三根轴之一上做延伸。

## 概念

### Qwen-VL(2023 年 8 月)

第一代:OpenCLIP ViT-bigG/14 作编码器(25 亿参数)、兼容 LLaMA 的 Q-Former(256 查询、单步)、Qwen-7B 基座。贡献:

- 448x448 分辨率(当时开放 VLM 的 SOTA)。
- 定位(grounding):在带显式坐标 token 输出的图文对上训练。"The cat is at <box>(112, 204), (280, 344)</box>"。
- 从第一天起就是中英双语训练。

当时基准:英文上与 GPT-4V 有竞争力,中文上碾压。定位监督才是真正的头条。

### Qwen2-VL(2024 年 9 月)—— M-RoPE 与原生分辨率

Qwen2-VL 把 固定分辨率 + Q-Former 的栈,换成了原生动态分辨率 ViT 编码器。关键变化:

- **原生动态分辨率。** ViT 接受任何能被 28 整除的 HxW(patch 14,带 2 倍空间合并)。1120x672 的图(合并后 40x24 个 patch)产出 960 个视觉 token。不缩放、不平铺、不要缩略图。
- **M-RoPE(多模态 RoPE)。** 每个 token 携带 3D 位置 (t, h, w),而不是 1D。图像 t=0,视频 t = 帧索引。RoPE 按每轴频率旋转 query/key 向量。没有位置嵌入表。
- **MLP 投影器。** 扔掉 Q-Former,在合并后的 patch token 上用 2 层 MLP。
- **动态 FPS 视频。** 默认 1–2 FPS 采样,但模型接受任意帧数。

结果:Qwen2-VL-7B 在多个多模态基准上追平 GPT-4o,DocVQA 上反超(94.5 对 88.4)。架构之变是决定性一步。

### Qwen2.5-VL(2025 年 2 月)—— 动态 FPS + 绝对时间

Qwen2.5-VL 的大动作在视频。动态 FPS 不只是"需要时多抽帧",论文把它形式化了:

- **绝对时间 token。** 不用位置索引(第 0、1、2 帧……),改用真实时间戳。"At 0:04, the cat jumps." 模型在帧 token 之间看到 `<time>0.04</time>` token。
- **动态 FPS。** 慢镜头 1 FPS,动作画面 4+ FPS。由用户或训练方选择,M-RoPE 自适应。
- **ViT 窗口注意力。** 空间注意力窗口化(块内局部)保吞吐,每隔几层插一次全局注意力。
- **显式 JSON 输出格式。** 在工具调用数据上训练:`{"tool": "click", "coords": [380, 220]}`。开箱即是智能体。
- **MRoPE-v2 缩放。** 位置随最大输入尺寸缩放,10 分钟视频也不会耗尽频率范围。

基准:Qwen2.5-VL-72B 在多数视频基准上击败 GPT-4o,文档上追平 Gemini 2.0,并创下开放模型 GUI 定位的 SOTA(ScreenSpot:84% 准确率,GPT-4o 只有 38%)。

### Qwen3-VL(2025 年 11 月)

Qwen3-VL 是巩固式升级,不是重新发明:更大的 LLM 骨干(Qwen3-72B)、更多训练数据、更好的 OCR、经 Qwen3"思考模式"的更强推理。ViT 和 M-RoPE 原样保留。论文重点在数据与训练改进,而非架构。

谱系启示:到 2025 年,Qwen-VL 的架构已经稳定。后续的代际,扩的是算力与数据,不是原语。

### M-RoPE 的数学

经典 RoPE 用配对坐标,按位置 `m` 旋转 d 维 query `q`:

```
q_rot[2i]   = q[2i]   * cos(m * theta_i) - q[2i+1] * sin(m * theta_i)
q_rot[2i+1] = q[2i]   * sin(m * theta_i) + q[2i+1] * cos(m * theta_i)
theta_i     = 10000^(-2i/d)
```

M-RoPE 把隐藏维度分成三段。设 `d = 96`:32 维给时间、32 维给高、32 维给宽。每段按自己那根轴的位置旋转。(t=5, h=10, w=20) 处的 patch,三段分别施加旋转 `R_t(5)`、`R_h(10)`、`R_w(20)`。

文本 token 用 `t = 文本索引, h = 0, w = 0`(或某种归一化选择),保持兼容;视频帧用 `t = 帧时间, h = 行, w = 列`;单图用 `t = 0`。

好处:一套位置编码同时处理文本、图像和视频,不用分支代码,不用不同的位置表。

### 动态 FPS 采样逻辑

给定时长 `T` 秒的视频和 token 预算 `B`:

1. 算你负担得起的最大 FPS:`fps_max = B / (T * 每帧token数)`。
2. 从 `{1, 2, 4, 8}` 中挑一个满足 `fps <= fps_max` 的目标 FPS。
3. 运动剧烈(光流启发式或用户显式要求)选高 FPS;运动平缓选低 FPS。
4. 按选定 FPS 均匀采样;帧间插入 `<time>t</time>` token。

Qwen2.5-VL 在训练中内化了这套逻辑;推理时用户通过 `fps` 参数控制。60 秒动作片段,4 FPS、每帧 81 token = 19440 token,3.2 万上下文装得下。

### 结构化智能体输出

Qwen2.5-VL 的智能体训练,显式瞄准结构化工具调用:

```
{
  "tool": "mouse_click",
  "coords": [1024, 512],
  "button": "left",
  "modifier": null
}
```

解析是确定性的:对模型输出 JSON.parse。对比自由文本 "click at (1024, 512)" 需要的正则和歧义处理,天壤之别。这正是 Qwen2.5-VL 的 ScreenSpot 从 Qwen2-VL 的 55% 跳到 84% 的原因。

## 关键术语

| 术语 | 人们常说的是 | 实际含义是 |
|------|-----------------|------------------------|
| M-RoPE | "多模态 RoPE" | 隐藏维度按 时间、高、宽 分段的 3D 旋转位置嵌入 |
| 动态 FPS | "聪明采样" | 按运动、时长和 token 预算,为每段视频选择抽帧率 |
| 绝对时间 token | "时间戳 token" | 序列中交错的 `<time>t</time>`,让模型看到真实秒数而非帧索引 |
| 窗口注意力 | "局部注意力" | 空间自注意力限制在小窗口内求速度;周期性插入全局注意力 |
| 结构化智能体输出 | "JSON 模式" | 用训练监督教 VLM 输出可解析的、含坐标和工具名的 JSON |
| min_pixels / max_pixels | "分辨率上下界" | Qwen2.5-VL 的按请求控制,给总像素数(从而 token 数)设上下界 |
| 定位(grounding) | "指给它看" | 以文本 token 形式输出边界框坐标;自 Qwen-VL v1 起就有 |
