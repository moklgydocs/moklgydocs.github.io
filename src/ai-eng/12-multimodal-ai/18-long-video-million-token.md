# 百万 token 上下文下的长视频理解

> 一段 1 小时 4K、24 FPS 的视频,切 patch 再嵌入,产出约 6000 万 token。一期 2 小时播客转录下来是 3 万 token。一部完整蓝光电影,即使用激进池化压缩,也是几十万 token。Google 的 Gemini 1.5(2024 年 3 月)以 1000 万 token 上下文开启了这个时代:对一小时长的视频做可靠的大海捞针召回。LWM(Liu et al., 2024 年 2 月)展示了 ring attention 的扩展路径;LongVILA 和 Video-XL 把摄入规模推得更远;VideoAgent 则把原始上下文换成智能体检索。每条路都是在算力、召回和工程复杂度之间的不同取舍。本课把它们并排读。

**类型:** 动手构建
**编程语言:** Python(标准库,大海捞针模拟器 + 智能体检索路由器)
**前置要求:** 第 12 阶段第 17 课(视频时间 token)
**预计耗时:** 约 180 分钟

## 学习目标

- 在不同 FPS 与池化下,计算长视频的视觉 token 总量。
- 解释三条扩展路径:硬堆上下文(Gemini 1.5)、ring attention(LWM)、token 压缩(LongVILA / Video-XL)。
- 从准确率与延迟,对比原始上下文视频 VLM 与智能体检索视频 VLM(VideoAgent)。
- 为 30 分钟视频设计大海捞针测试,测量特定分钟处的召回。

## 问题

Qwen2.5-VL 尺寸的 patch,384 原生分辨率,一帧约 729 token;3x3 池化后每帧 81 token。30 分钟、1 FPS = 1800 帧 = 145,800 token。2025 年的开放 VLM 装得下,但很紧。2 FPS 就是 291,600 token——只有最大的上下文装得下。

2 小时电影、1 FPS 是 58.3 万 token。超出多数 2026 开放模型;需要 Gemini 2.5 Pro,或更激进的池化。

三条扩展路径由此出现。

## 概念

### 路径 1:硬堆上下文(Gemini 1.5、Claude Opus)

用硬件砸问题:把上下文扩到数百万 token,一次前向处理全部。

Gemini 1.5 Pro 发布时 100 万 token;Gemini 1.5 Ultra 到 1000 万;2026 年的 Gemini 2.5 Pro 能可靠处理数小时视频。论文(arXiv:2403.05530)记录:约 950 万 token 内,大海捞针召回 99.7%。

工程上:定制注意力实现,带内存层级(局部 + 全局 + 稀疏),外加 MoE 专家路由做长上下文效率。细节未完全公开,不开源。

### 路径 2:Ring attention(LWM、LongVILA)

Ring attention 把长序列按"环"分布到多设备:每个设备持有一段,把自己的段发给环上的下一个设备,算部分注意力,再聚合。

LWM(Liu et al., 2024)以此训出 100 万 token 上下文模型。训练算力随上下文线性增长,而非平方——注意力的平方开销被摊到环上的设备里。

LongVILA(arXiv:2408.10188)把这个模式适配到 VLM:1400 帧视频、每帧 192 token = 26.8 万上下文,用 8 路并行的 ring attention 训练。

### 路径 3:Token 压缩(Video-XL、LongVA)

比硬堆上下文便宜:在 LLM 看到序列之前,先激进压缩。

Video-XL(arXiv:2409.14485)用视觉摘要 token:每段 N 帧产出一个 attend 全部 N 帧的"摘要"token。推理时,LLM 每段只看到一个摘要 token,上下文大幅缩水。

LongVA 用"长上下文迁移"技术,把 LLM 上下文从 20 万扩到 200 万:在长上下文文本上训练,经共享表示迁移到长上下文视频。

token 压缩拿特定时间戳的召回换可扩展性。模型大致知道发生了什么,但有时会错过确切帧。

### 路径 4:智能体检索(VideoAgent)

不把整段视频喂给 LLM,而是把视频当数据库,用 LLM 去查。

VideoAgent(arXiv:2403.10517):

1. LLM 读问题。
2. LLM 向检索工具要相关片段("给我看有猫的段落")。
3. 工具返回匹配的片段时间戳。
4. LLM 通过 VLM 读这些片段。
5. LLM 组织答案,或继续追问。

这是 LLM-as-agent 模式用在长视频上。推理更省(只编码相关片段),工程更难(检索质量成为瓶颈)。

### 大海捞针基准

标准长上下文测试:在视频随机位置插入一个独特的视觉或文本标记,再问一个必须回忆起它才能答的问题。

指标:跨视频长度与标记位置的 Recall@k。

Gemini 2.5 Pro 在 90 分钟视频内召回 >99%。开放 72B 模型(Qwen2.5-VL-72B、InternVL3-78B)30 分钟时约 85–90%,过 60 分钟退化。

VideoAgent 在 2 小时以上能追平或击败原始上下文模型——只要检索工具够好,大海里的针就能被捞到。

### 选哪条路

- 15 分钟片段、要前沿准确率:开放 72B + 原生上下文通常够。选 Qwen2.5-VL-72B。
- 30 分钟到 1 小时:开放选 LongVILA 或 Video-XL;闭源选 Gemini 2.5 Pro。质量门槛重要——要前沿就闭源。
- 2 小时以上:VideoAgent 或类似检索模式。或者,先摘要成小片段,再喂层级摘要。

### 2026 年生产模式

实践中,生产长视频流水线是混合式:

1. 对整段视频跑 动态 FPS 采样 + 激进池化(得到 10 万 token 的全局表示)。
2. 喂给 72B VLM 出全局摘要。
3. 用户问细节时,以摘要为索引跑智能体检索。

硬堆上下文管全局理解,智能体检索管局部细节,两全。

## 关键术语

| 术语 | 人们常说的是 | 实际含义是 |
|------|-----------------|------------------------|
| 硬堆上下文 | "就是多给 token" | 把 LLM 上下文扩到数百万 token,一次前向处理全部 |
| Ring attention | "LWM 式并行" | 每个设备持有一段并轮转传递的分布式注意力模式 |
| Token 压缩 | "摘要 token" | 进 LLM 前用学习到的压缩器减少每段 token |
| 大海捞针 | "NIH 测试" | 在随机点插入独特标记,测试时让模型回忆它 |
| 智能体检索 | "LLM 当查询规划器" | LLM 向检索工具要相关片段,经 VLM 阅读后组织答案 |
| VideoAgent | "视频检索模式" | 经典智能体检索设计:问题 → 工具 → 片段 → 答案 |
