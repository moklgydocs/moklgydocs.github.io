# InternVL3:原生多模态预训练

> InternVL3 之前的每一个开放 VLM,都遵循同一套三步配方:拿一个在数万亿文本 token 上训好的 LLM,接上视觉编码器,再微调接缝。能跑通,但背着对齐债——文本 LLM 把全部预训练预算花在了纯文本上,并不原生理解视觉 token。事后加视觉,LLM 就得重新学习"如何把视觉输入关联到文本推理",还不能把文本忘掉。InternVL3(Zhu et al., 2025 年 4 月)拒绝事后路线:一次预训练,文本与多模态从第一步就交错。结果:78B 参数开放模型,MMMU-Pro 追平 Gemini 2.5 Pro。本课精读原生预训练的理由,以及选了它会改变什么。

**类型:** 学习
**编程语言:** Python(标准库,训练语料混合器)
**前置要求:** 第 12 阶段第 05 课、第 12 阶段第 07 课(配方)
**预计耗时:** 约 120 分钟

## 学习目标

- 解释为什么事后 VLM 训练会积累对齐债,引述三个可测量症状(灾难性遗忘、回答漂移、文图不一致)。
- 描述 InternVL3 的原生预训练语料配比,以及 文本 : 交错 : 图文对 的比例为什么关键。
- 对比 V2PE(可变视觉位置编码)与 Qwen2-VL 的 M-RoPE。
- 说出视觉分辨率路由器(ViR)与视觉-语言解耦(DvD)这两个部署优化。

## 问题

事后 VLM 训练是默认做法。LLaVA、BLIP-2、Qwen-VL、Idefics——全都是拿一个已经预训练好的 LLM(Llama、Vicuna、Qwen、Mistral)往上加视觉。典型训练阶段:

1. 冻结 LLM + 冻结视觉编码器 + 可训练投影器,在图文对上对齐嵌入。
2. 解冻 LLM,在指令数据上训练(LLaVA-Instruct、ShareGPT4V)。
3. 可选的任务特定微调。

对齐债有三个症状会冒出来:

- **灾难性遗忘。** 事后 VLM 忘掉纯文本技能:GSM8K 掉 5–10 分,Hellaswag 掉分,纯文本智能体退化。
- **回答漂移。** 同一个视觉问题的不同措辞,得到不同答案。视觉编码器与 LLM 之间的绑定,比 LLM 自己的 token 之间的绑定弱。
- **文图不一致。** VLM 能正确描述一张图,然后回答一个与自己描述矛盾的问题。视觉 token 参与 LLM 内部一致性检查的方式,与文本不一样。

这些症状有据可查:MM1.5 第 4 节做了量化,LLaVA-OneVision 的消融也有暗示。原生预训练就是答案。

## 概念

### 原生多模态预训练

InternVL3 从零开始,语料从第一步起就是原生多模态的。配比:

- 40% 纯文本数据(FineWeb、Proof-Pile-2 等)
- 35% 图文交错数据(OBELICS、MMC4 风格)
- 20% 图文配对数据
- 5% 视频-文本数据

视觉 token、文本 token、跨模态交互,从第一个梯度步起就参与同一个损失。没有对齐预训练,没有投影器冻结阶段,没有需要补救的灾难性遗忘。

基座模型只有一个训练阶段。指令微调随后进行,但基座模型已经把视觉 token 当一等公民理解。

### V2PE(可变视觉位置编码)

Qwen2-VL 用轴分配固定的 M-RoPE。InternVL3 提出 V2PE:位置编码按模态类型(文本、图像、视频)变化,带可学习缩放。实践中:

- 文本 token 用 1D 位置(文本索引)。
- 图像 patch 用 2D 位置(行, 列)。
- 视频帧用 3D 位置(时间, 行, 列)。

三者共享同一个 RoPE 频率基,但各频段的隐藏维分配是可学习参数,而不是固定切分。预训练期间,可以在 时间频率分辨率 与 空间频率分辨率 之间自由权衡。

V2PE 的消融结论:同等算力下,视频基准上比 M-RoPE 高 1–2 分。不是革命,但更干净。

### 视觉分辨率路由器(ViR)

部署优化。不是所有图都需要全分辨率编码:一张只有一个低细节物体的照片,按 1280px 原生编码纯属浪费 token。ViR 是一个小分类器,在编码之前预测"回答这个问题所需的最低分辨率"。

路由分三档:低分辨率(256 token)、中(576)、高(2048+)。生产流量中 60% 的查询,低/中档就够。净效果:同等质量下吞吐 2–3 倍。

### 视觉-语言解耦部署(DvD)

服务大 VLM 时,视觉编码器每张图跑一次,LLM 却为每个输出 token 自回归地跑。两个组件瓶颈不同(视觉 = 卷积 + 注意力的 GPU 内存带宽;LLM = KV cache)。DvD 把它们拆到不同 GPU 上,中间流式交接。

对 8B LLM + 4 亿编码器的模型,DvD 大致让每节点吞吐翻倍(相比同机部署)。

### 单阶段 vs 多阶段的质量

InternVL3 的核心基准声明:78B 参数追平 Gemini 2.5 Pro 的 MMMU-Pro;38B 追平 GPT-4o;8B 领跑开放 8B 榜。全部基于 单阶段预训练 + 指令微调 配方。

对齐债假说是可测量的:每单位视觉基准增益,InternVL3-8B 损失的文本基准分数(MMLU、GSM8K)少于 Qwen2.5-VL-7B。这个模型更像通才,因为训练是一体的,不是两截。

### InternVL3.5 与 InternVL-U

InternVL3.5(2025 年 8 月)放大配方:同样的原生预训练,更多数据,更多参数。MMMU 提升是渐进式的。

InternVL-U(2026)加入统一生成——在同一骨干上加 MMDiT 头做图像输出。"U"代表 "Understanding + generation"(理解 + 生成),追赶 Transfusion 式统一模型(第 12.13 课)。同一个原生预训练骨干,同时支撑理解头与生成头。

### 原生预训练的代价

原生预训练不是免费的:

- **算力。** 从零训一个新 VLM,成本与训一个文本 LLM 相当——数百万 GPU 时。事后适配复用现有 LLM 权重,省下大头。
- **数据。** 大规模的图文交错语料稀缺:OBELICS 是 1.41 亿文档,MMC4 是 5.71 亿;而纯文本发货量 15 万亿 token。多模态预训练的数据荒是硬约束。
- **基座复用。** 原生预训练放弃了日后更换 LLM 的选项;事后路线让你只重训适配器,就能把 Llama-3.1 换成 Llama-4。

InternVL3 押的注是:对齐债比复用损失更痛。基准支持这个判断;生产成本则抬高了别家廉价复刻的门槛。事后 VLM 会一直存在——对多数项目它仍然更便宜。

## 投入使用

`code/main.py` 是训练语料混合器兼 ViR 路由模拟器:

- 输入目标语料配比(%文本、%交错、%图文对、%视频),计算各模态的预期步数。
- 在一批查询上模拟 ViR 路由(分布:50% 低细节、30% 中、20% 高细节),报告平均 token 数。
- 给定编码器 vs LLM 的 FLOPs,报告 DvD 吞吐估算。
- 并排打印 事后 vs 原生 预训练在参数、算力、数据和预期对齐债症状上的对比。

## 关键术语

| 术语 | 人们常说的是 | 实际含义是 |
|------|-----------------|------------------------|
| 原生多模态预训练 | "从零一起训" | 文本 + 图像 + 视频 token 从第 1 步就参与损失,而不是事后硬接 |
| 对齐债 | "事后惩罚" | 往冻结 LLM 上硬接视觉后,文本技能与回答一致性出现的可测量退化 |
| V2PE | "可变视觉位置编码" | 按模态可学习分配的位置编码;InternVL3 对 M-RoPE 的继任 |
| ViR | "分辨率路由器" | 编码前预测每个查询所需最低分辨率的小分类器,节省推理 token |
| DvD | "解耦部署" | 视觉编码器一张卡、LLM 另一张卡,流式交接;大 VLM 吞吐翻倍 |
| InternVL-U | "理解+生成统一" | 2026 年续作,在原生预训练骨干上加图像生成头 |
| 交错语料 | "OBELICS / MMC4" | 文本与图像按自然阅读顺序混排的文档;原生预训练的原材料 |
