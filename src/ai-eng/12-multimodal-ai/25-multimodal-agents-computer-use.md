# 多模态智能体与计算机操作(收官课)

> 2026 年的前沿产品,是一个能读截图、点按钮、操作网页 UI、填表单、端到端完成工作流的多模态智能体。SeeClick 和 CogAgent(2024)证明了 GUI grounding 这个原语可行;Ferret-UI 把它带到了移动端;ChartAgent 为图表引入了视觉工具调用;VisualWebArena 和 AgentVista(2026)是前沿模型正在攻的基准——就连 Gemini 3 Pro 和 Claude Opus 4.7,在 AgentVista 的难题上也只有约 30 分。这门收官课把 第 12 阶段 的所有线索收拢:感知(高分辨率 VLM)、推理(带工具调用的 LLM)、grounding(坐标输出)、长程记忆,以及评估。

**类型:** 收官课
**编程语言:** Python(标准库,动作 schema + 智能体循环骨架)
**前置要求:** 第 12 阶段 · 05(LLaVA)、第 12 阶段 · 09(Qwen-VL JSON)、第 14 阶段(智能体工程)
**预计耗时:** 约 240 分钟

## 学习目标

- 设计多模态智能体循环:感知 → 推理 → 行动 → 观察 → 重复。
- 构建一个 GUI grounding 输出 schema(点击坐标、输入文本、滚动、拖拽),让 VLM 以 JSON 形式输出。
- 对比纯截图智能体、无障碍树智能体和混合智能体。
- 在 VisualWebArena 的一个小切片上,搭建多模态智能体基准评估。

## 问题

一个订票网站的工作流:"帮我找 4 月 15 日飞东京的航班,800 美元以内的靠过道座位,订下来。"

多模态智能体需要:

1. 给浏览器截图。
2. 把截图 + URL + 目标解析成一个计划。
3. 发出结构化动作:点击(x, y)、在元素 E 处输入"Tokyo"、向下滚动、选择(单选按钮)。
4. 把动作施加到浏览器。
5. 观察新状态(下一张截图)。
6. 重复,直到任务完成。

每一步都是一次多模态 VLM 调用。VLM 输出必须是可解析的 JSON。错误会跨步累积,所以恢复机制很重要。

## 概念

### GUI grounding —— 那个原语

GUI grounding 是:给定一张截图和一句自然语言指令,输出要点击的 (x, y) 坐标(或其他动作)。

SeeClick(arXiv:2401.10935)是第一个规模化开源结果:在合成 + 真实 GUI 数据上微调 VLM,以纯文本 token 输出坐标。管用。

CogAgent(arXiv:2312.08914)加入 1120x1120 高分辨率编码,应对密集 UI。成绩:网页导航约 84%。

Ferret-UI(arXiv:2404.05719)聚焦移动端 UI,与 iOS 无障碍数据集成。

输出格式通常是 JSON:

```json
{"action": "click", "x": 384, "y": 220, "element_desc": "Search button"}
```

`element_desc` 有助于恢复:坐标在截图之间漂移时,语义提示能让系统重新 grounding。

### 动作 schema

典型动作 schema 有 6–10 种动作:

- `click`:(x, y)
- `type`:(text, x?, y?)
- `scroll`:(direction, amount)
- `drag`:(x0, y0, x1, y1)
- `select`:(option_index)
- `hover`:(x, y)
- `navigate`:(url)
- `wait`:(ms)
- `done`:(success, explanation)

智能体每步发出一个动作,浏览器封装层执行并返回新状态。

### 纯截图 vs 无障碍树

两种输入模式:

- 纯截图:完整图像,无结构信息。最通用,任何应用都行。
- 无障碍树(accessibility tree):结构化的 DOM / iOS 无障碍信息。grounding 可靠得多;只在有树可用的地方能用。
- 混合:两者都用——树为原子动作提供可靠 grounding,截图提供语义上下文。

生产智能体能用混合就用混合。浏览器自动化(Selenium + 无障碍)总是有树;桌面应用有时有。

### 长程记忆

一个 20 步的工作流产生 20 张截图,VLM 的上下文很快塞满。三种压缩策略:

- 摘要链:每 5 步总结一次已发生的事,丢掉旧截图。
- 跳帧:保留第一张、最后一张和每隔 3 张的截图。
- 工具记录日志:执行动作,保留一份"做了什么"的文本日志,不再回看旧截图。

Claude 的 computer-use API 用日志模式。更简单,更可靠。

### 视觉工具调用

ChartAgent(arXiv:2510.04514)为图表理解引入视觉工具调用:裁剪、缩放、OCR、调外部检测。智能体可以输出"裁剪到区域 (100, 200, 300, 400),然后调 OCR"这样的工具调用。工具返回文本,VLM 继续推理。

这个模式可推广:set-of-mark 提示、区域标注、外部检测工具,全都符合同一个"输出工具调用、收到结构化响应"的 schema。

### 2026 年的基准

- ScreenSpot-Pro:约 1k 张网页截图上的 GUI grounding。开源 SOTA Qwen2.5-VL-72B 约 85%,前沿约 90%。
- VisualWebArena:端到端网页任务(购物、论坛、分类信息)。开源 SOTA 约 20%,Gemini 3 Pro 约 27%。
- AgentVista(arXiv:2602.23166):2026 年最难的基准,横跨 12 个领域的真实工作流。前沿模型 27–40%,开源模型 10–20%。
- WebArena / WebShop:更老的基准,已被前沿打满。

### 为什么仍然难

智能体性能的瓶颈:

1. 细粒度视觉 grounding。"点那个小 X"在移动端分辨率下经常失败。
2. 长程规划。10 个动作之后,智能体开始偏离目标。
3. 错误恢复。点击失败(按错按钮)时,检测 + 恢复——训练数据里很少有这个。
4. 跨页上下文。在标签页之间跳转或填长表单时会丢状态。

研究方向:记忆架构、显式重规划、多模态验证(用截图比对确认动作成功)。

## 关键术语

| 术语 | 人们常说的 | 实际含义 |
|------|-----------------|------------------------|
| GUI grounding | "点击坐标" | 模型针对截图上的指令目标输出 (x,y) |
| 动作 schema | "工具定义" | 合法动作的 JSON 描述(click、type、scroll、drag) |
| 无障碍树 | "结构化 DOM" | 来自浏览器/iOS API 的机器可读 UI 层级 |
| 混合智能体 | "截图 + 树" | 图像与结构信息并用;比任一单用更可靠 |
| 视觉工具调用 | "缩放/裁剪/检测" | 智能体在规划中途调用外部视觉工具(OCR、检测) |
| 摘要链 | "记忆压缩" | 周期性文本摘要替代长长的截图历史 |
| VisualWebArena | "端到端网页基准" | 2024 年的端到端网页任务基准 |
| AgentVista | "2026 难基准" | 12 领域真实工作流;Gemini 3 Pro 也只有约 30 分 |
