# Prompt Engineering 系统指南

Prompt 是与 LLM 沟通的语言。写好 Prompt 能让模型能力充分发挥；写差了则事倍功半。本文系统讲解核心技术，并给出可直接复用的模板。

## 1. 基础原则

### 角色 + 任务 + 格式 = 标准 Prompt

```
你是一名 [角色描述]。

你的任务是 [明确的任务描述]。

[提供上下文/示例（可选）]

[具体输入内容]

请以 [格式要求] 输出。
```

**好的 Prompt 特征：**
- 角色清晰：让模型知道从哪个视角思考
- 任务具体：第一句话就说明要做什么
- 格式明确：告诉模型输出什么形式

**坏的 Prompt：**
```
帮我写一篇关于AI的文章
```

**好的 Prompt：**
```
你是一名面向初学者的技术科普作者。

请为完全没有技术背景的读者解释"什么是大语言模型"，要求：
- 长度 300-500 字
- 用至少一个生活类比
- 结尾给出一个可以亲手体验 LLM 的建议

读者群体：25-35 岁的非技术白领
```

## 2. Chain of Thought（思维链）

CoT 让模型在给出答案前先推理，显著提升复杂任务准确率。

### 零样本 CoT：加一句话

```python
prompt = """
一个工厂每天生产 240 个零件，周六日各只生产平时的一半。
一周（7天）共生产多少零件？

请一步一步思考。
"""
```

"请一步一步思考" / "Let's think step by step" 这一句话就能激活 CoT。

### 显式推理链

```python
prompt = """
分析以下评论的情感倾向。

分析步骤：
1. 识别关键词和短语
2. 判断每个关键信号的正负
3. 综合得出整体情感

评论：「这家餐厅环境不错，但服务太慢了，食物味道倒还可以」

请按步骤分析：
"""
```

### Self-Consistency（自一致性）

重复采样多次取多数，适合有明确正确答案的任务：

```python
import asyncio
from collections import Counter

async def self_consistent_answer(question: str, n: int = 5) -> str:
    """多次采样取多数票答案"""
    tasks = [llm.complete([{"role": "user", "content": question}]) for _ in range(n)]
    responses = await asyncio.gather(*tasks)
    
    # 简化：取第一行作为答案标识
    answers = [r.content.strip().split("\n")[0] for r in responses]
    most_common = Counter(answers).most_common(1)[0][0]
    return most_common
```

## 3. Few-Shot 示例学习

提供几个例子，让模型学习输出格式和风格。

### 基础 Few-Shot

```python
few_shot_prompt = """
将用户的口语描述转换为标准的 SQL 查询。

例子1：
用户：查一下张三的所有订单
SQL：SELECT * FROM orders WHERE customer_name = '张三'

例子2：
用户：最近30天销售额超过1万的商品有哪些
SQL：SELECT product_name, SUM(amount) as total 
     FROM orders 
     WHERE created_at >= DATE_SUB(NOW(), INTERVAL 30 DAY)
     GROUP BY product_name 
     HAVING total > 10000

现在请转换：
用户：{user_input}
SQL：
"""
```

### Few-Shot 选取原则

| 原则 | 说明 |
|------|------|
| 代表性 | 例子要覆盖边界情况，不只是简单情况 |
| 多样性 | 多给几个不同类型的例子 |
| 数量 | 通常 3-5 个，太多浪费 token |
| 顺序 | 最后一个例子最相关（近因效应）|

### 动态 Few-Shot（按相似度选例子）

```python
from openai import AsyncOpenAI
import numpy as np

examples = [
    {"input": "查所有用户", "output": "SELECT * FROM users"},
    {"input": "删除过期记录", "output": "DELETE FROM records WHERE expired_at < NOW()"},
    # ... 更多例子
]

async def get_embedding(text: str) -> list[float]:
    resp = await openai_client.embeddings.create(
        model="text-embedding-3-small",
        input=text,
    )
    return resp.data[0].embedding

async def select_few_shots(query: str, k: int = 3) -> list[dict]:
    """按语义相似度选取最相关的 k 个例子"""
    query_emb = np.array(await get_embedding(query))
    
    scores = []
    for ex in examples:
        ex_emb = np.array(await get_embedding(ex["input"]))
        score = np.dot(query_emb, ex_emb) / (np.linalg.norm(query_emb) * np.linalg.norm(ex_emb))
        scores.append((score, ex))
    
    scores.sort(key=lambda x: x[0], reverse=True)
    return [ex for _, ex in scores[:k]]
```

## 4. 结构化输出

让 LLM 输出稳定的 JSON，是 AI 工程落地的关键。

### 方法一：OpenAI Structured Outputs（最可靠）

```python
from pydantic import BaseModel, Field
from openai import AsyncOpenAI

client = AsyncOpenAI()

class RiskAnalysis(BaseModel):
    risk_level: str = Field(description="风险等级: low/medium/high/critical")
    summary: str = Field(description="风险摘要，不超过100字")
    factors: list[str] = Field(description="主要风险因素列表")
    recommendation: str = Field(description="处理建议")

async def analyze_risk(scenario: str) -> RiskAnalysis:
    response = await client.beta.chat.completions.parse(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "你是风险分析专家，请分析给定场景的风险"},
            {"role": "user", "content": scenario},
        ],
        response_format=RiskAnalysis,
    )
    return response.choices[0].message.parsed
```

### 方法二：JSON Mode + 手动解析

```python
import json
from pydantic import BaseModel, ValidationError

async def extract_json(content: str, schema_desc: str) -> dict:
    response = await client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": f"请以 JSON 格式返回，结构为：{schema_desc}"},
            {"role": "user", "content": content},
        ],
        response_format={"type": "json_object"},  # JSON Mode
    )
    return json.loads(response.choices[0].message.content)
```

### 方法三：通用厂商的 Prompt 约束

对于不支持 Structured Output 的厂商：

```python
def build_json_prompt(task: str, json_schema: dict) -> str:
    schema_str = json.dumps(json_schema, ensure_ascii=False, indent=2)
    return f"""
{task}

你必须严格以如下 JSON 格式返回，不要有任何额外文字：

```json
{schema_str}
```

注意：
- 只返回 JSON，不要加 ```json``` 标记
- 确保 JSON 合法可解析
- 不要省略任何必填字段
"""
```

### 解析时的容错处理

```python
import re
import json

def extract_json_from_response(text: str) -> dict | None:
    """从 LLM 响应中提取 JSON，处理各种格式"""
    # 1. 尝试直接解析
    try:
        return json.loads(text.strip())
    except json.JSONDecodeError:
        pass
    
    # 2. 提取 ```json ... ``` 代码块
    pattern = r"```(?:json)?\s*(\{.*?\})\s*```"
    match = re.search(pattern, text, re.DOTALL)
    if match:
        try:
            return json.loads(match.group(1))
        except json.JSONDecodeError:
            pass
    
    # 3. 找第一个 { 到最后一个 } 之间的内容
    start = text.find("{")
    end = text.rfind("}") + 1
    if start != -1 and end > start:
        try:
            return json.loads(text[start:end])
        except json.JSONDecodeError:
            pass
    
    return None
```

## 5. 高级技巧

### Prompt 模板系统

```python
from string import Template

class PromptTemplate:
    def __init__(self, template: str):
        self.template = Template(template)
    
    def format(self, **kwargs) -> str:
        return self.template.safe_substitute(**kwargs)

# 定义模板
code_review_template = PromptTemplate("""
你是一名资深 $language 工程师，专注于代码质量和安全性。

请审查以下代码，重点关注：
1. 潜在的 Bug
2. 性能问题
3. 安全漏洞

代码：
```$language
$code
```

以表格形式输出问题清单，列包括：严重程度 | 问题描述 | 建议修复方案
""")

# 使用
prompt = code_review_template.format(
    language="Python",
    code="def divide(a, b): return a/b"
)
```

### Prompt 版本管理

```python
# prompts/v1/code_review.txt
# 在文件中管理 prompt，方便 A/B 测试

import os
from pathlib import Path

class PromptRegistry:
    def __init__(self, base_dir: str = "prompts"):
        self.base_dir = Path(base_dir)
    
    def get(self, name: str, version: str = "latest") -> str:
        if version == "latest":
            # 找最新版本
            versions = sorted(self.base_dir.glob(f"*/#{name}.txt"))
            if not versions:
                raise FileNotFoundError(f"Prompt '{name}' not found")
            path = versions[-1]
        else:
            path = self.base_dir / version / f"{name}.txt"
        
        return path.read_text(encoding="utf-8")

registry = PromptRegistry()
system_prompt = registry.get("code_review")
```

## 6. 调试技巧

### 温度参数选择

| 任务类型 | temperature | 说明 |
|---------|------------|------|
| 代码生成 | 0 - 0.2 | 确定性，避免随机变体 |
| 信息提取/分类 | 0 - 0.3 | 准确性优先 |
| 问答/摘要 | 0.3 - 0.7 | 平衡 |
| 创意写作 | 0.7 - 1.0 | 多样性 |
| 头脑风暴 | 1.0+ | 最大发散 |

### 常见问题排查

```
问题：模型没有按格式输出
→ 在 prompt 末尾重申格式要求，用"必须"/"只返回"等强调词

问题：输出太长/太短
→ 明确指定字数范围："200-300字"比"简短"有效得多

问题：模型拒绝执行任务
→ 添加合理的角色背景和使用场景说明

问题：每次输出不稳定
→ 降低 temperature，增加 Few-Shot 示例，使用 Structured Output

问题：幻觉（模型编造信息）
→ 要求模型"仅根据提供的信息回答"，不确定时说"不知道"
```
