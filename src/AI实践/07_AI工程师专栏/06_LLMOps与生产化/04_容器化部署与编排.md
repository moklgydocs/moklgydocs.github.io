# 容器化部署与 K8s 编排

## Docker 最佳实践

### AI 服务 Dockerfile

```dockerfile
# 多阶段构建：构建阶段
FROM nvidia/cuda:12.4.0-devel-ubuntu22.04 AS builder

WORKDIR /app

# 安装 Python
RUN apt-get update && apt-get install -y python3.10 python3-pip && \
    rm -rf /var/lib/apt/lists/*

# 安装依赖（利用缓存层）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 运行阶段：更小的基础镜像
FROM nvidia/cuda:12.4.0-runtime-ubuntu22.04

WORKDIR /app

# 只复制必要的运行时文件
COPY --from=builder /usr/local/lib/python3.10 /usr/local/lib/python3.10
COPY --from=builder /usr/local/bin /usr/local/bin
COPY --from=builder /app /app

# 复制应用代码
COPY src/ ./src/

# 非 root 用户运行
RUN useradd -m appuser && chown -R appuser:appuser /app
USER appuser

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

EXPOSE 8000

CMD ["python", "-m", "vllm.entrypoints.openai.api_server", \
     "--host", "0.0.0.0", "--port", "8000", \
     "--model", "/models/qwen2.5-7b"]
```

### GPU 资源声明

```yaml
# llm-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: llm-inference
  namespace: ai-serving
spec:
  replicas: 2
  selector:
    matchLabels:
      app: llm-inference
  template:
    metadata:
      labels:
        app: llm-inference
    spec:
      # 调度到 GPU 节点
      nodeSelector:
        nvidia.com/gpu.present: "true"
      tolerations:
        - key: nvidia.com/gpu
          operator: Exists
          effect: NoSchedule
      containers:
        - name: vllm
          image: registry.example.com/llm-serving:v1.0
          ports:
            - containerPort: 8000
          resources:
            limits:
              nvidia.com/gpu: 1
            requests:
              nvidia.com/gpu: 1
              memory: "16Gi"
              cpu: "4"
          env:
            - name: MODEL_PATH
              value: "/models/qwen2.5-7b"
            - name: MAX_MODEL_LEN
              value: "4096"
          volumeMounts:
            - name: model-storage
              mountPath: /models
          livenessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 120
            periodSeconds: 30
          readinessProbe:
            httpGet:
              path: /health
              port: 8000
            initialDelaySeconds: 60
            periodSeconds: 10
      volumes:
        - name: model-storage
          persistentVolumeClaim:
            claimName: model-pvc
```

## HPA 自动伸缩

### 基于 GPU 利用率的 HPA

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: llm-inference-hpa
  namespace: ai-serving
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: llm-inference
  minReplicas: 1
  maxReplicas: 5
  metrics:
    # 基于 CPU 利用率
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    # 基于 GPU 利用率（需要 DCGM exporter）
    - type: Pods
      pods:
        metric:
          name: gpu_utilization
        target:
          type: AverageValue
          averageValue: "80"
    # 基于并发请求数（自定义指标）
    - type: Pods
      pods:
        metric:
          name: vllm_num_requests_running
        target:
          type: AverageValue
          averageValue: "16"
  behavior:
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Percent
          value: 100
          periodSeconds: 60
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 10
          periodSeconds: 60
```

## 关键配置参数

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `max-model-len` | 最大序列长度 | 根据业务需求 |
| `gpu-memory-utilization` | GPU 显存利用率 | 0.85-0.92 |
| `max-num-seqs` | 最大并发序列数 | 16-64 |
| `enable-prefix-caching` | 前缀缓存 | 开启 |
| `enforce-eager` | 禁用 CUDA Graph（调试用） | 生产关闭 |

## 故障排查

| 现象 | 可能原因 | 排查方法 |
|------|----------|----------|
| OOM Killed | 显存不足 | 降低 gpu-memory-utilization 或 max-model-len |
| 启动超时 | 模型加载慢 | 检查 PVC IOPS，预热模型 |
| 请求超时 | 排队过长 | 增加 replicas 或降低 max-num-seqs |
| GPU 利用率低 | batch 不足 | 增加 max-num-seqs 或降低 HPA 阈值 |
| 响应变慢 | KV Cache 不足 | 增加显存或减少并发 |
