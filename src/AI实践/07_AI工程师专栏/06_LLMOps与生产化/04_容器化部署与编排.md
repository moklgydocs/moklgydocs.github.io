## Docker 最佳实践

### AI 服务 Dockerfile

```dockerfile
# 多阶段构建：构建阶段
FROM nvidia/cuda:12.4.0-devel-ubuntu22.04 AS builder

WORKDIR /app

# 安装 Python
RUN apt-get update && apt-get install -y python3.10 python3-pip && \
    rm -rf /var/lib/apt/lists/*

# 安装依赖（利用缓存层）
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 运行阶段：更小的基础镜像
FROM nvidia/cuda:12.4.0-runtime-ubuntu22.04

WORKDIR /app

# 只复制必要的运行时文件
COPY --from=builder /usr/local/lib/python3.10 /usr/local/lib/python3.10
COPY --from=builder /usr/local/bin /usr/local/bin
COPY --from=builder /app /app

# 复制应用代码
COPY src/ ./src/

# 非 root 用户运行
RUN useradd -m appuser && chown -R appuser:appuser /app
USER appuser

# 健康检查
HEALTHCHECK --interval=30s --timeout=10s --retries=3 \
    CMD curl -f http://localhost:8000/health || exit 1

EXPOSE 8000

CMD ["python", "-m", "vllm.entrypoints.openai.api_server", \
     "--host", "0.0.0.0", "--port", "8000", \
     "--model", "/models/qwen2.5-7b"]
```

### GPU 共享策略

LLM 推理服务不一定需要独占整张 GPU。多个小模型可以共享一张 GPU，
显著降低成本。

#### 共享方案对比

| 方案 | 原理 | 隔离性 | 适用 GPU | 适用场景 |
|------|------|--------|---------|---------|
| **Time-Slicing** | 时间片轮转 | 无（共享显存） | 所有 NVIDIA GPU | 多个小模型（<4GB） |
| **MPS** (Multi-Process Service) | 共享 GPU 上下文 | 弱 | Volta+ (V100/A100) | 同构推理服务 |
| **MIG** (Multi-Instance GPU) | 硬件级分区 | 强 | A100 40GB/80GB, H100 | 异构工作负载 |

#### Time-Slicing 配置（最简单）

```yaml
# nvidia-device-plugin ConfigMap
apiVersion: v1
kind: ConfigMap
metadata:
  name: nvidia-device-plugin-config
data:
  config.yaml: |
    version: v1
    sharing:
      timeSlicing:
        renameByDefault: false
        resources:
          - name: nvidia.com/gpu
            replicas: 4  # 1 张 GPU 分成 4 个时间片
```

```yaml
# Pod 配置 — 请求 1/4 GPU
apiVersion: v1
kind: Pod
spec:
  containers:
    - name: llm-inference
      image: vllm/vllm-openai:latest
      resources:
        limits:
          nvidia.com/gpu: 1  # 占用 1 个时间片（1/4 GPU）
      env:
        - name: CUDA_VISIBLE_DEVICES
          value: "0"
        - name: VLLM_GPU_MEMORY_UTILIZATION
          value: "0.2"  # 限制显存使用
```

> ⚠️ Time-Slicing 无内存隔离 — 如果一个模型 OOM，会影响同 GPU 上所有服务。
> 仅适合低流量、可容忍偶尔延迟飙升的场景。

#### MIG 配置（推荐生产使用）

```yaml
# A100 80GB 分成 7 个实例（每个约 10GB 显存）
# 在 Kubernetes node 上配置
apiVersion: v1
kind: ConfigMap
metadata:
  name: nvidia-mig-config
data:
  config.yaml: |
    version: v1
    mig-strategy: mixed
    devices:
      - gpu: 0
        migEnabled: true
        migDevices:
          "1g.10gb": 7  # 7 个 10GB 实例
```

```yaml
# Pod 请求 1 个 MIG 实例
apiVersion: v1
kind: Pod
spec:
  containers:
    - name: llm-inference
      resources:
        limits:
          nvidia.com/mig-1g.10gb: 1  # 请求 1 个 10GB MIG 实例
```

> MIG 优势：硬件级隔离，一个实例崩溃不影响其他。
> 限制：仅支持 A100/H100，实例大小由 GPU 型号决定。

#### GPU 成本优化决策

```python
class GPUOptimizer:
    """GPU 成本优化决策器"""

    # 模型显存需求（估算，bf16 + KV Cache）
    MODEL_MEMORY = {
        "Qwen2-0.5B": 2, "Qwen2-1.5B": 4, "Qwen2-7B": 16,
        "Qwen2-72B": 150, "Llama3-8B": 18, "Llama3-70B": 145,
    }

    GPU_MEMORY = {
        "RTX_4090": 24, "L40S": 48, "A100_40GB": 40,
        "A100_80GB": 80, "H100_80GB": 80,
    }

    def recommend(self, models: list[str], qps_per_model: list[int]) -> dict:
        """推荐 GPU 部署方案"""
        total_memory = sum(self.MODEL_MEMORY.get(m, 16) for m in models)
        max_single = max(self.MODEL_MEMORY.get(m, 16) for m in models)

        if total_memory <= 24 and max(qps_per_model) < 5:
            return {
                "strategy": "time_slicing",
                "gpu": "RTX 4090 (24GB)",
                "reason": f"总需求 {total_memory}GB < 24GB，Time-Slicing 足够",
                "monthly_cost_cny": 4000,
            }
        elif total_memory <= 80 and max_single <= 10:
            return {
                "strategy": "MIG",
                "gpu": "A100 80GB",
                "reason": f"总需求 {total_memory}GB，MIG 提供硬件隔离",
                "monthly_cost_cny": 15000,
            }
        else:
            return {
                "strategy": "dedicated",
                "gpu": "A100 80GB × 2",
                "reason": f"总需求 {total_memory}GB，需独占 GPU",
                "monthly_cost_cny": 30000,
            }
```

### 密钥管理

生产部署中，API Key、数据库密码、模型访问令牌等敏感信息**绝不能**硬编码在镜像或 YAML 中。

#### 方案对比

| 方案 | 安全级别 | 复杂度 | 适用场景 |
|------|---------|--------|---------|
| K8s Secrets + RBAC | 基础 | 低 | 小团队/非敏感数据 |
| Sealed Secrets | 中 | 低 | GitOps 工作流 |
| External Secrets + Vault | 高 | 中 | 企业级合规 |
| HashiCorp Vault | 最高 | 高 | 金融/医疗合规 |

#### 基础方案：K8s Secrets + RBAC

```yaml
# 1. 创建 Secret
apiVersion: v1
kind: Secret
metadata:
  name: llm-api-keys
type: Opaque
stringData:
  OPENAI_API_KEY: "sk-xxx"
  DATABASE_URL: "postgresql://user:pass@db:5432/llm"
---
# 2. Pod 引用 Secret
apiVersion: v1
kind: Pod
spec:
  containers:
    - name: llm-service
      envFrom:
        - secretRef:
            name: llm-api-keys
---
# 3. RBAC 限制访问
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: secret-reader
rules:
  - apiGroups: [""]
    resources: ["secrets"]
    resourceNames: ["llm-api-keys"]  # 限制到特定 Secret
    verbs: ["get"]
```

#### 企业方案：HashiCorp Vault

```python
# Vault 集成示例
import hvac

class VaultSecretManager:
    """HashiCorp Vault 密钥管理"""

    def __init__(self, vault_addr: str, role_id: str, secret_id: str):
        self.client = hvac.Client(url=vault_addr)
        self.client.auth.approle.login(
            role_id=role_id,
            secret_id=secret_id,
        )

    def get_api_key(self, service: str) -> str:
        """从 Vault 获取 API Key（不落盘）"""
        response = self.client.secrets.kv.v2.read_secret_version(
            path=f"ai-services/{service}",
        )
        return response["data"]["data"]["api_key"]

    def get_database_url(self) -> str:
        """从 Vault 获取数据库连接串（动态凭据）"""
        response = self.client.secrets.database.generate_credentials(
            name="llm-db-readonly",
        )
        return (
            f"postgresql://{response['data']['username']}:"
            f"{response['data']['password']}"
            f"@db:5432/llm"
        )
```

```yaml
# Vault Agent Sidecar 注入（自动从 Vault 获取密钥）
apiVersion: v1
kind: Pod
metadata:
  annotations:
    vault.hashicorp.com/agent-inject: "true"
    vault.hashicorp.com/role: "llm-service"
    vault.hashicorp.com/secret-volume-path: "/etc/secrets"
    vault.hashicorp.com/agent-inject-secret-api-key: "ai-services/openai"
spec:
  containers:
    - name: llm-service
      env:
        - name: OPENAI_API_KEY_FILE
          value: "/etc/secrets/api-key"
```

> ⚠️ 关键原则：
> 1. 密钥不落盘 — 使用 Vault 动态凭据或 Sidecar 注入
> 2. 最小权限 — 每个 Service 只能访问自己需要的 Secret
> 3. 审计日志 — 记录每次密钥访问
> 4. 自动轮转 — 数据库密码定期更换（Vault 动态凭据支持）

## 关键配置参数

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `max-model-len` | 最大序列长度 | 根据业务需求 |
| `gpu-memory-utilization` | GPU 显存利用率 | 0.85-0.92 |
| `max-num-seqs` | 最大并发序列数 | 16-64 |
| `enable-prefix-caching` | 前缀缓存 | 开启 |
| `enforce-eager` | 禁用 CUDA Graph（调试用） | 生产关闭 |

## 故障排查

| 现象 | 可能原因 | 排查方法 |
|------|----------|----------|
| OOM Killed | 显存不足 | 降低 gpu-memory-utilization 或 max-model-len |
| 启动超时 | 模型加载慢 | 检查 PVC IOPS，预热模型 |
| 请求超时 | 排队过长 | 增加 replicas 或降低 max-num-seqs |
| GPU 利用率低 | batch 不足 | 增加 max-num-seqs 或降低 HPA 阈值 |
| 响应变慢 | KV Cache 不足 | 增加显存或减少并发 |

### API vs 自部署决策

```python
class DeploymentCostEstimator:
    """部署成本估算器

    帮助决策：API 调用 vs 自部署模型，哪个更划算？
    """

    # 模型定价（$/M tokens，2025 参考）
    API_PRICING = {
        "gpt-4o": {"input": 2.5, "output": 10.0},
        "gpt-4o-mini": {"input": 0.15, "output": 0.6},
        "claude-sonnet-4-20250514": {"input": 3.0, "output": 15.0},
        "deepseek-v3": {"input": 0.27, "output": 1.1},
    }

    # 自部署 GPU 成本（¥/月，含电费）
    GPU_COSTS = {
        "A100_80GB": 15000,   # 云服务器
        "A100_40GB": 10000,
        "L40S_48GB": 8000,
        "RTX_4090_24GB": 4000,  # 自建
    }

    def estimate_api_cost(self, model: str, daily_queries: int,
                          avg_input_tokens: int = 1000,
                          avg_output_tokens: int = 500,
                          cache_hit_rate: float = 0.3) -> dict:
        """估算 API 模式月度成本"""
        pricing = self.API_PRICING.get(model, self.API_PRICING["gpt-4o"])

        # Prompt Caching 折扣
        effective_input_price = pricing["input"] * (
            cache_hit_rate * 0.5 + (1 - cache_hit_rate) * 1.0
        )

        daily_cost = daily_queries * (
            avg_input_tokens * effective_input_price / 1_000_000 +
            avg_output_tokens * pricing["output"] / 1_000_000
        )
        monthly_cost = daily_cost * 30

        return {
            "model": model,
            "daily_queries": daily_queries,
            "monthly_cost_usd": round(monthly_cost, 2),
            "monthly_cost_cny": round(monthly_cost * 7.2, 2),
            "cache_hit_rate": cache_hit_rate,
            "per_query_cost_cny": round(monthly_cost * 7.2 / (daily_queries * 30), 4),
        }

    def estimate_self_deploy_cost(self, gpu_type: str,
                                   num_gpus: int = 1,
                                   daily_queries: int = 10000,
                                   avg_latency_ms: int = 200) -> dict:
        """估算自部署模式月度成本"""
        gpu_monthly = self.GPU_COSTS[gpu_type] * num_gpus

        # 辅助服务成本（Redis, 向量库, 监控等）
        infra_cost = gpu_monthly * 0.3

        # 人力运维成本（估算）
        ops_cost = 5000 if num_gpus <= 2 else 15000

        total = gpu_monthly + infra_cost + ops_cost

        return {
            "gpu_type": gpu_type,
            "num_gpus": num_gpus,
            "gpu_cost": gpu_monthly,
            "infra_cost": infra_cost,
            "ops_cost": ops_cost,
            "monthly_total_cny": total,
            "per_query_cost_cny": round(total / (daily_queries * 30), 4),
        }

    def recommend(self, daily_queries: int,
                   model: str = "gpt-4o") -> dict:
        """推荐部署方式"""
        api = self.estimate_api_cost(model, daily_queries)
        self_deploy = self.estimate_self_deploy_cost("A100_80GB", 1, daily_queries)

        # 简化决策：API 月成本 < 自部署 → 选 API
        use_api = api["monthly_cost_cny"] < self_deploy["monthly_total_cny"]

        return {
            "recommended": "API" if use_api else "self_deploy",
            "api_monthly_cny": api["monthly_cost_cny"],
            "self_deploy_monthly_cny": self_deploy["monthly_total_cny"],
            "savings_cny": abs(api["monthly_cost_cny"] - self_deploy["monthly_total_cny"]),
            "breakeven_queries": self._breakeven(model),
        }

    def _breakeven(self, model: str) -> int:
        """计算 API 与自部署的盈亏平衡点（日查询数）"""
        # 简化：约 10K-50K QPS/天是常见盈亏平衡区间
        # 取决于模型大小、GPU 利用率、查询复杂度
        return 30000 if model in ["gpt-4o", "claude-sonnet-4-20250514"] else 80000
```

### 成本优化清单

| 优化项 | 预期节省 | 实施难度 |
|--------|---------|---------|
| Prompt Caching（OpenAI/Claude） | 50-90% input cost | 低 |
| 语义缓存（相似查询复用） | 20-40% 总调用 | 中 |
| 模型路由（简单查询用小模型） | 30-60% 总调用 | 中 |
| 批量 API（离线处理） | 50% API cost | 低 |
| 自部署开源模型（高频场景） | 70-90% API cost | 高 |
| Prompt 压缩（减少 token） | 10-30% input cost | 中 |

> **关键结论**：日均 < 10K 查询选 API，> 50K 查询考虑自部署，10K-50K 需根据具体场景计算。
