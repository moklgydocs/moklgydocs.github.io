## 面试准备

### 技术面试常见问题

#### LLM 基础

**Q: Transformer 的自注意力机制原理是什么？**

A: 自注意力（Self-Attention）是 Transformer 的核心机制，具体包括以下几个层面：

**Q/K/V 的含义和计算方式**：输入序列经过三组线性投影得到 Query（查询）、Key（键）、Value（值）矩阵。类比检索系统：Query 是"我在找什么"，Key 是"这里有什么"，Value 是"实际内容"。计算过程为 Attention(Q, K, V) = softmax(QK^T / √d_k) · V。

**缩放因子 √d_k**：点积 QK^T 的方差与 d_k 成正比，当维度较大时点积值会极大，导致 Softmax 进入饱和区，梯度极小。除以 √d_k 将方差归一化为 1，保证梯度稳定流动。这是原始论文的关键设计，不加缩放的训练会不稳定。

**Multi-Head Attention**：将 Q/K/V 沿维度切分为 h 个头，各头独立计算注意力后拼接。好处：不同头关注不同子空间的特征（如一个头关注语法关系、另一个关注语义相似性），类似 CNN 中多个卷积核的效果。计算量与单头相近（每个头维度为 d_model/h）。

**位置编码的必要性**：自注意力本身是排列不变的（permutation invariant），即打乱输入顺序输出不变。但语言的词序至关重要（"狗咬人" vs "人咬狗"）。位置编码通过为每个位置添加唯一的位置向量，让模型感知词序。原始 Transformer 用正弦/余弦函数，现代模型多用可学习位置编码或 RoPE（旋转位置编码，支持长度外推）。

**对比 RNN/LSTM 的优势**：RNN 按时间步顺序计算，无法并行，且长距离依赖通过梯度传递容易衰减（梯度消失/爆炸）；LSTM 通过门控缓解但未根本解决。Transformer 的自注意力使任意两个位置直接交互，路径长度为 O(1)，且可完全并行计算。代价是 O(n²) 的内存和计算，这是长上下文的主要瓶颈。

**Q: 什么是 KV Cache？为什么推理需要它？**

A: KV Cache 缓存已计算过的 Key 和 Value 矩阵。自回归生成时，每一步只需要计算新 Token 的 Query，与缓存的 KV 做注意力即可，避免重复计算。没有 KV Cache，生成长度为 N 的序列需要 O(N^3) 计算；有了 KV Cache 降为 O(N^2)。

#### RAG 相关

**Q: RAG 的工作原理是什么？完整流程是怎样的？**

A: RAG（Retrieval-Augmented Generation）的核心思想是：让 LLM 基于外部知识生成回答，而非仅依赖训练数据。完整流程为：

1. **文档解析**：将 PDF/Word/HTML 等格式转为纯文本，提取表格、图片描述等结构化信息
2. **文本分块**：按语义边界（段落/章节）将长文档切分为 256-512 token 的块，保留适当重叠避免语义断裂
3. **Embedding**：用向量化模型（如 BGE-M3）将每个块编码为高维向量
4. **检索**：将用户问题同样向量化，在向量数据库中做相似度搜索，取 top-k 候选
5. **重排序**：用 Cross-Encoder 对候选块做精排，提升相关性
6. **生成**：将检索到的上下文和用户问题一起送入 LLM 生成回答

**检索质量的决定性影响**：RAG 的上限由检索决定——如果相关文档没有被检索到，LLM 再强也无法生成正确答案。检索质量对最终效果的影响远大于生成模型的选择。

**常见问题**：
- **分块粒度**：太大则检索不精确（噪声多），太小则丢失上下文（语义不完整）
- **检索召回率**：向量检索对语义相近但用词不同的查询效果好，但专有名词/错误码等精确匹配不如关键词检索
- **幻觉**：LLM 可能忽略检索到的上下文，编造检索结果中不存在的内容

**优化方向**：
- **混合检索**：向量检索 + BM25 关键词检索，取长补短
- **查询改写**：对用户查询进行扩展、纠错或分解子问题
- **Self-RAG**：让模型自己判断是否需要检索、检索结果是否有用、生成内容是否忠实

**Q: RAG 检索效果不好怎么优化？**

A: 分层排查：
1. **索引层**：分块策略是否合理（大小、重叠、结构感知）
2. **查询层**：查询是否需要改写、扩展或分解
3. **检索层**：向量模型是否适合、是否需要混合检索（向量 + BM25）
4. **重排层**：是否需要 Cross-Encoder 重排
5. **生成层**：Prompt 是否引导模型基于上下文回答

**Q: 向量检索和关键词检索各自的优势？**

A: 向量检索擅长语义匹配，能找到意思相近但用词不同的内容；关键词检索擅长精确匹配，对专有名词、术语、错误码等更可靠。生产环境通常使用混合检索，向量检索保证召回广度，关键词检索保证精确度。

#### Agent 相关

**Q: Agent 和简单 API 调用有什么区别？**

A: 核心区别在于是否有**自主决策能力**。

简单 API 调用是单轮 request-response：用户输入 → LLM 生成 → 返回结果。流程固定，没有循环，不需要管理状态。

Agent 具备自主决策能力：它可以**选择调用哪个工具**（函数调用）、**决定是否继续**（循环）、**处理错误并重试**（错误恢复）。Agent 的典型执行流程是 感知 → 规划 → 行动 → 观察 的循环（如 ReAct），直到任务完成或达到最大步数。

Agent 需要额外处理的问题：
- **循环控制**：设置最大步数防止无限循环
- **状态管理**：跨步骤维护上下文和中间结果
- **错误恢复**：工具调用失败时的重试或降级策略
- **成本控制**：每一步都消耗 Token，需要预算限制

何时用 Agent：多步骤任务（如"帮我查订单状态并申请退款"）、需要外部工具（数据库查询、API 调用）、需要根据中间结果做判断。

何时不用 Agent：简单问答（单次 LLM 调用即可）、单步推理、不需要外部工具的场景。过度使用 Agent 会增加延迟、成本和不可控性。

**Q: ReAct 和 Function Calling 的区别？**

A: ReAct 是思考-行动-观察的循环框架，模型自主决定何时调用工具、调用哪个工具；Function Calling 是模型输出结构化的工具调用请求，由系统执行后返回结果。ReAct 更灵活但更不可控，Function Calling 更可控但灵活性受限。实际项目中通常结合使用：用 Function Calling 定义可用工具，用 ReAct 控制推理流程。

#### 系统设计

**Q: 设计一个高可用的 LLM 推理服务。**

A:
1. **多模型路由**：根据请求复杂度路由到不同模型（GPT-4o-mini / GPT-4o）
2. **负载均衡**：多副本 vLLM 服务，基于队列深度动态路由
3. **缓存层**：语义缓存减少重复调用
4. **降级策略**：主模型不可用时切换备选模型
5. **限流熔断**：防止突发流量打垮服务
6. **监控告警**：TTFB、错误率、队列深度实时监控

## 谈薪策略

### 薪资构成

```
总包 = 基础薪资 + 绩效奖金 + 股票/期权 + 签字费
```

### 谈薪原则

1. **锚定高值**：先报出预期薪资的上限，给谈判留空间
2. **总包视角**：不要只看月薪，股票和奖金也是总包的一部分
3. **竞品对比**：用其他 offer 作为谈判筹码
4. **延迟满足**：不要在第一轮就接受，表达需要考虑
5. **书面确认**：所有承诺必须落到书面

### 薪资谈判话术

```
面试官：你的期望薪资是多少？

回答：基于我的经验和市场行情，我的期望是 XX-YY 万。
     我更看重总包和长期发展空间。

面试官：这个范围超出了我们的预算。

回答：理解。那我们可以看看其他维度的补偿：
     - 签字费是否可以调整？
     - 股票授予是否可以增加？
     - 绩效奖金的比例？
     - 晋升评估周期能否缩短？

面试官：我们需要内部审批。

回答：好的，期待您的回复。同时我也有其他流程在进行中，
     如果可能的话希望在本周内得到反馈。
```

| 项目类型 | 典型要求 | 评分标准 |

**关键建议**：
- 必须有评估指标（没有评估 = 没有完成）
- 代码要可运行（README 包含完整启动步骤）
- 记录实验过程（不是只交最终结果）
- 处理 edge case（空输入、超长文本、格式错误）
