# L6：工具设计 + Function Calling

> **关卡目标**：为 AI 装上"手"。通过 Function Calling 让 LLM 能真正调用内部工具（查订单、查库存、提工单、查知识库、发通知），从"会说话"变成"能办事"。

---

## 核心概念

### Function Calling 是什么

普通的 LLM 调用只能输入文字、输出文字。Function Calling 是 OpenAI 定义的一个协议扩展：你在请求中附上"工具清单"（JSON Schema 格式），LLM 在认为需要调用某个工具时，会在响应里返回 `tool_calls` 字段（工具名 + 参数），而不是直接回答用户。你的代码负责真正执行这个工具，把结果以 `tool` role 消息喂回给 LLM，LLM 再生成最终回答。

```
用户提问
  ↓
LLM: "我需要调用 query_order(order_id='2024-0312')"
  ↓ (代码执行工具)
工具返回: {"status": "运输中", "carrier": "顺丰"}
  ↓
LLM: "您的订单 2024-0312 目前状态为【运输中】，由顺丰负责配送..."
```

这个"来回"可以循环多次（本关最多 5 轮），直到 LLM 认为信息足够、直接输出最终回答（`finish_reason = "stop"`）为止。

### 工具描述决定了一切

LLM 选择调用哪个工具、传入什么参数，**完全依赖工具的 `description` 字段**。描述写得好，工具选对率 > 95%；描述模糊，选错率可达 30%。

好的工具描述包含：
- 明确的使用场景（"当用户询问订单状态时使用"）
- 参数说明和示例值
- 和其他相似工具的区别

## 实现细节

### ToolRegistry：工具注册中心

```python
@dataclass
class ToolDefinition:
    name: str
    description: str
    parameters: dict        # JSON Schema
    handler: Callable
    requires_confirm: bool = False

class ToolRegistry:
    def register(self, name, description, parameters, requires_confirm=False):
        """装饰器，注册工具到全局 registry"""

    def get_openai_schemas(self) -> list[dict]:
        """返回 OpenAI tools 参数格式，直接传给 LLM"""

    async def execute(self, name, args, timeout=10.0) -> dict:
        """执行工具，asyncio.wait_for 强制超时"""
        # 统一返回: {"status": "ok|error", "data": ..., "error_msg": ...}
```

工具注册使用装饰器语法：

```python
@registry.register(
    name="query_order",
    description="当用户需要查询订单状态、物流信息时调用...",
    parameters={
        "type": "object",
        "properties": {
            "order_id": {"type": "string", "description": "订单编号，格式 YYYY-NNNNN"}
        },
        "required": ["order_id"]
    },
    requires_confirm=False,
)
async def query_order(order_id: str) -> dict:
    ...
```

### AgentChain：Function Calling 流水线

核心循环（最多 5 轮）：

```python
for _ in range(self._settings.tool_max_iterations):
    yield {"type": "status", "content": "思考中..."}
    response = await self._llm.complete_with_tools(messages, tools_schema)

    if response.finish_reason == "stop":
        # 流式输出最终回答
        async for token in self._llm.stream_completion(messages):
            yield {"type": "token", "content": token}
        break

    # 处理工具调用
    messages.append({"role": "assistant", "tool_calls": response.tool_calls})
    for tc in response.tool_calls:
        name = tc["function"]["name"]
        args = json.loads(tc["function"]["arguments"])
        tool_def = self._registry.get(name)

        # 写操作需要用户确认
        if tool_def.requires_confirm and tc["id"] != confirmed_call_id:
            yield {"type": "confirm", "tool": name, "args": args, "call_id": tc["id"]}
            await self._session.save_history(session_id, messages[1:])
            return  # 暂停，等待用户确认

        yield {"type": "tool_call", "tool": name, "args": args}
        result = await self._registry.execute(name, args, self._settings.tool_timeout)
        yield {"type": "tool_result", "tool": name, "result": result}

        # 把工具结果注入消息链
        messages.append({
            "role": "tool",
            "tool_call_id": tc["id"],
            "content": json.dumps(result, ensure_ascii=False),
        })
```

### requires_confirm：二次确认机制

对于写操作（提工单、发通知），流程如下：

1. LLM 决定调用 `create_ticket`
2. AgentChain 检测到 `requires_confirm=True`，发送 `confirm` 事件并暂停
3. 前端弹出确认对话框，显示工具名和参数
4. 用户点击"确认执行"，前端重新发送请求，附带 `confirmed_call_id`
5. AgentChain 加载 Redis 历史，找到对应的 `call_id`，这次直接执行

## 前端 AgentChat 组件

前端解析 SSE 事件流，对应不同类型展示不同 UI：

| SSE 事件 | 前端展示 |
|---------|---------|
| `status` | 旋转图标 + 状态文字（"思考中..."） |
| `tool_call` | 展开/折叠卡片，显示工具名 + 参数 JSON |
| `tool_result` | 在对应工具卡片上显示结果 JSON，成功/失败图标 |
| `confirm` | 琥珀色确认弹框，"确认执行" + "取消" |
| `token` | 流式拼接，末尾显示闪烁光标 |
| `done` | 停止流式，隐藏状态指示器 |
| `error` | 显示错误信息 |

## 工具安全分级

| 分级 | 工具 | 执行方式 | 风险 |
|------|------|---------|------|
| 只读 | query_order, query_inventory, search_knowledge | 直接执行 | 无副作用 |
| 写操作 | create_ticket, send_notification | 需用户确认 | 会创建记录/发消息 |

`requires_confirm` 是工具层面的配置，Agent 流水线统一处理，业务代码无需关心。

## 知识点：工具描述的工程实践

写一个好的工具描述是 Function Calling 调优的核心。建议格式：

```
{工具用途一句话}。当{触发场景}时调用。
参数说明：
- {param1}：{说明}，示例："{example}"
- {param2}：{说明}，可选值：{values}
注意：{和兄弟工具的区别，或重要约束}
```

示例对比：

```
# 差（太简单，LLM 选错率高）
description = "查询订单"

# 好（场景明确，参数有示例，有边界说明）
description = """
查询指定订单的当前状态、物流信息和预计到达时间。
当用户询问"我的订单到哪了"、"货什么时候到"、"查一下订单 XXXX" 时调用。
参数 order_id 格式为 YYYY-NNNNN，例如 "2024-0312"。
注意：此工具只能查询订单信息，创建工单请使用 create_ticket。
"""
```
