# React 原理面试题

> 适合 3 年+ 高级岗位。能答好这些题，说明你对 React 有深入理解。

## Q1: 虚拟 DOM 是什么？它比直接操作 DOM 快吗？

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥🔥🔥

💡 **回答要点**：

虚拟 DOM 是用 JS 对象描述 DOM 结构。**它不一定比直接操作 DOM 快**。

虚拟 DOM 的真正价值：
1. **声明式编程模型**：开发者描述结果，框架计算变化
2. **批量更新**：收集多次 setState，一次 Diff 一次更新
3. **跨平台**：React Native、SSR 等
4. **合理的性能基线**：自动避免大部分不必要的 DOM 操作

> ⚠️ **面试官会追问**：那什么时候直接操作 DOM 更快？答：当你精确知道哪部分需要更新时（如 canvas 绑定），直接操作更快。虚拟 DOM 的 Diff 本身也有开销。

## Q2: React 的 Diff 算法是如何工作的？

**难度**：⭐⭐⭐⭐ | **频率**：🔥🔥🔥🔥

💡 **回答要点**：

理论上比较两棵树是 O(n³)，React 通过三个假设优化为 O(n)：

1. **不同类型生成不同树**：div→span 直接销毁重建
2. **同层比较**：不跨层级移动节点
3. **key 标识同级元素**：用 key 匹配复用节点

同级列表的 Diff 策略：遍历新列表，用 key 在旧列表中查找对应节点，找到则复用并更新，找不到则新建，旧列表多余的则删除。

🔗 **追问**：React 和 Vue 的 Diff 有什么区别？

答：React 是**单向遍历**（从左到右），Vue 2 使用**双端对比**（头尾指针），Vue 3 使用**最长递增子序列**算法，在移动场景下 Vue 的方式通常更优。

## Q3: 什么是 Fiber？为什么需要它？

**难度**：⭐⭐⭐⭐ | **频率**：🔥🔥🔥🔥🔥

💡 **回答要点**：

**问题**：React 15 的栈调和器（Stack Reconciler）渲染是同步不可中断的，大组件树会导致页面卡顿。

**Fiber 解决方案**：将渲染工作拆成小单元，通过链表遍历（child → sibling → return），实现**可中断的增量渲染**。

核心机制：
- **时间切片**：每 5ms 检查是否需要交还控制权给浏览器
- **优先级调度**：用户输入 > 动画 > 数据更新
- **双缓冲**：current 树 + workInProgress 树，构建完成后切换

渲染分两阶段：
- **Render 阶段**（可中断）：遍历 Fiber 树，标记需要更新的节点
- **Commit 阶段**（不可中断）：一次性执行所有 DOM 操作

## Q4: Hooks 的实现原理是什么？为什么不能在条件中调用？

**难度**：⭐⭐⭐⭐ | **频率**：🔥🔥🔥🔥🔥

💡 **回答要点**：

Hooks 的状态存储在 Fiber 节点的 `memoizedState` 属性上，以**链表**形式串联：

```
Fiber.memoizedState → Hook1(useState) → Hook2(useEffect) → Hook3(useRef)
```

React 通过**调用顺序**来匹配 Hook 和对应的状态。如果在条件中调用，顺序可能变化，导致 Hook 和状态错位。

```
// 第一次渲染：useState(A) → useState(B) → useEffect
// 第二次渲染（跳过了第一个）：useState(B) → useEffect
// React 会把 B 的 Hook 指向 A 的状态！💥
```

## Q5: React 的批量更新（Batching）机制是什么？

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥🔥

💡 **回答要点**：

批量更新：React 将多个 setState 合并为一次渲染。

- **React 17**：只在合成事件和生命周期中批量
- **React 18+**：**自动批量更新**，包括 setTimeout、Promise、原生事件

```jsx
// React 18：只渲染 1 次
setTimeout(() => {
  setCount(1);
  setFlag(true);
  // 自动批量，只渲染一次
}, 1000);

// 如果需要强制同步更新
import { flushSync } from 'react-dom';
flushSync(() => setCount(1)); // 立即渲染
flushSync(() => setFlag(true)); // 再渲染一次
```

## Q6: React 的并发模式（Concurrent Mode）是什么？

**难度**：⭐⭐⭐⭐ | **频率**：🔥🔥🔥

💡 **回答要点**：

并发模式让 React 可以同时准备多个 UI 版本，根据优先级决定渲染顺序。不是「多线程」，而是「可中断的单线程」。

关键 API：
- `startTransition`：标记非紧急更新
- `useTransition`：同上 + isPending
- `useDeferredValue`：延迟某个值的更新
- `Suspense`：声明式加载状态

```jsx
// 输入框（紧急）+ 搜索结果（非紧急）
const [query, setQuery] = useState('');
const [isPending, startTransition] = useTransition();

const handleChange = (e) => {
  setQuery(e.target.value);           // 紧急更新
  startTransition(() => {
    setResults(search(e.target.value)); // 可中断
  });
};
```

## Q7: React 合成事件和事件委托的原理？

**难度**：⭐⭐⭐ | **频率**：🔥🔥🔥

💡 **回答要点**：

React 不直接在 DOM 元素上绑定事件，而是：
1. 所有事件委托到 **root 容器**（React 17+ 是 root，之前是 document）
2. 收到原生事件后，React 创建 **SyntheticEvent** 对象
3. 根据 event.target 向上查找对应 Fiber，触发正确组件的处理函数

好处：
- 减少事件监听器数量
- 统一管理事件生命周期
- 跨浏览器兼容

> ⚠️ **常考点**：React 17 把事件绑定从 document 改到了 root，这解决了微前端场景下多个 React 实例事件冲突的问题。
