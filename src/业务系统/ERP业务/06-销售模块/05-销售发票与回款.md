# 销售发票与回款

## 概述

销售发票是确认收入的法定凭证，回款则是资金回收的关键环节。开票后生成应收账款进入财务 AR 子系统，客户回款通过核销流程清账。本文档描述从开票到回款的完整流程。

## 一、业务流程

### 1.1 开票到回款流程

```
销售订单已发货 → 创建销售发票(SI) → 发票审核 → 开票确认
                                                   │
                                          ┌────────┤
                                          ▼        ▼
                                    确认收入     生成应收单(AR)
                                    销项税       更新客户余额
                                                   │
                                                   ▼
                                    客户回款 → 回款核销 → 清账
                                                   │
                                          ┌────────┤
                                          ▼        ▼
                                     全额回款    部分回款
                                     (自动清账)  (部分核销)
```

## 二、核心实体

### 2.1 销售发票

```

├── TenantId: Guid

├── InvoiceType: InvoiceType           # 发票类型
├── CustomerId: Guid
├── CustomerName: string(200)
├── CustomerTaxId: string(30)          # 客户税号（开票信息）
├── CustomerAddress: string(300)       # 客户地址（开票信息）
├── CustomerBankInfo: string(200)      # 客户银行信息（开票信息）
│
├── InvoiceDate: DateTime              # 开票日期
├── DueDate: DateTime                  # 到期日
├── SalesOrderId: Guid                 # 关联 SO
├── SalesOrderNo: string(30)
├── DeliveryNoteId: Guid?              # 关联 DN
├── DeliveryNoteNo: string(30)?
│
├── CurrencyCode: string(3)
├── ExchangeRate: decimal(18,6)
├── SubTotal: decimal(18,2)           # 不含税金额
├── TaxRate: decimal(5,2)
├── TaxAmount: decimal(18,2)          # 税额
├── TotalAmount: decimal(18,2)        # 含税总额
├── PaidAmount: decimal(18,2)         # 已收金额
├── RemainingAmount: decimal(18,2)    # 未收金额
│
├── Status: SalesInvoiceStatus
├── ReceivableId: Guid?                # 生成的应收单ID
├── VoucherId: Guid?                   # 收入确认凭证
├── Remark: string(500)
└── Lines: List<SalesInvoiceLine>

SalesInvoiceLine (发票行)
├── Id: Guid
├── InvoiceId: Guid
├── LineNo: int
├── SOLineId: Guid                     # 关联 SO 行
├── ItemId: Guid
├── ItemCode: string(50)
├── ItemName: string(200)
├── Specification: string(200)?
├── UnitOfMeasure: string(20)
├── Quantity: decimal(18,4)
├── UnitPrice: decimal(18,6)
├── Amount: decimal(18,2)
├── TaxRate: decimal(5,2)
├── TaxAmount: decimal(18,2)
├── TotalAmount: decimal(18,2)
└── Remark: string(200)

枚举:
  InvoiceType: VATSpecial=1(增值税专票), VATGeneral=2(增值税普票),
               Electronic=3(电子发票), Other=9
  SalesInvoiceStatus: Draft=0, Submitted=1, Approved=2, Posted=3, 
                      PartPaid=4, Paid=5, Cancelled=-1
```

## 四、回款管理

回款由财务 AR 子系统处理，详见 [应收账款 AR](../05-财务模块/03-应收账款AR.md)。

关键要点：
- 回款确认后自动核销对应应收单
- 支持部分回款和多笔应收合并回款
- 现金折扣在约定期限内给予
- 预收款转应收在发货/开票时自动处理

## 七、业务规则

| 规则 | 描述 |
|------|------|
| 必须关联 SO | 发票必须关联已审批的销售订单 |
| 不超发票 | 开票数量不得超过 SO 行剩余未开票数量 |
| 开票信息完整 | 增值税专票需客户税号、地址、银行信息完整 |
| 过账即确认收入 | 过账自动生成收入确认凭证和应收单 |
| 退货需审批 | 所有退货必须经过审批流程 |
| 退货入库 | 退货收货后自动增加库存 |
| 退货红冲 | 退货完成后自动红冲收入和成本 |
| 已过账不可改 | 已过账发票只能通过红冲处理 |
