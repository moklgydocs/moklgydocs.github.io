# 仓库与库位管理

## 概述

仓库与库位管理是库存模块的物理基础，定义企业物料存储的空间结构。系统支持多级仓库层级（仓库→库区→排→货架→库位），配合上架策略和条码/RFID 集成，实现物料的精确定位和高效流转。

## 一、仓库层级体系

```
企业 (Tenant)
├── 原材料仓库 (RM-WH)
│   ├── 库区A: 收货暂存区 (Receiving)
│   │   ├── 收货码头 A-DOCK-01
│   │   └── 收货码头 A-DOCK-02
│   ├── 库区B: 待检区 (QC)
│   ├── 库区C: 合格品存储区 (Storage)
│   │   ├── 排01
│   │   │   ├── 货架01
│   │   │   │   ├── 库位 C-01-01-01 (排-架-层)
│   │   │   │   ├── 库位 C-01-01-02
│   │   │   │   └── ...
│   │   │   └── 货架02
│   │   └── 排02
│   ├── 库区D: 不合格品区 (Rejected)
│   └── 库区E: 危化品区 (Hazmat)
│
├── 半成品仓库 (WIP-WH)
│   ├── 车间线边仓
│   └── 半成品暂存区
│
├── 成品仓库 (FG-WH)
│   ├── 库区A: 常规存储区
│   ├── 库区B: 待发货区 (Staging)
│   └── 库区C: 大件区
│
├── 备品备件仓 (SP-WH)
├── 退货仓 (RT-WH)
├── 寄售仓 (CS-WH)
└── 在途虚拟仓 (IT-WH)
```

### 1.1 层级关系

```
┌──────────┐
│ Warehouse│ 仓库: 物理仓库或虚拟仓库
└────┬─────┘
     │ 1:N
     ▼
┌──────────┐
│   Zone   │ 库区: 按功能/存储条件划分
└────┬─────┘
     │ 1:N
     ▼
┌──────────┐
│ Location │ 库位: 最小存储单元 (排-架-层 或自定义编码)
└──────────┘
```

## 二、核心实体

### 2.1 仓库

```
Warehouse (仓库)
├── Id: Guid
├── TenantId: Guid
├── Code: string(20)                   # 仓库编码 (如 RM-WH)
├── Name: string(100)                  # 仓库名称
├── Type: WarehouseType                # 仓库类型
├── IsVirtual: bool                    # 是否虚拟仓 (在途仓、寄售仓)
├── Address: string(300)               # 地址
├── City: string(50)
├── Province: string(50)
├── Latitude: decimal(10,7)?           # 纬度
├── Longitude: decimal(10,7)?          # 经度
├── ContactName: string(50)?           # 联系人
├── ContactPhone: string(30)?
├── ManagerId: Guid?                   # 仓管负责人
├── OperatingStartTime: TimeOnly?      # 运营开始时间
├── OperatingEndTime: TimeOnly?        # 运营结束时间
├── MaxVolume: decimal(18,2)?         # 最大容积 (m³)
├── MaxWeight: decimal(18,2)?         # 最大承重 (kg)
├── AllowNegativeStock: bool           # 是否允许负库存
├── IsDefault: bool                    # 是否默认仓库
├── IsActive: bool
├── SortOrder: int
└── Remark: string(500)

枚举:
  WarehouseType:
    RawMaterial=1(原材料仓), WIP=2(半成品仓), FinishedGoods=3(成品仓),
    Spare=4(备品备件仓), Return=5(退货仓), Consignment=6(寄售仓),
    Transit=7(在途仓), QualityHold=8(质量冻结仓), Other=9
```

## 三、上架策略

### 3.1 策略实体

```
PutawayStrategy (上架策略)
├── Id: Guid
├── TenantId: Guid
├── Code: string(20)
├── Name: string(100)
├── StrategyType: PutawayStrategyType
├── Priority: int                      # 优先级 (数字越小优先级越高)
├── ApplicableWarehouseId: Guid?       # 适用仓库 (空=所有)
├── ApplicableItemCategoryId: Guid?    # 适用物料类别
├── ApplicableStorageClass: StorageClass?
├── PreferZoneId: Guid?                # 优先库区
├── AllowMixedItems: bool              # 允许混放
├── MaxLocationUtilization: decimal(5,2)? # 最大库位利用率
├── IsActive: bool
└── Remark: string(200)

枚举:
  PutawayStrategyType:
    FixedLocation=1(固定库位),     # 物料有固定存放位，直接上架
    NearestEmpty=2(最近空位),      # 距收货区最近的空库位
    ClassBased=3(分类上架),        # 按存储类别匹配库区
    ZoneBased=4(指定库区),         # 上架到指定库区
    Consolidate=5(合并上架),       # 已有同物料的库位优先
    Random=6(随机分配)             # 任意可用空库位
```

### 3.2 上架推荐流程

```
收货确认
    │
    ▼
获取物料信息 (存储类别、危化品标识、温度要求)
    │
    ▼
匹配上架策略 (按优先级排序)
    │
    ├── 策略1: 固定库位 → 查找物料的固定库位
    │   └── 有空间 → 推荐此库位
    │   └── 无空间 → 下一策略
    │
    ├── 策略2: 合并上架 → 查找已有同物料的库位
    │   └── 有空间 → 推荐此库位
    │   └── 无空间 → 下一策略
    │
    ├── 策略3: 分类上架 → 按存储类别筛选库区
    │   └── 查找该库区空位 → 推荐
    │
    └── 兜底: 最近空位 → 任意满足条件的空库位
    │
    ▼
生成上架任务 (PutawayTask)
    │
    ▼
仓管员执行上架 → 扫码确认
```

## 四、库位容量与利用率

### 4.1 利用率计算

```
库位利用率:
  重量利用率 = CurrentWeight / MaxWeight × 100%
  体积利用率 = CurrentVolume / MaxVolume × 100%
  托盘利用率 = CurrentPallets / MaxPallets × 100%
  综合利用率 = Max(重量利用率, 体积利用率, 托盘利用率)

库区利用率:
  = 已使用库位数 / 总库位数 × 100%

仓库利用率:
  = Σ(各库区已使用库位) / Σ(各库区总库位) × 100%
```

### 4.2 容量预警

| 级别 | 利用率范围 | 动作 |
|------|----------|------|
| 正常 | 0 - 70% | 无 |
| 预警 | 70% - 85% | 系统提醒 |
| 警告 | 85% - 95% | 限制新上架 |
| 满载 | > 95% | 禁止上架 |

## 五、条码/RFID 集成

### 5.1 条码体系

| 对象 | 条码类型 | 格式 | 示例 |
|------|---------|------|------|
| 库位 | Code128 | LOC-{仓库编码}-{库位编码} | LOC-RMWH-C010203 |
| 物料 | Code128/EAN13 | {物料编码} | MAT-20240001 |
| 批次 | Code128 | BAT-{物料编码}-{批次号} | BAT-MAT001-20240115 |
| 序列号 | Code128 | SN-{物料编码}-{序列号} | SN-MAT001-00001 |
| 入库单 | QR Code | {入库单号}-{行号} | RO-20240115-0001-01 |
| 出库单 | QR Code | {出库单号}-{行号} | IO-20240115-0001-01 |
| 托盘 | Code128 | PLT-{YYYYMMDD}-{SEQ} | PLT-20240115-0001 |

### 5.2 手持终端操作

```
扫描工作流:

上架操作:
  ① 扫描入库单条码 → 加载待上架物料
  ② 扫描目标库位条码 → 确认库位
  ③ 扫描物料条码 → 确认物料
  ④ 输入数量 → 确认上架
  ⑤ 系统更新库存 → 打印上架标签

拣货操作:
  ① 扫描拣货任务条码 → 加载待拣物料清单
  ② 按拣货路径导航到库位
  ③ 扫描库位条码 → 确认位置
  ④ 扫描物料条码 → 确认物料
  ⑤ 输入拣取数量 → 确认拣货
  ⑥ 下一个库位 → 重复③-⑤

盘点操作:
  ① 扫描盘点单条码 → 加载待盘物料
  ② 扫描库位条码 → 定位库位
  ③ 扫描物料条码 → 确认物料
  ④ 输入实盘数量 → 提交
```

## 八、业务规则

| 规则 | 描述 |
|------|------|
| 编码唯一 | 仓库编码租户内唯一，库位编码仓库内唯一 |
| 层级完整 | 库位必须属于某个库区，库区必须属于某个仓库 |
| 存储类别兼容 | 物料存储类别必须与库位存储类别兼容 |
| 容量约束 | 上架不可超过库位最大重量/体积/托盘数 |
| 冻结约束 | 冻结库位禁止上架和拣货操作 |
| 危化品隔离 | 危化品只能存放在危化品库区 |
| 温控验证 | 冷链/冷冻物料只能存放在对应温控库区 |
| 虚拟仓限制 | 虚拟仓库不可进行物理上架/拣货操作 |
| 删除约束 | 有库存的仓库/库区/库位不可删除 |
| 默认仓库 | 每个租户只能有一个默认仓库 |
| 混放控制 | 非混放库位只能存放单一物料 |
| 拣选位补货 | 拣选位库存低于下限时触发补货提醒 |
