# 采购申请与订单

## 概述

采购申请（PR）到采购订单（PO）是采购流程的核心环节。PR 表达采购需求（来自 MRP 计划或手工提出），经审批后转化为 PO 发送给供应商，PO 是企业与供应商之间的正式合同凭据。

## 一、业务流程

### 1.1 PR 到 PO 流程

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 需求产生   │───▶│ 创建PR   │───▶│ PR审批   │───▶│ 转为PO   │
│ MRP/手工  │    │          │    │          │    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                    │                 │
                                    ▼                 ▼
                               ┌──────────┐    ┌──────────┐
                               │ 驳回修改  │    │ PO审批   │
                               └──────────┘    └──────┬───┘
                                                      │
                                    ┌─────────────────┤
                                    ▼                 ▼
                               ┌──────────┐    ┌──────────┐
                               │ 驳回修改  │    │ 发送供应商│
                               └──────────┘    └──────┬───┘
                                                      │
                                                      ▼
                                               ┌──────────┐
                                               │ 供应商确认│
                                               └──────────┘
```

## 二、核心实体

### 2.1 采购申请

```
PurchaseRequisition (采购申请)
├── Id: Guid
├── TenantId: Guid
├── RequisitionNo: string(30)          # PR 编号
├── RequesterId: Guid                  # 申请人
├── DepartmentId: Guid                 # 申请部门
├── RequisitionDate: DateTime          # 申请日期
├── RequiredDate: DateTime             # 需求日期
├── Priority: Priority                 # 优先级
├── Source: PRSource                   # 来源
├── Status: PRStatus                   # 状态
├── TotalAmount: decimal(18,2)        # 预估总额
├── ApprovalStatus: ApprovalStatus
├── Remark: string(500)
└── Lines: List<PRLine>

PRLine (采购申请行)
├── Id: Guid
├── RequisitionId: Guid
├── LineNo: int
├── ItemId: Guid                       # 物料ID
├── ItemCode: string(50)
├── ItemName: string(200)
├── Specification: string(200)         # 规格
├── UnitOfMeasure: string(20)          # 计量单位
├── Quantity: decimal(18,4)            # 需求数量
├── EstimatedUnitPrice: decimal(18,6)  # 预估单价
├── EstimatedAmount: decimal(18,2)     # 预估金额
├── RequiredDate: DateTime             # 行级需求日期
├── SuggestedSupplierId: Guid?         # 建议供应商
├── PurchaseOrderId: Guid?             # 已转 PO 的 ID
└── Remark: string(200)

枚举:
  Priority: Low=1, Normal=2, High=3, Urgent=4
  PRSource: Manual=1, MRP=2
  PRStatus: Draft=0, Submitted=1, Approved=2, PartConverted=3, Converted=4, 
            Rejected=-1, Cancelled=-2
```

## 三、审批流程

### 3.1 审批层级

| 金额范围 | PR 审批 | PO 审批 |
|---------|---------|---------|
| ≤ 5,000 | 部门主管 | 采购主管 |
| 5,001 - 50,000 | 部门经理 | 采购经理 |
| 50,001 - 200,000 | 部门总监 | 采购总监 + 财务经理 |
| > 200,000 | VP | 总经理 |

### 3.2 审批规则

| 规则 | 描述 |
|------|------|
| 预算检查 | PR 审批时检查部门预算余额 |
| 供应商检查 | PO 的供应商必须为合格/优选/战略级 |
| 价格检查 | 单价超过历史均价 10% 需额外审批 |
| 单一来源 | 金额超限的单一来源采购需特别审批 |

## 六、业务规则

| 规则 | 描述 |
|------|------|
| PR 合并 | 同一供应商的多个 PR 可合并为一个 PO |
| PO 拆分 | 一个 PR 可拆分为多个 PO（不同供应商） |
| 已审批不可修改 | Approved 及以后状态的 PO 不可修改，需取消后重建 |
| 部分收货 | PO 支持多次收货，跟踪每行的已收数量 |
| 超收限制 | 收货数量不得超过订购数量的 105%（可配置） |
| 关闭条件 | 所有行收货完毕且发票匹配完成后可关闭 |
| 强制关闭 | 管理员可强制关闭未完全收货的 PO（记录原因） |
| 价格锁定 | PO 确认后价格不可修改，变更需创建补充协议 |
